# Модульный backend

`app` — единственный поддерживаемый прикладной процесс и Docker-сервис `backend`.
Отдельно работают Keycloak, PostgreSQL и MinIO. nginx сохранён как исторический снимок прежнего публичного входа,
но не запускается и вместе с монолитом не развивается. Актуальный контракт поддерживается
в OpenSpec и тестах приложения. Publisher не включён в зависимости приложения и Docker socket не нужен.

## Модули и ресурсы

Сборка `app` подключает четыре библиотечных `runtime` через Gradle composite build.
У каждой подсистемы остаются свои feature/core-модули и БД. Вызовы проверки доступа
к проекту, ключа и принадлежности DS выполняются через прикладные интерфейсы и адаптеры
`app/data`, выбираемые DI. Реализации сценариев не открываются ради связывания модулей.

Контракты получения контекста находятся в presentation-модулях потребителей, а app
поставляет проверенный контекст конкретного запроса. Runtime не зависит от app.
Политика доступа общая и загружается один раз; настройки и клиенты подсистем раздельны.
Переопределение DI-регистраций запрещено.

SQL и OpenAPI имеют единственный источник в runtime соответствующей подсистемы.
Начальные данные DS остаются в своих feature-модулях. `processResources` добавляет
пространства имён `dsbuilder/<subsystem>/...`; номера и содержимое SQL не меняются.
`verifyResourceOwnership` отклоняет неоднозначные прикладные ресурсы до упаковки JAR.

## Сборка и запуск

Из корня репозитория:

```bash
./backend-kt/gradlew -p backend-kt/app shadowJar
./backend-kt/start-local.sh --detach
```

`./setup-local.sh` дополнительно наполняет `base` и запускает веб-клиент.
`./backend-kt/start-local.sh --down` останавливает контейнеры без их удаления.
Новая установка получает постоянные именованные тома PostgreSQL, MinIO и Keycloak.
Явный `./setup-local.sh --reset` удаляет локальные данные. При переходе со старого контура локальные данные также могут потеряться; их сохранение не гарантируется.

Прямой запуск JVM не читает Compose и получает те же env:

```bash
KEYCLOAK_ISSUER=http://localhost:8080/realms/dsbuilder \
PROJECTS_DATABASE_URL=jdbc:postgresql://localhost:5432/projects_service \
java -jar backend-kt/app/build/libs/backend-app-all.jar
```

Остальные подключения задаются согласно таблице ниже. Для прямого запуска или
Kubernetes указывайте доступные из процесса адреса инфраструктуры. Наличие Compose
не влияет на чтение и приоритет настроек. Dockerfile production собирает JAR из
исходников, Dockerfile.local использует локально собранный JAR.

## Конфигурация через env

| Переменные | Назначение и значения по умолчанию |
|---|---|
| `BACKEND_PORT` | HTTP-порт приложения, 8080 |
| `BACKEND_PUBLIC_URL` | Публичный HTTP(S)-адрес для проксирования Keycloak; по умолчанию адрес из `KEYCLOAK_ISSUER` либо `http://localhost:8080` |
| `BACKEND_SHUTDOWN_TIMEOUT_MS` | Общий срок завершения, 30000 мс |
| `OIDC_WEB_ORIGIN` | Разрешённый origin веб-клиента; если отсутствует, допускаются локальные адреса разработки |
| `KEYCLOAK_INTERNAL_URL` | Адрес Keycloak из процесса; по умолчанию `PROJECTS_IDENTITY_KEYCLOAK_BASE_URL` либо `http://localhost:8090` |
| `KEYCLOAK_REALM` | Realm, `dsbuilder` |
| `KEYCLOAK_ISSUER`, `KEYCLOAK_AUDIENCE`, `KEYCLOAK_JWKS_URL` | Прежние параметры проверки JWT; issuer должен соответствовать публичному адресу выдачи токенов |
| `COMPOSE_PLUGIN_TIMEOUT_SECONDS` | Ожидание ответа публикации после приёма архива, 120 с; активная загрузка не ограничена общим временем 120 с |
| `GATEWAY_PROXY_TIMEOUT_SECONDS` | Таймауты чтения/записи, 300 с; установление соединения Keycloak — 10 с |
| `DOCUMENTATION_MAX_REQUEST_SIZE` | Входной предел документации, `101m`, поддерживаются суффиксы `k`/`m` |
| `AUTHORIZATION_POLICY_PATH`, `PROJECT_AUTHORIZATION_POLICY_PATH` | Прежние пути политики; если заданы оба, должны совпадать. Без них используется встроенный источник authorization-core |
| `PROJECTS_DATABASE_URL`, `PROJECTS_POSTGRES_USER`, `PROJECTS_POSTGRES_PASSWORD` | Отдельная БД проектов, прежние настройки runtime |
| `DS_DATABASE_URL`, `DS_DATABASE_USER`, `DS_DATABASE_PASSWORD` | Отдельная предметная БД, прежние настройки runtime |
| `DOCUMENTATION_DATABASE_URL`, `DOCUMENTATION_POSTGRES_USER`, `DOCUMENTATION_POSTGRES_PASSWORD` | Отдельная БД документации, прежние настройки runtime |
| `PROJECTS_DATABASE_POOL_SIZE`, `DS_DATABASE_POOL_SIZE`, `DOCUMENTATION_DATABASE_POOL_SIZE` | Максимальные размеры отдельных пулов, по 10 |
| `PROJECTS_DATABASE_CONNECTION_TIMEOUT_MS`, `DS_DATABASE_CONNECTION_TIMEOUT_MS`, `DOCUMENTATION_DATABASE_CONNECTION_TIMEOUT_MS` | Ожидание подключения, по 5000 мс |
| `DOCUMENTATION_WORKER_PARALLELISM` | Число обработчиков, 1; допустимо от 1 до 32. Задания остаются в БД до свободного места исполнения |
| `DOCUMENTATION_WORKER_*`, `DOCUMENTATION_CLEANUP_*` | Прежние параметры аренды, повторов, опроса и очистки |
| `DOCUMENTATION_S3_*`, `DS_PLUGIN_S3_*` | Прежние подключения и настройки MinIO/S3 |
| `PROJECTS_IDENTITY_KEYCLOAK_*`, `PROJECTS_ACCESS_KEYS_*` | Прежние настройки поиска пользователей и ключей проектов |

Лимиты остальных маршрутов сохраняются: 2 MiB по умолчанию, 16 MiB для DS/импорта
API-меты, 64 MiB для публикации плагина. Проверяется фактически прочитанное тело,
включая chunked. Частота — 10 запросов/с с допустимой пачкой 20 сверх первого;
для DS — не больше 16 активных запросов на IP/URI. Произвольный X-Forwarded-For
не меняет адрес клиента. Доверенная цепочка разбирается справа налево.

`/health` показывает жизнеспособность, `/ready` проверяет обязательные БД, миграции
и хранилище документации. Внутренние маршруты сервисов с публичного порта закрыты.

Для запуска только backend и его инфраструктуры из корня: `./setup-local.sh --backend-only`.
Веб-клиент и наполнение демонстрационными данными при этом не запускаются.

## Бюджеты ресурсов и диагностика

В обоих Compose app по умолчанию ограничен `BACKEND_MEMORY_LIMIT=2g`. Образ и Compose задают `JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=60.0`: около 1,2 GiB heap при лимите 2 GiB, с запасом для metaspace, стеков и прямых буферов. Обе настройки переопределяются окружением. Для запуска без Compose задавайте лимит памяти средствами инфраструктуры либо явный `-Xmx` с отдельным запасом для памяти вне heap. `-Xmx` ограничивает только heap; процент heap не является ограничением памяти процесса и не гарантирует отсутствие OOM.

Projects, DS и documentation имеют независимые Hikari-пулы, по 10 подключений и 5000 мс ожидания по умолчанию. Публикация DS использует тот же пул DS. Учитывайте сумму пулов всех экземпляров монолита, отдельное DS LISTEN-соединение и служебный запас при настройке `max_connections` каждого сервера PostgreSQL. Увеличение пулов без измерений не является способом ускорить backend.

Обычный app-тест `ExplicitDatabaseTest` запрещает Exposed-транзакции без `db = …`, `db = null` и wildcard-импорты транзакций. Общий default Exposed не используется для выбора БД подсистемы. Projects получает отдельный объект конфигурации, поэтому прежние ключи `database.*` не пересекаются с настройками других модулей.

`/ready` отдельно возвращает `documentation.database` и `documentation.storage`; подробные ошибки остаются вне публичного ответа. `stop(gracePeriod)` отменяет задачи, ожидает их ограниченное время и освобождает ресурсы. Идемпотентный `close()` освобождает ресурсы без ожидания задач, включая откат неполного запуска.

## Переход с прежнего контура

Локально достаточно обычного `./setup-local.sh` или `./backend-kt/start-local.sh --detach`.
Compose удаляет старые прикладные контейнеры этого проекта через `--remove-orphans`
и запускает монолит. Отдельные `--adopt`, инвентаризация, резервные копии или ручной
сброс для локального запуска не требуются. Контейнеры инфраструктуры могут
пересоздаваться; сохранение локальных БД, MinIO и настроек Keycloak при переходе
не гарантируется. Монолит получает отдельный набор локальных томов `monolith_*`, чтобы не смешивать старые данные разных подсистем. Обычные повторные запуски используют эти именованные тома;
автоматического `down -v` или очистки всех Docker-томов нет.

Для dev/prod с внешними PostgreSQL и S3 сохраняются существующие подключения,
базы, buckets, данные Keycloak и публичный адрес. Переключается прикладная часть
на образ `backend`; локальный сброс данных на эти окружения не распространяется.
Перед серверным переключением проверяются резервные копии и возможность отката.
Публикация образов и deployment выполняются только по отдельному запросу.

## Проверки и публикация

Основной публичный контракт зафиксирован в [contracts/README.md](contracts/README.md).
Узкие проверки: `./backend-kt/gradlew -p backend-kt/app test verifyResourceOwnership`.
Общие FAST, независимое ревью и FULL выполняются в конце реализации согласно OpenSpec.
Подготовка CI входит в изменение: публикуются `backend`, `keycloak`, `keycloak-bootstrap`.
Запуск публикации и переключение production требуют отдельного запроса.

## Внешняя точка входа и совместимость

Production backend сохраняет сетевой alias `gateway`, поэтому прежний upstream `gateway:8080` продолжает разрешаться в той же Compose-сети. `BACKEND_PUBLIC_URL` необязателен: без него origin для Keycloak берётся из `KEYCLOAK_ISSUER` до `/realms/`. Отдельное значение нужно только для явного переопределения публичного адреса.

Общие IP-лимиты частоты запросов и соединений настраиваются во внешнем reverse proxy или балансировщике. Backend не требует настройки доверенных прокси; авторизация, лимиты тела и параллелизм фоновых workers остаются внутри приложения.

Самостоятельные launcher'ы подсистем сохранены для модульной разработки и будущего разделения инфраструктуры. Они не являются вторым поддерживаемым Docker-контуром. DS standalone явно выбирает внутренний API за доверенным gateway; открывать его напрямую внешним клиентам нельзя.
