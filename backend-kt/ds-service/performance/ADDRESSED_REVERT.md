# Адресность полного отката

Новый маршрут принимает `(draftId, entityType, entityId, expectedRevision)`. Старые маршруты
по changeId сохранены. Частичный откат параметров использует прежний API.

## Проверенные потребители

| Участок | Ограничение чтения и необходимая область |
| --- | --- |
| `ExposedDraftChangeHandler` | `describeEntity` передаёт UUID в SQL differences; текущая и предыдущая ревизии только этой устойчивой сущности. Все обработчики компонентов и дизайн-системы используют эту основу. |
| Определение токена | Адресный delegate, затем удаление производного `/type` из отличия; полного describe нет. Пересчёт затрагивает старое и новое цветовые семейства. |
| Значение токена | Адресный delegate; основа новой темы ищется по `(draftId, valueId)`. Слушатели блокируют и пересчитывают соответствующее семейство. |
| Тема | Адресный delegate. Создание/удаление темы сохраняет обработку её начальных значений и затронутых семейств. |
| `withPaletteLocation` | Только выбранная запись палитры и её расположение. |
| `PaletteRebuildJournal` | Выбранная растяжка/ступень, родитель и ступени этой растяжки; общий журнал не читается. |
| Политика начальных значений | `visibleEntity` запрашивает только связанную тему; основы значений выбираются по переданным UUID. |
| Проверка ссылок палитры | Восстановленное значение и его определение. При наличии ссылок используется один снимок палитры на затронутую тему; это предметная зависимость, не журнал. |
| Проверки компонентов | Выбранное значение свойства и связанный токен либо вариации конкретного компонента. |
| Обвязка транзакции | Прежние SERIALIZABLE, повторы, контекст, идемпотентность и метаданные. Оптимизация SET и упаковка SQL ради счётчика удалены из эксперимента. |
| Триггеры и ограничения | Обычные триггеры включены; отложенные ограничения проверяются до успеха. Технические редакции и маркеры создаются штатно. |

`supportsAddressedRevert` по умолчанию выключен: обработчик с реализацией describeEntity
через полный describe не получает доступ к новому маршруту автоматически. Зарегистрированные
обработчики делегируют адресной Exposed-основе. Старые API от этого ограничения не меняются.

## Наборный путь значений

Текущие/предыдущие состояния читаются набором по выбранным UUID. Состав цветовых семейств
находится по именам, а необходимые значения — по UUID определений. После блокировки значений
и определений состояние проверяется повторно. Удаление выбранных черновых ревизий и путей
выполняется наборами. Восстанавливаемые ссылки, основы новой темы, создание сущности,
изменение производного типа и смешанные зависимые пакеты используют адресные предметные
обработчики с прежними проверками и входным порядком. Перехода к поиску changeId нет.

Специализация включается только при явной поддержке всех политик, валидаторов и слушателей.
Для неизменного цветового типа проверяются необходимые активные значения всего семейства,
включая другие темы и платформы. Число SQL не является критерием выбора алгоритма.

## Воспроизведение

Изолированная копия настоящей PostgreSQL-схемы: 153 105 значений, 10 407 в выбранной теме.
Фиксированный пакет — девять значений трёх определений одного семейства, три платформы,
Light. Во время роста нерелевантного набора состав семейства и число его значений фиксированы.
Посторонние правки создаются обычными INSERT ревизий с работающими триггерами. Добавление
только фиктивных технических состояний проверяется отдельно интеграционным тестом.

Пять прогревов и двадцать измерений каждого варианта. Время берётся из публичного HTTP-входа,
включает транзакцию, проверки и сохранение ответа. Повторы транзакции суммируются, выбросы
не удаляются. Каждый цикл сравнивает все значения темы до изменения и после отката, кроме
ожидаемо изменившейся технической редакции. SQL-планы снимаются auto_explain; сопоставимые
варианты имеют одинаковые настройки. Это локальная синтетическая нагрузка, не SLA dev.

Итоговые серии и ограничения приведены в RESULTS.md. FAST/FULL/review остаются отложенными
по указанию разработчика.
