## MODIFIED Requirements

### Requirement: Сохранение доводит до сервера созданные и удалённые токены

Сохранение темы SHALL одним атомарным запросом `POST /tenants/{id}/token-changes` создавать определения
токенов, созданных в черновике, сохранять значения tenant, записывать привязку новых токенов к группе
палитры и удалять токены, удаление которых запланировано в черновике.

#### Scenario: В черновике новый цветовой токен

- **WHEN** пользователь сохраняет тему с токеном, созданным в черновике
- **THEN** клиент MUST передать определения токена для всех подгрупп и состояний и их значения выбранного
  tenant одним запросом
- **THEN** при выбранной в черновике группе палитры клиент MUST передать её `paletteGroupId`
- **THEN** после сохранения токен MUST иметь значения во всех tenant дизайн-системы

#### Scenario: В черновике удаление токена

- **WHEN** пользователь сохраняет тему с запланированным удалением токена
- **THEN** клиент MUST передать токен в `delete` и MUST NOT передавать его значения

#### Scenario: Сохранение отклонено

- **WHEN** сервер отклонил запрос
- **THEN** на сервере MUST NOT остаться части изменений
- **THEN** клиент MUST сохранить черновик и показать причину; для `INVALID_TOKEN_VALUE` — токен, платформу и
  режим значения
