## Why

Раздел «Типографика» в клиенте остался прежним: старое меню, правки копятся в локальном черновике и уходят на сервер только общим сохранением темы, а значения правятся отдельно по каждой платформе в её единицах. Разделы «Палитра» и «Цвета» уже работают по прототипу SDDS Portal и сохраняют правки сразу, через операции `ds-service`. Типографика должна работать так же, чтобы тему можно было настраивать целиком в одном редакторе.

## What Changes

- **Экран «Типографика» по прототипу SDDS Portal.**
  - Слева переключатель размера экрана «Крупные / Средние / Мелкие» и дерево Display · Header · Body · Text. Строка дерева — стиль; состав стилей берётся из токенов темы.
  - В центре борд-шкала с живыми образцами текста.
  - Справа инспектор стиля:
    - «Стиль»: семейство шрифта, размер, высота строки, трекинг;
    - «Начертания»: вес Regular, Medium и Bold;
    - «Влияние»: компоненты, которые используют стиль.
- **Стиль типографии — три токена.** Токены `<экран>.<группа>.<размер>.normal|medium|bold` отличаются только весом, поэтому в интерфейсе это один стиль:
  - размер, строка и трекинг пишутся во все три токена стиля на выбранном экране;
  - вес начертания и семейство шрифта пишутся во все экраны темы.
- **Одно значение в px.** Пользователь вводит px и em, `ds-service` записывает их в формат каждой платформы.
- **Семейство шрифта — выбор из семейств темы.** Стиль ссылается на одно из семейств дизайн-системы (`fontFamily.<name>`); добавление шрифтов и файлов в изменение не входит.
- **Операции над стилем типографии в `ds-service`.**
  - Чтение стилей темы в px с семействами, компонентами, которые используют стиль, и техническими редакциями значений; чтение опубликованной версии по `versionId`.
  - Изменение стиля с проверкой значений, предметными редакциями значений токенов (базовая редакция на значение, «последняя запись побеждает» с предупреждениями в `X-DS-Mutation-Metadata`, без `409`) и правами `tenants:write`; изменения попадают в журнал черновика и откатываются общей ручкой.
- **Автосохранение.** Каждая правка сохраняется сразу через общую обёртку предметных мутаций редактора, с автоматическим повтором при ошибке сети; стили перечитываются, когда тему изменил другой пользователь. Неподтверждённые записи прежнего черновика отправляет общее автосохранение редактора, отдельного баннера в разделе нет.
- **Версии и журнал.** Опубликованная версия открывается только для чтения, стиль открывается из журнала по `?tokenId`.
- **BREAKING (интерфейс).** Убирается старый раздел «Типографика»: меню `MenuOld`, правка значений по платформам, добавление и отключение токенов типографии.

## Capabilities

### New Capabilities

- `typography-styles-api`: операции `ds-service` над стилями типографии темы: модель стиля из трёх токенов, чтение в px с семействами и использованием в компонентах на границе версии, изменение с переводом в формат платформ, проверка значений, предметные редакции и права.
- `typography-tokens-editor`: раздел «Типографика» клиента по прототипу SDDS Portal: размеры экрана, дерево, борд, инспектор, автосохранение с повтором, перечитывание по сигналу об изменении черновика, адресация из журнала, режим только для чтения и расхождения с прототипом.

### Modified Capabilities

Нет: существующие требования не меняются.

## Impact

- **backend-kt / `ds-service`:**
  - `feature-themes`: use case чтения и изменения стиля типографии, порт чтения использования стиля в конфигурациях компонентов, проверка и перевод значений в формат платформ, маршруты `/api/ds/tenants/{tenantId}/typography-styles`.
  - Чтение стилей и семейств — по последним редакциям `token_revisions` и `token_value_revisions` на выбранной границе; запись — новыми редакциями `token_value_revisions` черновика с путём `/value`. Журнал, откат и SSE-сигналы для `token-value` работают без изменений.
  - Чтение использования стиля — по последним редакциям значений свойств и стилей компонентов на той же границе, без изменения схемы.
  - `contracts/route-manifest.json` и `openapi/documentation.yaml` — новые операции с общими параметрами `VersionId`, `OptionalBaseRevision` и заголовками `MutationMetadata`; контрактные тесты.
  - Миграций нет.
- **js / клиент:**
  - Новый модуль `modules/typographyTokens` (домен, порт и HTTP-адаптер) и экран `pages/typography` по прототипу.
  - Мутации — через `api/subjectMutation.ts`, базовые редакции — `api/subjectRevisions.ts`, состояние очереди — `api/draftAutosaveActivity.ts`, путь операций — в `api/incompleteMutationMetadata.ts`, адресация — `hooks/useAddressedToken.ts`.
  - Удаление старого экрана и действий `typographyTokenActions` для добавления и отключения токенов.
  - Стили экрана — по правилам прототипа `.editor-fonts-workbench`.
- **js / db-service:** не затрагивается; маршруты типографии обслуживает `ds-service`.
- **frontend-kt:** не затрагивается: `theme fetch` читает значения токенов как раньше.
