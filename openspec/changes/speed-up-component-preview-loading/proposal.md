## Why

При выборе компонента в редакторе превью и панель свойств появляются через несколько секунд, и это касается и Web-, и Compose-компонентов. Сервер отвечает быстро (каждое чтение 4–33 мс на локальном контуре), а время уходит на три вещи:
- **Число запросов.** Клиент собирает один компонент из 11 запросов, большинство из них читают списки всей дизайн-системы (≈2 МБ на Web-компонент). Все чтения проходят через клиентский ограничитель (~8 запросов в секунду), который нужен из-за лимита gateway.
- **Последовательность.** Связанные компоненты превью загружаются по одному, разделы токенов тоже читаются друг за другом.
- **Перезапуск плагина.** Compose-плагин запускается заново при каждой смене компонента.

Пользователь ждёт на каждом клике, поэтому это стоит исправить до новых возможностей превью.

Замеры на локальном контуре (`base` для Web, `sdds_serv_local` для Compose):

| Компонент | Компонентов подряд | Чтений сейчас | Байт сейчас |
|---|---|---|---|
| Web `Button` | 1 | 11 | ≈2 МБ |
| Compose `ButtonGroup` (→ `BasicButton`, `IconButton`) | 3 | ≈27 | ≈3,5 МБ |
| Compose `Avatar` (→ `Badge`, `Counter`, `Indicator`) | 4 | ≈36 | ≈4,7 МБ |

Если отфильтровать ответы до одного компонента, на Web `Button` остаётся ≈38 КБ, на Compose `Avatar` — ≈15 КБ.

## What Changes

- **ds-service:** новый эндпоинт чтения `GET /api/ds/design-systems/{designSystemId}/components/{componentId}/editor-bundle?platform=web|compose[&versionId=]`. Он одним ответом отдаёт всё, что редактору нужно для одного компонента: компонент, его оформления в ДС, экспорт конфигураций, свойства с платформенными параметрами и вариациями свойств, вариации и стили, запись web-адаптера, зависимости и связанные по ним компоненты. Внутри ответа те же DTO, что у существующих списочных эндпоинтов, но отфильтрованные по компоненту. Существующие эндпоинты не меняются.
- **Клиент:** при выборе компонента делает один запрос `editor-bundle` вместо 11. Связанные компоненты превью загружаются такими же запросами параллельно по уровням ссылок и совмещаются на клиенте. Полная загрузка без выбранного компонента не меняется.
- **Клиент:** разделы токенов, нужные выбранному компоненту, читаются параллельно, а не по очереди.
- **Клиент:** Compose-плагин запускается один раз при входе в раздел компонентов и живёт при смене компонентов. Сейчас iframe уничтожается и плагин перезапускается на каждом клике.
- **Gateway:** сжимает gzip JSON-ответы маршрутов дизайн-системы. Сейчас сжатия нет нигде.
- Клиентский ограничитель чтений и лимит gateway не меняются.

## Capabilities

### New Capabilities

- `component-editor-bundle-api`: чтение всех данных одного компонента для редактора одним запросом ds-service.
- `gateway-response-compression`: сжатие JSON-ответов маршрутов дизайн-системы в gateway без влияния на поток SSE и ответы аутентификации.

### Modified Capabilities

- `tenant-aware-theme-editor`: требование «Данные отдельных компонентов также загружаются лениво» дополняется. Выбранный компонент и каждый связанный читаются одним запросом, связанные — одновременно в пределах уровня ссылок, разделы токенов — одновременно.
- `compose-preview-host`: добавляется требование, чтобы плагин не перезапускался при смене компонента внутри раздела.

## Impact

- **backend-kt / ds-service:**
  - новый маршрут, use case и DTO ответа в `feature-components`;
  - методы репозиториев с фильтром по компоненту и свойствам (платформенные параметры, вариации свойств, оформления, зависимости);
  - чтение стилей компонента в ДС;
  - регистрация в Koin и `Application.kt`;
  - `app/src/main/resources/openapi/documentation.yaml`, `contracts/route-manifest.json` и счётчик операций в `OpenApiDocumentResourceTest`;
  - HTTP-тест на Postgres.
  - Схема БД и миграции не меняются.
- **backend-kt / identity-gateway:** директивы `gzip` в `nginx.local.conf` и `nginx.prod.conf.template` для `location` маршрутов `/api/projects/{projectId}/ds`, плюс скрипт проверки.
- **js / client:**
  - `api/componentRepository.ts` — новый путь загрузки выбранного компонента через `editor-bundle`;
  - `features/themeEditor/EditorSectionData.ts` — параллельная загрузка уровней ссылок и разделов токенов;
  - `composePreview` и страница компонентов — iframe плагина живёт на уровне раздела;
  - тесты.
- frontend-kt не затрагивается.
- **Вне скоупа:**
  - Web-плагин превью;
  - лёгкий список компонентов для меню;
  - предзагрузка при наведении;
  - условные запросы (`ETag`/`304`);
  - изменение лимитов gateway и клиентского ограничителя;
  - brotli;
  - сжатие остальных маршрутов.
