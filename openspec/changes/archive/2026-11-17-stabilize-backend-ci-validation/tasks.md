# Задачи

## 1. Диагноз CI merge-коммита

- [x] 1.1 Сохранить точный SHA, исходный тест и подробную Linux-диагностику с потоками/SQL; на снятом снимке сопоставить холодный/ANALYZE/generic планы и точные UUID/revision, описав границы вывода в diagnosis.md.

## 2. Устойчивое чтение редакций

- [x] 2.1 Перевести чтение редакций всех срезов темы на полный ключ выбранных UUID с массивами до 5 000, прежним контекстом и default=0; PostgreSQL-регрессией подтвердить точный результат и отсутствие декартова роста при холодной статистике и 100 001 посторонней записи, включая generic plan.
- [x] 2.2 Подтвердить прежние DTO, editRevision, историческую границу, типы/платформы, адресный срез и отказы чужой теме существующими/расширенными узкими HTTP-тестами; неизменённый сценарий literal batch должен пройти на точном merge-коде с новым чтением без увеличения timeout.

## 3. Единый backend workflow

- [x] 3.1 Заменить две матрицы и отдельный анализ одним job с корневым verifyFull и Python-контрактом; сравнением dry-run графов подтвердить сохранение всех прежних проверок и одно выполнение каждой задачи без изменения frontend/deploy workflow.
- [x] 3.2 Добавить полные исключения Test-задач и always-загрузку отчётов; контрольным неуспешным тестом/проверкой конфигурации подтвердить читаемую причину и неуспешный статус при ошибке Python или Gradle.

## 4. Совместный результат

- [x] 4.1 Повторить целевой Linux-прогон на снимке CI merge-коммита с новым чтением и сохранить длительность, планы, хеши, точные результаты и состав CI-графа; исходный сценарий должен укладываться в прежний минутный лимит, без ослабления проверок.

## 5. Независимые сценарии HTTP-журнала (согласованное дополнение)

- [x] 5.1 Разделить проверки новой и опубликованной темы на независимые тесты с общей реализацией, отдельными БД и прежним минутным лимитом; сохранить все переходы/assertions и чужую тему, подтвердить оба сценария узким прогоном.
