## Контекст

Условие пропуска построчных триггеров не ссылается на `NEW`/`OLD`, чтобы не делить триггеры `INSERT OR DELETE` (решение 1 архивного change `speed-up-design-system-creation`). Цена — пропуск действует на любые записи редакций в транзакции, пока окно открыто.

## Решения

### Сторожевые триггеры вместо проверки при закрытии окна

На каждой из 25 таблиц `*_revisions`, кроме `design_system_revisions` (список берётся из `pg_class`, а не из таблиц с триггерами), появляются два триггера `BEFORE … FOR EACH ROW`:

- на `INSERT` с условием `WHEN (окно открыто AND (NEW.design_system_id::text IS DISTINCT FROM настройка OR NEW.version_sequence_number <> 0))`;
- на `UPDATE OR DELETE` с условием `WHEN (окно открыто)` — при раскладке строки только вставляются.

Оба вызывают `reject_baseline_seed_foreign_write()`, которая бросает `P0001` с сообщением `baseline_seed_foreign_write`. Для правильных строк раскладки условие ложно и функция не вызывается; вне окна условие ложно для всех записей.

Сторожа создаются после пересоздания предметных триггеров с общим условием окна, поэтому не попадают в него, и не начинаются на `enforce_`, поэтому не попадают в обход проверок при закрытии окна.

Рассмотренные альтернативы:

- *Проверка в `verify` по `xmin` всех `*_revisions`.* `xmin` не индексирован, это полный просмотр 26 таблиц (локально до 444 тыс. строк в одной) на каждое создание. Отклонено: съедает ускорение.
- *Только описание ограничения в KDoc.* Не защищает от ошибки. Отклонено.

### V22 дополняется, а не пишется V23

V22 есть только в ветке PR #190 и не применялась ни на одном стенде; отдельная миграция ради ещё не выкаченной оказалась бы лишней. Сама проверка по `xmin` не нужна: в окне у целевой ДС есть только граница `0`, а сторож отсекает остальное до проверки внешних ключей. Отпечаток схемы в `FlywayAdoptionIntegrationTest` обновляется.

## Риски

- [Новая таблица редакций не получит сторожа] → тест каталога проверяет, что на каждой таблице `*_revisions`, кроме `design_system_revisions`, есть оба сторожа.
- [Условие сторожа добавит стоимость к наполнению] → условие — сравнение строк без запросов; замер на одной копии базы: `origin/dev`, PR без сторожа и PR со сторожем, порядок A–B–C–C–B–A.
- [Будущая миграция повторит приём DO-блока V22 с отказом на уже заданное условие] → она упадёт на сторожах, у которых есть `WHEN`; сторожей исключать по суффиксу `_seed_guard_`. Новая таблица `*_revisions` должна получить и общее условие окна, и оба сторожа; каталожный тест проверяет сторожей и условие у всех пользовательских триггеров.
- [TRUNCATE] → строчные сторожа его не ловят; TRUNCATE таблиц редакций вне модели угроз окна, приложение его не выполняет.
