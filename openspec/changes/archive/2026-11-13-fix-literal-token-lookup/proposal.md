## Why

Импорт конфигураций компонентов считает литералом любое значение без точки и не ищет для него токен. После #144 тень может называться одним сегментом (`card`), и её полное имя — само имя. Ссылка на такую тень при импорте сохраняется строкой без привязки к токену, поэтому повторная загрузка выгрузки меняет данные — ровно то, что исправлял `fix-component-config-roundtrip`.

## What Changes

- Импорт сначала ищет токен по имени ссылки (с правилами типографики без экрана).
- Значение, для которого токен не нашёлся, сохраняется литералом без записи в отчёт, только если это литерал CSS из явного списка: `transparent`, `inherit`, `initial`, `unset`, `currentColor`, `none`, `#…`, `rgb(…)`, `rgba(…)`, `hsl(…)`, `hsla(…)`.
- Остальные ненайденные значения, в том числе имена без точки, попадают в список ненайденных токенов.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `component-config-import`: требование «Литерал не считается ссылкой на токен» — литерал определяется явным списком и только после безуспешного поиска токена.

## Impact

- **backend-kt:** `ds-service/feature-components` — `TokenReferenceName.kt` (`isLiteralValue`), `ComponentConfigImporter` (порядок поиска токена и записи в отчёт); unit-тесты правил имени.
- **frontend-kt, js:** не меняются. Формат пакета и CLI `dsbuilder` прежние.
- **Данные:** миграций нет. Значения без точки, сохранённые литералом до исправления, при следующем `push` привяжутся к токену, если он есть.
