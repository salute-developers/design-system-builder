## Context

`fix-component-config-roundtrip` добавил `isLiteralValue`: значение без точки, `#…`, `rgb(…)`, `rgba(…)` не ищется как токен и не попадает в `unresolvedTokens`. Признак «нет точки» опирался на правило, что имя токена всегда из нескольких сегментов. Правило имени тени (`SizeTokenNaming.SHADOW_RULE`) допускает один сегмент.

## Goals / Non-Goals

**Goals:** ссылка на токен с именем без точки привязывается к токену; литералы CSS по-прежнему не попадают в отчёт.

**Non-Goals:** проверка значения литерала на корректность CSS; изменение экспорта.

## Decisions

- **Сначала поиск, потом литерал.** `tokenName` больше не отбрасывает литералы: каждое непустое текстовое значение токенного типа ищется по `referenceCandidates`. Если токен не найден, значение остаётся текстом (как и раньше), а в отчёт попадает, только если не литерал. Так имя токена всегда важнее похожести на литерал: токен с именем `transparent` тоже привяжется.
- **Явный список литералов** вместо «нет точки»: ключевые слова CSS `transparent`, `inherit`, `initial`, `unset`, `currentcolor`, `none` (без учёта регистра) и функции/запись цвета `#…`, `rgb(`, `rgba(`, `hsl(`, `hsla(`. Альтернатива — сохранить «нет точки» и исключить имена теней — отвергнута: правило имён тени живёт в `feature-themes` и может расшириться на другие типы.

## Risks / Trade-offs

- Литерал вне списка (например, `auto`) снова появится в `unresolvedTokens` пробного `push`. Это видно в отчёте и лечится расширением списка; круг экспорт → импорт на сидах это проверяет.
