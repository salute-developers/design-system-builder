## Context

`ProjectConfigStore` находит ближайший `.sdds/config.json`; общий `ContextResolver` использует его в CLI и MCP. `ApiKeyResolver` и `ApiUrlResolver` читают один `EnvironmentReader`, который сейчас обращается только к env процесса. У `dsbuilder-mcp` и `dsbuilder mcp serve` отдельные composition root, но общий application и credential flow. Codex может запускать MCP без переменных, заданных интерактивным `zsh`.

## Goals / Non-Goals

**Goals:**

- Дать CLI и обоим MCP launcher одинаковое чтение `.env` рядом с найденным `.sdds`.
- Сохранить приоритет явных аргументов и env процесса, существующие credential policies и отсутствие secrets в `.sdds` и MCP results.
- Не привязывать проектный `.env` к глобальному состоянию долгоживущего MCP процесса.

**Non-Goals:**

- Хранение project key в `.sdds/config.json` или в конфигурации Codex.
- Загрузка `.env` без локального project context, в том числе для `auth`, `init` и вызовов с явным `designSystem` URI.
- Экспорт значений `.env` в окружение процесса или дочерних toolchain процессов.
- Изменение backend API, user-session login, MCP транспорта или credential policy.

## Decisions

### Корень `.env` определяется найденной конфигурацией

Для локального context путь к `.env` вычисляется как sibling директории `.sdds` из resolved `configPath`; стартовая директория команды и `--workspace` участвуют только в поиске config. Вложенный `.env` или `.env` родительского проекта не подменяет файл проекта, выбранного ближайшим `.sdds/config.json`. При явном `designSystem` URI локальный `.env` не используется: URI не связан с локальным проектом. Альтернатива — искать `.env` вверх от `cwd` независимо от `.sdds` — может соединить context и secret разных проектов.

### Env разрешается в контексте одного запроса

Общий application слой получает project-scoped read-only источник значений после context resolution и перед credential/API URL resolution. Он возвращает значение env процесса, затем значение проектного `.env`; существующие `ApiKeyResolver`/`ApiUrlResolver` и политики используют этот источник без изменения глобального окружения. MCP перечитывает проектный источник на каждом вызове, а не закрепляет один проект при запуске сервера. Composition root CLI и Node MCP предоставляет платформенные операции с файлами/env; domain не зависит от файловой системы, presentation не парсит `.env`, di связывает порты. Альтернатива — загрузить `.env` в process env при старте — нарушает изоляцию между проектами и не работает для явного выбора context per call.

`--api-key` и `--api-url` остаются выше обоих env-источников. Для project key сохраняется выбор имени `credential.name` перед fallback `DSBUILDER_API_KEY`; для каждого имени env процесса выше `.env`. Отсутствующее или пустое значение не считается найденным. `user-session` не читает project key, а `auto` использует session только при отсутствии key. Backend rejection найденного key не запускает fallback на session.

### Узкий, безопасный формат `.env`

Общая Kotlin Multiplatform логика парсит UTF-8 строки `NAME=VALUE`, пустые строки, комментарии, необязательный `export`, одинарные и двойные кавычки; имена соответствуют `[A-Za-z_][A-Za-z0-9_]*`. Интерполяции, shell-команды и `source` не выполняются. Повторное имя внутри файла разрешается последним значением. Ошибка синтаксиса, чтения или кодировки найденного файла возвращает ошибку конфигурации без вывода значений; отсутствующий файл означает пустой fallback. Альтернатива — запуск shell или платформенные dotenv-библиотеки — даёт различия JVM/macOS/Node и риск исполнения содержимого.

### Secret остаётся внутри runtime

Парсер и resolver не логируют значения, не помещают их в DTO, ошибки или MCP stdout/stderr. Файл не создаётся автоматически. Документация показывает `.env.example` с фиктивными значениями и напоминает, что `.env` уже исключён `.gitignore`. Для локального файла рекомендуется ограничить права чтения владельцем; реализация не меняет права существующего файла.

## Risks / Trade-offs

- [MCP читает изменённый `.env` между вызовами] → читать при каждом разрешении локального контекста; один вызов использует единый снимок значений.
- [Проектный `.env` содержит неверный или просроченный key] → сохранять существующую политику: backend error возвращается как есть, без скрытого переключения на user session.
- [Синтаксис shell `.env` бывает шире принятого подмножества] → документировать формат и выдавать ошибку с номером строки без содержимого.
- [Пишущая команда получает API URL из `.env`] → считать его явной настройкой проекта, в отличие от code default, и сохранить защиту от записи по умолчанию.

## Migration Plan

Никакой миграции данных нет. Без `.env` поведение остаётся прежним. Пользователь может перенести project key из `.zshrc` в локальный `.env`; пока env процесса задан, он сохраняет приоритет. Откат — удалить `.env` или вернуть предыдущий бинарник; `.sdds/config.json` не меняется.

## Open Questions

Нет блокирующих вопросов. При реализации нужно проверить, что все project-scoped команды разрешают context до API URL/credential, а оба MCP launcher используют один и тот же scoped механизм.
