## Контекст

`AnalyticsConsent` сейчас подключён вне защищённых маршрутов и показывает собственную плавающую кнопку. Общий `busy` выключает только «Разрешить»: при отказе меняется вид соседнего действия. Серверные запросы по описанию пользователя корректны; визуальная причина пока установлена по коду, видео отсутствует.

## Решения

### Выбранное действие и состояния кнопок

Баннер использует кнопки действий, раздел «Общее» — тумблер; оба используют текущий общий клиент согласия. В баннере ожидание отображается на выбранной кнопке с понятным текстом; в настройках круговой индикатор расположен рядом с тумблером в зарезервированном месте, высота строки не меняется. На время сохранения тумблер недоступен. Не выбранная кнопка не получает оформление нажатия или индикатор загрузки. Недоступность действия обозначается отдельно от нажатия. В баннере отказ/отзыв остаётся доступен при ожидающем разрешении и немедленно выключает сбор; повторные нажатия одного ожидающего действия блокируются. Все кнопки имеют type=button, чтобы раздел в настройках не отправлял чужую форму. Используются существующие стили кнопок настроек; новых библиотек и слоёв нет.

### Настройки пользователя

В существующей странице /settings добавляется раздел «Общее»; аналитика представлена пунктом в строке на всю ширину области с коротким уведомлением слева и тумблером справа. Включение записывает granted, выключение — withdrawn; положение отражает подтверждённое разрешение или выполняемое сохранение grant; после ошибки отображается выключенное состояние, повторное включение повторяет тот же grant, сбор по-прежнему требует серверного подтверждения. При ошибке записи показывается сообщение, сбор выключен. Плавающая кнопка исчезает. При отключённой конфигурации пункт и секция аналитики скрыты; при включённой аналитике по умолчанию открывается «Общее»; при отключённой «Общее» скрыто и сразу открывается PAT. Локальный отказ пользователя не скрывает настройки при включённой конфигурации. На самой странице настроек отдельный автоматический баннер не дублирует секцию. При недоступном уведомлении управление показывает ошибку, явное повторное открытие секции/страницы позволяет повторить загрузку существующим review(); отдельной кнопки повтора нет. В остальных разделах ошибка начальной загрузки оставляет баннер скрытым и сбор выключенным.

### Граница авторизации

Поток веб-согласия запускается в авторизованной части приложения. На странице входа SDK не загружается, очередь просмотров не создаётся и проверка согласия автоматически не выполняется. После входа неизвестный выбор вызывает неблокирующий баннер после получения уведомления; сохранённое разрешение требует обычной проверки сервером. После выхода сбор прекращается и очередь очищается. Поздний ответ ранее начатой проверки не может включить сбор вне авторизованной части. Возврат после входа учитывает только текущий устойчивый экран.

Альтернатива — скрывать только баннер на /login — отклонена: при сохранённом разрешении это оставило бы сбор до входа. Выбор хранится в области аккаунта в данном браузере и окружении. Каждая пара использует отдельный случайный ключ согласия; выход не удаляет выбор, повторный вход в тот же аккаунт проверяет его на сервере. Другой аккаунт или браузер получает собственный контекст без разрешения. Backend и поведение CLI/MCP остаются прежними.

## Проверки и риски

Потеря аналитики страницы входа — сознательное следствие запроса после авторизации. При смене аккаунта используется его отдельный выбор в текущем браузере.

Автоматические тесты проверяют правильный исход запроса и индикатор выбранной кнопки в обоих местах, отсутствие плавающей кнопки, сохранность управления PAT, вход/выход, поздние ответы и отсутствие запросов Метрики вне авторизации. Браузерная проверка с замедленным ответом подтверждает визуальную реакцию отказа и разрешения, клавиатурный фокус и отсутствие случайной отправки формы. FAST и полный веб-набор выполняются без изменения baseline. Схема БД и миграции не меняются.




До первого выпуска уточняется исходная редакция web-v1 с точным текстом: «Разрешить отправку аналитики для улучшения DS Builder? Передаются просмотры разделов, cookies и технические данные браузера и устройства.» Пользователей с выпущенным согласованием ещё нет, поэтому web-v2 удаляется, миграция и специальный повторный сбор не вводятся. CLI/MCP остаются на своей редакции. Сервер возвращает версию и SHA-256 фактически показываемого текста.


## Исправления по ревью ПР

Store владеет порядком start/review и проверяет поколение после ожидания запуска; компонент настроек вызывает только review при активном разделе. Раздел не перемонтируется при навигации. Общий useActiveSettingsSection определяет выбор по URL для каркаса и страницы; «Общее» имеет отдельный id user-general, «Основное» сохраняет general. Цвета тумблера, его ползунка и прогресса используют переменные темы.

«Разрешить» заблокировано при любом сохранении, чтобы не запускать grant во время записи отказа. При ожидающем grant отказ/отзыв в баннере остаётся доступен согласно прежнему требованию немедленного локального запрета. Баннер по-прежнему скрыт на всех вкладках настроек. При отключённой конфигурации пункт аналитики отсутствует; техническая заглушка внутри компонента удалена. Правая колонка «Общего» намеренно остаётся пустой вместо стандартного пояснения для настроек сущности.


## Область согласия аккаунта в браузере

Локальное пространство включает идентификатор текущего аккаунта из сессии; в API истории по-прежнему передаётся только случайный ключ, а его хеш хранится в прежней таблице. Новых таблиц, операций API и серверной привязки к аккаунту нет. На другом устройстве выбор задаётся отдельно. Идентификатор аккаунта не добавляется в события Метрики. Прежний общий ключ браузера не читается и не переносится автоматически.

Ключ области фиксируется до ожидания блокировки. Запись из прежней сессии не может попасть в область нового аккаунта; поколение сессии блокирует старые ответы. Storage-события других аккаунтов игнорируются. При отсутствии идентификатора аккаунта нет анонимного отката: аналитика выключена.


## Повторное открытие и смена сессии между вкладками

Обработчик storage заменяет текущую область аккаунта, останавливает прежний сбор и запускает проверку нового аккаунта без перемонтирования границы. Подписка SDK использует актуальную область; старые ответы по-прежнему исключаются поколением и ключом области.

review различает уже видимую ошибку и ошибку загрузки, которую он только ожидает: последняя не вызывает второй GET в том же открытии. Явное повторное открытие позволяет восстановить allowed из успешного серверного подтверждения локального granted, только если нет ожидающей записи. Неопределённый POST не заменяется проверкой GET.
