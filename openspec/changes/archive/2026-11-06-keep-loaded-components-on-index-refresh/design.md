## Context

`ThemeEditorSession.loadComponent(component?)` читает данные через `EditorSectionData.loadComponent`:

- с именем — полные данные компонента (`editor-bundle`);
- без имени — только индекс (`loadComponentIndex`).

При чтении индекса `readComponents` строит записи из индекса и подставляет им закешированные `sources` из `this.snapshot`. Этот кеш обновляется только полным чтением раздела. Подтверждённые правки компонента в него не попадают.

Снимок уходит в `onSnapshot(next, tokensChanged, componentsChanged)`. Там `useDesignSystem.applySnapshot` при `componentsChanged` пересоздаёт все экземпляры через `createAllComponentInstances()`. Экземпляры с неподтверждёнными правками защищает только `preservePendingComponents`, и только пока статус источника автосохранения не `saved`.

Страница компонентов вызывает `loadComponent()` без имени при открытии и по каждому сигналу инвалидации `all`, `design-system`, `component-configurations`. Такой сигнал рассылает и `reload()`, который вызывается после каждого подтверждённого сохранения компонента.

## Goals / Non-Goals

**Goals:**
- Чтение индекса не возвращает на экран устаревшие данные открытого или ранее открытого компонента.
- Изменение состава компонентов (скрыт, возвращён, добавлен из шаблона) по-прежнему видно после чтения индекса.

**Non-Goals:**
- Обновлять кеш раздела подтверждёнными данными компонента.
- Менять порядок и число запросов перечитывания после сохранения.
- Плавающая отправка двух `PATCH` на одну правку, замеченная однажды при разборе: она не воспроизвелась. Если повторится, её стоит разбирать отдельно.

## Decisions

### Снимок индекса помечается и применяется слиянием

`onSnapshot` получает четвёртый аргумент `componentsScope: 'index' | 'full'`. `ThemeEditorSession.loadComponent` передаёт `'index'`, когда имя компонента не задано. Остальные пути передают `'full'`.

При `'index'` `applySnapshot` строит список так:

- если экземпляр компонента с тем же именем и платформой уже есть, он остаётся;
- новые компоненты берутся из снимка;
- компоненты, которых нет в индексе, уходят.

`preservePendingComponents` применяется поверх, как сейчас.

```ts
export function keepLoadedComponents(current: Config[] | null, next: Config[]): Config[];
```

Альтернатива — обновлять `sources` в кеше `EditorSectionData` при каждом подтверждении сохранения компонента. Отклонена: подтверждённое состояние компонента живёт в его `Config`, а не в DTO снимка. Пришлось бы сериализовать модель обратно и согласовывать с алиасами стилей.

Альтернатива — не вызывать `loadComponent()` на собственный сигнал после сохранения. Отклонена: тот же сигнал приходит и от SSE других пользователей, и чтение индекса там тоже нужно.

## Risks / Trade-offs

- **[Устаревший экземпляр при изменении извне]** Если компонент изменил другой пользователь, чтение индекса не обновит его данные. → Это и так делает полное чтение раздела, которое запускается тем же сигналом (`reload` → `activateSection`). Чтение индекса не было источником свежих данных компонента: оно отдавало кеш.

## План проверки и развёртывания

- Модульный тест `keepLoadedComponents`: прежние экземпляры остаются, новые добавляются, пропавшие уходят.
- Тест сессии: `loadComponent()` без имени сообщает `componentsScope: 'index'`.
- Ручная проверка: две правки цвета Accordion с интервалом 1,3 с. Поле не откатывается, итоговое значение верное.
