## MODIFIED Requirements

### Requirement: Редактор собирает модель выбранной темы

Веб-клиент SHALL загружать общие определения токенов и компонентные настройки дизайн-системы отдельно от значений
выбранного tenant и SHALL учитывать выбранную версию дизайн-системы. Компонентные настройки клиент SHALL собирать из
ответов ds-service и дополнять web-параметрами свойств, объявленными вариациями свойств, шаблонами web-параметров и
зависимостями компонентов обоих типов (`compose`, `reuse`) из `GET /ds/component-deps`;
клиент MUST NOT обращаться к `/ds/legacy/**` и MUST NOT публиковать версию дизайн-системы сам.

#### Scenario: Данные редактора загружены

- **WHEN** пользователь открывает существующий tenant без `versionId`
- **THEN** клиент MUST загрузить метаданные дизайн-системы, определения токенов и компонентные настройки активного
  черновика по `designSystemId`
- **THEN** клиент MUST загрузить метаданные tenant и значения токенов по `tenantId`
- **THEN** клиент MUST собрать объекты редактора только после проверки связи tenant с дизайн-системой

#### Scenario: Данные опубликованной версии загружены

- **WHEN** пользователь открывает tenant с `versionId` опубликованной версии
- **THEN** клиент MUST передать `versionId` всем предметным запросам данных дизайн-системы
- **THEN** клиент MUST показать редактор в режиме только для чтения
- **THEN** клиент MUST NOT отправлять изменяющие запросы

#### Scenario: У выбранного tenant отсутствует значение

- **WHEN** для общего определения токена отсутствует значение выбранного tenant на выбранной границе
- **THEN** клиент MUST показать контролируемое состояние неполных данных
- **THEN** клиент MUST NOT использовать значение другого tenant или другой версии

#### Scenario: Пользователь переключает темы

- **WHEN** пользователь переходит с одного `tenantId` на другой
- **THEN** клиент MUST дождаться либо сохранить сведения о неподтверждённых запросах прежнего tenant
- **THEN** клиент MUST сбросить вычисленное состояние прежней темы и отменить либо проигнорировать её устаревшие ответы
- **THEN** интерфейс MUST показывать только серверное состояние нового tenant

#### Scenario: Компонентные настройки дополнены для web-превью

- **WHEN** клиент загружает компоненты дизайн-системы для платформы `web`
- **THEN** у свойства в API компонента MUST быть web-параметры из `GET /ds/property-platform-params` в порядке базы,
  шаблон поправки из `POST /ds/component-config/web-adapter` и объявленный список вариаций из
  `GET /ds/property-variations`
- **THEN** свойство без web-параметра MUST остаться без web-маппинга
- **THEN** дополнительные запросы MUST передавать `versionId` выбранной версии, как остальные чтения редактора

#### Scenario: Связи reuse доходят до превью

- **WHEN** у компонента дизайн-системы есть связь `reuse` с другим компонентом этой дизайн-системы (AvatarGroup → Avatar)
- **THEN** модель родителя MUST содержать ребёнка в `deps` с типом `reuse`; связи обоих типов у одного родителя MUST идти
  по `order` (отсутствующий `order` считается `0`, как в web-адаптере), при равенстве — по имени ребёнка
- **AND** связь, у которой родитель или ребёнок не входит в дизайн-систему, MUST быть пропущена
