## Why

В редакторе темы DS Builder нет палитры: клиент берёт цвета из встроенной `@salutejs/plasma-colors`, а
цветовые токены ссылаются на неё строками `[general.red.500]`. Дизайнер не видит растяжки своей темы и не
может заменить или перестроить, например, акцентную растяжку, не перебирая вручную десятки токенов.
Прототип SDDS Portal (`kenymook/SDDS-Design-System`, `portal/apps/portal-flow-prototype`) задаёт целевое
поведение и целевой дизайн раздела «Палитра»: растяжки сгруппированы по назначению и редактируются
целиком или по ступеням без разрыва связей с семантическими токенами.

Серверная часть палитры темы появится в Kotlin `ds-service` отдельным изменением
`add-theme-palette-api`, и её могут влить позже клиента. Это изменение делает раздел в клиенте так,
чтобы он работал и до появления сервера, и после — без переделки экрана.

## What Changes

- В редакторе темы появляется раздел «Палитра» по маршруту
  `projects/:projectId/design-systems/:designSystemId/themes/:tenantId/palette` с кнопкой в панели
  разделов перед «Цветами».
- Палитра темы — независимая копия общей палитры-шаблона, сделанная при создании палитры темы: правки
  темы не меняют шаблон и другие темы, правки шаблона не меняют существующие темы.
- Принадлежность цветового токена к группе палитры задаётся явной привязкой по `id` группы и меняется
  пользователем в инспекторе палитры и в редакторе цветового токена. Правило по имени токена даёт только
  группу по умолчанию для токенов без привязки; в пользовательскую группу токен попадает только явно.
- Группы, включая системные, адресуются по UUID; системная группа дополнительно несёт `systemKey`.
- Раздел повторяет поведение прототипа: группы Neutral, Accent, Статус, Data, Syntax и пользовательские,
  режимы «Палитра» и «Цвет», поиск и фильтры «Все / Связанные / Изменённые», «Поменять» и «Изменить»
  (перестроить от опорного цвета) только в своей группе, правка ступени, добавление и удаление растяжки,
  создание и удаление группы, инспектор «Источник палитры» и «Связанные токены», признак «вне брендовой
  палитры», режим только для чтения.
- Вёрстка переносит целевой дизайн прототипа, закреплённого коммитом `bae288a`: разметка экрана палитры
  в `app.js`, правила `.source-palette-*` в `styles.css` и значения `builder-ui-tokens.css`. Готовность
  подтверждается сверкой скриншотов эталонных состояний.
- Данные палитры идут через порт `PaletteRepository` с двумя адаптерами:
  - `api` — HTTP-клиент контракта `add-theme-palette-api`;
  - `local` — временный источник в браузере: копия шаблона из `@salutejs/plasma-colors` и состояние
    палитры темы в `localStorage`, те же операции и та же семантика.
  Адаптер выбирается переменной `VITE_PALETTE_SOURCE`; до слияния сервера по умолчанию `local`.
- Превью цветовых токенов, превью компонентов и расчёт состояний вычисляют ссылки на палитру по палитре
  темы через единый резолвер вместо прямых вызовов `getRestoredColorFromPalette`.
- Вкладка Library в выборе цвета токена показывает растяжки палитры темы по группам.
- Чистая логика палитры (группа токена по умолчанию, вычисление ступени, перестройка, отображаемые имена) покрыта
  vitest-тестами на эталонных данных `palette-golden.json`; тот же файл проверяет сервер в
  `add-theme-palette-api`.

Вне изменения: серверная часть и доставка палитры в CLI (`add-theme-palette-api`); доставка в generator;
обновление палитры существующей темы до новой версии шаблона; отслеживание изменений палитры (Changes, счётчик и сброс правок, отмена и повтор, сравнение с
опубликованной версией); обмен с Figma; связь стартового профиля темы с группами палитры; глобальная
замена растяжки во всех группах.

## Порядок реализации

Работа идёт в два этапа, сначала фронт, потом бэк:

1. `add-theme-palette-editor` — клиент. Реализуется, проходит ревью и вливается первым; раздел работает
   с адаптером `local` и не зависит от сервера.
2. `add-theme-palette-api` — `ds-service` и CLI. Реализация начинается после слияния клиента и
   опирается на его контракт DTO и эталон `palette-golden.json`; последняя задача переключает клиент на
   адаптер `api`.

## Capabilities

### New Capabilities

- `theme-palette-editor`: раздел «Палитра» темы в клиенте, источники данных палитры, вычисление цветов
  токенов по палитре темы и вкладка Library выбора цвета.

### Modified Capabilities

- Нет.

## Impact

- `js/apps/client`:
  - новый модуль `src/modules/palette/{domain,application,data}` и эталон `palette-golden.json`;
  - страница `src/pages/palette/*`, стили `src/styles/palette.css`;
  - `App.tsx` (маршрут), `pages/Main.tsx` (кнопка раздела, контекст палитры);
  - `src/palette/*` (активная палитра для резолвера цветов, сессия адаптера `local`, запись правок
    ссылок в черновик при удалении растяжки);
  - замена `getRestoredColorFromPalette` в местах отображения цветов токенов, `features/ColorPicker`
    (Library), `hooks/useDesignSystem.ts`, `pages/colors` (переход к токену из инспектора, группа
    токена в редакторе цвета), `api/themeEditorRepository.ts` (сохранение прозрачности ссылки при
    загрузке);
  - переменная окружения `VITE_PALETTE_SOURCE` (описана в `README.md` клиента и `js/docker-compose.dev.yml`).
- `js/eslint.config.js`: запрет прямого импорта `getRestoredColorFromPalette` в клиенте.
- `backend-kt`, `frontend-kt`, `js/services/*`: изменений нет.
