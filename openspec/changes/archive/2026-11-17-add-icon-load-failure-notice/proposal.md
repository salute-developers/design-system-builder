## Why

Файлы иконок лежат в S3, и клиент читает их напрямую из браузера. Один файл может не загрузиться (удалён, не прошёл CORS, временная ошибка хранилища), а остальные при этом доступны. Сейчас `IconMask` молча подменяет такую иконку пунктирной заглушкой: пользователь не понимает, что случилось, особенно в пикере, где выбранная иконка выглядит «пустой».

## What Changes

- Клиент запоминает адреса SVG, которые не загрузились, и делится этим состоянием между плитками каталога, миниатюрой пикера и панелью сведений.
- В каталоге на месте незагруженной иконки остаётся заглушка, но с доступным названием («Не удалось загрузить иконку»); остальные плитки не затрагиваются.
- В пикере иконки при выборе иконки, SVG которой не загрузился, под полем появляется уведомление в стиле остальных блоков инспектора. Значение при этом сохраняется как обычно: иконка есть в каталоге, не загрузился только файл.
- Уведомление показывается и для уже сохранённого значения, если файл его иконки не загрузился, и исчезает, когда выбрана другая иконка или файл загрузился.
- На странице каталога панель сведений показывает сообщение о незагруженном файле для выбранной иконки.

Не входит: уведомления в превью Compose (предупреждения плагина остаются в консоли), общий механизм toast, повторная загрузка по кнопке, изменения бэкенда и CLI.

- `backend-kt` и `frontend-kt` не затрагиваются; API и конфигурация не меняются.
