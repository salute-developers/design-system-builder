## Context

Имя конфигурации (`appearances.name`) уникально в паре (дизайн-система, компонент) без учёта регистра. Его проверяет
`AppearanceNaming.requireFree` (пустое и длина ≤ 255, занятость) в редакторских создании и дублировании; простые
`POST /appearances` и `PATCH /appearances/{id}` проверяют только длину. Генерация — `AppearanceNaming.freeName`:
`<Компонент>` для первой, `<Компонент> new` для новой, `<имя> copy` для копии, суффикс ` 2`. Импорт пакетов берёт
`styleName` как есть. Все имена в локальных данных, кроме созданных редактором, — kebab-case; у web-конфигураций —
одно слово (`default`, `clear`), у Compose — с префиксом компонента (`accordion-clear-action-end`).

Web-генератор (`js/cli/src/generator/creators/createComponent.ts`) подставляет имя в `Accordion.<имя>.config.ts`,
`<имя>Config`, `merged<Имя>Config`, `<Компонент><Имя>` и ключ объекта `createConditionalComponent`.

## Goals / Non-Goals

**Goals:**
- Новые имена конфигураций — только kebab-case, на всех путях записи.
- Web-генератор корректно обрабатывает любое kebab-case имя.

**Non-Goals:**
- Автоматическое переименование существующих конфигураций и миграция данных.
- Нормализация произвольных имён в генераторе и в выгрузке: выгрузку по имени сопоставляет `components push`, а угадывание
  в генераторе разошлось бы с другими платформами.
- Правила имён вариаций и стилей.

## Decisions

1. **Правило:** `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`, длина до 255. Дефис разрешён: без него не импортировались бы пакеты
   Compose. Проверка — в `AppearanceNaming.requireName`, её вызывают `requireFree`, простые `POST`/`PATCH` и импорт.
   Код ошибки — существующий `appearance_name_invalid` (`422`). Само правило — в домене (`ConfigurationName`), его
   используют и `AppearanceNaming`, и маршруты, и импорт.
2. **Генерация имён:** первая — `kebab(componentName)` (`TextField` → `text-field`), новая — `new`, копия —
   `<основа>-copy`; занятое — `-2`, `-3`. Основа копии — `kebab(имя источника)`: старые имена не по правилу не переносят
   пробелы в копию. Требование «имя первой конфигурации совпадает с именем компонента» меняется на kebab-форму; признак
   конфигурации по умолчанию — `isDefault`, а не имя, поэтому на выбор по умолчанию это не влияет.
3. **Импорт:** запись, которая создала бы конфигурацию с именем не по правилу, попадает в `rejected` отчёта с причиной
   `appearance_name_invalid`, остальные записи импортируются. Запись для уже существующей конфигурации со старым именем
   обновляет её: иначе перестали бы импортироваться старые данные.
4. **Редактор:** поле имени приводит ввод к нижнему регистру, пробелы и `_` заменяет дефисом, остальные недопустимые
   символы не пропускает; пустое и не по правилу имя не отправляется, подсказка показывает правило.
5. **Web-генератор:** `appearanceIdentifier(name)` — camelCase из kebab-case (`clear-action` → `clearAction`); файл —
   `<Компонент>.<camelCase>.config.ts` (у `default` — прежний `<Компонент>.config.ts`), переменные и экспорт — от
   camelCase, ключ объекта — `'<имя>'` строкой. Однословные имена дают прежний код. Имя не по правилу —
   ошибка генерации с компонентом и именем.

## Risks / Trade-offs

- [Изменились имена, которые сервер даёт новой конфигурации и копии] → затрагивает только новые сущности.
- [На проде могут быть конфигурации с именами не по правилу] → их web-генерация падает с понятной ошибкой до ручного
  переименования; проверка имён на стенде — отдельный шаг перед выкладкой.
