## Why

Пакет компонентов, выгруженный `dsbuilder components fetch` и загруженный обратно `dsbuilder components push` без правок, меняет данные дизайн-системы. На локальной `base` пробная загрузка своей же выгрузки даёт `Updated: 68` из 111 конфигураций и 48 «ненайденных» ссылок на токены, на DEV — то же самое.

Причина — несимметричные имена токенов типографики. Экспорт (`ComponentConfigBuilder` → `referenceName`) пишет ссылку на стиль типографики без экрана: токен `screen-s.body.l.bold` уходит как `body.l.bold`. Импорт ищет токен по точному имени, не находит его и сохраняет значение текстом вместо привязки к токену. Компонент теряет связь со стилем типографики: правки токена его больше не затрагивают.

Вторая, безвредная часть: литералы цвета (`transparent`, `#F3A912`, `rgba(…)`, `inherit`) импорт тоже ищет как токены. Сохраняются они правильно, но попадают в отчёт как ненайденные ссылки и прячут настоящие ошибки.

Третья причина нашлась при проверке исправления: корневая вариация. Спека `component-appearance-model` требует, чтобы при отсутствии `rootVariationId` сервис выбирал корень по правилу фолбэка (ось `size`, иначе первая) и сохранял его. Импорт так и делает, а создание дизайн-системы из сидов (`GeneratedDesignSystemComponentInitializer`) сохраняет корень пустым. Выгрузка честно пишет `rootVariationId: null`, а загрузка назначает `size` — это было 93 из 104 `updated` на чистой дизайн-системе из сидов.

Остальные расхождения нашлись тем же способом — загрузкой выгрузки дизайн-системы, созданной из сидов:
- создание из сидов пишет всем значениям позицию `0`, а импорт нумерует значения состояний `1`, `2`, …;
- числовое смещение значения (например, `-2` для `round.l` у `Button.shape`) сиды держат только в поправке web-параметра, а импорт пишет его в колонку `adjustment` значения;
- в сидах `Badge` два набора стилей, отличающиеся регистром (`Accent`/`accent`, `M`/`m`, `Pilled`): импорт сравнивает имена без учёта регистра и склеивает их, теряя значения.

Без исправления `push` нельзя использовать для правок существующей дизайн-системы, в том числе для очистки значений свойств без web-параметров на DEV.

## What Changes

- Импорт конфигураций привязывает ссылку на стиль типографики без экрана (`body.l.bold`) к токену `screen-s` того же стиля (`screen-s.body.l.bold`) — по тому же правилу, по которому экспорт отбрасывает экран и по которому редактор типографики привязывает ссылки. Ссылка с экраном привязывается к токену этого экрана.
- Значения, которые не являются именем токена (нет точки-разделителя: `transparent`, `inherit`; цвета `#…`, `rgb(…)`, `rgba(…)`), импорт сохраняет литералом и не включает в список ненайденных токенов.
- Создание дизайн-системы из сидов пишет позиции значений и числовое смещение так же, как импорт: база — `0`, состояния — `1…n` в порядке сидов; смещение из числовой web-поправки — в колонку `adjustment`.
- Стили `Badge` в сидах приведены к строчным именам, как у остальных компонентов; дубли с другим регистром удалены.
- Создание дизайн-системы из сидов назначает корневую вариацию по тому же правилу фолбэка, что импорт и ручки осей.
- Повторная загрузка неизменённой выгрузки не меняет конфигурации: `Updated: 0`, ненайденных токенов нет.

## Capabilities

### New Capabilities

- `component-config-import`: правила разрешения ссылок на токены при импорте конфигураций компонентов и симметричность экспорта и импорта.

### Modified Capabilities

Нет.

## Impact

- **backend-kt:** `ds-service/feature-components` — `ComponentConfigImporter` (разрешение токена), общий помощник имён рядом с `TokenReferenceName`, `GeneratedDesignSystemComponentInitializer` (корень по фолбэку, позиции, смещение), `component-seeds.json` (`Badge`) и `app/contracts/resources.sha256.json`; `ds-service/feature-themes` — `ExposedSizeTokenUsageRepository` (параметр использования производного радиуса); unit-тесты и HTTP-тест на Postgres «экспорт → импорт без изменений».
- **frontend-kt, js:** не затрагиваются. CLI отправляет пакет как есть.
- **Данные:** уже испорченных значений нет — никто не применял `push` к существующим дизайн-системам. У дизайн-систем, созданных до исправления, корень остаётся пустым, пока его не назначит импорт или ручка осей; их первая загрузка покажет `updated` по корню, и это ожидаемо.
