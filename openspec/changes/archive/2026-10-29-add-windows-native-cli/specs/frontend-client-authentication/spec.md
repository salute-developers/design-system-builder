# Spec Delta

## ADDED Requirements

### Requirement: Пользовательская авторизация нативного CLI на Windows

`dsbuilder.exe` SHALL выполнять существующий сценарий Authorization Code + PKCE S256 через системный браузер и локальный callback на Windows x64 без Java или Node.js.

#### Scenario: Успешный вход

- **WHEN** пользователь запускает `dsbuilder.exe auth login` на Windows
- **THEN** CLI MUST открыть системный браузер, принять callback только на `127.0.0.1`, проверить `state` и обменять код на токены
- **THEN** CLI MUST использовать тот же OAuth clientId и ту же страницу результата, что и другие средства запуска

#### Scenario: Отмена или ошибочный callback

- **WHEN** вход отменён, истёк лимит времени либо callback содержит ошибку или неверный `state`
- **THEN** локальный listener MUST закрыться
- **THEN** новая сессия MUST NOT быть сохранена

### Requirement: Защищённая сессия Windows

Нативный CLI Windows SHALL использовать общий формат `~/.sdds/sessions` и межпроцессную блокировку обновления сессии; файл с refresh token SHALL быть доступен текущему пользователю и системным администраторам.

#### Scenario: Сохранение и чтение сессии

- **WHEN** вход или обновление токена завершается успешно
- **THEN** файл MUST сохранять тот же набор полей и вычисление имени, что и другие CLI/MCP средства запуска
- **THEN** замена файла MUST быть атомарной, а права доступа MUST исключать чтение другими обычными пользователями

#### Scenario: Одновременное обновление

- **WHEN** нативный CLI и `dsbuilder-mcp` одновременно обновляют одну сессию на Windows
- **THEN** только один процесс MUST владеть блокировкой до атомарной записи
- **THEN** ожидающий процесс MUST повторно прочитать сессию после освобождения блокировки
