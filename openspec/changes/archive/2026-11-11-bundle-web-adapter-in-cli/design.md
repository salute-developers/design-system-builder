## Контекст

Генератор web-пакета (`js/cli`, `generate:components` и `generate:ds`) собирает модель из трёх источников: конфигураций компонентов из `<sdds>/components`, web-маппингов из аннотаций установленного `@salutejs/plasma-new-hope` и `web-adapter.json`. Сейчас `web-adapter.json` (имена, описания, шаблоны многозначных web-параметров по стилям и `compose`-связи) читается из `<sdds>/web`, куда его кладёт `dsbuilder components fetch` из ручки `POST /ds/component-config/web-adapter`, а шаблоны там вычисляются из поправок значений в базе.

Web-плагин превью уже держит копию этого файла в бандле (`js/apps/preview-web-plugin/src/data/web-adapter.json`). Шаблоны в базе решено не развивать и позже удалить. У новых компонентов их туда не занести: `components push` шаблоны не передаёт, а `import:plasma` пишет их только в `webTemplates` манифеста генератора, который генератор не читает.

## Цели / Вне целей

**Цели:**
- Генератор берёт `web-adapter.json` из файла в `js/cli`, одинаково при запуске из репозитория и из установленного npm-пакета.
- Копии CLI и плагина совпадают, и это проверяется тестом.
- Шаблоны новых web-компонентов (Attach, Autocomplete, Calendar, CalendarDouble, DatePicker, DateTimePicker, InformationWrapper, Table, TextFieldSlider, TimePicker, Tree) доходят до пакета без базы.
- Стиль без поля `props` в выгрузке не роняет генерацию.

**Вне целей:**
- Общий модуль CLI и плагина вместо двух копий — отдельная задача о переиспользуемых механизмах.
- Автоматическая запись шаблонов из `import:plasma` в `web-adapter.json`: пока перенос ручной, при необходимости вернём.
- Удаление шаблонов, поправок и ручки `web-adapter` из `ds-service`, изменения `dsbuilder components fetch` во `frontend-kt`.
- Клиент редактора, который получает шаблоны из той же ручки базы.

## Решения

### Файл лежит в `js/cli/src/data/web-adapter.json`

Путь повторяет расположение копии в плагине. Каталог `src` уже входит в `files` публикуемого пакета, поэтому отдельная настройка публикации не нужна; путь вычисляется от каталога CLI (`cliDirectory`), как уже делается для поиска установленного ядра.

Альтернативы: оставить чтение `<sdds>/web` и вручную дописывать туда шаблоны — отвергнуто, файл перезаписывается каждым `components fetch` из базы; читать копию прямо из каталога плагина — отвергнуто, её нет в опубликованном пакете генератора.

### Явный `--web` сохраняется как подмена

`--web <каталог>` по-прежнему указывает каталог с `web-adapter.json`, но без флага используется встроенный файл, а не `<sdds>/web`. Так локальная генерация не зависит от состояния шаблонов в базе, а для отладки остаётся способ подложить другой адаптер.

### Совпадение копий проверяет тест `js/cli`

Тест сравнивает содержимое двух файлов побайтно. Тестовые файлы не публикуются, поэтому ссылка на соседний каталог плагина в тесте допустима. Синхронизацию копий скриптом не вводим: дублирование временное, а тест достаточно громко ловит расхождение.

### Записи новых компонентов

В обе копии добавляются записи 23 компонентов, заведённых в базовую ДС: `componentName` в написании `meta.json`, `name` в написании кода и `description` как у остальных записей. Шаблоны 11 из них переносятся из `webTemplates` манифестов `import:plasma` в `styles.default.templates` (у этих компонентов один appearance `default`). Записи упорядочены по `componentName`, как отдаёт ручка базы.

### `webTemplates` убирается из манифестов

Поле появилось как временное место для шаблонов до доработки генератора, которой не было: генератор его не читает. С файлом в CLI это второй источник тех же данных, поэтому поле удаляется из 11 манифестов и из `import:plasma`. Импорт печатает шаблоны в отчёте фрагментом записи `web-adapter.json`, который переносится в обе копии вручную.

Альтернатива — дописывать шаблоны в обе копии из `import:plasma` автоматически — отложена: ручной перенос проще, а запись в файлы плагина из инструмента импорта можно добавить позже.

### Стиль без `props`

Чтение конфигурации считает отсутствующее `props` стиля пустым набором значений. Такой стиль генератор получает как обычный стиль без значений.

## Риски / Компромиссы

- [Копии расходятся при ручной правке одной из них] → тест `js/cli` падает; в скилле `add-component` фиксируется правило дописывать обе копии.
- [Имена, описания и `compose`, изменённые в базе, больше не попадают в локальный пакет] → такие изменения вносятся в `web-adapter.json`; для старого поведения есть `--web .sdds/web`.
- [Встроенный файл отстаёт от базы, где у старых компонентов ещё есть шаблоны] → исходная копия плагина собрана из той же выгрузки; расхождения проверяются генерацией пакета базовой ДС перед публикацией.
