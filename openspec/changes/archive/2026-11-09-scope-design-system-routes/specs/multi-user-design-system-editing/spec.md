## MODIFIED Requirements

### Requirement: Небезопасные повторные запросы имеют устойчивый результат

API SHALL принимать ключ повторяемости для мутаций `POST`, `PUT`, `PATCH`, `DELETE`, включая импорт,
публикацию и откат. Чтения `GET`, `HEAD`, `OPTIONS` SHALL NOT создавать результаты повторяемых команд. Для системной команды дизайн-система из пути SHALL учитываться при сопоставлении операции; остальные правила повторяемости SHALL сохраняться.

#### Scenario: Повторяется тот же запрос

- **WHEN** проект, ключ, операция и хэш тела совпадают с завершённым запросом
- **THEN** API MUST вернуть ранее сохранённые статус, тело и технические метаданные ответа без повторного предметного изменения
- **THEN** повтор MUST NOT создавать новые предметные редакции, отметки или уведомления

#### Scenario: Ключ повторён с другим телом

- **WHEN** тот же проект и ключ используются с другим хэшем тела
- **THEN** API MUST отклонить повтор без выполнения предметной операции

#### Scenario: В прежнем результате нет сохранённых метаданных

- **WHEN** повторяется результат, сохранённый до добавления технических метаданных
- **THEN** API MUST вернуть сохранённые статус и тело, не выполняя команду заново
- **THEN** API MUST явно сообщить о необходимости сверки через `X-DS-Mutation-Metadata-Truncated: true`

#### Scenario: Чтение содержит ключ повторяемости

- **WHEN** клиент читает данные через `GET`, `HEAD` или `OPTIONS` с `Idempotency-Key`
- **THEN** API MUST NOT сохранять результат этого чтения в таблицу повторяемых команд

#### Scenario: Ключ повторён в другой системе

- **WHEN** тот же проект и ключ используются для системы B вместо A при одинаковых остальных данных команды
- **THEN** API MUST обработать различие системы существующим конфликтом `409 IDEMPOTENCY_KEY_REUSED`, не возвращая ответ A и не выполняя команду B

#### Scenario: Повтор удаления самой дизайн-системы

- **WHEN** успешный `DELETE /api/projects/{projectId}/design-systems/{designSystemId}` с ключом повторяемости уже удалил систему и клиент повторяет тот же запрос
- **THEN** API MUST сохранить существующую проектную авторизацию и проверку разрешения операции, сопоставить сохранённый результат с той же командой и системой пути и вернуть исходные статус, тело и технические метаданные
- **AND** отсутствие удалённой системы MUST NOT превращать сопоставленный повтор в `404`; повтор MUST NOT создавать новые предметные изменения, отметки или события

#### Scenario: Новая команда к удалённой системе

- **WHEN** система отсутствует и поиск результата по ключу вернул `IdempotentRequestLookup.New` — записи по этому ключу в проекте нет
- **THEN** API MUST проверить доступность системы перед новым предметным выполнением и вернуть `404` без новой записи или результата команды

#### Scenario: Конфликт ключа при удалённой системе

- **WHEN** система A уже удалена, а ключ запроса занят результатом другой команды или системы (`IdempotentRequestLookup.PayloadMismatch`)
- **THEN** API MUST вернуть `409 IDEMPOTENCY_KEY_REUSED` до проверки существования системы A, не заменяя конфликт на `404`
- **AND** API MUST NOT выполнять новую команду или возвращать сохранённое тело несовпадающей команды
