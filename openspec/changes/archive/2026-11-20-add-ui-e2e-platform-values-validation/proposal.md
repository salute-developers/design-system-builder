# Платформенные значения, слои и валидация UI E2E

## Причина

Первые три этапа покрывают основной ввод, роли, связи палитры и изоляцию тем, но не закрепляют платформенные радиусы и слои теней, независимость начертаний и границы числового ввода. Четвёртая группа ROADMAP содержит десять соответствующих Jira-кейсов.

## Изменения

- Добавить T800, T754, T696, T751, T700, T702, T703, T704, T738 и T739 в существующий набор Playwright.
- Проверять изменения через UI, затем независимым API-чтением и повторным открытием; для невалидного ввода сохранять исходные значения и ревизии.
- Подготавливать отдельную ДС каждого теста через публичные API и переиспользовать FIX-BASE/RSS-BASE, текущие страницы и контроль мутаций.
- Исследовать нужные взаимодействия Playwright до написания сценариев. Выполнить только десять новых E2E; при блокере остановиться, небольшие дефекты исправлять в пределах согласованного поведения.

## Возможности

### Новые возможности

- `web-ui-e2e-platform-values-validation`: регресс платформенных радиусов и теней, начертаний типографики и границ числового ввода.

### Изменяемые возможности

Нет.

## Влияние

Основной объём — `js/apps/client/tests` и OpenSpec. Новых зависимостей и изменений API, схемы данных, CLI, `backend-kt` или `frontend-kt` не требуется. Небольшое подтверждённое отклонение UI от действующего контракта можно исправить в клиенте с целевой проверкой; изменение продуктового контракта требует отдельного решения пользователя. Коммит, push и запуск прежних сорока E2E в эту задачу не входят.
