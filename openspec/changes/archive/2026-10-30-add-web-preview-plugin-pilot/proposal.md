## Why

Web-превью компонентов рисуется прямо в клиенте. Story, правила отображения значений редактора в CSS-переменные ядра plasma (`coreTokens.ts`) и версия `@salutejs/plasma-new-hope` вшиты в сборку DS Builder. Из-за этого любое обновление библиотеки или story требует пересобрать клиент, а знание о конкретной библиотеке живёт не рядом с ней.

Compose-превью уже устроено иначе: плагин в `iframe` получает payload по Preview Protocol и сам знает свою библиотеку. Пилот проверяет тот же подход для Web на одном компоненте, `Button`. Нужно убедиться, что хост, протокол и story-модель годятся для web до того, как переносить остальные компоненты и строить публикацию.

> Формат payload `WEB` из этого изменения (CSS-строки, корневое поле `web`) и запасное React-превью заменены изменением `unify-web-preview-payload`.

## What Changes

- **Новое приложение `js/apps/preview-web-plugin`.** Web-плагин превью: React и `@salutejs/plasma-new-hope` в собственном бандле, `preview-plugin.json` с платформой `web` и списком компонентов `["Button"]`, мост `postMessage` по сообщениям `sdds.preview.*`, как у Compose-плагина. Плагин содержит:
  - story `Button`, перенесённую из клиента;
  - отображение web-параметров в CSS-переменные ядра для `Button`;
  - ответ на `describe` по аргументам story.
- **Payload для платформы `WEB` без изменения JSON-схемы.**
  - `component.properties` — web-параметры компонента со значениями CSS из выбранных стилей и инвариантов;
  - `component.variations` — имена выбранных стилей;
  - `example` — story и её аргументы;
  - CSS-переменные темы и шрифт — в корневом поле `web`, разрешённом схемой.
  - Семантика описана в README контракта, добавлена валидная фикстура.
- **Хост в клиенте понимает две платформы:**
  - манифест с `platform: "web"`;
  - без Wasm-проверок для web;
  - отдельный адрес web-плагина.

  Web `Button` рисуется плагином, если адрес задан и манифест перечисляет `Button`, иначе — React-превью, как сейчас. В debug-режиме есть переключатель «React | Плагин» для сравнения.
- **Локальная раздача.** Dev-сервер плагина на отдельном порту, то есть отдельном origin, адрес по умолчанию в `js/docker-compose.dev.yml`.
- Story `Button` в клиенте остаётся запасным React-превью до публикации web-плагина через бэкенд.

## Capabilities

### New Capabilities

- `web-preview-plugin`: web-плагин превью — манифест, мост сообщений, реестр компонентов, отрисовка `Button` по payload, ответ на `describe`, локальная раздача.

### Modified Capabilities

- `compose-preview-rollout`: условие включения превью-плагина распространяется на web-компоненты при заданном адресе web-плагина. React-превью остаётся запасным.
- `compose-preview-plugin-loading`: проверка манифеста принимает платформу, совпадающую с платформой компонента (`compose` или `web`).

## Impact

- **js:**
  - новое приложение `js/apps/preview-web-plugin` (`package.json`, Vite, тесты);
  - `js/apps/client/src/composePreview` — платформа в типах, манифесте, проверке окружения, адресе плагина и хосте; сборка web-payload;
  - `ComponentEditorPreview` — выбор рендерера для web;
  - `js/docker-compose.dev.yml` — сервис или адрес web-плагина;
  - README клиента.
- **backend-kt:** только `backend-kt/preview/contract` — README с семантикой `WEB` и валидная фикстура. Схема не меняется, поэтому копия в plasma-android не затрагивается. ds-service, gateway и публикация не меняются.
- **frontend-kt** не затрагивается.
- **Вне скоупа:**
  - публикация web-плагина через ds-service, S3 и CLI;
  - остальные компоненты;
  - удаление `useStory`, `src/stories` и `coreTokens.ts` из клиента;
  - полная web-семантика протокола: токены темы с единицами, типографика, тени, градиенты, шрифты как ассеты, состояния через `states`.
