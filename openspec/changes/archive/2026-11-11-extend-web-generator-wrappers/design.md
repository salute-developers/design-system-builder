## Контекст

Генератор web-пакета (`js/cli`) выбирает обёртку компонента по данным ДС и манифесту `templates/<X>/component.json`, а корневой `src/index.ts` собирает по папкам компонентов и теме. Три экспорта sdds-serv в эту схему не ложатся: `SSRProvider` (реэкспорт ядра, в ДС не заводится из-за необратимого имени), `ViewContainer` (стили берут наборы переменных `viewContainer` из темы) и `Select` с appearance `clear` (дженерик-обёртка собирается только из конфига `default`, хотя `configs.length > 1`).

## Цели / Вне целей

**Цели:**
- Пакет экспортирует `SSRProvider`, `ViewContainer` (в пакете с темой) и `Select` с выбором appearance так же, как sdds-serv.
- Решения записаны в генераторе и манифестах, без ручных правок сгенерированного кода.

**Вне целей:**
- Общий механизм зависимостей компонента от темы, кроме признака в манифесте.
- Превью ViewContainer, точно совпадающее с пакетом: story плагина строит наборы переменных по тому же правилу, что генератор темы, из переменных, которые плагин кладёт на сцену.

## Решения

### Реэкспорт ядра — список в генераторе

Список `CORE_REEXPORTS = ['SSRProvider']` живёт рядом с записью корневого индекса (`package-output.ts`) и дописывается в `src/index.ts`, когда в пакете есть компоненты. Альтернативы: реэкспорт из манифеста постороннего компонента (Portal) — отвергнуто как неочевидная связь; заводить `SSRProvider` в ДС — невозможно без изменения правила имён на бэкенде.

### `requiresTheme` в манифесте

Признак в манифесте — тот же источник правды, что `castToProps` и `generic`. Генерация знает, будет ли тема в пакете: `generate:ds` пишет тему всегда, `generate:components --package` — никогда, `generate:components` без `--package` сохраняет существующую `src/theme`. Компонент с признаком в пакете без темы пропускается с предупреждением, а не роняет сборку: пакет только с компонентами по-прежнему собирается. Альтернатива — обёртка ViewContainer без `onDark`/`onLight` — отвергнута: компонент без своего назначения хуже, чем его отсутствие с понятным предупреждением.

### Шаблон ViewContainer

`templates/ViewContainer/ViewContainer.ts` импортирует `viewContainer` из `../../theme` и строит конфиг `variations.view.onDark/onLight` через `css` ядра, как sdds-serv из `sdds-themes`. В ДС компонент заводится пустым: стили вида в данных не выражаются, их даёт тема. Вариация `view` со стилями без значений не подходит: генератор записал бы для неё конфиг темы с импортом несуществующего `viewContainerTokens`. Пустой компонент получает обёртку, которую перекрывает шаблон, как у Mask.

### Дженерик с несколькими appearance

`createGenericComponent` получает имена appearance. При одном appearance результат прежний. При нескольких обёртка повторяет `Select.tsx` sdds-serv: компонент на каждый appearance (идентификаторы и файлы — через `appearanceIdentifier`/`appearanceConfigFile`, как в условной обёртке), `createConditionalComponent`, тип пропсов с `appearance?: '<имена>'`, `fixedForwardRef` с параметром типа элемента.

## Риски / Компромиссы

- [Пакет без темы молча теряет компонент] → предупреждение с именем компонента в выводе генерации.
- [Список реэкспортов ядра разойдётся с sdds-serv] → в список входят только компоненты без конфига темы; новые добавляются по тому же правилу и отражаются в скилле `add-component`.
