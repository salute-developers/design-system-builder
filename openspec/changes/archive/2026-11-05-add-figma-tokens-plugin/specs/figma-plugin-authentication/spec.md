## ADDED Requirements

### Requirement: Вход через подтверждение в браузере

Плагин SHALL входить в DS Builder через OAuth Device Authorization Grant клиентом `dsbuilder-figma-plugin`. Плагин MUST NOT запрашивать логин и пароль в своём окне.

#### Scenario: Успешный вход

- **WHEN** пользователь нажимает «Войти»
- **THEN** плагин MUST запросить код устройства через публичный gateway и открыть `verification_uri_complete` во внешнем браузере
- **THEN** плагин MUST показать `user_code`, чтобы пользователь сверил его в браузере, и действие «Открыть снова»
- **THEN** после подтверждения в браузере плагин MUST получить токены и перейти к выбору контекста

#### Scenario: Ожидание и замедление опроса

- **WHEN** token endpoint отвечает `authorization_pending`
- **THEN** плагин MUST повторить запрос не чаще `interval` из ответа устройства
- **WHEN** token endpoint отвечает `slow_down`
- **THEN** плагин MUST увеличить интервал на 5 секунд

#### Scenario: Вход не завершён

- **WHEN** token endpoint отвечает `expired_token` или `access_denied`
- **THEN** плагин MUST прекратить опрос и показать причину и действие «Войти снова»
- **WHEN** пользователь нажимает «Отмена» или закрывает плагин во время ожидания
- **THEN** плагин MUST прекратить опрос
- **WHEN** token endpoint отвечает `not_allowed`
- **THEN** плагин MUST прекратить опрос и сообщить, что пользователю нужно обратиться к администратору

### Requirement: Хранение сессии

Плагин SHALL запрашивать `offline_access`, чтобы сессия переживала перерывы в работе. Refresh token SHALL храниться в `figma.clientStorage` и записываться только основным потоком плагина. Access token SHALL храниться только в памяти окна плагина. Токены MUST NOT попадать в журнал, адрес запроса или `figma.root` и другие данные файла.

#### Scenario: Повторный запуск

- **WHEN** пользователь запускает плагин, а refresh token сохранён
- **THEN** плагин MUST обновить access token без открытия браузера и перейти к выбору контекста

#### Scenario: Запуск после перерыва

- **WHEN** пользователь запускает плагин позже срока обычной сессии, но в пределах срока простоя офлайн-сессии
- **THEN** плагин MUST войти без открытия браузера

#### Scenario: Refresh token недействителен

- **WHEN** token endpoint отвечает на обновление `invalid_grant` или `not_allowed`
- **THEN** плагин MUST удалить сохранённый токен и показать экран входа

#### Scenario: Сервер недоступен при обновлении

- **WHEN** обновление завершается сетевой ошибкой или ответом `5xx`
- **THEN** плагин MUST сохранить refresh token и показать ошибку с действием «Повторить»

### Requirement: Обновление при истечении токена

Запрос к API, получивший `401`, SHALL один раз обновить access token и один раз повториться. Одновременные запросы MUST использовать одно обновление.

#### Scenario: Истёкший access token

- **WHEN** запрос получает `401`, а обновление успешно
- **THEN** плагин MUST повторить запрос с новым access token
- **WHEN** повторный запрос снова получает `401`
- **THEN** плагин MUST показать экран входа

### Requirement: Выход

Действие «Выйти» SHALL завершать сессию на сервере и всегда очищать локальные токены.

#### Scenario: Выход при недоступном сервере

- **WHEN** пользователь выходит, а `/auth/logout` недоступен
- **THEN** плагин MUST удалить локальные токены и показать экран входа

### Requirement: Адреса сервера заданы в сборке

Плагин SHALL обращаться только к боевому gateway, а сборка для разработки — к локальному. Адреса SHALL быть перечислены в `networkAccess` манифеста: боевой в `allowedDomains`, локальный в `devAllowedDomains`.

#### Scenario: Сборка для публикации

- **WHEN** собирается плагин для публикации
- **THEN** манифест и код MUST NOT содержать разрешения на произвольные домены (`*`)
