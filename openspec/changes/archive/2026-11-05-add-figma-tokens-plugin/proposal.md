## Why

Дизайнеры работают в Figma, а токены дизайн-системы живут в DS Builder: сейчас значения приходится переносить вручную, и они расходятся. Нужен Figma-плагин, который подключается к DS Builder от имени пользователя и работает с токенами темы прямо в Figma.

Работа разбита на два изменения. Это первое: плагин, вход и просмотр токенов. Оно снимает главный риск — вход и сетевой доступ из песочницы Figma — до работы над записью в файл.

## What Changes

- Новое приложение `js/apps/figma-plugin`: приватный плагин организации, TypeScript и React.
- Вход пользователя DS Builder через OAuth Device Authorization Grant в Keycloak: плагин открывает браузер, пользователь входит и подтверждает, плагин опрашивает выдачу токена. Сессия переживает перезапуск Figma, есть выход.
- Выбор контекста: проект → дизайн-система → тема → активный черновик или опубликованная версия; по умолчанию последняя опубликованная.
- Просмотр токенов только для чтения: цвета и градиенты в режимах Light и Dark, типографика по экранам, радиусы, отступы и тени, с поиском.
- Новый публичный OAuth-клиент Keycloak `dsbuilder-figma-plugin`: только Device Authorization Grant, audience `dsbuilder-api`.
- Gateway разрешает origin `null` (его имеет iframe плагина) только для входа и чтения: настраиваемый список, без расширения для записи.
- Долгая сессия: плагин запрашивает `offline_access`, эта роль входит в составную роль `user`.
- Endpoint устройства публикуется в API Reference.
- Плагин ничего не пишет в файл Figma и не меняет данные DS Builder.

## Следующий этап: экспорт токенов в Figma

Отдельное изменение после этого, на основе того же плагина и тех же чтений:

- кнопка экспорта выбранной темы и версии в открытый файл Figma;
- цвета и размеры — в Variables: коллекции по разделам токенов, режимы Light и Dark, алиасы там, где они есть;
- типографика — в Text Styles с привязкой полей к переменным, тени — в Effect Styles, градиенты — в Paint Styles: целиком переменной они в Figma не задаются;
- повторный экспорт обновляет созданное, а не дублирует: связь токена и объекта Figma по идентификатору токена;
- предпросмотр изменений, выбор разделов, отчёт о пропущенном (нет шрифта в файле, превышен лимит режимов тарифа).

Это изменение закладывает для экспорта слой чтения с разобранными значениями и обмен сообщениями с основным потоком плагина, но запись в файл не реализует.

## Capabilities

### New Capabilities

- `figma-plugin-authentication`: вход в DS Builder из Figma-плагина, хранение и обновление сессии, выход.
- `figma-plugin-token-browser`: выбор контекста и просмотр токенов темы в Figma-плагине.

### Modified Capabilities

- `gateway-authorization`: разрешённый origin Figma-плагина для входа и чтения.
- `identity-authentication`: OAuth-клиент Figma-плагина и документирование Device Authorization Grant.

## Impact

- **js:** новое приложение `js/apps/figma-plugin` с манифестом Figma, сборкой в один HTML и основной поток; подключение его сборки и тестов к `npm run verify:fast` и `validate-js.yml`. Новые зависимости только в этом приложении: `@figma/plugin-typings`, `vite-plugin-singlefile`.
- **backend-kt:** `backend-kt/app` — настройка `OIDC_PLUGIN_ORIGINS` и правило CORS в `GatewayRequestHandler`; `identity-gateway/keycloak` — клиент в `dsbuilder-realm.json` и `bootstrap-production-keycloak.sh`; `public-authentication.yaml` — endpoint устройства. Маршруты `ds-service`, схема БД и миграции не меняются.
- **frontend-kt:** меняется только контрактный тест настроек Keycloak (`OAuthConfigurationTest`). Плагин для Android Studio — образец сценария выбора контекста и просмотра. Окно на Compose Multiplatform не делается сейчас: причины и условия возврата в `design.md`.
- **Развёртывание:** новая переменная окружения gateway в `docker-compose.prod.yml`; приватная публикация плагина выполняется в организации Figma.
