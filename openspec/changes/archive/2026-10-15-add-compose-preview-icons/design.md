## Context

Свойства api-меты типа `icon` (`iconClosed`, `iconOpened` и аналоги) принимают `ImageSource`. В базе их значения хранятся
строкой в формате, который выгружает Theme Builder: `disclosure.down.fill.16`, `plus.16`. Клиент собирает payload из
модели конфигурации; `getConfigToken` создаёт свойство только для типов `color`, `float`, `shadow`, `shape`, `dimension`,
`typography`, `value` и `component_style`, для остальных возвращает `null`, и такое свойство пропадает из модели.
`assembler.ts` превращает значение в `literal`, `tokenRef` или `styleRef`; строка любого типа, кроме `value`, `float` и
`dimension`, уходит как `tokenRef`.

## Проверено на данных

- В базе `ds_registry` 21 свойство типа `icon`, значений у вариаций 106 и у инвариантов 15; у `AccordionItem` стили
  `xs`…`h5` всех четырёх вариантов (`solid`/`clear`, `action-start`/`action-end`) имеют `closedIcon` и `openedIcon`.
- Платформенная привязка `compose` у этих свойств есть (`closedIcon` → `closedIcon`).
- Различных имён иконок в базе 20. В выгрузках Compose-конфигураций всех дизайн-систем (`plasma-android/tokens/*/build/
  theme-builder/components`) их 26; все 26 есть в `icons-compose` после приведения `a.b.c.16` к `ABC16`. Расхождение с базой
  (`disclosure.down.outline.24`, `disclosure.up.outline.24`, `info.circle.outline.16`) вызвано компонентами без записи в
  api-мете (`IconTabs`, `FormItem`).
- Причина, по которой иконок нет в payload: клиент, а не данные и не API.

## Decisions

1. **Имя иконки — строка из данных.** Клиент передаёт её как есть: `{ "type": "literal", "value": "disclosure.down.fill.16" }`.
   Приведение к члену `SddsIcons` делает плагин: делит по `.`, `-`, `_` и пишет части с заглавной буквы. Так данные не
   переименовываются, а клиент не знает про Kotlin. Схема payload не меняется (`literal` допускает строку).
2. **Модель конфигурации.** Новый `IconProp` (по образцу `StyleReferenceProp`): хранит строку и отдаёт значение. Правки
   компонента клиент не сохраняет (они живут в сессии редактора), поэтому записи иконки в базу нет.
3. **Ассемблер.** Значение свойства типа `icon` уходит как `literal`, а не `tokenRef`; пустое значение свойство не создаёт.
4. **Панель свойств.** Значение иконки показывается строкой только для чтения, как ссылка на стиль; редактировать нельзя,
   чтобы случайная правка не испортила данные.
5. **Реестр и подстановка в плагине** описаны в парном change.

## Risks / Trade-offs

- Иконка, имени которой нет в реестре плагина, рисуется без иконки с предупреждением; предупреждения клиент пока не
  показывает, поэтому причину видно только в `details`/консоли плагина.
- Редактор не даёт выбрать иконку.
