## Зачем

Полный `dsbuilder` сейчас требует JVM либо нативного дистрибутива, хотя общая клиентская логика уже частично используется в Node.js через MCP. Дополнительный Kotlin/JS-таргет и публичный npm-пакет позволят устанавливать CLI через `npm install -g @sddsjs/design-system-builder-cli` и запускать все команды в Node.js на Linux, macOS и Windows с теми же настройками проекта и пользовательской сессией.

## Что изменится

- `:cli` получит Node.js executable с общим деревом команд, включая интерактивный `init`, браузерный вход, генерацию, публикацию, аналитику и `mcp serve`.
- **BREAKING**: Kotlin-контракт `ProcessRunner.run` станет `suspend`; приостанавливаемое выполнение распространится на делегаты, установщики, вызывающие сценарии и общий путь выполнения CLI. Синтаксис пользовательских команд сохранится.
- Общие Node-адаптеры файловой системы, HTTP, PKCE, блокировок сессии и процессов будут доступны CLI и `:mcp-node` через отдельный инфраструктурный модуль `:runtime-node`.
- JS-заглушки документации и чтения ZIP preview-плагина будут заменены полноценными реализациями.
- Существующие JVM, macOS arm64/x64 и Windows x64 сборки и установщики сохранятся; поддержка целевых генераторов будет определяться ОС и установленными инструментами.
- Появится публичный npm-пакет с командой `dsbuilder`, единой версией CLI и публикацией в рамках текущего `.github/workflows/publish-cli-release.yml`. Отдельные шаги публикуют сначала `@sddsjs/design-system-builder-generator` из `js/cli`, затем `@sddsjs/design-system-builder-cli`; публичный доступ, проверки состава и глобальной установки сохраняются. Tarball CLI также поставляется как дополнительный файл GitHub Release.

## Возможности

### Новые возможности

- `cli-node-runtime`: полный набор команд под Node.js, общая инфраструктура CLI/MCP, файловые операции, архивы, интерактивный терминал и жизненный цикл ресурсов.

### Изменяемые возможности

- `web-generator-package`: автоматическая публикация web-генератора из исходников выбранного CLI-тега при сохранении самостоятельной версии и ручного npm publish.

- `frontend-cli`: дополнительная точка входа Kotlin/JS с сохранением JVM/native и единым набором команд.
- `cli-platform-delegates`: асинхронный порт процессов, распространение отмены и корректное завершение дочернего процесса на всех средах выполнения.
- `cli-release-delivery`: дополнительный Node.js tarball, публикация обоих npm-пакетов в текущем процессе выпуска и глобальная установка CLI по имени пакета при сохранении существующих дистрибутивов и совместимости старых выпусков.

## Влияние

Изменяются `frontend-kt/cli`, `mcp-node`, новый `runtime-node`, `core-process`, `core-platform`, вызывающие их `feature-*`, `platform-*`, JS-адаптеры `feature-docs`/`feature-components`, `analytics-metrica`, Gradle-конфигурация и проверки. Обновляются ADR-0004, архитектурные инструкции `frontend-kt/AGENTS.md` и `cli/AGENTS.md`, документация и `.github/workflows/publish-cli-release.yml`/`validate-frontend-kt.yml`.

Базовая среда — Node.js 22+, имя пакета — `@sddsjs/design-system-builder-cli`, имя команды — `dsbuilder`. Сам пакет не требует Java или Kotlin/Native при запуске; требования Gradle, Swift и web-генератора остаются требованиями соответствующих команд. Версия берётся из `CLI_RELEASE_TAG`, локальное значение остаётся `0.1.0`; публикация локальной версии без релизного тега запрещается. Существующий workflow получает `NPM_TOKEN` с правом публикации обоих пакетов в scope `@sddsjs`; значение передаётся как `NODE_AUTH_TOKEN` только шагам публикации. Версия web-генератора берётся из `js/cli/package.json`, независимо от CLI-тега.

Backend API, хранилища, схема `.sdds` и форматы сессии не меняются. Код `backend-kt` не затрагивается; `js/cli` остаётся отдельным web-генератором, для которого обновляются документация выпуска и необходимые проверки публикации. При изменении файлов `js/cli` версия поднимается один раз вместе с package-lock.json по AGENTS.md. Выбор ZIP/TAR.GZ-зависимостей ограничен Node-адаптерами и фиксируется вместе с lock-файлом Kotlin/JS. Производственные изменения защищённых архитектурных тестов, Strictacode policy и агентского процесса не требуются.
