# Проектирование второй волны UI E2E

## Роли и данные

Owner готовит данные через API; браузер использует отдельную member-сессию. Проверяются разные
subject, отсутствие system_admin и реальный effectiveRole через GET active-проекта.
Credentials участника необязательны для прежних Owner-тестов. Приоритет источника настроек:
DSB_E2E_CREDENTIALS_FILE, затем .env.e2e.local; секреты не выводятся.

Проекты с суффиксами UI Roles editor/viewer и членство тестового участника переиспользуются.
Чужое или несовпадающее членство не переписывается. Каждый сценарий создаёт собственную обычную ДС
и темы; ID и ревизии берутся из свежих ответов. Мутации подготовки не повторяются автоматически.

## Fixtures и UI

Ролевые fixtures расширяют существующие. API helpers готовят данные, Page Objects задают локаторы
и переходы, spec-файлы содержат проверки. Owner-готовность редактора сохраняется; Viewer определяется
положительными признаками просмотра и выбранного токена, а не отсутствием всех элементов.

Наблюдатели записи подписываются до навигации, проверяют origin и scope проекта/ДС и снимаются
в finally до Owner cleanup. Технический preview POST палитры не считается записью.
Действующий PendingMutation и очистка только успешной ДС сохраняются; ошибки не скрываются.

## Предметные исходные значения

- Цвета подготавливаются независимым CT-BASE; сравниваются только относящиеся к сценарию значения.
- Типографика Body M: 16/20/0, 15/20/0, 14/18/0. T709 задаёт Size iOS=17 только на крупных экранах.
- RSS-BASE: round.m=8, round.l=16, round.circle=Full, spacing.4x=8; down.hard.m имеет один слой
  X=0/Y=4/Blur=8/Spread=0, чёрный цвет с прозрачностью 16%, без своих платформенных значений.
- T593 подготавливает известную связь textAccent с Accent Green/Hue130 #500. Количество остальных
  связей произвольное; поиск Green, очистка и возврат проверяют доступность данных и запреты Viewer.
- В T631 согласован выбор плитки цветового токена вместо отсутствующего Button на канвасе.

## Проверка CLI

Windows-фиксы трёх CLI-тестов и подъём версии исключены из diff. Исходный CLI 0.1.3
проверен в WSL Ubuntu 24.04 с Linux Node.js 22.23.3: typecheck и 95/95 unit-тестов прошли.
Ранее FAST/FULL прошли в Git Bash с Windows-фиксами; после их отката целиком не повторялись.

Strictacode 0.0.12 запускался с process-local UTF-8 Python и временным npm.exe launcher вне Git.
Нормализация EOL для проверки Git-хешей ограничена дочерним процессом. Protected policy не отключалась;
исходники tools, baseline и thresholds не менялись.

строгую валидацию OpenSpec, diff check, Strictacode compare, FAST/FULL JavaScript-контура,
