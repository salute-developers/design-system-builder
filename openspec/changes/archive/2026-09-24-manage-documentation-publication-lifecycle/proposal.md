## Why

Повторная публикация документации для одного ключа `(projectId, designSystemId, version, platform)` атомарно переключает указатель на новую публикацию, но прежний полный снимок остаётся в PostgreSQL и S3 без ограничения срока хранения. Наиболее быстро растут записи привязок к коду: их число зависит от количества компонентов, вариантов и значений вариантов, а каждый снимок дублирует весь набор.

Удалять разные версии документации автоматически пока нельзя: опубликованная версия библиотеки в Maven или npm должна оставаться согласованной с документацией этой версии. Нужна более узкая гарантия — одна и та же версия и платформа не должны бесконечно накапливать заменённые публикации.

## What Changes

- Для каждого ключа публикации активной остаётся только текущая публикация; заменённая публикация получает устойчивое задание асинхронной очистки.
- Очистка начинается после настраиваемой защитной задержки, удаляет точные объекты публикации и исходного пакета из S3, затем удаляет заменённый снимок из PostgreSQL.
- Повторные попытки безопасны: удаление отсутствующего объекта считается успешным, задания захватываются с арендой, а незавершённая работа продолжается после перезапуска процесса.
- Миграция создаёт задания для уже существующих заменённых публикаций с фиксированной задержкой 24 часа от момента миграции.
- Добавляются настройки, структурированные журналы и низкокардинальные метрики процесса очистки.
- Хранение разных версий, дедупликация по хешу содержимого и хранение разностей между снимками в это изменение не входят.

## Capabilities

### New Capabilities

Отсутствуют.

### Modified Capabilities

- `documentation-processing-pipeline`: публикация полного снимка дополнительно планирует безопасное удаление заменённого снимка для того же ключа версии и платформы.

## Impact

- `backend-kt/documentation-service/feature-processing`: правила жизненного цикла, прикладной сценарий и адаптеры PostgreSQL и S3 в пакете `data`.
- `backend-kt/documentation-service/app`: конфигурация, фоновый цикл, журналы и подключение метрик.
- Публичные контракты чтения, поиска и публикации документации не меняются; изменения в `frontend-kt` и `js` не требуются.
- Новые библиотеки времени выполнения не требуются. Учётной записи сервиса понадобятся права `DeleteObject` только для уже используемых префиксов S3.
