## Why

Пересечение вариаций — значения свойств, которые действуют только при одновременном выборе нескольких стилей,
например `size: l` и `shape: pilled`. `ds-service` хранит пересечения и умеет их читать и записывать, а редактор
компонента их не показывает: увидеть, настроить или удалить пересечение в DS Builder нельзя. Значения пересечений из
выгрузки редактор сейчас просто отбрасывает, поэтому превью рисует компонент без них, хотя в сгенерированном пакете
они есть.

## What Changes

- Клиент читает пересечения открытой конфигурации из бандла редактора и передаёт их в превью. Значение пересечения
  больше не может стать отдельным стилем с тем же именем, что и обычный стиль.
- Во вкладке «Структура» появляется третий блок «Дерево вариаций»: дерево всех сочетаний значений вариаций открытой
  конфигурации. Настроенные сочетания, то есть пересечения со значениями, отмечены. Фильтр «Только настроенные»
  скрывает остальные, кнопка раскрывает или сворачивает все ветки.
- Выбор сочетания в дереве ставит его значения в превью и переключает «Стилизацию» на это пересечение: инспектор
  показывает и правит значения свойств пересечения. Пересечение появляется на сервере с первым записанным значением.
- Настроенное пересечение можно удалить вместе со всеми его значениями, с подтверждением.
- Новых маршрутов `ds-service` нет: запись и удаление идут через существующий редакторский API
  (`PUT` и `DELETE /api/ds/appearances/{id}/property-values` со списком `styleIds`).

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `component-editor-workbench`: блок «Дерево вариаций» во вкладке «Структура», правка значений пересечения в
  «Стилизации», удаление пересечения, пересечения в превью.

## Impact

- **js, `apps/client`:**
  - `api/componentRepository.ts`: сборка пересечений из выгрузки редактора (значения с `targets`) в `combinations`
    модели компонента;
  - `api/componentStructureRepository.ts`: запись, удаление значения и удаление всего пересечения;
  - `pages/components/features/ComponentStructure`: блок дерева;
  - `pages/components/features/ComponentInspector`: режим пересечения во «Стилизации»;
  - превью компонента: учёт пересечений для выбранных стилей.
- **backend-kt, `ds-service`:** без изменений. Используются `GET /appearances/{id}/editor-model`,
  `PUT` и `DELETE /appearances/{id}/property-values`.
- **frontend-kt:** без изменений.
- Хранение данных, пакеты `.sdds` и генерация не меняются.
