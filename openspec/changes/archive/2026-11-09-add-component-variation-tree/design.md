## Context

`ds-service` хранит значение свойства пересечения строкой `style_combinations` со списком стилей-членов: одна строка —
одно свойство. Пересечение в интерфейсе — все строки конфигурации с одинаковым набором стилей.
В выгрузке редактора, где включён флаг `editorIds`, пересечение приходит как значение стиля-владельца с полем
`targets`: остальные стили сочетания перечислены по вариациям. После `add-component-structure-tab` клиент такие
значения пропускает, чтобы они не превращались в одноимённые дубли стилей. Модель `Config` клиента уже умеет хранить
сочетания (`Combination`: `styleIDs` и `props`), и Compose-превью их применяет, но загрузка их не заполняет.

Редакторский API пишет значения адресно: `PUT /appearances/{id}/property-values` со `styleIds` из нескольких стилей
создаёт строку сочетания для свойства или обновляет её. `DELETE` с теми же `styleIds` удаляет строку вместе с её
членами. Пустое пересечение без значений не хранится.

Автосохранение «Стилизации» пишет через устаревшие маршруты `variation-property-values`, и они адресуют только один
стиль.

## Goals / Non-Goals

**Goals:**

- Видеть, настраивать и удалять пересечения открытой конфигурации.
- Применять пересечения в превью.
- Обойтись существующим API `ds-service`.

**Non-Goals:**

- Пересечения больше чем из двух вариаций не запрещаются, но отдельного интерфейса для них нет: дерево позволяет
  выбрать сочетание любой глубины.
- Перевод автосохранения обычных стилей на редакторский API.
- Состояния (`states`) в значениях пересечения. Пересечение пишется для набора без состояний, как в прототипе.

## Decisions

**Загрузка.** `toLegacyComponentConfig` превращает каждое значение с `targets` в `Combination`: стиль-владелец плюс
стили из `targets`, найденные по ID вариации и имени значения. Если стиль не найден, пересечение пропускается с
предупреждением в консоли. В список стилей вариации значение пересечения по-прежнему не попадает.

**Дерево.** Вариации упорядочены как в блоке «Вариации», цветовая схема последней. В корне — значения всех вариаций,
вложенные ветки — значения вариаций после вариации ветки. Каждое сочетание встречается один раз, в том числе
сочетание без первой вариации. В прототипе корень — только первая вариация: сочетание без неё туда не попадает, а
сочетание с пропуском вариации повторяется под каждым промежуточным значением. Ветки строятся по мере раскрытия: всех
сочетаний слишком много, чтобы строить их заранее. По умолчанию ветки свёрнуты; кнопка раскрывает пути к настроенным
пересечениям или сворачивает всё. Фильтр «Только настроенные» оставляет настроенные ветки с предками и раскрывает пути
к ним. Состояние раскрытия и фильтр хранятся в памяти панели, без `localStorage`.

**Выбор и правка.** Выбор ветки ставит её стили в выбор превью (`selection`) и открывает в «Стилизации» режим
пересечения: над секциями плашка «Пересечение size: l · shape: pilled» с кнопкой выхода. В этом режиме секции
показывают свойства вариаций сочетания со значениями пересечения: привязанные к вариациям и заданные хотя бы у одного
их стиля. Привязки в данных бывают неполными, и одних привязок не хватает, чтобы показать свойства. Пустое значение
означает, что действует значение обычного стиля. Правка пишется сразу через `PUT .../property-values` со `styleIds`
сочетания, без автосохранения. Сброс значения — `DELETE` с теми же `styleIds`. После записи компонент перечитывается
тем же механизмом, что и структурные операции.

Альтернатива: писать пересечения через автосохранение. Отвергнута, потому что устаревшие маршруты не адресуют
сочетание, а их расширение требует бэкенда.

**Удаление пересечения.** Кнопка удаления у настроенной ветки удаляет все значения сочетания по очереди
(`DELETE` по каждому свойству). Подтверждение показывается через `StructureConfirmDialog`.

**Превью.** Compose-превью уже применяет `combinations`. Web-превью в рамках изменения проверяется: если оно не
учитывает сочетания, они добавляются к значениям выбранных стилей в том же порядке, что и в Compose: сочетания с
меньшим числом стилей раньше.

## Risks / Trade-offs

- [Правка пересечения не идёт через автосохранение, нет отмены и индикатора неотправленных правок] → каждое изменение
  сразу отправляется, ошибки показываются тем же сообщением, что и у структурных операций.
- [Удаление пересечения — несколько запросов, сбой посередине оставляет часть значений] → после любого исхода компонент
  перечитывается, дерево показывает фактическое состояние, удаление можно повторить.
- [Много вариаций — много сочетаний в дереве] → ветки глубже первого уровня свёрнуты, есть фильтр «Только
  настроенные».
