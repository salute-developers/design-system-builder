## Контекст

- `NumberControl` разбирает ввод `parseNumber`; нечисловой ввод без `invalidMessage` откатывается. Единица `px`
  показывается всегда. В сидах нечисловые значения числовых свойств — `auto` (Chip `width`) и `initial` (Switch
  `descriptionMaxLines`); выражения `calc(…)` у Avatar и Toast — свойства типа `value`, инспектор их не показывает.
- Импорт ядра (`import-plasma-component.ts`) сохраняет выражения ядра как есть, с шаблоном `${<объект>Tokens.<ключ>}`;
  генератор подставляет экспорт ядра в сгенерированный конфиг. В сидах это `statusLeft`, `statusTop` у Avatar и
  `buttonLoadingBackgroundColor` у ButtonGroup.
- Web-плагин (`literalToCss`) переводит числа в rem, остальные строки передаёт как есть.

## Решения

### Выражение в числовом поле

Для `dimension`, `float` и `integer` строка инспектора разбирает ввод так: число — числом, как раньше; другое
непустое значение — строкой как есть. Единица `px` показывается, только когда в поле число. Пустой ввод
по-прежнему откатывается. Поле прозрачности не меняется: там нужен процент.

### Свойства `value` в инспекторе

`sectionOf` больше не скрывает `value`: секция определяется по имени (`color`/`background` → Color,
`width`/`height` в конце → Size, `radius` → Appearance, остальное → Layout). Контрол — то же поле, что у чисел,
без единицы и с разбором «строка как есть»: без приведения `1.50` к `1.5`, пустой ввод не сохраняется.

### Шаблоны ядра в плагине

Перед `literalToCss` строковое значение проходит `resolveCoreTemplates`: каждое `${<объект>.<ключ>}` заменяется
значением `<ключ>` из экспорта ядра `<объект>` (`avatarTokens.avatarSize` → `--plasma-avatar-size`). Неизвестный
объект или ключ оставляет шаблон как есть и пишет предупреждение `incompatible_value`. Версия плагина — patch.

## Риски / Компромиссы

- [Пользователь вводит недействительный CSS] → значение сохраняется как есть, превью его отбросит; проверки CSS нет.
