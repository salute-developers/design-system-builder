## ADDED Requirements

### Requirement: Единый владелец схемы Preview Protocol

Каноническая JSON Schema Preview Protocol v1 SHALL храниться в
`backend-kt/preview/contract/schemas/v1/preview-payload.schema.json`. Копии схемы в клиенте
и в `plasma-android` MUST быть побайтово идентичны канонической. Номер версии протокола
остаётся `1`: версия не выпускалась за пределы разработки, поэтому изменения вносятся в неё
без повышения номера.

#### Scenario: Копия совпадает с канонической схемой

- **WHEN** запускается проверка схемы клиента
- **THEN** проверка MUST сравнить копию с канонической схемой и завершиться успешно при
  побайтовом совпадении.

#### Scenario: Копия разошлась

- **WHEN** содержимое копии отличается от канонической схемы
- **THEN** проверка MUST завершиться ошибкой с именем расходящегося файла
- **AND** скрипт синхронизации MUST уметь восстановить копию из канонической схемы.

### Requirement: Состояния свойства задаются упорядоченным массивом наборов

Значение свойства SHALL иметь вид `{base, states}`, где `states` это упорядоченный массив записей
`{when, source}`. Поле `when` SHALL быть непустым массивом уникальных имён состояний, запись
действует, когда активны все перечисленные состояния. Имена состояний SHALL быть открытым
набором строк: допустимы интерактивные (`pressed`, `hovered`, `focused`, `selected`,
`activated`, `disabled`) и кастомные (`checked`, `indeterminate`, `error`) состояния. Если
подходящих записей несколько, применяется запись с наибольшим числом имён в `when`, а при
равенстве последняя в массиве.

#### Scenario: Составное состояние

- **WHEN** `states` содержит запись с `when: ["pressed", "selected"]`
- **THEN** payload MUST проходить валидацию схемы.

#### Scenario: Пустой набор

- **WHEN** запись `states` содержит `when: []` либо повторяющиеся имена
- **THEN** валидация по схеме MUST завершиться ошибкой.

#### Scenario: Несколько подходящих записей

- **WHEN** активны состояния `pressed` и `selected`, а `states` содержит записи для
  `["pressed"]` и `["pressed", "selected"]`
- **THEN** потребитель MUST выбрать запись `["pressed", "selected"]`.

### Requirement: Источник значения поддерживает alpha, styleRef и assetRef

Источник значения (`source`) SHALL быть одним из: `literal{value}`, `tokenRef{tokenId}`,
`styleRef{styleId}`, `assetRef{assetId}`. Источники `literal` и `tokenRef` MAY содержать `alpha`
числом от 0 до 1 включительно. Источники `styleRef` и `assetRef` MUST NOT содержать `alpha`.

#### Scenario: Токен с прозрачностью

- **WHEN** источник `tokenRef` содержит `alpha: 0.4`
- **THEN** payload MUST проходить валидацию схемы.

#### Scenario: Alpha вне диапазона

- **WHEN** `alpha` меньше 0 либо больше 1
- **THEN** валидация по схеме MUST завершиться ошибкой.

#### Scenario: Ссылка на ресурс

- **WHEN** источник `assetRef` указывает на идентификатор из `assets`
- **THEN** payload MUST проходить валидацию схемы
- **AND** потребитель MUST отклонить payload, если такого ресурса нет.

### Requirement: Вложенные стили передаются словарём styles

Payload SHALL содержать необязательный словарь верхнего уровня `styles`, где ключ это
идентификатор стиля, а значение содержит `component` и `properties` в том же формате, что и
свойства основного компонента. Источник `styleRef` SHALL ссылаться на ключ `styles`.
Потребитель MUST отклонять payload с неизвестной ссылкой на стиль и с циклом ссылок между
стилями.

#### Scenario: Вложенный стиль

- **WHEN** свойство основного компонента содержит `styleRef` на стиль, описанный в `styles`
- **THEN** payload MUST проходить валидацию схемы.

#### Scenario: Неизвестный стиль

- **WHEN** `styleRef` указывает на отсутствующий ключ `styles`
- **THEN** плагин MUST вернуть `PreviewResult.Failure` с кодом `unknown_style_ref`
- **AND** MUST NOT рисовать частичный результат.

#### Scenario: Цикл стилей

- **WHEN** стиль прямо или через другие стили ссылается сам на себя
- **THEN** плагин MUST вернуть `PreviewResult.Failure` с кодом `style_ref_cycle`.

### Requirement: Тема содержит gradient и shadow со spread

Токен темы `gradient` SHALL иметь вид `{type: "gradient", layers}`, где каждый слой это
`{kind: "linear", angle, stops}`, `angle` в градусах по соглашению CSS (0° снизу вверх, 90° слева направо, 180° сверху вниз), а `stops` содержит не менее двух
элементов `{color, position}` с цветом `#RRGGBBAA` и позицией от 0 до 1. Слой токена `shadow`
SHALL содержать `x`, `y`, `blur`, `spread` и `color`; `spread` обязателен, допустимы
отрицательные значения.

#### Scenario: Линейный градиент

- **WHEN** тема содержит gradient-токен с двумя stops
- **THEN** payload MUST проходить валидацию схемы.

#### Scenario: Градиент с одним stop

- **WHEN** слой градиента содержит менее двух stops
- **THEN** валидация по схеме MUST завершиться ошибкой.

#### Scenario: Тень без spread

- **WHEN** слой тени не содержит `spread`
- **THEN** валидация по схеме MUST завершиться ошибкой.

### Requirement: Ресурсы поддерживают SVG и PNG

Тип ресурса в `assets` SHALL допускать значения `TTF`, `OTF`, `SVG`, `PNG`. Превращение SVG и
PNG в painter в этот протокол не входит: плагин, не умеющий отрисовать ресурс, SHALL вернуть
предупреждение, а не ошибку.

#### Scenario: SVG-ресурс

- **WHEN** `assets` содержит ресурс типа `SVG` с дайджестом и URL
- **THEN** payload MUST проходить валидацию схемы.

### Requirement: Успешный результат может содержать предупреждения

`PreviewResult.Success` SHALL содержать необязательный массив `warnings` из элементов
`{code, message, path?}`. Предупреждение MUST NOT менять статус результата на ошибку.

#### Scenario: Неизвестное имя состояния

- **WHEN** плагин не знает имя состояния из `when`
- **THEN** результат MUST быть `Success` с предупреждением `unknown_state` и путём к записи
- **AND** запись MUST быть пропущена.

### Requirement: Общие фикстуры проверяют всех потребителей

Репозиторий SHALL содержать каталог общих фикстур контракта v1 с подкаталогами `valid` и
`invalid`. Клиент и `plasma-android` MUST иметь побайтово идентичные копии каталога и проверку
идентичности. Тесты каждого потребителя MUST проверять, что все `valid` проходят, а все
`invalid` не проходят валидацию.

#### Scenario: Валидная фикстура

- **WHEN** тест потребителя валидирует файл из `valid`
- **THEN** валидация MUST завершиться успешно.

#### Scenario: Невалидная фикстура

- **WHEN** тест потребителя валидирует файл из `invalid`
- **THEN** валидация MUST завершиться ошибкой.

#### Scenario: Копия фикстур разошлась

- **WHEN** набор файлов либо содержимое копии отличается от канонического каталога
- **THEN** проверка идентичности MUST завершиться ошибкой.
