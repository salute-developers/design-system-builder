# Design

## Context

`token_groups` — двухуровневое дерево. Чтение без страницы уже собирает корни и их детей по позициям; общий постраничный помощник сортирует записи по `label`. MCP всегда передаёт `limit=50`. Реестр инструментов общий для двух средств запуска; его поля `required` и описания напрямую преобразуются в схему MCP.

## Цели и границы

Цель — единый порядок дерева в HTTP и понятный контракт чтения MCP. Не вводятся новые инструменты, хранилище групп или автоматическая обрезка полных ответов. Объём подробных ответов измеряется отдельно: сокращение `component_config_get` либо страницы документации без способа продолжения исказило бы ответ.

## Решения

### Страницы дерева

Хранилище применяет один порядок для обычного и постраничного чтения: корень `(position, id)`, затем его дети `(position, id)`. Непрозрачный курсор хранит последнюю позицию обхода и привязку к проекту, дизайн-системе, версии, виду и родителю. При `parentId` читаются только непосредственные дети по позиции. Изменение родителя или порядка между страницами, как и в текущем чтении, не создаёт снимок нескольких запросов; клиент при необходимости начинает обход заново.

У групп нет заявленных `name`/`query`; маршрут отклоняет их до выборки. Это сохраняет общее значение поиска для остальных списков и исключает ложное успешное фильтрование.

### Схемы и диагностика MCP

Реестр остаётся единственным источником для обоих средств запуска. Обязательность задаётся на свойствах входа и проверяется на итоговой схеме MCP, а не только на внутренних DTO. Описания разделяют список, единичное чтение и чтение опубликованных привязок. Для модельной версии указан порядок `version` → версия контекста → `draft`.

Некорректное тело либо метаданные успешного HTTP-ответа обозначаются отдельным `INVALID_BACKEND_RESPONSE`; HTTP 503 и сетевые сбои остаются `BACKEND_UNAVAILABLE`. Код ошибки не включает тело ответа. HTTP 401 даёт `AUTH_REQUIRED` с командой входа. Неизвестный аргумент называется по имени.

### Размер ответа

Сохраняются полный результат для явно выбранной конфигурации и страницы документации и краткий ответ `code_binding_get` по умолчанию. Проверка размеров на характерных данных записывается в задаче; если обнаружится неприемлемый объём, отдельное согласованное изменение добавит краткий режим или постраничное чтение без потери данных. Универсального ограничения байтов в этом изменении нет.

## Риски и совместимость

- Порядок постраничных групп изменится для клиентов, которые полагались на сортировку по `label`; поля DTO и тип курсора сохраняются. Старые курсоры с прежней сортировкой следует отклонить как неверные и начать обход заново.
- Большое число групп потребует оценки стоимости обхода; тест проверяет границы страниц и одинаковый результат двух режимов.
- Новый код `INVALID_BACKEND_RESPONSE` требует обновить проверки клиентов, которые перечисляют коды ошибок; он не означает повторный запрос.

## План проверки

Проверить контракт HTTP и OpenAPI, схему `tools/list` обоих средств запуска, сообщения ошибок и чтение версии. Запустить FAST и FULL для изменённых контуров. Для PostgreSQL-интеграционного теста требуется доступный Docker/Testcontainers; отсутствие инфраструктуры не считается успешной проверкой.
