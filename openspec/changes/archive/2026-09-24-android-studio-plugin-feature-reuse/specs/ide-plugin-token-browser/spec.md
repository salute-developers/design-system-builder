## MODIFIED Requirements

### Requirement: Plugin module structure

`frontend-kt` SHALL предоставлять модуль `:plugins:android-studio` — плагин для Android Studio / IntelliJ IDEA, реализованный как plain JVM Gradle-модуль на IntelliJ Platform Gradle Plugin, зависящий от `core-domain`, `core-network`, `core-auth`, `core-application`, `feature-projects`, `feature-theme` и `feature-auth` того же composite build.

#### Scenario: Модуль зарегистрирован в settings

- **WHEN** разработчик открывает `frontend-kt/settings.gradle.kts`
- **THEN** список активных модулей включает `:plugins:android-studio`

#### Scenario: Плагин переиспользует общий прикладной слой там, где паттерн доступа совпадает

- **WHEN** разработчик инспектирует Gradle-зависимости `:plugins:android-studio`
- **THEN** модуль зависит от `core-domain`, `core-network`, `core-auth`, `core-application` через `project(...)`
- **THEN** модуль зависит от `feature-projects` (список проектов), `feature-theme` (tenant дизайн-системы и code-ссылка токена) и `feature-auth` (OAuth PKCE-логин) через `project(...)`
- **THEN** модуль не дублирует резолвинг контекста, credential-резолвинг или OAuth-оркестрацию, уже реализованные в этих модулях
- **THEN** модуль продолжает содержать собственный REST-клиент чтения токенов дизайн-системы (`DesignSystemDataClient`/`HttpDesignSystemDataClient`) — единственный доступный в `feature-theme` аналог (`TokenReadUseCases.values`) читает значения по одному `tokenId` за раз и не подходит для bulk-отображения списка токенов без N+1 запросов; это не дублирование существующей переиспользуемой возможности, а иной, оправданно локальный паттерн доступа

## ADDED Requirements

### Requirement: Tenant selection for token values

Плагин SHALL позволять выбрать tenant дизайн-системы при просмотре токенов, если у дизайн-системы больше одного tenant, и SHALL фильтровать значения токенов по выбранному tenant.

#### Scenario: У дизайн-системы один tenant

- **WHEN** пользователь выбрал дизайн-систему, у которой ровно один tenant (`GET /api/projects/{projectId}/ds/design-systems/{designSystemId}/tenants`, use case `feature-theme`)
- **THEN** плагин выбирает этот tenant автоматически, не показывая отдельный шаг выбора

#### Scenario: У дизайн-системы несколько tenant

- **WHEN** пользователь выбрал дизайн-систему, у которой больше одного tenant
- **THEN** плагин показывает шаг выбора tenant перед просмотром токенов

#### Scenario: Значения токенов фильтруются по выбранному tenant

- **WHEN** пользователь выбрал конкретный tenant (автоматически или вручную)
- **THEN** плагин запрашивает значения токенов для выбранного `tenantId`
- **THEN** плагин не показывает значения токена, принадлежащие другому tenant той же дизайн-системы

### Requirement: Copy token code reference to clipboard

Плагин SHALL предоставлять на платформе Android действие копирования в буфер обмена code-ссылки на токен (например `SddsServTheme.colors.textDefaultAccent`), получая её по нажатию на конкретный токен из CodeBinding (`kind=token`) опубликованной документации выбранной дизайн-системы (поле `themeReference`).

#### Scenario: Ссылка найдена в публикации

- **WHEN** выбрана платформа Android и пользователь нажимает «Копировать код» у токена
- **THEN** плагин находит последнюю публикацию дизайн-системы для платформы `compose` (`GET /documentation/publications/active` без `version`)
- **THEN** плагин ищет биндинг токена по точному `subject` — `tokens.<режим>.<имя>` для токенов, зависящих от темы (режим — выбранный в плагине), иначе `tokens.<имя>`
- **THEN** плагин копирует в буфер обмена значение `themeReference` и показывает статус «Скопировано»

#### Scenario: Ссылки нет — сообщается пользователю

- **WHEN** дизайн-система не опубликована для платформы, токена нет в публикации или `themeReference` пуст (например у `fontFamily`)
- **THEN** плагин ничего не копирует и показывает статус «Нет ссылки»
- **THEN** при ошибке запроса плагин показывает статус «Ошибка»

#### Scenario: Запрос выполняется по нажатию

- **WHEN** пользователь просматривает список токенов
- **THEN** плагин не загружает биндинги заранее и обращается к API документации только после нажатия «Копировать код»

#### Scenario: Действие недоступно вне платформы Android

- **WHEN** выбрана платформа `ios` или `web`
- **THEN** плагин не показывает действие "скопировать код" ни для одного токена

### Requirement: Full selection path in breadcrumbs

Плагин SHALL показывать в хлебных крошках полный путь выбора (проект / дизайн-система / tenant / платформа), включая шаги, выбранные автоматически.

#### Scenario: Автовыбранные шаги видны, но не кликабельны

- **WHEN** проект, дизайн-система или tenant выбраны автоматически как единственный вариант
- **THEN** их названия присутствуют в крошках как обычный текст
- **THEN** возврат на такой шаг невозможен, чтобы единственный вариант не выбирался заново автоматически

#### Scenario: Вручную выбранные шаги позволяют вернуться

- **WHEN** пользователь выбрал элемент вручную из списка
- **THEN** его название в крошках кликабельно и возвращает на шаг выбора этого элемента

### Requirement: Navigation state survives panel collapse

Плагин SHALL сохранять состояние навигации (выбранные проект, дизайн-система, tenant, платформа, текущий экран, режим темы токенов, выбранная вкладка типа токена и текст поиска) при сворачивании и повторном разворачивании tool window.

#### Scenario: Возврат на тот же экран

- **WHEN** пользователь на экране списка токенов сворачивает панель `SDDS` и разворачивает её снова
- **THEN** плагин показывает тот же список токенов с теми же проектом, дизайн-системой, tenant, платформой, режимом, вкладкой типа токена и текстом поиска, а не первый шаг выбора

#### Scenario: Выход сбрасывает навигацию

- **WHEN** пользователь нажимает «Выйти» или сессия истекает
- **THEN** сохранённая навигация сбрасывается к выбору проекта
