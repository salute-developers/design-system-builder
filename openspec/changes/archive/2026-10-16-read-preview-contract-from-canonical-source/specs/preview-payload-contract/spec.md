## MODIFIED Requirements

### Requirement: Единый владелец схемы Preview Protocol

Каноническая JSON Schema Preview Protocol v1 SHALL храниться в
`backend-kt/preview/contract/schemas/v1/preview-payload.schema.json`. Клиент MUST читать её из этого файла и MUST NOT хранить копию.
Копия схемы в `plasma-android` MUST быть побайтово идентична канонической. Номер версии протокола
остаётся `1`: версия не выпускалась за пределы разработки, поэтому изменения вносятся в неё
без повышения номера.

#### Scenario: Клиент читает каноническую схему

- **WHEN** запускаются тесты клиента
- **THEN** схема MUST быть прочитана из `backend-kt/preview/contract/schemas/v1/preview-payload.schema.json`
- **AND** в клиенте MUST NOT быть копии схемы и скрипта синхронизации.

#### Scenario: Схема испорчена

- **WHEN** каноническая схема или фикстура перестаёт соответствовать ожиданиям клиента
- **THEN** тест клиента MUST завершиться ошибкой.

#### Scenario: Правка контракта запускает проверку

- **WHEN** в запросе изменены только файлы из `backend-kt/preview/contract`
- **THEN** CI MUST запустить тесты клиента.

### Requirement: Общие фикстуры проверяют всех потребителей

Репозиторий SHALL содержать каталог общих фикстур контракта v1 с подкаталогами `valid` и
`invalid`. Клиент MUST читать фикстуры из этого каталога без копии, а `plasma-android` MUST иметь побайтово идентичную копию каталога
и проверку идентичности. Тесты каждого потребителя MUST проверять, что все `valid` проходят, а все
`invalid` не проходят валидацию.

#### Scenario: Валидная фикстура

- **WHEN** тест потребителя валидирует файл из `valid`
- **THEN** валидация MUST завершиться успешно.

#### Scenario: Невалидная фикстура

- **WHEN** тест потребителя валидирует файл из `invalid`
- **THEN** валидация MUST завершиться ошибкой.

#### Scenario: Копия фикстур в plasma-android разошлась

- **WHEN** набор файлов либо содержимое копии в `plasma-android` отличается от канонического каталога
- **THEN** проверка идентичности MUST завершиться ошибкой.
