## Context

`schema.test.ts` импортирует `./schema/preview-payload.schema.json` и собирает фикстуры через `import.meta.glob('./schema/fixtures/*/*.json')`.
Скрипт `sync-preview-payload-schema.mjs` копирует канонические файлы в `src/composePreview/schema` и в режиме `--check` сравнивает
их побайтово. В `validate-js.yml` для клиента есть только задание `build` (`npm run build`); задание с тестами отключено и относится
к другому проекту.

## Decisions

1. **Чтение через `fs`, а не импорт.** Тест читает канонические файлы Node-API (`readFileSync`, `readdirSync` от пути
   `../../../../../backend-kt/preview/contract/...`, вычисленного от `import.meta.url`). JSON-импорт из каталога вне `src` не
   подходит: `tsc -b` с составными проектами отклоняет файлы вне списка проекта, а `import.meta.glob` за пределами корня Vite требует
   `server.fs.allow`. Чтение через `fs` не меняет ни `tsconfig`, ни конфигурацию Vite.
2. **Валидатор и проверки те же.** Ajv, правило «все `valid` проходят, все `invalid` отклоняются» и проверка собранного payload
   остаются как есть; меняется только источник файлов. Если каталога нет, тест падает с понятной ошибкой, а не проходит на пустом
   наборе (уже есть проверка «фикстуры есть в обеих группах»).
3. **Удаление копии целиком.** Каталог `schema/`, скрипт и две npm-команды удаляются вместе с описанием в `README.md`, иначе в
   документации останутся инструкции для несуществующей копии.
4. **Тесты клиента в CI.** Новое задание `Tests (client)` в `validate-js.yml`: `npm ci` и `npm test` в `js/apps/client`, Node той же
   версии, что у сборки. Задание запускается по тем же событиям, что и `Build`.
5. **Путь запуска.** В `paths` workflow добавляется `backend-kt/preview/contract/**`: правка схемы или фикстур без изменений в `js/**`
   иначе не запускала бы тесты клиента.
6. **Копия `plasma-android`.** Правило «копия в `plasma-android` побайтово идентична» остаётся в требованиях; механизм сверки
   (отпечатки SHA-256 в CI) описывается и вводится отдельным change.

## Risks / Trade-offs

- Тест клиента зависит от структуры репозитория (путь к `backend-kt`). Клиент, собранный отдельно от монорепозитория, этот тест не
  пройдёт; в Docker-сборке (`context: ./apps/client`) тесты не запускаются.
- Весь набор тестов клиента в CI удлиняет проверку (порядка 30 секунд локально) и впервые выполняет тесты, которые раньше в CI не шли:
  возможны падения, не связанные со схемой (зависимость от окружения).
- Пока не введена сверка с `plasma-android`, расхождение той копии по-прежнему не ловится автоматически.
