## Context

`saveComponentMutation` читает инварианты по компоненту и дизайн-системе: в ответе значения всех конфигураций
компонента. Ключ существующего значения — стиль (или `invariant`), свойство и набор состояний, без конфигурации.

`ComponentStructurePanel` хранит модель (`axes`) в состоянии и заменяет её только по ответу `loadModel`.

`runStructureOperation` вызывает `loadComponent(name, true)` после успешной операции; разбор имени (`parseComponentRoute`)
считает имя без префикса `compose-` web-компонентом.

`setCombinationValue` перед каждой записью читает `GET /design-systems/{id}/tokens` без кеша.

`treeChildren` берёт значения всех вариаций после вариации ветки: в корне — значения всех вариаций.

Имя файла конфига строится из camelCase имени: `dense-2` и `dense2` дают `dense2`.

## Goals / Non-Goals

**Goals:** исправить замечания ревью; дерево вариаций — строгая иерархия.

**Non-Goals:** переименование существующих конфигураций с совпадающими идентификаторами; новые маршруты `ds-service`.

## Decisions

**Инварианты.** Значения инвариантов фильтруются по `appearanceId` открытой конфигурации до построения карты
существующих значений; так правка и очистка не задевают другие конфигурации.

**Модель «Структуры».** Модель хранится вместе с `appearanceId`, для которого загружена. Если он не совпадает с открытой
конфигурацией, блок «Вариации» показывает загрузку, кнопки действий недоступны; при смене конфигурации сбрасываются
режим редактирования и подтверждение удаления.

**Перечитывание.** `runStructureOperation` перечитывает `toComponentRoute(platform, name)` в `finally`: после успеха и
после ошибки; ошибка операции пробрасывается дальше и показывается как прежде. Открытие созданной конфигурации — только
после успеха.

**Токены.** Значение, которое не похоже на ссылку на токен (`#…`, число, число с единицами), пишется литералом без
чтения справочника. Для ссылки справочник читается через `readEditor` с `freshFor`, как другие списочные чтения
редактора; запись значения пересечения его не меняет.

**Дерево.** Уровни — вариации в порядке блока «Вариации», цветовая схема последней. Ветка уровня `n` — значение
вариации `n`, её дочерние ветки — значения вариации `n + 1`. Пересечение в дереве — путь от корня длиной от двух.
Настроенное пересечение, стили которого не образуют такой путь (пропущен уровень), показывается в списке «Другие
пересечения» под деревом подписью `size: l · view: accent` с выбором и удалением. Фильтр «Только настроенные»
оставляет настроенные пути с предками; список «Другие пересечения» виден всегда, когда не пуст. Создать пересечение с
пропуском уровня из дерева нельзя.

Альтернативы: повторять пересечение с пропуском под каждым промежуточным значением, как прототип, — одно пересечение
видно в нескольких местах; корень из всех вариаций (текущая реализация) — не совпадает с ожиданием.

**Идентификатор имени.** Ключ сравнения имени — имя без дефисов в нижнем регистре: он совпадает у имён с одинаковым
camelCase-идентификатором, а также у идентификаторов, которые различаются только регистром (на файловых системах без
учёта регистра это один файл). `requireFree` и `freeName` сравнивают ключи; импорт новой конфигурации с занятым ключом
отклоняет запись с `appearance_name_taken`. Генератор проверяет ключи конфигураций компонента до записи файлов.

## Risks / Trade-offs

- [Существующие данные уже могут содержать совпадающие ключи] → `ds-service` их не трогает, генератор остановится с
  ошибкой, называющей обе конфигурации; одну нужно переименовать.
- [Пересечения с пропуском уровня нельзя создать из дерева] → такие пересечения в данных редки; существующие видны и
  удаляются в «Других пересечениях».
