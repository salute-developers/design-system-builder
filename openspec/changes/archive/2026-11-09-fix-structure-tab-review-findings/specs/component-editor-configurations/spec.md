## MODIFIED Requirements

### Requirement: Имя конфигурации в kebab-case

Имя конфигурации SHALL состоять из строчных латинских букв и цифр, частей через одиночный дефис и начинаться с буквы
(`^[a-z][a-z0-9]*(-[a-z0-9]+)*$`, до 255 символов). `ds-service` SHALL проверять имя при создании, дублировании с именем,
переименовании и при создании конфигурации импортом. Существующие имена не по правилу MUST NOT переименовываться автоматически.

Имя SHALL быть уникальным среди конфигураций компонента с учётом идентификатора в коде: имена, которые совпадают после
удаления дефисов без учёта регистра (`dense-2` и `dense2`), считаются одинаковыми и отклоняются: с кодом
`appearance_name_taken` в редакторских маршрутах и импорте, с `409 APPEARANCE_NAME_CONFLICT` в `POST` и `PATCH
/appearances`, как и прежде для занятого имени. Сгенерированные имена (`new-2`, `<имя>-copy`) SHALL обходить такие совпадения.

#### Scenario: Переименование с пробелом

- **WHEN** клиент переименовывает конфигурацию в `Accordion new`
- **THEN** `ds-service` MUST ответить `422` с кодом `appearance_name_invalid` и MUST NOT менять данные

#### Scenario: Импорт пакета

- **WHEN** импортируется пакет, где у одной записи `styleName` равен `Accordion new`, а такой конфигурации у компонента нет
- **THEN** эта запись MUST попасть в `rejected` отчёта с причиной `appearance_name_invalid`
- **THEN** остальные записи пакета MUST импортироваться

#### Scenario: Повторный импорт старого имени

- **WHEN** импортируется запись для уже существующей конфигурации с именем не по правилу
- **THEN** `ds-service` MUST обновить эту конфигурацию, не отклоняя запись

#### Scenario: Поле имени в редакторе

- **WHEN** пользователь вводит в поле имени конфигурации `Dense Mode`
- **THEN** поле MUST показать `dense-mode`

#### Scenario: Совпадение идентификатора

- **WHEN** у компонента есть конфигурация `dense-2`, и клиент переименовывает другую конфигурацию в `dense2`
- **THEN** `ds-service` MUST ответить `409` с кодом `APPEARANCE_NAME_CONFLICT`

#### Scenario: Дублирование с совпадающим идентификатором

- **WHEN** у компонента есть конфигурация `new-2`, и клиент дублирует конфигурацию с именем `ne-w2`
- **THEN** `ds-service` MUST ответить `422` с кодом `appearance_name_taken`

## ADDED Requirements

### Requirement: Инварианты открытой конфигурации при автосохранении

Автосохранение правки инварианта SHALL искать существующее значение только среди значений открытой конфигурации.
Правка и очистка инварианта MUST NOT менять значения других конфигураций компонента.

#### Scenario: Одноимённый инвариант в двух конфигурациях

- **WHEN** у конфигураций `default` и `copy` задан инвариант `focusColor`, и пользователь меняет его в `copy`
- **THEN** клиент MUST изменить значение конфигурации `copy`
- **THEN** значение конфигурации `default` MUST остаться прежним
