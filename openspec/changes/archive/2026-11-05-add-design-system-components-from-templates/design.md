## Context

Компонент попадает в дизайн-систему двумя путями. При создании ДС `GeneratedDesignSystemComponentInitializer` раскладывает шаблоны 63 web-компонентов из `component-seeds.json` целиком: всё или ничего, пакетно в базовую версию (`ComponentSeedBatchWriter` требует, чтобы черновика ещё не было). Позже компоненты заливают импортом конфигурации (`dsbuilder components push`). Ручки «добавить один компонент из шаблона в существующую ДС» нет, поэтому ДС, созданная без компонентов, из редактора не наполняется.

Скрытие компонента удаляет только связь, конфигурация остаётся. Диалог «+» возвращает скрытые компоненты через `POST /design-system-components`. Это поведение сохраняется.

Раздел «Компоненты» уже доступен без связей, если в ДС есть оформления. Для ДС совсем без компонентов он скрыт, и это нужно изменить.

## Goals / Non-Goals

**Goals:**

- Добавление web-компонента в существующую ДС из шаблона, с зависимостями, в черновик.
- Один диалог для возврата скрытых и добавления новых компонентов.

**Non-Goals:**

- Шаблоны Compose и компонентов, заведённых через `push` после снимка: пополнение шаблонов решается отдельно.
- Удаление компонента вместе с конфигурацией и флаг видимости: команда оставила текущее скрытие.

## Decisions

### Раскладка шаблона пишет в любую границу версий

`ComponentSeedBatchWriter` получает границу версий при создании: `baseline(designSystemId)` для новой ДС (как раньше, только до первого черновика) и `draft(designSystemId)` для текущего черновика существующей ДС. Пакетная вставка запускает триггеры журнала, поэтому добавление видно в журнале и откатывается как остальные правки. Раскладка компонента (`insertComponent` и вложенные методы) не меняется; инициализатор получает `templates()` и `seedIntoDraft(designSystemId, names, linked)`, проверку метаданных и токенов для набора шаблонов. Токены для черновика берутся из разрешённого состояния (`ComponentTokensTable`), а не только из базовой версии.

Альтернативы: отдельный интерфейс и второй writer — не нужен, отличается только граница; импорт шаблона через `ComponentConfigImporter` — шаблоны в другом формате, конвертер добавил бы третий путь записи.

### Добавление — флаг существующей ручки

`POST /api/ds/design-system-components` получает необязательное поле `fromTemplate`. Без него поведение прежнее: создать или восстановить связь (на это опираются сценарии «связать, затем создать оформление» на неполной мете). С `fromTemplate: true` вызывается `ComponentTemplateRepository.addOwned`:

1. обойти компонент и его зависимости по шаблону: связанные пропустить, с оформлением — восстановить связь, остальным нужен web-шаблон, иначе `422 template_not_found`;
2. связь без конфигурации, оставшуюся в стабильной таблице, восстановить и не создавать заново;
3. разложить шаблоны в черновик; при нехватке метаданных или токенов — `422 template_metadata_missing` со списком, транзакция откатывается.

Отдельная ручка `POST /design-systems/{id}/components` отклонена: она дублировала бы смысл существующей.

### Список шаблонов

`GET /api/ds/component-templates` возвращает `{ componentId, name, platform, dependsOn }` по шаблонам, сопоставленным с web-компонентами глобального каталога. Список одинаков для всех проектов; клиент вычитает из него компоненты ДС.

### Клиент

- Состав диалога: скрытые (как сейчас: оформление без связи, любые платформы) и новые (шаблон есть, компонента в ДС нет, только web), пометка у строки.
- Подтверждение вызывает `POST /design-system-components` (для новых — с `fromTemplate: true`); предупреждение о зависимостях берёт `dependsOn` и из шаблонов.
- `hasComponents` оболочки становится `true`, если есть связи, оформления или хотя бы один шаблон, чтобы раздел был доступен в пустой ДС.

    participant Д as Диалог «+»

## Risks / Trade-offs

- [На проде ДС без компонентов, вероятно, из-за неполных метаданных: инициализатор пропустил всё] → поштучная проверка покажет, каких метаданных и токенов не хватает; до выкладки проверить мету прода.
- [Шаблоны покрывают только 63 web-компонента снимка] → новые компоненты из `push` в диалоге не появятся, пока шаблоны не пополнятся; в списке их нет, а не ошибка.
- [Переработка инициализатора затрагивает создание каждой ДС] → тест сравнения результата до и после.
- [Добавление пишет много ревизий в черновик] → проверить, как журнал показывает добавление компонента.

## Migration Plan

Миграций нет. Бэкенд выезжает раньше клиента. Откат клиента безопасен, новые ручки аддитивны.
