# Решение

## Подготовка и проверка

Использовать существующие fixtures собственной ДС и её очистки, TokenValuesApi, PaletteApi и страницы редакторов. Подготовка идёт через публичные API, проверяемые действия — через UI. Для зависимостей используется точный слот Accent Green и связанное семейство textAccent; контрольные группы Status и Syntax выявляют выход изменения за границы группы.

Наблюдение ответа начинается до действия. После успешной записи проверяются UI, независимый GET и повторное открытие. Проверяемые запросы не подменяются. Сравнение значений других тем и платформ включает ревизии, чтобы заметить нежелательные записи.

GET значений токенов возвращает вычисленный цвет в массиве `value`, а исходную ссылку — в `paletteRef`. Проверки сохранения адресов используют ссылку и ревизии; при замене источника отдельно проверяется новый вычисленный цвет. Сравнение содержимого палитры при редактировании токена исключает только вычисляемые счётчики `linkedCount` растяжек и ступеней.

## Ограничения проверки

Авторизация и очистка сохраняют текущие правила набора. Неуспешная ДС остаётся для диагностики. Отдельный запуск выбирает новые сценарии перечислением Jira-ключей через --grep. Пользователь выполняет E2E и подтверждает приёмку; агент выполняет статические проверки, Strictacode, независимое review и FAST/FULL перед архивированием.
