## Purpose

Определяет краткую серверную сводку дизайн-систем для каталога доступных пользователю проектов без загрузки содержимого каждой карточки и без нарушения владения данными сервисами.

## ADDED Requirements

### Requirement: Каталог получает количества одним публичным чтением

Обычный `GET /projects` SHALL возвращать список доступных пользователю проектов с обязательным полем `designSystemCount: Int?` на каждом проекте без параметра включения сводки. Сводка SHALL считать только нетехнические дизайн-системы; отдельная прежняя форма ответа SHALL NOT требоваться.

#### Scenario: Пользователь имеет несколько проектов
- **WHEN** пользователь запрашивает каталог с количеством для 1, 10 или 50 проектов
- **THEN** клиент MUST выполнить один публичный запрос списка
- **THEN** ни клиент, ни сервер MUST NOT делать отдельное полное чтение дизайн-систем для каждого проекта
- **THEN** подтверждённое отсутствие нетехнических систем MUST возвращаться как ноль

#### Scenario: Каталог пуст
- **WHEN** у пользователя нет доступных проектов
- **THEN** ответ MUST быть пустым списком без обращения к сервису дизайн-систем за количествами

### Requirement: Сводка не расширяет доступ к проектам

Набор проектов сводки SHALL определяться сервером по действующей авторизации списка проектов. Доступ к количествам SHALL NOT предоставляться по присланному браузером списку чужих идентификаторов или одному ключу проекта.

#### Scenario: Пользователь видит только часть проектов
- **WHEN** в хранилище существуют проекты, недоступные пользователю
- **THEN** публичный каталог MUST NOT включать их идентификаторы или количества

#### Scenario: Каталог запрошен ключом проекта
- **WHEN** запрос пользовательского каталога содержит только project access key
- **THEN** шлюз MUST отклонить запрос согласно прежнему контракту user-scoped доступа

### Requirement: Сводка использует прикладные границы монолита

Подсистема projects SHALL получать количества через application-порт и in-process адаптер app/data, вызывающий прикладной интерфейс DS. DS SHALL выполнять группировку в своей явно выбранной БД пакетами до 500 ID. Новый внутренний HTTP-маршрут и секрет SHALL NOT требоваться; прямой доступ projects к таблицам DS SHALL NOT допускаться.

#### Scenario: Запрошено много проектов
- **WHEN** каталог содержит N доступных проектов
- **THEN** подсчёт MUST использовать не более ceil(N/500) пакетных группировок без полных объектов ДС
- **THEN** набор ID MUST происходить из авторизованного списка projects

#### Scenario: Собирается монолит
- **WHEN** app связывает подсистемы
- **THEN** адаптер MUST подключаться через DI без override регистраций и доступа к data другой подсистемы
- **THEN** публичный API MUST NOT получать альтернативный маршрут произвольного подсчёта чужих проектов

### Requirement: Отказ сводки не скрывает доступные проекты

Недоступность агрегата SHALL возвращать `null` вместо неизвестных количеств, сохраняя список проектов. Ошибка SHALL NOT запускать резервный N+1 или подставлять ложный ноль.

#### Scenario: Не удалось чтение DS
- **WHEN** пакетная группировка завершилась ошибкой
- **THEN** пользователь MUST увидеть доступные проекты с неизвестными количествами
- **THEN** клиент MUST NOT самостоятельно запрашивать полные списки для восстановления счётчиков

#### Scenario: Ошибка затронула только один пакет
- **WHEN** часть пакетов уже успешно прочитана
- **THEN** подтверждённые количества MUST сохраняться, а неизвестные MUST оставаться `null`

#### Scenario: Запрос отменён
- **WHEN** выполнение каталога отменено
- **THEN** отмена MUST распространяться по существующему механизму и MUST NOT подменяться успешным списком с null
