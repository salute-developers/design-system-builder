# Первая волна регрессионных UI E2E

## Зачем

Текущий набор проверяет проекты, создание тем и часть журнала, но не подтверждает
сохранение пользовательских правок в редакторах и изоляцию соседних данных.
Первая волна добавляет десять наиболее полезных для релиза кейсов: сохранение,
переход к источнику, откат и неизменяемость опубликованной версии.

## Что меняется

- В `tests/ROADMAP.md` фиксируются реализованные 10 тестов и очередь волн по
  10 новых кейсов с Jira-key, приоритетом и ссылкой на задачи. Статусы выполнения
  активной волны ведутся в `tasks.md`; рабочие блоки остаются по 1–2 теста.
- Добавляются независимые UI-проверки T784, T791, T647, T560, T782, T776, T604,
  T742, T750 и T793 с полными согласованными проверками каждого кейса.
- Под конкретные сценарии расширяются Page Objects, API-подготовка и fixtures;
  перед реализацией проверяются актуальные экраны через Playwright.
- Очистка учитывает несколько начатых записей одного теста; текущая защита
  неизвестного исхода и отсутствие автоматических повторов мутаций сохраняются.
- Реализация идёт блоками по 1–2 кейса; новые сценарии проверяются отдельно,
  итоговый прогон и Strictacode выполняются при завершении волны.

## Возможности

### Новая возможность

- `web-ui-e2e-data-integrity`: браузерные регрессионные проверки сохранения,
  изоляции, адресного отката и опубликованного снимка DS Builder.

### Изменяемые возможности

Нет. Требования к поведению продукта, публичные API и права доступа не меняются.
При расхождении кейса с текущим UI реализация зависимого сценария останавливается
для согласования, без исправления приложения ради прохождения теста.

## Влияние

Изменяется только `js/apps/client`: тесты, общие методы, страницы, подготовка
данных и документация. Используется фундамент из коммита `5a2525b7` и Change
`add-web-ui-e2e-testing`; его открытый общий этап проверки не закрывается этим
изменением автоматически.

Backend, frontend-kt, Docker, миграции, зависимости, продуктовый код, Strictacode
policy и baseline остаются прежними. Стенд и общий E2E-проект сохраняются;
каждый сценарий получает собственную ДС. Роли Editor/Viewer, новые метки наборов
и остальные волны выполняются отдельно. Новые тесты не реализуются до
согласования подготовленных артефактов.
