## Context

Раздел «Компоненты» входит в редактор темы (`.../themes/:tenantId/components/:componentName?`) и состоит из трёх
частей: кнопка `editor-nav-components` в `Main.tsx`, маршрут в `App.tsx` и загрузка конфигураций компонентов
(`ThemeEditorRepository.load`, а при заданном адресе плагина ещё и Compose-конфигурации). Другие входы в раздел
(старый маршрут `:designSystemProjectId/:designSystemName/:designSystemVersion/*`) ведут в тот же маршрут через
`LegacyThemeRedirect`.

Клиент собирается Vite; переменные `VITE_*` подставляются при сборке. DEV и PROM собираются разными workflow
(`deploy-front-apps-dev.yml` и `deploy-front-apps-prom.yml`) со своими значениями переменных.

## Goals / Non-Goals

**Goals:** один выключатель на этапе сборки; PROM по умолчанию не получает раздел; DEV и локальная разработка не
меняются.

**Non-Goals:** флаги во время работы, флаги по пользователям или проектам, отключение на стороне backend, флаг для
остальных разделов, переработка системы конфигурации клиента.

## Decisions

1. **Имя и значение.** `VITE_COMPONENT_EDITOR_ENABLED`; включает только значение `true`. Без значения решает режим
   сборки: dev-сервер включает раздел, production-сборка выключает. Забытая переменная на PROM не открывает раздел, а
   локальная разработка не требует настройки. Файл `.env.development` не используется: в репозитории `.env.*`
   игнорируются (трекаются только `*.example`).
2. **Один модуль.** `isComponentEditorEnabled()` в `src/utils/featureFlags.ts` читает `import.meta.env` при вызове, чтобы
   тесты могли подменять значение, а остальной код не знал о формате переменной.
3. **Что скрывается.** Кнопка раздела, маршрут (`ComponentsRoute` перенаправляет на `colors`, а не открывает пустую
   страницу) и запросы конфигураций в обоих путях загрузки (`ThemeEditorRepository.load` и `loadDesignSystem`). Запросы
   отключаются, потому что при выключенном разделе их результат никому не нужен, а сбой
   `component-configs` на PROM не должен ломать остальные разделы.
4. **Где задаётся значение.** Для DEV и PROM — литералами в workflow (`'true'` и `'false'`). Локально — умолчание dev-сервера
   и `true` в `js/docker-compose.dev.yml`. Сборка в CI проверки (`validate-js.yml`) идёт без значения, то есть с
   выключенным разделом; тесты работают в режиме dev и включают раздел по умолчанию, а проверки флага подменяют значение.

## Risks / Trade-offs

- Забытое значение в новом окружении выключает раздел; это сознательный выбор в пользу PROM.
- Ссылка на раздел, сохранённая у пользователя, ведёт на `colors`, а не на ошибку.
- `hasComponents` и `Debug` используют список компонентов; при выключенном флаге он пуст, и поведение должно остаться
  корректным (проверяется тестами).

## Решено при согласовании

- Значения в workflow задаются литералами, а не переменными GitHub.
- Запросы конфигураций отключаются вместе с интерфейсом.
