## ADDED Requirements

### Requirement: Заголовок записи компонента называет изменённую сущность

Заголовок записи журнала о структурной сущности компонента SHALL называть эту сущность и её имя, а не только компонент:

- стиль вариации — «Создание стиля «<стиль>» вариации «<вариация>» компонента «<компонент>»»;
- подключение стиля к конфигурации без пары — «Перемещение стиля «<стиль>» в вариации «<вариация>» компонента «<компонент>»» при изменении места, «Добавление стиля «<стиль>» в конфигурацию компонента «<компонент>»» при создании, «Исключение стиля …» при удалении;
- вариация — «Создание вариации «<вариация>» компонента «<компонент>»»;
- подключение вариации к конфигурации без пары — «Подключение вариации «<вариация>» к конфигурации «<конфигурация>» компонента «<компонент>»»;
- конфигурация — «Создание конфигурации «<конфигурация>» компонента «<компонент>»»;
- связь компонента с дизайн-системой — «Добавление компонента «<компонент>» в дизайн-систему», удаление — «Скрытие компонента «<компонент>»»;
- значение свойства — «Создание/Изменение/Удаление значения свойства компонента «<компонент>»»;
- платформенная корректировка значения — «… платформенного параметра компонента «<компонент>»».

Для операций изменения и удаления глагол SHALL меняться соответственно. Остальные сущности компонента сохраняют заголовок «<Операция> компонента «<компонент>»». Неизвестное имя MUST пропускаться вместе с поясняющим словом без вывода идентификаторов. Поле `position` подключения SHALL подписываться «Место в списке» и показываться с отсчётом от единицы.

Записи одного действия SHALL склеиваться в одну строку журнала, если они созданы или удалены одним автором:

- `style` и `appearance-variation-value` с тем же стилем — «Добавление стиля «<стиль>» в вариацию «<вариация>» компонента «<компонент>»» с полем «Стиль»; удаление — «Удаление стиля «<стиль>» из вариации …»;
- `variation` и `appearance-variation` с той же вариацией — «Добавление вариации «<вариация>» в компонент «<компонент>»» с полями «Вариация» и «Стиль по умолчанию»; удаление — «Удаление вариации …».

Отмена склеенной строки MUST откатывать обе записи: для созданной пары сначала подключение, затем сущность; для удалённой — наоборот.

#### Scenario: Добавлен стиль вариации

- **WHEN** пользователь добавил стиль `xxxs` в вариацию `size` компонента `Button`, и сервер записал создание `style` и `appearance-variation-value`
- **THEN** журнал MUST показать одну строку «Добавление стиля «xxxs» в вариацию «size» компонента «Button»» с полем «Стиль»: «Не задано» → `xxxs`
- **THEN** поля «Порядок», «Позиция» и «Место в списке» MUST NOT показываться в этой строке
- **THEN** отмена строки MUST сначала отменить подключение, затем создание стиля

#### Scenario: Стиль переставлен в списке

- **WHEN** изменилось только место стиля `xxxs` в списке вариации `size` с `6` на `2`
- **THEN** запись MUST иметь заголовок «Перемещение стиля «xxxs» в вариации «size» компонента «Button»» с полем «Место в списке»: `7` → `3`

#### Scenario: Добавлена вариация

- **WHEN** сервер записал создание `variation` `size` и её подключение `appearance-variation` со стилем по умолчанию `m`
- **THEN** журнал MUST показать одну строку «Добавление вариации «size» в компонент «Button»» с полями «Вариация» и «Стиль по умолчанию»

#### Scenario: Компонент добавлен в дизайн-систему

- **WHEN** создана связь компонента `Button` с дизайн-системой
- **THEN** запись MUST иметь заголовок «Добавление компонента «Button» в дизайн-систему»

#### Scenario: Имя вариации неизвестно

- **WHEN** у записи стиля нет известного имени вариации
- **THEN** заголовок MUST быть «Создание стиля «xxxs» компонента «Button»»
