## Why

Журнал подписывает любую запись о компоненте одним шаблоном: «Создание/Изменение/Удаление компонента «Button»». Добавление стиля `xxxs` в вариацию `size` выглядит как две записи «Создание компонента «Button»» с полями «Название → xxxs» и «Позиция → 6». Пользователь видит «создание компонента», хотя компонент он не создавал, и не может понять, что именно произошло.

Одно действие редактора порождает несколько записей разных сущностей:

- `style` — сам стиль (`xxxs`) вариации;
- `appearance-variation-value` — подключение стиля к конфигурации компонента;
- аналогично для вариаций: `variation` и `appearance-variation`.

Имена стилей, вариаций и конфигураций журнал уже загружает.

## What Changes

Заголовок записи называет сущность, а не только компонент:

| Сущность | Заголовок |
|---|---|
| `style` | «Создание стиля «xxxs» вариации «size» компонента «Button»» |
| `appearance-variation-value` | «Подключение стиля «xxxs» к вариации «size» компонента «Button»» (удаление — «Отключение …», изменение — «Изменение стиля … в конфигурации») |
| `variation` | «Создание вариации «size» компонента «Button»» |
| `appearance-variation` | «Подключение вариации «size» к конфигурации «default» компонента «Button»» |
| `appearance` | «Создание конфигурации «default» компонента «Button»» |
| `design-system-component` | «Добавление компонента «Button» в дизайн-систему» (удаление — «Скрытие компонента «Button»») |
| `variation-property-value`, `invariant-property-value` | «Создание/Изменение/Удаление значения свойства компонента «Button»» |
| платформенные корректировки значений | «… платформенного параметра компонента «Button»» |

Дополнительно:

- Парные записи одного действия склеиваются в одну строку журнала:
  - создание стиля и его подключение к конфигурации — «Добавление стиля «xxxs» в вариацию «size» компонента «Button»» с полем «Стиль: Не задано → xxxs»;
  - удаление стиля и его отключение — «Удаление стиля «xxxs» из вариации «size» компонента «Button»»;
  - создание вариации и её подключение к конфигурации — «Добавление вариации «size» в компонент «Button»» с полями «Вариация» и «Стиль по умолчанию»; удаление — «Удаление вариации …».

  Отмена такой строки откатывает обе записи в безопасном порядке. Журнал уже умеет отменять несколько записей одной строкой.
- Подключение без пары (например, стиль переставили в списке) остаётся отдельной строкой: «Перемещение стиля «xxxs» в вариации «size» компонента «Button»». Поле «Место в списке» показывается с отсчётом от единицы вместо технического «Порядок» с отсчётом от нуля.
- Остальные сущности компонента сохраняют прежний заголовок «… компонента «Button»».
- Неизвестные имена пропускаются: например, «Создание стиля вариации «size» компонента «Button»».
- Переход к источнику не меняется. Отдельные записи по-прежнему отменяются сами, а склеенные — обе вместе.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities
- `design-system-version-journal-ui`: появляется требование называть в заголовке записи изменённую структурную сущность компонента.

## Impact

- `js/apps/client`: `features/versionJournal/journalPresenter.ts` (заголовки), `journalFields.ts` (подпись `position`), тесты презентера.
- `backend-kt`, `frontend-kt`: не затрагиваются.
