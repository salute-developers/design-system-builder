## Why

Сейчас MCP и project-scoped команды CLI в основном зависят от локальной `.sdds/config.json`: пользователь не может просто передать ссылку на дизайн-систему и работать с ней из произвольной директории. Авторизация также непоследовательна: часть команд поддерживает пользовательскую session, а публикация и некоторые операции с моделью требуют project key. Это мешает потребительским и headless-сценариям и делает выбор действующего credential неочевидным.

## What Changes

- Ввести переносимую ссылку на дизайн-систему и общее разрешение явного `projectId`/`designSystemId`/`version`/`platform` для CLI и MCP без обязательной `.sdds`. Ссылка выбирает ресурс, но не является credential и не переключает backend API URL.
- Позволить агенту передавать ссылку в MCP tools без привязки MCP server к одной дизайн-системе при запуске. Контекст одного чата/вызова не должен менять контекст других чатов в том же процессе. Сохранить существующий workspace-сценарий.
- Дать project-scoped CLI-командам явный выбор дизайн-системы по ссылке из произвольной директории. Команды, которым нужны локальные исходники или артефакты, по-прежнему требуют соответствующий локальный путь.
- Расширить `.sdds/config.json` явной политикой авторизации: `auto`, только пользовательская session или только project key из указанной env-переменной. Существующие конфиги с `credential.type = "env"` сохранить совместимыми с нынешним поведением `auto`: доступный key имеет приоритет, при его отсутствии используется session. Не переключать actor после `401`/`403`.
- Поддержать пользовательскую session во всех CLI-командах, которым требуется backend-авторизация, включая публикацию и операции с токенами/компонентами. Не сохранять пароль, key или токены в `.sdds` либо в ссылке; backend остаётся источником истины для прав пользователя и scopes ключа.
- Для отсутствующего, неоднозначного, некорректного или недоступного контекста возвращать явную диагностическую ошибку. Явная неверная ссылка не должна незаметно заменяться контекстом текущей директории; version/platform не должны угадываться.

## Capabilities

### New Capabilities

- `design-system-context-links`: переносимый идентификатор дизайн-системы, его разрешение, валидация и правила выбора явного контекста без локального workspace.

### Modified Capabilities

- `frontend-mcp-server`: явный контекст в read tools, независимость от `.sdds` и изоляция параллельных вызовов разных дизайн-систем.
- `frontend-cli`: выбор дизайн-системы по ссылке для project-scoped команд и единое применение выбранной политики авторизации.
- `cli-core`: расширение формата `.sdds/config.json`, разрешение контекста и credential policy с обратной совместимостью.
- `frontend-client-authentication`: режимы `auto`/session/project key, отсутствие fallback после отказа backend и поддержка session во всех авторизованных CLI-операциях.
- `documentation-bundle-cli-publishing`: публикация с пользовательской session в дополнение к project key.
- `cli-themes`: авторизованные команды для тем и токенов принимают выбранный тип credential.
- `cli-components`: авторизованные команды для компонентов принимают выбранный тип credential.

## Impact

- `frontend-kt/core-application`, `core-domain`, `core-workspace`, `core-auth`: общий контекст, формат credential reference/policy и выбор runtime credential без хранения секретов в проектном конфиге.
- `frontend-kt/cli`, `mcp-server-core`, `mcp-node` и авторизованные `feature-*`: входные параметры, передача контекста и credential, диагностика и тесты сценариев с session/project key.
- Backend authorization и `js/apps/client` остаются вне scope этого change. CLI/MCP используют существующие project-scoped gateway routes; найденные ограничения backend фиксируются аудитом без изменения серверного кода.
- `openspec/architecture/ADR-0005-frontend-local-context-auth.md` и затронутые capability specs: согласовать архитектурное описание с выбранной моделью контекста и авторизации.
