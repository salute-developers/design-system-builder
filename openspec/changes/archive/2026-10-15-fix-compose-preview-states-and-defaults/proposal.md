## Why

Замечания к Compose-превью, у которых нашлись причины:

- **`pressed` не меняет цвет.** Конфигурация хранит состояния в порядке Android (`ColorStateList`: побеждает первое совпадение,
  `pressed` перед `hovered`), а протокол отдаёт победу последней записи при равенстве. Клиент порядок не разворачивает, поэтому
  при зажатой мышке над компонентом (активны `pressed` и `hovered`) выигрывает `hovered`. Читающий маршрут `legacy.ts` при этом не
  сортирует значения состояний по `position`.
- **Вложенные стили не применяются, пока не выберешь вид.** У вариации без стиля по умолчанию (`view` у `TabBar` и `Segment`) в
  выборе нет стиля, и сочетание «размер × вид», из которого берётся стиль айтемов (`tabBarItemStyle`, `segmentItemStyle`),
  не совпадает. Редактор подставляет стиль только при открытии вкладки вариации.
- **Числа с точкой нельзя ввести.** Поле числового свойства показывает `String(value)`, и `0.` превращается в `0`.
- **Состояния инвариантов теряются.** `component-configs` отдаёт только базовые значения инвариантов: значения их состояний
  (например, `checked` у `toggleColor` RadioBox) отфильтрованы, поэтому выбранный RadioBox белый, а не зелёный.
- **Вспомогательные элементы историй не стилизованы.** Android-песочница оборачивает истории в тему со стилями по умолчанию
  (`LocalButtonStyle`, `LocalSwitchStyle`, `LocalSpinnerStyle`) и текстом по умолчанию (`ProvideTextStyle`). В плагине этого нет:
  кнопки «Show …», Switch и подписи в историях `DropZone`, `FormItem`, `Popover`, `TextArea`, `DropdownMenu` рисуются стилем
  библиотеки, текст чёрным на тёмном. Стили должна определять тема дизайн-системы, поэтому их собирает клиент.

## What Changes

- Клиент разворачивает порядок состояний при сборке payload (первое по конфигурации становится последним), `legacy.ts` отдаёт
  значения состояний в порядке `position`.
- Редактор подставляет первый стиль вариации без стиля по умолчанию при открытии компонента (не для флагов).
- `legacy.ts` отдаёт значения состояний инвариантов вместе с базовым значением (`states`).
- Числовое поле хранит введённый текст отдельно от значения.
- Payload получает необязательный раздел `defaults`: стиль и цвет текста по умолчанию (токены темы) и стили `button`, `switch`,
  `spinner` (ссылки на стили в `styles`). Клиент собирает его из темы дизайн-системы (по образцу песочницы: `basic-button.m.default`,
  `switch.s`, `spinner.xs.default`, `body.m.normal`, `text.default.primary`); плагин задаёт по нему `Local*Style` и текст
  (парный change `apply-host-defaults-in-plugin`).

## Capabilities

### New Capabilities

- `compose-preview-states-and-defaults`: приоритет состояний, выбор по умолчанию, числовой ввод и стили по умолчанию превью.

### Modified Capabilities

Нет.

## Impact

- `js/services/db-service`: `routes/api/legacy.ts` (порядок), тест маршрута.
- `js/apps/client`: `composePreview` (`assembler.ts`, `draft.ts`, типы, схема payload), `hooks/useComponentData.ts`, `ComponentEditorPreview`, тесты.
- `backend-kt/preview/contract`: схема payload и `README.md` (раздел `defaults`, порядок состояний).
- `plasma-android`: контракт, SDK и плагин (парный change).
- В плагине история `SelectItem` получает содержимое disclosure: без него переключатель `disclosureEnabled` ничего не рисовал.
