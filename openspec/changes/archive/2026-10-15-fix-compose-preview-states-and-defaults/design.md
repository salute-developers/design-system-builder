## Context

`PreviewPropertyValue.states` в протоколе: при нескольких подходящих записях выигрывает та, у которой больше имён состояний,
при равенстве последняя. UIKit и Android выбирают первую подходящую запись. SDK уже разворачивает порядок для UIKit
(`toStateful`), значит записи payload должны идти в порядке «последняя побеждает».

## Проверено

- `BasicButton.backgroundColor`: состояния `[pressed → #F5F5F5, hovered → #FFFFFF]`; при зажатой мышке над кнопкой экран
  показывает `#FFFFFF` (цвет `hovered`), ожидается `#F5F5F5`.
- `variation_property_values` хранит `position`, а `legacy.ts` читает их без `ORDER BY`.
- `TabBar.view` и `Segment` не имеют стиля по умолчанию (`appearance_variations.default_style_id` пуст), а `tabBarItemStyle` и
  `segmentItemStyle` хранятся только как сочетания (48 и 30 записей); в payload открытого компонента `styles` пуст.
- Песочница: `SandboxTheme.kt` задаёт `LocalButtonStyle = BasicButton.M.Default`, `LocalSwitchStyle = Switch.S`,
  `LocalSpinnerStyle = Spinner.Xs.Default`, `SddsSandboxTheme` задаёт `ProvideTextStyle(bodyMNormal + textDefaultPrimary)`.

- Маршрут `component-configs` читает инварианты с фильтром `stateSetId = сентинел`: значения состояний инвариантов (у `RadioBox`
  `toggleColor` и `toggleBorderColor` для `checked`) не попадают в ответ, хотя в базе они есть.
- `SelectItemStory` передаёт `disclosureEnabled`, но не `disclosureContent`; `SelectItem` рисует только переданное содержимое.

## Decisions

1. **Порядок состояний.** Ассемблер отдаёт записи `states` в обратном порядке конфигурации, так что запись, которую Android
   выбрал бы первой, в payload последняя и выигрывает при равенстве. Это касается всех свойств, включая вложенные стили.
2. **Состояния инвариантов.** `legacy.ts` читает все значения инвариантов, отдаёт базовое значение как `value`, а значения состояний
   как `states` (имена состояний, `alpha`) в порядке `position`; `outerProps` и прочее по-прежнему используют только базовые строки.
3. **Порядок в API.** `legacy.ts` сортирует значения вариаций по `position`, чтобы порядок конфигурации не зависел от порядка
   строк в базе.
4. **Выбор по умолчанию.** `getDefaultProps` добавляет первый стиль каждой вариации без стиля по умолчанию, кроме флагов
   (`isFlag()`: выключенный флаг означает отсутствие аргумента).
5. **Числовой ввод.** Свойство хранит значение, а поле показывает введённый текст (`0.`, `-`, пустое): значение обновляется, когда текст
   разбирается в число. Текст сбрасывается при смене описания компонента.
6. **`defaults` в payload.** Необязательный объект `{ text?: { style?: tokenId, color?: tokenId }, styles?: { button?, switch?,
   spinner? } }`; значения `styles` — идентификаторы из `styles` (стили компонентов `BasicButton`, `Switch`, `Spinner`), токены попадают
   в замыкание `theme`. Версия протокола не меняется.
7. **Источник значений по умолчанию — тема.** Клиент разворачивает ссылки `basic-button.m.default`, `switch.s`,
   `spinner.xs.default` по конфигурациям дизайн-системы и токены `body.m.normal`, `text.default.primary`; если чего-то нет в
   теме, соответствующий элемент `defaults` не добавляется, а плагин оставляет значения библиотеки.

## Risks / Trade-offs

- Разворот порядка меняет вид всех свойств с несколькими состояниями при совпадении (например, `pressed` вместо `hovered`);
  это соответствует Android.
- Стили по умолчанию увеличивают payload на три вложенных стиля.
- Ссылки по умолчанию (`basic-button.m.default` и другие) завязаны на имена конфигураций дизайн-системы; для других дизайн-систем
  они могут не найтись, тогда превью не стилизует эти элементы.
