## Why

`dsbuilder components import-api` заводит **глобальный** слой компонентной модели: компоненты, свойства, состояния и платформенные имена, общие для всех дизайн-систем всех проектов. Сегодня её вызывает любой владелец ключа проекта со scope `components:write` через проектный маршрут. Ключ одного проекта получает право писать в данные, на которые опираются чужие дизайн-системы; полагаться при этом остаётся только на аккуратность владельца ключа.

Эта операция по смыслу административная: меты платформ выпускает команда DS Builder, а не проекты. Кроме того, текущий способ получения меты (запуск Gradle в проекте пользователя и чтение файла из артефакта uikit) оказался тяжёлым и не нужен администратору, у которого файл меты уже есть: он собирает его из plasma-android или скачивает вместе с релизом.

## What Changes

- **Только системный администратор.** Ручка переезжает на административный маршрут `POST /api/admin/component-config/import-api-meta`, который gateway пропускает только по токену пользователя (ключ проекта отсекается на входе), а `db-service` дополнительно требует `X-System-Admin: true` и отвечает `403` во всех остальных случаях. Признак — realm-роль Keycloak `system_admin`, которую gateway превращает в доверенный заголовок. Проектный маршрут `.../ds/component-config/import-api-meta` удаляется. **BREAKING**: вызовы с ключом проекта перестают работать.
- **Нет привязки к дизайн-системе.** Из запроса, отчёта и вывода уходят `designSystemId`, `createdLinks` и строка «Linked to the design system»; импорт больше не создаёт строк `design_system_components`.
- **Журнал изменений без дизайн-системы.** Импорт по-прежнему записывается в `design_system_changes`: колонка `design_system_id` становится необязательной (миграция), глобальная операция пишется со значением `NULL`, в `data` попадают пользователь, платформа и счётчики. В ленты дизайн-систем такие записи не попадают.
- **Мета из файла.** CLI получает `--from <путь к файлу>` и читает его напрямую. Запуск Gradle, поиск `gradlew`, `--tool` и capability `API_META` платформенных делегатов удаляются вместе со спеками.
- **CLI не зависит от проекта.** Команде не нужны `.sdds/config.json`, `projectId`, `designSystemId`; платформа задаётся `--platform`, URL — `--api-url`. Credential — только user session (`dsbuilder auth login`), ключи проекта и `--api-key` не принимаются.
- **Понятная причина отказа.** При `401` и `403` CLI дописывает к сообщению текст ошибки из ответа backend, чтобы «нужна роль системного администратора» не выглядело как «нет доступа к проекту».

Не входит: платформы `swiftui` и `react`; проверка роли на стороне CLI (источник истины — сервер); защита остальных `/api/admin/*` маршрутов `db-service`, которые сегодня тоже не проверяют роль (отдельная задача).

## Capabilities

### New Capabilities
Нет.

### Modified Capabilities
- `component-api-meta-import`: маршрут и ограничение «только системный администратор», манифест и отчёт без дизайн-системы и привязок, запись журнала без дизайн-системы.
- `cli-components`: источник меты из файла, user session вместо ключа проекта, команда без проекта, причина отказа из ответа.
- `cli-platform-delegates`: из контракта делегата уходит capability `API_META`.
- `platform-android-delegate`: удаляется поддержка `API_META` и Gradle-задач `readUikitComposeApiMeta` / `readUikitApiMeta`.

## Impact

- **js/db-service**: новый маршрут под `/admin/component-config`, middleware `requireSystemAdmin`, удаление проектного маршрута, схема манифеста без `designSystemId`, запись без привязок, журнал с `design_system_id = NULL`, **новая миграция** (`ALTER COLUMN design_system_id DROP NOT NULL`), правки `schema.ts`, `docs/db-schema.dbml`, `nl-query/schema-context.ts`, регенерация OpenAPI и типов админки (`/sync-all`), тесты `vitest`.
- **frontend-kt**: `core-platform` (удаление `API_META`), `platform-android` и `platform-ios` (ветки `when`), `feature-components` (чтение файла вместо делегата, use case без проекта и привязки, user session), `cli` (`--from`, `--platform`, удаление `--tool` и `--api-key`), `core-network` (причина отказа при `401`/`403`), тесты и `cli/USAGE.md`.
- **backend-kt**: gateway уже содержит маршрут `/api/admin` (локальный и prod-конфиг); правка нужна только для размера тела (сейчас общий лимит 2 МБ, манифест может его приближать).
- **Конфигурация**: новых переменных нет. Администратору нужна user session (`dsbuilder auth login --api-url …`) на том же API URL, который передаётся команде.
- **Совместимость**: выпущенные CLI с проектным маршрутом получат `404`; обновлять CLI и backend нужно вместе.
