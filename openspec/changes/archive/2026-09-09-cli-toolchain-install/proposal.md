## Why

`dsbuilder` умеет делегировать генерацию платформенному инструменту, но не умеет его ставить.
Сейчас `dsbuilder-ios` приходится собирать из исходников или скачивать релиз вручную, а потом
объяснять CLI, где он лежит, через `DSBUILDER_IOS_TOOL` или `--tool`. На ревью решили паковать
архив со всеми зависимостями и ставить его install-командой.

Инструменты остаются независимыми артефактами: Kotlin CLI не вшивает в себя Swift-бинарь,
а забирает опубликованный релиз и кладёт его туда, где `doctor` его уже ищет.

## What Changes

- Новый порт `ToolchainInstaller` и реестр установщиков рядом с `PlatformDelegate`.
- Команда `dsbuilder toolchain install <toolchain>`: ставит инструмент в
  `~/.dsbuilder/toolchains/<toolchain>/<version>/` и переставляет симлинк `current`,
  на который уже смотрит locator.
- `--version <tag>` ставит конкретный релиз, без опции берётся последний;
  `--from <path|url>` ставит готовый архив, не ходя в сеть.
- `IosToolchainInstaller`: релиз из GitHub Releases plasma-ios, ассет `dsbuilder-ios-cli-*.zip`
  (бинарь и `ios-api-meta.json` рядом).
- Минимальная версия по-прежнему не проверяется: у инструмента одна опубликованная линия.

Затронуто: только `frontend-kt`. `backend-kt` и `js` не затронуты.
