## Purpose

Определяет выпуск согласованных дистрибутивов DS Builder CLI и воспроизводимую установку из сети либо локального архива.

## ADDED Requirements

### Requirement: Четыре дистрибутива одного выпуска

Выпуск CLI SHALL содержать архивы macOS arm64, macOS x64, Windows x64 и JVM с одним номером версии и SHA-256 каждого архива.

#### Scenario: Выпуск по тегу
- **WHEN** отправлен тег `cli-v1.2.3` либо вручную выбран существующий тег такого формата
- **THEN** выпуск MUST содержать `dsbuilder-cli-macos-arm64.zip`, `dsbuilder-cli-macos-x64.zip`, `dsbuilder-cli-windows-x64.zip`, `dsbuilder-cli-jvm.zip` и `SHA256SUMS`
- **THEN** каждый CLI MUST сообщать `1.2.3` через `--version`

#### Scenario: Неправильный тег
- **WHEN** ручной запуск задаёт отсутствующий тег или значение вне формата `cli-vX.Y.Z`
- **THEN** выпуск MUST завершиться ошибкой до публикации

### Requirement: Публикация полного комплекта

Workflow SHALL загружать версионные артефакты в S3 и обновлять указатель стабильного выпуска только после проверки полного комплекта. JVM-архив SHALL сохраняться в GitHub Releases под существующим именем.

#### Scenario: Конфигурация доставки
- **WHEN** запускается публикация
- **THEN** endpoint, bucket, регион и credentials S3 MUST использовать существующие GitHub secrets публикации клиента, а отдельный префикс CLI MUST поступать из окружения workflow
- **THEN** публичный HTTPS-адрес MUST задаваться отдельно через `CLI_DOWNLOAD_BASE_URL`
- **THEN** скачивание MUST NOT требовать backend API или S3 credentials

#### Scenario: Частичный сбой
- **WHEN** сборка, проверка или загрузка одного архива завершилась ошибкой
- **THEN** `stable.json` MUST остаться на предыдущем полном выпуске

#### Scenario: Повторная публикация
- **WHEN** каталог версии уже содержит файл с другой SHA-256
- **THEN** публикация MUST завершиться ошибкой без замены файла
- **THEN** совпадающие файлы MUST допускать безопасное продолжение прерванной загрузки

### Requirement: Сетевые установщики

Сетевые shell и PowerShell установщики SHALL выбирать последнюю стабильную либо явно указанную версию, проверять SHA-256 архива и вызывать локальный установщик. Они SHALL устанавливать нативный CLI по умолчанию и JVM только при явном выборе.

#### Scenario: Выбор платформы
- **WHEN** установщик запущен на macOS arm64/x64 либо Windows x64
- **THEN** он MUST выбрать соответствующий нативный архив
- **WHEN** явно выбран JVM
- **THEN** он MUST проверить наличие Java 17 или новее без автоматической установки Java

#### Scenario: Ошибка загрузки или проверки
- **WHEN** архив недоступен, SHA-256 не совпала, платформа не поддерживается или необходимый инструмент отсутствует
- **THEN** установщик MUST завершиться с ненулевым кодом и понятной причиной до изменения установленного CLI

#### Scenario: Перенаправление загрузки
- **WHEN** сервер отвечает HTTP-редиректом при загрузке stable.json, контрольных сумм или архива
- **THEN** установщик MUST NOT обращаться по адресу Location и MUST завершиться ошибкой
- **THEN** установленный CLI MUST остаться неизменным

#### Scenario: Адрес загрузки
- **WHEN** workflow публикует сетевые установщики
- **THEN** они MUST содержать настроенный публичный адрес без S3 credentials
- **THEN** переопределение `CLI_DOWNLOAD_BASE_URL` MUST поддерживаться для проверки и локального контура

### Requirement: Локальная установка без сети

Каждый архив SHALL содержать локальный установщик, работающий без скачивания. Локальный контур SHALL переиспользовать этот уровень установки; установка SHALL поддерживать пользовательский каталог без административных прав.

#### Scenario: Готовые локальные файлы
- **WHEN** локальный установщик получает распакованный дистрибутив без доступа к сети
- **THEN** он MUST установить CLI и обеспечить команду через ссылку либо пользовательский PATH
- **THEN** повторная установка MUST NOT дублировать запись PATH

#### Scenario: Каталог с пробелами
- **WHEN** архив и каталог установки имеют пробелы в пути
- **THEN** локальная установка MUST сохранить работоспособную команду и остальные файлы пользователя
