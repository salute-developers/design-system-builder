## Context

Экран токенов плагина Android Studio (`ui/MainScreen.kt`, `ui/TokenList.kt`) состоит из блоков, которые компонуются друг под другом:

```
Breadcrumbs        padding(h = 4x, v = 2x)
ModeSwitch (Tabs)  padding(h = 4x, v = 2x)   ← MainScreen.kt, TokensStep
TokenTypeTabs      padding(h = 4x, v = 2x)   ← TokenList.kt
TokenSearchField   padding(h = 4x, v = 2x)   ← TokenList.kt
LazyColumn токенов
```

Каждый блок сам добавляет себе вертикальный отступ, поэтому между блоками получается 4x, а над первым и под последним 2x; к этому добавляются собственные высота и отступы `Tabs`. Режим и типы живут в разных composable (`TokensStep` и `TokenList`), так что единого места, где задаётся ритм, нет.

Оба переключателя выбирают одно значение из небольшого набора, то есть это `Segment`, а не `Tabs`. `SegmentHorizontal` и `SegmentItem` есть в `sdds-uikit-compose` 0.51.0, стили `Segment.{Xs,S,M,L,Xl}.{Primary,Secondary,Accent}` (и `.Pilled`) — в `sdds-serv-compose` 0.43.0; обе зависимости уже подключены. `SegmentHorizontal` не имеет `clip`/скролла, в отличие от `Tabs`.

## Goals / Non-Goals

**Goals:**
- Заменить `Tabs`/`TabItem` в `ModeSwitch` и `TokenTypeTabs` на `Segment` из дизайн-системы.
- Ровный вертикальный ритм на экране токенов: один владелец отступов, одинаковый шаг между блоками.
- Убрать обходные приёмы обнуления встроенных отступов `Tabs`/`TabItem`.

**Non-Goals:**
- Менять набор режимов, набор и порядок типов токенов, сохранение выбора в `MainScreenState`.
- Менять `Breadcrumbs`, шаги выбора проекта/дизайн-системы/tenant/платформы и строки токенов.
- Менять существующие требования `ide-plugin-token-browser`; добавляется только требование к фильтрам (см. specs).

## Decisions

**1. Колонка фильтров — единственный владелец вертикального ритма.**
Режим, тип и поиск собираются в одну `Column` с `Arrangement.spacedBy(spacing4x)` и отступом снизу `spacing4x` (сверху `spacing2x`: вместе с нижним отступом хлебных крошек тоже даёт шаг). Значение `spacing2x` по итогам ручной проверки оказалось слишком плотным. У самих блоков остаётся только содержимое: их `padding(vertical = 2x)` убирается. Так шаг между блоками один и тот же, а верхний и нижний отступы группы равны ему.
*Альтернатива:* подобрать `padding` каждому блоку так, чтобы суммы совпали. Отвергнуто: ритм снова зависит от того, какие блоки показаны (вкладка типов скрыта при единственном типе), и ломается при следующей правке.

**2. Колонку фильтров держит `TokenList`, режим приходит слотом.**
`TokenList` получает параметр-слот (например `modeSwitch: @Composable () -> Unit`), который рисуется первым в колонке фильтров; `TokensStep` передаёт туда `ModeSwitch`. Состояние режима остаётся в `MainScreenState`, слот его только отображает.
*Альтернативы:* (а) перенести режим внутрь `TokenList` — тянет за собой `tokenMode`/`onModeChange` в его публичную сигнатуру и логику загрузки токенов, которая от режима зависит в `TokensStep`; (б) поднять типы и поиск в `TokensStep` — размазывает состояние фильтрации по двум уровням. Слот меняет сигнатуру `TokenList` минимально.

**3. Стиль сегмента типов — `Segment.Xs.Primary`.**
Размер стиля (`Xs`, затем `TextFieldS`/`IconButtonS` у соседей) подбирается по высоте в живом плагине, а не подгоняется отступами.
*Альтернатива:* `Pilled`-вариант. Выбор на глаз в плагине, решение не архитектурное.

**4. Сегмент типов — `SegmentHorizontal` внутри `Modifier.horizontalScroll(rememberScrollState())`, `stretch = false`.**
У `SegmentHorizontal` нет собственного скролла, а типов до семи («Типографика», «Градиенты» и т. д.) и панель узкая. Скролл добавляется снаружи. `stretch = false` нужен, чтобы сегмент не растягивался по ширине и брал естественный размер.
*Альтернативы:* оставить `Tabs` только для типов — отвергнуто пользователем; сократить подписи или заменить иконками — продуктовое решение вне этого изменения.

**5. Выбранный пункт всегда виден.**
Индикации «справа есть ещё» у сегмента нет. Минимум: обрезанный по краю сегмент на реальной ширине уже сигнализирует о скролле. Дополнительно выбранный пункт прокручивается в видимую область (`animateScrollTo`) при смене выбора и при возврате на экран, так как `tokenTabIndex` переживает сворачивание tool window, а `ScrollState` — нет.

**6. Режим темы блокируется, а не скрывается, на типах без зависимости от темы.**
Значение зависит от режима только у `color` и `gradient` (`TokenType?.isThemeDependent()`); у остальных оно одно на обе темы. Иконка режима на них получает `enabled = false` (приглушена, не кликается). Выбранный режим при этом не сбрасывается: в `MainScreenState` он остаётся тем, что был, и возвращается в силу при возврате на «Цвета»/«Градиенты».
*Альтернатива:* скрывать сегмент. Отвергнуто: на смене вкладки список прыгал бы на высоту сегмента и шаг, то есть возвращался бы неровный ритм, ради которого сделан этот change. Блокировка вместо скрытия нужна и после переноса: иконка не сдвигает поле поиска.

**7. Режим темы — иконка-кнопка в строке поиска, а не сегмент.**
Два сегмента подряд одинакового веса конкурировали: режим (второстепенный, нужен только на цветах и градиентах) читался как главный переключатель над типами. Режим переносится в строку поиска справа: `IconButtonS` (тот же размер `S`, что у `TextFieldS`) с иконкой текущего режима — `SunOutline24` (солнце) для светлого, `SleepOutline24` (полумесяц) для тёмного; клик переключает. Строк в группе фильтров становится две, экран короче. В состояниях загрузки/ошибки кнопки нет — нечего переключать. Иконка объясняется тултипом (`Tooltip` из `sdds-uikit-compose`, `TooltipS`) по наведению: текст называет режим и действие, на заблокированной кнопке — причину. Показ управляется `hoverable` на обёртке кнопки (у заблокированной кнопки собственный hover может не приходить), popup с `focusable = false`, чтобы не забирать фокус у поля поиска, выравнивание по концу кнопки — она у правого края панели. Иконка полумесяца в библиотеке называется `Sleep`; семейства `Brightness*`/`Contrast*` отвергнуты: диск без лучей (`Contrast0`) визуально мельче солнца, а `Contrast2` слишком похож на `Brightness2`.
*Альтернативы:* переставить режим под типы; приглушить режим стилем `Secondary`/`hasBackground = false`. Отвергнуты: остаётся два сегмента подряд.

## Risks / Trade-offs

- [Segment внутри `ComposePanel` ведёт себя иначе, чем `Tabs` (hover, фокус, состояния)] → проверить вручную в запущенном плагине: hover, нажатие, выбор, тёмная и светлая тема IDE.
- [Скролл сегмента неочевиден, пользователь не заметит скрытые типы] → см. решение 5; если на реальной ширине этого недостаточно, добавить fade у края отдельной задачей.
- [Высота `Segment.S` не совпадёт с `TextFieldM`, ритм визуально «поплывёт»] → выбрать размер стиля по факту (решение 3), не компенсировать отступами.
- [Смена сигнатуры `TokenList` (публичная функция)] → единственный вызов в `TokensStep`, других потребителей нет; внутренние тесты `TokenListTest` проверяют чистые функции и сигнатуры composable не затрагивают.
