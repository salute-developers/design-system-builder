## ADDED Requirements

### Requirement: Владелец проекта импортирует дизайн-систему из файла

Веб-клиент SHALL показывать владельцу активного проекта (`effectiveRole = owner`) действие «Импортировать» в каталоге дизайн-систем проекта; оно открывает окно импорта с кнопками «Отмена» и «Импортировать». Окно создания дизайн-системы действий импорта не содержит. Импорт MUST принимать `.zip` сборки темы или `.json` данных темы и MUST выполняться существующими ручками: `POST /design-systems` с `projectId` из адреса страницы, `POST /tenants` для темы `<имя>_default` и один пакетный `PUT /tenants/{id}/token-values` со значениями файла.

#### Scenario: Успешный импорт

- **WHEN** владелец выбирает файл, подтверждает имя из `meta.name` и запускает импорт
- **THEN** клиент MUST создать дизайн-систему в проекте из адреса страницы и тему `<имя>_default`
- **THEN** клиент MUST отправить все значения файла одним запросом `PUT /tenants/{id}/token-values`
- **THEN** клиент MUST открыть обзор созданной дизайн-системы

#### Scenario: В файле есть токены, которых нет в наборе

- **WHEN** значения файла ссылаются на токены, которых нет в наборе новой дизайн-системы
- **THEN** клиент MUST NOT отправлять их значения
- **THEN** клиент MUST показать список пропущенных токенов перед переходом в дизайн-систему

#### Scenario: Пакет значений отклонён

- **WHEN** `PUT /tenants/{id}/token-values` или создание темы завершилось ошибкой
- **THEN** клиент MUST удалить созданную дизайн-систему
- **THEN** клиент MUST оставить окно импорта открытым и показать ошибку

#### Scenario: Файл не разобран

- **WHEN** файл не удалось прочитать как сборку темы или JSON данных темы
- **THEN** клиент MUST показать ошибку и MUST NOT отправлять запросы

#### Scenario: Пользователь не владелец или проект архивирован

- **WHEN** каталог или окно создания открывает `viewer`, `editor` или `maintainer`, либо проект архивирован
- **THEN** клиент MUST NOT показывать действия импорта, в том числе при `?mode=import` в адресе

### Requirement: Владелец проекта экспортирует дизайн-систему

Веб-клиент SHALL показывать владельцу проекта пункт «Экспортировать» в меню «три точки» карточки дизайн-системы в каталоге проекта, если у дизайн-системы есть темы. Экспорт MUST собирать данные темы `<имя>_default`, а без неё — первой темы так же, как редактор (`GET /design-systems/{id}/tokens` и `GET /tenants/{id}/token-values`), и сохранять их файлом `<имя дизайн-системы>.json`, который принимает импорт.

#### Scenario: Экспорт из меню карточки

- **WHEN** владелец открывает меню «три точки» карточки и выбирает «Экспортировать»
- **THEN** клиент MUST сохранить файл `<имя>.json` с данными темы `<имя>_default` и `meta.name`, равным имени дизайн-системы
- **THEN** меню MUST закрыться после успешного сохранения

#### Scenario: Экспорт не удался

- **WHEN** чтение данных темы завершилось ошибкой
- **THEN** пункт меню MUST показать ошибку и позволить повторить

#### Scenario: Пользователь не владелец

- **WHEN** меню карточки открывает пользователь без роли `owner`
- **THEN** клиент MUST NOT показывать пункт «Экспортировать»

### Requirement: Отладочное меню не содержит импорт и скачивание темы

Отладочное меню редактора MUST NOT содержать «Импортировать дизайн систему» и «Скачать тему»; клиент MUST NOT вызывать legacy-маршруты `POST /legacy/design-systems/create` и `GET /legacy/design-systems/{name}/download-theme`.

#### Scenario: Отладочный режим включён

- **WHEN** пользователь включил `debug_mode` и открыл тему
- **THEN** меню MUST показывать только «Сохранить тему и компоненты», «Очистить черновик дизайн системы» и «Импортировать токены (PIXSO)»
