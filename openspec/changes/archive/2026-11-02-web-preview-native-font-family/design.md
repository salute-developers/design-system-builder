## Контекст

`normalizeFontFamily` читает из web-значения только `fonts` и отбрасывает `name`. В протоколе имени нет, поэтому плагин строит `fontFamilyName(tokenId)` и использует его в `@font-face`, параметрах типографики и шрифте области превью. Схема контракта запрещает лишние поля токена.

## Цели / Вне целей

**Цели:**

- `@font-face` и `font-family` превью используют настоящее имя, как сгенерированная тема.
- Разные значения шрифта всегда отображаются по-разному.

**Вне целей:**

- Изменение Compose-плагина и Android-значений.
- Новая версия протокола.

## Решения

### Необязательное поле `family`

Поле необязательное, поэтому старые payload и Compose-плагин не затрагиваются, а версия v1 сохраняется. Подстановка настоящего имени вместо `tokenId` в существующие поля отвергнута: идентификатор токена нужен для ссылок типографики.

### Совпадения имён снимаются до разрешения payload

В начале `resolvePayload` строится копия `theme`, где у конфликтующих токенов нет `family`. Дальше все потребители работают как обычно и выводят имя из самого токена, отдельной таблицы имён не появляется.

Токены обходятся в порядке `theme`. Для каждого имени первый токен закрепляет набор файлов (URL, вес, стиль). Токен с тем же именем и таким же набором остаётся одним семейством, правила `@font-face` не дублируются. Токен с другим набором теряет `family` и получает имя токена, поэтому его файлы не смешиваются с первыми.

Сравнение идёт по URL ресурсов, а не по `assetId`: идентификаторы содержат токен и всегда различаются.

### Имя в правиле и значение свойства разделены

Внутри `@font-face` и в `document.fonts.load` нужно одно имя, а в свойстве `font-family` — список с запасным семейством. Запасной `sans-serif` добавляется всем значениям, включая именованные по токену.

## Программное проектирование

```ts
type PreviewFontFamilyToken = { type: 'fontFamily'; family?: string; faces: PreviewFontFace[]; allowFallback?: boolean };

// tokens.ts
const fontFaceName: (tokenId: string, token: PreviewFontFamilyToken) => string; // "SB Sans Text"
const fontFamilyCss: (tokenId: string, token: PreviewFontFamilyToken) => string; // "SB Sans Text", sans-serif

// theme.ts
const uniqueFontFamilies: (theme: ThemeTokens, assets: PreviewAsset[]) => ThemeTokens;
```

## Риски / Компромиссы

- [Какой из конфликтующих токенов сохранит настоящее имя, зависит от порядка `theme`] → Порядок детерминирован сборкой payload, отображение обоих значений верное.
- [Шрифт с настоящим именем установлен в системе пользователя] → `@font-face` имеет приоритет над системным шрифтом с тем же именем.
- [Отпечаток `CONTRACT.sha256` читает CI репозитория plasma-android, схема там хранится копией] → После влития схему нужно перенести через `fingerprint.sh --sync-to`. Поле необязательное, поэтому Compose-плагин работает и со старой копией, пока токены с `family` не приходят в платформу `COMPOSE`.
