## ADDED Requirements

### Requirement: Запуск хода

Монолит SHALL предоставлять `POST /api/projects/{projectId}/ai/chat` с заголовком `Idempotency-Key` и телом с `designSystemId`, `messages` и необязательными `confirmations`. Сервер SHALL обрабатывать запрос в порядке: проверки формы запроса; поиск уже принятого запроса по ключу и по хешу токена подтверждения; для нового запроса — проверка принадлежности DS и подписи токена; атомарная регистрация хода со слотом пользователя и пределом памяти; запуск хода в области подсистемы. Ответ `202` с `turnId` MUST отправляться после запуска хода. Ход MUST выполняться в области подсистемы, не связанной с HTTP-запросом. Сервер MUST NOT хранить разговор между ходами: только события и итог хода до 10 минут после его завершения.

#### Scenario: Ход принят
- **WHEN** участник проекта отправляет корректный запрос
- **THEN** сервер MUST ответить `202 { "turnId": … }`
- **AND** `GET` событий этого `turnId` MUST отдавать события хода

#### Scenario: Повтор POST с тем же ключом
- **WHEN** клиент повторяет POST с тем же `Idempotency-Key` и тем же телом
- **THEN** сервер MUST вернуть тот же `turnId` и MUST NOT запускать второй ход

#### Scenario: Тот же ключ с другим телом
- **WHEN** клиент отправляет POST с уже использованным `Idempotency-Key` и другим телом
- **THEN** сервер MUST вернуть `409 IDEMPOTENCY_KEY_REUSED` без запуска хода

#### Scenario: Ключ другого проекта
- **WHEN** тот же пользователь отправляет POST с тем же `Idempotency-Key` в другом проекте
- **THEN** сервер MUST рассматривать его как новый запрос этого проекта

#### Scenario: Повтор после вытеснения событий хода
- **WHEN** события хода вытеснены из памяти, и клиент повторяет POST с тем же ключом либо с тем же токеном подтверждения
- **THEN** сервер MUST вернуть прежний `turnId` без запуска нового хода
- **AND** `GET` событий этого хода MUST вернуть `404 turn_unknown`

#### Scenario: Запуск хода во время остановки монолита
- **WHEN** ход зарегистрирован, но область ходов уже не активна из-за остановки монолита
- **THEN** регистрация MUST отменяться, и слот пользователя MUST освобождаться
- **AND** клиент MUST получить `503 ai_unavailable`, а не `202`

### Requirement: Контекст экрана

`POST /ai/chat` SHALL принимать необязательное поле `context` с разделом редактора (`section`), темой (`tenantId`), выбранным токеном (`token`) и открытым компонентом (`component`) с выбранными значениями вариаций. Сервер MUST проверять форму контекста и MUST добавлять его в системный промпт хода отдельным блоком, помеченным как данные. Контекст MUST NOT давать прав и MUST NOT сохраняться в истории хода. Контекст MUST входить в отпечаток тела запроса.

#### Scenario: Просьба про открытый компонент
- **WHEN** контекст содержит компонент Button с `appearanceId`, а пользователь пишет «сделай её красной»
- **THEN** системный промпт MUST содержать имя и идентификаторы компонента и правило, что просьба без другого объекта относится к открытому
- **THEN** промпт MUST требовать менять свойства конфигурации компонента, а не токены и стили темы, пока пользователь прямо не попросит иное

#### Scenario: Значения вариаций из превью
- **WHEN** контекст содержит выбранные в превью значения вариаций, а пользователь не называет вариант
- **THEN** промпт MUST требовать менять базовое значение свойства и передавать `styleIds` из контекста, только если пользователь говорит об этом варианте

#### Scenario: Открыт токен
- **WHEN** контекст содержит раздел `typography` и выбранный токен
- **THEN** системный промпт MUST содержать раздел, тему и идентификатор с именем токена

#### Scenario: Неверная форма контекста
- **WHEN** `section` не из списка, идентификатор не UUID либо `selectedValues` длиннее 20
- **THEN** сервер MUST вернуть `400 invalid_request` без запуска хода

#### Scenario: Недопустимое имя
- **WHEN** имя токена, компонента, вариации или значения длиннее 200 символов или содержит символы кроме букв, цифр, пробела и `._-/`
- **THEN** сервер MUST отбросить это имя и запустить ход с остальным контекстом

#### Scenario: Контекст не даёт прав
- **WHEN** модель передаёт в аргумент инструмента `tenantId` или `appearanceId` другой дизайн-системы, полученный из контекста
- **THEN** инструмент MUST вернуть отказ use case (`NOT_FOUND` или `FORBIDDEN`), а ход MUST продолжиться

#### Scenario: Повтор с другим контекстом
- **WHEN** POST повторён с тем же `Idempotency-Key`, но с другим `context`
- **THEN** сервер MUST вернуть `409 IDEMPOTENCY_KEY_REUSED`

#### Scenario: Подтверждение с контекстом
- **WHEN** POST с подтверждением содержит контекст другой страницы, чем ход, выдавший токен
- **THEN** подтверждённая операция MUST выполниться по данным токена, а контекст MUST влиять только на продолжение хода

#### Scenario: Ход без контекста
- **WHEN** POST не содержит `context`
- **THEN** ход MUST выполняться как раньше, без блока контекста в промпте

### Requirement: Проверки запуска хода

Сервер SHALL возвращать ошибки проверок обычным JSON. Отклонённый запрос MUST NOT оставлять зарегистрированного хода и занятого слота.

#### Scenario: Неверный запрос
- **WHEN** тело не разбирается, нет `Idempotency-Key`, `messages` пусто либо последняя реплика не от пользователя и нет `confirmations`
- **THEN** сервер MUST вернуть `400 invalid_request`

#### Scenario: Слишком длинное сообщение
- **WHEN** последнее сообщение пользователя длиннее `AI_MESSAGE_MAX_CHARS`
- **THEN** сервер MUST вернуть `400 message_too_long` до обращения к модели

#### Scenario: Дизайн-система другого проекта
- **WHEN** `designSystemId` не принадлежит проекту маршрута
- **THEN** сервер MUST вернуть `404 design_system_not_found` по результату существующего адаптера принадлежности DS без вызова модели

#### Scenario: Нет доступа к дизайн-системе
- **WHEN** адаптер принадлежности DS вернул отказ в доступе для принципала запроса
- **THEN** сервер MUST вернуть `403 design_system_forbidden` без вызова модели

#### Scenario: Проверка принадлежности недоступна
- **WHEN** адаптер принадлежности DS не смог выполнить проверку
- **THEN** сервер MUST вернуть `503 dependency_unavailable`, а не `404`

#### Scenario: У пользователя уже идёт ход
- **WHEN** у пользователя идёт ход и он отправляет POST с новым `Idempotency-Key`
- **THEN** сервер MUST вернуть `429 ai_busy` с `activeTurnId`, `projectId` и `designSystemId` идущего хода

#### Scenario: Слот освобождается после завершения
- **WHEN** ход пользователя завершился любым исходом, в том числе ошибкой или остановкой
- **THEN** следующий POST этого пользователя MUST быть принят

#### Scenario: Память занята идущими ходами
- **WHEN** объём хранилища ходов превышает `AI_TURN_STORE_MAX_MB`, а вытеснить завершённые ходы нельзя
- **THEN** новый POST MUST получить `503 ai_overloaded`

### Requirement: Чтение событий хода

Монолит SHALL предоставлять `GET /api/projects/{projectId}/ai/turns/{turnId}/events` с необязательным параметром `after` — поток `text/event-stream` с событиями `tool_started`, `tool_result`, `confirmation_required`, `message`, `state`, `error`, `done`. Каждое событие MUST иметь порядковый номер в поле `id`, начиная с 1 в каждом ходе, и MUST сохраняться в хранилище хода до того, как станет доступно подписчикам. Между событиями сервер MUST писать `: heartbeat` не реже раза в 15 секунд; `heartbeat` не сохраняется. Ход и его события MUST быть доступны только пользователю, который его начал, и только в проекте маршрута. У одного пользователя MUST быть не больше трёх одновременных потоков событий.

#### Scenario: Ответ без инструментов
- **WHEN** модель отвечает текстом
- **THEN** поток MUST содержать `message`, затем `state` с итоговой историей, затем `done`

#### Scenario: Цепочка вызовов инструментов
- **WHEN** модель последовательно запрашивает чтение и запись
- **THEN** для каждого вызова поток MUST содержать `tool_started`, затем `tool_result` с тем же `callId`
- **THEN** итоговый `state` MUST содержать все выполненные вызовы и их результаты в порядке выполнения

#### Scenario: Код ошибки инструмента
- **WHEN** инструмент вернул ошибку
- **THEN** `tool_result` MUST содержать `isError: true` и `code` — категорию отказа use case (`FORBIDDEN`, `NOT_FOUND`, `INVALID_ARGUMENT`, `CONFLICT`, `VALIDATION_FAILED`, `BACKEND_UNAVAILABLE`) либо код агента

#### Scenario: Код ds-service в ошибке инструмента
- **WHEN** отказ use case содержит машиночитаемый код
- **THEN** `tool_result` MUST содержать его в `backendCode`, а текст сообщения отказа MUST NOT попадать в `backendCode`

#### Scenario: Переподключение после обрыва
- **WHEN** клиент переподключается с `after=7`, пока ход продолжает добавлять события
- **THEN** поток MUST отдать события с номерами больше 7 без повторов и без пропусков

#### Scenario: Неверный курсор
- **WHEN** `after` не является неотрицательным целым числом
- **THEN** сервер MUST вернуть `400 invalid_request`

#### Scenario: Подключение к завершённому ходу
- **WHEN** клиент подключается к ходу, который уже завершился, но ещё хранится
- **THEN** поток MUST отдать оставшиеся события до `done` включительно и закрыться

#### Scenario: Неизвестный или чужой ход
- **WHEN** `turnId` неизвестен, вытеснен, принадлежит другому пользователю или другому проекту, либо процесс перезапускался
- **THEN** сервер MUST вернуть `404 turn_unknown`

#### Scenario: Слишком много потоков
- **WHEN** у пользователя уже открыто три потока событий и он открывает четвёртый
- **THEN** сервер MUST вернуть `429 too_many_streams`

#### Scenario: Запись зафиксирована, а событие до клиента не дошло
- **WHEN** запись инструмента зафиксирована в ds-service, соединение оборвалось до доставки её `tool_result`, и клиент переподключился с номером последнего полученного события
- **THEN** поток MUST отдать `tool_result` этой записи и дальнейшие события хода
- **THEN** в ds-service MUST NOT появиться повторной записи

### Requirement: Независимость хода от соединения

Отключение клиента SHALL NOT влиять на выполнение хода. Начатый вызов инструмента MUST доводиться до ответа при остановке и при таймауте хода и MUST ограничиваться `AI_TOOL_CALL_TIMEOUT_SECONDS`. Ход MUST завершаться событиями `state` и `done` при любом исходе, кроме остановки процесса монолита.

#### Scenario: Отключение клиента во время записи
- **WHEN** клиент закрыл соединение, пока выполняется вызов инструмента записи
- **THEN** вызов MUST завершиться, его `tool_result` MUST сохраниться, и ход MUST продолжиться

#### Scenario: Отмена HTTP-запроса не отменяет ход
- **WHEN** корутина POST или GET отменена во время хода
- **THEN** ход и начатый вызов инструмента MUST продолжиться

#### Scenario: Остановка хода
- **WHEN** пользователь вызывает `DELETE /api/projects/{projectId}/ai/turns/{turnId}` во время ожидания модели
- **THEN** сервер MUST ответить `204` и завершить ход событиями `error` с `stopped`, `state` и `done`

#### Scenario: Остановка до первого шага
- **WHEN** `DELETE` пришёл до первого обращения хода к модели, и ход не запускался подтверждением с `approved: true`
- **THEN** ход MUST завершиться с `stopped` без обращения к модели

#### Scenario: Остановка хода с подтверждённой операцией до старта
- **WHEN** `DELETE` пришёл до старта хода, запущенного подтверждением
- **THEN** подтверждённая операция MUST выполниться
- **AND** ход MUST завершиться с `stopped` без обращения к модели после неё

#### Scenario: Остановка между вызовами одного ответа модели
- **WHEN** модель вернула три вызова, и `DELETE` пришёл во время выполнения первого
- **THEN** первый вызов MUST завершиться, второй и третий MUST NOT выполняться
- **AND** итоговый `state` MUST NOT содержать невыполненных вызовов в `toolCalls`

#### Scenario: Остановка во время записи
- **WHEN** пользователь останавливает ход, пока выполняется вызов инструмента записи
- **THEN** в события MUST попасть результат вызова либо `OUTCOME_UNKNOWN` по `AI_TOOL_CALL_TIMEOUT_SECONDS`, а новые вызовы MUST NOT начинаться

#### Scenario: Остановка завершённого хода
- **WHEN** `DELETE` пришёл для уже завершённого хода
- **THEN** сервер MUST ответить `204` без новых событий

#### Scenario: Остановка чужого хода
- **WHEN** `DELETE` пришёл для хода другого пользователя или другого проекта
- **THEN** сервер MUST вернуть `404 turn_unknown`

#### Scenario: Зависший вызов записи
- **WHEN** вызов инструмента записи не завершился за `AI_TOOL_CALL_TIMEOUT_SECONDS`
- **THEN** `tool_result` MUST содержать `isError: true` и `code: "OUTCOME_UNKNOWN"`
- **AND** ход MUST продолжиться

#### Scenario: Зависший вызов чтения
- **WHEN** вызов инструмента чтения не завершился за `AI_TOOL_CALL_TIMEOUT_SECONDS`
- **THEN** `tool_result` MUST содержать `isError: true` и `code: "BACKEND_UNAVAILABLE"`

### Requirement: Подтверждение операций

Удаляющая операция и запись сверх `AI_MAX_WRITES` за ход SHALL выполняться только после явного решения пользователя по операции, которую предложил сервер. Без решения ход MUST завершаться событием `confirmation_required`, затем `state` и `done`. Сервер MUST сам формировать итоговые аргументы и `idempotencyKey` операции, читать идентификатор активного черновика и выдавать `confirmationToken`, подписанный над идентификатором ключа, пользователем, проектом, DS, черновиком, инструментом, аргументами, ключом идемпотентности и сроком действия. Подтверждённую операцию сервер MUST выполнять только по данным из токена, без опоры на присланную историю, и только в черновике из токена. Один токен MUST запускать не больше одного хода. Токен MUST NOT содержать учётных данных пользователя.

#### Scenario: Черновик не удалось прочитать
- **WHEN** операция требует подтверждения, а идентификатор активного черновика прочитать не удалось
- **THEN** сервер MUST NOT выдавать `confirmationToken` и MUST вернуть модели `tool_result` с `isError: true` и `code: "BACKEND_UNAVAILABLE"`

#### Scenario: Пауза на подтверждение
- **WHEN** модель запрашивает `component_property_reset`
- **THEN** сервер MUST NOT вызывать инструмент
- **THEN** поток MUST содержать `confirmation_required` с `callId`, `tool`, аргументами без служебных полей, `reason: destructive`, `confirmationToken` и `expiresAt`

#### Scenario: Превышен лимит записей
- **WHEN** модель запрашивает запись после `AI_MAX_WRITES` выполненных записей в ходе
- **THEN** сервер MUST остановить ход событием `confirmation_required` с `reason: write_limit`

#### Scenario: Пользователь подтвердил
- **WHEN** POST содержит `confirmations: [{confirmationToken, approved: true}]` с действительным токеном
- **THEN** ход MUST выполнить операцию с аргументами и `idempotencyKey` из токена и продолжить работу

#### Scenario: Подтверждение отправлено дважды
- **WHEN** POST с тем же `confirmationToken` приходит повторно от того же пользователя с другим `Idempotency-Key`, в том числе из другой вкладки
- **THEN** сервер MUST вернуть `turnId` хода, запущенного первым подтверждением, и MUST NOT запускать новый ход

#### Scenario: Принятый токен в другом проекте или другой DS
- **WHEN** тот же пользователь присылает уже принятый `confirmationToken` в другом проекте или с другим `designSystemId`
- **THEN** сервер MUST вернуть `400 confirmation_invalid` и MUST NOT возвращать `turnId` хода другой области

#### Scenario: Повтор принятого подтверждения после истечения токена
- **WHEN** POST с уже принятым подтверждением повторяется после истечения срока токена
- **THEN** сервер MUST вернуть прежний `turnId`, а не `410 confirmation_expired`

#### Scenario: Решение не принято
- **WHEN** итоговый `state` содержит вызов, ожидающий подтверждения, а следующий POST не содержит решения по нему
- **THEN** сервер MUST добавить перед обращением к модели результат этого вызова с `isError: true` и `code: "not_confirmed"`

#### Scenario: Публикация между выдачей токена и подтверждением
- **WHEN** после события `confirmation_required` DS опубликовали, и активным стал другой черновик
- **THEN** подтверждённая операция MUST передать ожидаемый черновик в ds-service, и запись MUST NOT выполниться
- **THEN** `tool_result` MUST содержать `isError: true`, `code: "CONFLICT"` и `backendCode: "draft_changed"`

#### Scenario: Подменённая история
- **WHEN** присланная история содержит у ожидающего вызова другие аргументы, чем в токене
- **THEN** ход MUST выполнить операцию с аргументами из токена и MUST записать в историю именно их

#### Scenario: Чужой или изменённый токен
- **WHEN** идентификатор ключа токена известен, но подпись не сходится либо пользователь, проект или DS токена не совпадают с текущим запросом
- **THEN** сервер MUST вернуть `400 confirmation_invalid` без запуска хода

#### Scenario: Истёкший токен
- **WHEN** новый запрос содержит токен, срок которого прошёл, либо идентификатор ключа которого неизвестен после перезапуска монолита
- **THEN** сервер MUST вернуть `410 confirmation_expired` без запуска хода

#### Scenario: Пользователь отказал
- **WHEN** решение `approved: false` с действительным токеном
- **THEN** ход MUST NOT выполнять вызов и MUST передать модели результат с `isError: true` и `code: "user_rejected"`

### Requirement: Права пользователя и область дизайн-системы

Каждый вызов инструмента SHALL выполняться от имени участника проекта из проверенного контекста запроса, начавшего ход, и только в DS из этого запроса в проекте маршрута. Права участника фиксируются на время хода; use case повторно проверяет их по тому же снимку на каждую операцию. Набор инструментов SHALL отбираться по точному разрешению каждого инструмента через существующий `PolicyEvaluator` по принципалу из проверенного контекста.

#### Scenario: Редактор из браузера
- **WHEN** участник с ролью editor пишет в чат из браузера
- **THEN** модели MUST передаваться инструменты записи с разрешениями `tokens:write`, `tenants:write` и `components:variations:write`
- **THEN** запись в черновик MUST проходить и отображаться в журнале от имени этого пользователя

#### Scenario: Редактору недоступен сброс свойства
- **WHEN** участник с ролью editor пишет в чат
- **THEN** `component_property_reset` с разрешением `components:variations:delete` MUST NOT передаваться модели

#### Scenario: Maintainer видит сброс свойства
- **WHEN** участник с ролью maintainer пишет в чат
- **THEN** модели MUST передаваться `component_property_reset`, и его вызов MUST требовать подтверждения

#### Scenario: Пользователь без права записи
- **WHEN** участник с ролью viewer либо PAT без разрешений записи пишет в чат
- **THEN** модели MUST передаваться только инструменты чтения

#### Scenario: PAT с частью разрешений
- **WHEN** PAT имеет `tenants:write`, но не `components:variations:write`
- **THEN** модели MUST передаваться инструменты записи значений темы и MUST NOT передаваться инструменты записи компонентов

#### Scenario: Отказ ds-service
- **WHEN** ds-service отклонил вызов по правам или ревизии
- **THEN** `tool_result` MUST содержать `isError: true` и безопасные детали, а ход MUST продолжиться

#### Scenario: Учётные данные не утекают
- **WHEN** выполняется любой ход, в том числе с подтверждением
- **THEN** подсистема MUST NOT читать, хранить и передавать дальше заголовок `Authorization`, и он MUST NOT появляться в событиях, хранилище ходов, истории, `confirmationToken`, журналах и запросах к провайдеру модели

#### Scenario: Роль изменилась во время хода
- **WHEN** у участника отозвали право записи, пока его ход идёт
- **THEN** следующий ход MUST строить набор инструментов по новым правам

### Requirement: Ограничения хода

Ход SHALL ограничиваться `AI_MAX_STEPS` обращениями к модели и `AI_TURN_TIMEOUT_SECONDS`. Хранилище ходов SHALL удерживаться в пределах `AI_TURN_STORE_MAX_MB`, считая байты UTF-8 сериализованных событий и входной истории, вытеснением самых старых завершённых ходов; идущие ходы MAY временно превышать предел. Связи ключа и токена с ходом MUST NOT вытесняться по объёму.

#### Scenario: Превышен лимит шагов
- **WHEN** модель продолжает запрашивать инструменты после `AI_MAX_STEPS` обращений
- **THEN** поток MUST содержать `error` с `step_limit_reached`, затем `state` и `done`

#### Scenario: Превышено время хода
- **WHEN** ход длится дольше `AI_TURN_TIMEOUT_SECONDS`
- **THEN** перед следующим шагом поток MUST содержать `error` с `turn_timeout`, затем `state` и `done`

#### Scenario: Время хода истекло между вызовами одного ответа модели
- **WHEN** `AI_TURN_TIMEOUT_SECONDS` истекает после первого из нескольких вызовов одного ответа модели
- **THEN** остальные вызовы MUST NOT выполняться, и ход MUST завершиться с `turn_timeout`

#### Scenario: Время хода истекло во время записи
- **WHEN** `AI_TURN_TIMEOUT_SECONDS` истекает, пока выполняется вызов инструмента записи
- **THEN** в события MUST попасть результат вызова либо `OUTCOME_UNKNOWN` по `AI_TOOL_CALL_TIMEOUT_SECONDS`, после чего ход MUST завершиться с `turn_timeout`

#### Scenario: История не помещается после сокращений
- **WHEN** после всех сокращений история хода всё равно превышает `AI_HISTORY_MAX_CHARS`
- **THEN** поток MUST содержать `error` с `context_overflow`, затем `state` и `done`, без обращения к модели с превышением лимита

#### Scenario: Провайдер ограничил частоту
- **WHEN** провайдер отвечает 429 или кодом из `AI_RETRY_ERROR_CODES` после всех повторов
- **THEN** поток MUST содержать `error` с `llm_rate_limited`, затем `state` и `done`

#### Scenario: Провайдер недоступен
- **WHEN** провайдер отвечает 5xx, недоступен по сети или не ответил вовремя после всех повторов
- **THEN** поток MUST содержать `error` с `llm_unavailable`, затем `state` и `done`

#### Scenario: Вытесняются только завершённые ходы
- **WHEN** объём хранилища превышает `AI_TURN_STORE_MAX_MB`, и в нём есть идущие и завершённые ходы
- **THEN** вытесняться MUST самые старые завершённые ходы, а события идущих ходов MUST сохраняться

### Requirement: Прерванный ход

Если история содержит сообщение с ролью `interrupted`, сервер SHALL добавлять в системный промпт требование перечитать данные перед любой записью и передавать модели пометку о прерванном ходе с неизвестным исходом. Если в ходе было хотя бы одно успешное обращение к модели, пометки `interrupted` MUST NOT возвращаться в итоговом `state`; иначе они MUST сохраняться.

#### Scenario: История с пометкой о прерванном ходе
- **WHEN** POST содержит в истории `{ "role": "interrupted" }`
- **THEN** системный промпт хода MUST содержать требование перечитать данные перед записью

#### Scenario: История без пометки
- **WHEN** в истории нет сообщения с ролью `interrupted`
- **THEN** системный промпт MUST NOT содержать этого требования

#### Scenario: Пометка действует один ход
- **WHEN** ход с пометкой `interrupted` в истории получил хотя бы один ответ модели и завершился `done`
- **THEN** итоговый `state` MUST NOT содержать сообщений с ролью `interrupted`

#### Scenario: Пометка сохраняется, если модель её не получила
- **WHEN** ход с пометкой `interrupted` завершился до первого успешного ответа модели, например с `llm_unavailable` или `stopped`
- **THEN** итоговый `state` MUST содержать пометку `interrupted`

### Requirement: Состояние подсистемы

Монолит SHALL предоставлять `GET /api/projects/{projectId}/ai/status` с полями `enabled`, `provider`, `model`, `messageMaxChars`. Ответ MUST NOT содержать ключи, адреса и прочие секреты провайдера.

#### Scenario: Подсистема выключена
- **WHEN** `AI_ENABLED` не равно `true`
- **THEN** `status` MUST вернуть `{ "enabled": false }`
- **AND** маршруты хода MUST возвращать `503 ai_unavailable`
