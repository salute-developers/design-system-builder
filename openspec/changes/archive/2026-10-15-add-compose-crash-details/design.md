## Context

Плагин (`index.html`) ловит `error` и `unhandledrejection`, а также запоминает последнюю запись `console.error`; из
этого собирает `crashMessage`. Дальше хосту уходит `failure` с кодом `render_crashed` (запросы в полёте) или
`plugin_crashed` (новые запросы после сбоя). Клиент (`ComposePreviewFrame`) показывает `message` и перезапускает iframe.

## Decisions

1. **Поле `details` в `failure`, версия протокола прежняя.** `{ stack?: string; consoleError?: string }`, оба поля
   необязательны. Добавление поля обратно совместимо: старый клиент его не читает, новый без него просто не показывает блок.
2. **Что попадает в `details`.** `stack` — `reason.stack` из `error`/`unhandledrejection`; если исключения нет (сбой
   найден по записи `console.error`), берётся stack из аргумента этой записи, а не stack искусственного `Error`, созданного
   в таймере. `consoleError` — текст последней записи `console.error`. Длина каждого поля ограничена (8000 символов).
3. **Один набор на сбой.** `reportCrash` сохраняет `crashDetails` при первом сбое; `plugin_crashed` для последующих
   запросов отдаёт те же `details`, чтобы причину было видно и тогда, когда запрос пришёл уже после остановки.
4. **Показ только в debug-режиме.** Вне debug-режима плашка не меняется: stack пользователю PROM не нужен и может
   содержать внутренние имена. `details` доходят до `ComposePreviewFrame` всегда, условие показа проверяется при render.
5. **Таймаут без `details`.** Если плагин не ответил, причины у него нет; блок показывает только то, что получено.
6. **Копирование.** Запасной путь без Clipboard API уже есть в `ComposePayloadDebug`; выносится в общий хелпер и
   используется обоими блоками.

7. **Причину отдаёт Kotlin.** Исключение Kotlin/Wasm попадает в JS как `WebAssembly.Exception`: у него нет текста и
   `stack`, а тег Kotlin-исключения модуль не экспортирует, поэтому прочитать содержимое из JS нельзя. Плагин оборачивает
   содержимое превью в `Layout`, который вызывает `measure` дочерних внутри `try`, и при исключении передаёт `toString()`
   и `stackTraceToString()` в `globalThis.__sddsPreviewCrashCause` до повторного броска. `reportCrash` берёт причину
   оттуда, а `message` отказа вместо `[object WebAssembly.Exception]` получает текст исключения. Обёртка не меняет размер
   и положение содержимого. Причина очищается при приёме нового payload.

## Risks / Trade-offs

- Kotlin/Wasm показывает имена функций в stack только при names section в сборке; иначе в stack будут индексы
  `wasm-function[N]`. Текст исключения при этом читаем всегда.
- Обёртка видит только исключения фазы layout. Сбои композиции и отрисовки остаются `WebAssembly.Exception` без
  причины (в `details` попадёт только запись `console.error`, если она была).
- Новый plugin с `details` и старый клиент совместимы; старый plugin без `details` и новый клиент — тоже.
