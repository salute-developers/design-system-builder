## ADDED Requirements

### Requirement: Plugin module structure

`frontend-kt` SHALL предоставлять модуль `:plugins:android-studio` — плагин для Android Studio / IntelliJ IDEA, реализованный как plain JVM Gradle-модуль на IntelliJ Platform Gradle Plugin, зависящий от `core-domain`, `core-network`, `core-auth` и `core-application` того же composite build.

#### Scenario: Модуль зарегистрирован в settings

- **WHEN** разработчик открывает `frontend-kt/settings.gradle.kts`
- **THEN** список активных модулей включает `:plugins:android-studio`

#### Scenario: Плагин переиспользует общий прикладной слой

- **WHEN** разработчик инспектирует Gradle-зависимости `:plugins:android-studio`
- **THEN** модуль зависит от `core-domain`, `core-network`, `core-auth` и `core-application` через `project(...)`
- **THEN** модуль не дублирует резолвинг контекста, credential-резолвинг или REST-клиенты, уже реализованные в этих модулях

### Requirement: Plugin authentication

Плагин SHALL требовать интерактивной авторизации пользователя через OAuth Authorization Code + PKCE в системном браузере перед доступом к данным DS Builder и SHALL NOT запрашивать логин/пароль напрямую в своём UI.

#### Scenario: Неавторизованный пользователь видит экран логина

- **WHEN** пользователь открывает tool window `SDDS` без активной сессии
- **THEN** плагин показывает экран логина с кнопкой "Войти в DS Builder"
- **THEN** плагин не показывает списки проектов, дизайн-систем или токенов

#### Scenario: Экран логина не содержит полей пароля

- **WHEN** пользователь видит экран логина плагина
- **THEN** экран MUST NOT содержать поля ввода логина или пароля

#### Scenario: Успешная авторизация переключает экран

- **WHEN** пользователь завершает вход через системный браузер и плагин получает access и refresh токены
- **THEN** плагин сохраняет refresh token в защищённом хранилище IDE (`PasswordSafe`) и переключается с экрана логина на основной экран

#### Scenario: Ошибка авторизации отображается пользователю

- **WHEN** обмен authorization code на токены завершается ошибкой или пользователь закрывает браузер до завершения флоу
- **THEN** плагин показывает состояние ошибки на экране логина с возможностью повторить попытку

### Requirement: Read-only token browsing

Плагин SHALL предоставлять только просмотр данных дизайн-системы через REST API DS Builder и SHALL NOT изменять файлы, зависимости или конфигурацию проекта пользователя.

#### Scenario: Просмотр доступных проектов

- **WHEN** пользователь авторизован
- **THEN** плагин запрашивает `GET /api/projects` и показывает только проекты, в которых пользователь состоит участником

#### Scenario: Пустой список проектов

- **WHEN** у авторизованного пользователя нет ни одного проекта с ролью `viewer` и выше
- **THEN** плагин показывает явное пустое состояние с пояснением, что владелец проекта должен добавить пользователя участником, а не выглядит как ошибка

#### Scenario: Просмотр токенов выбранной дизайн-системы

- **WHEN** пользователь выбрал проект, дизайн-систему, версию и платформу
- **THEN** плагин запрашивает `GET /api/projects/{projectId}/ds/tokens` и `GET /api/projects/{projectId}/ds/token-values`
- **THEN** плагин показывает токены, сгруппированные по типу (`color`, `gradient`, `typography`, `fontFamily`, `spacing`, `shape`, `shadow`), с превью значения, соответствующим типу

#### Scenario: Плагин не пишет в проект пользователя

- **WHEN** пользователь выполняет любое действие в любом экране плагина
- **THEN** плагин MUST NOT создавать директорию `.sdds` в открытом проекте
- **THEN** плагин MUST NOT записывать, изменять или удалять какие-либо файлы открытого проекта
- **THEN** плагин MUST NOT запускать генерацию кода дизайн-системы

### Requirement: Plugin UI theming

UI плагина SHALL быть реализован на Compose Desktop, встроенном в tool window через `ComposePanel`, и оформлен библиотекой `sdds-serv-compose`, с автоматическим переключением цветовой схемы в зависимости от текущей темы IDE.

#### Scenario: Светлая тема IDE

- **WHEN** текущая тема IDE светлая
- **THEN** плагин оборачивает содержимое tool window в `SddsServTheme` со светлой цветовой схемой

#### Scenario: Тёмная тема IDE

- **WHEN** текущая тема IDE тёмная
- **THEN** плагин оборачивает содержимое tool window в `SddsServTheme` с тёмной цветовой схемой

#### Scenario: UI остаётся пригодным для узкого/низкого tool window

- **WHEN** tool window `SDDS` задокан узкой полосой или уменьшен по высоте
- **THEN** экран логина и список токенов остаются читаемыми и прокручиваемыми, без обрезанного или наложенного друг на друга содержимого

### Requirement: Design-system agnostic data

Плагин SHALL уметь отображать токены любой дизайн-системы DS Builder, доступной авторизованному пользователю, независимо от того, что UI самого плагина построен на конкретной библиотеке `sdds-serv-compose`.

#### Scenario: Данные дизайн-системы, отличной от той, что стилизует плагин

- **WHEN** пользователь выбрал проект с дизайн-системой, отличной от той, что использована для оформления самого плагина (например `sdds_finai` вместо `sdds_serv`)
- **THEN** плагин отображает её токены как данные внутри UI, построенного на `sdds-serv-compose`
- **THEN** плагин не подключает и не требует отдельную Compose-библиотеку под каждую отображаемую дизайн-систему
