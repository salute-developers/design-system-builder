## Контекст

`writePackagePart` собирает пакет во временном `js/cli/result-*` и с `--package` упаковывал его через
`pacote.tarball`, который запускал `prepare` (`npm run build`) с инструментами из `js/cli/node_modules`.

## Решения

### Папка пакета вместо архива, без сборки

Шаг сборки и упаковки убирается целиком: команда получает исходный пакет и сама решает, когда
выполнить `npm install` (он запустит `prepare`), `npm run build` и `npm pack`.

### Запись в `--out`

`src` заменяется целиком: рядом с `package.json` пакета из одной части не должны оставаться чужие
части. Остальное (`node_modules`, `package-lock.json`, результаты сборки) не трогается, чтобы
повторная генерация не заставляла ставить зависимости заново.

### Сборка — в окружении `js/cli`

Папка пакета не самодостаточна и не должна быть: `tsc`, eslint и его плагины берутся из
`js/cli/node_modules`, как и при прежней сборке через `pacote`. Отдельный `npm install` в папке
пакета вне `js/cli` не поддерживается. Шаг `lint` вызывает `eslint` без пути: `npm run` добавляет
в `PATH` все родительские `node_modules/.bin`, поэтому lint работает при любом расположении
`--output` внутри репозитория, а не только в `js/cli/result-*`.

### Пакет без компонентов собирается из терминала

`pacote` собирал пакет дочерним процессом без терминала и скрывал вывод сборки. Поэтому дефект
`scripts/copy-linaria-components.sh` для пакета из одной темы не был виден: `grep` по отсутствующему
`src/components` падал, а `perl -i` без файлов переходил в режим чтения stdin и сразу получал конец
ввода. Теперь пакет собирают из терминала (`npm pack`), и тот же `perl` ждёт ввода бесконечно.
Скрипт ищет компоненты, только если `src/components` есть, и вызывает `perl`, только если есть
файлы. Тест запускает скрипт с открытым stdin, как у терминала.
