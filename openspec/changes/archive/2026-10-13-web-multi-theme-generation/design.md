## Контекст

`dsbuilder theme fetch` сохраняет каждую тему дизайн-системы в `.sdds/tenants/<каталог>/` (`meta.json` с именем темы и списком токенов, `web/web_*.json` со значениями) и перечисляет темы в `.sdds/config.json`. Палитра общая: `.sdds/tenants/palette.json`. При повторной загрузке у темы, которой больше нет на сервере, удаляются `meta.json` и файлы платформ; пустой каталог остаётся.

Web-генерация (`js/cli`) читает одну тему и вызывает сборщик тем сервиса генерации `themeBuilder.generate`. Сборщик принимает список тем, но один общий источник данных на всех, а файл токенов дописывает на каждой теме, дублируя объявления, — то есть фактически рассчитан на одну. Список тем CLI берёт из `config.json`; при нескольких темах `resolveLocalThemePaths` бросает ошибку «Choose --tenant».

Состав `src/theme` для одной темы:

```text
src/theme/
  index.ts                 экспорт themes и tokens
  themes/index.ts          экспорт <имя>__dark и <имя>__light
  themes/<имя>__dark.ts    CSS-переменные темы строкой
  themes/<имя>__light.ts
  css/<имя>__dark.css
  css/<имя>__light.css
  css/<имя>.module.css
  tokens/index.ts          export const x = 'var(--x, <запасное значение>)'
```

Токены определены на уровне дизайн-системы, поэтому имена переменных у всех её тем одинаковы; различаются только значения.

## Цели / Вне целей

**Цели:**

- Все темы дизайн-системы попадают в `src/theme` одним запуском `generate:theme` или `generate:ds`.
- Для дизайн-системы с одной темой результат не меняется.
- `dsbuilder theme generate` и `dsbuilder ds generate` для React работают при нескольких темах без изменений в `frontend-kt`.

**Вне целей:**

- Удалённая генерация сервисом (`js/services/generator` по HTTP) и клиент: они по-прежнему собирают пакет с одной темой.
- Переключение тем в рантайме и изменения компонентов: компоненты ссылаются на переменные из `tokens`, от числа тем не зависят.
- Android и iOS.
- Формат `.sdds` и команда `theme fetch`.

## Решения

### 1. Темы берутся из каталога `tenants`, без `--tenant` — все

Тема — это каталог в `.sdds/tenants` с файлом `meta.json`; остальное (пустые каталоги удалённых тем, скрытые каталоги, `palette.json`) пропускается. Для генерации всех тем `config.json` не нужен: набор тем определяют сами данные, и генерация работает на каталоге, куда темы положили вручную.

Порядок тем — по имени каталога. Он не зависит от порядка ответа сервера и определяет порядок экспортов и тему по умолчанию.

Сейчас отсутствие `--tenant` при нескольких темах — ошибка, так что рабочих сценариев это не ломает. `--tenant <name>` сохраняет нынешнее поведение: тема ищется по имени в `config.json` и читается из её `directoryPath`. `theme fetch` нормализует имя темы в имя каталога, поэтому они могут различаться, и существующие вызовы с именем темы не должны сломаться. Если `config.json` нет или темы с таким именем в нём нет, `<name>` считается именем каталога в `tenants` — так выбор одной темы работает и на данных без конфигурации. `--default-tenant` ищет тему так же.

Палитра в обоих режимах берётся из `palettePath` в `config.json`, если он задан, иначе из `tenants/palette.json`.

Альтернатива — брать список из `config.json`, как сейчас. Отклонена: это второй источник того же списка, который может разойтись с каталогами, а порядок в нём задаёт сервер. Цена решения: при генерации всех тем `directoryPath` из `config.json` не учитывается — тема, вынесенная за пределы `tenants`, в общий набор не попадёт, её можно сгенерировать только через `--tenant`. `theme fetch` всегда пишет темы в `tenants`.

Альтернатива — отдельный параметр `--all-tenants`. Отклонена: `WebNpmDelegate` вызывает скрипты без параметров темы, и пришлось бы менять `frontend-kt` ради поведения, которое и так единственно осмысленное.

### 2. Несколько тем собирает сборщик сервиса, а не CLI

В `themeBuilder` появляется `generateThemeSet` — вход из нескольких тем, где у каждой свой источник данных: файлы тем и CSS пишутся на каждую тему, индекс `themes/index.ts` накапливает экспорты всех тем (утилита записи дописывает существующий файл), `tokens/index.ts` пишется один раз из темы по умолчанию. Существующий вызов из `generateThemeFiles` (одна тема и один источник) остаётся совместимым и даёт прежний результат.

Альтернатива — вызывать сборщик из CLI по разу на тему во временные каталоги и склеивать индексы самим. Отклонена: CLI пришлось бы знать формат файлов, которые пишет сборщик, и повторять его.

### 3. Тема по умолчанию для запасных значений

`tokens/index.ts` содержит `var(--имя, запасное значение)`. Запасное значение одно, тем несколько, поэтому нужна тема по умолчанию: первая из генерируемых либо заданная `--default-tenant <name>`. С `--tenant` параметр избыточен, но допустим, если называет ту же тему.

### 4. Проверки до записи

CLI читает все темы и проверяет их до вызова сборщика: имена из `meta.json` уникальны и подходят как идентификаторы (сборщик пишет `export { <имя>__dark }`), web-значения каждой темы и общая палитра на месте. Ошибка называет тему. Каталог результата заменяется только после успешной генерации во временном каталоге — так уже работает `writePackagePart`.

## Риски / Компромиссы

- [Тема по умолчанию определяется алфавитом] → новая тема с именем раньше по алфавиту меняет запасные значения токенов. Для устойчивого пакета тему по умолчанию задают явно через `--default-tenant`.
- [В `tenants` лежит посторонний каталог с `meta.json`] → он попадёт в пакет. `theme fetch` за собой убирает; вручную положенные темы — ответственность разработчика, ограничить набор можно через `--tenant`.
- [У `--tenant` два способа поиска: имя в `config.json`, затем имя каталога] → при совпадении имени одной темы с каталогом другой побеждает `config.json`; порядок поиска описывается в справке команд.
- [Общий код сборщика используется сервисом генерации] → путь одной темы закрепляется тестом на неизменность результата.
- [Размер пакета растёт с числом тем] → каждая тема добавляет пять файлов; ограничить набор можно через `--tenant`.

## Открытые вопросы

- Достаточно ли выбора темы по умолчанию «первая по имени каталога или `--default-tenant`», или тему по умолчанию нужно хранить в данных дизайн-системы — это уже изменение бэкенда и `theme fetch`.
