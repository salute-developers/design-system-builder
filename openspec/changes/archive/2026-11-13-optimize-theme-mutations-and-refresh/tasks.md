# Задачи

## 1. Раскрытие значений и палитра

- [x] 1.1 Реализовать лёгкий resolver и подключить publisher; узкими сравнительными тестами подтвердить группы, источники, ступени, прозрачность и неизвестные ссылки.
- [x] 1.2 Убрать повторные преобразования JSON на пути token-values; узкими тестами DTO подтвердить неизменность ответа.
- [x] 1.3 Индексировать сборку полной палитры и выделить получение связей; узкими тестами сравнить порядок, связи и счётчики.

- [x] 1.4 По фазовым измерениям сравнить стратегии ревизий, ограничить технические редакции темой, исключить ненужное чтение палитры и вынести чистое раскрытие за транзакцию; узко проверить эквивалентность и итоговое время.
- [x] 1.5 Сравнить прямую проекцию значений с материализацией ResultRow и ограничить технические редакции фактически выбранными значениями; подтвердить ответы и время на пустых и заполненных редакциях.

## 2. Сохранение цвета

- [x] 2.1 Загружать контекст и текущие значения набором, блокировать адреса в общем порядке; целевыми PostgreSQL-тестами подтвердить существующие и новые адреса.
- [x] 2.2 Пакетно записывать изменения с индивидуальными редакциями и путями; узкими тестами подтвердить rollback, непересекающиеся изменения, тип семейства и подтверждения.

## 3. Адресное обновление редактора

- [x] 3.1 Добавить ограниченные чтения подтверждений семейств с согласованными DTO/OpenAPI; узкими контрактными тестами подтвердить доступ, фильтры и исторические границы.
- [x] 3.2 Применять подтверждения после отката без полной загрузки значений; узкими клиентскими тестами подтвердить смену типа, зависимости, новый ввод и fallback.
- [x] 3.3 Получать области связей инспектора одним запросом; узкими тестами подтвердить разные группы и локальные изменения.

## 4. Журнал и наблюдаемость

- [x] 4.1 Ограничить сводку изменёнными типами, пакетно переиспользовать контекст родителей; узкими тестами сравнить пользовательский счётчик и видимость между порциями.
- [x] 4.2 Ограничить отметки выбранной темой и убрать повторное разрешение границы и сортировку страницы; узкими тестами подтвердить порядок, пагинацию и скрытые создания.
- [x] 4.3 Добавить снимки счётчиков пула к включаемым ds_transaction без нового HTTP-маршрута; узким тестом подтвердить состав данных и сохранение диагностики по флагу.

## 5. Подтверждение результата

- [x] 5.1 Сравнить целевые сценарии с актуальным dev на одинаковом наборе и ресурсах; сохранить отчёт о равенстве ответов и достижении критериев design.md.

## 6. Замечания независимой проверки

- [x] 6.1 Согласовать HTTP/1.1-транспорт с контрактом 200 UUID и узко проверить публичный путь с фильтрами.
- [x] 6.2 Сохранять соседние типы при адресном слиянии и проверить переход color → gradient.
- [x] 6.3 Передавать неизвестный результат команды в общую сверку; после ошибки сверки повторять только чтения.
- [x] 6.4 Проверять штатную очередь до адресного чтения и перед применением, сохраняя ожидающее подтверждения переименование и следующий ввод.
- [x] 6.5 Проверить конкурентное создание отсутствующего адреса, чтения с ненулевыми редакциями непривилегированной ролью, исторические границы и фактическое наличие RLS.

## 7. Клиентская очередь первичного чтения

- [x] 7.1 Исправить общий ограничитель `readEditor`: убрать обязательный интервал 125 мс между стартами независимых чтений, согласовать ограничение параллелизма и приоритет данных открытого раздела с gateway rate limit; сохранить дедупликацию, отмену и обработку 429/503. Проверить повторное чтение темы и обязательные зависимости оболочки. Узко проверить корректность очереди и повторить браузерный HAR-прогон на той же теме.
