## MODIFIED Requirements

### Requirement: Глобальные определения сохраняют самостоятельный контракт

Глобальный каталог компонентов, свойств, платформенных параметров, зависимостей компонентов, состояний, наборов состояний, палитры и плагинов SHALL использовать публичный префикс `/api/projects/{projectId}/design-systems/catalog` без ID ДС с проектной авторизацией, кроме разрешённых общих GET preview и иконок. Настройки переиспользования, оси, стили и значения свойств SHALL оставаться системными. Обогащение глобального компонента системными настройками SHALL обслуживаться системным маршрутом.

#### Scenario: Чтение глобального определения
- **WHEN** клиент читает глобальный компонент или свойство без системного обогащения
- **THEN** API MUST использовать новый адрес под `catalog` без ID системы и сохранить прежнюю доступность независимо от предшествующего системного запроса

#### Scenario: Обогащение свойств или зависимостей
- **WHEN** клиент запрашивает `include=platformParams` либо `include=reuseConfig`
- **THEN** клиент MUST использовать путь `/api/projects/{projectId}/design-systems/{designSystemId}/components/{componentId}/properties` либо `/deps`; прежний глобальный путь MUST отклонить системные параметры с `400`

#### Scenario: Каталог не открывается контекстом query
- **WHEN** гость либо пользователь вне проекта читает общий каталог компонентов, свойств, параметров, состояний, наборов, зависимостей, шаблонов или палитры
- **THEN** запрос MUST требовать проектную авторизацию, даже если query содержит ID публичной ДС
- **THEN** необходимые для публичного просмотра определения MUST читаться через маршруты конкретной ДС

#### Scenario: Query не подменяет систему пути
- **WHEN** путь адресует ДС A, а query содержит designSystemId ДС B
- **THEN** сервер MUST определять систему только из параметров пути и MUST NOT выдавать данные B

#### Scenario: Общие preview и иконки
- **WHEN** гость читает GET catalog/web-preview/plugin, catalog/compose-preview/plugin или catalog/icons
- **THEN** чтение MUST быть доступно без входа, без выбранной ДС и без версии
- **THEN** это MUST NOT открывать остальные общие каталоги или операции изменения

## ADDED Requirements

### Requirement: Публичное чтение сохраняет релизный контекст Core
Публичное и проектное чтение одной публикации SHALL использовать единый механизм разрешения границы ДС/версии и Core-релизов по платформам из `version-core-entities-and-preview`. Проверка доступа и принадлежности версии SHALL предшествовать чтению Core-привязок. ModelReadContext.coreReleases и X-DS-Read-Context MUST соответствовать одной границе; обязательный входной coreReleaseId или предварительное чтение карточки MUST NOT вводиться.

#### Scenario: Импорт Core не меняет публичную публикацию
- **WHEN** публикация V1 закрепляет Core A, а затем импортирован Core B
- **THEN** гость и участник, читающие V1, MUST получить определения Core A через системные маршруты
- **THEN** клиент MUST NOT получать определения V1 из актуального общего каталога

#### Scenario: Принадлежность проверяется до Core
- **WHEN** передан versionId другой ДС либо публичность отозвана
- **THEN** сервер MUST отклонить запрос по правилам доступа до чтения или раскрытия Core-привязок

#### Scenario: Необязательная проверка Core
- **WHEN** доступ разрешён, но переданный необязательный fingerprint не совпадает с Core выбранной границы
- **THEN** сервер MUST сохранить ошибку CORE_CONTEXT_STALE из #167 без подмены версии или проверки доступа

#### Scenario: Черновой контекст остаётся закрытым
- **WHEN** гость читает публикацию
- **THEN** ответ MUST NOT раскрывать текущий coreSelectionRevision черновика или давать право выбирать Core, ремонтировать конфигурации либо читать compatibility-диагностику
