## Why

Структуру компонента — конфигурации, вариации и их значения — в редакторе сейчас почти не изменить: открывается
только первая конфигурация, а временное меню «⋯» в «Variants» умеет лишь добавить и удалить стиль и выбрать стиль по
умолчанию. В прототипе для этого есть вкладка инспектора «Структура». Это третий пункт переноса редактора компонента;
серверная часть (редакторский API конфигураций) уже есть, клиент ею не пользуется.

## What Changes

- В инспекторе две вкладки: «Стилизация» и «Структура»; выбранная вкладка запоминается.
- Блок «Конфигурации»: список конфигураций компонента, выбор открытой конфигурации, создание новой, дублирование
  существующей, переименование, удаление. Конфигурацию по умолчанию удалить нельзя.
- В «Variants» при нескольких конфигурациях — выбор открытой конфигурации. Превью, инспектор и автосохранение работают
  с открытой конфигурацией, а не всегда с первой.
- Блок «Вариации»: вариации открытой конфигурации со значениями (стилями) — добавить, переименовать, удалить вариацию,
  поменять порядок вариаций перетаскиванием; добавить, переименовать, удалить значение; сделать значение стилем по
  умолчанию. Вариацию цветовой схемы (`view`) удалить нельзя.
- Удаление конфигурации, вариации и значения спрашивает подтверждение.
- Временное меню «⋯» в «Variants» убирается: его действия теперь во «Структуре».
- Переименование вариации и значения действует только в открытой конфигурации (отображаемое имя оси и значения);
  для этого клиент сопоставляет вариации и стили конфигурации по ID, а не по имени.
- В секциях свойств стиля — переключатель «Показать все свойства»: кроме привязанных к вариации свойств видны
  пустыми строками остальные свойства компонента; первое значение такого свойства привязывает его к вариации.

## Impact

- Клиент: инспектор (вкладки, новая панель «Структура»), `ComponentEditor`/`Components.tsx` (открытая конфигурация),
  `componentRepository.ts` (автосохранение в открытую конфигурацию, вызовы редакторского API и переименований),
  перечитывание компонента после структурной операции.
- Используются существующие маршруты `ds-service`: `/appearances/new`, `/appearances/{id}/duplicate`,
  `PATCH|DELETE /appearances/{id}`, `/appearances/{id}/axes`, `/axis-order`, `/axes/{axisId}/values`,
  `/axis-values/{valueId}`, `PATCH /appearance-variations/{id}`, `PATCH /appearance-variation-values/{id}`,
  `POST /property-variations`.
- `ds-service`: выгрузка конфигураций (`POST /component-config/export`) по флагу `editorIds` и бандл редактора
  отдают `variationId` у оси и `styleId` у значения. В пакеты конфигураций (`.sdds`) эти поля не попадают.
- `toLegacyComponentConfig`: вариации и стили конфигурации находятся по ID из выгрузки, значения-пересечения
  (`targets`) не превращаются в стили. Это же чинит загрузку конфигурации, в которой ось названа так же, как вариация
  другой конфигурации.
- «Дерево вариаций» (пересечения) — следующим изменением.
