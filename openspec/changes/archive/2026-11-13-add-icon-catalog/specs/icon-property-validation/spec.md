## ADDED Requirements

### Requirement: Значение иконки проверяется по каталогу при записи

Операции редактора, записывающие значение свойства типа `icon` (создание и изменение значения вариации, инвариантного значения и значения комбинации стилей `style-combinations`, а также запись значения свойства оформления `PUT /appearances/{id}/property-values`), SHALL проверять значение по активному каталогу, если он загружен. Значение MUST быть строкой старого формата `<ключ>.<размер>` (например `disclosure.down.fill.16`), ключ которой есть в каталоге, а размер входит в размеры иконки. Неизвестное значение MUST отклоняться кодом `400` с причиной `unknown_icon`, кроме записи значения, равного уже сохранённому. Очистка значения MUST всегда разрешаться. Сохраняемая строка MUST остаться в старом формате без преобразований.

#### Scenario: Значение есть в каталоге

- **WHEN** редактор записывает `disclosure.down.fill.16`, а каталог содержит `DisclosureDownFill` с размером `16`
- **THEN** запись MUST быть принята, а в БД MUST сохраниться строка `disclosure.down.fill.16`.

#### Scenario: Значения нет в каталоге

- **WHEN** редактор записывает `legacy.star.24`, которого нет в каталоге
- **THEN** сервис MUST ответить `400` с причиной `unknown_icon` и MUST NOT менять значение.

#### Scenario: Размера нет у иконки

- **WHEN** иконка есть в каталоге только с размерами `16` и `24`, а записывается значение с размером `36`
- **THEN** сервис MUST ответить `400` с причиной `unknown_icon`.

#### Scenario: Очистка значения

- **WHEN** редактор очищает значение свойства `icon`
- **THEN** запись MUST быть принята без обращения к каталогу.

### Requirement: Пустой каталог не блокирует редактор

Пока в окружении нет активного каталога, сервис SHALL принимать любое значение свойства `icon` без проверки, как до этого change.

#### Scenario: Каталог не загружался

- **WHEN** активного каталога нет, а редактор записывает любое значение
- **THEN** запись MUST быть принята.

### Requirement: Существующие значения не ломаются

Чтение, выгрузка и импорт конфигураций компонентов SHALL возвращать и принимать значения `icon` без проверки по каталогу и без изменений. Импорт и отправка конфигураций (`components push`) MUST NOT отклоняться из-за значений, которых нет в каталоге.

#### Scenario: Выгрузка конфигурации с неизвестной иконкой

- **WHEN** в конфигурации хранится значение, которого нет в каталоге
- **THEN** выгрузка MUST вернуть значение без изменений и без ошибки.

#### Scenario: Повторное сохранение прежнего значения

- **WHEN** запись содержит то же значение, что уже сохранено, а в каталоге его нет
- **THEN** сервис MUST принять запись без ошибки, чтобы автосохранение других полей не ломалось.
