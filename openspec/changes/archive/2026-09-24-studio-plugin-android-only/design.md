## Context

`MainScreen.kt` строит навигацию из шагов `PickProject → PickDesignSystem → PickTenant → PickPlatform → ShowTokens`. Шаг платформы предлагал `ANDROID`, `WEB`, `IOS`. Действие «Копировать код» включалось только при `platform == ANDROID`, а превью значений парсилось по платформе.

## Goals / Non-Goals

**Goals:**
- Убрать экран выбора платформы и платформу из состояния навигации и крошек.

**Non-Goals:**
- Удалять из слоя данных поддержку `web`/`ios` (`TokenPlatform`, ветки `TokenValueParser`, тесты).

## Decisions

**1. Платформа — константа `TOKENS_PLATFORM = TokenPlatform.ANDROID` в UI-слое.**
Слой данных остаётся платформо-параметризованным, поэтому изменение локальное и обратимое: при необходимости шаг можно вернуть, не трогая парсер и клиент.
*Альтернатива:* убрать `TokenPlatform` из слоя данных целиком. Отвергнуто: заметно больший diff (парсер, use case, клиент, тесты) без пользы для пользователя; можно сделать отдельно.

**2. Хлебные крошки заканчиваются tenant.**
Последний элемент пути — название tenant (жирный, как последний шаг раньше), возврат на предыдущие шаги работает как прежде.

**3. «Копировать код» всегда включено.**
Условие по платформе исчезает: платформа всегда `android`, `resolveCodeReference` больше не `null` в `TokensStep`. Параметр остаётся nullable в `TokenList`, чтобы не менять его публичный контракт.

## Risks / Trade-offs

- [Пользователи, смотревшие токены `web`/`ios` через плагин, потеряют эту возможность] → плагин для Android Studio; для других платформ есть web-клиент и CLI.
- [Мёртвый код в слое данных (`web`/`ios`-ветки парсера)] → сознательно оставлен, отдельная чистка.
