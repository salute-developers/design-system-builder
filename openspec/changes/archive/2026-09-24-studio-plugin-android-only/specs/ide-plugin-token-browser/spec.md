## MODIFIED Requirements

### Requirement: Read-only token browsing

Плагин SHALL предоставлять только просмотр данных дизайн-системы через REST API DS Builder и SHALL NOT изменять файлы, зависимости или конфигурацию проекта пользователя. Плагин SHALL работать только с платформой `android`: выбор платформы не предлагается, значения токенов запрашиваются для `android`. Плагин SHALL показывать превью значения токена, специфичное для его типа (`color`, `gradient`, `shadow`, `shape`, `spacing`, `typography`), вместо сырого JSON-текста.

#### Scenario: Просмотр доступных проектов

- **WHEN** пользователь авторизован
- **THEN** плагин запрашивает `GET /api/projects` и показывает только проекты, в которых пользователь состоит участником

#### Scenario: Пустой список проектов

- **WHEN** у авторизованного пользователя нет ни одного проекта с ролью `viewer` и выше
- **THEN** плагин показывает явное пустое состояние с пояснением, что владелец проекта должен добавить пользователя участником, а не выглядит как ошибка

#### Scenario: Единственный доступный вариант выбирается автоматически

- **WHEN** на шаге выбора проекта или дизайн-системы доступен только один вариант
- **THEN** плагин выбирает его автоматически, не заставляя пользователя явно кликать по единственному пункту списка, и не оставляет этот шаг в истории навигации

#### Scenario: Просмотр токенов выбранной дизайн-системы

- **WHEN** пользователь выбрал проект, дизайн-систему и tenant
- **THEN** плагин запрашивает `GET /api/projects/{projectId}/ds/tokens` и `GET /api/projects/{projectId}/ds/token-values`
- **THEN** плагин показывает токены, сгруппированные по типу (`color`, `gradient`, `typography`, `spacing`, `shape`, `shadow`) во вкладках с поиском по имени токена внутри вкладки; тип `fontFamily` из просмотра исключён — его значение является именем шрифта и не несёт визуальной информации, полезной в этом UI

#### Scenario: Значение токена подбирается под выбранную тему

- **WHEN** пользователь выбрал светлую или тёмную тему просмотра токенов
- **THEN** плагин показывает значение токена, опубликованное для этой темы, если оно есть, иначе — значение, не зависящее от темы (например для `spacing`/`shape`)
- **THEN** выбор темы просмотра не зависит от текущей темы оформления самой IDE и может отличаться от неё

#### Scenario: Превью значения формы (`shape`)

- **WHEN** значение токена типа `shape` разобрано как объект `{"kind":"round","cornerRadius":N}`
- **THEN** плагин показывает квадрат фиксированного размера, обрезанный по `RoundedCornerShape(N.dp)`, вместо сырого JSON-текста

#### Scenario: Превью значения отступа (`spacing`)

- **WHEN** значение токена типа `spacing` разобрано как объект `{"value":N}`
- **THEN** плагин показывает полоску шириной `N.dp` рядом с числовой подписью значения, вместо сырого JSON-текста

#### Scenario: Превью значения градиента (`gradient`)

- **WHEN** значение токена типа `gradient` разобрано как массив слоёв, каждый со своим `kind` (`linear`, `radial`, `angular` или `color`)
- **THEN** плагин показывает квадрат, залитый градиентной кистью, построенной из полей слоя (используя `com.sdds.compose.uikit.graphics.Gradients.Linear`/`Radial`/`Sweep` из уже подключённой `sdds-uikit-compose` для `linear`/`radial`/`angular` соответственно, или сплошной цвет `background` для `kind: "color"`), вместо сырого JSON-текста

#### Scenario: Превью значения тени (`shadow`)

- **WHEN** значение токена типа `shadow` разобрано как массив из одного или нескольких слоёв (`color`, `offsetX`, `offsetY`, `spreadRadius`, `blurRadius`)
- **THEN** плагин показывает карточку с тенью, отрисованной по всем слоям (используя `com.sdds.compose.uikit.shadow.ShadowAppearance`/`Modifier.shadow` из уже подключённой `sdds-uikit-compose`), вместо сырого JSON-текста

#### Scenario: Превью значения типографики (`typography`)

- **WHEN** значение токена типа `typography` разобрано в общую модель (размер, межстрочный интервал, начертание, трекинг) по полям исходного JSON платформы `android`
- **THEN** плагин показывает текст-сэмпл, отрисованный этим размером, межстрочным интервалом, начертанием и трекингом, вместо сырого JSON-текста

#### Scenario: Нераспознанная форма значения не ломает список

- **WHEN** значение токена не соответствует ожидаемой для его типа форме (например неизвестный `kind` у `shape`, или структура не совпадает с описанной для `android`)
- **THEN** плагин показывает значение как текст вместо падения с ошибкой или пустой строки

#### Scenario: Плагин не пишет в проект пользователя

- **WHEN** пользователь выполняет любое действие в любом экране плагина
- **THEN** плагин MUST NOT создавать директорию `.sdds` в открытом проекте
- **THEN** плагин MUST NOT записывать, изменять или удалять какие-либо файлы открытого проекта
- **THEN** плагин MUST NOT запускать генерацию кода дизайн-системы

### Requirement: Copy token code reference to clipboard

Плагин SHALL предоставлять действие копирования в буфер обмена code-ссылки на токен (например `SddsServTheme.colors.textDefaultAccent`), получая её по нажатию на конкретный токен из CodeBinding (`kind=token`) опубликованной документации выбранной дизайн-системы (поле `themeReference`).

#### Scenario: Ссылка найдена в публикации

- **WHEN** пользователь нажимает «Копировать код» у токена
- **THEN** плагин находит последнюю публикацию дизайн-системы для платформы `compose` (`GET /documentation/publications/active` без `version`)
- **THEN** плагин ищет биндинг токена по точному `subject` — `tokens.<режим>.<имя>` для токенов, зависящих от темы (режим — выбранный в плагине), иначе `tokens.<имя>`
- **THEN** плагин копирует в буфер обмена значение `themeReference` и показывает статус «Скопировано»

#### Scenario: Ссылки нет — сообщается пользователю

- **WHEN** дизайн-система не опубликована для платформы, токена нет в публикации или `themeReference` пуст (например у `fontFamily`)
- **THEN** плагин ничего не копирует и показывает статус «Нет ссылки»
- **THEN** при ошибке запроса плагин показывает статус «Ошибка»

#### Scenario: Запрос выполняется по нажатию

- **WHEN** пользователь просматривает список токенов
- **THEN** плагин не загружает биндинги заранее и обращается к API документации только после нажатия «Копировать код»

### Requirement: Full selection path in breadcrumbs

Плагин SHALL показывать в хлебных крошках полный путь выбора (проект / дизайн-система / tenant), включая шаги, выбранные автоматически.

#### Scenario: Автовыбранные шаги видны, но не кликабельны

- **WHEN** проект, дизайн-система или tenant выбраны автоматически как единственный вариант
- **THEN** их названия присутствуют в крошках как обычный текст
- **THEN** возврат на такой шаг невозможен, чтобы единственный вариант не выбирался заново автоматически

#### Scenario: Вручную выбранные шаги позволяют вернуться

- **WHEN** пользователь выбрал элемент вручную из списка
- **THEN** его название в крошках кликабельно и возвращает на шаг выбора этого элемента

### Requirement: Navigation state survives panel collapse

Плагин SHALL сохранять состояние навигации (выбранные проект, дизайн-система, tenant, текущий экран, режим темы токенов, выбранная вкладка типа токена и текст поиска) при сворачивании и повторном разворачивании tool window.

#### Scenario: Возврат на тот же экран

- **WHEN** пользователь на экране списка токенов сворачивает панель `SDDS` и разворачивает её снова
- **THEN** плагин показывает тот же список токенов с теми же проектом, дизайн-системой, tenant, режимом, вкладкой типа токена и текстом поиска, а не первый шаг выбора

#### Scenario: Выход сбрасывает навигацию

- **WHEN** пользователь нажимает «Выйти» или сессия истекает
- **THEN** сохранённая навигация сбрасывается к выбору проекта

## ADDED Requirements

### Requirement: No platform selection

Плагин SHALL NOT показывать экран выбора платформы: после выбора проекта, дизайн-системы и tenant он сразу показывает список токенов платформы `android`.

#### Scenario: Переход от tenant к токенам

- **WHEN** пользователь выбрал tenant (или он выбран автоматически как единственный)
- **THEN** плагин сразу показывает список токенов платформы `android`, не предлагая выбрать платформу
- **THEN** хлебные крошки заканчиваются названием tenant
