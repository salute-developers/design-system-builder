## MODIFIED Requirements

### Requirement: Публикация полного комплекта

Процесс выпуска SHALL размещать `dsbuilder-cli-macos-arm64.zip`, `dsbuilder-cli-macos-x64.zip`, `dsbuilder-cli-windows-x64.zip`, `dsbuilder-cli-jvm.zip`, `SHA256SUMS` и `release.json` в GitHub Release точного тега `cli-vX.Y.Z`. Выпуск MUST оставаться черновиком до проверки полного комплекта. Архивы и метаданные MUST NOT загружаться в S3 новым процессом публикации.

#### Scenario: Конфигурация доставки
- **WHEN** запускается публикация CLI
- **THEN** запись GitHub Release MUST выполняться с `contents: write`, а AWS credentials MUST использоваться только шагом публикации установщиков в том же релизном процессе
- **THEN** публичное скачивание MUST NOT требовать backend API, GitHub-токен или S3 credentials

#### Scenario: Частичный сбой
- **WHEN** сборка, запуск проверок, загрузка или проверка одного файла завершается ошибкой
- **THEN** новый выпуск MUST NOT становиться опубликованным или Latest
- **THEN** существующий Latest MUST сохраняться, а черновик SHALL допускать повторный запуск

#### Scenario: Повторная публикация
- **WHEN** повторно выпускается тег с незавершённым черновиком
- **THEN** процесс MUST восстановить полный комплект и повторно проверить все файлы перед публикацией

#### Scenario: Повтор опубликованного выпуска
- **WHEN** повторно выбран уже опубликованный тег
- **THEN** процесс MUST проверить согласованность удалённых метаданных, всех четырёх архивов и SHA-256 без замены опубликованных файлов
- **THEN** неполный или повреждённый выпуск MUST завершить проверку ошибкой
- **THEN** повтор MUST перезаписывать оба S3-установщика из выбранного тега и MUST NOT менять Latest

### Requirement: Сетевые установщики

Shell и PowerShell установщики SHALL выбирать стабильную версию через GitHub Latest либо явно указанную версию, закреплять один тег на время установки, проверять SHA-256 и вызывать локальный установщик из архива. Они SHALL автоматически выбирать нативный архив macOS arm64/x64 или Windows x64; Linux SHALL автоматически выбирать JVM с проверкой Java 17+. Явный выбор JVM на macOS/Linux SHALL сохраняться.

#### Scenario: Выбор платформы
- **WHEN** установщик запущен на macOS arm64/x64 либо Windows x64
- **THEN** он MUST выбрать соответствующий нативный архив; macOS arm64 под Rosetta MUST определяться как arm64
- **WHEN** он запущен на Linux либо явно выбран JVM на macOS/Linux
- **THEN** он MUST выбрать JVM и проверить Java 17+ без автоматической установки Java
- **WHEN** определена неподдерживаемая ОС или Windows arm64/32-bit
- **THEN** он MUST завершиться ошибкой без установки несовместимого бинарника

#### Scenario: Latest сменился во время установки
- **WHEN** установка без версии получила `release.json` через `/releases/latest/download/release.json`, после чего Latest изменился
- **THEN** она MUST использовать версию из полученного манифеста и скачивать контрольные суммы и ZIP только по соответствующему `cli-vX.Y.Z`
- **THEN** установщик MUST NOT повторно разрешать Latest для других файлов

#### Scenario: Явная версия
- **WHEN** задан `--version X.Y.Z` либо `-Version X.Y.Z`
- **THEN** установщик MUST загружать метаданные и архив из `cli-vX.Y.Z` без обращения к Latest

#### Scenario: Ошибка загрузки или проверки
- **WHEN** Latest отсутствует, метаданные недопустимы, архив недоступен, SHA-256 не совпала, платформа не поддерживается или необходимый инструмент отсутствует
- **THEN** установщик MUST завершиться с ненулевым кодом и понятной причиной до изменения установленного CLI
- **THEN** при недоступном GitHub установщик MUST NOT выбирать старый выпуск из S3

#### Scenario: Перенаправление загрузки
- **WHEN** GitHub отвечает HTTPS-перенаправлением при загрузке метаданных, контрольных сумм или архива
- **THEN** установщик MUST поддерживать не более пяти перенаправлений и MUST запрещать переход с HTTPS на HTTP
- **THEN** при превышении лимита или запрещённом переходе установленный CLI MUST оставаться неизменным

#### Scenario: Адрес загрузки
- **WHEN** скачанный из S3 установщик выбирает выпуск
- **THEN** он MUST обращаться к GitHub Releases репозитория `salute-developers/design-system-builder`, а `CLI_DOWNLOAD_BASE_URL` MUST NOT задавать корень архивов
- **THEN** отдельное переопределение `CLI_RELEASE_BASE_URL` MUST поддерживаться для проверки с HTTPS либо HTTP loopback
- **THEN** установщик MUST NOT требовать наличия `gh`, `jq` или Python

#### Scenario: Согласованность манифеста
- **WHEN** получен `release.json`
- **THEN** установщик MUST проверить `schemaVersion: 1`, допустимую версию `X.Y.Z`, фиксированное имя выбранного архива и единственную запись его SHA-256
- **THEN** SHA-256 выбранного архива в манифесте, `SHA256SUMS` закреплённого тега и скачанном ZIP MUST совпадать
- **THEN** небезопасные пути и символические ссылки ZIP MUST отклоняться до распаковки в каталог установки

## REMOVED Requirements

### Requirement: Версия stable управляется из Git

**Reason**: Источник стабильной версии переносится в GitHub Latest; отдельный `stable.json` больше не требуется.

**Migration**: Удалить `frontend-kt/cli/distribution/stable.json`, его чтение/публикацию и `sync-cli-stable.yml`. Старые S3-объекты автоматически не удалять, новые установщики их не используют. Откат выполнять назначением ранее опубликованного стабильного GitHub-релиза как Latest через интерфейс GitHub Releases.

## ADDED Requirements

### Requirement: Установщики сохраняют адреса S3

`install.sh` и `install.ps1` SHALL оставаться в S3 под существующими ключами и публичными адресами. Релизный процесс CLI SHALL перезаписывать только эти два файла из исходников выбранного тега после проверки GitHub-комплекта, используя существующие AWS secrets, `CLI_S3_PREFIX` и `CLI_DOWNLOAD_BASE_URL`, и проверять загруженные байты повторным чтением. Версионные копии установщиков SHALL NOT создаваться.

#### Scenario: Обновление установщиков
- **WHEN** релизный процесс CLI выполняет выпуск нового либо повтор существующего тега
- **THEN** процесс MUST обновить прежние `<prefix>/install.sh` и `<prefix>/install.ps1` без смены публичных адресов
- **THEN** он MUST NOT записывать архивы CLI, `release.json`, `SHA256SUMS` или `stable.json` в S3

#### Scenario: Повтор старого тега
- **WHEN** процесс выпуска повторно выполняется для старого тега CLI
- **THEN** он MUST перезаписать текущие установщики в S3 скриптами выбранного тега без создания версионных копий
- **THEN** скрипты MUST по умолчанию выбирать GitHub Latest, а не версию тега, из которого они опубликованы

#### Scenario: Ошибка публикации установщика
- **WHEN** запись либо повторное чтение любого из двух скриптов завершается ошибкой или возвращает другие байты
- **THEN** процесс MUST завершиться ошибкой без изменения GitHub Latest
- **THEN** повторный запуск MUST повторно загрузить оба скрипта из выбранного тега

### Requirement: Стабильная версия управляется GitHub Latest

GitHub Latest SHALL быть единственным указателем стабильного CLI-релиза. Автоматическое назначение Latest SHALL происходить только после проверки полного комплекта и перезаписи с проверкой обоих S3-установщиков и только при отсутствии Latest либо при увеличении числовой версии CLI. Ручное переключение Latest и откат SHALL выполняться оператором через интерфейс GitHub Releases без отдельного workflow или команды доставки CLI, без пересборки и без записи в S3. Автоматические публикации SHALL сериализоваться.

#### Scenario: Первый и следующий выпуски
- **WHEN** первый полный стабильный выпуск опубликован либо опубликована версия выше текущего Latest
- **THEN** процесс MUST назначить его Latest после проверки, не обращаясь к `stable.json`
- **WHEN** выпускается версия ниже или равная текущему Latest
- **THEN** автоматический процесс MUST сохранить Latest

#### Scenario: Откат на готовый выпуск
- **WHEN** оператор через интерфейс GitHub Releases назначает ранее опубликованный стабильный CLI-релиз как Latest
- **THEN** следующая установка без явной версии MUST выбрать этот релиз через GitHub Latest
- **THEN** переключение MUST NOT требовать запуска отдельного workflow или команды доставки CLI, пересборки либо обновления S3-установщиков
- **THEN** установщик MUST сохранить проверки метаданных и SHA-256 выбранного выпуска; дополнительная автоматическая проверка при ручном переключении не выполняется

#### Scenario: Latest другого продукта
- **WHEN** текущий Latest не соответствует корректному стабильному CLI-релизу
- **THEN** установщик и автоматическое продвижение MUST завершиться понятной ошибкой без угадывания другой версии
