## Зачем

Дев-база содержит схему Drizzle после `0005`, а прежняя V1 Flyway объединяет миграции до `0006`. Пользователь подтвердил, что V1/V2 Flyway нигде не применялись, поэтому можно исправить разбиение до первой регистрации истории и обойтись штатными миграциями.

## Что меняется

- V1 содержит только миграции Drizzle до `0005` включительно и соответствует существующей дев-базе.
- Новая V2 содержит изменения `0006` и прежнее заполнение значений токенов в одной транзакции.
- При явном adoption Flyway проверяет схему V1, регистрирует baseline V1 и автоматически выполняет V2 при обычном запуске ds-service.
- Fingerprint сравнивает колонки по имени без физических номеров; остальные проверки структуры сохраняются.
- Нормализация имён в V2 предварительно проверяет конфликты и не изменяет данные при конфликте.
- Специальная команда migrate-legacy и её отдельный координатор не добавляются.

## Возможности

### Новые возможности

- `legacy-ds-schema-transition`: штатный переход существующей схемы после `0005` на Flyway с отдельными V2.

### Изменяемые возможности

Нет.

## Влияние

Затрагиваются backend-kt/ds-service: файлы Flyway, отпечаток схемы, тесты и эксплуатационная документация. Источник структуры и исходная миграция 0006 в js/services/db-service не меняются. HTTP API, frontend-kt и Docker-команда запуска остаются прежними. Новые зависимости отсутствуют. Разбиение допустимо только до первой регистрации текущих V1/V2; это условие явно подтверждено пользователем.
