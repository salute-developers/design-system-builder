## Context

Связи свойств с вариациями (`GET /property-variations`) клиент кладёт в `api.variations` именами вариаций и только для
web: бандл редактора отдаёт их только web-компоненту, а клиент обнуляет их для других платформ. В данных связи есть и у
Compose (в локальной базе — у 67 из 79 Compose-компонентов). Модель конфигурации (`Config`) хранит вариации по ID. `sourceApi` в `inspectorModel.ts` сравнивает
`api.variations` с ID вариации стиля, поэтому совпадений нет; у свойств Compose `variations` пустые, и все они
считаются инвариантами. Фикстура тестов использует ID вариаций, равные именам, и ошибку не ловит.

Выгрузка конфигурации отдаёт пересечение как значение стиля-владельца с `targets`; клиент превращает каждое такое
значение в стиль с тем же именем.

Пикеры закрываются слушателем `pointerdown`/`mousedown` на `document`. Холст превью — `iframe`, клик в нём до
родительского `document` не доходит.

## Goals / Non-Goals

**Goals:** исправить замечания ревью без изменения модели данных и маршрутов (кроме проверки `PATCH`).

**Non-Goals:** загрузка пересечений как сочетаний и редактирование пересечений — это отдельное изменение вкладки
«Структура». Заполнение связей у Compose-компонентов, где их нет совсем.

## Decisions

**Связи для Compose.** Бандл редактора отдаёт `propertyVariations` для любой платформы, клиент перестаёт их обнулять.

**Источник свойства.** `sourceApi` проверяет `variations` по имени и по ID вариации. Признак «данных о связях нет» —
ни у одного свойства API компонента нет `variations`. Тогда инвариантами считаются только заданные инварианты, а
пустые строки не строятся ни для инвариантов, ни для стилей. Фикстура получает ID вариаций, отличные от имён, чтобы
тесты проверяли сопоставление.

**Пересечения.** `toLegacyComponentConfig` пропускает значения с непустым `targets` и при поиске стиля по умолчанию.

**Один пикер цвета.** Исключение из закрытия по клику — только поле своего пикера, а не все поля цвета: клик по
другому полю закрывает текущий пикер, и то поле открывает свой.

**Клик по холсту.** `useDismiss` и закрытие пикера цвета дополнительно слушают `blur` окна: если фокус ушёл в
`iframe` (`document.activeElement` — `IFRAME`), окно закрывается.

**`Escape` в типографике.** Закрытие с возвратом фокуса ставит флаг, и следующий `onFocus` не открывает список.

**Состояние цвета.** На локальных данных не воспроизводится: состояние стилевого свойства уходит
`POST /variation-property-values` и остаётся после перечитывания и перезагрузки. Для исправления нужны шаги
воспроизведения.

**Индикатор сохранения.** Индикатор тулбара уже собирает статус всех очередей редактора, включая очередь компонента,
но его повтор повторял только сохранение токенов. Очереди регистрируют свой повтор в `draftAutosaveActivity`
(`setDraftAutosaveRetry`), кнопка тулбара повторяет все (`retryDraftAutosave`). После этого индикатор в панели
окружения превью и над сообщениями раздела компонентов убирается.

**`PATCH` без значения.** После применения изменений к текущей строке проверяется, что остался токен или значение;
иначе `422 property_value_empty`: результат зависит от сохранённой записи, а не от формы тела, поэтому это нарушение правила (`EditorRuleViolationException`), а не `400`. Проверка в общей операции изменения, чтобы вариационные и инвариантные значения
вели себя одинаково.

## Risks / Trade-offs

- [Compose-компонент совсем без связей остаётся без пустых строк] → это лучше, чем дубли и запись не в тот источник;
  связи для таких компонентов — отдельная задача.
- [Бандл Compose-компонента становится больше на связи его свойств] → это десятки строк на компонент.
- [`blur` окна срабатывает и при переходе в другое приложение] → пикер закрывается, как при клике снаружи; значение не
  меняется.
