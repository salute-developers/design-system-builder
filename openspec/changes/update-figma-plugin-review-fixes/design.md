## Context

Ключи переменных строятся по id токенов, поэтому переименование токена обновляет ту же переменную. Ключ меняется, когда токен создан заново или когда у подтемы сменился токен, по которому строится её ключ. Ревьюер предложил ключ подтемы по имени, но тогда переименование создавало бы новую переменную.

## Decisions

- **Подхват по имени в записи, а не ключ по имени в плане.** Если переменной с ключом плана нет, а имя занято устаревшей переменной DS Builder того же типа, запись меняет ей ключ. Так сохраняются оба случая: переименование (тот же ключ) и смена ключа (то же имя). Это работает для всех коллекций, а не только для подтем.
- **Тени через отдельные переменные.** Палитра непрозрачна, а у слоёв теней есть альфа; прямая привязка к палитре сделала бы тень непрозрачной. Переменная `ShadowColors/<тень>/Layer N` в `01. Theme` ссылается на ступень с прозрачностью, как цвета темы, область применения `EFFECT_COLOR`.
- **Группа палитры для тени.** Бэкенд выбирает группу палитры тени по своим правилам и отдаёт раскрытый HEX. План берёт ту группу, где ступень совпадает с раскрытым цветом, иначе первую со ступенью.
- **Срок сессии на уровне realm.** Клиентский верхний срок действует только при включённом верхнем сроке realm. `offline_access` нужен только плагину, поэтому realm получает те же 90 дней без влияния на другие клиенты.
- **Размер `ui.html`.** 630 КиБ из 796 — рантайм Kotlin (stdlib, coroutines, ktor, serialization). Сборка одним файлом и короткие имена членов размер не уменьшили. Порог остаётся, замена ktor на `fetch` в общем ядре — отдельная задача.
