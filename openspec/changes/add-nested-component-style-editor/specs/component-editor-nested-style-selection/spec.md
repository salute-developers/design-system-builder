## ADDED Requirements

### Requirement: Выбор стиля вложенного компонента в панели свойств

Панель свойств редактора компонента SHALL показывать для свойства `component_style` выбор оформления целевого компонента и выбор стиля по каждой оси этого оформления.

#### Scenario: Показ текущего значения

- **WHEN** у свойства задана ссылка `basic-button.xxs.default`
- **THEN** редактор MUST показать выбранным оформление `basic-button` и стили `xxs` и `default` в соответствующих осях

#### Scenario: Смена оформления

- **WHEN** пользователь выбирает другое оформление целевого компонента
- **THEN** редактор MUST показать оси нового оформления и выбрать в каждой стиль по умолчанию

#### Scenario: Смена стиля оси

- **WHEN** пользователь выбирает другой стиль одной из осей
- **THEN** значение свойства MUST собраться как `оформление.стиль1.стиль2` в порядке осей оформления
- **THEN** превью MUST отобразить вложенный компонент с выбранными стилями

#### Scenario: Исключение собственного оформления

- **WHEN** пользователь открывает список оформлений
- **THEN** редактор MUST NOT предлагать оформление, редактируемое в данный момент

### Requirement: Выбор доступен только для compose-компонентов

Выбор стиля вложенного компонента SHALL быть доступен только при редактировании компонента платформы `compose`.

#### Scenario: Compose-компонент

- **WHEN** пользователь редактирует компонент платформы `compose`
- **THEN** редактор MUST показать для `component_style` выбор оформления и стилей

#### Scenario: Компонент другой платформы

- **WHEN** пользователь редактирует компонент платформы, отличной от `compose`
- **THEN** редактор MUST показать `component_style` только для чтения и MUST NOT предлагать выбор или запись ссылки

#### Scenario: Цели выбора

- **WHEN** пользователь открывает список оформлений
- **THEN** редактор MUST предлагать только оформления compose-компонентов той же дизайн-системы

### Requirement: Сохранение ссылки на стиль вложенного компонента

Клиент SHALL сохранять изменение значения `component_style` операцией записи значения свойства оформления с полем `reference`, содержащим идентификатор целевого оформления и идентификаторы выбранных стилей.

#### Scenario: Сохранение выбора

- **WHEN** пользователь выбрал оформление и стили, и правка сохраняется
- **THEN** клиент MUST вызвать `PUT /api/ds/appearances/{id}/property-values` с `reference.targetAppearanceId` и `reference.styleIds`
- **THEN** клиент MUST NOT записывать значение этого свойства как токен или произвольную строку

#### Scenario: Значение области стиля

- **WHEN** свойство редактируется в области стиля оси
- **THEN** клиент MUST передать в `styleIds` записи стиль этой области

#### Scenario: Очистка

- **WHEN** пользователь очищает значение
- **THEN** клиент MUST удалить значение свойства операцией удаления значения оформления, и ссылка MUST исчезнуть вместе с ним

### Requirement: Отображение отказа проверки ссылки

Клиент SHALL показывать пользователю причину отклонения ссылки сервером и оставлять в редакторе последнее сохранённое значение.

#### Scenario: Цикл ссылок

- **WHEN** `ds-service` отвечает `422` с кодом `reference_cycle`
- **THEN** редактор MUST показать сообщение о недопустимом цикле и вернуть прежнее значение

#### Scenario: Прочие коды проверки

- **WHEN** `ds-service` отвечает `reference_target_not_found`, `reference_invalid_styles` или `reference_too_deep`
- **THEN** редактор MUST показать сообщение, соответствующее коду, и вернуть прежнее значение
