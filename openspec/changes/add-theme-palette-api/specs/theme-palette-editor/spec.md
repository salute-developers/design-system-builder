## MODIFIED Requirements

### Requirement: Источник данных палитры

Клиент SHALL получать и изменять палитру темы только через порт `PaletteRepository`, реализованный
адаптерами `api` и `local`. Адаптер SHALL выбираться переменной `VITE_PALETTE_SOURCE`; при отсутствии
переменной SHALL использоваться `api`, а `local` — только при `VITE_PALETTE_SOURCE = local`. Оба адаптера
SHALL возвращать DTO контракта палитры темы и выполнять операции с одинаковой семантикой.

#### Scenario: Адаптер api

- **WHEN** `VITE_PALETTE_SOURCE` не задана или равна `api`
- **THEN** клиент MUST читать палитру запросом `GET /api/projects/{projectId}/ds/tenants/{tenantId}/palette` и выполнять операции запросами контракта палитры темы
- **THEN** растяжки в телах запросов MUST передаваться только полями `type` и `shade`

#### Scenario: Адаптер local

- **WHEN** `VITE_PALETTE_SOURCE = local`
- **THEN** клиент MUST хранить состояние палитры темы в `localStorage` под ключом `ds_palette:<projectId>:<designSystemId>:<tenantId>`
- **THEN** раздел MUST показывать баннер «Палитра хранится в этом браузере и не публикуется»

#### Scenario: Операции local не меняют ссылки токенов

- **WHEN** в режиме `local` выполняется замена источника, перестройка, правка ступени, добавление растяжки, создание или удаление группы, привязка токена к группе
- **THEN** клиент MUST NOT менять значения токенов темы и их черновик

#### Scenario: Удаление растяжки в режиме local

- **WHEN** в режиме `local` растяжка со связями удаляется со стратегией `replace` или `detach`
- **THEN** клиент MUST записать новые ссылки или вычисленный HEX в черновик значений токенов темы
- **THEN** эти значения MUST уходить на сервер обычным сохранением значений токенов темы

#### Scenario: Логика совпадает с эталоном

- **WHEN** выполняются тесты модуля `modules/palette/domain` на данных `palette-golden.json`
- **THEN** группы по умолчанию, состав групп, значения ступеней, результаты перестройки и отображаемые имена MUST совпасть с ожидаемыми значениями эталона

## ADDED Requirements

### Requirement: Черновик клиента в режиме api

Сервер знает только сохранённые значения токенов темы, а редактор показывает значения черновика. В режиме
`api` клиент SHALL считать связи токенов, значения которых берутся из черновика (созданных в редакторе и
сохранённых с записью черновика), по черновику и учитывать их в инспекторе, в окне удаления растяжки и при
удалении растяжки.

#### Scenario: Связи по черновику

- **WHEN** в режиме `api` значение токена в черновике ссылается на слот группы, а сохранённое значение — нет или токена ещё нет на сервере
- **THEN** инспектор и окно удаления растяжки MUST показывать связь этого токена по значению черновика вместо сохранённого

#### Scenario: Удаление растяжки со связями черновика

- **WHEN** в режиме `api` удаляется растяжка без стратегии, а на неё ссылается значение черновика
- **THEN** клиент MUST отклонить операцию с кодом `PALETTE_RAMP_LINKED` без запроса к серверу
- **WHEN** у растяжки замены нет ступени, на которую ссылается значение черновика
- **THEN** клиент MUST отклонить операцию с кодом `PALETTE_STEP_MISSING` и списком ступеней

#### Scenario: Ссылки черновика после удаления растяжки

- **WHEN** в режиме `api` сервер удалил растяжку со стратегией `replace` или `detach`
- **THEN** клиент MUST переписать ссылки на убранный слот в записях черновика токенов группы: у токенов только из черновика — всегда, у сохранённых — если у них есть запись черновика; остальные правки записей MUST сохраниться
- **THEN** клиент MUST перезагрузить тему и показать уведомление после перезагрузки
