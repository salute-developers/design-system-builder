## Why

Раздел «Палитра» темы (`add-theme-palette-editor`) до появления сервера хранит палитру в браузере: её не
видят другие участники проекта и не получают потребители темы. Kotlin `ds-service` знает только
глобальную библиотеку `palette`, изменять которую может лишь системный администратор. Это изменение
добавляет в `ds-service` палитру темы с операциями прототипа, переключает клиент на неё и доводит цвета
палитры темы до CLI `theme fetch`.

## What Changes

- У темы (тенанта) появляется собственная палитра — независимая копия общей палитры-шаблона. Копия
  создаётся вместе с темой (для существующих тем — миграцией) и дальше не зависит от шаблона: правки
  темы не меняют шаблон и другие темы, правки шаблона не меняют существующие темы.
- Поверх копии тема хранит группы и экземпляры растяжек в группах с заменённым источником, перестройкой
  от опорного цвета и правками ступеней. Все группы, включая системные `neutral`, `accent`, `status`,
  `data`, `syntax`, хранятся строками и адресуются по UUID; системные отличаются полем `kind` и
  `systemKey`.
- Принадлежность цветового токена к группе хранится явной привязкой и меняется операцией
  `PUT /token-groups/{tokenId}`. Правило по имени токена — только группа по умолчанию для токенов без
  привязки; в пользовательскую группу токен попадает только явно.
- Flyway-миграция `V3` создаёт таблицы `tenant_palette_template`, `tenant_palette_groups`,
  `tenant_palette_ramps`, `tenant_palette_steps`, `tenant_palette_token_groups` и заполняет копию
  шаблона и системные группы существующих тем.
- Новый API палитры темы под `/api/ds/tenants/{tenantId}/palette`: чтение палитры с вычисленными
  значениями, связями и привязками токенов к группам, список связей, создание и удаление
  пользовательской группы, привязка токена к группе, добавление растяжки, замена источника в группе, перестройка с предварительным просмотром,
  правка ступени, удаление растяжки с переназначением связей или сохранением цветов как Custom.
- Каждая операция изменения передаёт `editRevision` темы, увеличивает его и возвращает новое значение;
  устаревшая ревизия даёт `409 TENANT_EDIT_CONFLICT`, как при сохранении значений токенов.
- Права: чтение — `tenants:read`, изменение — `tenants:write`; ответ чтения содержит `canEdit`.
- `GET /api/ds/tenants/{tenantId}/token-values?resolvePalette=true` возвращает цвета, вычисленные по
  палитре темы с учётом группы токена, и исходную ссылку в поле `paletteRef`. Без параметра ответ прежний.
- CLI `theme fetch` запрашивает значения токенов с `resolvePalette=true` и записывает вычисленные цвета.
- Клиент переключается на адаптер `api`: значение по умолчанию `VITE_PALETTE_SOURCE` становится `api`.
- Маршруты палитры темы добавляются в `contracts/route-manifest.json`; генерация OpenAPI начинает
  допускать операции, которых нет в db-service.

Вне изменения: доставка палитры темы в generator (он читает legacy `theme-data` из db-service и не знает
тенанта), обновление палитры существующей темы до новой версии шаблона, изменение шаблона, отслеживание изменений палитры, перенос ссылок `palette_id` в строки.

## Порядок реализации

Работа идёт в два этапа, сначала фронт, потом бэк:

1. `add-theme-palette-editor` — клиент. Реализуется, проходит ревью и вливается первым; раздел работает
   с адаптером `local` и не зависит от сервера.
2. `add-theme-palette-api` — `ds-service` и CLI. Реализация начинается после слияния клиента и
   опирается на его контракт DTO и эталон `palette-golden.json`; последняя задача переключает клиент на
   адаптер `api`.

## Capabilities

### New Capabilities

- `theme-palette-api`: палитра темы как копия шаблона в `ds-service`, группы и привязки токенов,
  операции, права, конкурентный доступ и вычисление цветов для потребителей.

### Modified Capabilities

- `cli-themes`: `theme fetch` запрашивает значения токенов с `resolvePalette=true` и записывает цвета,
  вычисленные по палитре темы.
- `theme-palette-editor`: источник палитры по умолчанию — `api`; в режиме `api` связи и удаление растяжки
  учитывают значения черновика клиента.

## Impact

- `backend-kt/ds-service`:
  - `feature-themes`: domain, application, data и presentation палитры темы; создание копии шаблона в
    `CreateTenantUseCase` и при первом обращении к теме без палитры; `GetTenantTokenValuesUseCase` и
    маршрут `token-values` с `resolvePalette`;
  - `app`: `db/migration/V3__tenant_palette.sql`, регистрация маршрутов, ручной OpenAPI
    `resources/openapi/documentation.yaml`;
  - `contracts/route-manifest.json`, тесты манифеста, OpenAPI и Flyway.
- `authorization/policy.json`: без изменений, используются `tenants:read` и `tenants:write`.
- `frontend-kt/feature-theme`: `HttpRemoteThemeDataSource`, нормализация значений и тесты `theme fetch`.
- `js/apps/client`: значение по умолчанию `VITE_PALETTE_SOURCE = api` (и в `docker-compose.dev.yml`),
  адаптер `api` с учётом черновика клиента.
- `js/services/db-service`: код сервиса не меняется, новые таблицы ему не видны; тест манифеста
  `route-manifest.test.ts` и `src/test/differential-runner.ts` пропускают группы `"origin": "ds-service"`.
- Gateway: изменений нет, `/api/projects/{id}/ds/tenants/**` уже ведёт в `ds-service`.
