## Why

Web-плагин превью получает payload другого вида, чем Compose-плагин. Для web клиент сам разрешает токены темы в CSS-строки, применяет шаблоны и корректировки, превращает состояния в суффиксы `Hover`/`Active`, собирает конфиги связанных компонентов и цвета темы. Всё это лежит в корневом поле `web`, которое схема контракта не описывает. Получается, что знание о том, как значения дизайн-системы становятся стилями web-библиотеки, осталось в клиенте, хотя смысл плагина — вынести его. Кроме того, у двух платформ разные форматы одного протокола.

Нужно, чтобы клиент для обеих платформ собирал один и тот же payload по одной схеме, а весь перевод значений в стили делал плагин своей платформы — как Compose-плагин уже делает для Compose.

## What Changes

- **Клиент собирает payload WEB тем же ассемблером, что Compose** (`composePreview/draft.ts`, `assembler.ts`):
  - свойства по каноническому имени;
  - источники `tokenRef`, `literal`, `styleRef`, состояния через `states`;
  - тема — структуры схемы со значениями платформы web.

  `webPayload.ts`, корневое поле `web`, суффиксы `Hover`/`Active` и CSS-строки в payload удаляются. Клиент только переводит формат хранения дизайн-системы в единицы протокола. **BREAKING** для текущего формата WEB: старый web-плагин новый payload не примет. Оба живут в одном изменении и выкатываются вместе.
- **Web-плагин сам переводит payload в стили.** Он владеет:
  - **API-метой** `api-meta.json` во время работы: свойство и состояние → ключ токена ядра;
  - **шаблонами многозначных свойств** `web-adapter.json`: файл статичный, генерируется один раз и переносится из `js/cli/.sdds/web` в плагин;
  - **CSS-переменными ядра:** имена по объектам токенов, разрешение `tokenRef`, единицы, цвета, тени, градиенты и типографика в CSS;
  - **переменными темы** для окружения story;
  - **сборкой конфигов связанных компонентов** из `styles`.
- **Связанные компоненты передаются через `styles`.** Это словарь, который уже есть в схеме. Каждый стиль дочернего компонента — запись с вариацией, именем стиля и признаками «по умолчанию» и «инвариант». Поля `relatedComponents` и `relatedProperties` удаляются.
- **В клиенте не остаётся web-рендера:** React-превью, story, `useStory`, `coreTokens.ts`, сборка конфигов и CSS-переменных (`createComponentVars`, `createThemeVars`, `createThemeConfig`, `createRelated*`, `componentVars.ts`). Без плагина область превью показывает «Превью недоступно» с причиной.
- **Схема Preview Protocol v1 расширяется обратносовместимо, только необязательными полями:** типы ресурсов `WOFF2`/`WOFF`, `fontStyle` у типографики, `variation`/`name`/`default`/`invariant` у записи `styles`. Шаблоны и корректировки в payload не передаются. Обновляются `CONTRACT.sha256` и копия в plasma-android.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `preview-payload-contract`: типы ресурсов `WOFF2`/`WOFF`; записи `styles` с вариацией, именем стиля, признаками «по умолчанию» и «инвариант»; необязательный `fontStyle`; платформа `WEB` использует тот же формат без собственных полей.
- `compose-preview-payload-assembly`: ассемблер формирует свойства для платформы компонента (`COMPOSE` или `WEB`), отбор свойств — по параметрам этой платформы.
- `web-preview-plugin`: плагин разрешает payload сам по API-мете, `web-adapter.json`, токенам темы и объектам токенов ядра; клиент не содержит web-рендера. Требования пилота к payload `WEB` с CSS-строками и полем `web` отменяются.

## Impact

- **js / `js/apps/client`:**
  - `composePreview/draft.ts` и `assembler.ts` — платформа компонента, значения темы `web`, разбор web-значений хранения (`rem`, CSS-строки теней и градиентов, `woff2`), шаблоны;
  - удаление `webPayload.ts` и web-полей `types.ts`;
  - `ComponentEditorPreview` — web-превью только через плагин на общем ассемблере;
  - удаление React-превью и логики конфигов: `src/stories`, `hooks/useStory.ts`, `controllers/componentPreview` (`coreTokens.ts`, `themeConfig.ts`, `componentVars.ts`), `createComponentVars`/`createThemeVars`/`createRelated*` в `ComponentEditor.utils.ts`;
  - тесты.
- **js / `js/apps/preview-web-plugin`:**
  - новый слой разрешения payload: мета, тема, единицы, состояния, шаблоны, связанные компоненты из `styles`;
  - `web-adapter.json` переносится из `js/cli/.sdds/web` в плагин;
  - удаление разбора поля `web`;
  - тесты.
- **backend-kt / `backend-kt/preview/contract`:** схема v1 (необязательные поля), README, фикстуры (web-фикстура в новом формате; общие фикстуры на новые поля), `CONTRACT.sha256`.
- **plasma-android:** синхронизация копии контракта (`fingerprint.sh --sync-to`) отдельным PR. Код Compose-плагина не меняется: новые поля необязательны, декодер их игнорирует.
- **openspec:** требования к payload `WEB` из `add-web-preview-plugin-pilot` и `add-web-preview-plugin-components` заменяются этим изменением.
- ds-service, gateway и frontend-kt не затрагиваются.
- **Вне скоупа, отдельными изменениями:**
  - удаление web-шаблонов и web-корректировок из ds-service (`variation_platform_param_adjustments`, 1230 записей, все web, у Compose 0) и из `components push`/`web-adapter`;
  - перевод генератора пакета `js/cli` на мету и шаблоны плагина и общий с плагином код перевода;
  - публикация web-плагина в S3.
