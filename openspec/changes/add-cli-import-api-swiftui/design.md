## Context

`ios-api-meta.json` — продукт сборки репозитория iOS: SwiftSyntax-сканер снимает публичное API `*Appearance`-структур `SDDSComponents`. Корень — массив записей компонента, у записи есть `componentName`, `params` и необязательный `stateEnum`.

Форма близка к мете Compose, но у iOS есть свои поля, которых нет у других платформ, и решения ниже отвечают на вопрос, что из них попадает в манифест.

Исходные данные на момент изменения: 66 компонентов, 903 свойства, 8 компонентов с объявленным набором состояний, 56 параметров без кода на платформе.

## Goals / Non-Goals

Goals:

- Принять мету SwiftUI без изменений на стороне генератора iOS.
- Получить манифест, сопоставимый с Compose и View: те же правила ключа, конфликтов и пропусков.

Non-Goals:

- Нормализатор `react`.
- Пометки устаревания: генератор iOS поля `deprecated` не отдаёт.
- Изменения backend, схемы базы и модели манифеста.

## Decisions

### Платформенное имя — `methodName`

Платформенное имя свойства — то, как оно называется в коде платформы. На iOS это имя stored-property в `*Appearance` или в конфигурации размеров, то есть `methodName`.

`id` для этого не годится: это ключ свойства в конфигурации оформления, и у 290 параметров из 903 он отличается от имени в коде (`titleStyle` против `titleTypography`). Ключом свойства `id` при этом остаётся — как `id` у Compose и `name` у View.

Альтернатива `paramName` отвергнута: на iOS это имя аргумента memberwise-инициализатора, оно всегда совпадает с `methodName`, и отдельного смысла не несёт.

### Параметры без кода на платформе пропускаются

У 56 параметров `methodName` пуст, а `unmapped` равен `true`. Такой параметр описывает свойство, которое знает дизайн-система, но не реализует библиотека iOS: генератор держит его в мете, чтобы печатать в отчёте дыры покрытия.

Платформенного имени у такого свойства нет, темизировать на iOS его нечем, поэтому в манифест оно не идёт и учитывается в сводке пропущенного категорией `unmapped`.

### Состояния — из `stateEnum`

Собственные состояния компонента объявлены в `stateEnum`, у значений есть `configName` в форме конфигурации оформления (`text-inlined`). Это тот же источник, что у Compose, и правило совпадает: `configName`, иначе `name` в kebab-case.

Поле `state` у отдельного параметра состоянием компонента не считается: оно говорит, из какого состояния ключа берётся значение, и среди таких состояний есть состояния взаимодействия (`activated`), чей словарь в базе общий. На стороне iOS набор `stateEnum` проверен тестом против конфигураций оформления всех тем, поэтому он полон.

### Служебные признаки генератора не передаются

`copyOf`, `fromVariation`, `valueEnum`, `markupValue`, `markupZero`, `rawNumber`, `alwaysEmit`, `stateOnly` и `sizeFromIconId` описывают, как генератор iOS добывает значение из конфигурации. Базе они не нужны: манифест описывает, что у компонента есть, а не как оно вычисляется.

`valueEnum` как источник типа тоже не используется: у таких свойств уже стоит тип `value`, и этого достаточно.

### Описание свойства включает группу

Описание свойства — `group: <group>; method: <methodName>; param: <paramSimpleType>`.

В отличие от Compose, у iOS `group` несёт смысл: `root` — свойство самого appearance, `size` — свойство конфигурации размеров. Это разделение видно в коде платформы, и в описании оно помогает сопоставлять свойство с исходником.

### Дубли `id` обрабатываются общим правилом

Общее правило — побеждает первое вхождение, конфликт типов уходит в `conflicts`. Нормализатор SwiftUI его соблюдает, хотя на свежей мете конфликтов быть не должно: инвариант «один `id` — один тип внутри компонента» закреплён тестом в репозитории iOS.

## Risks / Trade-offs

- Мета — продукт сборки iOS и меняется вместе с библиотекой. Снижаем риск так же, как Compose и View: модели чтения с полями по умолчанию и `ignoreUnknownKeys`, корпус из реального фрагмента меты.
- Пропуск `unmapped` скрывает из базы часть свойств дизайн-системы. Это осознанно: такие свойства попадают в базу с других платформ, где они реализованы, а сводка пропущенного показывает их число на каждом прогоне.

## Migration Plan

Изменение добавляет поддержку платформы и ничего не ломает: до него команда на `swiftui` завершалась ошибкой. Данные других платформ импорт не трогает — компонент адресуется парой `(имя, платформа)`.

## Open Questions

- Нужны ли базе свойства iOS, которых нет в конфигурациях оформления (например `Avatar.activeStatusColor`): сейчас они попадают в манифест как обычные свойства платформы.
