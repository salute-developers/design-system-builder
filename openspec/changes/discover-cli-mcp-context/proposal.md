# Выбор проекта и дизайн-системы в CLI и MCP

## Зачем

Сейчас `init` требует заранее известные ID, а агент без локального контекста не может показать доступные проекты и системы. Пользователь должен выбирать их по названиям и описаниям через общие клиентские сценарии.

## Изменения

- Добавить последовательный интерактивный выбор проекта и его дизайн-системы стрелками и Enter в `dsbuilder init`, сохранив явные параметры и работу без терминала.
- Сохранять пользовательскую сессию как источник авторизации после интерактивного выбора; сохранить совместимость явного режима с API key.
- Переиспользовать `feature-projects` для проектов, перенести получение списка дизайн-систем из IDE в `feature-ds`.
- Добавить MCP `projects_list` и `design_systems_list` без требования workspace; разрешить существующему `design_system_versions_list` работать по явной паре ID без предварительно известной версии.
- Возвращать канонические ссылки с обязательной версией и необязательной платформой после выбора версии. Не сохранять глобальный выбор в MCP.

## Возможности

### Новые возможности

- `frontend-design-systems-listing`: общий список дизайн-систем доступного проекта до выбора контекста.

### Изменяемые возможности

- `frontend-cli`: интерактивная и явная инициализация.
- `frontend-mcp-server`: обнаружение проектов, систем и версий без локального контекста.

## Влияние

Переиспользуется `frontend-kt/feature-projects`. Изменяются `feature-init`, `feature-ds`, `core-domain` при расширении команды записи, `cli`, `mcp-server-core`, `mcp-node` и подключение общих сценариев в Android Studio plugin. Используются существующие API проектов, дизайн-систем и версий; backend-kt, js, схема БД и публичные HTTP-контракты не меняются. Нового TUI-фреймворка нет. Change независим от публикации CLI.
