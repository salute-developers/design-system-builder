## ADDED Requirements

### Requirement: Конфигурация по умолчанию

Для каждой пары (дизайн-система, компонент) ровно одно оформление SHALL быть конфигурацией по умолчанию. Такое оформление SHALL NOT удаляться; переименовывать его допускается. Признак `isDefault` SHALL быть изменяемым полем оформления в модели редакций и отдаваться в модели редактора.

#### Scenario: Первое оформление компонента

- **WHEN** компонент добавляется в дизайн-систему и у него ещё нет оформлений
- **THEN** `ds-service` MUST создать оформление с `isDefault = true`
- **THEN** его имя MUST совпадать с именем компонента

#### Scenario: Удаление конфигурации по умолчанию

- **WHEN** клиент удаляет оформление с `isDefault = true`
- **THEN** `ds-service` MUST ответить `422` с кодом `default_appearance_protected` и MUST NOT менять данные

#### Scenario: Существующие оформления

- **WHEN** применяется миграция
- **THEN** для каждой пары (дизайн-система, компонент) оформление, имя которого равно имени компонента без учёта регистра, MUST получить `isDefault = true`
- **THEN** если такого нет, `isDefault` MUST получить оформление, созданное раньше остальных

#### Scenario: Единственность

- **WHEN** запись нарушила бы единственность конфигурации по умолчанию пары
- **THEN** `ds-service` MUST отклонить запись с кодом `default_appearance_conflict`

### Requirement: Создание новой конфигурации

`ds-service` SHALL предоставлять операцию создания пустой конфигурации компонента в дизайн-системе. Новая конфигурация SHALL получать уникальное имя вида `<имя компонента> new` (с числовым суффиксом при занятом имени) либо имя из запроса, `isDefault = false` и ось цветовой схемы со значением `default`.

#### Scenario: Создание

- **WHEN** редактор создаёт новую конфигурацию
- **THEN** `ds-service` MUST создать оформление, ось цветовой схемы и её значение `default` одной транзакцией
- **THEN** новая конфигурация MUST NOT содержать значений свойств

#### Scenario: Имя занято

- **WHEN** имя оформления уже занято в паре (дизайн-система, компонент)
- **THEN** `ds-service` MUST ответить `422` с кодом `appearance_name_taken`

### Requirement: Дублирование конфигурации

`ds-service` SHALL предоставлять операцию дублирования конфигурации: копию объявления осей (на те же вариации каталога), значений осей с отображаемыми именами, стилей, сочетаний, значений свойств с наборами состояний и порядком, поправок платформенных параметров и ссылок на стили вложенных компонентов. Копия SHALL иметь `isDefault = false` и новое уникальное имя.

#### Scenario: Копия независима

- **WHEN** конфигурация продублирована, а затем значение свойства или имя оси изменено в копии
- **THEN** исходная конфигурация MUST остаться без изменений

#### Scenario: Копия состояний и ссылок

- **WHEN** в исходной конфигурации есть значения с состояниями и ссылки на стили вложенных компонентов
- **THEN** копия MUST содержать те же значения, порядок состояний и ссылки на те же целевые стили

#### Scenario: Одна транзакция и журнал

- **WHEN** выполняется дублирование
- **THEN** `ds-service` MUST записать все сущности копии одной транзакцией
- **THEN** журнал MUST содержать запись `CREATE` для каждой созданной сущности
- **THEN** откат создания копии MUST удалять её целиком, если на неё не ссылаются другие действующие сущности

#### Scenario: Повтор запроса

- **WHEN** запрос повторён с тем же ключом повторяемости и телом
- **THEN** `ds-service` MUST вернуть сохранённый результат без второй копии

### Requirement: Переименование и удаление конфигурации

Переименование и удаление конфигурации SHALL выполняться существующими `PATCH` и `DELETE` оформления по правилам многопользовательского редактирования.

#### Scenario: Переименование

- **WHEN** редактор переименовывает конфигурацию, в том числе конфигурацию по умолчанию
- **THEN** `ds-service` MUST записать новое имя уникально в паре (дизайн-система, компонент)
- **THEN** ссылки других оформлений на неё MUST пересобраться правилами `component-nested-style-references`

#### Scenario: Удаление обычной конфигурации

- **WHEN** редактор удаляет конфигурацию с `isDefault = false`, на которую не ссылаются другие значения
- **THEN** `ds-service` MUST удалить объявления осей, значения, сочетания и ссылки этой конфигурации в черновике
- **THEN** откат MUST вернуть конфигурацию

#### Scenario: На конфигурацию ссылаются

- **WHEN** на удаляемую конфигурацию ссылаются значения других оформлений
- **THEN** `ds-service` MUST ответить `409` с кодом `reference_in_use` и перечнем затронутых значений, если каскад не подтверждён
