## Why

Новый редактор компонентов (прототип SDDS Portal) позволяет добавлять и переименовывать оси вариаций, добавлять состояния (интерактивные и семантические) к значениям свойств и задавать для свойства ссылку на стиль вложенного компонента. Бэкенд `ds-service` к этому не готов: переименование оси через `PATCH /variations/{id}` меняет её во всех оформлениях и дизайн-системах, правки пишутся отдельными неатомарными запросами либо заменой всего оформления через `import`, а ссылки на стили вложенных компонентов (`component_style_references`) есть только в схеме и пишутся лишь при импорте.

## What Changes

- **Операции над оформлением.** Новый набор операций над оформлением компонента (`appearance`) по образцу операций токенов и палитры: каждая операция выполняется в одной транзакции, несёт `editRevision`, увеличивает его и возвращает `{ editRevision, value }`. Устаревшая ревизия даёт `409 APPEARANCE_EDIT_CONFLICT`.
- **Модель для редактора.** Чтение оформления одним запросом: оси, значения осей, сочетания, значения свойств с наборами состояний и вложенные ссылки, с идентификаторами и `editRevision`.
- **Оси и их значения.** Добавление, переименование, перестановка и удаление оси и её значений внутри оформления. Переименование меняет только отображаемое имя в этом оформлении; технические имена `variations.name` и `styles.name`, `authoredId` и другие оформления не затрагиваются.
- **Состояния значений свойств.** Запись значения свойства для базы, стиля или сочетания с упорядоченным набором состояний (интерактивные и семантические компонента); переупорядочивание наборов; неизвестное состояние отклоняется, а не теряется. Создание самих состояний остаётся за системным администратором.
- **Вложенные компоненты.** Значение типа `component_style` записывается вместе со ссылкой на стиль вложенного компонента: проверка цели, циклов и глубины, запись `component_style_references` в той же транзакции, в том числе для значений с состояниями. Переименование оси или значения пересобирает строки ссылок, которые на них указывают.
- **Миграция схемы** `V8` (Flyway, `ds-service`): `appearances.edit_revision`, `appearance_variations.display_name`, `appearance_variation_values.display_name`.
- **Чтение конфигурации** (`ComponentConfigBuilder`, экспорт, превью) использует действующее имя оси и значения.
- **Не входит:** условия `instanceTarget` (булевы и строковые пропсы экземпляра), копирование оформления целиком, создание состояний и осей общего слоя вне оформления, серверное хранение черновика, изменение клиентского редактора.

## Capabilities

### New Capabilities
- `component-editor-operations`: чтение модели оформления для редактора, операции над осями, значениями осей и значениями свойств с наборами состояний, ревизия оформления, права.
- `component-nested-style-references`: запись и проверка ссылок на стиль вложенного компонента, пересборка при переименовании.

### Modified Capabilities
- `component-appearance-model`: действующее имя оси и значения принадлежит оформлению; конфигурация отдаётся с действующими именами.
- `component-state-model`: набор состояний значения задаётся именами, порядок значим, неизвестное состояние отклоняется, редактор не создаёт состояния.

## Impact

- `backend-kt/ds-service`: `feature-components` (use case, репозиторий, маршруты, DTO, `ComponentConfigBuilder`, `ComponentConfigImporter`), `app` (Flyway `V8`; номер `V7` занят change `select-compose-preview-plugin-by-meta-version`, порядок слияния согласовать), `contracts` (манифест маршрутов, аудит потребителей), `openapi/documentation.yaml`.
- `js/services/db-service`: схему не дублируем (таблицы принадлежат `ds-service`); проверить потребителей `legacy/.../component-configs`, читающих `variations.name`.
- `js/apps/client`: контракт для будущего редактора; кода этого change здесь нет.
- `frontend-kt`: `dsbuilder components` (импорт и экспорт) читает и пишет действующие имена; изменений интерфейса CLI нет.
- Совместимость: новые колонки допускают `NULL`, существующие данные и клиенты работают без изменений.
