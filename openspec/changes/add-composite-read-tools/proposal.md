# Составные чтения модели и документации

## Зачем

Выбор вариаций, извлечение токен-ссылок и проекции опубликованного кода сейчас частично выполняются клиентом. Эти предметные операции должны жить на бэкенде и одинаково использоваться MCP и будущим Agent Service.

## Что меняется

- Существующий `component-config/export` расширяется `componentId` и объектом `selection`; сборщик конфигурации переиспользуется, полный экспорт CLI сохраняется.
- Новая операция чтения проверенных токен-ссылок выбранной конфигурации со стабильными ID и путями использования.
- Существующие чтения вариаций, свойств и зависимостей дополняются допустимыми значениями/defaults, платформенными параметрами и настройками переиспользования. Уже доступные метаданные целей не реализуются повторно.
- Новый список публикаций документации; существующие search/fetch/navigation/page/bindings маршруты сохраняются.
- Поиск получает явный `publicationId`; проекции и точные фильтры CodeBinding переносятся на сервер и включаются параметрами. Старые запросы продолжают получать полный ответ.
- **BREAKING** для MCP: `component_config_get` переходит на `componentId` и объект `selection`; отдельный `component_tokens_get` заменяет `projection=token-references`; поиск документации принимает `subjects[]`. HTTP-контракты прежних клиентов сохраняются.
- Добавляются четыре tools; итоговый реестр содержит ровно 26 инструментов чтения.

## Возможности

### Новые возможности

Нет: расширяются существующие возможности модели, документации и MCP.

### Изменяемые возможности

- `design-system-model-api`: составная конфигурация, ссылки на токены и обогащённые детали компонента.
- `documentation-publication-reading`: список публикаций, необязательные серверные проекции, сохранение ID-маршрутов.
- `documentation-search`: явная публикация и закрепление её между страницами без смены типов cursor.
- `frontend-mcp-server`: завершение реестра из 26 tools и перенос предметных вычислений на сервер.

## Зависимости и влияние

Зависит от `add-versioned-read-tools`: использует его серверный селектор, HTTP-метаданные и 22 инструмента. Не зависит от PKCE и работает с действующей пользовательской сессией или project key.

Затрагивает `backend-kt/ds-service`, `backend-kt/documentation-service`, их application/domain/data/presentation/di и OpenAPI, `frontend-kt/feature-components`, `feature-docs`, `mcp-server-core` и оба launcher. Схема JS db-service, платформы, данные, существующие маршруты и полная загрузка CLI сохраняются; web/admin не переводятся на новые обёртки. Нового Agent Service, миграций и сетевых поисковых зависимостей нет. Защищённые файлы процесса, архитектурных тестов и Strictacode policy вне scope.

Вместе с двумя соседними Change заменяет объединённый `unify-read-tools-and-pkce`; перенесённые задачи не считаются выполненными.
