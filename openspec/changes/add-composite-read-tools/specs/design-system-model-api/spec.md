## ADDED Requirements

### Requirement: Совместимый серверный выбор конфигурации

Существующий экспорт конфигураций SHALL поддерживать альтернативный componentId и объект selection без изменения прежнего полного пакета. Сборка, валидация и выбор SHALL выполняться на сервере в одной согласованной read-only транзакции выбранной версии.

#### Scenario: Прежний полный экспорт

- **WHEN** клиент передал прежние designSystemId, platform и необязательные components/styles без новых параметров
- **THEN** API MUST вернуть прежний полный пакет meta/components/underivedTypes без лимита списка и новой обёртки

#### Scenario: Выбор по ID

- **WHEN** componentId адресует доступный компонент выбранной DS
- **THEN** сервер MUST определить его платформу и использовать существующие данные и сборщик
- **WHEN** componentId передан вместе с components либо явная platform ему противоречит
- **THEN** сервер MUST вернуть INVALID_QUERY

#### Scenario: Частичный или неверный выбор

- **WHEN** selection определяет допустимые значения части осей
- **THEN** сервер MUST сузить выбранные оси и сохранить остальные
- **WHEN** ось или значение неизвестны либо выбор неоднозначен
- **THEN** сервер MUST вернуть INVALID_QUERY без успешного частичного результата

#### Scenario: Конкурентная запись

- **WHEN** черновик меняется во время сборки
- **THEN** конфигурация и метаданные X-DS-Read-Context MUST относиться к одному согласованному состоянию
- **THEN** операция MUST NOT записывать изменения в БД

### Requirement: Чтение проверенных токен-ссылок компонента

API SHALL предоставлять новую операцию по designSystemId, componentId, необязательным styles и полному selection, возвращающую проверенные tokenId, имена и пути использования в выбранной версии.

#### Scenario: Полный выбор

- **WHEN** определены все оси каждого выбранного оформления
- **THEN** сервер MUST проверить ссылки по каталогу той же версии и вернуть стабильные ID и места использования
- **THEN** результат MUST NOT вычислять значения темы или объявлять произвольные строки конфигурации токенами

#### Scenario: Неполный или недоступный выбор

- **WHEN** хотя бы одна ось не выбрана
- **THEN** сервер MUST вернуть INVALID_QUERY с безопасным описанием отсутствующего выбора
- **WHEN** компонент недоступен либо не связан с указанной DS
- **THEN** сервер MUST вернуть NOT_FOUND без утечки данных

### Requirement: Необязательное обогащение деталей компонента

Существующие чтения свойств и зависимостей SHALL поддерживать явный include для платформенных параметров и настроек переиспользования. Без include прежние тела SHALL сохраняться. Чтение осей конфигурации через GET /appearances/{id}/variations SHALL сохранить существующие values/defaults без повторного расширения.

#### Scenario: Детали запрошены

- **WHEN** клиент передал include=platformParams для properties либо include=reuseConfig для deps
- **THEN** сервер MUST собрать дополнительные данные выбранной модели без обхода связей клиентом
- **THEN** метаданные родителей и детей, уже доступные в deps, MUST сохраниться

#### Scenario: Вариации уже доступны в первом Change

- **WHEN** клиент читает GET /appearances/{id}/variations
- **THEN** контракт первого Change MUST сохранить обязательный appearanceId, существующие оси, values и defaultStyleId без include=values,defaults и новой серверной проекции
- **THEN** этот Change MUST NOT реализовывать их повторно или расширять GET /components/{id}/variations

#### Scenario: Предметный контекст расширения

- **WHEN** расширение глобального ресурса зависит от указанной DS
- **THEN** сервер MUST использовать существующую проверку связи ресурса с ней
- **THEN** старые ID-чтения без расширения MUST NOT получить новый обязательный designSystemId

#### Scenario: Платформы и формат сохранены

- **WHEN** прежний клиент читает детали без include
- **THEN** сервер MUST вернуть прежние массивы/объекты без context/data
- **THEN** платформы токенов, компонентов и документации MUST NOT преобразовываться
