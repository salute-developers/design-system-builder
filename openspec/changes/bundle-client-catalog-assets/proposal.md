## Why

На стенде разработки клиент DS Builder открывается по подпути `/dev/design-system-builder/client/`, а картинки каталога
(иконки боковой панели, заглушки пустых состояний, картинка ошибки) указаны в разметке путями от корня домена
`/catalog/...`. Браузер запрашивает их по адресу без подпути, получает перенаправление на HTML и показывает битые
картинки. Локально ошибка не видна, потому что там приложение открывается из корня, а сборка и тесты её не ловят.

## What Changes

- Картинки каталога, на которые ссылается клиент, переносятся из `js/apps/client/public/catalog/` в исходники клиента и
  подключаются через `import`. Итоговый адрес с учётом `BASE_URL` формирует сборщик Vite.
- Ссылки вида `src="/catalog/..."` в компонентах клиента заменяются на импортированные значения.
- Неиспользуемые файлы `project-cover-placeholder.svg`, `icons/rail-help.svg`, `icons/rail-notifications.svg`
  удаляются.
- Тест, который ищет картинку ошибки по буквальному пути `/catalog/error-state.png`, переводится на проверку
  импортированного адреса.

## Capabilities

### New Capabilities
- `client-static-assets`: клиент загружает собственные картинки по адресам, которые учитывают подпуть публикации
  приложения, а отсутствие файла картинки обнаруживается при сборке.

### Modified Capabilities

## Impact

- `js/apps/client`: `public/catalog/` (удаляется), новый каталог картинок в `src`, компоненты `Main.tsx`,
  `BuilderShell.tsx`, `Catalog.tsx`, `DesignSystemCard.tsx`, `Palette.tsx`, тест `ProjectsWorkflow.test.tsx`.
- Конфигурация сборки и deploy workflow не меняются: `BASE_URL` уже передаётся в `vite build`.
- `backend-kt` и `frontend-kt` не затрагиваются.
