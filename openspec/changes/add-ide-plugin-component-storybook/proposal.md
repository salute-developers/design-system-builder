## Why

Плагин для Android Studio / IntelliJ IDEA показывает только токены. Разработчику, который подключает
компонент дизайн-системы, всё равно приходится открывать веб-редактор, чтобы увидеть, как компонент
выглядит, выбрать вариацию и найти, как она называется в коде. Кроме того, плагин не публикуется:
его собирают вручную и передают файлом.

## What Changes

- В плагин добавляется раздел «Компоненты» (storybook): список Compose-компонентов выбранной
  дизайн-системы и окно компонента с превью.
- Окно компонента позволяет менять вариацию (значения осей вариаций) и конфигурацию (оформление
  компонента) и сразу показывает результат. Изменения живут только в окне и никуда не сохраняются.
- В окне компонента есть кнопка «Копировать код»: в буфер обмена попадает представление выбранной
  вариации в коде (`composeReference`) из CodeBinding опубликованной документации, так же как для
  токенов. Ссылка выбирается по конфигурации и полному набору значений осей; неоднозначное
  совпадение не копируется.
- Превью рисуется тем же Wasm-плагином превью Compose, что и в веб-клиенте, внутри встроенного
  браузера IDE (JCEF). Адрес плагина плагин IDE получает у ds-service
  (`GET /api/design-systems/catalog/compose-preview/plugin`). Сборка payload превью переносится на Kotlin в
  `frontend-kt` и проверяется общими фикстурами протокола. Для вложенных ссылок на стили
  дополнительно загружаются конфигурации связанных компонентов той же дизайн-системы.
- Релиз плагина публикуется в GitHub Release по тегу `idea-plugin-v*`: архив плагина и `SHA256SUMS`.
- **Не меняются** ds-service, схема Preview Protocol v1 и веб-клиент.

## Capabilities

### New Capabilities
- `ide-plugin-component-storybook`: список компонентов, окно компонента, выбор вариации и
  конфигурации, копирование кода вариации.
- `ide-plugin-preview-host`: запуск Compose-плагина превью в JCEF, обмен сообщениями протокола,
  сборка payload в Kotlin, запасное состояние без JCEF.
- `ide-plugin-release`: сборка и публикация плагина в GitHub Release.

### Modified Capabilities
- `ide-plugin-token-browser`: плагин перестаёт быть «только про токены»: расширяется требование
  read-only и состав зависимостей модуля, навигация сохраняет раздел и выбранный компонент.

## Impact

- `frontend-kt/plugins/android-studio`: новые пакеты `components`, `preview`, `storybook`; зависимость
  от JCEF (входит в платформу IDE), `plugin.xml` (версия, `since/until`, описание).
- `frontend-kt`: возможное расширение `feature-theme`/`core-*` не требуется; общий код не выносится.
- `js`: меняется только набор golden-файлов для проверки Kotlin-ассемблера (экспорт из TypeScript
  ассемблера без изменения его поведения); веб-клиент остаётся источником эталона.
- `backend-kt`: без изменений, используются существующие маршруты `editor-bundle`, `compose-preview/plugin`,
  публикации документации.
- `.github/workflows`: новый `publish-ide-plugin-release.yml`; `validate-frontend-kt.yml` запускает
  сборку плагина.
- Новые зависимости: нет, кроме Gradle-задачи `buildPlugin` и проверки совместимости IDE.
