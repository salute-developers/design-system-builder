## ADDED Requirements

### Requirement: Плагин превью запускается в JCEF

Плагин IDE SHALL запускать опубликованный Compose-плагин превью во встроенном браузере IDE (JCEF), получая адрес плагина запросом `GET /api/design-systems/catalog/compose-preview/plugin`, и SHALL общаться с ним сообщениями Preview Protocol v1 (`sdds.preview.ready`, `payload`, `result`, `describe`, `description`). Манифест `preview-plugin.json` MUST проверяться теми же правилами, что в `compose-preview-plugin-loading`.

#### Scenario: Совместимый плагин

- **WHEN** ds-service отдаёт адрес активного билда, а манифест объявляет платформу `compose`, протокол v1, точку входа, обязательные сообщения и выбранный компонент
- **THEN** плагин IDE загружает точку входа в JCEF и после `sdds.preview.ready` отправляет payload

#### Scenario: Несовместимый или недоступный плагин

- **WHEN** адрес не получен, манифест недоступен, версия протокола или платформа не поддерживается либо компонента нет в манифесте
- **THEN** окно компонента показывает причину и не запускает превью
- **THEN** остальные функции окна продолжают работать

#### Scenario: Одна сессия на раздел

- **WHEN** пользователь меняет выбранный компонент внутри раздела «Компоненты»
- **THEN** плагин использует ту же сессию превью без повторной загрузки плагина
- **THEN** до `success` нового payload область превью показывает состояние загрузки, а не кадр предыдущего компонента

#### Scenario: Закрытие

- **WHEN** пользователь покидает раздел «Компоненты», меняет дизайн-систему или закрывает tool window
- **THEN** сессия освобождает браузер, подписки и таймеры

#### Scenario: Плагин не отвечает

- **WHEN** `ready` или результат не получен за заданное время
- **THEN** окно показывает ошибку с повтором, не зависая

### Requirement: Сборка payload на Kotlin

Плагин IDE SHALL собирать payload превью из данных основного `editor-bundle`, дополнительно загруженных конфигураций ссылочных компонентов и значений токенов выбранного tenant платформы `android` функцией, не зависящей от Compose и IDE. Результат MUST соответствовать каноничной JSON Schema Preview Protocol v1 и MUST совпадать с payload TypeScript-ассемблера веб-клиента на общих фикстурах.

Плагин SHALL читать определения через `GET /api/design-systems/{designSystemId}/tokens`, а значения — через `GET /api/design-systems/{designSystemId}/tenants/{tenantId}/token-values?platforms=android`, используя тот же `versionId`, что у конфигураций, если версия выбрана. Режим `light`/`dark` SHALL выбирать соответствующие тематические токены без подстановки значений других платформ или tenant. Для обхода ссылок SHALL применяться предел `MAX_STYLE_REFERENCE_DEPTH = 5` из `js/apps/client/src/composePreview/draft.ts`: при пяти ссылках в активном пути следующая ссылка отклоняется.

#### Scenario: Значения токенов для Compose

- **WHEN** пользователь открывает Compose-превью для выбранных tenant и режима темы
- **THEN** запрос значений содержит `platforms=android`, данные принадлежат выбранному tenant и версии
- **THEN** черновик использует `themeValuePlatform=android` и выбранный режим темы, как веб-превью Compose

#### Scenario: Предел глубины ссылок

- **WHEN** активный путь уже содержит пять ссылок и требуется переход по следующей
- **THEN** загрузчик возвращает диагностику с путём ссылки и не отправляет неполный payload

#### Scenario: Паритет с веб-клиентом

- **WHEN** Kotlin-ассемблер получает черновик из общей фикстуры (кнопка, состояния, alpha, ресурсы, вложенные стили)
- **THEN** его payload MUST совпадать с эталоном, экспортированным из TypeScript-ассемблера

#### Scenario: Полный путь загрузки вложенного стиля

- **WHEN** тестовый клиент получает HTTP-ответы основного компонента и другого компонента, на стиль которого ссылается основной
- **THEN** построенный из этих ответов черновик и payload содержат разрешённый вложенный стиль и совпадают с эталоном веб-клиента
- **THEN** проверка охватывает загрузку и построение черновика, а не только ассемблер готового черновика

#### Scenario: Некорректный вход

- **WHEN** в черновике нет токена, свойство не сопоставлено с Compose или есть цикл ссылок
- **THEN** ассемблер возвращает диагностику с кодом и путём вместо payload
- **THEN** окно показывает, какое свойство не удалось собрать

### Requirement: Превью недоступно без JCEF

Плагин IDE SHALL проверять поддержку JCEF перед созданием превью и при её отсутствии MUST NOT падать.

#### Scenario: JCEF не поддерживается

- **WHEN** `JBCefApp.isSupported()` возвращает `false`
- **THEN** окно компонента показывает состояние «Превью недоступно в этой IDE» с пояснением
- **THEN** выбор вариации и копирование кода остаются доступными

### Requirement: Изоляция браузера и JS-моста

Плагин SHALL запускать удалённое превью только в изолированном `iframe` локальной доверенной страницы-обёртки. Разрешённый удалённый origin SHALL фиксироваться из проверенного `pluginUrl`. `CefRequestHandler` SHALL блокировать навигацию и перенаправления на посторонние origin и открытие внешних окон; локальная обёртка SHALL быть единственным исключением для верхнего фрейма. `CefResourceRequestHandler` SHALL блокировать сетевые ресурсы посторонних origin. Мост `JBCefJSQuery` SHALL быть доступен только доверенной обёртке; сообщения от `iframe` SHALL проверяться по `event.source`, `event.origin`, схеме Preview Protocol v1, текущей сессии и `requestId`. Исходящие сообщения SHALL адресоваться точному `targetOrigin`. Мост SHALL NOT исполнять команды, скрипты или произвольные вызовы JVM/IDE по данным удалённой страницы.

#### Scenario: Переход на посторонний адрес

- **WHEN** превью пытается перейти, перенаправить фрейм, открыть окно или загрузить сетевой ресурс с другого origin
- **THEN** запрос блокируется до загрузки постороннего содержимого
- **THEN** удалённая страница не получает доступ к мосту JVM

#### Scenario: Недопустимое сообщение

- **WHEN** сообщение пришло из другого фрейма или origin, нарушает схему, направление, текущую сессию или `requestId`
- **THEN** оно отбрасывается без выполнения действия в JVM и изменения актуального превью

### Requirement: Секреты сессии не передаются в браузер

Плагин SHALL получать дескриптор превью и данные дизайн-системы авторизованным JVM-клиентом. Манифест, точка входа и статические Wasm/JS-ресурсы по `pluginUrl` SHALL загружаться анонимно. Плагин SHALL NOT передавать access/refresh token, заголовки авторизации, cookie OAuth или иные сведения сессии в URL, страницу, профиль браузера или JS-мост. В браузер SHALL передаваться только данные, необходимые для превью; профиль авторизации IDE SHALL NOT переиспользоваться.

#### Scenario: Анонимная раздача сборки

- **WHEN** опубликованная сборка статических файлов доступна по `pluginUrl` без авторизации
- **THEN** превью загружается без токенов в запросах браузера и сообщениях моста

#### Scenario: Статическая раздача требует авторизацию

- **WHEN** манифест, точка входа или ресурс отвечают `401`/`403` либо перенаправляют на страницу входа
- **THEN** плагин показывает ошибку загрузки без передачи токена или открытия формы входа внутри JCEF
- **THEN** остальные функции окна компонента остаются доступны
