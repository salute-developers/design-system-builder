## MODIFIED Requirements

### Requirement: Плагин загружается во время работы по адресу
Клиент SHALL загружать плагин Compose-preview во время работы. Адрес плагина определяется либо прямым значением переменной сборки `VITE_COMPOSE_PREVIEW_PLUGIN_URL`, либо запросом к бэкенду за адресом активного билда (capability `compose-preview-plugin-selection`); прямое значение имеет приоритет. Файлы плагина MUST NOT входить в сборку клиента, MUST NOT линковаться с кодом клиента и MUST NOT храниться в Git-репозитории.

#### Scenario: Смена адреса плагина
- **WHEN** значение `VITE_COMPOSE_PREVIEW_PLUGIN_URL` указывает на другую сборку плагина
- **THEN** клиент MUST загружать manifest и точку входа новой сборки без изменения кода клиента

#### Scenario: Адрес от бэкенда
- **WHEN** прямой адрес не задан, а бэкенд вернул адрес активного билда
- **THEN** клиент MUST загрузить manifest и точку входа этого билда

#### Scenario: Сборка клиента не содержит плагин
- **WHEN** выполняется сборка клиента
- **THEN** результат сборки MUST NOT содержать файлы плагина

#### Scenario: Архив плагина не хранится в репозитории
- **WHEN** выполняется проверка файлов, добавленных переносом прототипа
- **THEN** бинарный архив плагина и распакованные файлы Wasm MUST отсутствовать в Git

### Requirement: Происхождение выполняемого кода
Эта функция SHALL использовать только плагин, собранный командой SDDS из `plasma-android` и опубликованный на бэкенд DSB авторизованной служебной учёткой или системным администратором. Загрузка плагинов из других источников, в том числе пользовательских, MUST NOT поддерживаться, а адрес по умолчанию MUST NOT задаваться в коде клиента.

#### Scenario: Адрес не задан и активного билда нет
- **WHEN** клиент собран без `VITE_COMPOSE_PREVIEW_PLUGIN_URL`, а бэкенд не сообщает активного билда
- **THEN** клиент MUST NOT пытаться загрузить плагин из какого-либо адреса по умолчанию

## ADDED Requirements

### Requirement: Документированная настройка источника адреса
`README.md` клиента SHALL описывать оба источника адреса плагина (бэкенд и прямой `VITE_COMPOSE_PREVIEW_PLUGIN_URL`), приоритет прямого адреса, локальный запуск с прямым адресом и принятый риск общего origin плагина и клиента при размещении в одном бакете. Прежнее требование раздавать плагин с отдельного origin MUST быть заменено описанием этого риска и мер.

#### Scenario: Разработчик настраивает окружение
- **WHEN** разработчик читает раздел Compose-preview в README клиента
- **THEN** README MUST описывать получение адреса от бэкенда, прямой адрес для локальной разработки и принятый риск общего origin
