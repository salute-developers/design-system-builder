## ADDED Requirements

### Requirement: Клиент получает адрес плагина от бэкенда

Если не задан прямой адрес плагина, клиент SHALL запросить системный маршрут preview выбранной ДС/версии, согласованный в `version-core-entities-and-preview` и использовать `pluginUrl` из ответа как адрес каталога плагина. Дальнейшая загрузка (manifest, entrypoint, iframe, проверка протокола) MUST выполняться существующим способом.

#### Scenario: Активный билд есть

- **WHEN** прямой адрес не задан, а бэкенд вернул `pluginUrl`
- **THEN** клиент MUST загрузить `preview-plugin.json` из этого каталога и продолжить стандартную загрузку плагина.

#### Scenario: Активного билда нет

- **WHEN** бэкенд ответил `404`
- **THEN** клиент MUST продолжать запрашивать доступные Compose-компоненты и данные редактора, но MUST NOT загружать отсутствующий плагин
- **AND** React-preview MUST работать без изменений.

### Requirement: Недоступность адреса отключает только Compose-preview

Если запрос адреса плагина завершился ошибкой (кроме `404`), клиент SHALL продолжать запрашивать доступные Compose-компоненты, оставить редактор/диагностику/исправления доступными, записать причину в консоль браузера и оставить React-preview доступным. Клиент MUST NOT подставлять адрес по умолчанию.

#### Scenario: Ошибка запроса адреса

- **WHEN** бэкенд отвечает ошибкой сервера или запрос не доходит
- **THEN** клиент MUST NOT предлагать Compose-preview ни в одном компоненте и MUST записать причину в консоль
- **AND** редактор токенов, тем и компонентов MUST продолжить работать.

#### Scenario: Некорректный ответ

- **WHEN** ответ бэкенда не содержит непустого `pluginUrl`
- **THEN** клиент MUST трактовать его как ошибку запроса адреса.

### Requirement: Прямой адрес плагина обходит запрос к бэкенду

Если задан `VITE_COMPOSE_PREVIEW_PLUGIN_URL`, клиент SHALL использовать его как адрес плагина и MUST NOT запрашивать адрес у бэкенда.

#### Scenario: Локальная разработка

- **WHEN** задан прямой адрес плагина
- **THEN** клиент MUST загрузить плагин по этому адресу
- **AND** запрос `GET .../compose-preview/plugin` MUST NOT выполняться.

### Requirement: Адрес плагина кешируется по выбранному контексту

Кеш MUST учитывать проект, ДС, выбранную границу, Core и buildId. Смена контекста MUST инвалидировать адрес и iframe; запоздалый ответ прежнего контекста MUST игнорироваться.

#### Scenario: Переключение компонентов не повторяет запрос

- **WHEN** пользователь переключает несколько Compose-компонентов в одном неизменившемся контексте
- **THEN** клиент MUST использовать ранее полученный адрес без повторного запроса.

### Requirement: Адрес плагина определяется выбранной версией дизайн-системы

Клиент SHALL запрашивать адрес по ДС и выбранной версии. Опубликованная версия MUST использовать закреплённую сборку, черновик — совместимую сборку текущего Core по правилам `version-core-entities-and-preview`.

#### Scenario: Просмотр опубликованной версии

- **WHEN** пользователь открывает редактор на опубликованной версии дизайн-системы
- **THEN** запрос адреса плагина MUST содержать селектор опубликованной версии
- **AND** Compose-preview MUST использовать закреплённый билд этой версии, независимо от глобально активного.
