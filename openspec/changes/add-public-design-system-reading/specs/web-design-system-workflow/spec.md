## ADDED Requirements

### Requirement: Поле доступности в настройках ДС
Настройки ДС SHALL показывать сразу под полем имени поле «Доступность» с выбором «Приватная» / «Публичная». Сохранение MUST использовать существующий PATCH и право `design-systems:write`, сохраняя ограничения проекта и технической ДС.

#### Scenario: Сохранение доступности
- **WHEN** уполномоченный участник выбирает «Публичная» и сохраняет форму
- **THEN** клиент MUST передать `visibility=public` и после успешного ответа отобразить сохранённое состояние
- **THEN** пояснение MUST сообщать, что без входа доступны по прямой ссылке только опубликованные версии

#### Scenario: Ошибка сохранения
- **WHEN** сервер отклоняет изменение
- **THEN** интерфейс MUST показать ошибку, сохранить введённое значение для исправления и MUST NOT показывать успешное сохранение

#### Scenario: Ссылка на последнюю публикацию
- **WHEN** ДС публична
- **THEN** настройки MUST предоставлять «Скопировать ссылку» с прямым веб-URL без версии
- **THEN** копирование ссылки для CLI/MCP MUST предоставлять `dsbuilder://…` без версии
- **THEN** существующее копирование точной версии MUST оставаться доступным отдельно

#### Scenario: Публикаций ещё нет
- **WHEN** публичность включена до первой публикации
- **THEN** интерфейс MUST разрешить сохранение и пояснить отсутствие доступных опубликованных данных по ссылке

### Requirement: Адресный веб-просмотр без входа
Прямые страницы публичной ДС и её тем SHALL открываться без входа и без загрузки закрытого проекта. Гостю и пользователю вне проекта SHALL предоставляться просмотр опубликованных данных без команд редактора.

#### Scenario: Прямая ссылка
- **WHEN** гость открывает ссылку без версии
- **THEN** клиент MUST открыть последнюю публикацию, показать её номер и закрепить границу для вложенных запросов
- **THEN** клиент MUST NOT запрашивать каталоги, карточку проекта, журнал или SSE и MUST NOT запускать автосохранение

#### Scenario: Закрытые действия
- **WHEN** публичную ДС просматривает гость либо пользователь вне проекта
- **THEN** настройки, создание, удаление, изменение, публикация и переходы к закрытому проекту MUST NOT предоставляться как доступные действия
- **THEN** серверный запрет MUST действовать независимо от интерфейса

#### Scenario: Приватная или пустая ДС
- **WHEN** прямое чтение возвращает `404` из-за приватности либо отсутствия публикаций
- **THEN** клиент MUST показать отсутствие доступных данных без обязательного перенаправления на вход

#### Scenario: Участник проекта
- **WHEN** участник с соответствующими правами открывает ДС без версии
- **THEN** действующий редактор черновика MUST сохраняться

### Requirement: Кеш и сессия публичного просмотра
Клиентский кеш SHALL различать API URL, ДС, версию и режим доступа/сессию. Смена сессии и доступности MUST сбрасывать соответствующие записи и MUST NOT выдавать кеш черновика гостю.

#### Scenario: Выход из редактора
- **WHEN** участник завершает сессию после чтения черновика
- **THEN** публичный просмотр MUST заново разрешить опубликованную версию без данных черновика из кеша

#### Scenario: Истёкшая сессия
- **WHEN** выбранная сессия не обновляется
- **THEN** клиент MUST показать ошибку авторизации без скрытого повтора гостем
- **THEN** чистый гостевой запрос MUST NOT запускать обновление токена
