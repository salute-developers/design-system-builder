## MODIFIED Requirements

### Requirement: Единый приоритет PAT и OAuth
CLI и MCP SHALL выбирать учётные данные сервера согласно явной политике авторизации. В `auto` явный `--api-key`, затем PAT из настроенного окружения, затем `DSBUILDER_API_KEY` имеют приоритет над пользовательской сессией; принудительная политика SHALL использовать только указанный тип; после серверного отказа авторизации субъект MUST NOT меняться.

#### Scenario: PAT найден

- **WHEN** политика `auto` находит непустой PAT выбранного запуска
- **THEN** запрос MUST использовать `Authorization: Bearer <PAT>`
- **THEN** пользовательская сессия MUST NOT использоваться для этого запроса

#### Scenario: PAT отсутствует

- **WHEN** политика `auto` не находит PAT
- **WHEN** для выбранного API URL существует валидная пользовательская сессия
- **THEN** клиент MUST получить access token и использовать `Authorization: Bearer <token>`

#### Scenario: Принудительная session

- **WHEN** политика выбирает `user-session`
- **THEN** клиент MUST использовать сессию для выбранного API URL или вернуть `AUTH_REQUIRED`
- **THEN** клиент MUST NOT выбирать доступный PAT

#### Scenario: Принудительный PAT

- **WHEN** политика выбирает `pat-env`
- **THEN** клиент MUST использовать выбранный PAT или вернуть ошибку учётных данных
- **THEN** клиент MUST NOT выбирать пользовательскую сессию

#### Scenario: PAT отклонен backend

- **WHEN** запрос с найденным PAT получает `401` или `403`
- **THEN** клиент MUST вернуть `PAT_INVALID` или `FORBIDDEN`
- **THEN** клиент MUST NOT повторять запрос с пользовательской авторизацией

#### Scenario: Bearer получает HTTP 401

- **WHEN** сервер отвечает `401` на GET, POST или multipart POST с пользовательским Bearer
- **THEN** общий HTTP-слой авторизации MUST принудительно обновить ту же пользовательскую сессию и повторить запрос ровно один раз
- **THEN** повторный `401` MUST удалить сессию и вернуть `AUTH_REQUIRED` без выбора PAT

#### Scenario: Bearer получает HTTP 403

- **WHEN** сервер отвечает `403` на запрос с пользовательским Bearer
- **THEN** клиент MUST вернуть `FORBIDDEN` без обновления токена и повтора

#### Scenario: Token endpoint недоступен во время refresh

- **WHEN** механизм авторизации возвращает `BACKEND_UNAVAILABLE` при обновлении выбранной пользовательской сессии
- **THEN** сценарий проектного чтения и MCP MUST сохранить `BACKEND_UNAVAILABLE`
- **THEN** клиент MUST NOT сообщать `AUTH_REQUIRED` и MUST NOT удалять сессию из-за транспортного сбоя

#### Scenario: PAT получает HTTP 401

- **WHEN** GET, POST или multipart POST с PAT получает `401`
- **THEN** клиент MUST вернуть `PAT_INVALID` без обновления токена OAuth и повтора
- **AND** MUST NOT удалять или менять сохранённую OAuth-сессию

#### Scenario: PAT получает HTTP 403

- **WHEN** запрос с PAT получает `403`
- **THEN** клиент MUST вернуть `FORBIDDEN` без повтора и смены учётных данных

#### Scenario: Чтение без источников авторизации
- **WHEN** операция допускает публичное чтение, политика `auto` не нашла PAT и сохранённой сессии
- **THEN** клиент MUST выполнить запрос без `Authorization`, открытия браузера и создания сессии
- **THEN** сервер MUST самостоятельно проверить доступность ресурса

#### Scenario: Ошибка существующей авторизации
- **WHEN** найденный PAT отклонён, обновление найденной сессии завершилось ошибкой или задана принудительная политика авторизации
- **THEN** клиент MUST сохранить существующую диагностику без скрытого перехода в анонимный режим

#### Scenario: Операция записи без входа
- **WHEN** операция требует авторизацию и источники учётных данных отсутствуют
- **THEN** клиент MUST вернуть `AUTH_REQUIRED` до запроса записи
