## Purpose

Определяет доступность отдельной дизайн-системы и адресное чтение её опубликованных версий без входа, сохраняя закрытость проекта, черновика и команд изменения.

## ADDED Requirements

### Requirement: Доступность отдельной дизайн-системы
ДС SHALL иметь текущую доступность `private` или `public`, независимую от версий. Новые, импортированные и скопированные ДС и все ДС после миграции MUST быть приватными по умолчанию.

#### Scenario: Обновление существующей базы
- **WHEN** применяется миграция доступности
- **THEN** ранее существовавшие ДС MUST получить `private`
- **THEN** техническое отсутствие проекта MUST NOT означать публичность

#### Scenario: Откат содержимого
- **WHEN** участник публикует, откатывает черновик или читает прежнюю версию
- **THEN** текущая доступность MUST сохраняться независимо от содержимого версии

### Requirement: Изменение доступности по существующему праву
PATCH карточки ДС SHALL принимать необязательное `visibility`; ответ SHALL содержать текущее значение. Изменение MUST требовать `design-systems:write` и действующих ограничений изменяемости ДС и проекта.

#### Scenario: Уполномоченный участник сохраняет публичность
- **WHEN** участник с необходимыми правами передаёт `{"visibility":"public"}`
- **THEN** сервер MUST сохранить значение и вернуть его в DTO
- **THEN** отсутствие публикаций MUST NOT запрещать настройку

#### Scenario: Совместимый запрос и неверное значение
- **WHEN** PATCH не содержит `visibility`
- **THEN** доступность MUST остаться прежней
- **WHEN** значение не входит в `private` / `public` либо равно `null`
- **THEN** сервер MUST вернуть `400` без изменения ДС

#### Scenario: Недостаточно прав
- **WHEN** гость или субъект без права изменения пытается поменять доступность
- **THEN** сервер MUST отказать с `401` либо `403` без изменения данных

### Requirement: Публичное чтение только по явному адресу
Гость и пользователь вне проекта SHALL читать публичную ДС только по ссылке или явно указанным проекту и ДС. Публичность MUST NOT открывать каталоги проектов и ДС, карточку проекта или его участников.

#### Scenario: Каталоги остаются закрытыми
- **WHEN** гость вызывает `GET /api/projects` либо `GET /api/projects/{projectId}/design-systems`
- **THEN** сервер MUST вернуть `401` без списка, даже если проект содержит публичную ДС

#### Scenario: Авторизованный пользователь вне проекта
- **WHEN** действующий пользователь без членства открывает явно указанную публичную ДС
- **THEN** сервер MUST разрешить только публичное чтение её публикаций
- **THEN** пользователь MUST NOT получить проектную роль или список соседних систем

### Requirement: Только опубликованные данные
Публичный доступ SHALL возвращать только опубликованную границу выбранной ДС; без селектора SHALL выбираться последняя поддерживаемая публикация по порядку публикации. Явный `draft` MUST NOT заменяться публикацией.

#### Scenario: Последняя публикация
- **WHEN** публичная ДС имеет две публикации и отличающийся черновик, а версия не указана
- **THEN** ответ MUST соответствовать последней публикации и сообщать её номер и `versionId`

#### Scenario: Точная версия
- **WHEN** гость указывает доступный номер версии или `versionId`
- **THEN** сервер MUST вернуть указанную опубликованную границу без перехода на последнюю или черновик

#### Scenario: Нет доступной публикации
- **WHEN** публикаций нет, версия неизвестна, ДС приватна, удалена либо принадлежит другому проекту
- **THEN** публичное чтение MUST вернуть `404` без содержимого и признаков существования недоступной ДС

#### Scenario: Черновик закрыт
- **WHEN** гость или пользователь вне проекта явно запрашивает `draft` публичной ДС
- **THEN** сервер MUST вернуть `403` без данных черновика

#### Scenario: Участник читает без версии
- **WHEN** участник с правом чтения черновика не указывает версию
- **THEN** сервер MUST сохранить чтение черновика
- **THEN** публичность MUST NOT расширять недостаточные проектные права участника

### Requirement: Граница публичных операций
Публичность SHALL разрешать только адресные операции чтения модели и необходимые экспорты. Запись, импорт с предварительной проверкой, публикация, журнал изменений, SSE, документация, поиск документации и административные операции MUST сохранять прежнюю авторизацию.

#### Scenario: Экспорт является чтением
- **WHEN** гость запрашивает `POST .../component-config/export` или `POST .../component-config/web-adapter` доступной публикации
- **THEN** сервер MUST вернуть только данные выбранной опубликованной границы без мутаций

#### Scenario: Изменение и служебное чтение
- **WHEN** гость обращается к операции записи, журналу, SSE или документации
- **THEN** сервер MUST потребовать авторизацию и MUST NOT выдать данные только на основании публичности ДС

#### Scenario: Подмена вложенного ресурса
- **WHEN** путь содержит публичную ДС A, а ID токена, темы, конфигурации или версии относится к B
- **THEN** сервер MUST вернуть `404` без содержимого B, включая пакетные и пустые ответы

#### Scenario: Разрешение чтения не открывает соседний GET
- **WHEN** публичному запросу разрешено читать карточку ДС, но он обращается к журналу или SSE с тем же проектным разрешением
- **THEN** сервер MUST отказать независимо от совпадения разрешений
- **THEN** неизвестная операция MUST NOT становиться публичной только из-за метода GET

### Requirement: Безопасный состав публичного ответа
Карточки, списки тем, счётчики, preview, токены и конфигурации SHALL соответствовать выбранной публикации. Публичные DTO MUST NOT раскрывать текущие `draftId`, `draftRevision`, журнал или сведения участников.

#### Scenario: Тема удалена в черновике
- **WHEN** опубликованная тема удалена или изменена только в черновике
- **THEN** гость MUST получить её опубликованные данные и соответствующие счётчики
- **THEN** nullable-поля актуального черновика MUST быть `null`

### Requirement: Отзыв публичности
После сохранения `private` каждый новый публичный запрос SHALL заново проверять доступность, включая запросы с ранее полученным `versionId`. Публичные HTTP-ответы MUST запрещать хранение через `Cache-Control: no-store`.

#### Scenario: Ранее выбранная версия после отзыва
- **WHEN** ДС стала приватной и гость повторяет запрос прежней публикации
- **THEN** сервер MUST вернуть `404`
- **THEN** участник с соответствующими правами MUST сохранить проектный доступ

#### Scenario: Уже полученные данные
- **WHEN** пользователь ранее скачал опубликованные файлы
- **THEN** отзыв MUST ограничивать новые серверные запросы и MUST NOT обещать удаление локальных копий

### Requirement: Перенос сохраняет текущую доступность
Перенос ДС SHALL сохранять её текущую доступность и опубликованные версии. Публичный доступ MUST проверять текущую принадлежность проекту, поэтому прежний адрес MUST NOT продолжать открывать перенесённую ДС.

#### Scenario: Публичная ДС перенесена
- **WHEN** уполномоченный пользователь переносит публичную ДС в другой проект
- **THEN** прежний адрес с исходным projectId MUST вернуть `404`
- **THEN** прямой адрес с новым projectId MUST открыть прежние доступные публикации по правилам публичного чтения без открытия каталога целевого проекта

#### Scenario: Приватная ДС перенесена
- **WHEN** уполномоченный пользователь переносит приватную ДС
- **THEN** она MUST остаться приватной и недоступной публичному чтению по обоим адресам
