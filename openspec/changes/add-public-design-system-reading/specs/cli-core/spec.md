## MODIFIED Requirements

### Requirement: Независимый выбор контекста и авторизации
Общая логика CLI SHALL получать контекст из `--design-system` либо локальной конфигурации независимо от авторизации. Для явной ссылки SHALL применяться `auto` с источниками `--api-key`, `DSBUILDER_API_KEY` процесса и OAuth-сессией без чтения авторизации из постороннего локального проекта. Для допускающей публичность операции чтения отсутствие этих источников SHALL разрешать анонимный запрос.

#### Scenario: Явная ссылка из чужой директории
- **WHEN** ссылка выбирает A, а `.sdds` и `.env` текущей директории относятся к B
- **THEN** контекст MUST соответствовать A
- **AND** клиент MUST NOT использовать настройки авторизации или `.env` B

#### Scenario: PAT со ссылкой
- **WHEN** задана ссылка и PAT доступен в `DSBUILDER_API_KEY` процесса
- **THEN** клиент MUST использовать PAT без дополнительных флагов выбора авторизации

#### Scenario: Ссылка без PAT
- **WHEN** PAT не задан, а OAuth-сессия доступна
- **THEN** клиент MUST использовать сессию для контекста ссылки


### Requirement: Общий HTTP-слой PAT и OAuth
Общий HTTP-слой SHALL поддерживать чтение, JSON-запись и multipart через типизированные PAT и OAuth-учётные данные с заголовком Bearer, а разрешённое публичное чтение — без заголовка авторизации. Авторизация PAT SHALL проверяться сервером; клиент MUST NOT проверять локально области разрешений, членство, отзыв или срок.

#### Scenario: Чтение и запись с PAT
- **WHEN** команда выполняет GET, JSON POST или multipart POST с выбранным PAT
- **THEN** запрос MUST использовать выбранный API URL и `Authorization: Bearer <PAT>`

#### Scenario: Отказы backend
- **WHEN** PAT получает `401`, `403` или `404`
- **THEN** клиент MUST вернуть соответственно `PAT_INVALID`, ошибку доступа или ошибку отсутствующего ресурса без смены учётных данных

#### Scenario: Анонимный HTTP-запрос
- **WHEN** общий сценарий выбрал анонимное чтение
- **THEN** транспорт MUST использовать тот же API URL и маршрут без `Authorization`
- **THEN** ответ `401` MUST NOT запускать обновление токена или повтор с другими учётными данными



## ADDED Requirements

### Requirement: Разрешённое начало многошагового чтения
Многошаговое чтение SHALL разрешать публикацию по метаданным первого разрешённого предметного ответа, без обязательного чтения карточки ДС. Неизменная граница SHALL закрепляться только для публикаций; живой черновик SHALL продолжать читаться через `draft`.

#### Scenario: Нет лишнего права карточки
- **WHEN** PAT разрешает предметную загрузку, но не разрешает чтение карточки ДС
- **THEN** клиент MUST начать с разрешённого предметного запроса и MUST NOT требовать `design-systems:read` ради выбора версии

#### Scenario: Опубликованная граница
- **WHEN** первый ответ содержит номер публикации и `versionId`
- **THEN** все последующие зависимые чтения одной загрузки MUST использовать этот `versionId`, пока доступ сохраняется

#### Scenario: Черновик публикуется между запросами
- **WHEN** участник читает `draft`, а между чтениями появляется публикация и новый черновик
- **THEN** последующие запросы MUST продолжить чтение активного `draft`, не используя прежний `draftId` как `versionId`
- **THEN** клиент MUST NOT обещать неизменный снимок черновика или переключаться на публикацию без выбора пользователя
