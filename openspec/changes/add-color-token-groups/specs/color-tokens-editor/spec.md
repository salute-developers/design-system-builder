## ADDED Requirements

### Requirement: Дерево показывает хранимые группы и подгруппы

Дерево SHALL строиться по группам и подгруппам токенов дизайн-системы (`GET …/token-groups?kind=color`) в их хранимом порядке. Токены SHALL располагаться в своей группе или подгруппе по `position`. Группы и подгруппы без токенов SHALL показываться.

#### Scenario: Строка токена

- **WHEN** дерево показывает токен
- **THEN** строка MUST содержать отображаемое имя и чип, верхняя половина которого — цвет Light, нижняя — Dark
- **THEN** выбор строки MUST открыть токен в инспекторе и прокрутить канвас к его свотчу

#### Scenario: Группы и подгруппы

- **WHEN** у дизайн-системы есть группа Text & Icons с подгруппами Accent и Status и токеном прямо в группе
- **THEN** дерево MUST показать заголовок группы, под ним токены группы без подгруппы, затем заголовки подгрупп с их токенами

#### Scenario: Пустая группа

- **WHEN** у группы или подгруппы нет токенов
- **THEN** дерево MUST показать её заголовок без строк токенов

#### Scenario: Первое открытие дизайн-системы без групп

- **WHEN** пользователь впервые открывает раздел «Цвета» дизайн-системы, у которой ещё нет групп, и `ds-service` создаёт их при чтении списка групп
- **THEN** клиент MUST запрашивать определения токенов после ответа списка групп, а не одновременно с ним
- **THEN** дерево MUST сразу показать токены в их группах и подгруппах; первая операция над деревом MUST NOT переносить остальные токены из «Без группы»

#### Scenario: Токен без группы

- **WHEN** у токена `groupId` равен `null`
- **THEN** дерево MUST показать его в подгруппе «Без группы» группы, код которой совпадает с первым сегментом имени, а если такой группы нет — в конце дерева

#### Scenario: Сортировка

- **WHEN** пользователь выбирает «А–Я»
- **THEN** токены внутри группы или подгруппы MUST быть упорядочены по отображаемому имени
- **WHEN** пользователь выбирает «Исходные»
- **THEN** группы, подгруппы и токены MUST быть в хранимом порядке

#### Scenario: Поиск

- **WHEN** пользователь вводит строку поиска
- **THEN** дерево MUST показать токены, имя или отображаемое имя которых содержит строку без учёта регистра, с их группами и подгруппами
- **THEN** при пустом результате MUST показываться пустое состояние «Ничего не найдено»

#### Scenario: Фильтр проблем

- **WHEN** пользователь включает фильтр — кнопку с подсказкой «Только токены с ошибками» (в прототипе подсказки нет)
- **THEN** дерево MUST показать только токены, у которых хотя бы одно значение Light, Dark или подтемы не проходит проверку значения

#### Scenario: Сворачивание

- **WHEN** пользователь сворачивает группу или подгруппу
- **THEN** её содержимое MUST скрыться, а состояние MUST сохраниться после перезагрузки страницы

### Requirement: Группы, подгруппы и токены создаются в списке

Редактор SHALL создавать группы, подгруппы и токены строкой с полем ввода прямо в дереве, без отдельного окна.

#### Scenario: Новая группа

- **WHEN** пользователь нажимает «+» в заголовке дерева, вводит «Brand» и нажимает Enter
- **THEN** клиент MUST отправить создание группы и после успеха показать группу в конце дерева

#### Scenario: Меню «+» у группы и подгруппы

- **WHEN** пользователь нажимает «+» у группы
- **THEN** клиент MUST показать меню «Добавить токен» и «Добавить подгруппу»
- **WHEN** пользователь нажимает «+» у подгруппы
- **THEN** клиент MUST сразу показать строку ввода нового токена в конце подгруппы
- **WHEN** группа или подгруппа свёрнута и пользователь начинает в ней добавление токена или подгруппы
- **THEN** группа или подгруппа MUST раскрыться, а строка ввода MUST быть видна

#### Scenario: Закрытие меню «+»

- **WHEN** меню «+» группы открыто
- **THEN** «+» MUST показываться нажатым, пока его меню открыто
- **THEN** меню MUST закрываться клавишей Escape, кликом вне меню и повторным нажатием на тот же «+»

#### Scenario: Новый токен

- **WHEN** пользователь добавляет токен в подгруппу, вводит «Highlight» и нажимает Enter
- **THEN** клиент MUST отправить создание токена типа `color` с именем `<код группы>.default.highlight`, `groupId` подгруппы, позицией в её конце, определениями всех контекстов и состояний и значениями выбранного токена той же группы, а без него — `#171717` для Light и `#F5F5F5` для Dark
- **THEN** после успеха токен MUST быть выбран, а его значения MUST редактироваться в инспекторе

#### Scenario: Вид строки ввода токена

- **WHEN** открыта строка ввода нового токена или переименования токена
- **THEN** строка MUST выглядеть как строка токена: квадрат цвета слева и имя, которое вводится прямо в строке, без поля с рамкой и скруглением
- **THEN** у нового токена квадрат MUST быть заглушкой нейтрального цвета, у переименуемого — чипом его цветов Light и Dark

#### Scenario: Отмена

- **WHEN** пользователь нажимает Escape или подтверждает пустое поле
- **THEN** строка ввода MUST исчезнуть без запроса

#### Scenario: Уход фокуса

- **WHEN** строка ввода создания или переименования теряет фокус: пользователь кликает вне поля или выбирает другой токен
- **THEN** изменённое непустое значение MUST сохраняться так же, как по Enter, а пустое или неизменённое — закрывать строку без запроса
- **THEN** после отказа сервера строка MUST остаться с текстом и ошибкой, и повторный уход фокуса с тем же значением MUST NOT отправлять его снова

#### Scenario: Открытие строки переименования

- **WHEN** пользователь открывает строку переименования группы, подгруппы или токена
- **THEN** текущее имя MUST быть выделено, чтобы ввод заменял его

#### Scenario: Ошибка создания

- **WHEN** имя после приведения пустое, занято или сервер отклонил создание
- **THEN** строка ввода MUST остаться с введённым текстом и показать ошибку: «Введите имя: латиница и цифры.», «Имя X уже занято.» или текст ошибки сервера

### Requirement: Группы, подгруппы и токены переименовываются на месте

Редактор SHALL переименовывать группу, подгруппу и токен двойным щелчком по строке дерева.

#### Scenario: Переименование группы

- **WHEN** пользователь меняет название группы и нажимает Enter
- **THEN** клиент MUST отправить изменение названия, а имена токенов группы MUST NOT измениться

#### Scenario: Переименование токена

- **WHEN** пользователь меняет имя токена `textAccent` на «Brand»
- **THEN** клиент MUST отправить перенос токена в его же группу с `name: "brand"` и после успеха показать токен как `textBrand`

#### Scenario: Переименование опубликованного токена

- **WHEN** у токена `publishedIn` не `null` и пользователь меняет его имя или переносит в группу с другим кодом
- **THEN** в строке ввода или у места вставки MUST показываться иконка-предупреждение с подсказкой «Токен опубликован в версии X. Новое имя изменит переменную в пакете дизайн-системы»
- **THEN** переименование MUST выполняться без подтверждения

#### Scenario: Переименование неопубликованного токена

- **WHEN** у токена `publishedIn` равно `null`
- **THEN** иконка-предупреждение MUST NOT показываться

### Requirement: Элементы дерева удаляются при наведении

Кнопка удаления SHALL появляться при наведении на группу, подгруппу и токен у пользователей с правом удаления.

#### Scenario: Пустая группа или подгруппа

- **WHEN** Maintainer удаляет группу или подгруппу без токенов
- **THEN** клиент MUST сразу отправить удаление

#### Scenario: Группа с токенами

- **WHEN** Maintainer удаляет группу или подгруппу с токенами
- **THEN** клиент MUST показать подтверждение с числом токенов и списком компонентов, где они используются, и после подтверждения отправить удаление

#### Scenario: Токен

- **WHEN** Maintainer нажимает удаление у строки токена
- **THEN** клиент MUST удалить токен по правилу «Удаление токена выполняется сразу»

#### Scenario: Editor

- **WHEN** тему открывает Editor
- **THEN** кнопки удаления групп, подгрупп и токенов MUST NOT показываться

### Requirement: Перетаскивание переносит токены и подгруппы

Редактор SHALL переносить перетаскиванием токен в другую группу или подгруппу и на позицию в ней, подгруппу — в другую группу, группу — на другую позицию.

#### Scenario: Токен в подгруппу другой группы

- **WHEN** пользователь перетаскивает `textAccent` в подгруппу группы Surfaces
- **THEN** клиент MUST отправить перенос токена с `groupId` подгруппы и позицией вставки
- **THEN** после успеха токен MUST показываться в новой подгруппе под новым именем, а значения и ссылки компонентов MUST сохраниться

#### Scenario: Порядок внутри подгруппы

- **WHEN** выбрана сортировка «Исходные» и пользователь переставляет токен внутри подгруппы
- **THEN** клиент MUST отправить перенос с новой позицией
- **WHEN** выбрана сортировка «А–Я»
- **THEN** перестановка внутри подгруппы MUST быть недоступна, перенос в другую группу или подгруппу MUST работать

#### Scenario: Подгруппа в другую группу

- **WHEN** пользователь перетаскивает подгруппу в другую группу
- **THEN** клиент MUST отправить изменение подгруппы с `parentId` новой группы и позицией вставки

#### Scenario: Сервер отклонил перенос

- **WHEN** перенос вернул ошибку, например `409 TOKEN_NAME_CONFLICT`
- **THEN** элемент MUST вернуться на прежнее место, а клиент MUST показать ошибку

## MODIFIED Requirements

### Requirement: Раздел «Цвета» показывает цветовые токены темы экраном Color Tokens

Веб-клиент SHALL показывать раздел «Цвета» темы тремя колонками — дерево токенов, канвас и инспектор — с
панелью инструментов над канвасом, а цветовым токеном экрана SHALL считать группу и имя без режима и
подгруппы.

#### Scenario: Пользователь открывает раздел

- **WHEN** пользователь открывает раздел «Цвета» темы
- **THEN** клиент MUST показать дерево, панель инструментов с вкладкой «Обзор», выбор вида канваса, канвас и
  инспектор
- **THEN** вкладка «Доступность» MUST NOT показываться: по решению команды проверка контраста на экране пока
  не выводится
- **THEN** каждый цветовой и градиентный токен MUST быть одной строкой дерева независимо от числа режимов и
  подгрупп
- **THEN** состояния `-hover` и `-active` MUST NOT показываться отдельными строками

#### Scenario: Пользователь меняет ширину панелей

- **WHEN** пользователь перетаскивает разделитель панели или нажимает стрелки на разделителе
- **THEN** ширина дерева MUST оставаться в пределах 220–320 px, а инспектора — 280–400 px
- **THEN** ширина MUST сохраниться после перезагрузки страницы

### Requirement: Канвас показывает борд свотчей или компонент

Канвас SHALL показывать либо борд свотчей, либо живой компонент дизайн-системы на текущих значениях темы.

#### Scenario: Борд свотчей

- **WHEN** выбран вид канваса «Палитра»
- **THEN** канвас MUST показать токены по группам и подгруппам в хранимом порядке карточками, разделёнными на Light и Dark; токены группы без подгруппы MUST идти перед подгруппами; группы и подгруппы без токенов MUST NOT выводиться
- **THEN** подпись Light и Dark MUST быть чёрной или белой по большему контрасту с цветом половины, наложенным на фон канваса с учётом прозрачности
- **THEN** выбор карточки MUST выбрать токен

#### Scenario: Компонент

- **WHEN** пользователь выбирает компонент в выборе вида канваса
- **THEN** канвас MUST показать компонент из конфигураций дизайн-системы
- **THEN** изменение значения токена MUST сразу отражаться на компоненте

### Requirement: Инспектор показывает значения токена и его связь с палитрой

Инспектор SHALL показывать заголовок с отображаемым именем и описанием, значения Light и Dark, подтемы OnDark,
OnLight и Inverse и действия токена. Поле группы палитры и поле имени SHALL NOT показываться.

#### Scenario: Имя токена

- **WHEN** пользователь выбирает токен
- **THEN** инспектор MUST показать отображаемое имя в заголовке и MUST NOT показывать поле «Имя»; токен переименовывается только двойным щелчком по строке дерева

#### Scenario: Значение связано с палитрой

- **WHEN** значение Light или Dark — ссылка на ступень палитры темы
- **THEN** поле MUST показать имя ступени палитры (например «Blue 500») и свотч с цветом по палитре темы
- **THEN** поле MUST быть только для чтения и открывать выбор цвета на вкладке Library
- **THEN** поле прозрачности MUST показываться только при прозрачности меньше 100 %

#### Scenario: Пользователь вводит HEX

- **WHEN** пользователь вводит HEX в поле значения
- **THEN** клиент MUST записать HEX с текущей прозрачностью, если не введены 8 цифр, и поставить токен в
  очередь автосохранения
- **THEN** связь значения с палитрой MUST быть снята

#### Scenario: Пользователь меняет прозрачность связанного значения

- **WHEN** пользователь меняет прозрачность значения, связанного с палитрой
- **THEN** клиент MUST сохранить ссылку на ту же ступень с новой прозрачностью

#### Scenario: Ступень палитры изменилась

- **WHEN** ступень, на которую ссылается токен, изменена в палитре темы
- **THEN** свотч, чип дерева, борд и компонент на канвасе MUST показать новый цвет без правки токена

### Requirement: Режим только для чтения

Раздел SHALL быть доступен только для чтения, если тема недоступна для изменения.

#### Scenario: Viewer открывает раздел

- **WHEN** Viewer открывает раздел «Цвета»
- **THEN** клиент MUST показать баннер режима просмотра
- **THEN** поля, выбор цвета, переключатели связи, «+», удаление, переименование, перетаскивание и сброс
  подтем MUST быть недоступны
- **THEN** клиент MUST NOT отправлять операции над токенами и группами
- **THEN** дерево, борд и компонент MUST работать

## REMOVED Requirements

### Requirement: Дерево группирует токены по разделам

**Reason**: Разделы больше не выводятся из имени токена: дерево строится по хранимым группам и подгруппам.
**Migration**: Требование «Дерево показывает хранимые группы и подгруппы»; разделы перенесены в группы миграцией `ds-service`.

### Requirement: Категория токена — группа палитры темы

**Reason**: Категория стала хранимой подгруппой и не зависит от группы палитры; поле «Группа палитры» на экране убрано по ревью.
**Migration**: Миграция `ds-service` создаёт подгруппы по прежним правилам категорий; явные привязки к группам палитры остаются в данных, смена группы в интерфейсе убрана (`theme-palette-editor`).

### Requirement: Пользователь создаёт цветовой токен

**Reason**: Окно «Новый токен» с полем «Категория» заменено созданием в списке.
**Migration**: Требование «Группы, подгруппы и токены создаются в списке».

### Requirement: Вкладка «Доступность» проверяет пары контраста в компонентах

**Reason**: Команда решила пока не показывать вкладку «Доступность» на экране «Цвета».
**Migration**: Вкладка и расчёт пар контраста остаются в коде клиента (`AccessibilityPanel`, `collectContrastPairs`) и возвращаются отдельным change вместе с этим требованием.
