## Why

Разделы и категории экрана «Цвета» сейчас не хранятся, а вычисляются. Раздел (Text & Icons, Surfaces) берётся из первого сегмента имени токена, категория (Accent, Status, General, Solid и Transparent) — из группы палитры темы и префикса `transparent-`, порядок — из случайного порядка строк в БД. Из-за этого нельзя завести свою группу или подгруппу, переложить токен в другую подгруппу или задать порядок. Создание через окно с непонятной «Категорией» ревью предлагает заменить созданием прямо в списке (комментарии к salute-developers/design-system-builder#106 от 15.10 и обсуждение команды).

Группы и подгруппы нужны всем типам токенов. Модель закладывается общей, а в этом изменении включается для цветовых и градиентных токенов.

## What Changes

- **Модель групп в `ds-service`.** У дизайн-системы появляются хранимые группы и подгруппы токенов: двухуровневое дерево с названием, порядком и типом токенов. Группа соответствует разделу экрана, подгруппа — категории внутри раздела. У группы есть код — первый сегмент имени её токенов, например `text` или `surface`. Токен ссылается на подгруппу и хранит позицию в ней. Пустые группы и подгруппы сохраняются.
- **Миграция существующих данных.** Для каждой дизайн-системы группы и подгруппы цветовых и градиентных токенов создаются по сегодняшним правилам экрана: раздел по имени, категория по правилу группы палитры по умолчанию и виду Solid или Transparent. Порядок берётся из сида определений.
- **Операции над группами.** Создание, переименование, перестановка и удаление группы или подгруппы, перенос подгруппы в другую группу. Каждая операция атомарна и сверяет общую ревизию тем дизайн-системы.
- **Перенос и переименование токена с сохранением идентификаторов.** Отдельная операция меняет подгруппу, позицию и имя всего семейства определений токена: контексты и состояния, в одной транзакции. Идентификаторы определений не меняются, поэтому ссылки компонентов через `token_id` остаются верными. При переносе в группу с другим кодом меняется первый сегмент имени. Отображаемое имя обновляется вместе с именем.
- **Ссылки компонентов на токены разрешаются по `token_id`.** Импорт конфигураций компонентов перестаёт дублировать имя токена текстом в `value`. Существующие дубли очищаются миграцией, сборка конфигурации берёт имя по `token_id`. Без этого переименованный токен оставался бы в компонентах под старым именем.
- **Создание токена в подгруппе.** Операция создания цветового токена принимает подгруппу вместо категории. Группа палитры для нового токена определяется правилом по умолчанию.
- **Цвет и градиент не разделяются при создании.** «Добавить токен» создаёт цветовой токен. Создание градиента и смена вида значения переходят в отдельную задачу, где градиент станет видом значения цветового токена в теме и режиме.
- **Экран «Цвета».**
  - Дерево и борд строятся по хранимым группам и подгруппам и их порядку, пустые группы видны.
  - «+» в заголовке дерева добавляет группу. «+» у группы открывает меню «Добавить токен» и «Добавить подгруппу», «+» у подгруппы сразу добавляет токен.
  - Группы, подгруппы и токены создаются прямо в списке и сразу переименовываются. Значения нового токена задаются в инспекторе, там же его переименовывают и удаляют. Переключатель Solid / Gradient в выборе цвета остаётся индикатором типа токена.
  - Кнопка удаления появляется при наведении на любой элемент списка.
  - Перетаскиванием токен переносится между подгруппами и группами, а подгруппа — между группами.
- **BREAKING (интерфейс).** Убираются окно «Новый токен» с полем «Категория» и поле «Группа палитры» в инспекторе. Смена группы палитры токена в интерфейсе больше не предлагается нигде: в разделе «Палитра» её не было, а на экране «Цвета» поле убрано. Явные привязки остаются в данных и в API `assignTokenGroup`, группа без привязки определяется правилом по имени. Нужна ли привязка токенов к пользовательским группам палитры, решается отдельно.

## Capabilities

### New Capabilities

- `token-groups-api`: хранимые группы и подгруппы токенов дизайн-системы в `ds-service`: модель, порядок, миграция существующих цветовых токенов, операции над группами, перенос и переименование токена с сохранением идентификаторов.

### Modified Capabilities

- `color-token-operations-api`: создание цветового токена в подгруппе вместо категории группы палитры; перенос и переименование семейства определений.
- `theme-palette-editor`: смена группы палитры токена убирается из интерфейса; явные привязки и правило по имени сохраняются.
- `color-tokens-editor`: дерево и борд по хранимым группам; создание в списке вместо окна; меню «+»; удаление при наведении; перетаскивание; нет поля «Группа палитры».
- `design-system-model-api`: значения свойств компонентов ссылаются на токен по `token_id`, имя в ответе берётся у токена, а не из сохранённого текста.

## Impact

- **backend-kt / `ds-service`:**
  - миграция Flyway V6: таблица групп, ссылка и позиция подгруппы у токенов, перенос данных, очистка дублей имени в значениях компонентов;
  - модули `feature-tokens` (группы, операции), `feature-themes` (создание, перенос и переименование цветового токена, блокировка тем дизайн-системы и ревизии) и `feature-components` (импорт и сборка конфигураций без текстовых имён);
  - OpenAPI `documentation.yaml`, `contracts/route-manifest.json`, `consumer-route-audit.json`.
- **js / `apps/client`:** раздел «Цвета» — дерево, борд, инспектор, перетаскивание, новые адаптеры операций. Окно «Новый токен» и поле `TokenPaletteGroupField` на экране удаляются.
- **js / `services/db-service`:** код не меняется. Legacy-маршрут `component-configs` после очистки дублей миграцией берёт имя по `token_id`.
- **js / `services/generator`, `documentation-generator`:** код не меняется. Имена переменных в собранном пакете строятся из имени токена, поэтому переименование и перенос токена между группами меняют публичный API пакета дизайн-системы. У опубликованных токенов это отмечается иконкой-предупреждением; признак публикации отдаёт `GET …/tokens`.
- **frontend-kt:** не затрагивается — плагин читает имена токенов в момент запроса.
- **Вне изменения:** группы для остальных типов токенов (формы, тени, типографика), градиент как вид значения отдельного режима цветового токена (цвет в Light и градиент в Dark) — отдельная задача, отдельные значения градиента по платформам.
