# Промежуточные измерения

## Условия

Исходная версия — `dev` на `f09a229e`. Одна копия синтетического снимка PostgreSQL 17:
153105 значений всего, 10407 в выбранной теме, 9804 в запросе цветов и градиентов.
Снимок создан исходной версией: старый дамп имел несовместимый checksum V18 и не использовался.
История миграций не исправлялась. Действующие dev и локальный стенд не изменялись.

Сравнительный код измерения одинаковый для вариантов. Исходники baseline извлечены в
`/tmp/ds-theme-optimization-baseline` без отдельной Git-ветки или worktree.
Данные `/tmp/theme-opt-fixture.dump` используются только в временных БД Testcontainers.

Это предварительные пары серий, а не итоговая приёмка. Не выполнены оба порядка A–B/B–A,
сравнение записи вместе с клиентской сверкой и полный набор сценариев design.md.
При профилировании JFR время не используется для сравнения скорости.

## Сохранение 36 значений

Одинаковое семейство из девяти определений, 36 адресов; три прогрева и двадцать измерений.
Обычный тестовый HTTP-хост; значения и базовые редакции берутся из подтверждения предыдущей записи.

| Показатель | Исходный | Первый пакетный вариант |
| --- | ---: | ---: |
| Медиана HTTP с получением и разбором ответа, мс | 276,292 | 74,957 |
| p95, мс | 318,636 | 80,380 |
| SQL-выполнений по pg_stat_statements | 892 | 122 |

Снижение медианы около 73%. SQL-счётчик PostgreSQL не равен JDBC-счётчику из dev-лога.
Это измерение первого пакетного варианта; последующие изменения снимка раскрытия требуют
повторной итоговой серии. Функциональные PostgreSQL-тесты отдельно подтвердили разные основания,
предупреждение по устаревшему адресу, атомарный отказ недопустимого пакета, непереданные значения,
смену типа и конкуренцию записи с откатом, переименованием, удалением и публикацией.

## Чтение

Первые варианты только лёгкого resolver дали недостаточный выигрыш полного `token-values`:
104,404 → 95,253 / 99,614 мс в тестовом хосте. Ответы совпали. Переход к Netty и отключение
отладочных имён корутин применены одинаково к обоим вариантам измерения; эти серии не смешиваются.

В Netty-серии отдельно используется существующее событие `http_request`, поскольку полное
время измерительного клиента включает получение и разбор большого JSON. Для цветов и градиентов
исходная серверная медиана — 91 мс, после переиспользования значений и определений — 66 мс
(около 27%) в промежуточном варианте. Последний вариант после устранения повторного чтения темы: 70 мс серверной медианы (около 23%), 97,109 мс полного клиентского времени, p95 132,037 мс, 20,1 SQL-выполнения. Исходное полное клиентское время — 120,730 мс. Отпечатки ответов совпадают. Цель снижения чтения на 30% пока не подтверждена; промежуточное лучшее значение не подменяет результат последней версии.

JFR короткой серии показал значительные выделения памяти в измерительном процессе, в том числе
при получении тела ответа; это не профиль работающего dev и не доказательство его причины задержек.

## Узкие проверки

- Сравнительные тесты resolver, эталон палитры, формы значений и use case связей.
- PostgreSQL: тип семейства, конкурентный откат, индивидуальные предупреждения записи,
  ограничения фильтра tokenIds, draft/published, изоляция тем и проектов, компактный журнал,
  серверные страницы и исторические чтения.
- Контракт OpenAPI фильтра tokenIds; привязка курсора к фильтрам; счётчики пула в диагностике.
- Клиент: 104 теста трёх затронутых наборов, включая одну загрузку связей, адресное обновление
  без потери соседних значений и защиту нового ввода. Проверка типов клиента прошла.

verify/FAST/FULL/review не запускались. Задача итогового сравнения остаётся открытой.
