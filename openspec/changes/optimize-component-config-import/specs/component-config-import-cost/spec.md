## ADDED Requirements

### Requirement: Чтения справочников не зависят от числа значений

Импорт конфигураций компонентов (`POST /api/design-systems/{designSystemId}/component-config/import`) SHALL читать
справочные данные, не зависящие от конкретной конфигурации, не более одного раза на запрос: компоненты платформы
импорта, свойства компонента, состояния, дочерние связи компонентов, идентификатор дизайн-системы. Число чтений
справочника MUST NOT расти с числом значений свойств, осей или сочетаний в пакете.

#### Scenario: Много значений одного компонента
- **WHEN** импортируется конфигурация, в которой у одного компонента сто значений свойств
- **THEN** свойства этого компонента MUST читаться из базы не более одного раза
- **THEN** идентификатор дизайн-системы MUST NOT читаться из базы при записи значений

#### Scenario: Один компонент в нескольких оформлениях
- **WHEN** пакет содержит несколько оформлений одного компонента
- **THEN** строка компонента, его свойства и состояния MUST читаться не более одного раза на запрос импорта

### Requirement: Бюджет обращений к базе на конфигурацию

Импорт SHALL укладываться в бюджет round trip к базе (`jdbcExecutions` в событии `ds_transaction`), заданный на
конфигурацию пакета: повторный импорт пакета без изменений — не более 40 обращений на конфигурацию плюс не более 200
на запрос; импорт новых и изменённых конфигураций — не более 150 обращений на конфигурацию плюс не более 200 на
запрос. Числа предварительные: их уточняет профиль задачи 1.2 до включения теста, но не в сторону ослабления более чем
вдвое без записи причины в design.

#### Scenario: Повторный импорт без изменений
- **WHEN** пакет из 144 конфигураций уже загружен и импортируется повторно без изменений
- **THEN** все конфигурации MUST попасть в `unchanged`
- **THEN** число обращений к базе MUST NOT превышать 40 × 144 + 200

#### Scenario: Первичный импорт пакета
- **WHEN** пакет из 144 конфигураций той же формы, что `sdds_serv`, импортируется в дизайн-систему без этих оформлений
- **THEN** число обращений к базе MUST NOT превышать 150 × 144 + 200
- **THEN** при задержке базы 5,5 мс время транзакции MUST быть не больше 120 секунд

#### Scenario: Рост пакета
- **WHEN** число конфигураций того же состава удваивается
- **THEN** число обращений к базе MUST NOT вырасти более чем вдвое

### Requirement: Результат импорта не зависит от способа выполнения

Оптимизация SHALL NOT менять результат импорта: состав строк и редакций в базе, идентификаторы существующих сущностей,
позиции значений и отчёт (`created`, `updated`, `unchanged`, `rejected`, `unknownProperties`, `unknownStates`,
`unresolvedTokens`, `unresolvedComponentStyles`, `typeMismatches`, `gradientOnlyProperties`,
`underivableVariationIds`) MUST совпадать с результатом до изменения на одном и том же входе.

#### Scenario: Эквивалентность на корпусе конфигураций
- **WHEN** один и тот же набор конфигураций (новые оформления, обновление существующих, неизменные, отклонённые,
  с ссылками на стили других компонентов, с сочетаниями стилей) импортируется до и после изменения
- **THEN** экспорт дизайн-системы после импорта MUST быть идентичен
- **THEN** отчёт импорта MUST быть идентичен

#### Scenario: Последняя запись оформления побеждает
- **WHEN** пакет содержит две записи одного оформления с разными значениями
- **THEN** в базе MUST оказаться значения последней записи
- **THEN** оформление MUST быть посчитано в отчёте один раз

#### Scenario: Идентификаторы сохраняются
- **WHEN** импортируется пакет, где часть значений существующего оформления не изменилась
- **THEN** идентификаторы неизменившихся значений MUST остаться прежними
- **THEN** редакции MUST NOT создаваться для значений без изменений

### Requirement: Атомарность и dry run сохраняются

Импорт SHALL выполняться одной транзакцией на запрос: при ошибке не должно остаться частичной записи. Пробный запуск
CLI без `--apply` SHALL выполнять тот же импорт и откатывать его, а его отчёт MUST совпадать с отчётом записи.

#### Scenario: Ошибка в середине пакета
- **WHEN** обработка одной из конфигураций пакета завершается ошибкой записи
- **THEN** ни одна конфигурация пакета MUST NOT остаться записанной

#### Scenario: Пробный запуск
- **WHEN** импорт выполняется без `--apply`
- **THEN** в базе MUST NOT остаться изменений
- **THEN** отчёт MUST совпадать с отчётом того же импорта с `--apply`

### Requirement: Стоимость импорта наблюдаема

Событие `ds_transaction` для запроса импорта SHALL содержать число SQL-операций, число обращений к базе (`jdbcExecutions`
и `jdbcBatchExecutions`) и время транзакции, чтобы стоимость пакета можно было сверить с бюджетом по логу `ds-service`.

#### Scenario: Сверка по логу
- **WHEN** на dev выполняется импорт пакета
- **THEN** лог `ds-service` MUST содержать событие `ds_transaction` этого запроса с `sqlCount`, `jdbcExecutions`,
  `jdbcBatchExecutions` и `totalMs`
