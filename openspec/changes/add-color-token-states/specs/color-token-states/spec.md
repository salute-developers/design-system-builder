## ADDED Requirements

### Requirement: Состояния токена показываются в дереве под токеном

Дерево раздела «Цвета» SHALL показывать состояния `-hover`, `-active` и `-brightness` цветового токена
дочерними строками его строки в порядке Hover, Active, Brightness. Состояние SHALL показываться, если в
дизайн-системе есть определение `<группа>.default.<имя>-<состояние>`.

#### Scenario: Токен с состояниями

- **WHEN** у токена `text.accent` есть определения `-hover` и `-active`
- **THEN** строка токена MUST показать стрелку раскрытия, по умолчанию свёрнутую
- **WHEN** пользователь раскрывает строку
- **THEN** под ней MUST показаться строки «Hover» и «Active» с чипом, верхняя половина которого — цвет Light
  состояния, нижняя — Dark
- **THEN** раскрытие MUST сохраниться после перезагрузки страницы

#### Scenario: Токен без состояний

- **WHEN** у токена нет определений состояний
- **THEN** строка токена MUST NOT показывать стрелку раскрытия

#### Scenario: Выбор состояния

- **WHEN** пользователь выбирает строку «Hover» токена `text.accent`
- **THEN** инспектор MUST открыть состояние `text.accent-hover`, а адрес MUST содержать `tokenId` определения
  `text.default.accent-hover`
- **THEN** борд MUST прокрутиться к карточке токена `text.accent` и подсветить её
- **WHEN** пользователь перезагружает страницу или переключает тему с этим адресом
- **THEN** редактор MUST снова открыть состояние `-hover` этого токена

#### Scenario: Поиск и фильтр проблем

- **WHEN** строка поиска совпадает с именем или отображаемым именем токена
- **THEN** результат MUST показать токен с его строками состояний
- **WHEN** включён фильтр «Только токены с ошибками» и не проходит проверку только значение состояния
- **THEN** дерево MUST показать токен с этим состоянием

#### Scenario: Строка состояния не переименовывается и не переносится

- **WHEN** пользователь дважды щёлкает строку состояния или начинает её перетаскивать
- **THEN** переименование и перетаскивание MUST NOT начинаться
- **WHEN** пользователь переносит или переименовывает токен
- **THEN** строки его состояний MUST остаться под ним с новым именем

### Requirement: Состояние добавляется кнопкой «+» у токена

Строка токена SHALL показывать при наведении кнопку «Добавить состояние» с меню недостающих состояний из
Hover, Active и Brightness. Имя определений состояния SHALL строить система, пользователь его не вводит.

#### Scenario: Добавление состояния с формулой

- **WHEN** пользователь с правом создания токенов выбирает «Hover» в меню токена `surface.accent` без `-hover` в дизайн-системе с темами A
  и B
- **THEN** клиент MUST прочитать значения токена в темах A и B, рассчитать формулой значение `-hover` каждой
  подгруппы и режима в каждой теме и отправить добавление состояния со значениями обеих тем
- **THEN** у значений подгруппы `default` MUST быть `detached: false`
- **THEN** после успеха строка «Hover» MUST появиться под раскрытым токеном и открыться в инспекторе

#### Scenario: Добавление состояния без формулы

- **WHEN** пользователь добавляет состояние токену группы без формулы, например `background`
- **THEN** значения состояния в каждой теме MUST совпадать со значениями токена той же подгруппы и режима
- **THEN** инспектор состояния MUST показать переключатель «По формуле» выключенным и недоступным

#### Scenario: Все состояния уже есть

- **WHEN** у токена есть Hover, Active и Brightness
- **THEN** кнопка «Добавить состояние» MUST NOT показываться

#### Scenario: Сервер отклонил добавление

- **WHEN** операция добавления вернула ошибку
- **THEN** дерево MUST остаться прежним, а клиент MUST показать ошибку
- **WHEN** ошибка — `400 INVALID_TOKEN_FAMILY` из-за изменившегося списка тем
- **THEN** клиент MUST перечитать список тем и значения токена и повторить добавление один раз

#### Scenario: Ручное имя с суффиксом состояния

- **WHEN** пользователь вводит в строке нового токена имя, оканчивающееся на `-hover`, `-active` или
  `-brightness`
- **THEN** клиент MUST показать ошибку «Имя не может оканчиваться на -hover, -active или -brightness.
  Состояние добавляется кнопкой «+» у токена.»

### Requirement: Инспектор состояния и расчёт по формуле

Инспектор состояния SHALL показывать Light, Dark, блок подтем, значения платформ и блок «В других темах» так же,
как инспектор токена, и переключатель «По формуле» над полями. Формула SHALL существовать у `-hover`, `-active`
и `-brightness` токенов групп `text`, `surface`, `outline` и `data`: у каждого правила формулы своя операция для
каждого состояния. Состояние SHALL считаться рассчитанным по формуле, если
формула есть и ни одно значение его подгруппы `default` не отмечено `detached`.

#### Scenario: Состояние по формуле

- **WHEN** пользователь открывает состояние `-hover`, рассчитанное по формуле
- **THEN** переключатель «По формуле» MUST быть включён, а поля Light, Dark и подтем MUST быть только для чтения
- **WHEN** пользователь меняет Light или подтему токена
- **THEN** значение состояния той же подгруппы и режима MUST пересчитаться формулой от нового значения токена,
  а у градиента MUST стать тем же градиентом

#### Scenario: Пользователь выключает формулу

- **WHEN** пользователь выключает «По формуле»
- **THEN** значения состояния MUST остаться прежними, а значения подгруппы `default` MUST сохраниться с
  `detached: true`
- **THEN** поля MUST стать доступными для правки, подтемы состояния MUST быть связаны с Light и Dark состояния
- **WHEN** пользователь затем меняет значение токена
- **THEN** значения состояния MUST NOT меняться
- **WHEN** тема перечитывается, пока правка токена ждёт автосохранения, а ручное состояние изменил другой
  пользователь
- **THEN** редактор MUST оставить значение состояния из новой загрузки и MUST NOT отправлять прежнее

#### Scenario: Ручная правка состояния

- **WHEN** формула выключена и пользователь меняет Light состояния
- **THEN** связанные подтемы состояния MUST получить унаследованное значение, как подтемы токена
- **WHEN** пользователь правит подтему состояния
- **THEN** подтема состояния MUST отвязаться от Light и Dark состояния

#### Scenario: Пользователь включает формулу

- **WHEN** пользователь включает «По формуле»
- **THEN** все значения состояния MUST пересчитаться формулой от значений токена, а `detached` MUST быть снят у
  значений подгруппы `default` и подтем состояния

#### Scenario: Заполнение ручного состояния

- **WHEN** у ручного состояния нет части значений и пользователь нажимает «Заполнить»
- **THEN** пустые значения MUST заполниться в определениях этого состояния, заданные значения MUST NOT меняться

#### Scenario: Состояние без формулы

- **WHEN** пользователь открывает состояние токена группы без формулы
- **THEN** переключатель «По формуле» MUST быть выключен и недоступен, рядом MUST быть подпись «Для группы нет
  формулы»
- **THEN** поля MUST быть доступны для правки

#### Scenario: Ручной признак одной платформы

- **WHEN** признак `detached` есть только у одного значения подгруппы `default` состояния, например iOS Dark после
  отката отдельной записи
- **THEN** инспектор MUST показать формулу выключенной, а правка токена MUST NOT менять значения состояния

#### Scenario: Формула для другой темы

- **WHEN** значение токена в теме B — ссылка палитры, которая в палитрах тем A и B даёт разные цвета
- **THEN** значение состояния темы B MUST считаться формулой от цвета палитры темы B

#### Scenario: Состояние сида

- **WHEN** у состояния сида нет `detached`, а его значения отличаются от результата формулы
- **THEN** инспектор MUST показать «По формуле» включённым, а значения MUST NOT меняться при открытии

#### Scenario: Режим только для чтения

- **WHEN** раздел открыт с `versionId` или пользователем без права записи
- **THEN** переключатель MUST быть недоступен, кнопки «Добавить состояние» и удаления состояния MUST NOT
  показываться

### Requirement: Состояние удаляется из дерева

Строка состояния и инспектор состояния SHALL показывать кнопку удаления у пользователей с правом удаления
токенов. Удаление SHALL подтверждаться, как удаление токена, и убирать состояние во всех подгруппах и темах
дизайн-системы.

#### Scenario: Состояние используется в компонентах

- **WHEN** Maintainer удаляет состояние, член которого используется в стилях или общих свойствах компонентов
- **THEN** окно «Удалить состояние?» MUST перечислить эти компоненты; компоненты, которые ссылаются только на
  сам токен или другие его состояния, MUST NOT перечисляться
- **THEN** после подтверждения клиент MUST отправить очередь автосохранения, затем удаление состояния

#### Scenario: Компоненты раздела загружены не полностью

- **WHEN** Maintainer открыл «Цвета» напрямую и удаляет состояние, а конфигурации компонентов в разделе загружены
  не полностью
- **THEN** окно MUST прочитать конфигурации всех компонентов дизайн-системы и до окончания чтения показывать
  «Проверяем, используется ли состояние в компонентах…» с недоступной кнопкой удаления
- **THEN** при ошибке чтения окно MUST перечислить известные компоненты и сообщить, что список может быть неполным

#### Scenario: Состояние без связей

- **WHEN** Maintainer удаляет состояние, которое не используется в компонентах
- **THEN** окно MUST сообщить «Состояние не используется в компонентах дизайн-системы.»
- **THEN** после подтверждения строка состояния MUST исчезнуть, а инспектор MUST открыть токен

#### Scenario: Editor

- **WHEN** тему открывает Editor
- **THEN** кнопка удаления состояния MUST NOT показываться
