## Why

Состояния цветовых токенов `-hover`, `-active` и `-brightness` хранятся отдельными определениями, но редактор их
скрывает. Пользователь не видит их значений, не может поправить состояние, если формула даёт не тот цвет, и не
может добавить состояние токену без него. Об этом напомнил ревью PR #166. На встрече 18 ноября команда решила:
состояние добавляется кнопкой «+» у токена, видно в дереве под токеном, а в инспекторе состояния есть
переключатель «По формуле».

## What Changes

- Дерево цветов показывает состояния токена дочерними строками `Hover`, `Active`, `Brightness` под строкой
  токена. Щелчок по строке состояния открывает инспектор состояния.
- У строки токена при наведении появляется «+» с меню недостающих состояний. Имя определения состояния система
  строит сама: `<группа>.<подгруппа>.<имя>-<состояние>`. Ручной ввод имени с суффиксом состояния по-прежнему
  запрещён.
- Инспектор состояния показывает Light, Dark, подтемы и значения платформ так же, как инспектор токена. Сверху
  стоит переключатель «По формуле». Включён — значения считаются формулой редактора от значений токена и не
  правятся. Выключен — значения задаются вручную, подтемы связаны с Light и Dark состояния, как у токена.
- Формула есть у `-hover`, `-active` и `-brightness` групп `text`, `surface`, `outline`, `data`: это правила
  `formulas.ts`, по которым прежний конструктор тем считал все три состояния. У других групп формулы нет:
  состояние задаётся только вручную, переключатель выключен и недоступен.
- Ручное значение состояния хранится признаком `detached` значений подгруппы `default` состояния. Новой колонки
  и миграции нет.
- Состояние удаляется кнопкой при наведении на его строку, с подтверждением, если оно используется в
  компонентах.
- `ds-service` получает две операции: добавление состояния существующему токену со значениями для каждой темы
  дизайн-системы и удаление состояния во всех подгруппах.
- Новый токен групп с формулой по-прежнему создаётся с `-hover` и `-active` по формуле.

## Capabilities

### New Capabilities

- `color-token-states`: состояния цветового токена в редакторе — строки дерева, добавление и удаление,
  инспектор состояния, расчёт по формуле и ручные значения.

### Modified Capabilities

- `color-tokens-editor`: дерево больше не скрывает состояния — они показываются дочерними строками токена.
- `color-token-operations-api`: операции добавления и удаления состояния цветового токена.

## Impact

- `backend-kt/ds-service/feature-themes`:
  - use case и маршруты `POST .../color-tokens/{tokenId}/states` и
    `DELETE .../color-tokens/{tokenId}/states/{state}`;
  - запросы, проверки состава семейства, журнал и откат через существующие редакции определений;
  - OpenAPI `runtime/src/main/resources/openapi/documentation.yaml` и контрактная проверка;
  - схема и миграции не меняются.
- `js/apps/client`:
  - модель дерева и разбор состояний `modules/colorTokens/domain`;
  - редактор `pages/colors/colorTokenEditor.ts` с формулой состояний, ручными значениями и переносом правок
    токена в состояния;
  - `ColorTokenTree`, `ColorTokenInspector`, `ColorTokensScreen`, репозиторий
    `modules/colorTokens/application/colorTokenRepository.ts`.
- `frontend-kt`: не меняется; CLI и плагин эти операции не используют.
- Редактор компонентов: выбор токенов состояний в библиотеке делается отдельной задачей и сюда не входит.
