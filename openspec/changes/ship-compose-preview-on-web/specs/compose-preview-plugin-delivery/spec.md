## ADDED Requirements

### Requirement: Плагин раздаётся как независимый статический артефакт
Wasm-плагин Compose-preview SHALL публиковаться как набор статических файлов по адресу, не входящему в сборку клиента. Клиент MUST NOT включать файлы плагина в свой каталог сборки и MUST NOT хранить их в Git-репозитории.

#### Scenario: Деплой клиента не затрагивает плагин
- **WHEN** выполняется синхронизация сборки клиента с хранилищем с удалением отсутствующих файлов
- **THEN** файлы плагина MUST остаться на месте, потому что лежат вне синхронизируемого каталога клиента

#### Scenario: Архив плагина не хранится в репозитории
- **WHEN** выполняется проверка файлов, добавленных переносом прототипа
- **THEN** бинарный архив плагина и распакованные файлы Wasm MUST отсутствовать в Git

### Requirement: Версионированный неизменяемый адрес
Каждая версия плагина SHALL публиковаться по собственному адресу, содержащему идентификатор версии, и опубликованные файлы версии MUST NOT перезаписываться. Адрес версии, с которой работает клиент, MUST задаваться переменной сборки `VITE_COMPOSE_PREVIEW_PLUGIN_URL`.

#### Scenario: Выпуск новой версии плагина
- **WHEN** публикуется новая версия плагина
- **THEN** она MUST быть размещена по новому адресу, а адрес предыдущей версии MUST продолжать отдавать прежние файлы

#### Scenario: Переключение версии у клиента
- **WHEN** значение `VITE_COMPOSE_PREVIEW_PLUGIN_URL` меняется на адрес другой версии и клиент пересобирается
- **THEN** клиент MUST загружать manifest и точку входа новой версии без изменения кода клиента

#### Scenario: Раздельные значения для окружений
- **WHEN** клиент собирается для DEV и для PROM
- **THEN** каждое окружение MUST получать свой адрес из собственной переменной репозитория, а не общий

### Requirement: Проверка manifest перед запуском
Клиент SHALL загружать `preview-plugin.json` из адреса плагина и MUST отклонять плагин, если manifest недоступен, не является корректным JSON, объявляет неподдерживаемую версию протокола или платформу, не содержит точки входа, не объявляет обязательных сообщений обмена либо не перечисляет компонент, для которого запрашивается preview.

#### Scenario: Совместимый plugin
- **WHEN** manifest объявляет платформу Compose, поддерживаемую версию протокола, точку входа, сообщения обмена и нужный компонент
- **THEN** клиент MUST продолжить загрузку точки входа в `iframe`

#### Scenario: Несовместимая версия протокола
- **WHEN** manifest объявляет версию протокола, которую клиент не поддерживает
- **THEN** клиент MUST не запускать плагин и MUST сообщить причину отказа

#### Scenario: Компонент не поддержан плагином
- **WHEN** нужный компонент отсутствует в списке компонентов manifest
- **THEN** клиент MUST не запускать Compose-preview для этого компонента

### Requirement: Требования к раздаче файлов
Хранилище, раздающее плагин, SHALL отдавать файлы `.wasm` с типом содержимого `application/wasm`, остальные файлы со своими корректными типами и разрешать браузеру загрузку точки входа в `iframe` страницы клиента. Раздача MUST быть проверена в целевом окружении до включения Compose-preview для пользователей.

#### Scenario: Тип содержимого Wasm
- **WHEN** браузер запрашивает файл `.wasm` плагина с адреса окружения
- **THEN** ответ MUST содержать `Content-Type: application/wasm`

#### Scenario: Кеширование
- **WHEN** запрашивается файл версионированного адреса
- **THEN** ответ MAY быть кеширован на длительный срок, а `preview-plugin.json` и точка входа этого адреса MUST оставаться неизменными для данной версии

### Requirement: Происхождение выполняемого кода
Первый выпуск SHALL использовать только плагин, собранный командой SDDS из `plasma-android`. Загрузка плагинов из других источников, в том числе пользовательских, MUST NOT поддерживаться этим изменением.

#### Scenario: Адрес не задан доверенно
- **WHEN** клиент собирается без `VITE_COMPOSE_PREVIEW_PLUGIN_URL`
- **THEN** клиент MUST NOT пытаться загрузить плагин из какого-либо умолчания
