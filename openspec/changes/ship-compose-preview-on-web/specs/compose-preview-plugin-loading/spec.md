## ADDED Requirements

### Requirement: Плагин загружается во время работы по адресу
Клиент SHALL загружать плагин Compose-preview во время работы по адресу из переменной сборки `VITE_COMPOSE_PREVIEW_PLUGIN_URL`. Файлы плагина MUST NOT входить в сборку клиента, MUST NOT линковаться с кодом клиента и MUST NOT храниться в Git-репозитории.

#### Scenario: Смена адреса плагина
- **WHEN** значение `VITE_COMPOSE_PREVIEW_PLUGIN_URL` указывает на другую сборку плагина
- **THEN** клиент MUST загружать manifest и точку входа новой сборки без изменения кода клиента

#### Scenario: Сборка клиента не содержит плагин
- **WHEN** выполняется сборка клиента
- **THEN** результат сборки MUST NOT содержать файлы плагина, а только строку адреса

#### Scenario: Архив плагина не хранится в репозитории
- **WHEN** выполняется проверка файлов, добавленных переносом прототипа
- **THEN** бинарный архив плагина и распакованные файлы Wasm MUST отсутствовать в Git

### Requirement: Проверка manifest перед запуском
Клиент SHALL загружать `preview-plugin.json` из адреса плагина и MUST отклонять плагин, если manifest недоступен, не является корректным JSON, объявляет неподдерживаемую версию протокола или платформу, не содержит точки входа, не объявляет обязательных сообщений обмена либо не перечисляет компонент, для которого запрашивается preview.

#### Scenario: Совместимый плагин
- **WHEN** manifest объявляет платформу Compose, поддерживаемую версию протокола, точку входа, сообщения обмена и нужный компонент
- **THEN** клиент MUST продолжить загрузку точки входа в `iframe`

#### Scenario: Несовместимая версия протокола
- **WHEN** manifest объявляет версию протокола, которую клиент не поддерживает
- **THEN** клиент MUST не запускать плагин и MUST сообщить причину отказа

#### Scenario: Компонент не поддержан плагином
- **WHEN** нужный компонент отсутствует в списке компонентов manifest
- **THEN** клиент MUST не запускать Compose-preview для этого компонента

### Requirement: Документированная раздача плагина
`README.md` клиента SHALL описывать, как собрать архив плагина в `plasma-android`, как раздать его статическим сервером и какие требования предъявляются к хостингу: тип содержимого `application/wasm` для файлов `.wasm`, возможность загрузки точки входа в `iframe` страницы клиента и доступность ресурсов, которые плагин запрашивает по сети. Для локальной работы MUST быть готовая команда запуска раздачи.

#### Scenario: Локальный запуск
- **WHEN** разработчик собрал архив плагина и выполнил команду локальной раздачи из README
- **THEN** клиент с адресом локального сервера MUST загружать плагин без дополнительной настройки

#### Scenario: Тип содержимого Wasm
- **WHEN** браузер запрашивает файл `.wasm` у локального сервера раздачи
- **THEN** ответ MUST содержать `Content-Type: application/wasm`

### Requirement: Происхождение выполняемого кода
Эта функция SHALL использовать только плагин, собранный командой SDDS из `plasma-android`. Загрузка плагинов из других источников, в том числе пользовательских, MUST NOT поддерживаться, а адрес по умолчанию MUST NOT задаваться в коде клиента.

#### Scenario: Адрес не задан
- **WHEN** клиент собирается без `VITE_COMPOSE_PREVIEW_PLUGIN_URL`
- **THEN** клиент MUST NOT пытаться загрузить плагин из какого-либо адреса по умолчанию
