## Why

На экране «Цвета» градиент сейчас — отдельный тип токена с отдельным семейством определений. Задать градиент только в одной теме или одном режиме нельзя: например, цвет в Light и градиент в Dark. Редактор градиента умеет только Linear, угол не меняется, Radial и Conic открываются только для просмотра, а выбранная в стопе ступень палитры сохраняется как HEX. Из 204 сидовых градиентных определений у 184 в web лежит HEX-заглушка, а в iOS и Android — градиент «белый → чёрный», который на web не виден.

Прототип SDDS Portal задаёт градиент как вид значения цветового токена в каждой паре «тема × режим». Это изменение доводит модель и редактор до прототипа и закрывает его пробелы: тип Linear / Radial / Conic, угол, центр и радиус, перетаскивание стопов, ссылки стопов на палитру. Кнопка выбора платформы в шапке прототипа ничего не делает; вместо неё у значения появляется «+», которым задаётся своё значение для iOS или Android.

## What Changes

- **Вид значения вместо выбора типа.** Пользователь работает с одним цветовым токеном. Каждое значение в паре «тема × режим» — либо цвет, либо градиент. Переключатель ▣ / ◇ в выборе цвета меняет вид только этого значения; новый градиент — Linear 90° с двумя стопами.
- **Тип токена следует из значений.** Если хотя бы одно значение семейства в какой-либо теме, режиме или на какой-либо платформе — градиент, `ds-service` сам переводит всё семейство в тип `gradient`. Если градиентов не осталось — обратно в `color`. В семействе типа `gradient` сплошные значения iOS и Android хранятся слоем `{ kind: "color", background }`. Потребители пакета (генератор, `dsbuilder theme fetch`, плагин Android Studio, сборка конфигураций компонентов) продолжают различать токены по типу и не меняются.
- **Миграция сида.**
  - Градиентные семейства, у которых нет ни одного градиента в web, становятся цветовыми: web-HEX сохраняется, iOS и Android получают тот же цвет. В сиде это 12 семейств из 17 (144 определения), градиентными остаются `text/accent-gradient`, `surface/accent-gradient`, `outline/accent-gradient`, `surface/skeleton-gradient` и `surface/skeleton-deep-gradient`.
  - В семействах с настоящим градиентом нативные заглушки у членов со сплошным web-значением заменяются слоем `color`.
- **Редактор градиента:** тип Linear, Radial или Conic; угол Linear, центр Radial и Conic с перетаскиванием и полями X/Y, радиус Radial и начальный угол Conic; перетаскивание стопов, «+» и «−». Щелчок по цвету стопа открывает отдельное окно выбора цвета с вкладками Custom и Library; ступень палитры сохраняется ссылкой.
- **Свои значения iOS и Android — строками в инспекторе.** По умолчанию значения iOS и Android строятся из web при каждой правке. «+» справа от значения открывает меню iOS / Android и добавляет под значением строку платформы с подписью «↳ iOS» в колонке подписей; правки строки меняют только эту платформу, «×» возвращает построение из web. Кнопка «Web» в панели инструментов убирается. Начальный угол Conic на Android, где в формате `angular` угла нет, передаётся сдвигом стопов по кругу.
- **Переименование и имя в инспекторе.** Токен переименовывается двойным щелчком по строке дерева и по имени в заголовке инспектора; отдельное поле «Имя» в инспекторе убирается.
- **Ссылки на палитру внутри градиента.**
  - `ds-service` проверяет их при записи и раскрывает в HEX при чтении `token-values` для потребителей;
  - ссылки учитываются в связях растяжки и переписываются при удалении растяжки;
  - пакет собирается `js/cli` из выгрузки `dsbuilder theme fetch`, которая читает уже раскрытые `token-values`, поэтому генератору раскрывать ссылки не нужно.
- **Проверка значений.** Web-градиент проверяется по грамматике, которую порождает редактор. Слои iOS и Android проверяются по формату своей платформы, а не только как «массив».

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `color-token-value-validation`: проверка значений по виду (цвет или градиент), грамматика web-градиента со ссылками на палитру в стопах, проверка структуры слоёв iOS и Android.
- `color-token-operations-api`: тип семейства вычисляется из значений и переключается операцией изменения значений; признак собственного значения платформы; тип в ответе операции изменения значений.
- `theme-palette-api`: ссылки на палитру в стопах градиента — разрешение, связи растяжки, переписывание при удалении растяжки, раскрытие для потребителей с исходным значением.
- `color-tokens-editor`: вид значения в каждом режиме, редактор градиента Linear / Radial / Conic с отдельным окном цвета стопа, строки своих значений iOS и Android через «+», без кнопки платформы в панели инструментов, строка и карточка токена с градиентом, переименование двойным щелчком по имени в инспекторе без поля «Имя».

## Impact

- **backend-kt / `ds-service`:**
  - миграция Flyway V7: признак `overridden` у значений, перевод градиентных семейств без градиентов в `color`, нормализация нативных значений;
  - модуль `feature-themes`:
    - правила `TokenValueRule` и разбор web-градиента в домене;
    - операции цветового токена: вычисление типа семейства во всех темах, нормализация сплошных нативных значений, признак `overridden`;
    - палитра темы: связи, удаление растяжки, раскрытие ссылок в градиентах в `token-values`;
    - превью темы без падения на слоях;
  - OpenAPI `documentation.yaml`: поле `overridden`, тип в ответе изменения значений, `sourceValue` в `token-values`. Маршруты не добавляются, `contracts/route-manifest.json` не меняется.
- **js / `apps/client`:**
  - экран «Цвета»: ключ токена без типа, вид значения, редактор градиента, построение iOS и Android из web, строки своих значений платформ, переименование в заголовке инспектора;
  - утилиты `utils/gradient.ts`: Conic, позиции стопов из одной цифры, ссылки на палитру.
- **js / `cli`:** код не меняется; тест на то, что градиент из выгрузки `theme fetch` проходит генерацию без изменений.
- **js / `services/db-service`:** код не меняется. Legacy-маршруты `theme-data` и `download-theme` отдают градиентный тип как раньше. Ссылки в нативных слоях приходят в них нераскрытыми, как и ссылки сплошных цветов сегодня.
- **frontend-kt:** код не меняется. `theme fetch` и плагин читают раскрытые `token-values`, а градиентные токены приходят с типом `gradient`.
- **Публичный API пакета дизайн-системы.** Переход токена между `color` и `gradient` переносит его из файла цветовых токенов в файл градиентных: `{platform}_color.json` ↔ `{platform}_gradient.json`. На iOS и Android это меняет и тип токена в коде приложения: цвет становится градиентом. Это прямое следствие правила публикации «градиент хотя бы где-то — градиент везде на iOS и Android». Предупреждение в интерфейсе при этом не показывается. Миграция пакет по умолчанию не меняет: 12 семейств-заглушек в сиде выключены (`enabled: false`), а `theme fetch` выгружает только включённые токены.
- **Зависимость.** Изменение опирается на `add-color-token-groups`: его код уже в `dev` (salute-developers/design-system-builder#106), а сам change архивируется в этой же ветке, до этого изменения. Его дельты уже перенесены в `openspec/specs`.
