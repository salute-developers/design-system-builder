## ADDED Requirements

### Requirement: Значение режима — цвет или градиент

Каждое значение токена в теме и режиме SHALL быть цветом или градиентом независимо от других тем и режимов.
Вид значения SHALL выбираться в выборе цвета переключателем ▣ / ◇ и SHALL NOT выбираться при создании токена.

#### Scenario: Цвет в Light и градиент в Dark

- **WHEN** пользователь открывает Dark токена `surfaceAccent` в теме B и нажимает ◇
- **THEN** значение Dark темы B MUST стать градиентом Linear 90° со стопами «текущий цвет» 0 % и `#F5F5F5` 100 %;
  если текущий цвет — ссылка на палитру, первый стоп MUST сохранить ссылку
- **THEN** Light темы B, значения темы A и подтемы, не связанные с Dark, MUST NOT измениться
- **THEN** связанные подтемы MUST получить новое значение по правилам наследования

#### Scenario: Возврат к цвету

- **WHEN** пользователь нажимает ▣ у градиентного значения
- **THEN** значение MUST стать цветом первого стопа, ссылка стопа на палитру MUST сохраниться

#### Scenario: Поле градиентного значения

- **WHEN** значение Light или Dark — градиент
- **THEN** поле инспектора MUST показать свотч с градиентом и подпись «Linear · <угол>°», «Radial» или
  «Conic · <начальный угол>°», а при нескольких слоях — с добавкой «+ ещё N»
- **THEN** поле прозрачности MUST NOT показываться, а щелчок MUST открыть выбор цвета в режиме градиента

#### Scenario: Состояния градиента

- **WHEN** значение режима — градиент
- **THEN** члены `-hover` и `-active` этого режима MUST получить то же значение

#### Scenario: Тип семейства сменился на сервере

- **WHEN** ответ изменения значений содержит другой `type` семейства
- **THEN** выбор токена, свёрнутые группы, открытый выбор цвета и очередь автосохранения MUST сохраниться:
  ключ токена на клиенте MUST NOT зависеть от типа
- **THEN** клиент MUST продолжать отправлять значения с актуальными `baseRevision` из `X-DS-Mutation-Metadata`

#### Scenario: Опубликованная версия

- **WHEN** пользователь просматривает раздел с `versionId` опубликованной версии
- **THEN** градиентные значения MUST показываться так же, как в черновике, а выбор цвета, ▣ / ◇, «+» и «×»
  MUST быть недоступны

#### Scenario: Проверка значения в редакторе

- **WHEN** значение — градиент по грамматике проверки значений `ds-service`
- **THEN** редактор MUST NOT считать его ошибкой
- **WHEN** значение не цвет и не градиент по этой грамматике
- **THEN** токен MUST считаться токеном с ошибкой и попадать в фильтр «Только токены с ошибками»

### Requirement: Редактор градиента

Выбор цвета в режиме градиента SHALL позволять менять тип, геометрию и стопы первого слоя градиента. Остальные
слои SHALL сохраняться без изменений. Превью SHALL обновляться во время перетаскивания, а значение SHALL
записываться и ставиться в очередь автосохранения при отпускании, по Enter, при уходе фокуса из поля или при
выборе цвета.

#### Scenario: Тип градиента

- **WHEN** пользователь выбирает Linear, Radial или Conic
- **THEN** градиент MUST сменить тип с сохранением стопов
- **THEN** Radial и Conic без прежней геометрии MUST получить центр 50 % / 50 %, Radial — радиус 50 %, Conic —
  начальный угол 0°

#### Scenario: Linear

- **WHEN** выбран Linear
- **THEN** выбор MUST показать круговой регулятор и поле «Угол» от 0 до 359°, изменение которых меняет угол

#### Scenario: Radial

- **WHEN** выбран Radial
- **THEN** выбор MUST показать плоскость превью с перетаскиваемым центром, поля X и Y от 0 до 100 % и ползунок с
  полем «Радиус» от 5 до 150 %

#### Scenario: Conic

- **WHEN** выбран Conic
- **THEN** выбор MUST показать плоскость превью с перетаскиваемым центром, поля X и Y и круговой регулятор с
  полем «Начальный угол» от 0 до 359°

#### Scenario: Стопы

- **WHEN** пользователь перетаскивает маркер стопа по полосе или вводит позицию от 0 до 100
- **THEN** позиция стопа MUST измениться, а стопы MUST оставаться упорядоченными по позиции
- **WHEN** пользователь щёлкает маркер стопа
- **THEN** стоп MUST стать выбранным
- **WHEN** пользователь нажимает «+»
- **THEN** MUST добавиться стоп в позиции 50 % с цветом градиента в этой точке
- **WHEN** пользователь нажимает «−» у стопа
- **THEN** стоп MUST удалиться, а при двух стопах «−» MUST быть недоступна

#### Scenario: Окно цвета стопа

- **WHEN** пользователь щёлкает цвет стопа в списке стопов
- **THEN** стоп MUST стать выбранным, и рядом с выбором цвета градиента MUST открыться отдельное окно выбора
  цвета стопа с вкладками Custom и Library, а выбор цвета градиента MUST остаться открытым
- **WHEN** пользователь нажимает «×» окна, Escape или щёлкает вне окна цвета стопа
- **THEN** окно цвета стопа MUST закрыться, а выбор цвета градиента MUST остаться открытым

#### Scenario: Цвет стопа

- **WHEN** пользователь выбирает цвет на вкладке Custom окна цвета стопа
- **THEN** стоп MUST получить HEX с прозрачностью стопа
- **WHEN** пользователь выбирает ступень на вкладке Library окна цвета стопа
- **THEN** стоп MUST получить ссылку `[type.shade.step]` с прозрачностью стопа, а строка стопа MUST показать имя
  ступени, например «Green 500»
- **THEN** при изменении ступени в палитре темы стоп MUST показать новый цвет без правки токена

#### Scenario: Клавиатура и Library не сбрасывают градиент

- **WHEN** пользователь нажимает стрелки на ползунках цвета стопа или выбирает ступень в Library
- **THEN** MUST меняться только цвет выбранного стопа, а тип, геометрия и другие стопы MUST NOT измениться

### Requirement: Строка и карточка токена с градиентом

Дерево и борд SHALL показывать градиентные значения градиентом.

#### Scenario: Чип строки

- **WHEN** значение Light или Dark — градиент
- **THEN** соответствующая половина чипа строки MUST быть залита этим градиентом

#### Scenario: Без меток вида

- **WHEN** у токена есть градиентное значение
- **THEN** строка дерева MUST NOT показывать метку вида значения: вид виден по чипу

#### Scenario: Карточка борда

- **WHEN** половина карточки — градиент
- **THEN** половина MUST быть залита градиентом, а подпись Light или Dark MUST быть чёрной или белой по
  большему контрасту с цветом первого стопа

### Requirement: Своё значение платформы задаётся строкой в инспекторе

Справа от каждого поля значения Light и Dark в разделе «Темы по умолчанию» инспектор SHALL показывать кнопку «+».
У полей подтем OnDark, OnLight и Inverse кнопки «+» SHALL NOT быть: подтема показывает только строки платформ,
унаследованные от режима. Кнопка «+» SHALL открывать меню
платформ iOS и Android, в котором нет уже добавленных платформ. Выбор платформы SHALL добавлять под полем
строку этой платформы с её собственным значением. Без строки значение платформы SHALL строиться из web.
Дерево, борд и компонент на канвасе SHALL показывать значения web.

#### Scenario: Добавление платформы

- **WHEN** у токена `surfaceAccent` в теме B значение Light — Green 500, и пользователь нажимает «+» у Light и
  выбирает iOS
- **THEN** под полем Light MUST появиться строка с подписью «↳ iOS» в колонке подписей, копией значения web и
  кнопкой «×»; название платформы MUST NOT показываться внутри поля значения
- **THEN** выбор цвета MUST NOT открываться автоматически: он открывается щелчком по строке платформы
- **THEN** клиент MUST отправить значение `ios` режима `light` с `overridden: true`

#### Scenario: Выбор цвета у строки платформы

- **WHEN** пользователь щёлкает свотч строки «↳ iOS»
- **THEN** выбор цвета MUST открыться рядом с этой строкой: верх окна выравнивается по строке и не выходит за
  пределы экрана

#### Scenario: Правка строки платформы

- **WHEN** пользователь меняет в строке iOS цвет на Green 400
- **THEN** поле Light MUST показывать «Green 500», а строка «↳ iOS» под ним — «Green 400»
- **THEN** значения web и Android MUST NOT измениться
- **THEN** вверху выбора цвета MUST показываться пояснение «своё значение: правки меняют только iOS»

#### Scenario: Все платформы добавлены

- **WHEN** у поля уже есть строки iOS и Android
- **THEN** кнопка «+» MUST быть недоступна

#### Scenario: Удаление строки платформы

- **WHEN** пользователь нажимает «×» у строки платформы
- **THEN** строка MUST исчезнуть, значение платформы MUST перестроиться из web и отправиться с
  `overridden: false`
- **THEN** значения платформы членов `-hover` и `-active` MUST стать равными их web-значениям

#### Scenario: Подтемы

- **WHEN** у значения режима есть строка платформы, а подтема наследует этот режим
- **THEN** подтема MUST показывать под своим полем ту же строку платформы
- **THEN** в связанной подтеме у строки MUST NOT быть кнопок «+» и «×»: строку убирают у поля режима
- **WHEN** подтема отвязана
- **THEN** у её строки платформы MUST быть «×», а кнопки «+» у полей подтемы MUST NOT быть
- **THEN** клиент MUST NOT убирать строку платформы связанной подтемы и в обход интерфейса

#### Scenario: Только чтение

- **WHEN** раздел открыт только для чтения
- **THEN** строки платформ MUST показываться, а кнопки «+» и «×» MUST NOT показываться

### Requirement: Значения iOS и Android строятся из web

Клиент SHALL строить значения `ios` и `android` из web-значения того же члена и режима при каждой правке, если
у платформы нет своей строки, и SHALL отправлять их с `overridden: false`. Значение строки платформы SHALL
отправляться с `overridden: true` и SHALL NOT перестраиваться при правке web.

#### Scenario: Построение цвета

- **WHEN** web-значение — цвет
- **THEN** значения `ios` и `android` MUST быть тем же цветом или ссылкой

#### Scenario: Построение по членам семейства

- **WHEN** у платформы нет своей строки
- **THEN** значение платформы каждого члена семейства, включая `-hover` и `-active`, MUST строиться из web-значения
  того же члена, а не вычисляться заново из основного цвета

#### Scenario: Построение Linear и Radial

- **WHEN** web-значение — `linear-gradient(A deg, …)` или `radial-gradient(R% R% at X% Y%, …)`
- **THEN** слой MUST быть `linear { locations, colors, angle: A }`, а Radial — `radial { centerX: X/100, centerY:
  Y/100, startRadius: 0, endRadius: R/100 }` на iOS и `radial { centerX, centerY, radius: R/100 }` на Android
- **THEN** `locations` MUST быть позициями стопов, делёнными на 100, а `colors` — цветами стопов в `#RRGGBBAA` или
  ссылками

#### Scenario: Построение Conic

- **WHEN** web-значение — `conic-gradient(from A deg at X% Y%, …)`
- **THEN** на iOS слой MUST быть `angular { startAngle: A, endAngle: A + 360, centerX, centerY }`
- **THEN** на Android слой MUST быть `angular { centerX, centerY }`, а стопы MUST быть сдвинуты по кругу на
  `A / 360`, с добавленными стопами в позициях 0 и 1 цвета градиента на шве, так что Android начинает
  градиент с угла `A`
- **THEN** выбор цвета web-значения без строки Android MUST показать пояснение «На Android начальный угол A°
  передаётся сдвигом стопов: в формате angular угла нет»

#### Scenario: Строка платформы не перестраивается

- **WHEN** у Light есть строка Android, и пользователь меняет цвет стопа web-значения Light
- **THEN** значение `ios` MUST перестроиться из web, а значение `android` MUST NOT измениться

#### Scenario: Conic в строке Android

- **WHEN** выбор цвета открыт для строки Android со слоем `angular`
- **THEN** выбор MUST показывать центр и MUST NOT показывать поле «Начальный угол»: в формате Android у conic
  нет угла

#### Scenario: Подтемы и состояния

- **WHEN** у значения режима есть строка платформы
- **THEN** связанные подтемы и члены `-hover` и `-active` MUST получить то же значение платформы и тот же
  признак `overridden`

## MODIFIED Requirements

### Requirement: Раздел «Цвета» показывает цветовые токены темы экраном Color Tokens

Веб-клиент SHALL показывать раздел «Цвета» темы тремя колонками — дерево токенов, канвас и инспектор — с
панелью инструментов над канвасом, а цветовым токеном экрана SHALL считать группу и имя без режима и
подгруппы.

#### Scenario: Пользователь открывает раздел

- **WHEN** пользователь открывает раздел «Цвета» темы
- **THEN** клиент MUST показать дерево, панель инструментов с вкладкой «Обзор», выбор вида канваса, канвас и
  инспектор
- **THEN** вкладка «Доступность» MUST NOT показываться: по решению команды проверка контраста на экране пока
  не выводится
- **THEN** кнопка выбора платформы «Web» MUST NOT показываться в панели инструментов: значения платформ
  задаются строками в инспекторе. В прототипе кнопка есть, но её поведение не определено
- **THEN** каждый цветовой и градиентный токен MUST быть одной строкой дерева независимо от числа режимов и
  подгрупп
- **THEN** состояния `-hover` и `-active` MUST NOT показываться отдельными строками

#### Scenario: Пользователь меняет ширину панелей

- **WHEN** пользователь перетаскивает разделитель панели или нажимает стрелки на разделителе
- **THEN** ширина дерева MUST оставаться в пределах 220–320 px, а инспектора — 280–400 px
- **THEN** ширина MUST сохраниться после перезагрузки страницы

### Requirement: Инспектор показывает значения токена и его связь с палитрой

Инспектор SHALL показывать имя, описание, значения Light и Dark, подтемы OnDark, OnLight и Inverse и
действия токена. Поле группы палитры и отдельное поле «Имя» SHALL NOT показываться.

#### Scenario: Имя токена

- **WHEN** пользователь с правом записи дважды щёлкает имя токена в заголовке инспектора
- **THEN** имя MUST стать редактируемым на месте заголовка тем же шрифтом, без рамки и фона, с выделенным
  целиком текстом, как при переименовании в навигаторе Xcode
- **THEN** Enter или уход фокуса MUST переименовать токен, а Escape MUST отменить правку
- **THEN** отдельного поля «Имя» под заголовком MUST NOT быть

#### Scenario: Значение связано с палитрой

- **WHEN** значение Light или Dark — ссылка на ступень палитры темы
- **THEN** поле MUST показать имя ступени палитры (например «Blue 500») и свотч с цветом по палитре темы
- **THEN** поле MUST быть только для чтения и открывать выбор цвета на вкладке Library
- **THEN** поле прозрачности MUST показываться только при прозрачности меньше 100 %

#### Scenario: Пользователь вводит HEX

- **WHEN** пользователь вводит HEX в поле значения
- **THEN** клиент MUST записать HEX с текущей прозрачностью, если не введены 8 цифр, и поставить токен в
  очередь автосохранения
- **THEN** связь значения с палитрой MUST быть снята

#### Scenario: Пользователь меняет прозрачность связанного значения

- **WHEN** пользователь меняет прозрачность значения, связанного с палитрой
- **THEN** клиент MUST сохранить ссылку на ту же ступень с новой прозрачностью

#### Scenario: Ступень палитры изменилась

- **WHEN** ступень, на которую ссылается токен, изменена в палитре темы
- **THEN** свотч, чип дерева, борд и компонент на канвасе MUST показать новый цвет без правки токена

### Requirement: Группы, подгруппы и токены переименовываются на месте

Редактор SHALL переименовывать группу, подгруппу и токен двойным щелчком по строке, а токен — ещё и двойным
щелчком по имени в заголовке инспектора.

#### Scenario: Переименование группы

- **WHEN** пользователь меняет название группы и нажимает Enter
- **THEN** клиент MUST отправить изменение названия, а имена токенов группы MUST NOT измениться

#### Scenario: Переименование токена

- **WHEN** пользователь дважды щёлкает строку токена `textAccent` в дереве
- **THEN** имя MUST стать редактируемым прямо в этой строке: чип, отступы и высота строки MUST NOT измениться,
  отдельное поле с рамкой MUST NOT появляться, текст имени MUST быть выделен целиком
- **WHEN** пользователь меняет имя на «Brand» и нажимает Enter
- **THEN** клиент MUST отправить перенос токена в его же группу с `name: "brand"` и после успеха показать токен как `textBrand`

#### Scenario: Переименование опубликованного токена

- **WHEN** у токена `publishedIn` не `null` и пользователь меняет его имя или переносит в группу с другим кодом
- **THEN** рядом с полем имени, в строке ввода или у места вставки MUST показываться иконка-предупреждение с подсказкой «Токен опубликован в версии X. Новое имя изменит переменную в пакете дизайн-системы»
- **THEN** переименование MUST выполняться без подтверждения

#### Scenario: Переименование неопубликованного токена

- **WHEN** у токена `publishedIn` равно `null`
- **THEN** иконка-предупреждение MUST NOT показываться

### Requirement: Выбор цвета повторяет прототип

Выбор цвета SHALL открываться у поля значения и SHALL содержать переключатель вида значения ▣ / ◇, вкладки
Custom и Library для цвета и редактор градиента для градиента.

#### Scenario: Вкладка Custom

- **WHEN** пользователь двигает поле насыщенности и яркости, ползунок тона или прозрачности
- **THEN** превью MUST обновляться во время движения, а значение MUST записываться и ставиться в очередь
  автосохранения при отпускании
- **THEN** стрелки клавиатуры на ползунках MUST менять значение и ставить его в очередь автосохранения
- **THEN** форматы Hex, RGB и HSL MUST принимать ввод, а Hex MUST копироваться в буфер обмена

#### Scenario: Вкладка Library

- **WHEN** пользователь открывает Library
- **THEN** вкладка MUST показать растяжки палитры темы со ступенями, вычисленными для группы палитры токена
- **THEN** выбор ступени MUST записать ссылку `[type.shade.step]` с текущей прозрачностью
- **THEN** поиск MUST фильтровать растяжки по имени

#### Scenario: Градиентное значение

- **WHEN** пользователь открывает градиентное значение
- **THEN** выбор цвета MUST открыться в режиме градиента с типом, геометрией и стопами значения
- **THEN** переключатель ▣ / ◇ MUST менять вид только этого значения

#### Scenario: Закрытие

- **WHEN** пользователь нажимает Escape, кнопку закрытия или щёлкает вне выбора цвета
- **THEN** выбор цвета MUST закрыться, а фокус внутри него MUST оставаться до закрытия
