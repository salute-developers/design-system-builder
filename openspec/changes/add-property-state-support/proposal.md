## Зачем

Редактор компонентов разрешает добавить состояние только цветовому свойству, в имени которого нет `focus`. Это
эвристика: она не знает, что у Compose `DropZone.paddingStart` или `titleStyle` принимают значения по состояниям
(`StatefulValue`), а у многих цветовых свойств состояний на платформе нет. Из-за этого дизайнер либо не может задать
состояние, которое код компонента поддерживает, либо задаёт состояние, которое генерация молча проигнорирует.

Мета платформ уже говорит, какие слоты принимают значения по состояниям, но эти сведения теряются в CLI и не доходят
до модели `ds-service`. Признак нужно перенести из меты в глобальный слой компонентов и сделать его источником правды
для редактора.

## Что меняется

- У свойства компонента появляется признак поддержки состояний `stateSupport`: `none` (состояний нет),
  `interaction` (только общие состояния взаимодействия) или `any` (состояния взаимодействия и состояния самого
  компонента). Признак хранится в `properties.state_support`; у свойств, заведённых до изменения, он не задан
  (`null`).
- Нормализаторы `dsbuilder components import-api` выводят признак из существующих полей меты каждой платформы:
  Compose — перегрузки `StatefulValue` и `InteractiveColor`, View — `stateValues` параметра, SwiftUI — поле `state`
  параметра, web — токены с `state`. Манифест передаёт его полем `stateSupport` свойства.
- Импорт API-меты записывает `stateSupport` у новых свойств и обновляет его у существующих, как статус устаревания
  алиаса; отчёт получает счётчик `stateSupportChanged`. Манифест без поля (прежние версии CLI) признак не меняет.
- `ComponentPropertySummaryResponse` отдаёт `stateSupport`; `editor-bundle` дополнительно отдаёт `states` — общие
  состояния и состояния этого компонента.
- Операции записи значения редактора отклоняют набор состояний, который свойство не поддерживает (`422`,
  `states_not_supported`). Свойство с незаданным признаком ограничений не получает. Импорт конфигураций и удаление
  значений не ограничиваются.
- Билдер показывает кнопку «Добавить состояние» и строки состояний у свойства любого типа, поддерживающего состояния,
  с тем же контролом, что у базового значения. Меню предлагает состояния по признаку: `interaction` — общие
  состояния, `any` — ещё и состояния компонента. Для свойства без признака сохраняется прежнее поведение (цвет без
  `focus` в имени, `hovered`/`pressed`/`focused`). Уже записанные значения состояний у свойства `none` видны и
  удаляются, но новые не добавляются.

## Возможности

### Новые возможности

- `component-property-state-support`: признак поддержки состояний свойства компонента, его значения, хранение и
  правило выбора допустимых состояний.

### Изменяемые возможности

- `component-api-meta-import`: поле `stateSupport` манифеста, обновление признака импортом и счётчик
  `stateSupportChanged`.
- `cli-components`: вывод признака нормализаторами платформ, передача в манифест и печать счётчика.
- `component-editor-bundle-api`: `stateSupport` у свойств и список `states` в `editor-bundle`.
- `component-editor-operations`: проверка набора состояний по признаку свойства при записи значения.
- `component-editor-workbench`: состояния у свойств любого типа по признаку вместо цветовой эвристики.

## Влияние

- `backend-kt/ds-service`: Flyway-миграция `V21` (enum `property_state_support`, столбец `properties.state_support`),
  `PropertiesTable`, `ComponentPropertySummary`/`ComponentPropertySummaryResponse`, импорт API-меты
  (`ImportApiMetaRequest`, `ImportApiMeta`, `ExposedApiMetaRepository`, `ImportApiMetaResponse`), `editor-bundle`,
  `AppearanceEditorValueOperations`, `openapi/documentation.yaml`, тесты.
- `frontend-kt/feature-components`: `ApiMetaProperty`, четыре нормализатора, сетевой формат
  `HttpApiMetaRemoteSource`, `ApiMetaImportReport` и печать отчёта в `:cli`, корпуса и тесты, `API_META_NORMALIZERS.md`,
  `cli/USAGE.md`.
- `js/apps/client`: DTO бандла и `ComponentAPI`, `StateBindingMenu`, `InspectorPropertyRow`, тип `PropState`, тесты.
  `js/cli` и `js/apps/preview-web-plugin` не меняются.
- Данные: после выкатки признак появляется у свойств только после повторного `import-api` по каждой платформе; до
  этого редактор работает по прежней эвристике.
