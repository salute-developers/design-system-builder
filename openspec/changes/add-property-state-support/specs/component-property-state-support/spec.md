## ADDED Requirements

### Requirement: Поддержка состояний свойства

Свойство компонента SHALL нести признак поддержки состояний `stateSupport`. Признак либо не задан, либо задан
и тогда состоит из двух частей:

- `states` — список состояний, в которых генератор платформы может выразить значение этого свойства;
- `combinations` — допускаются ли сочетания нескольких состояний в одном наборе.

`ds-service` SHALL хранить флаг в `properties.state_combinations` (`boolean`, допускает `NULL`), а список — в
таблице `property_supported_states (property_id, state_id)`, где `state_id` ссылается на `states`. `NULL` в
`state_combinations` MUST означать, что признак не задан, и тогда строк в `property_supported_states` у свойства
MUST NOT быть. Пустой список при заданном признаке MUST означать, что значения по состояниям свойство не принимает.
Признак относится к свойству компонента конкретной платформы. `ds-service` MUST NOT выводить его из типа или имени
свойства.

#### Scenario: Свойство без поддержки состояний

- **WHEN** у свойства `state_combinations` равен `false`, а строк в `property_supported_states` нет
- **THEN** признак MUST означать, что свойство не принимает значения по состояниям

#### Scenario: Свойство заведено до признака

- **WHEN** свойство создано до миграции или импортом без признака
- **THEN** `state_combinations` MUST быть `NULL`, а строк в `property_supported_states` MUST NOT быть
- **THEN** миграция MUST NOT заполнять признак по типу или имени свойства

#### Scenario: Признак в ответах каталога

- **WHEN** клиент читает свойства компонента (`ComponentPropertySummaryResponse`)
- **THEN** ответ MUST содержать `stateSupport`: `null` или объект `{ "stateIds": [...], "combinations": <bool> }`
- **THEN** `stateIds` MUST идти в порядке создания состояний

### Requirement: Имя состояния разрешается одинаково во всех путях

Имя состояния SHALL разрешаться в идентификатор по одному правилу в пределах компонента: сначала среди общих
состояний (строки `states` с `component_id IS NULL`), затем среди собственных состояний компонента. Правило SHALL
применяться везде, где `ds-service` или клиент переводит имя в идентификатор:

- импорт API-меты — списки свойств;
- импорт конфигураций — `ComponentConfigImporter`;
- операции редактора — `EditorSupport.stateIds`;
- клиент редактора.

Состояние другого компонента MUST NOT находиться. Собственное состояние компонента с именем общего состояния
(«тень»: импорт меты заводит собственные состояния компонента независимо от общего словаря) MUST NOT выбираться для
новых записей.

#### Scenario: Имя есть и среди общих, и у компонента

- **WHEN** у Compose `TextField` есть собственное состояние `disabled`, а в общем словаре тоже есть `disabled`
- **THEN** имя `disabled` для `TextField` MUST разрешаться в общее состояние во всех путях

#### Scenario: Имя есть только у компонентов

- **WHEN** `collapsed` не входит в общий словарь, а собственные `collapsed` есть у двух компонентов
- **THEN** для каждого компонента имя MUST разрешаться в его собственное состояние
- **THEN** состояние другого компонента MUST NOT находиться

### Requirement: Допустимый набор состояний свойства

Набор состояний значения SHALL считаться допустимым для свойства, если выполняется одно из условий:

- набор пуст;
- признак свойства не задан, и каждое состояние набора общее или принадлежит компоненту свойства;
- признак задан, имя каждого состояния набора есть среди имён состояний списка свойства, и набор состоит из одного
  состояния либо `combinations` равен `true`.

Имена сравниваются в канонической форме. Поэтому значение, записанное раньше в «тень» общего состояния, считается
тем же состоянием, что и общее. Состояние другого компонента MUST делать набор недопустимым при любом признаке.

#### Scenario: Состояния нет в списке

- **WHEN** у свойства Compose `Slider.thumbColor` список `focused`, `pressed`, `hovered`, `activated`, `selected`, а набор содержит `disabled`
- **THEN** набор MUST считаться недопустимым

#### Scenario: Сочетание при запрете сочетаний

- **WHEN** у web-свойства `Button.backgroundColor` список `pressed`, `hovered`, а `combinations` равен `false`
- **THEN** набор `hovered` MUST считаться допустимым
- **THEN** набор `pressed + hovered` MUST считаться недопустимым

#### Scenario: Значение в «тени» общего состояния

- **WHEN** у свойства `TextField` в списке общий `disabled`, а существующее значение записано в набор с собственным `disabled` компонента `TextField`
- **THEN** набор MUST считаться допустимым

#### Scenario: Состояние чужого компонента

- **WHEN** набор содержит собственный `collapsed` другого компонента
- **THEN** набор MUST считаться недопустимым при любом признаке, в том числе незаданном

#### Scenario: Признак не задан

- **WHEN** у свойства `stateSupport` равен `null`
- **THEN** любой набор общих состояний и состояний компонента свойства MUST считаться допустимым
