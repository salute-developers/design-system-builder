## ADDED Requirements

### Requirement: Состояния свойства

Кнопка «+» («Добавить состояние») SHALL показываться у строки свойства источника стиля, инварианта или пересечения вариаций, если в признаке
`stateSupport` свойства есть хотя бы одно состояние, независимо от типа свойства. У свойства без признака (`null`)
кнопка SHALL показываться по прежнему правилу: только у цветового свойства без `focus` в имени. У свойства с пустым списком кнопки MUST NOT быть.

Кнопка открывает меню с флажками состояний и кнопкой «Добавить» (или «Добавить · N»). Пока ничего не выбрано, кнопка
недоступна. Меню SHALL предлагать:

- при заданном признаке — ровно состояния из `stateIds` свойства, найденные в `states` бандла;
- при незаданном признаке — общие `hovered`, `pressed`, `focused`.

Сначала идут `focused`, `pressed`, `hovered`, затем остальные в порядке бандла. Отметка выбранного флажка SHALL
рисоваться глифом `check` по центру флажка. Если `combinations` равен `false`, меню SHALL позволять выбрать только одно
состояние: отметка другого флажка снимает прежнюю.

Подтверждение SHALL добавлять одно состояние из выбранных флажков; подпись сочетания записывается через `+` в порядке
меню. Значение состояния равно базовому значению свойства. Уже существующее состояние MUST NOT добавляться повторно.

Клиент SHALL работать с состояниями по идентификаторам из `states` бандла. Имя состояния из конфигурации SHALL
разрешаться в пределах компонента: сначала общее, затем собственное состояние компонента. Готовый набор состояний SHALL искаться
по множеству идентификаторов, а не по именам, и новый набор SHALL создаваться из тех же идентификаторов. Состояние
другого компонента с тем же именем MUST NOT попадать в набор.

Состояния SHALL показываться строками под свойством: соединительные линии слева, подпись состояния, тот же контрол,
что у базового значения этого типа (цвет с пикером, число, форма, тень, типографика, иконка), и кнопка удаления
состояния. Строки уже записанных состояний, которые признак свойства не допускает, SHALL показываться только для
чтения, с кнопкой удаления. Если автосохранение получило `422 states_not_supported` или `state_not_in_component`,
редактор SHALL вернуть прежнее значение и показать причину, как при других отказах автосохранения. Добавленное
состояние SHALL сохраняться и оставаться после перечитывания компонента.

#### Scenario: Сочетание состояний

- **WHEN** у цветового свойства в признаке `pressed` и `hovered`, `combinations` равен `true`, пользователь отмечает оба и нажимает «Добавить · 2»
- **THEN** под свойством MUST появиться строка `pressed + hovered` со значением базового цвета
- **THEN** состояние MUST записаться в источник свойства как набор состояний `pressed`, `hovered`

#### Scenario: Сочетания запрещены

- **WHEN** у web-свойства `Button.backgroundColor` в признаке `pressed`, `hovered` и `combinations: false`
- **THEN** меню MUST предлагать только `pressed` и `hovered` и MUST NOT позволять отметить оба
- **THEN** меню MUST NOT предлагать `disabled`

#### Scenario: Состояние числового свойства

- **WHEN** в признаке свойства `paddingStart` типа `dimension` есть `dragging-over`, и пользователь добавляет это состояние
- **THEN** под свойством MUST появиться строка `dragging-over` с числовым полем и базовым значением
- **THEN** правка числа в строке MUST записать значение состояния

#### Scenario: Состояние с именем, общим для нескольких компонентов

- **WHEN** в редакторе Compose `CheckBox` пользователь добавляет состояние `checked`, а собственный `checked` есть также у `RadioBox` и `Switch`, и общего `checked` нет
- **THEN** набор состояний значения MUST содержать идентификатор `checked` компонента `CheckBox`
- **WHEN** общий `checked` есть
- **THEN** набор MUST содержать общий `checked`

#### Scenario: Свойство без поддержки состояний

- **WHEN** у цветового свойства признак с пустым списком
- **THEN** кнопки «Добавить состояние» MUST NOT быть
- **WHEN** у такого свойства уже записано значение в состоянии `hovered`
- **THEN** строка `hovered` MUST показываться только для чтения с кнопкой удаления

#### Scenario: Свойство без признака

- **WHEN** у цветового свойства `background` признак `null`
- **THEN** кнопка MUST показываться, а меню MUST предлагать `hovered`, `pressed`, `focused`
- **WHEN** у цветового свойства `focusColor` признак `null`
- **THEN** кнопки MUST NOT быть

#### Scenario: Удаление состояния

- **WHEN** пользователь нажимает удаление в строке состояния `hovered`
- **THEN** состояние MUST удалиться из свойства

#### Scenario: Состояние сохраняется

- **WHEN** пользователь добавил состояние `hovered`, и после автосохранения компонент перечитан или страница перезагружена
- **THEN** строка `hovered` MUST остаться под свойством с прежним значением


### Requirement: Состояния свойства на пересечении вариаций

Редактор SHALL разрешать состояния поддерживаемого свойства при выборе нескольких вариаций.
Добавление и правка SHALL создавать значение только на точном пересечении выбранных стилей
и состояний. Унаследованные состояния SHALL показываться с источником; их правка SHALL создавать
собственное переопределение. Удаление SHALL быть доступно только у собственной записи и SHALL
восстанавливать унаследованное значение, если оно существует. Базовое значение и состояния SHALL
сохраняться независимо. Ограничения `stateSupport` SHALL применяться как для обычного стиля.

#### Scenario: Размер TextField на пересечении

- **WHEN** выбраны Size, Label-placement и Required-placement у Compose TextField и пользователь добавляет `disabled` к `boxPaddingStart`
- **THEN** редактор MUST сохранить состояние только для выбранного набора стилей
- **THEN** после перезагрузки состояние MUST остаться редактируемым и учитываться в preview и экспорте
- **THEN** исходные стили и другие пересечения MUST остаться неизменными

#### Scenario: Переопределение унаследованного состояния

- **WHEN** на пересечении пользователь изменяет унаследованное состояние свойства
- **THEN** редактор MUST создать собственную запись на пересечении
- **WHEN** пользователь удаляет эту запись
- **THEN** редактор MUST снова показать унаследованное значение без изменения исходного стиля

#### Scenario: Пересечение без базовой записи

- **WHEN** пересечение содержит только значение свойства в состоянии
- **THEN** перечитывание MUST сохранить его, а базовое значение MUST продолжить наследоваться
- **WHEN** пользователь удаляет базовую запись пересечения или всё пересечение
- **THEN** в первом случае состояния MUST сохраниться, а во втором MUST удалиться вместе с пересечением

#### Scenario: Отказ записи состояния пересечения

- **WHEN** сервер отклоняет запись состояния пересечения с `422 states_not_supported`
- **THEN** редактор MUST показать причину и сохранить последнее подтверждённое значение



### Requirement: Совместимость полного переопределения свойства

Прежняя запись только с собственной базой и без состояний SHALL оставаться полным переопределением
свойства, скрывающим состояния нижних источников. Если запись содержит состояния, с собственной
базой или без неё, редактор и нативная выдача SHALL объединять наборы состояний независимо.
При удалении последнего собственного состояния у записи с собственной базой SHALL снова действовать
полное переопределение; удаление собственной базы SHALL открыть наследуемые значения.

#### Scenario: Прежняя база без состояний

- **WHEN** прежнее пересечение содержит только собственное базовое значение свойства
- **THEN** редактор и нативный пакет MUST сохранить прежнее поведение полного переопределения

#### Scenario: Собственная база вместе с состояниями

- **WHEN** пользователь добавляет собственную базу пересечению, содержащему собственные и унаследованные состояния
- **THEN** редактор и нативный пакет MUST сохранить все действующие состояния


## REMOVED Requirements

### Requirement: Состояния цветового свойства

**Reason**: Эвристика «цвет без `focus` в имени» заменяется признаком `stateSupport` из меты; состояния доступны свойствам любого типа.
**Migration**: Поведение описывает требование «Состояния свойства»; для свойств без признака прежнее правило сохраняется там как запасное.

#### Scenario: Состояние ссылки на вложенный Compose-стиль

- **WHEN** у свойства `component_style` задан непустой список состояний и пользователь добавляет состояние
- **THEN** строка состояния MUST содержать выбор оформления и стилей вложенного компонента
- **THEN** изменение стиля состояния MUST сохранять базовую ссылку
- **WHEN** после обновления меты состояние становится недопустимым
- **THEN** выбор MUST быть недоступен, а удаление состояния MUST оставаться доступным
