## ADDED Requirements

### Requirement: Набор состояний значения проверяется по признаку свойства

Операция записи значения свойства оформления с непустым набором состояний SHALL проверять набор по правилу
допустимого набора возможности `component-property-state-support`. Недопустимый набор SHALL отклоняться ответом `422`
с кодом `states_not_supported` без изменения данных. Удаление значения, переупорядочивание наборов и импорт
конфигураций MUST NOT ограничиваться признаком.

#### Scenario: Состояние у свойства без поддержки

- **WHEN** редактор записывает значение с набором `hovered` свойству с признаком `none`
- **THEN** `ds-service` MUST ответить `422` с кодом `states_not_supported`
- **THEN** значения свойства MUST NOT измениться

#### Scenario: Состояние компонента у свойства interaction

- **WHEN** набор содержит состояние компонента, а признак свойства `interaction`
- **THEN** `ds-service` MUST ответить `422` с кодом `states_not_supported`

#### Scenario: Допустимый набор

- **WHEN** набор содержит `dragging-over` компонента свойства, а признак `any`
- **THEN** `ds-service` MUST записать значение

#### Scenario: Признак не задан

- **WHEN** у свойства признак `null`
- **THEN** `ds-service` MUST принять любой набор состояний, объявленных для компонента, как до изменения

#### Scenario: Удаление прежнего значения состояния

- **WHEN** у свойства с признаком `none` есть значение в состоянии `hovered` и редактор его удаляет
- **THEN** `ds-service` MUST удалить значение
