## Зачем

Часть дизайнеров работает в Pixso, а не в Figma. Окно плагина, вход и просмотр токенов от редактора не зависят: вызовы
`figma.*` занимают семь строк основного потока, а вся работа с бэкендом уже лежит в общих Kotlin-модулях. Поэтому Pixso
можно поддержать той же кодовой базой, без второго приложения и без второй интеграции с бэкендом.

## Что меняется

- Плагин `js/apps/figma-plugin` собирается для двух редакторов: Figma и Pixso. Окно плагина общее, вместе с ним общий
  модуль `:plugins:figma-core`: Pixso получает вход, сессию и чтение токенов из тех же Kotlin-модулей.
- Появляется точка входа основного потока для Pixso и манифест Pixso.
- В API Pixso нет `openExternal`, поэтому браузер для входа открывается из окна плагина.
- Появляется команда локального запуска в отладчике Pixso.
- Экспорт темы работает и в Pixso: план строит тот же `:plugins:figma-core`, основной поток Pixso записывает его через
  переходник API. То, чего Pixso не умеет, записывается значениями из плана с оговоркой в отчёте.

## Возможности

### Новые возможности

- `pixso-plugin-host`: запуск плагина DS Builder в Pixso, вход через браузер и локальная отладка.

### Изменяемые возможности

Нет. Требования к входу, просмотру токенов и общей интеграции с бэкендом не меняются. Отличия Pixso описаны в
`pixso-plugin-host`: способ открытия браузера, хранилище `pixso.clientStorage`, тема окна и манифест без `networkAccess`.

## Влияние

- `js`: `js/apps/figma-plugin` (основной поток, протокол сообщений, мост окна, сборка, тесты, `README.md`), новая
  dev-зависимость `ws`.
- `backend-kt`: без изменений. Окно Pixso загружается как `data:`-iframe с origin `null`, который уже разрешён настройкой
  `OIDC_PLUGIN_ORIGINS`. Используется существующий клиент `dsbuilder-figma-plugin`.
- `frontend-kt`: без изменений. Сборка Pixso использует результат `:plugins:figma-core` через готовый `ui.html`.
- Хранилище и конфигурация: без изменений.
- Зависимость: изменение опирается на [#148](https://github.com/salute-developers/design-system-builder/pull/148).
