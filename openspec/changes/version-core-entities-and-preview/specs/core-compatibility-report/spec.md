## ADDED Requirements

### Requirement: Единая проверка сохранённых настроек

Сервер MUST проверять все сохранённые настройки до фильтрации по Core: компоненты, свойства, состояния, платформенные параметры, доказуемую совместимость типов/токенов и вложенных ссылок. Общие состояния MUST проверяться по предустановленному системному набору независимо от меты Core; состояния конкретного компонента MUST проверяться по выбранному релизу. Отсутствие используемой сущности в соответствующем источнике MUST быть конфликтом; deprecated само по себе MUST быть предупреждением.

#### Scenario: Удалённое свойство

- **WHEN** в B нет свойства с сохранённым значением черновика
- **THEN** отчёт MUST содержать блокирующую проблему с этим значением, не удаляя его

#### Scenario: Предупреждение

- **WHEN** используемое свойство только deprecated
- **THEN** отчёт MUST вернуть предупреждение без блокировки

#### Scenario: Свойство с новым типом

- **WHEN** сохранённый токен не подходит новому типу
- **THEN** сервер MUST вернуть конфликт; при доказанной совместимости MUST NOT блокировать только из-за смены типа

#### Scenario: Неизвестное ограничение

- **WHEN** нормализованная мета не задаёт допустимые enum значения
- **THEN** сервер MUST NOT объявлять недоказуемый enum-конфликт

### Requirement: Полный адрес проблемы и старое значение

DTO проблемы MUST содержать issueId/code/severity, компонент, оформление при наличии, свойство, вид и ID назначения, стили/подписи осей и значений, состояния, сохранённый литерал/токен/поправки/вложенную ссылку, revision и разрешённые действия. Отдельные платформенные поправки MUST включать их ID/revision, platformParamId, смещение и template, а не заменяться скалярным adjustment. Описание прошлого Core MUST включаться только при доказуемом происхождении.

#### Scenario: Сочетание

- **WHEN** неподдерживаемое свойство задано для Size=L и View=Primary в hovered
- **THEN** DTO MUST однозначно показать сочетание, состояние и сохранённое значение

#### Scenario: Инвариант

- **WHEN** конфликт относится к базовому значению
- **THEN** DTO MUST явно обозначить базовую область без выдуманной вариации

#### Scenario: Ссылка на токен

- **WHEN** назначение хранит tokenId
- **THEN** DTO MUST сохранить ID/доступное имя токена и поправки без обещания вычисленного значения до смены Core

### Requirement: Актуальность общего отчёта

Отчёт MUST иметь контекст границы, draftRevision, Core-релизы и версию проверки, общие blockingCount/warningCount и постраничные items. Фильтр componentId MUST возвращать те же проблемы, что сводка ДС. Устаревшие отчёты MUST NOT разрешать публикацию.

#### Scenario: Проблемы по компоненту

- **WHEN** одна проблема показана в сводке и секции компонента
- **THEN** issueId и причина MUST совпадать

#### Scenario: Пагинация

- **WHEN** возвращена первая страница
- **THEN** blockingCount MUST учитывать весь отчёт, не только страницу

#### Scenario: Core изменился

- **WHEN** draftRevision тот же, но импортирован B
- **THEN** кеш MUST быть инвалидирован, а проверка публикации MUST использовать B

### Requirement: Блокировка только несовместимой ДС

Публикация и получение нового экспорта для генерации MUST отклоняться при блокирующих конфликтах Core выбранной версии или черновика. Этот отказ MUST NOT запрещать локальную генерацию из ранее сохранённого снимка или требовать его обновления. Проверка публикации MUST быть согласована с фиксацией Core. Отсутствие preview и одни предупреждения MUST NOT блокировать конфигурационную публикацию; прочие существующие проверки сохраняются.

#### Scenario: Обход UI

- **WHEN** клиент напрямую публикует конфликтный черновик
- **THEN** сервер MUST вернуть 409 CORE_COMPATIBILITY_CONFLICT без новой версии или черновика

#### Scenario: Проверен A, импортируется B

- **WHEN** импорт и публикация выполняются одновременно
- **THEN** публикация MUST проверить и закрепить один согласованный набор Core

#### Scenario: Нет preview

- **WHEN** конфликтов конфигурации нет, совместимая сборка ещё не загружена
- **THEN** публикация MUST разрешаться при соблюдении остальных проверок

#### Scenario: Экспорт

- **WHEN** CLI запрашивает экспорт конфликтного черновика
- **THEN** сервер MUST вернуть структурированную ошибку вместо частичного конфига

### Requirement: Различение общих и компонентных состояний

Проверка MUST NOT считать отсутствие системного состояния в мета-файле удалением из Core.

#### Scenario: Системное состояние сохранено

- **WHEN** значение использует предустановленное hovered, которого нет в мете B
- **THEN** checker MUST разрешить это состояние по системному набору

#### Scenario: Удалено компонентное состояние

- **WHEN** состояние конкретного компонента присутствовало в A, отсутствует в B и используется настройкой
- **THEN** checker MUST вернуть блокирующую проблему без удаления настройки
