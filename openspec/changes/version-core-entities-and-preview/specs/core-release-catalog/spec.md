## ADDED Requirements

### Requirement: Неизменяемый API Core-релиза

Система MUST хранить релиз по libraryId/platform/version с исходной метой и SHA-256, составом компонентов/свойств/компонентных состояний/платформенных параметров и их используемыми характеристиками. Общие ID MUST сохраняться; чтение ДС MUST NOT брать изменяемое описание API из общего каталога.

#### Scenario: Новый релиз

- **WHEN** в B добавлен параметр и изменён deprecated существующего имени
- **THEN** API ДС на A MUST сохранить прежний состав и deprecated

#### Scenario: Повтор

- **WHEN** импорт повторяет координаты A
- **THEN** одинаковая мета MUST дать идемпотентный результат; другая MUST дать 409 CORE_RELEASE_IMMUTABLE

#### Scenario: Смена типа

- **WHEN** известное свойство получило другой поддерживаемый тип в B
- **THEN** система MUST сохранить типы A и B раздельно, не переписывая исторические данные

### Requirement: Удаление из Core сохраняет идентичность и данные

Импорт MUST разрешать отсутствие ранее существовавших сущностей, включая deprecated, без блокировки Core-релиза. Общие записи и настройки ДС MUST сохраняться. Состав нового релиза MUST строиться из его меты, не из накопленного каталога.

#### Scenario: Удалено deprecated свойство

- **WHEN** в B отсутствует свойство A
- **THEN** B MUST успешно импортироваться; ID и значения свойства A MUST остаться

#### Scenario: Удаление не используется

- **WHEN** ДС не содержит настроек удалённого свойства
- **THEN** это отсутствие MUST NOT создавать блокирующую проблему

#### Scenario: Пустой состав

- **WHEN** передана корректная мета релиза с пустым составом
- **THEN** импорт MUST сохранить пустой релиз без физического удаления каталога

### Requirement: Автоматический Core черновика

Черновик MUST использовать текущий успешно импортированный Core своей библиотеки/платформы без ручного выбора и отдельной активации. Переход MUST сохранять настройки и обновлять контекст/отчёт/кеш даже без смены draftRevision.

#### Scenario: Импорт B

- **WHEN** черновик использовал A и успешно импортирован B
- **THEN** следующее разрешение MUST использовать B и проверить сохранённые настройки

#### Scenario: Повтор A

- **WHEN** после B повторён идентичный импорт уже известного A
- **THEN** указатель MUST остаться на B

#### Scenario: Неполный набор артефактов

- **WHEN** мета B загружена, preview и Markdown ещё нет
- **THEN** импорт MUST NOT ожидать их отдельной активации

### Requirement: Разделение Core и публикации ДС

Импорт Core MUST оставаться техническим обновлением каталога и контекста черновика. Он MUST NOT создавать версию ДС, следующий черновик, предметную запись журнала или запускать публикацию пакета; смена Core сама по себе MUST NOT менять draftRevision. Опубликованные версии MUST сохранять закреплённый Core.

#### Scenario: Только импорт Core

- **WHEN** успешно импортирован B при существующих опубликованной V1 и черновике
- **THEN** количество и статусы версий ДС, её активный draftId/draftRevision и предметный журнал MUST остаться прежними; контекст черновика MUST разрешать B

### Requirement: Системные состояния и вложенность Core

Общие состояния взаимодействия MUST оставаться предустановленным системным набором вне меты и состава Core. Компонентные состояния и представленная метой вложенность MUST разрешаться из Core. Настройки ДС MUST NOT изменять вложенность, но MUST сохранять выбор оформлений/стилей вложенных свойств в предметных редакциях. Технические REUSE-связи MUST NOT расширять Core. Неописанные метой ограничения MUST NOT выдумываться.

#### Scenario: Общее состояние отсутствует в мете

- **WHEN** в настройке используется системное hovered, отсутствующее в мете релиза
- **THEN** это отсутствие MUST NOT считаться удалением состояния или блокирующим конфликтом

#### Scenario: Выбор оформления после импорта

- **WHEN** после импорта A пользователь меняет оформление предусмотренного Core вложенного свойства
- **THEN** назначение MUST сохраняться в границе ДС без изменения проекции A; опубликованная граница MUST сохранять своё прежнее назначение

#### Scenario: Вложенность изменилась в B

- **WHEN** мета B изменяет известную вложенность Core
- **THEN** модель V1 на A MUST сохранить прежнюю вложенность, а черновик на B MUST проверять назначения по известным ограничениям B

### Requirement: Защита импортной идентичности

После включения сущности в Core административные операции MUST NOT менять её импортный ключ: имя/платформу компонента, имя и принадлежность свойства. Изменение отображаемого описания MUST NOT менять сопоставление при последующих импортах. Переименование в исходном API MUST трактоваться как исчезновение старой сущности и появление новой без автоматического переноса настроек.

#### Scenario: Ручное изменение ключа

- **WHEN** административный запрос пытается переименовать компонент, уже включённый в Core
- **THEN** операция MUST быть отклонена без изменения ключа; последующий импорт прежнего имени MUST сохранить ID
