## ADDED Requirements

### Requirement: Удаление несовместимого назначения

Операция MUST удалять сохранённое назначение по valueKind/valueId с проверкой прав, принадлежности, ожидаемой редакции и существующим согласованием правок. Отсутствие свойства/состояния в новом Core MUST NOT запрещать удаление. Общие сущности и опубликованные настройки MUST сохраняться.

#### Scenario: Удалённое свойство

- **WHEN** редактор удаляет конфликтное значение
- **THEN** сервер MUST удалить значение с его ссылками/поправками через существующие редакции и журнал

#### Scenario: Старая редакция

- **WHEN** значение уже изменено другим участником
- **THEN** операция MUST вернуть конфликт без удаления новой записи

### Requirement: Атомарный перенос несовместимого назначения

Перенос MUST явно выбирать целевое свойство текущего Core и проверять тип, токен, состояния, область и вложенную ссылку. Создание назначения и удаление источника MUST быть атомарными; занятое назначение MUST NOT перезаписываться молча. В первой реализации отдельные платформенные поправки источника MUST запрещать перенос с объяснением: ни смещения/шаблоны, ни их старые platformParamId MUST NOT теряться или копироваться в другое свойство. Наличие поправок MUST проверяться атомарно с операцией.

#### Scenario: Допустимая замена

- **WHEN** цель совместима и свободна, источник не содержит отдельных платформенных поправок
- **THEN** сервер MUST сохранить область/состояния/значение в цели и удалить источник одной операцией

#### Scenario: Цель занята

- **WHEN** в целевой ячейке есть значение
- **THEN** сервер MUST вернуть конфликт, сохранив обе исходные настройки

#### Scenario: Нельзя перенести

- **WHEN** тип или состояние цели не поддерживает значение
- **THEN** сервер MUST отклонить перенос без изменений и вернуть объяснение

#### Scenario: Назначение с платформенными поправками

- **WHEN** источник содержит отдельное платформенное смещение или template
- **THEN** сервер MUST отклонить перенос с понятной причиной, сохранив значение, все поправки, их ревизии и цель без изменений
- **THEN** UI MUST объяснить необходимость ручного исправления
