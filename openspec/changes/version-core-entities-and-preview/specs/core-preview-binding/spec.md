## ADDED Requirements

### Requirement: Связь с существующим реестром preview

Сервер MUST связывать существующие buildId/platform/libraryVersion/metaSha256 с Core-релизом без второго реестра сборок. Канал и мета архива MUST совпадать с релизом; сборка другого релиза MUST NOT использоваться как замена.

#### Scenario: Совместимая сборка

- **WHEN** версия библиотеки и SHA-256 меты совпадают с A
- **THEN** сборка MUST зарегистрироваться для A

#### Scenario: Другой хеш

- **WHEN** при тех же координатах архив содержит иную мету
- **THEN** операция MUST быть отклонена без замены Core или закреплённой сборки

### Requirement: Фиксация и позднее поступление preview

Публикация MUST фиксировать точный buildId совместимой доступной сборки либо ожидающий слот закреплённого Core. Первая поздняя совместимая сборка MUST заполнять пустой слот однократно; последующие MUST NOT менять preview опубликованной ДС. Черновик MUST выбирать последнюю зарегистрированную сборку своего Core.

#### Scenario: После нового Core

- **WHEN** V1 закрепила A и buildA, пользователь явно выбрал B для этой платформы черновика
- **THEN** V1 MUST использовать buildA; черновик MUST NOT подставлять его вместо отсутствующего buildB

#### Scenario: Поздний preview

- **WHEN** V1 опубликована без сборки A, затем пришли A1 и A2
- **THEN** пустой слот MUST закрепить A1 атомарно; A2 MUST NOT заменить A1 у V1

#### Scenario: Очистка

- **WHEN** сборка перестала быть глобально активной, но закреплена у V1
- **THEN** очистка MUST сохранить её объекты и проверенную мету

### Requirement: Системное разрешение и кеш preview

Адрес preview MUST разрешаться по DS/version/platform и возвращать buildId/Core/channel/хеш меты. Обязательный coreReleaseId во входе MUST NOT требоваться: сервер MUST использовать выбранную настройку черновика или историческую привязку. Кеш и iframe MUST учитывать выбранный контекст, а локальный прямой URL MUST оставаться явно обозначенным режимом разработки.

#### Scenario: Смена версии

- **WHEN** пользователь переключает V1/A на V2/B
- **THEN** клиент MUST получить соответствующую сборку, сбросить прежний iframe и игнорировать старый ответ

#### Scenario: Прямой адрес

- **WHEN** задан локальный VITE URL
- **THEN** UI MUST обозначить режим разработки без утверждения соответствия закреплённому Core

#### Scenario: Новый импорт без выбора

- **WHEN** зарегистрирован preview dev/B, но ДС выбрала stable/A
- **THEN** её preview MUST остаться на A; отсутствие сборки A MUST NOT приводить к подстановке B

### Requirement: Замена незакреплённого dev-preview обычной загрузкой

Обычная загрузка MUST заменять изменённый ZIP с тем же build ID только для dev, при прежних Core-координатах, исходной мете и совместимом протоколе. Новый API Core MUST NOT поставляться заменой preview. Stable и сборки, закреплённые опубликованной либо архивной версией ДС, MUST отклонять замену. Идентичный ZIP MUST оставаться идемпотентным без нового каталога.

Новые файлы MUST загружаться в отдельный служебный каталог, после полной загрузки URL сборки MUST переключаться атомарно с записью в БД. Неудачная загрузка/фиксация MUST сохранять прежний URL и файлы доступными. URL новой редакции MUST отличаться для обновления кеша manifest, JS и Wasm без смешивания поколений; logical build ID MUST оставаться прежним. Устаревший каталог MUST удаляться после фиксации и повторной проверки отсутствия ссылок; сбой удаления MUST допускать повторную очистку осиротевших каталогов. Редакции файлов MUST NOT образовывать бессрочную историю S3.

#### Scenario: Замена черновика

- **WHEN** явно загружен изменённый ZIP dev-preview с прежней неизменной метой и незакреплённым build ID
- **THEN** сервер MUST вернуть outcome=replaced, новый URL и прежний build ID; прежний каталог MUST быть удалён после успешного переключения
- **AND** Core, coreSelectionRevision, предметные настройки и журнал ДС MUST остаться прежними

#### Scenario: Историческое закрепление и гонка

- **WHEN** публикация ДС выполняется одновременно с заменой её preview
- **THEN** общий барьер Core MUST сериализовать операции: история либо закрепит полностью заменённую сборку, либо заблокирует замену, сохранив прежнюю
- **AND** текущие draft-привязки MUST NOT сами по себе запрещать замену, в отличие от защиты исторических слотов

#### Scenario: Отказ и пробная загрузка

- **WHEN** задан dryRun, изменён Core, выбран stable или сборка закреплена
- **THEN** dryRun MUST проверять возможность операции без записи файлов/БД; остальные недопустимые замены MUST отклоняться до загрузки файлов
- **AND** ошибка хранения или БД MUST NOT переключать клиент на неполную сборку

#### Scenario: Повторная dev-регистрация после очистки

- **WHEN** незакреплённая dev-сборка A удалена retention-очисткой и затем загружается изменённый ZIP B с тем же build ID и Core
- **THEN** первая регистрация каждой редакции MUST использовать служебный storageKey с SHA-256 архива; URL B MUST отличаться от URL A, а logical build ID MUST сохраниться
- **AND** существующие legacy storageKey MUST продолжать читаться; идемпотентный ZIP MUST NOT создавать дополнительный каталог

### Requirement: Канал публикации задаёт вызывающий CLI

preview-plugin publish MUST требовать явный --channel stable|dev и передавать его в нормализованной мете запроса. Сборка ZIP MUST NOT выбирать канал, требовать канал или включать его в новый manifest. Старое поле channel в ZIP MUST игнорироваться; сервер MUST доверять проверенному полю запроса, а не архиву, адресу сервера или номеру версии. Уже зарегистрированный Core MUST сохранять неизменяемый канал; отправка в другой канал MUST давать CORE_RELEASE_IMMUTABLE.

Build ID MUST быть независим от одного лишь commit SHA. Producer MUST детерминированно вычислять первые 12 hex SHA-256 от commit, libraryId, platform и версии Core, разделённых переводом строки. Одна комбинация MUST давать прежний ID при пересборках, новая явно заданная версия Core MUST давать другой ID без коммита. Старые ID-prefix SHA MUST оставаться читаемыми. Мета под прежней версией Core MUST оставаться неизменяемой независимо от ID.

#### Scenario: Новая мета без коммита

- **WHEN** пользователь задаёт новую coreVersion и собирает изменённую мету в том же рабочем дереве без коммита
- **THEN** ZIP MUST содержать новые координаты и build ID; CLI --channel dev --apply MUST зарегистрировать новый dev-Core и preview
- **AND** повтор идентичных данных MUST быть идемпотентным; изменение только preview под прежней версией MUST проходить обычную допустимую замену

#### Scenario: Канал вне архива

- **WHEN** ZIP не содержит channel или старый ZIP содержит другой channel
- **THEN** явно переданный CLI канал MUST определять попытку регистрации; отсутствие --channel MUST отклоняться до сети
- **AND** смена канала уже зарегистрированных координат MUST отклоняться сервером, не изменяя данные

### Requirement: Полномочия издателя Core и preview

Роль composePreviewPublisher MUST разрешать регистрацию нового Core вместе с проверенным preview, включая продвижение явно выбранного latest соответствующего канала во всех проектах. Прямой импорт меты MUST по-прежнему требовать globalAdmin. Назначение роли MUST явно описывать это влияние; pinned и опубликованные границы MUST сохраняться.

#### Scenario: Публикация доверенным издателем

- **WHEN** composePreviewPublisher без globalAdmin публикует корректный ZIP нового Core
- **THEN** регистрация MUST быть разрешена, а latest MUST обновляться по общему контракту
