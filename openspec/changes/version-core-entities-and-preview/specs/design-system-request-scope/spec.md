## ADDED Requirements

### Requirement: Релизный контекст системной модели

Системные чтения компонентов, свойств, состояний, параметров, зависимостей, оформления и экспорта MUST разрешать Core по существующему DS/version селектору: сохранённый выбор канал/версия для каждой платформы черновика либо неизменяемые привязки опубликованной границы. Новые импорты MUST NOT менять это разрешение. Отдельный обязательный coreReleaseId MUST NOT требоваться. Глобальные catalog-входы сохраняются для реестра и MUST NOT использоваться клиентом как модель опубликованной ДС.

#### Scenario: Исторические данные

- **WHEN** запрос содержит versionId V1 на A
- **THEN** все API-описания MUST соответствовать A независимо от текущего каталога

#### Scenario: Чужая версия

- **WHEN** versionId относится к другой ДС/проекту
- **THEN** сервер MUST вернуть 404 без раскрытия API и настроек

#### Scenario: Смена Core между чтениями

- **WHEN** клиент продолжает согласованное чтение с устаревшим отпечатком Core/coreSelectionRevision после явной смены выбора
- **THEN** сервер MUST потребовать повторное разрешение, не смешивая A и B

### Requirement: Единая релизная граница для публичного и проектного чтения

После интеграции публичного чтения сервер MUST разрешать Core одним механизмом по проверенной DS/version-границе для гостя и участника. X-DS-Read-Context и coreReleases MUST описывать одну границу; клиент MUST NOT выбирать Core независимо. Адресные catalog-чтения с designSystemId/version MUST использовать релизные описания этой границы, а не изменяемые поля общего каталога. Публичный ответ MUST NOT раскрывать ревизии черновика. Права и доступность определяются зависимым Change публичного чтения, не этим требованием.

#### Scenario: Публикация A после импорта B

- **WHEN** гость и участник имеют право читать V1 на A после импорта B
- **THEN** описания компонентов, модель, экспорт и разрешённая preview-сборка V1 MUST соответствовать A для обоих
- **AND** catalog-чтение с контекстом V1 MUST NOT возвращать поля B или определения, недоступные выбранной границе

### Requirement: Принадлежность Core проверяется через версию ДС

Сервер MUST проверять принадлежность выбранной версии запрошенной ДС/проекту через таблицу версий до чтения привязок Core. Таблица привязок MUST использовать versionId без дублирования design_system_id; непроверенный versionId MUST NOT давать доступ к Core другой ДС.

#### Scenario: Версия соседней ДС того же проекта

- **WHEN** запрос к ДС A содержит versionId, принадлежащий ДС B того же проекта
- **THEN** сервер MUST вернуть 404 без Core, API-описаний и настроек B

### Requirement: Отказ при устаревшем контексте согласованного чтения

Необязательный отпечаток чтения MUST проверяться относительно фактически выбранной границы. Устаревший отпечаток MUST давать 409 CORE_CONTEXT_STALE. Он MUST NOT становиться обязательным предварительным запросом или заменять проверку доступа. Устаревшая coreSelectionRevision команды записи MUST давать 409 CORE_SELECTION_STALE.

#### Scenario: Обычное чтение без отпечатка

- **WHEN** разрешённое чтение не передаёт отпечаток
- **THEN** сервер MUST вернуть данные и фактический Core-контекст выбранной границы без требования предварительного разрешения
