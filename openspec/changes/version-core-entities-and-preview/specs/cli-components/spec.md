## ADDED Requirements

### Requirement: Core-контекст экспорта

Fetch/export MUST использовать явно выбранные для платформ Core выбранной границы и сохранять его координаты и канал в локальных метаданных без изменения формата конфигурации для генератора. Сервер MUST проверять совместимость конфигурации относительно Core выбранной версии или черновика при получении нового экспорта.

#### Scenario: Экспорт V1

- **WHEN** импортирован B, но CLI получает V1 на A
- **THEN** конфигурация и метаданные MUST соответствовать A

#### Scenario: Отказ в получении нового экспорта

- **WHEN** CLI запрашивает новый экспорт и сервер возвращает CORE_COMPATIBILITY_CONFLICT
- **THEN** CLI MUST показать причину и завершить операцию с ошибкой без запуска генератора с результатом этого запроса и без незаметной подстановки ранее сохранённого снимка

### Requirement: Независимая генерация из сохранённого снимка

CLI MUST разрешать локальную генерацию из выбранного сохранённого снимка ДС без обязательного обращения к серверу, проверки актуальности серверного контекста или совпадения Core снимка с локальными исходниками и зависимостями. Метаданные Core MUST сохранять происхождение снимка и MUST NOT служить требованием обновить его перед генерацией. CLI MUST NOT автоматически обновлять снимок из-за изменения серверного состояния или локальной версии Core. Совместимость с локальными исходниками и зависимостями MUST проверяться локальной сборкой и тестами, а не выводиться из равенства версий Core.

#### Scenario: Серверный черновик изменился

- **WHEN** после сохранения снимка изменились серверный черновик, его отпечаток или Core, в том числе появились блокирующие конфликты
- **THEN** CLI MUST разрешать генерацию из выбранного сохранённого снимка без требования обновить данные или проверить актуальный серверный контекст

#### Scenario: Сервер недоступен

- **WHEN** выбранный снимок и необходимые локальные средства генерации доступны, а сервер недоступен
- **THEN** CLI MUST разрешать генерацию без серверной проверки совместимости или актуальности

#### Scenario: Разработка следующего Core в том же репозитории

- **WHEN** снимок ДС относится к опубликованному Core A, а локальные исходники или зависимости используют ещё не выпущенный Core B
- **THEN** CLI MUST разрешать генерацию из снимка A без требования совпадения версий или публикации B; совместимость результата с B MUST проверяться локальной сборкой и тестами

#### Scenario: Новый экспорт отклонён после сохранения снимка

- **WHEN** сервер отклонил новый экспорт из-за конфликтов, а пользователь отдельно запускает генерацию из ранее сохранённого снимка A
- **THEN** CLI MUST разрешать эту локальную генерацию без повторной проверки конфликтного серверного состояния

### Requirement: Явный канал поставки Core

CLI импорта MUST требовать --channel stable|dev рядом с --library-id/--core-version. Публикация preview MUST требовать --channel stable|dev и сверять его с зарегистрированным релизом; общий контекст CLI/MCP MUST переносить coreSelectionRevision и каналы. Канал MUST NOT выводиться из версии, API URL или статуса ДС.

#### Scenario: Нет канала

- **WHEN** импорт или публикация preview вызваны без --channel
- **THEN** CLI MUST завершить операцию с понятной ошибкой без записи и без подстановки stable/dev

#### Scenario: Новый импорт после сохранённого снимка

- **WHEN** импортирован новый Core в любом канале, а ДС сохранила прежний выбор
- **THEN** новый fetch MUST использовать прежний выбор, а локальная генерация сохранённого снимка MUST оставаться автономной

## MODIFIED Requirements

### Requirement: API meta import backend contract

CLI SHALL регистрировать Core-релиз одним запросом на административный маршрут `import-api-meta`. Контракт общий для всех поддерживаемых платформ, включая SwiftUI: координаты coreRelease, channel stable/dev, sourceMetaBase64 с точными исходными байтами, metaSha256 и полный нормализованный состав. Ошибка недопустимого релиза MUST исключать частичное принятие независимо от --strict. Алгоритмы нормализации и предусмотренные пропуски служебных данных MUST сохраняться; диагностируемый нормализатором недопустимый конфликт MUST NOT превращаться в успешный частичный релиз.

#### Scenario: Один запрос

- **WHEN** манифест готов
- **THEN** CLI MUST отправить `POST /api/admin/component-config/import-api-meta`
- **THEN** тело MUST содержать `platform`, `coreRelease`, `channel`, `sourceMetaBase64`, `metaSha256`, метаданные источника, `dryRun` и все компоненты
- **THEN** тело MUST NOT содержать `designSystemId`
- **THEN** CLI MUST NOT отправлять по запросу на компонент или свойство

#### Scenario: Источник — имя файла

- **WHEN** CLI формирует метаданные источника
- **THEN** он MUST передать имя файла без директорий

#### Scenario: Платформенные имена с устареванием

- **WHEN** CLI формирует свойство манифеста
- **THEN** каждый элемент `platformNames` MUST быть объектом `{ name }` и MUST содержать `deprecated: { message }` только если соответствующая запись меты помечена как устаревшая

#### Scenario: Печать отчёта

- **WHEN** backend вернул успешный ответ
- **THEN** CLI MUST напечатать счётчики созданных компонентов, свойств, состояний и платформенных имён и число неизменённых свойств
- **THEN** CLI MUST напечатать счётчики `deprecatedMarked`, `deprecatedMessageChanged` и `deprecatedCleared`, если хотя бы один из них не равен нулю
- **THEN** CLI MUST NOT печатать строку о привязках к дизайн-системе
- **THEN** CLI MUST напечатать releaseId/CoreReleaseRef/channel и диагностику с причинами; успешная регистрация MUST NOT содержать частично отклонённый состав
- **THEN** CLI MUST напечатать справочный раздел `Absent from meta` со списком `absent`, если он не пуст

#### Scenario: Строгий режим

- **WHEN** диагностика нормализации или ответ backend сообщает недопустимый релиз, с --strict или без него
- **THEN** CLI MUST завершиться кодом `1`, не регистрируя неполную проекцию и не продолжая импорт по компонентам
- **THEN** непустой `absent` и ненулевые счётчики `deprecated*` MUST NOT влиять на код выхода

#### Scenario: Ошибка backend

- **WHEN** backend вернул неуспешный статус
- **THEN** CLI MUST обработать его общим HTTP error handling CLI core
- **THEN** CLI MUST NOT выводить raw credential

#### Scenario: Отчёт не разбирается

- **WHEN** backend вернул успех с телом, которое не разбирается как отчёт
- **THEN** CLI MUST вернуть deterministic failure и MUST NOT печатать частичный отчёт

#### Scenario: SwiftUI со служебными пропусками

- **WHEN** нормализатор SwiftUI пропустил unmapped и служебные поля по своему контракту без недопустимых конфликтов
- **THEN** CLI MUST отправить допустимый нормализованный состав с исходными байтами всего файла и полными координатами/channel одним запросом
- **AND** предусмотренные пропуски MUST NOT считаться частичным отказом релизного импорта

#### Scenario: Старый формат запроса

- **WHEN** старый CLI отправляет мету без обязательных координат, канала или исходной меты/контрольной суммы
- **THEN** новый сервер MUST вернуть 400 CORE_RELEASE_METADATA_REQUIRED до изменения каталога с пояснением о необходимости обновить CLI или формат запроса

#### Scenario: Недопустимый конфликт нормализации

- **WHEN** нормализатор SwiftUI сообщает конфликт типов, делающий релиз недопустимым, сохранив первое вхождение для диагностики
- **THEN** CLI MUST показать конфликт и завершить операцию без отправки неполного релиза независимо от --strict

#### Scenario: Рабочее дерево не ограничивает загрузку артефакта

- **WHEN** CLI импортирует мету или отправляет готовый preview-архив из каталога с незакоммиченными либо неотслеживаемыми файлами
- **THEN** CLI MUST проверять входной артефакт и ответ сервера без проверки чистоты локального Git-дерева
- **AND** сервер MUST сохранять проверку неизменяемости Core-координат, меты и preview build ID

#### Scenario: Обычная загрузка dev-preview

- **WHEN** CLI загружает dev-preview под прежним build ID с изменённым ZIP и прежним Core
- **THEN** CLI MUST выполнять обычную загрузку без специального флага замены; запись MUST по-прежнему требовать --apply, без него выполняется dryRun
- **AND** CLI MUST показать outcome=replaced и новый URL либо точную причину запрета, не проверяя локальное Git-дерево
