## ADDED Requirements

### Requirement: Сводка проблем перед публикацией

Раздел публикации MUST показывать серверный список конфликтов и предупреждений всей ДС, расположение и сохранённые значения с переходом к компоненту. Публикация MUST отключаться при блокирующих проблемах; deprecated MUST NOT считаться блокирующим сам по себе.

#### Scenario: Есть конфликт

- **WHEN** отчёт содержит хотя бы одну блокирующую проблему
- **THEN** список MUST показать её причину и расположение, а действие публикации MUST быть недоступно

#### Scenario: Только предупреждения

- **WHEN** блокирующих проблем нет
- **THEN** предупреждения MUST быть видны и MUST NOT запрещать публикацию сами по себе

#### Scenario: Отчёт не готов

- **WHEN** проверка ещё загружается либо завершилась ошибкой
- **THEN** UI MUST показывать это состояние, а не сообщать об отсутствии проблем

### Requirement: Секция Проблемы в редакторе компонента

Редактор MUST иметь секцию «Проблемы» рядом со «Стилизацией» и «Структурой». Она MUST показывать оформление, вариации/сочетания, состояния, причину и старую настройку, поддерживать переход из сводки и действия удаления/допустимого переноса.

#### Scenario: Переход из публикации

- **WHEN** выбрана проблема сочетания вариаций
- **THEN** редактор MUST открыть нужный компонент/оформление и соответствующую проблему

#### Scenario: Компонент удалён

- **WHEN** Core больше не содержит настроенный компонент
- **THEN** компонент MUST оставаться доступным в UI для диагностики и исправления, даже если обычный экспорт конфликтует

#### Scenario: Исправление

- **WHEN** сервер подтвердил удаление или перенос
- **THEN** UI MUST обновить счётчики/список; старый ответ MUST NOT вернуть устранённую проблему
