## ADDED Requirements

### Requirement: Сводка проблем перед публикацией

Раздел публикации MUST показывать краткое состояние проверки в секции «Состояние» с полным сообщением в hover tooltip, в том числе при отсутствии проблем, без встроенного списка конфликтов. Публикация MUST отключаться при блокирующих проблемах. ApiDeprecated MUST NOT создавать строки проблем или индикаторы и MUST NOT запрещать публикацию; пометка устаревания MUST оставаться непосредственно у свойства в стилизации. Серверный формат предупреждений сохраняется для совместимости API.

#### Scenario: Есть конфликт

- **WHEN** отчёт содержит хотя бы одну блокирующую проблему
- **THEN** действие публикации MUST быть недоступно, а ссылка MUST открывать «Валидацию → Совместимость» в выбранной границе ДС

#### Scenario: Только предупреждения об устаревании

- **WHEN** назначение использует ApiDeprecated без иных конфликтов
- **THEN** пользовательский отчёт MUST NOT считать его проблемой и MUST NOT показывать индикатор или вкладку проблем из-за него
- **AND** публикация MUST оставаться доступной при выполнении остальных условий

#### Scenario: Отчёт не готов

- **WHEN** проверка ещё загружается либо завершилась ошибкой
- **THEN** UI MUST показывать это состояние, а не сообщать об отсутствии проблем

### Requirement: Индикаторы и секция Проблемы в инспекторе компонента

Компоненты с блокирующими проблемами MUST иметь индикатор в списке, ведущий к отчёту. Инспектор MUST иметь вкладку «Проблемы» рядом со «Стилизацией» и «Структурой» при наличии блокирующих проблем. Она MUST перечислять все проблемные назначения этого компонента во всех оформлениях с вариациями/сочетаниями, состояниями и причинами. Вкладка MUST содержать только переходы, без самостоятельного UI исправления.

#### Scenario: Переход к назначению

- **WHEN** выбрана проблема значения
- **THEN** редактор MUST открыть нужный компонент/оформление, точные стили/пересечение и «Стилизацию», прокрутить к проблемной строке и выделить её красным с причиной и состоянием
- **AND** ссылка MUST сохранять историческую границу и восстанавливать адрес после обновления страницы

#### Scenario: Компонент удалён

- **WHEN** Core больше не содержит настроенный компонент
- **THEN** его сохранённые данные MUST оставаться доступными для диагностики независимо от конфликта экспорта; проблема уровня компонента MUST вести к объяснению и выбору библиотеки в валидации

### Requirement: Исправление несовместимых назначений в стилизации

Стилизация MUST сохранять читаемыми прежние имя, значение и область проблемного назначения. Удалённое свойство MUST показываться специальной строкой сохранённого назначения с прежним значением в обычном поле только для чтения и стандартной очисткой, без выбора свойства для переноса и без создания новых значений. Обычные свойства MUST исправляться привычными контролами с подсветкой причины. Несовместимый тип или недоступное состояние MUST NOT приводить к неявному преобразованию или потере исходного значения.

#### Scenario: Удаление или перенос

- **WHEN** пользователь исправляет сохранённое назначение
- **THEN** UI MUST дождаться автосохранения, проверить актуальность проблемы и применить существующий контракт с ревизиями; серверный отказ MUST сохранять данные, обновлять отчёт и показывать ошибку
- **AND** после подтверждения UI MUST перечитать модель и счётчики; устранённая проблема MUST исчезнуть

#### Scenario: Историческая граница

- **WHEN** выбран опубликованный снимок или пользователь имеет только чтение
- **THEN** переходы и вкладки MUST оставаться доступны, а изменение свойств и действия исправления MUST быть недоступны

### Requirement: Общая валидация дизайн-системы

В панели навигации MUST существовать «Валидация» с единственным левым разделом «Совместимость». Страница MUST использовать общий каркас настроек. Центральная область MUST показывать полный отчёт с группировкой по компонентам; правая MUST содержать объяснение выбранной проблемы, исходные данные и переход к назначению, без изменения данных. Историческая версия MUST сохраняться в ссылках. Не найденная по ссылке проблема MUST явно отмечаться как отсутствующая, без неявного выбора другой проблемы.

#### Scenario: Платформа без визуального редактора

- **WHEN** проблема относится к Android View или SwiftUI
- **THEN** полный отчёт MUST оставаться доступным для диагностики без изменения данных и без перехода к неподдерживаемому визуальному редактору

### Requirement: Компактное представление валидации

Индикатор компонента MUST занимать отдельную колонку рядом с кнопкой скрытия без переноса строки. Вкладка «Проблемы» MUST иметь нейтральный текст и danger-точку слева по центру по вертикали; в rail MUST использоваться размер остальных иконок и danger-точка справа вверху при блокирующих проблемах. Строка недоступного назначения в стилизации MUST повторять обычную строку свойства: имя, прежнее значение, красная рамка поля и стандартная очистка. Вариация/оформление MUST NOT дублироваться внутри такой строки; состояние MUST оставаться различимым при нескольких назначениях. Перенос значения пользователь выполняет вручную. Общий отчёт MUST занимать всю ширину центральной области; правая секция MUST предоставлять только сведения и переходы, без удаления или переноса.

#### Scenario: Блокирующие проблемы перед публикацией
- **WHEN** проверка нашла N блокирующих проблем активного черновика
- **THEN** статус в секции «Состояние» MUST кратко обозначить проблему и раскрывать полное объяснение в hover tooltip без отдельной подписи над действием, а danger-кнопка «Валидация (N проблема/проблемы/проблем)» MUST заменить кнопку публикации и открыть отчёт
- **AND** склонения MUST учитывать 1/2–4/5–20 и составные числа, например 21, 22 и 111

#### Scenario: Проблем нет или проверка недоступна
- **WHEN** блокирующих проблем нет
- **THEN** MUST отображаться обычная кнопка публикации с остальными существующими ограничениями
- **AND** пока проверка загружается либо завершилась ошибкой, публикация MUST оставаться недоступной и MUST показываться состояние/повтор проверки

### Requirement: Точные подписи и расположение навигации

Причина отсутствующего свойства MUST быть «Свойство отсутствует в выбранной версии библиотеки.» и MUST показываться в hover tooltip круглой warning-иконки перед названием свойства. Название и бордер поля MUST быть danger; подпись под полем MUST NOT дублироваться. Индикатор компонента MUST идти после крестика. В отчёте MUST быть нейтральные счётчики у пункта «Совместимость» слева и справа в заголовке средней панели, без отдельной строки «Проблем: N»; компонентные счётчики MUST NOT быть красными. Текст строки MUST совпадать по левой границе с заголовком/разделителем; отдельная IconButton быстрого перехода MUST быть вертикально центрирована и входить в общую подложку выбранной ячейки с отступами по границе заголовка. Акцентная кнопка основного перехода MUST быть закреплена внизу правой панели на всю ширину внутри её отступов.

#### Scenario: Быстрый переход
- **WHEN** пользователь нажимает иконку перехода в строке
- **THEN** MUST открываться тот же точный адрес назначения, что и по основной кнопке правой панели, без изменения выбранного назначения
