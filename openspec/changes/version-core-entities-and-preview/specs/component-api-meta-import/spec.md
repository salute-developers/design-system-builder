## MODIFIED Requirements

### Requirement: API meta import is additive

Правила неизменности полей и typeMismatches ниже относятся к общему аддитивному каталогу. Релизная проекция MUST хранить поступившее описание нового релиза отдельно, включая иной поддерживаемый тип, без изменения прежней проекции.

Импорт SHALL идентифицировать компонент по паре `(name, platform запроса)`; он SHALL создавать компоненты этой платформы, состояния компонентов, свойства и алиасы платформенных имён, которых ещё нет, и MUST NOT удалять или перенумеровывать существующие строки; описание нового релиза MUST сохраняться отдельно.

#### Scenario: Границы обновления существующих данных

- **WHEN** импорт обрабатывает уже существующие строки или другие платформы
- **THEN** Единственное исключение — статус устаревания алиаса (`deprecated`, `deprecated_message`), который импорт обновляет по правилам требования об устаревании. Импорт MUST NOT создавать привязки компонентов к дизайн-системам и MUST NOT создавать и изменять компоненты других платформ.

#### Scenario: Новый компонент создаётся вместе со свойствами и состояниями

- **WHEN** компонента с таким `(name, platform)` нет
- **THEN** backend MUST создать компонент этой платформы, его свойства, его состояния и алиасы `(property, platform, name)` для каждого платформенного имени

#### Scenario: Компонент другой платформы не используется

- **WHEN** существует компонент с таким `name` только на другой платформе
- **THEN** backend MUST создать новый компонент платформы запроса и MUST NOT изменять компонент другой платформы

#### Scenario: Привязка к дизайн-системе не создаётся

- **WHEN** компонент импортируется
- **THEN** backend MUST NOT создавать и MUST NOT изменять строки привязок компонентов к дизайн-системам

#### Scenario: Несколько платформенных имён одного свойства

- **WHEN** свойство содержит несколько платформенных имён
- **THEN** backend MUST создать по одному алиасу на каждое имя, которого у свойства на этой платформе ещё нет
- **THEN** существующие алиасы MUST NOT удаляться, и их поля, кроме статуса устаревания, MUST NOT изменяться

#### Scenario: Существующие строки не меняются

- **WHEN** компонент, свойство, состояние или алиас уже существует
- **THEN** backend MUST NOT изменять его поля, включая `description`, кроме статуса устаревания алиаса
- **THEN** backend MUST NOT создавать дубликат

#### Scenario: Расхождение типа существующего свойства

- **WHEN** свойство с таким `(component, name)` на платформе запроса существует с другим `type`
- **THEN** backend MUST NOT менять тип
- **THEN** backend MUST вернуть запись в `typeMismatches`
- **THEN** алиасы платформы MUST быть созданы, если их ещё нет

#### Scenario: Тип свойства другой платформы не конфликтует

- **WHEN** свойство с тем же именем на другой платформе имеет другой тип
- **THEN** backend MUST NOT считать это расхождением и MUST NOT вернуть запись в `typeMismatches`

#### Scenario: Повторный импорт не создаёт данных

- **WHEN** тот же манифест применён повторно
- **THEN** все счётчики `created*` MUST быть равны нулю

#### Scenario: Порядок импорта платформ не влияет на состав данных

- **WHEN** манифесты двух платформ импортируются в любом порядке
- **THEN** набор компонентов, свойств, их типов и состояний каждой платформы MUST быть одинаковым при обоих порядках

### Requirement: Property type validation belongs to backend

Backend SHALL проверять нормализованный `type` по поддерживаемым значениям `property_type`. Неизвестный тип или противоречащие дубликаты MUST отклонять весь релиз без записи каталога, проекции или смены текущего указателя. Диагностический `rejected` MUST NOT означать успешный частичный релиз. Предусмотренные контрактом преобразования исходной меты MUST отличаться от ошибок нормализованного состава.

#### Scenario: Неизвестный тип отклоняет свойство, а не импорт

Название существующего сценария сохранено для применения дельты; его прежнее поведение заменяется атомарным отказом релизного импорта.

- **WHEN** одно из нормализованных свойств релиза содержит неподдерживаемый тип
- **THEN** сервер MUST вернуть ошибку с компонентом/свойством/типом, не регистрируя и не активируя релиз
- **THEN** сервер MUST NOT расширять enum или выполнять DDL

#### Scenario: Схема БД не меняется

- **WHEN** тип неизвестен
- **THEN** backend MUST NOT выполнять DDL и MUST NOT расширять enum

#### Scenario: Противоречащие дубликаты

- **WHEN** нормализованный состав содержит несовместимые описания одной сущности
- **THEN** весь импорт MUST быть отклонён без частичного сохранения

#### Scenario: Исправленный повтор после отказа

- **WHEN** ошибка отклонённого импорта исправлена и повторены те же координаты
- **THEN** валидный релиз MUST импортироваться, поскольку прежняя попытка его не зарегистрировала

## ADDED Requirements

### Requirement: Релизный импорт Core

Запрос импорта MUST принимать coreRelease отдельно от исходного файла и полный состав нормализованных сущностей. Исходный мета-файл MUST сохранять прежний платформенный формат: массив компонентов для Compose/React/SwiftUI и объект с `components` для Android View. SHA-256 MUST вычисляться по его исходным байтам без нормализации, повторной сериализации и координат релиза. Сохранение проекции и новых ID MUST быть транзакционным. Запрос без координат MUST NOT получать выдуманную версию; наличие координат внутри массива не требуется. Существующие права администратора, dryRun и безопасные отчёты MUST сохраняться.

#### Scenario: Сохранение A

- **WHEN** администратор импортирует валидный релиз
- **THEN** сервер MUST сохранить неизменяемый релиз и обновить каталог согласованно

#### Scenario: Пробный режим

- **WHEN** dryRun=true
- **THEN** релиз, каталог и текущий указатель MUST остаться прежними

#### Scenario: Ошибка

- **WHEN** проекция не прошла проверку или запись
- **THEN** новые записи и указатель MUST NOT частично активироваться

#### Scenario: Нет координат

- **WHEN** запрос импорта не содержит координат релиза
- **THEN** сервер или CLI MUST потребовать передать координаты отдельно, без требования перегенерировать мета-файл

#### Scenario: Изменена нормализованная проекция

- **WHEN** повторены зарегистрированные координаты и исходная мета, но нормализованный состав отличается
- **THEN** импорт MUST вернуть 409 CORE_RELEASE_IMMUTABLE, не изменяя существующий релиз или указатель

#### Scenario: Прежний массив с отдельными координатами

- **WHEN** передан существующий мета-файл-массив и корректные координаты в запросе
- **THEN** импорт MUST принять формат файла без JSON-оболочки и проверить SHA-256 исходных байтов

#### Scenario: Сохранение формата Android View

- **WHEN** CLI импортирует исходный объект Android View с `components`
- **THEN** сервер MUST сохранить его исходные байты и SHA-256 без преобразования в массив; координаты Core передаются отдельно
