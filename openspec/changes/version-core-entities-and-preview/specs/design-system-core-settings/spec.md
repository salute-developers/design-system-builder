## ADDED Requirements

### Requirement: Канал и выбор версии по платформам любой ДС

Настройки любой ДС MUST позволять независимо выбирать для каждой платформы channel stable/dev и конкретный Core-релиз этого канала либо режим latest. Особый тип, флаг или роль «тестовая ДС» MUST NOT требоваться. Выбор MUST хранить selectionMode=pinned/latest вместе с фактически разрешённым releaseId. При отсутствии selectionMode API MUST использовать pinned для прежних клиентов. latest MUST следовать только явно выбранным платформе и каналу.

#### Scenario: Разные платформы одной ДС

- **WHEN** пользователь сохраняет Compose dev/B при выбранном web stable/A
- **THEN** только Compose черновика этой ДС MUST перейти на B; web, другая ДС и опубликованные версии MUST остаться неизменными

#### Scenario: Новый компонент dev

- **WHEN** импортирован dev-релиз с новым компонентом, но ДС сохраняет прежнюю stable-версию
- **THEN** новый компонент MUST NOT появиться среди доступных для добавления компонентов этой ДС
- **AND** он MUST стать доступным после явного выбора соответствующего dev-релиза, без изменения типа ДС
- **AND** обычный участник с правами настройки MUST видеть этот компонент в каталоге выбранного Core, даже если он ещё нигде не привязан; отсутствие предустановленного шаблона или preview MUST NOT закрывать создание пустого оформления

#### Scenario: Новый stable-релиз

- **WHEN** зарегистрирован новый stable-релиз
- **THEN** он MUST появиться в списке версий stable без переключения уже настроенных ДС

### Requirement: Форма выбора и каталог версий

UI MUST показывать сохранённые канал/версию для каждой платформы. Каталог MUST возвращать конкретные releaseId/version/channel/libraryId/platform с фильтрами platform/channel и пагинацией. Смена канала формы MUST обновлять список версий и сбрасывать несоответствующее локальное значение; серверная настройка MUST меняться только при сохранении полной пары. Отсутствие preview MUST NOT запрещать выбор Core. История MUST показывать закреплённые настройки только для чтения.

#### Scenario: В канале нет версий

- **WHEN** пользователь выбирает канал с пустым списком
- **THEN** UI MUST показать отсутствие версий, запретить сохранение неполной пары и сохранить прежнюю серверную настройку

#### Scenario: Версия без preview

- **WHEN** выбранный релиз зарегистрирован, но совместимая сборка preview отсутствует
- **THEN** сохранение MUST быть разрешено, а preview MUST явно показывать недоступность без подмены другим релизом

### Requirement: Атомарная смена выбора и согласование запросов

Запись настройки платформы MUST принимать channel/selectionMode/releaseId/expectedDraftId/expectedCoreSelectionRevision (releaseId обязателен для pinned; для latest сервер сам разрешает последний релиз), проверять существующие права изменения настроек ДС, принадлежность черновика и соответствие релиза библиотеке/платформе/каналу. Смена MUST быть атомарной и увеличивать отдельную coreSelectionRevision без изменения предметного draftRevision. Повтор текущего режима и пары с актуальным контекстом MUST быть без изменений. Неверные входы MUST NOT менять прежний выбор; устаревшая ревизия MUST возвращать 409 CORE_SELECTION_STALE.

#### Scenario: Несовпадение версии и канала

- **WHEN** для channel=stable передан releaseId зарегистрированного dev-релиза или другой платформы
- **THEN** сервер MUST отклонить запрос без частичного изменения настройки

#### Scenario: Нет права записи

- **WHEN** пользователь с правом только чтения пытается изменить Core
- **THEN** сервер MUST вернуть 403 и сохранить прежний выбор

#### Scenario: Чужая или опубликованная граница

- **WHEN** запрос указывает чужую границу либо пытается менять опубликованную версию
- **THEN** сервер MUST отклонить запрос без раскрытия чужих данных или изменения истории

#### Scenario: Параллельная смена выбора

- **WHEN** две сессии сохраняют разные версии с одной ожидаемой coreSelectionRevision
- **THEN** только первая запись MUST пройти; вторая MUST получить 409 CORE_SELECTION_STALE без перезаписи

#### Scenario: Устаревшая предметная запись или публикация

- **WHEN** после чтения модели другой пользователь сменил выбранный Core
- **THEN** обычная запись, исправление и публикация со старой coreSelectionRevision MUST быть отклонены до изменения данных
- **AND** после обновления модели новый явный запрос MUST проверяться по выбранному Core

### Requirement: Совместимость после явного выбора

Смена Core MUST сохранять все предметные настройки и возвращать обновлённый контекст и сводку blockingCount/warningCount. Ответ настроек MUST NOT раскрывать items, сохранённые значения, токены или адреса назначений; подробности MUST читаться через compatibility с отдельным правом компонентов. Блокирующие конфликты MUST NOT запрещать сохранить выбор, но MUST блокировать новый экспорт и публикацию до исправления. UI MUST обновлять модель/каталог компонентов/отчёт/preview после успешного выбора и игнорировать старые ответы. Предметный журнал MUST NOT пополняться одной сменой Core; при пустом журнале публикация MUST оставаться запрещённой.

#### Scenario: Выбрана несовместимая версия

- **WHEN** пользователь выбирает B с удалённым используемым свойством
- **THEN** B MUST сохраниться, значение MUST остаться доступным в диагностике и отчёт MUST показать конфликт
- **AND** пользователь MUST иметь возможность исправить назначение или явно выбрать прежнюю доступную версию

#### Scenario: Импорт без выбора

- **WHEN** B импортирован, но пользователь продолжает использовать A
- **THEN** coreSelectionRevision, модель, отчёт и доступность экспорта ДС MUST остаться прежними

### Requirement: Создание ДС, публикация и миграция сохраняют конкретный выбор

При создании ДС UI MUST предлагать stable как канал формы, но конкретная версия либо latest MUST выбираться и сохраняться явно. Пока выбор не сохранён, платформа MUST оставаться без Core; ни stable, ни dev релиз MUST NOT подставляться автоматически. Следующий после публикации черновик MUST наследовать конкретные привязки опубликованной границы и выбранную до публикации политику pinned/latest. Миграция MUST сохранить фактически использовавшийся Core существующих черновиков и исторические привязки без назначения будущего latest. Канал наследованных данных MUST NOT угадываться; технические/неопределённые привязки MUST явно показывать неизвестное происхождение и MUST NOT предлагаться как новые stable/dev-релизы.

#### Scenario: Stable отсутствует

- **WHEN** новая ДС создана без сохранённого выбора платформы, в том числе когда в stable нет версий
- **THEN** UI MUST показывать отсутствие выбора; последующий импорт MUST NOT заполнять его автоматически
- **AND** операции, требующие Core этой платформы, MUST возвращать CORE_SELECTION_REQUIRED, сохраняя работу других платформ
- **AND** публикация/экспорт MUST требовать выбора для платформ активных компонентов, а не всех платформ каталога

#### Scenario: Следующий черновик

- **WHEN** ДС публикуется с pinned Compose dev/B и web stable/A при наличии более новых версий
- **THEN** опубликованная версия и следующий черновик MUST сохранить B/A с теми же каналами

#### Scenario: Наследованные данные

- **WHEN** существующий черновик разрешал Core A до миграции, а канал A не доказан
- **THEN** миграция MUST закрепить A без подмены stable/dev или новым релизом
- **AND** UI MUST позволить явно выбрать доступную пару канала и версии без объявления ДС особым типом

#### Scenario: Удаление используемого релиза

- **WHEN** Core используется хотя бы черновиком или опубликованной версией
- **THEN** удаление релиза и исходной меты MUST быть запрещено

### Requirement: Последняя версия выбранного канала

latest MUST означать последний успешно зарегистрированный Core-релиз выбранных платформы/канала в порядке created_at DESC, id ASC (created_at фиксируется после получения барьера импорта платформы), независимо от строки версии. Это тот же порядок, что у каталога. Повторный импорт старого релиза и регистрация ещё одной preview-сборки MUST NOT продвигать latest. Канал без релизов MUST отклонять выбор latest без изменения настройки; пустая платформа MUST NOT автоматически включать latest.

UI MUST помещать в список версии вариант «Последняя (номер версии)» и MUST NOT показывать фактическую версию отдельной подписью рядом. При отсутствии релизов этот вариант MUST отсутствовать. Сохранённый режим latest MUST отмечаться галочкой как самостоятельный вариант, даже если его releaseId совпадает с доступной конкретной версией. Изменение pinned/latest при том же releaseId MUST увеличивать coreSelectionRevision.

#### Scenario: Автоматическое обновление

- **WHEN** черновик выбрал latest в dev для Compose и успешно импортирован новый dev-релиз B
- **THEN** только соответствующие latest-привязки черновиков MUST перейти на B в транзакции импорта с увеличением coreSelectionRevision один раз на затронутую ДС
- **AND** предметные значения, draftId/draftRevision и журнал MUST сохраниться; pinned, другие каналы/платформы и опубликованные версии MUST остаться прежними
- **AND** актуальные модель, совместимость и preview MUST использовать B; несовместимые настройки MUST блокировать новые экспорт и публикацию без автоматического исправления или отката

#### Scenario: Публикация и локальные снимки

- **WHEN** ДС с latest явно публикуется с непустым журналом и без блокирующих проблем
- **THEN** опубликованная версия MUST закреплять фактический Core и preview; следующий черновик MUST наследовать режим latest выбранного канала
- **AND** сохранённый локальный снимок MUST оставаться на своей конкретной версии без сетевого разрешения latest

#### Scenario: Конкурирующие импорт и выбор

- **WHEN** новый импорт выполняется параллельно выбору latest/pinned или публикации ДС
- **THEN** сервер MUST сериализовать выбор с импортом платформы, затем с изменением/публикацией ДС; итоговый latest MUST соответствовать зарегистрированному каталогу, а устаревшая coreSelectionRevision MUST отклоняться
- **AND** dryRun, неуспешный и идентичный повторный импорт MUST NOT менять привязки и ревизии

#### Scenario: Начальный канал формы для старого снимка

- **WHEN** в настройках черновика сохранён старый снимок без известного канала
- **THEN** форма MUST использовать stable как начальный фильтр доступных версий и показывать «Выберите версию» вместо версии снимка; техническое «Неизвестно» MUST NOT предлагаться как вариант выбора
- **AND** открытие формы MUST NOT менять привязку, историческое происхождение или автоматически выбирать новый релиз; сохранение конкретной версии либо latest MUST выполняться явно

#### Scenario: Ожидание параллельного импорта

- **WHEN** транзакция импорта началась раньше другой, но регистрирует новый релиз после ожидания барьера платформы
- **THEN** latest MUST выбрать последний успешно зарегистрированный релиз независимо от времени начала транзакций и SemVer
