# Версии и ограниченное чтение существующих API

## Зачем

MCP должен читать выбранную версию модели и нужную часть списка без локального поиска версии, фильтрации и обрезки полного каталога. Существующим клиентам и командам полной загрузки нужны прежние маршруты и тела ответов.

## Что меняется

- Общий серверный выбор `version=draft|major.minor.patch` при сохранении `versionId` и существующих проверок доступа и связей.
- Необязательные фильтры и `limit/cursor` существующих списков; без ограничения возвращается полный прежний ответ.
- Метаданные фактического чтения и продолжения в HTTP-заголовках; массивы и объекты не оборачиваются.
- Шесть новых MCP tools обнаружения; после этапа реестр содержит 22 инструмента. Простые чтения передают версии и фильтры серверу.
- **BREAKING** только для MCP-списков этого этапа: без `limit` адаптер явно запрашивает 50 элементов; появляются `nextCursor` и контекст в результате tool. HTTP без `limit/cursor` сохраняет полную выдачу.
- Составные операции и изменения документации принадлежат `add-composite-read-tools`, который зависит от этого Change. Авторизация принадлежит независимому `use-pkce-for-cli-mcp`.

## Возможности

### Новые возможности

Нет: расширяются существующие возможности продукта.

### Изменяемые возможности

- `design-system-model-api`: серверный выбор версии, совместимая пагинация, фильтры и метаданные чтения.
- `frontend-mcp-server`: 22 инструмента промежуточного этапа и тонкие адаптеры простых чтений.

## Влияние

`backend-kt/ds-service`: application/domain, репозитории, HTTP и OpenAPI; `identity-gateway/gateway`: открытие безопасных заголовков через CORS в local/prod. `frontend-kt/core-network`, соответствующие feature-модули, `mcp-server-core`, оба executable: чтение метаданных и реестр. Схема JS db-service, платформы, данные и существующие тела ответов web/admin/CLI не меняются; массового обновления клиентов нет. Новые сервисы и зависимости не нужны. Нельзя менять архитектурные тесты, Strictacode policy и файлы агентского процесса.

## Разделение исходного Change

Вместе с `add-composite-read-tools` и `use-pkce-for-cli-mcp` заменяет `unify-read-tools-and-pkce`. Старая объединённая заявка удаляется из активных Change без архивирования и без отметки реализации. Все задачи новых Change остаются невыполненными.
