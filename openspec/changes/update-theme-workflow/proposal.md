## Why

Работа с несколькими темами одной дизайн-системы сейчас неудобна. Чтобы сравнить значение токена в двух темах,
приходится выходить на обзор дизайн-системы и открывать другую тему заново. Вторая тема обычно отличается от первой
парой токенов, но создаётся только из стартового профиля, и все правки первой темы приходится повторять. Настройки
в редакторе относятся к одной теме, а управление темами (переименование, удаление) разбросано по меню карточек.
Перед раскаткой билдера дизайнерам это основной сценарий, поэтому флоу тем нужно пересобрать сейчас.

## What Changes

- В шапке редактора крошка «Тема» становится переключателем тем с поиском. Переключение сохраняет раздел, выбранный
  токен и выбранную версию, поэтому значение того же токена в другой теме видно без перехода на обзор.
- Экраны размеров и типографики, как и экран цветов, открывают токен по параметру `tokenId` в адресе.
- Новое действие «Дублировать тему»: в меню карточки темы и в разделе тем настроек. Копия получает все значения
  токенов всех платформ и режимов, палитру, группы токенов палитры и профиль исходной темы.
- Форма создания темы, когда в дизайн-системе уже есть темы, по умолчанию предлагает создать копию существующей
  темы; создание из стартового профиля остаётся вторым вариантом.
- Новый маршрут API `POST /api/design-systems/{designSystemId}/tenants/{id}/duplicates` создаёт копию темы атомарно
  в активном черновике.
- Шестерёнка в редакторе открывает настройки дизайн-системы, а не одной темы. В настройках появляется раздел
  «Темы»: список тем с переименованием, дублированием и удалением.
- **BREAKING** для закладок: отдельная страница настроек темы `.../themes/{tenantId}/settings` перестаёт
  существовать как самостоятельный экран и перенаправляет в раздел «Темы» настроек дизайн-системы. Пункты меню
  карточки «Настройки», «Переименовать» и «Удалить» ведут туда же.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `token-screens-workspace`: шапка редактора получает переключатель тем, экраны токенов адресуют токен через
  `tokenId`.
- `theme-lifecycle`: добавляется дублирование темы через API; форма создания темы предлагает копию существующей
  темы.
- `web-design-system-workflow`: настройки дизайн-системы получают раздел «Темы» и открываются из редактора;
  меню карточки темы получает «Дублировать» и ведёт в раздел «Темы».

## Impact

- **backend-kt / ds-service, `feature-themes`**: новый сценарий `DuplicateTenantUseCase`, копирование палитры темы
  (`tenant_palette_*`) и значений токенов (`token_values` и редакции) в хранилищах, маршрут
  `POST /tenants/{id}/duplicates` в `TenantRoutes.kt`, описание в OpenAPI `documentation.yaml` и контрактная
  проверка. Миграции схемы не нужны: копия пишется в существующие таблицы.
- **backend-kt / identity-gateway**: новый путь проходит существующим правилом переписывания
  `/api/projects/{id}/design-systems/...`; проверить, что правило покрывает вложенный путь.
- **js / apps/client**: переключатель тем в `BuilderHierarchyBar`, `tokenId` на экранах размеров и типографики,
  диалог дублирования, режим копии в `CreateThemePage`, раздел «Темы» в `DesignSystemSettingsPage`, перенаправление
  со старого маршрута настроек темы, меню карточки темы. Клиентский API `themesApi` получает `duplicate`.
- **frontend-kt**: не затрагивается.
- **Права**: дублирование требует `tenants:write`, как создание темы; удаление по-прежнему `tenants:delete`;
  изменение общих настроек дизайн-системы по-прежнему `design-systems:write`.
