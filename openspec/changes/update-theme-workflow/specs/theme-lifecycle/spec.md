## ADDED Requirements

### Requirement: Пользователь дублирует тему

Система SHALL создавать новую тему как копию существующей темы той же дизайн-системы по
`POST /api/design-systems/{designSystemId}/tenants/{id}/duplicates`. Копия SHALL создаваться атомарно в активном
черновике и SHALL быть независимой от исходной темы после создания.

#### Scenario: Тема продублирована

- **WHEN** Editor, Maintainer или Owner отправляет запрос с телом `{ "name": "<название>" }` для темы активного
  черновика
- **THEN** API MUST создать tenant с переданным названием, описанием и `colorConfig` исходной темы
- **THEN** API MUST скопировать значения всех токенов исходной темы для всех платформ и режимов, включая
  переопределённые значения платформ и ссылки на палитру
- **THEN** API MUST скопировать палитру исходной темы: шаблон, группы, шкалы, шаги и привязки токенов к группам
  палитры, с новыми идентификаторами, принадлежащими копии
- **THEN** API MUST вернуть `201 Created` с tenant DTO копии, включая `preview`
- **THEN** чтение `GET /tenants/{newId}/token-values` MUST возвращать те же разрешённые значения, что и для
  исходной темы в момент копирования

#### Scenario: Копия независима

- **WHEN** пользователь изменяет значение токена или палитру копии
- **THEN** значения и палитра исходной темы MUST остаться без изменений
- **WHEN** пользователь изменяет исходную тему после копирования
- **THEN** копия MUST остаться без изменений

#### Scenario: Журнал черновика после дублирования

- **WHEN** тема продублирована
- **THEN** журнал черновика MUST содержать одну запись о создании темы
- **THEN** журнал MUST NOT содержать отдельных записей об изменении значений или палитры копии

#### Scenario: Название занято или пусто

- **WHEN** нормализованное название пусто
- **THEN** API MUST вернуть `400 Bad Request` и MUST NOT создавать tenant
- **WHEN** в дизайн-системе уже есть тема с таким нормализованным названием
- **THEN** API MUST вернуть ту же ошибку конфликта названия, что и при создании темы, и MUST NOT создавать tenant

#### Scenario: Исходная тема недоступна

- **WHEN** тема с `id` не принадлежит дизайн-системе, удалена в активном черновике или недоступна пользователю
- **THEN** API MUST вернуть `404 Not Found` и MUST NOT создавать tenant

#### Scenario: Нет права записи

- **WHEN** пользователь без разрешения `tenants:write` отправляет запрос дублирования
- **THEN** API MUST вернуть `403 Forbidden`

#### Scenario: Копирование не удалось

- **WHEN** хотя бы одна строка копии не может быть записана
- **THEN** API MUST откатить tenant, палитру и значения копии и вернуть ошибку без частично созданной темы

#### Scenario: Повтор запроса

- **WHEN** клиент повторяет запрос с тем же заголовком `Idempotency-Key` и тем же телом
- **THEN** API MUST вернуть ранее созданную копию и MUST NOT создавать вторую

## MODIFIED Requirements

### Requirement: Форма создания темы следует прототипу без несуществующего жизненного цикла

Веб-клиент SHALL реализовать одноэкранную форму с секциями основных параметров и внешнего вида, предварительным просмотром Light и Dark и профилями `Sber`, `Malachite`, `B2B`, `Custom`. Когда в дизайн-системе уже есть темы, форма SHALL предлагать создать тему копией существующей темы.

#### Scenario: Форма открыта

- **WHEN** Editor, Maintainer или Owner открывает создание темы в дизайн-системе без тем
- **THEN** профиль Malachite MUST быть выбран по умолчанию
- **THEN** предварительный просмотр MUST отражать выбранный профиль и выбранный режим Light или Dark

#### Scenario: Форма открыта в дизайн-системе с темами

- **WHEN** Editor, Maintainer или Owner открывает создание темы, а в дизайн-системе есть хотя бы одна тема
- **THEN** форма MUST предложить два способа: «Копия темы» и «Из профиля», и способ «Копия темы» MUST быть выбран по
  умолчанию
- **THEN** при способе «Копия темы» форма MUST показать выбор исходной темы, по умолчанию — тему из параметра адреса
  `from`, если она есть в дизайн-системе, иначе первую тему списка
- **THEN** предварительный просмотр MUST показывать `preview` выбранной исходной темы
- **THEN** поля профиля и Custom MUST быть скрыты, пока выбран способ «Копия темы»

#### Scenario: Копия создана из формы

- **WHEN** пользователь создаёт тему способом «Копия темы»
- **THEN** клиент MUST вызвать `POST /tenants/{sourceId}/duplicates` с введённым названием
- **THEN** клиент MUST открыть созданную копию в редакторе

#### Scenario: Выбран Custom

- **WHEN** пользователь выбирает профиль Custom
- **THEN** клиент MUST показать пресеты Neutral, Brand и Warm и четыре обязательных поля HEX
- **THEN** невалидный HEX MUST блокировать создание и иметь текстовую ошибку

#### Scenario: Создание выполнено

- **WHEN** API успешно создаёт tenant и начальные значения
- **THEN** клиент MUST открыть созданную тему в редакторе по `projectId`, `designSystemId` и `tenantId`
- **THEN** клиент MUST NOT показывать создание Draft или версии `0.1.0` темы

#### Scenario: Viewer открывает создание напрямую

- **WHEN** Viewer открывает маршрут создания темы
- **THEN** клиент MUST показать состояние отсутствия доступа
- **THEN** клиент MUST NOT отправлять запрос создания
