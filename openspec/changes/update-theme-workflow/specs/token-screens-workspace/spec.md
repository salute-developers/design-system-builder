## ADDED Requirements

### Requirement: Переключатель тем в шапке редактора

Крошка «Тема» в шапке редактора SHALL открывать список тем дизайн-системы и SHALL переключать редактор на выбранную
тему без перехода на обзор дизайн-системы.

#### Scenario: Список тем открыт

- **WHEN** пользователь нажимает крошку с названием текущей темы
- **THEN** клиент MUST показать список всех тем дизайн-системы с названием и цветовым превью каждой
- **THEN** текущая тема MUST быть отмечена в списке
- **THEN** в активном черновике список MUST строиться из того же кэша `themes:${projectId}:${designSystemId}`, что и
  обзор дизайн-системы

#### Scenario: Открыта опубликованная версия

- **WHEN** адрес редактора содержит `versionId` опубликованной версии
- **THEN** клиент MUST читать список тем с этим `versionId`, то есть на границе выбранной версии, и MUST хранить его
  под отдельным ключом кэша `themes:${projectId}:${designSystemId}:${versionId}`
- **THEN** список MUST NOT показывать темы, созданные после публикации, и MUST показывать темы версии, удалённые
  позже в черновике

#### Scenario: Тем много

- **WHEN** в дизайн-системе больше семи тем
- **THEN** заголовок списка MUST содержать кнопку «Поиск», как шапка дерева токенов; поле поиска MUST NOT
  показываться, пока её не нажали
- **WHEN** пользователь нажимает «Поиск»
- **THEN** поле поиска по названию MUST встать на место заголовка и получить фокус, а кнопка MUST смениться на
  «Закрыть поиск», которая очищает строку и скрывает поле
- **THEN** Escape в поле поиска MUST закрывать поиск, а следующий Escape — список
- **THEN** список MUST прокручиваться внутри всплывающей панели, не увеличивая шапку

#### Scenario: Тема выбрана

- **WHEN** пользователь выбирает в списке другую тему
- **THEN** клиент MUST перейти на маршрут той же секции с `tenantId` выбранной темы
- **THEN** клиент MUST сохранить параметр `versionId`, если он был в адресе
- **THEN** на экранах цветов, размеров и типографики клиент MUST передать в адрес `tokenId` выбранного токена, чтобы в
  новой теме был выбран тот же токен
- **THEN** при переходе MUST выполняться требование `tenant-aware-theme-editor` о переключении тем: незавершённые
  сохранения прежней темы не теряются, устаревшие ответы игнорируются

#### Scenario: Управление с клавиатуры

- **WHEN** список открыт
- **THEN** стрелки MUST перемещать выделение по темам, Enter MUST выбирать тему, Escape MUST закрывать список и
  возвращать фокус на крошку
- **THEN** Tab MUST переходить между кнопкой поиска, полем поиска и «Создать тему» внутри панели, а Enter на них MUST
  выполнять их действие, а не выбирать тему
- **THEN** Tab за край панели MUST закрывать список и возвращать фокус на крошку, а Tab с самой крошки MUST закрывать
  список и переводить фокус дальше по странице
- **WHEN** пользователь повторно нажимает крошку при открытом списке
- **THEN** список MUST закрыться

#### Scenario: В дизайн-системе одна тема

- **WHEN** в дизайн-системе только текущая тема
- **THEN** список MUST показать её и действие «Создать тему» пользователю с разрешением `tenants:write`

### Requirement: Экраны токенов открывают токен по адресу

Экраны цветов, размеров и типографики SHALL выбирать токен по параметру `tokenId` адреса, где `tokenId` —
идентификатор общего определения токена дизайн-системы.

#### Scenario: Адрес содержит существующий токен

- **WHEN** экран токенов открыт с `tokenId` определения, которое есть на этом экране
- **THEN** экран MUST выбрать этот токен, раскрыть его группу в дереве и прокрутить дерево к нему

#### Scenario: Пользователь выбирает другой токен

- **WHEN** пользователь выбирает токен в дереве
- **THEN** экран MUST заменить `tokenId` в адресе без новой записи истории браузера

### Requirement: Значения токена в других темах

Инспектор токена на экранах цветов, размеров и типографики SHALL содержать сворачиваемый блок «В других темах» со
значениями выбранного токена во всех остальных темах дизайн-системы на выбранной границе версии.

#### Scenario: Блок свёрнут по умолчанию

- **WHEN** пользователь выбирает токен
- **THEN** блок «В других темах» MUST быть свёрнут и показывать в заголовке число других тем
- **THEN** клиент MUST NOT запрашивать значения других тем, пока блок свёрнут
- **WHEN** пользователь раскрывает блок
- **THEN** клиент MUST запросить значения одним вызовом `GET /token-values?tokenIds=…` с `versionId` выбранной версии
- **THEN** состояние раскрытия MUST сохраняться при выборе другого токена и после перезагрузки страницы

#### Scenario: Строки блока

- **WHEN** значения загружены
- **THEN** блок MUST показать по строке на каждую другую тему с её названием и значениями токена: для цвета — Light
  и Dark с образцом и HEX, для градиента — образец и тип с углом («Линейный · 45°») с полной подписью в подсказке,
  для размера — значение в px, для типографики — размер, высота строки и вес открытого таба
- **THEN** строки MUST NOT содержать отдельной отметки отличия от текущей темы: разница видна по самим значениям
- **THEN** значения MUST быть только для чтения
- **THEN** блок MUST показывать основное значение веба; свои значения платформ и подтем в блок не входят

#### Scenario: Тем много

- **WHEN** других тем больше семи
- **THEN** заголовок раскрытого блока MUST содержать кнопку «Поиск»; поле поиска по названию темы MUST появляться
  только после её нажатия и закрываться «Закрыть поиск» так же, как в переключателе тем
- **THEN** блок MUST прокручиваться внутри инспектора

#### Scenario: Переход в тему из блока

- **WHEN** пользователь нажимает строку темы
- **THEN** клиент MUST открыть эту тему на том же разделе и токене тем же переходом, что и переключатель тем в шапке

#### Scenario: Ошибка загрузки

- **WHEN** запрос значений других тем завершился ошибкой
- **THEN** блок MUST показать текст ошибки и действие «Повторить», остальной инспектор MUST работать

#### Scenario: Других тем нет

- **WHEN** в дизайн-системе только текущая тема
- **THEN** клиент MUST NOT показывать блок «В других темах»

### Requirement: Начертания типографики — самостоятельные токены

Токены начертаний стиля типографики (`-normal`, `-medium`, `-bold`) SHALL показываться самостоятельными токенами в
дереве и на борде предпросмотра. Размер, высота строки, трекинг и шрифт SHALL оставаться общими для стиля, а вес SHALL
задаваться у каждого начертания.

#### Scenario: Начертания в дереве и на борде

- **WHEN** экран типографики показывает стиль
- **THEN** дерево MUST показать по строке на каждое начертание: «M Regular», «M Medium», «M Bold» со значением
  «размер/высота строки · вес»
- **THEN** борд MUST показать по карточке на каждое начертание с его весом и образцом этим весом
- **THEN** переименование и удаление MUST относиться ко всему стилю; кнопка удаления MUST быть одна на стиль, у строки
  первого начертания

#### Scenario: Выбор начертания

- **WHEN** пользователь выбирает строку начертания в дереве или карточку на борде
- **THEN** инспектор MUST открыть это начертание: заголовок «<группа> / <размер> <начертание>», полное имя токена,
  поле веса начертания и подписанные как общие поля шрифта, размера, высоты строки и трекинга
- **THEN** инспектор MUST NOT содержать отдельного переключателя начертаний
- **THEN** экран MUST записать в адрес `tokenId` токена начертания без новой записи истории браузера
- **WHEN** экран открыт с `tokenId` токена начертания
- **THEN** экран MUST выбрать стиль и начертание
- **WHEN** пользователь переключает тему переключателем в шапке или из блока «В других темах»
- **THEN** в новой теме MUST быть открыт тот же стиль и то же начертание

### Requirement: Имя нового стиля типографики без начертания

Имя нового стиля типографики SHALL NOT заканчиваться названием начертания, потому что каждый стиль всегда создаёт три
начертания.

#### Scenario: Имя заканчивается начертанием

- **WHEN** пользователь вводит имя, которое после нормализации заканчивается на `normal`, `regular`, `medium` или
  `bold`, например «M normal»
- **THEN** клиент MUST показать ошибку «Начертание указывать не нужно: у стиля всегда есть Regular, Medium и Bold.» и
  MUST NOT отправлять запрос создания

#### Scenario: Начертание внутри имени

- **WHEN** название начертания стоит не в конце имени, например «bold-title»
- **THEN** клиент MUST создать стиль как обычно

### Requirement: Отключение токена

Экраны цветов, размеров и типографики SHALL показывать, что токен отключён (`enabled = false` у определения), и SHALL
давать отключить и включить токен переключателем в инспекторе. Отключённый токен не попадает в пакет темы и в экспорт
в Figma, и это действует во всех темах дизайн-системы, потому что признак принадлежит определению токена.

#### Scenario: Отключённый токен в дереве

- **WHEN** у токена экрана признак `enabled` равен `false`
- **THEN** строка дерева MUST быть приглушённой и MUST показывать иконку перечёркнутого глаза с доступным именем
  «Отключён»
- **THEN** при наведении на строку иконка MUST уступать место действиям строки, как значение строки
- **THEN** токен MUST оставаться доступным для выбора и правки значений

#### Scenario: Фильтр отключённых токенов

- **WHEN** пользователь нажимает в шапке дерева кнопку «Скрыть отключённые токены»
- **THEN** дерево MUST NOT показывать отключённые токены, а кнопка MUST быть нажатой (`aria-pressed`)
- **THEN** состояние фильтра MUST быть общим для трёх экранов и MUST сохраняться после перезагрузки страницы

#### Scenario: Состав отключаемого токена

- **WHEN** пользователь отключает или включает токен
- **THEN** на экране цветов клиент MUST изменить признак у всех определений семейства: режимы, подтемы и состояния
  `-hover`, `-active`, `-brightness`
- **THEN** на экране размеров клиент MUST изменить признак у одного токена размера, радиуса или тени
- **THEN** на экране типографики клиент MUST изменить признак у токена начертания на всех экранах (`screen-s`,
  `screen-m`, `screen-l`): отметка и фильтр относятся к строке этого начертания
- **THEN** каждое определение MUST меняться запросом `PATCH /tokens/{id}` с телом `{ "enabled": <значение> }`

#### Scenario: Переключатель в инспекторе

- **WHEN** пользователь с правом правки открывает токен
- **THEN** шапка инспектора MUST содержать переключатель-глаз для обоих состояний: открытый глаз «Отключить токен» у
  включённого токена и перечёркнутый глаз «Включить токен» (`aria-pressed`) у отключённого, без отдельного сообщения
  и отдельной кнопки
- **WHEN** токен не используется в компонентах дизайн-системы и пользователь его отключает
- **THEN** клиент MUST отключить токен без подтверждения
- **WHEN** токен используется в компонентах
- **THEN** клиент MUST показать подтверждение со списком компонентов и предупреждением, что после публикации токена не
  будет в пакете ни в одной теме, и MUST отключить токен только после подтверждения
- **WHEN** экран не знает полного списка использований, как экран цветов, где загружены не все конфигурации
  компонентов
- **THEN** клиент MUST всегда спрашивать подтверждение с предупреждением, что токен может использоваться в компонентах
- **THEN** включение MUST выполняться без подтверждения

#### Scenario: Ошибка изменения

- **WHEN** хотя бы один запрос изменения признака завершился ошибкой
- **THEN** клиент MUST показать сообщение об ошибке в инспекторе и действие «Повторить», которое повторяет изменение для
  всех определений токена
- **THEN** если часть определений уже сохранилась, клиент MUST перечитать раздел, чтобы дерево и инспектор показывали
  фактически сохранённые признаки

#### Scenario: Режим просмотра

- **WHEN** открыта опубликованная версия или у пользователя нет права правки
- **THEN** отключённый токен MUST быть отмечен иконкой в дереве и в шапке инспектора, а переключатель MUST NOT
  показываться

#### Scenario: Созданный токен попадает в адрес

- **WHEN** пользователь создаёт токен цвета или размера
- **THEN** экран MUST записать `tokenId` созданного токена в адрес, как при выборе, чтобы переключатель тем открыл его же

### Requirement: Платформа предпросмотра редактора токенов

Экраны цветов, размеров и типографики SHALL иметь один переключатель платформы Web, iOS и Android в шапке
предпросмотра, как в редакторе компонентов, вместо строк своих значений платформ под каждым полем инспектора.

#### Scenario: Выбор платформы

- **WHEN** пользователь выбирает платформу в меню «Платформа» шапки предпросмотра
- **THEN** борд MUST показать значения этой платформы: своё значение iOS или Android, иначе значение, построенное из Web
- **THEN** выбор MUST быть общим для трёх экранов и MUST сохраняться при переходе между ними и после перезагрузки

#### Scenario: Поля инспектора на платформе

- **WHEN** выбрана платформа Web
- **THEN** поля инспектора MUST показывать и править значения Web без кнопок своего значения платформы
- **WHEN** выбрана iOS или Android и у поля нет своего значения платформы
- **THEN** поле MUST показывать значение Web без возможности правки и кнопку «+», которая делает значение своим для
  выбранной платформы
- **WHEN** у поля есть своё значение выбранной платформы
- **THEN** поле MUST показывать и править его, а кнопка «×» MUST возвращать поле к значению Web

## MODIFIED Requirements

### Requirement: Дерево токенов

Дерево слева SHALL одинаково выглядеть на трёх экранах: шапка `Sidebar/CatalogHeader`, строки `Builder/ListItem`,
иконки `@salutejs/sdds-icons`. Содержимое группы и подгруппы SHALL быть сдвинуто вправо относительно её заголовка;
это осознанное отступление от Figma, где строки группы стоят на одной линии с её заголовком.

#### Scenario: Шапка и строки

- **WHEN** открыто дерево
- **THEN** шапка MUST быть высотой 40 px с горизонтальным отступом 12 px и без нижней линии
- **THEN** строки токенов и групп MUST быть высотой 32 px, а их подписи — 12/14
- **THEN** стрелка группы MUST быть иконкой 16 px, а не текстовым символом

#### Scenario: Выбранная строка

- **WHEN** токен выбран
- **THEN** его строка MUST иметь нейтральную подложку `rgba(255,255,255,0.1)` со скруглением 6 px и отступом 8 px
  от краёв панели на всех трёх экранах

#### Scenario: Вложенность

- **WHEN** дерево показывает группу с токенами и подгруппами
- **THEN** токены группы и заголовки её подгрупп MUST начинаться на шаг 16 px правее стрелки заголовка группы
- **THEN** токены подгруппы MUST начинаться ещё на шаг 16 px правее стрелки заголовка подгруппы
- **THEN** подложка выбранной строки MUST сохранять отступ 8 px от краёв панели на любом уровне вложенности

### Requirement: Поиск в дереве

Поиск SHALL работать одинаково на трёх экранах, на палитре, в переключателе тем и в блоке «В других темах»: все они
используют одну шапку поиска.

#### Scenario: Открытие поиска

- **WHEN** пользователь нажимает кнопку поиска
- **THEN** поле поиска MUST появиться в шапке дерева вместо её заголовка или сортировки, с иконкой поиска и
  кнопкой «Закрыть поиск»
- **THEN** ввод в поле MUST NOT менять выбранный токен

#### Scenario: Закрытие поиска

- **WHEN** пользователь нажимает «Закрыть поиск» или Escape в поле поиска
- **THEN** строка поиска MUST очиститься, а шапка MUST вернуть заголовок или сортировку
- **THEN** Escape MUST закрывать только поиск, не затрагивая панель или список вокруг шапки

#### Scenario: Пустой результат

- **WHEN** поиск не нашёл токенов
- **THEN** под шапкой MUST показываться текст «По вашему запросу ничего не найдено» 12/16 цветом `#9e9fa2` по
  центру панели, без заголовков групп и разделов
