## ADDED Requirements

### Requirement: Значения выбранных токенов во всех темах дизайн-системы

Чтение `GET /api/design-systems/{designSystemId}/token-values` SHALL принимать необязательный параметр
`tokenIds=<id>[,<id>…]` и с ним SHALL возвращать значения только этих токенов во всех темах дизайн-системы одним
запросом. Без параметра ответ SHALL оставаться прежним.

#### Scenario: Значения прочитаны по токенам

- **WHEN** пользователь с разрешением `tokens:read` запрашивает от одного до двадцати `tokenIds`
- **THEN** API MUST вернуть `200 OK` со списком значений этих токенов во всех темах дизайн-системы в форме элемента
  ответа без `tokenIds`, где у каждого значения есть `tenantId`
- **THEN** цветовые значения со ссылкой на палитру MUST быть разрешены по палитре своей темы, как без `tokenIds`

#### Scenario: Граница версии

- **WHEN** запрос содержит `versionId` опубликованной версии
- **THEN** API MUST вернуть значения, действовавшие на границе этой версии

#### Scenario: Некорректный список токенов

- **WHEN** `tokenIds` содержит не идентификатор или больше двадцати идентификаторов
- **THEN** API MUST вернуть `400 Bad Request` с кодом `invalid_token_ids`

#### Scenario: Запрос без параметра

- **WHEN** клиент запрашивает `GET /token-values` без `tokenIds`
- **THEN** API MUST вернуть значения всех токенов, как до появления параметра
