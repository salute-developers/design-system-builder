## ADDED Requirements

### Requirement: Значения токенов по всем темам дизайн-системы

Система SHALL возвращать значения выбранных токенов во всех темах дизайн-системы одним запросом
`GET /api/design-systems/{designSystemId}/token-values?tokenIds=<id>[,<id>…]` с необязательным `versionId`.

#### Scenario: Значения прочитаны

- **WHEN** пользователь с разрешением `tenants:read` запрашивает от одного до двадцати `tokenIds` дизайн-системы
- **THEN** API MUST вернуть `200 OK` со списком `{ tenantId, tenantName, values }` по всем темам дизайн-системы,
  отсортированным по названию темы
- **THEN** каждый элемент `values` MUST иметь ту же форму, что элемент ответа `GET /tenants/{id}/token-values`, и
  содержать только значения запрошенных токенов
- **THEN** цветовые значения со ссылкой на палитру MUST быть разрешены по палитре и группе токена своей темы, как в
  `GET /tenants/{id}/token-values`

#### Scenario: Граница версии

- **WHEN** запрос содержит `versionId` опубликованной версии
- **THEN** API MUST вернуть темы и значения, действовавшие на границе этой версии
- **WHEN** `versionId` нет
- **THEN** API MUST вернуть темы и значения активного черновика без удалённых в нём тем

#### Scenario: Некорректный список токенов

- **WHEN** `tokenIds` пуст, содержит больше двадцати идентификаторов или идентификатор токена другой дизайн-системы
- **THEN** API MUST вернуть `400 Bad Request`

#### Scenario: Нет права чтения

- **WHEN** пользователь без разрешения `tenants:read` отправляет запрос
- **THEN** API MUST вернуть `403 Forbidden`
