## MODIFIED Requirements

### Requirement: Удаление цветового токена

`ds-service` SHALL сохранять существующую операцию удаления семейства цветового токена с прежними
правами и атомарным обновлением зависимостей. Логическое удаление SHALL выражаться редакциями
определений, значений и привязок, без уничтожения данных опубликованных версий.

#### Scenario: Успешное удаление

- **WHEN** Maintainer удаляет существующее семейство токена из активного черновика
- **THEN** семейство, его значения и привязки MUST исчезнуть из активного чтения атомарно
- **THEN** опубликованные версии MUST сохранять прежние определения, значения и привязки
- **THEN** отмена MUST оставаться доступной по существующей ручке с проверкой зависимостей

#### Scenario: Editor удаляет токен

- **WHEN** пользователь с ролью Editor удаляет токен
- **THEN** API MUST вернуть `403` и MUST NOT удалять данные

### Requirement: Общая ревизия темы в операциях токена

Операции над цветовым токеном SHALL использовать предметные редакции механизма многопользовательского
редактирования ДС вместо общего счётчика темы. Заголовки, ключ повторяемости и технические метаданные
SHALL быть согласованы с другими мутациями ДС. Устаревший счётчик темы SHALL NOT приводить к отказу
при независимом изменении другого токена.

#### Scenario: Устаревшая ревизия

- **WHEN** клиент изменяет токен с базовой предметной редакцией, после которой изменили тот же параметр
- **THEN** сервер MUST выполнить согласованное правило конкурентной записи и вернуть метаданные
- **THEN** он MUST NOT перезаписать соседние параметры или платформы, отсутствующие в изменении

#### Scenario: Ошибка внутри операции

- **WHEN** любая проверка или запись операции завершилась ошибкой
- **THEN** API MUST NOT сохранять ни определения, ни значения, ни привязки, ни удаления
- **THEN** предметные редакции и ключ повторяемости MUST NOT фиксировать частичный результат
