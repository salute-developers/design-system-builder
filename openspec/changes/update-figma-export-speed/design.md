## Контекст

Замеры: dev — `token-values?types=color,gradient` 2,4 с, `palette` 1,7–2 с; локально — 0,2 и 0,1 с при одной дизайн-системе. `EXPLAIN ANALYZE` основного запроса значений локально: полный проход `token_value_revisions` всех дизайн-систем с коррелированным поиском последней ревизии на каждую строку, 35 мс; тот же запрос с фильтром ревизий по дизайн-системе через `DISTINCT ON` — 6 мс. Ответ `token-values` — 2,35 МБ, по трети на платформу, gzip нет.

## Решения

- **Сжатие в gateway** — по решению архивного изменения `speed-up-component-preview-loading`: `gzip` только в `location` маршрутов `ds`, только `application/json`, от 1 КБ, `gzip_proxied any`, `gzip_vary on`. Поток `text/event-stream` не сжимается: его тип не входит в `gzip_types`.
- **Фильтр платформ после чтения, до публикации.** Значения отбираются в сценарии чтения по платформе, поэтому публикатор и сериализация обрабатывают только нужное. Сам SQL фильтр не сужает: он уже ограничен темой и типами, а выигрыш даёт объём ответа.
- **Дизайн-система в снимке палитры.** `colorValues` и `layerValues` передают `designSystemId` темы: иначе последующая проверка активных токенов и тем читает все темы базы. Запрос значений с известной дизайн-системой фильтрует и ревизии по ней — планировщик начинает обход с индекса дизайн-системы.
- **Индексы V18** без `CONCURRENTLY`: Flyway выполняет миграцию в транзакции; таблицы значений на стендах — десятки тысяч строк, блокировка записи на время построения короткая.
- **Запись только изменившегося в плагине.** Значение режима сравнивается с `valuesByMode` с допуском 1e-4 на каналы цвета (Figma хранит их во float32); имя, области применения и дизайн-система переменной пишутся только при отличии. Стили пишутся всегда: их мало, а форма прочитанных заливок и эффектов отличается от записываемой.
