# ИИ-чат в билдере

## Зачем

Сейчас дизайн-систему можно менять только вручную в редакторах билдера или через свой агент, подключённый к MCP. Чтобы подключить агента, нужно установить CLI, войти через PKCE и настроить клиент. Встроенный чат даёт ту же возможность прямо в интерфейсе: пользователь пишет «перекрась кнопку в красный», а изменение появляется в черновике. Инструменты редактирования в MCP уже есть (change `add-mcp-design-system-editor`), поэтому чат строится поверх них и не требует второй реализации операций.

## Что изменится

- В монолите `backend-kt/app` появится подсистема ИИ-ассистента с публичным маршрутом `/api/projects/{projectId}/ai/chat`. Подсистема запускает цикл агента: отправляет модели запрос и описания инструментов, выполняет запрошенные инструменты и возвращает ответ.
- Реестр инструментов берётся из `DsBuilderMcpServerCore` (`frontend-kt/mcp-server-core`): методы `tools()` и `callTool()` вызываются внутри процесса, без транспорта MCP. Инструменты обращаются к API от имени пользователя, токен которого пришёл в запросе чата.
- Появится слой `LlmClient`, не зависящий от провайдера, с собственной моделью сообщений. В нём два адаптера:
  - `OpenAiCompatibleClient` — для провайдеров с API формата OpenAI (ZAI и другие); провайдер выбирается настройками;
  - `GigaChatClient` — OAuth, формат `functions`/`function_call`, один вызов инструмента за ответ.
- Модели доступен только отобранный набор инструментов. Служебные поля мутаций и выбор дизайн-системы подставляет сервер. Удаляющие операции выполняются только после подтверждения пользователя в интерфейсе.
- Ход работы агента передаётся клиенту по SSE. Клиент перерисовывается через уже существующий поток изменений черновика, а отменить сделанное можно через существующий откат по журналу.
- В `js/apps/client` появится панель чата в рабочей области дизайн-системы.
- Появится набор эталонных сценариев, по которому проверяется, справляется ли модель с нашими инструментами.
- Добавится ADR о встраивании MCP-ядра в серверный процесс. Он дополняет ADR-0004: удалённый MCP-сервер по-прежнему не делается.

## Возможности

### Новые возможности

- `builder-ai-chat` — HTTP-контракт чата: сессия разговора, поток событий, подтверждение опасных операций, права и ошибки.
- `ai-agent-tooling` — цикл агента поверх MCP-ядра: отбор инструментов, сокрытие служебных полей, подстановка контекста, ограничения на число шагов.
- `llm-provider-adapters` — слой `LlmClient`, нейтральная модель сообщений, адаптеры OpenAI-совместимого API и GigaChat, их настройка.
- `web-ai-chat-panel` — панель чата в веб-клиенте: ход работы агента, подтверждения, отмена, обновление интерфейса.

### Изменённые возможности

- `frontend-mcp-server` — ядро MCP становится пригодным для встраивания в сервер: учётные данные берутся из контекста вызова, а не только из локального хранилища, и вызов работает без локального рабочего каталога.
- `backend-monolith-runtime` — монолит подключает подсистему ИИ-ассистента с публичным префиксом `/api/projects/{projectId}/ai` и выключателем `AI_ENABLED`.

## Влияние

- **backend-kt.** Новая сборка `backend-kt/ai-assistant` (`runtime` и `feature-chat`) подключается в `backend-kt/app` через composite build. Публичная граница пополняется префиксом `/ai`. В `app/Dockerfile` добавляется копирование `frontend-kt`, нужное для сборки MCP-ядра. OpenAPI — `ai-assistant/runtime/src/main/resources/openapi/documentation.yaml`. Новые переменные окружения: `AI_ENABLED`, `AI_PROVIDER`, `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, `AI_EXTRA_BODY`, `AI_RETRY_ERROR_CODES`, `AI_GIGACHAT_AUTH_KEY`, `AI_GIGACHAT_SCOPE`, `AI_GIGACHAT_CA_PATH`, `AI_MAX_STEPS`, `AI_TURN_TIMEOUT_SECONDS`, `AI_HISTORY_MAX_CHARS`. Их нужно прописать в `docker-compose.prod.yml` и `backend-kt/docker-compose.local.yml`. Отдельного контейнера, порта или проверки готовности нет: подсистема работает в процессе `backend` и использует его `/ready`.
- **frontend-kt.** `core-application` получает реализацию `CredentialProvider`, которая читает токен из контекста корутины. `mcp-server-core` получает публичное описание служебных полей инструментов. JVM-артефакт `mcp-server-core` начинает использоваться из `backend-kt`. Поведение CLI и `dsbuilder-mcp` не меняется.
- **js.** `js/apps/client`: панель и API-клиент чата, флаг `VITE_AI_CHAT_ENABLED` для dev и prom deploy workflow. Работа с ZAI из браузера и vite-прокси не используются.
- **Внешние сервисы.** API выбранного провайдера модели; ключи хранятся только в env монолита. Для GigaChat нужен корневой сертификат НУЦ Минцифры.
- **Данные.** Новых таблиц и миграций нет. История разговора хранится на клиенте и передаётся в каждом запросе. Изменения дизайн-системы попадают в существующий журнал от имени пользователя.

## Вне целей

- Удалённый MCP-сервер по HTTP/SSE для внешних агентов.
- Хранение истории разговоров на сервере, общие чаты и учёт расхода токенов по проектам.
- Изменение общего каталога компонентов, публикация версий и управление участниками проекта из чата.
- Перенос клиентского чата из локальной ветки `AI-CHAT`.
