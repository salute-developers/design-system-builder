## ADDED Requirements

### Requirement: Инструменты агента из ядра MCP

Подсистема ИИ-ассистента SHALL получать описания и выполнение инструментов только из `DsBuilderMcpServerCore` через `tools()`, `callTool()` и публичную функцию схемы `inputJsonSchema`. Подсистема MUST NOT содержать собственных реализаций операций над DS и собственного перевода описаний инструментов в JSON Schema.

#### Scenario: Описание инструмента для модели
- **WHEN** агент готовит запрос к модели
- **THEN** имя, описание и схема каждого инструмента MUST строиться из `McpToolDefinition` и `inputJsonSchema`, включая поля `type = "json"` и `nullable`

#### Scenario: Новое поле инструмента в ядре
- **WHEN** в ядре у разрешённого инструмента появляется новое поле
- **THEN** оно MUST попасть в схему для модели без изменения кода подсистемы

### Requirement: Отобранный набор инструментов

Агенту SHALL быть доступны только инструменты из списка `ChatToolPolicy`. Каждый инструмент MUST передаваться модели, только если `PolicyEvaluator` разрешает пользователю его точное разрешение. Инструменты с `destructive = true` из этого списка MUST требовать подтверждения. Инструменты вне списка MUST отклоняться без вызова ядра.

#### Scenario: Модель запросила инструмент вне списка
- **WHEN** модель вернула вызов `token_delete`
- **THEN** агент MUST NOT вызывать ядро и MUST вернуть модели результат с `isError: true` и кодом `tool_not_allowed`

#### Scenario: Отбор по точному разрешению
- **WHEN** `PolicyEvaluator` разрешает пользователю `components:variations:write`, но не `components:variations:delete`
- **THEN** `component_property_set` MUST передаваться модели, а `component_property_reset` MUST NOT передаваться и MUST отклоняться при прямом вызове

#### Scenario: Поиск по документации недоступен
- **WHEN** модель запрашивает `documentation_search`
- **THEN** агент MUST отклонить вызов с `tool_not_allowed`, пока поиск не проверяет принадлежность публикации к DS чата

### Requirement: Поля, заполняемые сервером

Поля `designSystem`, `version` и `idempotencyKey` SHALL отсутствовать в `properties` и `required` схемы для модели. Агент MUST подставлять каждое из них только тем инструментам, в схеме которых это поле есть: `designSystem` — ссылкой на DS запроса и черновик, `version` — значением `draft`, `idempotencyKey` — новым ключом на каждый вызов записи. Значения этих полей, присланные моделью, MUST заменяться.

#### Scenario: Модель указала другую дизайн-систему
- **WHEN** аргументы модели содержат `designSystem` с другой ссылкой
- **THEN** агент MUST вызвать ядро со ссылкой на DS запроса

#### Scenario: Инструмент без поля версии
- **WHEN** схема инструмента не содержит `version`
- **THEN** агент MUST NOT добавлять `version` в аргументы, и закрытая схема MUST NOT отклонять вызов

#### Scenario: Конфликт ревизии
- **WHEN** запись отклонена из-за устаревшей ревизии
- **THEN** агент MUST вернуть ошибку модели без автоматического повтора
- **THEN** новый вызов модели после перечитывания MUST получить новый `idempotencyKey`

### Requirement: Последовательное выполнение вызовов

Агент SHALL выполнять вызовы инструментов по одному в порядке ответа модели. Если ответ содержит вызов, требующий подтверждения, вызовы до него MUST выполняться, а он и последующие MUST NOT выполняться до решения пользователя.

#### Scenario: Несколько вызовов в одном ответе
- **WHEN** модель вернула три вызова, второй из которых требует подтверждения
- **THEN** агент MUST выполнить первый вызов, отправить `confirmation_required` для второго и MUST NOT выполнять третий
- **THEN** `state` MUST содержать только выполненный вызов и ожидающий подтверждения

### Requirement: Ограничение истории для модели

Перед каждым обращением к модели агент SHALL укладывать историю в `AI_HISTORY_MAX_CHARS`. Сначала сокращается текст старых результатов инструментов, затем старые реплики. Сообщение с результатом инструмента MUST NOT удаляться при сокращении: его текст заменяется пометкой о сокращении. Системный промпт и последнее сообщение пользователя MUST NOT сокращаться.

#### Scenario: Длинный разговор
- **WHEN** история превышает лимит
- **THEN** модель MUST получить историю не длиннее лимита с последним сообщением пользователя без изменений
- **THEN** у каждого вызова инструмента в истории MUST оставаться сообщение с его результатом

### Requirement: Эталонные сценарии

Подсистема SHALL содержать набор эталонных сценариев и задачу Gradle, которая прогоняет их против настроенного провайдера и локального контура и сообщает результат по каждому сценарию.

#### Scenario: Проверка новой модели
- **WHEN** разработчик меняет `AI_MODEL` и запускает задачу проверки
- **THEN** задача MUST вывести для каждого сценария «прошёл» или «не прошёл» и причину
- **THEN** сценарии MUST включать изменение цвета свойства компонента, изменение значения размера, вопрос без изменений и сброс свойства от maintainer с ожиданием подтверждения

#### Scenario: Нет ключа или контура
- **WHEN** задача запущена без ключа провайдера или без доступного локального контура
- **THEN** задача MUST завершиться ошибкой, а не пропуском сценариев
