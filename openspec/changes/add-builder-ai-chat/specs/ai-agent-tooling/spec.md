## ADDED Requirements

### Requirement: Инструменты агента из ядра MCP

Подсистема ИИ-ассистента SHALL получать описания и выполнение инструментов только из `DsBuilderMcpServerCore` через `tools()` и `callTool()`. Подсистема MUST NOT содержать собственных реализаций операций над DS.

#### Scenario: Описание инструмента для модели
- **WHEN** агент готовит запрос к модели
- **THEN** имя, описание и схема каждого инструмента MUST строиться из `McpToolDefinition`, без ручного дублирования

#### Scenario: Новое поле инструмента в ядре
- **WHEN** в ядре у разрешённого инструмента появляется новое поле
- **THEN** оно MUST попасть в схему для модели без изменения кода подсистемы

### Requirement: Отобранный набор инструментов

Агенту SHALL быть доступны только инструменты из списка `ChatToolPolicy`. Инструменты с `destructive = true` из этого списка MUST требовать подтверждения. Инструменты вне списка MUST отклоняться без вызова ядра.

#### Scenario: Модель запросила инструмент вне списка
- **WHEN** модель вернула вызов `token_delete`
- **THEN** агент MUST NOT вызывать ядро и MUST вернуть модели результат с `isError: true` и кодом `tool_not_allowed`

#### Scenario: Отбор по правам
- **WHEN** в проверенном контексте нет `components:write`
- **THEN** инструменты записи компонентов MUST NOT передаваться модели и MUST отклоняться при прямом вызове

### Requirement: Поля, заполняемые сервером

Поля `designSystem`, `version` и `idempotencyKey` SHALL отсутствовать в схеме для модели. Агент MUST подставлять `designSystem` ссылкой на DS запроса и черновик, `version = draft` и новый `idempotencyKey` на каждый вызов записи. Значения этих полей, присланные моделью, MUST заменяться.

#### Scenario: Модель указала другую дизайн-систему
- **WHEN** аргументы модели содержат `designSystem` с другой ссылкой
- **THEN** агент MUST вызвать ядро со ссылкой на DS запроса

#### Scenario: Конфликт ревизии
- **WHEN** запись отклонена из-за устаревшей ревизии
- **THEN** агент MUST вернуть ошибку модели без автоматического повтора
- **THEN** новый вызов модели после перечитывания MUST получить новый `idempotencyKey`

### Requirement: Последовательное выполнение вызовов

Агент SHALL выполнять вызовы инструментов по одному в порядке ответа модели. Если ответ содержит вызов, требующий подтверждения, вызовы до него MUST выполняться, а он и последующие MUST NOT выполняться до решения пользователя.

#### Scenario: Несколько вызовов в одном ответе
- **WHEN** модель вернула три вызова, второй из которых требует подтверждения
- **THEN** агент MUST выполнить первый вызов, отправить `confirmation_required` для второго и MUST NOT выполнять третий
- **THEN** `state` MUST содержать только выполненный вызов и ожидающий подтверждения

### Requirement: Ограничение истории для модели

Перед каждым обращением к модели агент SHALL укладывать историю в `AI_HISTORY_MAX_CHARS`. Сначала сокращаются старые результаты инструментов, затем старые реплики. Системный промпт и последнее сообщение пользователя MUST NOT сокращаться.

#### Scenario: Длинный разговор
- **WHEN** история превышает лимит
- **THEN** модель MUST получить историю не длиннее лимита с последним сообщением пользователя без изменений

### Requirement: Эталонные сценарии

Подсистема SHALL содержать набор эталонных сценариев и задачу Gradle, которая прогоняет их против настроенного провайдера и локального контура и сообщает результат по каждому сценарию.

#### Scenario: Проверка новой модели
- **WHEN** разработчик меняет `AI_MODEL` и запускает задачу проверки
- **THEN** задача MUST вывести для каждого сценария «прошёл» или «не прошёл» и причину
- **THEN** сценарии MUST включать изменение цвета свойства компонента, изменение значения размера и вопрос без изменений
