## ADDED Requirements

### Requirement: Ход чата через публичный маршрут

Монолит SHALL предоставлять `POST /api/projects/{projectId}/ai/chat`. Тело запроса MUST содержать `designSystemId` и `messages` и MAY содержать `confirmations`. Ответ SHALL быть потоком `text/event-stream` с событиями `tool_started`, `tool_result`, `confirmation_required`, `message`, `state`, `error`, `done`. Пока ход ждёт модель, сервер MUST писать комментарий `: heartbeat` не реже раза в 15 секунд. Сервер MUST NOT хранить разговор между запросами.

#### Scenario: Ответ без инструментов
- **WHEN** участник проекта отправляет вопрос, на который модель отвечает текстом
- **THEN** поток MUST содержать `message` с текстом, затем `state` с историей, дополненной ответом, затем `done`

#### Scenario: Цепочка вызовов инструментов
- **WHEN** модель последовательно запрашивает чтение и запись
- **THEN** для каждого вызова поток MUST содержать `tool_started`, затем `tool_result` с тем же `callId`, затем `state` с историей, включающей этот результат
- **THEN** последний `state` MUST содержать все выполненные вызовы и их результаты в порядке выполнения

#### Scenario: Долгий ответ модели
- **WHEN** модель отвечает дольше 15 секунд
- **THEN** поток MUST содержать `: heartbeat` до прихода следующего события

### Requirement: Проверки до открытия потока

Сервер SHALL выполнять проверки тела, длины сообщения, принадлежности DS, подтверждения и занятости пользователя до начала ответа `text/event-stream` и возвращать их ошибки обычным JSON.

#### Scenario: Неверный запрос
- **WHEN** тело не разбирается, `messages` пусто либо последняя реплика не от пользователя и нет `confirmations`
- **THEN** сервер MUST вернуть `400 invalid_request` без открытия потока

#### Scenario: Слишком длинное сообщение
- **WHEN** последнее сообщение пользователя длиннее `AI_MESSAGE_MAX_CHARS`
- **THEN** сервер MUST вернуть `400 message_too_long` до обращения к модели и без открытия потока

#### Scenario: Дизайн-система другого проекта
- **WHEN** `designSystemId` не принадлежит проекту маршрута
- **THEN** сервер MUST вернуть `404 design_system_not_found` по результату существующего адаптера принадлежности DS без открытия потока и без вызова модели

#### Scenario: Второй одновременный ход
- **WHEN** у пользователя уже идёт ход и он отправляет новый запрос
- **THEN** сервер MUST вернуть `429 ai_busy` без открытия потока

### Requirement: Подтверждение операций

Удаляющая операция и запись сверх `AI_MAX_WRITES` за ход SHALL выполняться только после явного решения пользователя по операции, которую предложил сервер. Без решения ход MUST завершаться событием `confirmation_required`, затем `state` и `done`. Сервер MUST сам формировать итоговые аргументы и `idempotencyKey` операции, читать идентификатор активного черновика и выдавать `confirmationToken`, подписанный над идентификатором ключа, пользователем, проектом, DS, черновиком, инструментом, аргументами, ключом идемпотентности и сроком действия. Подтверждённую операцию сервер MUST выполнять только по данным из токена, без опоры на присланную историю, и только в черновике из токена. Ход, запущенный подтверждением, MUST выполняться не более одного раза для одного токена. Токен MUST NOT содержать учётных данных пользователя.

#### Scenario: Пауза на подтверждение
- **WHEN** модель запрашивает `component_property_reset`
- **THEN** сервер MUST NOT вызывать инструмент
- **THEN** поток MUST содержать `confirmation_required` с `callId`, `tool`, аргументами без служебных полей, `reason: destructive`, `confirmationToken` и `expiresAt`

#### Scenario: Превышен лимит записей
- **WHEN** модель запрашивает запись после `AI_MAX_WRITES` выполненных записей в ходе
- **THEN** сервер MUST остановить ход событием `confirmation_required` с `reason: write_limit`

#### Scenario: Пользователь подтвердил
- **WHEN** следующий запрос содержит `confirmations: [{confirmationToken, approved: true}]` с действительным токеном
- **THEN** сервер MUST выполнить операцию с аргументами и `idempotencyKey` из токена и продолжить ход

#### Scenario: Публикация между выдачей токена и подтверждением
- **WHEN** после события `confirmation_required` DS опубликовали, и активным стал другой черновик
- **THEN** подтверждённая операция MUST передать ожидаемый черновик в ds-service, и запись MUST NOT выполниться
- **THEN** `tool_result` MUST содержать `isError: true` с кодом `draft_changed`, а модель и панель MUST сообщить, что операцию нужно запросить заново

#### Scenario: Повтор подтверждения во время выполнения хода
- **WHEN** клиент повторно отправляет то же подтверждение, пока ход по нему ещё идёт
- **THEN** сервер MUST вернуть `429 ai_busy` без открытия потока и без вызовов

#### Scenario: Повтор подтверждения после обрыва продолжения
- **WHEN** после подтверждённой операции агент выполнил ещё одну запись, соединение оборвалось до финального `state`, и клиент повторно отправил то же подтверждение
- **THEN** сервер MUST вернуть сохранённые события этого хода без вызова модели и инструментов
- **THEN** в ds-service MUST NOT появиться ни одной новой записи

#### Scenario: Подменённая история
- **WHEN** присланная история содержит у ожидающего вызова другие аргументы, чем в токене
- **THEN** сервер MUST выполнить операцию с аргументами из токена и MUST записать в историю именно их

#### Scenario: Чужой или изменённый токен
- **WHEN** идентификатор ключа токена известен, но подпись не сходится либо пользователь, проект или DS токена не совпадают с текущим запросом
- **THEN** сервер MUST вернуть `400 confirmation_invalid` без вызова инструмента

#### Scenario: Истёкший токен
- **WHEN** срок токена прошёл либо идентификатор ключа токена неизвестен после перезапуска монолита
- **THEN** сервер MUST вернуть `410 confirmation_expired` без вызова инструмента

#### Scenario: Пользователь отказал
- **WHEN** решение `approved: false` с действительным токеном
- **THEN** сервер MUST NOT выполнять вызов и MUST передать модели результат с `isError: true` и пояснением «пользователь отклонил операцию»

### Requirement: Права пользователя и область дизайн-системы

Каждый вызов инструмента SHALL выполняться с учётными данными пользователя из исходного запроса и только в DS из тела запроса в проекте маршрута. Набор инструментов SHALL отбираться по точному разрешению каждого инструмента через существующий `PolicyEvaluator` по принципалу из проверенного контекста.

#### Scenario: Редактор из браузера
- **WHEN** участник с ролью editor пишет в чат с JWT из браузера
- **THEN** модели MUST передаваться инструменты записи с разрешениями `tokens:write`, `tenants:write` и `components:variations:write`
- **THEN** запись в черновик MUST проходить и отображаться в журнале от имени этого пользователя
- **THEN** `component_property_reset` с разрешением `components:variations:delete` MUST NOT передаваться модели

#### Scenario: Maintainer видит сброс свойства
- **WHEN** участник с ролью maintainer пишет в чат
- **THEN** модели MUST передаваться `component_property_reset`, и его вызов MUST требовать подтверждения

#### Scenario: Пользователь без права записи
- **WHEN** участник с ролью viewer либо PAT без разрешений записи пишет в чат
- **THEN** модели MUST передаваться только инструменты чтения

#### Scenario: PAT с частью разрешений
- **WHEN** PAT имеет `tenants:write`, но не `components:variations:write`
- **THEN** модели MUST передаваться инструменты записи значений темы и MUST NOT передаваться инструменты записи компонентов

#### Scenario: Отказ ds-service
- **WHEN** ds-service отклонил вызов по правам или ревизии
- **THEN** `tool_result` MUST содержать `isError: true` и безопасные детали, а ход MUST продолжиться

#### Scenario: Учётные данные не утекают
- **WHEN** выполняется любой ход, в том числе с подтверждением
- **THEN** заголовок `Authorization` пользователя MUST NOT появляться в событиях, истории, `confirmationToken`, журналах и запросах к провайдеру модели

### Requirement: Ограничения хода

Ход SHALL ограничиваться `AI_MAX_STEPS` обращениями к модели и `AI_TURN_TIMEOUT_SECONDS`. Событие `state` MUST отправляться после каждого выполненного шага и перед `done` при любом завершении хода, кроме остановки процесса монолита.

#### Scenario: Превышен лимит шагов
- **WHEN** модель продолжает запрашивать инструменты после `AI_MAX_STEPS` обращений
- **THEN** поток MUST содержать `error` с `step_limit_reached`, затем `state` с выполненными шагами и `done`

#### Scenario: Отключение клиента во время ожидания модели
- **WHEN** клиент закрыл соединение, пока ход ждёт ответа модели
- **THEN** сервер MUST отменить ход не позже следующей записи `: heartbeat` и MUST NOT начинать новые вызовы модели и инструментов

#### Scenario: Токен истёк во время хода
- **WHEN** обратный вызов инструмента получил 401
- **THEN** поток MUST содержать `error` с `auth_expired`, затем `state` с выполненными шагами и `done`
- **THEN** сервер MUST NOT повторять вызов с тем же токеном

#### Scenario: История не помещается после сокращений
- **WHEN** после всех сокращений история хода всё равно превышает `AI_HISTORY_MAX_CHARS`
- **THEN** поток MUST содержать `error` с `context_overflow`, затем `state` с выполненными шагами и `done`, без обращения к модели с превышением лимита

#### Scenario: Провайдер недоступен
- **WHEN** провайдер не ответил после всех повторов
- **THEN** поток MUST содержать `error` с `llm_unavailable` либо `llm_rate_limited`, затем `state` и `done`

### Requirement: Состояние подсистемы

Монолит SHALL предоставлять `GET /api/projects/{projectId}/ai/status` с полями `enabled`, `provider`, `model`, `messageMaxChars`, `minTokenLifetimeSeconds`. Ответ MUST NOT содержать ключи, адреса и прочие секреты провайдера.

#### Scenario: Подсистема выключена
- **WHEN** `AI_ENABLED` не равно `true`
- **THEN** `status` MUST вернуть `{ "enabled": false }`
- **THEN** `POST /ai/chat` MUST вернуть `503 ai_unavailable`

#### Scenario: Запас срока токена
- **WHEN** подсистема включена с `AI_TURN_TIMEOUT_SECONDS=120`
- **THEN** `minTokenLifetimeSeconds` MUST быть не меньше 150
