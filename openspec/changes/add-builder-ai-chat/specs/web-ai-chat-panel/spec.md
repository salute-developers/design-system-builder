## ADDED Requirements

### Requirement: Панель чата в рабочей области дизайн-системы

Веб-клиент SHALL показывать панель чата в рабочей области открытой DS, только если `VITE_AI_CHAT_ENABLED=true` и `GET /ai/status` вернул `enabled: true`. Панель MUST предупреждать, что данные DS передаются внешнему провайдеру модели.

#### Scenario: Чат выключен на сервере
- **WHEN** `ai/status` вернул `enabled: false`
- **THEN** клиент MUST NOT показывать панель и кнопку её открытия

### Requirement: Отображение хода агента

Клиент SHALL читать поток `POST /ai/chat` через `fetch` и показывать шаги по мере поступления событий. Историю для следующего запроса клиент MUST брать только из последнего события `state`.

#### Scenario: Шаги во время выполнения
- **WHEN** приходят `tool_started` и `tool_result`
- **THEN** панель MUST показать понятное название шага и его итог до прихода `message`

#### Scenario: Ошибка хода
- **WHEN** приходит `error`
- **THEN** панель MUST показать текст ошибки и сохранить выполненные шаги из `state`

#### Scenario: Новый чат
- **WHEN** пользователь нажимает «Новый чат»
- **THEN** клиент MUST очистить историю, а следующий запрос MUST начаться с одной реплики пользователя

### Requirement: Подтверждение в интерфейсе

При событии `confirmation_required` клиент SHALL показывать описание операции с кнопками «Выполнить» и «Отклонить» и отправлять решение следующим запросом с полученной историей.

#### Scenario: Подтверждение удаления
- **WHEN** пользователь нажимает «Выполнить»
- **THEN** клиент MUST отправить `confirmations: [{callId, approved: true}]` и историю из `state`

### Requirement: Обновление интерфейса и отмена

Изменения из чата SHALL появляться в редакторах через существующий поток инвалидации черновика, без отдельной перезагрузки данных панелью. Для хода с записями панель MUST предлагать «Отменить», который откатывает изменения этого хода через существующий откат журнала.

#### Scenario: Перекраска кнопки
- **WHEN** ход изменил свойство компонента
- **THEN** открытый редактор компонента MUST показать новое значение после события инвалидации

#### Scenario: Отмена хода
- **WHEN** пользователь нажимает «Отменить» у хода с двумя записями
- **THEN** клиент MUST откатить обе записи через журнал и MUST показать результат отката
