## ADDED Requirements

### Requirement: Дизайн-система имеет независимые временные границы

Система SHALL представлять исходное состояние, активный черновик и публикации независимыми записями версии с
монотонным `sequenceNumber` внутри дизайн-системы и SHALL NOT связывать версии родительской ссылкой.

#### Scenario: Для дизайн-системы существует один активный черновик

- **WHEN** клиент читает рабочее состояние дизайн-системы
- **THEN** система MUST выбрать единственную версию со статусом `DRAFT`
- **THEN** её `sequenceNumber` MUST быть больше номеров всех опубликованных границ этой дизайн-системы

#### Scenario: Существующие данные получают исходную границу

- **WHEN** миграция встречает дизайн-систему без новой истории версий
- **THEN** система MUST создать технический `BASELINE` с `sequenceNumber = 0`
- **THEN** система MUST создать активный `DRAFT` со следующим номером
- **THEN** `BASELINE` MUST NOT отображаться клиенту как опубликованная версия

### Requirement: Предметное состояние разрешается на границе версии

Система SHALL собирать состояние выбранной версии из последних предметных редакций, номер которых не превышает
`sequenceNumber` этой версии.

#### Scenario: Сущность не изменялась в выбранной версии

- **WHEN** выбранная версия не содержит собственной редакции сущности
- **THEN** предметный репозиторий MUST вернуть последнюю редакцию с меньшим номером временной границы
- **THEN** репозиторий MUST выполнить предметную выборку без рекурсивного обхода предыдущих версий

#### Scenario: Последняя редакция удаляет сущность

- **WHEN** последняя применимая редакция содержит `deleted = true`
- **THEN** предметное чтение MUST считать сущность отсутствующей в выбранной версии
- **THEN** та же сущность MUST оставаться доступной в более ранней версии, предшествующей удалению

### Requirement: Публикация фиксирует текущий черновик

`POST /api/ds/design-system-versions` SHALL атомарно переводить активный черновик в опубликованную версию и создавать
следующий пустой черновик без копирования неизменившихся предметных данных.

#### Scenario: Черновик успешно опубликован

- **WHEN** уполномоченный пользователь передаёт `designSystemId`, актуальные `draftId` и `draftRevision`, уникальный
  номер `major.minor.patch` и `changelog`
- **THEN** API MUST изменить статус указанного черновика на `PUBLISHED`
- **THEN** API MUST назначить номер версии и время публикации на сервере
- **THEN** API MUST создать новый `DRAFT` со следующим `sequenceNumber`
- **THEN** API MUST NOT копировать предметные редакции опубликованного черновика в новый черновик

#### Scenario: Клиент пытается передать серверные поля публикации

- **WHEN** запрос публикации содержит `snapshot`, `changesSnapshot`, `publicationStatus` или `publishedAt`
- **THEN** API MUST отклонить запрос как не соответствующий контракту

#### Scenario: Черновик не содержит изменений

- **WHEN** вычисляемый журнал активного черновика пуст
- **THEN** API MUST отклонить публикацию без создания новой версии

#### Scenario: Запись пришла во время публикации

- **WHEN** предметная запись получает блокировку черновика после начала публикации
- **THEN** она MUST продолжить выполнение в новом активном черновике
- **THEN** она MUST NOT изменить уже опубликованную версию

### Requirement: Опубликованная версия неизменяема

Система SHALL запрещать изменение и удаление опубликованной версии отдельными публичными операциями.

#### Scenario: Клиент изменяет опубликованную версию

- **WHEN** клиент вызывает прежний `PATCH /api/ds/design-system-versions/{id}`
- **THEN** маршрут MUST отсутствовать в публичном API

#### Scenario: Клиент удаляет опубликованную версию

- **WHEN** клиент вызывает прежний `DELETE /api/ds/design-system-versions/{id}`
- **THEN** маршрут MUST отсутствовать в публичном API

### Requirement: Предметные API читают опубликованную версию

Предметные методы чтения SHALL принимать необязательный `versionId` и возвращать состояние указанной временной
границы без изменения формы предметных данных.

#### Scenario: Параметр версии отсутствует

- **WHEN** клиент вызывает предметный метод чтения без `versionId`
- **THEN** API MUST вернуть состояние активного черновика

#### Scenario: Указана опубликованная версия

- **WHEN** клиент передаёт `versionId` опубликованной версии той же дизайн-системы
- **THEN** API MUST вернуть состояние на временной границе этой версии
- **THEN** редактор MUST использовать ответ только для чтения

#### Scenario: Версия принадлежит другой дизайн-системе

- **WHEN** `versionId` не принадлежит запрошенной дизайн-системе
- **THEN** API MUST вернуть `404 Not Found`
