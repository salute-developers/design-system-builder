## ADDED Requirements

### Requirement: Журнал вычисляется из предметных редакций

Система SHALL формировать журнал как разницу предметных редакций выбранной версии и состояния на предыдущей
опубликованной границе или `BASELINE` и SHALL NOT принимать записи журнала от клиента.

#### Scenario: Сущность создана в черновике

- **WHEN** выбранная версия содержит действующую предметную редакцию сущности, отсутствовавшей на предыдущей границе
- **THEN** журнал MUST вернуть операцию `CREATE`

#### Scenario: Сущность изменена в черновике

- **WHEN** предметные поля выбранной версии отличаются от предыдущего состояния
- **THEN** журнал MUST вернуть операцию `UPDATE` и изменённые пути

#### Scenario: Сущность удалена в черновике

- **WHEN** выбранная версия содержит последнюю редакцию `deleted = true`, а сущность существовала ранее
- **THEN** журнал MUST вернуть операцию `DELETE`
- **THEN** предыдущее состояние MUST оставаться доступным для отката и исторического чтения

#### Scenario: Изменение вернулось к предыдущему состоянию

- **WHEN** все предметные поля снова равны предыдущему опубликованному состоянию
- **THEN** сущность MUST отсутствовать в журнале

### Requirement: Клиент читает журнал дизайн-системы

`GET /api/ds/design-systems/{id}/changes` SHALL возвращать понятное пользователю описание фактических предметных
изменений.

#### Scenario: Запрошен журнал активного черновика

- **WHEN** клиент вызывает маршрут без `versionId`
- **THEN** API MUST вернуть изменения активного черновика
- **THEN** каждая запись MUST содержать `changeId`, `versionId`, `entityType`, `entityId`, `operation`, изменённые пути,
  прежние и новые отображаемые значения, автора, время и текущую техническую редакцию

#### Scenario: Запрошен журнал опубликованной версии

- **WHEN** клиент передаёт `versionId` опубликованной версии этой дизайн-системы
- **THEN** API MUST вернуть её разницу с предыдущей опубликованной границей или `BASELINE`

#### Scenario: Клиент создаёт запись журнала

- **WHEN** клиент вызывает прежний `POST /api/ds/design-system-changes`
- **THEN** маршрут MUST отсутствовать в публичном API

### Requirement: Черновое изменение можно откатить

`POST /api/ds/design-systems/{id}/changes/{changeId}/revert` SHALL направлять откат типизированному обработчику
предметного модуля и SHALL принимать `X-DS-Base-Revision` и ключ повторяемости.

#### Scenario: Откатывается изменение опубликованной сущности

- **WHEN** актуальная запись журнала имеет операцию `UPDATE` или `DELETE`
- **THEN** обработчик MUST восстановить состояние предыдущей опубликованной границы удалением или изменением
  предметной редакции черновика
- **THEN** журнал MUST быть пересчитан после завершения транзакции

#### Scenario: Откатывается создание

- **WHEN** актуальная запись журнала имеет операцию `CREATE`
- **THEN** обработчик MUST удалить черновую редакцию и устойчивую сущность после проверки зависимостей
- **THEN** опубликованные данные MUST остаться без изменений

#### Scenario: Изменение успело измениться повторно

- **WHEN** переданная базовая редакция не совпадает с текущей редакцией записи журнала
- **THEN** API MUST вернуть `409 Conflict` с кодом `DRAFT_CHANGE_STALE` и актуальной редакцией
- **THEN** API MUST NOT выполнять откат автоматически
- **THEN** клиент MUST обновить журнал

#### Scenario: Клиент откатывает опубликованную версию

- **WHEN** `changeId` относится не к активному черновику
- **THEN** API MUST отклонить откат без изменения предметных данных
