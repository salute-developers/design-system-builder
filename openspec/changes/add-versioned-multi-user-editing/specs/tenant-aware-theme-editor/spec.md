## MODIFIED Requirements

### Requirement: Редактор собирает модель выбранной темы

Веб-клиент SHALL загружать общие определения токенов и компонентные настройки дизайн-системы отдельно от значений
выбранного tenant и SHALL учитывать выбранную версию дизайн-системы.

#### Scenario: Данные активного черновика загружены

- **WHEN** пользователь открывает существующий tenant без `versionId`
- **THEN** клиент MUST загрузить метаданные дизайн-системы, определения токенов и компонентные настройки активного
  черновика по `designSystemId`
- **THEN** клиент MUST загрузить метаданные tenant и значения токенов по `tenantId`
- **THEN** клиент MUST собрать объекты редактора только после проверки связи tenant с дизайн-системой

#### Scenario: Данные опубликованной версии загружены

- **WHEN** пользователь открывает tenant с `versionId` опубликованной версии
- **THEN** клиент MUST передать `versionId` всем предметным запросам данных дизайн-системы
- **THEN** клиент MUST показать редактор в режиме только для чтения
- **THEN** клиент MUST NOT отправлять изменяющие запросы

#### Scenario: У выбранного tenant отсутствует значение

- **WHEN** для общего определения токена отсутствует значение выбранного tenant на выбранной границе
- **THEN** клиент MUST показать контролируемое состояние неполных данных
- **THEN** клиент MUST NOT использовать значение другого tenant или другой версии

#### Scenario: Пользователь переключает темы

- **WHEN** пользователь переходит с одного `tenantId` на другой
- **THEN** клиент MUST дождаться либо сохранить сведения о неподтверждённых запросах прежнего tenant
- **THEN** клиент MUST сбросить вычисленное состояние прежней темы и отменить либо проигнорировать её устаревшие ответы
- **THEN** интерфейс MUST показывать только серверное состояние нового tenant

### Requirement: Значения одного выбранного tenant сохраняются пакетно и атомарно

API SHALL сохранять пакет значений токенов одного tenant одной транзакцией, а веб-клиент SHALL автоматически вызывать
существующую tenant-scoped операцию после изменения данных вместо отдельного явного сохранения всего редактора.

#### Scenario: Editor изменяет тему

- **WHEN** Editor, Maintainer или Owner изменяет одно или несколько значений выбранной темы
- **THEN** клиент MUST отправить `tenantId`, базовые редакции затронутых логических значений и согласованный набор
  намеренно изменённых значений одним запросом
- **THEN** API MUST проверить, что все `tokenId` принадлежат дизайн-системе tenant
- **THEN** API MUST атомарно применить значения только к выбранному tenant активного черновика
- **THEN** API MUST вернуть актуальные значения и их технические редакции

#### Scenario: Платформенные значения сохраняются раздельно

- **WHEN** пакет содержит значения одного токена для `web`, `ios` или `android` и режимов Light или Dark
- **THEN** API MUST различать логические сущности по `tokenId + tenantId + platform + mode`
- **THEN** сохранение одной комбинации MUST NOT изменить редакцию другой платформы или режима

#### Scenario: Клиент пытается изменить платформу или режим значения

- **WHEN** изменяющий запрос существующего значения содержит другие `platform` или `mode`
- **THEN** API MUST отклонить изменение неизменяемого ключа
- **THEN** клиент MUST использовать существующие операции удаления и создания другого значения

#### Scenario: Клиент повторно создаёт удалённую комбинацию

- **WHEN** устойчивое значение с теми же `tokenId`, `tenantId`, `platform`, `mode` существует с последней редакцией `deleted = true`
- **THEN** API MUST использовать прежний устойчивый идентификатор
- **THEN** API MUST создать редакцию активного черновика с `deleted = false` и новым значением

#### Scenario: Одно значение пакета невалидно

- **WHEN** хотя бы одно значение пакетного запроса не прошло проверку
- **THEN** API MUST отклонить весь запрос без частичного изменения значений tenant

#### Scenario: Сохраняется одна из двух тем

- **WHEN** пользователь изменяет tenant A в дизайн-системе, также содержащей tenant B
- **THEN** значения и технические редакции tenant B MUST остаться без изменений

#### Scenario: Viewer открывает редактор

- **WHEN** Viewer открывает тему
- **THEN** клиент MUST показать редактор в режиме чтения
- **THEN** клиент MUST NOT отправлять изменяющие запросы

### Requirement: Конкурентное редактирование одного tenant не теряет изменения незаметно

Система SHALL назначать техническую редакцию каждому логическому значению tenant и SHALL NOT представлять её
пользователю как версию Theme.

#### Scenario: Два редактора изменяют разные tenant

- **WHEN** два редактора одновременно изменяют разные tenant одной дизайн-системы
- **THEN** оба сохранения MUST завершиться независимо
- **THEN** изменение одного tenant MUST NOT изменить редакции или значения другого tenant

#### Scenario: Редакторы изменяют разные значения одного tenant

- **WHEN** запрос основан на устаревшей редакции другого логического значения tenant
- **THEN** API MUST применить изменение без `TENANT_EDIT_CONFLICT`
- **THEN** API MUST сохранить уже подтверждённое значение другого пользователя

#### Scenario: Редакторы изменяют одно значение

- **WHEN** второй запрос изменяет путь, уже изменённый после его базовой редакции
- **THEN** API MUST применить последнюю успешно зафиксированную запись
- **THEN** ответ MUST содержать машиночитаемое предупреждение и актуальную редакцию
- **THEN** первая версия интерфейса MAY не показывать предупреждение пользователю

#### Scenario: Устарела операция отката

- **WHEN** клиент пытается откатить изменение tenant с неактуальной редакцией
- **THEN** API MUST вернуть `409 Conflict` с кодом `DRAFT_CHANGE_STALE`
- **THEN** клиент MUST обновить журнал без автоматического повторения отката

## REMOVED Requirements

### Requirement: Черновики редактора изолированы по tenant

**Reason**: Подтверждённые предметные изменения теперь хранятся в общем серверном черновике дизайн-системы, а не в
локальном черновике каждого браузера.

**Migration**: Клиент переносит изменения на серверное автосохранение. В `localStorage` временно остаются только
неподтверждённые запросы с `projectId`, `designSystemId`, `tenantId`, ключом повторяемости и базовой редакцией.
