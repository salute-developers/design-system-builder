## Context

Веб-мета — вывод `js/cli/src/generate-api-meta.ts`:

```json
[{ "componentName": "Button", "params": [
  { "paramName": "buttonColor", "type": "color", "id": "labelColor" },
  { "paramName": "buttonColorHover", "type": "color", "id": "labelColor", "state": "hovered" },
  { "paramName": "buttonFontFamily", "type": "typography", "id": "labelStyle", "part": "fontFamily" },
  { "paramName": "buttonTextColor", "type": "color", "id": "buttonTextColor", "deprecated": { "message": "..." } } ] }]
```

Запись в `params` описывает токен (CSS-переменную), а не свойство. `id` берётся из `@styleProp` (по умолчанию это ключ токена), `part` — из `@stylePart`, `state` — из `@styleState`. `deprecated` пишется как `{}`, если у `@deprecated` нет `{@link}`.

Как web-параметры используются сейчас:

- сиды db-service заводят web-параметр с именем ключа токена, а у типографики — шесть параметров `*FontFamily … *LineHeight`;
- генерация web (`js/cli/src/component-source.ts`) берёт параметры свойства как `params.filter(id == name && !state).map(paramName)`.

## Decisions

### Свойство — пара `(componentName, id)`

Это то же правило, что у Compose и View. Повтор с другим типом попадает в `conflicts`, и побеждает первое вхождение. На реальной мете конфликтов нет.

### Платформенные имена — ключи токенов без `state`

Так имена совпадают с сидами и с тем, что ищет генерация. Части типографики становятся несколькими именами одного свойства, и порядок у них тот же, что в мете. Так же становятся несколькими именами и токены одного значения (`buttonLeftContentMargin` и `buttonRightContentMargin` у `Button.iconMargin`).

Токен с `state` несёт значение свойства в состоянии взаимодействия, и сиды его как параметр не заводят. Если бы он стал именем, у `labelColor` появились бы `buttonColorHover` и `buttonColorActive`, которых генерация не читает.

Свойство, у которого есть только токены состояний, генерация пропускает, и импорт делает так же: оно попадает в `skipped` с категорией `properties with state tokens only`. На реальной мете таких свойств нет.

Альтернатива — все токены как имена. Её отклонили: имена расходились бы с сидами и генерацией.

### Состояния взаимодействия не становятся состояниями компонента

`hovered`, `pressed`, `focused`, `selected`, `activated`, `readonly` и `disabled` — строки общего словаря `states` с `component_id = NULL` из базовой миграции. Backend заводит состояния манифеста как компонентные, поэтому у каждого компонента появился бы дубль общего состояния. Нормализатор отбрасывает их по списку. Список фиксирован миграцией с детерминированными идентификаторами, поэтому константа в CLI допустима. Остальные значения `state` приводятся к kebab-case и становятся состояниями компонента. Сейчас таких значений в мете нет.

### `deprecated` на уровне токена

Устаревание относится к токену, как у View — к XML-атрибуту. Пометка одного токена не распространяется на другие имена свойства. `{}` без сообщения означает пустое сообщение.

### Компонент без токенов попадает в манифест

Компонент веб-меты — это файл токенов пакета. Если у файла нет словаря, компонент в пакете всё равно существует (`AvatarGroup`, `Image`, `Popup`, `Price`, `Resizable`), и в базе он должен быть, чтобы к нему можно было привязать оформление. Поэтому нормализатор web отправляет его с пустыми `properties`. Backend такой компонент принимает: `ImportApiMetaRequest.valid()` не требует свойств, а `ensureComponents` заводит недостающую пару `(имя, web)`.

`Empty` остаётся только для меты без единого компонента. У Compose и View компонент без свойств по-прежнему отбрасывается: там пустая запись означает отсутствующий артефакт, а не существующий компонент.

### Описание — `token: <paramName>[/<paramName>…]`

Это справочная строка по образцу `attr:` у View.

### Отличие от меты Compose — обязательный `paramName`

Мета Compose — тоже список `{componentName, params}`. Если все поля необязательны, файл Compose с `--platform react` разобрался бы в манифест с именами из `id`. Поэтому `paramName` обязателен: у Compose его нет, и результат — `Invalid` с путём файла. Мета View (объект) тоже даёт `Invalid`.

## Risks / Trade-offs

- **Дубли веб-компонентов.** Имена из меты (например, `LinkButton`, `IconTabItem`) могут не совпасть с сидами. Импорт аддитивный, поэтому дубль останется. Чтобы этого избежать, первый запуск делают в dry run и сверяют `Created components`.
- **Расхождение `id` с именами свойств сидов.** Если `@styleProp` отличается от имени свойства в сиде, появится новое свойство с тем же web-параметром. Это проверяется тем же dry run.
