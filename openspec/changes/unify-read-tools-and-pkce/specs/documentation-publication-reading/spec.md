## MODIFIED Requirements

### Requirement: Чтение navigation и page

Сервис SHALL предоставлять упорядоченную навигацию и страницу с содержимым, subjects и assets по ID публикации либо селектору дизайн-системы, точной версии и платформы. Разрешение селектора и чтение SHALL выполняться одной серверной операцией.

#### Scenario: Page с несколькими content sources

- **WHEN** страница содержит Core и User content
- **THEN** ответ MUST сохранить нормализованный порядок блоков и метаданные источников

#### Scenario: Выбрана активная публикация

- **WHEN** клиент передал дизайн-систему, точную версию и платформу
- **THEN** сервер MUST разрешить активную публикацию и вернуть данные вместе с её publicationId

#### Scenario: Ошибка разрешения

- **WHEN** разрешение публикации завершается отказом доступа или недоступностью
- **THEN** ответ MUST сохранить категорию ошибки без преобразования в отсутствие публикации

### Requirement: Чтение и listing CodeBinding

Сервис SHALL предоставлять точную привязку и постраничный поиск с subject/kind/name, селектором публикации и серверными проекциями summary/variations/full. Существующие маршруты по ID публикации SHALL сохранять прежний полный ответ без новых параметров.

#### Scenario: Exact binding прочитана

- **WHEN** клиент вызывает существующий маршрут по publicationId без detail
- **THEN** ответ MUST вернуть канонические поля и полный platform payload

#### Scenario: Listing отфильтрован по subject

- **WHEN** передан subject=components.avatar
- **THEN** список MUST содержать только привязки с этим subject и cursor

#### Scenario: Компактный серверный ответ

- **WHEN** расширенная операция получает detail=summary
- **THEN** ответ MUST содержать оформления, оси, defaults и counts без развёрнутых вариаций и styleApi
- **WHEN** detail=variations
- **THEN** ответ MUST содержать конкретные ссылки кода без styleApi
- **WHEN** detail=full
- **THEN** ответ MUST сохранить полный payload после точных appearanceNames/variationNames фильтров

## ADDED Requirements

### Requirement: Обнаружение и проверка публикаций

Сервис SHALL предоставлять постраничный список опубликованных публикаций выбранной дизайн-системы с необязательными version/platform, включая переиздания, и проверять принадлежность явно выбранной публикации проекту и дизайн-системе.

#### Scenario: Обнаружение без выбранной версии

- **WHEN** клиент не знает version и platform
- **THEN** список MUST вернуть доступные опубликованные публикации, новые первыми, без candidate и с фактическими version/platform/publicationId
- **THEN** действующие документационные ограничения 20 по умолчанию и 100 максимум MUST сохраниться

#### Scenario: Чужая публикация

- **WHEN** publicationId принадлежит другому проекту или дизайн-системе
- **THEN** сервис MUST вернуть NOT_FOUND без раскрытия её существования

#### Scenario: Явные параметры противоречат ID

- **WHEN** явно переданные version или platform не совпадают с метаданными publicationId
- **THEN** сервер MUST вернуть INVALID_QUERY

#### Scenario: Документация без публикации модели

- **WHEN** опубликованная документация доступна, но одноимённой версии новой модели нет
- **THEN** сервис MUST сохранить возможность её чтения
- **THEN** метаданные MUST NOT содержать выдуманный versionId модели

### Requirement: Проекции источников и связь с моделью

Расширенный ответ фрагмента SHALL исключать searchText. Привязка SHALL содержать componentId только при доказуемом соответствии выбранной модели; опубликованная документация MUST NOT представляться состоянием модели.

#### Scenario: Компактный фрагмент

- **WHEN** клиент запрашивает фрагмент в расширенном режиме
- **THEN** сервер MUST вернуть markdown и метаданные источника без копии поискового индекса

#### Scenario: Сопоставление не установлено

- **WHEN** компонент нельзя однозначно сопоставить с привязкой выбранной версии
- **THEN** componentId MUST отсутствовать без угадывания по похожему имени
