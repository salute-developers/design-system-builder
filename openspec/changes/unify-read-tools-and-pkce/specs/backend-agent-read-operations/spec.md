## Purpose

Определяет общие серверные операции чтения дизайн-систем, используемые MCP, обычным клиентом и будущим встроенным агентом без дублирования предметных вычислений.

## ADDED Requirements

### Requirement: Серверные операции доступны через разные доверенные входы

Бэкенд SHALL предоставлять общие предметные операции через Gateway и внутренний HTTP с проверенным контекстом. Контекст проекта и разрешения MUST NOT считаться доказанными на основании аргументов LLM.

#### Scenario: Одинаковое чтение через два входа

- **WHEN** один авторизованный контекст вызывает операцию через Gateway и внутренний HTTP
- **THEN** результаты MUST иметь одинаковую предметную семантику и ограничения доступа
- **THEN** операция MUST NOT требовать локального workspace или пользовательского логина внутреннего вызывающего сервиса

#### Scenario: Ресурс другой дизайн-системы

- **WHEN** компонент, токен, tenant или группа не принадлежит выбранной дизайн-системе
- **THEN** API MUST вернуть NOT_FOUND без раскрытия чужих данных

### Requirement: Единый выбор версии модели

Чтение модели SHALL принимать `version=draft` или точный номер публикации и разрешать его внутри выбранной дизайн-системы. Явный аргумент SHALL перекрывать контекст; отсутствие выбора SHALL означать черновик.

#### Scenario: Чтение исторического состояния

- **WHEN** клиент выбирает существующую публикацию новой модели
- **THEN** все предметные данные ответа MUST соответствовать её временной границе
- **THEN** ответ MUST содержать фактические version и versionId

#### Scenario: Черновик меняется между вызовами

- **WHEN** два независимых чтения черновика разделены изменением данных
- **THEN** второе чтение SHALL вернуть актуальные данные без требования expectedDraftRevision
- **THEN** ответ SHALL содержать draftId и draftRevision

#### Scenario: Неверная или архивная версия

- **WHEN** запрошена отсутствующая, чужая либо архивная snapshot-версия
- **THEN** API MUST вернуть NOT_FOUND без перехода на черновик

#### Scenario: Противоречивые селекторы

- **WHEN** запрос содержит одновременно version и versionId
- **THEN** API MUST вернуть INVALID_QUERY

### Requirement: Серверные фильтры и ограниченные списки

Расширенные списки модели SHALL выполнять фильтры на сервере, возвращать items/nextCursor и применять limit по умолчанию 50 с максимумом 200. Порядок SHALL быть детерминированным с устойчивым дополнительным ключом ID.

#### Scenario: Точное имя и поиск

- **WHEN** клиент передаёт name
- **THEN** API MUST выполнить точное сравнение до пагинации
- **WHEN** одновременно переданы name и query
- **THEN** API MUST вернуть INVALID_QUERY

#### Scenario: Cursor не соответствует выборке

- **WHEN** cursor используется с другой дизайн-системой, версией или фильтрами
- **THEN** API MUST вернуть INVALID_QUERY

#### Scenario: Проверка лимита

- **WHEN** limit неположителен, нецелый или превышает максимум
- **THEN** расширенная операция MUST вернуть INVALID_QUERY

### Requirement: Обнаружение версий и предметных данных

API SHALL предоставлять метаданные выбранной версии, список публикаций модели и журнал изменений, списки tenants и групп токенов, палитру с фильтрами, свойства и зависимости компонентов согласно контрактам design.md.

#### Scenario: Список версий

- **WHEN** клиент запрашивает версии дизайн-системы
- **THEN** API MUST вернуть только публикации новой модели в порядке убывания sequenceNumber с пагинацией

#### Scenario: Журнал публикации

- **WHEN** клиент выбирает опубликованную версию для журнала
- **THEN** API MUST вернуть изменения этой границы без вычисления сравнения произвольной пары версий

#### Scenario: Фильтры палитры

- **WHEN** клиент передаёт tenantId и фильтры groupId/type/shade
- **THEN** API SHALL вернуть соответствующую часть палитры выбранной версии
- **THEN** shade без type MUST быть отклонён как INVALID_QUERY

### Requirement: Серверная выборка конфигурации компонента

Операция SHALL принимать componentId, необязательные style и объект selection, проверять выбор и собирать конфигурацию выбранной версии на сервере.

#### Scenario: Частичный выбор

- **WHEN** selection задаёт допустимые значения части осей
- **THEN** API MUST сузить выбранные оси и сохранить структуру остальных

#### Scenario: Неверная вариация

- **WHEN** selection содержит неизвестную ось или значение
- **THEN** API MUST вернуть INVALID_QUERY без частичного результата

#### Scenario: Составное чтение при конкурентной записи

- **WHEN** конфигурация читается одновременно с изменением черновика
- **THEN** одна серверная операция MUST вернуть согласованное состояние, а не смесь редакций

### Requirement: Серверное извлечение токен-ссылок

Операция SHALL принимать componentId, необязательный style и полный объект selection и возвращать проверенные ссылки на токены выбранной версии с ID и местами использования.

#### Scenario: Выбор полностью определён

- **WHEN** выбранные оформления имеют значения всех осей
- **THEN** сервер MUST проверить ссылки по каталогу той же версии и вернуть стабильные tokenId и пути использования
- **THEN** ответ MUST NOT выдавать произвольные строки конфигурации за токен-ссылки или вычислять значения темы

#### Scenario: Выбор неполон

- **WHEN** хотя бы одна ось выбранного оформления не определена
- **THEN** сервер MUST вернуть INVALID_QUERY с безопасным описанием недостающего выбора

### Requirement: Совместимость действующих клиентов и платформ

Расширенные операции SHALL сохранять действующие HTTP-ответы вне явно выбранного расширенного режима. Наборы платформ токенов, компонентов и документации SHALL оставаться неизменными.

#### Scenario: Старый клиент читает список

- **WHEN** клиент вызывает существующий маршрут без расширенного режима view=agent
- **THEN** API MUST сохранить действующую форму ответа и прежнюю политику ограничения выдачи

#### Scenario: Платформы токенов сохранены

- **WHEN** клиент читает значения токенов
- **THEN** platform SHALL по-прежнему принимать web, android и ios
- **THEN** изменение MUST NOT мигрировать android в compose/xml либо автоматически преобразовывать платформу
