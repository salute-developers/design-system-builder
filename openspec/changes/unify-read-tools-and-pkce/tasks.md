# Задачи

## 1. Серверный выбор версии и совместимость

- [ ] 1.1 Реализовать общий серверный селектор version/draft с проверкой проекта и DS, не меняя versionId; тестами проверить приоритет выбора, неизвестную/чужую/архивную версию и запрет двух селекторов.
- [ ] 1.2 Добавить read-context и метаданные версии/черновика, расширенный ответ view=agent; контрактными тестами проверить context, отсутствие секретов и сохранение прежних ответов web-клиента.
- [ ] 1.3 Добавить расширенную пагинацию и серверные фильтры списков версий, журнала, tenants, tokens, components, styles и token-groups; тестами проверить точное name, конфликт с query, лимиты, порядок и привязку cursor.
- [ ] 1.4 Реализовать фильтры палитры и проверку принадлежности ID всех предметных чтений выбранной DS; проверить исторические ответы и отказ для чужих tenant/token/component/group.
- [ ] 1.5 Обновить OpenAPI ds-service и документацию селекторов/совместимости; контрактная проверка должна покрывать новые маршруты, параметры, DTO и ошибки без изменений платформ и JS-схемы.

## 2. Серверные составные чтения компонентов

- [ ] 2.1 Реализовать прикладную выборку config по componentId/style/selection и новый POST query; тестами проверить канонический результат, частичный выбор, неизвестные оси/значения и отсутствие записи в БД.
- [ ] 2.2 Реализовать единое чтение токен-ссылок по полному selection с ID и путями использования; проверить неполные оси, недоказанные ссылки, историческую версию и отсутствие вычисления значений темы.
- [ ] 2.3 Расширить чтение свойств платформенными параметрами и зависимостей настройками переиспользования; проверить полный результат без клиентского обхода связей и безопасность чужих компонентов.
- [ ] 2.4 Обеспечить согласованность составной выборки при конкурентной записи подходящей транзакционной изоляцией; добавить интеграционный тест, обновить OpenAPI и примеры запросов.

## 3. Серверное чтение документации

- [ ] 3.1 Добавить единый селектор publicationId либо version/platform с проверкой проекта/DS и список опубликованных публикаций; тестами проверить переиздания, исключение candidate, конфликты селектора и независимость от наличия версии модели.
- [ ] 3.2 Добавить составные navigation/page/bindings операции с одной серверной точкой входа; тестами проверить сохранение 401/403/503 вместо ложного отсутствия публикации и совместимость прежних ID-маршрутов.
- [ ] 3.3 Перенести summary/variations/full и точные фильтры имён CodeBinding на сервер, компактный fetch без searchText; проверить старый полный ответ, новый default, недопустимые комбинации и отсутствие выдуманных связей модели.
- [ ] 3.4 Добавить поиск по явной опубликованной публикации и привязку cursor к ней; проверить смену active pointer между страницами, чужую публикацию, subjects и регрессионный корпус ранжирования.
- [ ] 3.5 Обновить OpenAPI documentation-service, включая фактические фильтры и ответы bindings; контрактными тестами проверить все новые пути и сохранение действующих платформ и лимитов 20/100.
