# Единое чтение дизайн-систем и браузерный вход CLI/MCP

## Зачем

MCP не учитывает опубликованные версии модели и самостоятельно фильтрует конфигурации и привязки к коду. Эти вычисления должны быть доступны обычному клиенту и будущему Agent Service через общие операции бэкенда. Парольный вход CLI/MCP заменяется браузерным Authorization Code + PKCE.

## Что меняется

- Реестр из 26 инструментов чтения: сохраняются 16 имён, добавляются 10; полный контракт приведён в design.md.
- Единый выбор черновика или точной опубликованной версии; разрешение версии, фильтрация, пагинация, сбор конфигурации, извлечение ссылок на токены и проекции CodeBinding выполняются на бэкенде.
- Публикации документации адресуются независимо от версий модели; составные чтения публикаций выполняются одной серверной операцией.
- **BREAKING**: `component_config_get` принимает `componentId` и объект `selection`; `projection=token-references` заменяется `component_tokens_get`; поиск документации принимает `subjects[]`; списки MCP становятся ограниченными и постраничными.
- **BREAKING**: `auth login` CLI/MCP использует браузер и PKCE вместо ввода логина/пароля. Refresh token сохраняется в общем файловом хранилище, access token кешируется только в памяти.
- Архитектурные границы соответствуют документу «DS Builder Agent — краткая архитектурная выжимка»: MCP идёт через Gateway, будущий Agent Service — через внутренний HTTP к тем же прикладным операциям. Agent Service в этом изменении не создаётся.
- Платформы токенов, компонентов и документации, ключи проектов, операции записи и серверная модель черновиков не меняются. `expectedDraftRevision` для чтения не вводится.

## Возможности

### Новые возможности

- `backend-agent-read-operations`: общие серверные операции чтения версий и предметных данных для нескольких клиентских входов.

### Изменяемые возможности

- `frontend-mcp-server`: 26 инструментов, новые параметры и тонкие обработчики без предметных вычислений.
- `frontend-client-authentication`: браузерный вход CLI/MCP, общая сессия и кеш access token.
- `documentation-publication-reading`: выбор публикации, составные чтения и серверные проекции.
- `documentation-search`: поиск по явно выбранной опубликованной публикации и сохранение публикации при пагинации.

## Влияние

- `backend-kt/ds-service`: прикладные сценарии, запросы репозиториев, DTO, HTTP и OpenAPI; используется существующее версионированное хранение.
- `backend-kt/documentation-service`: выбор публикации, проекции, фильтры, список публикаций, OpenAPI; существующие индекс и ранжирование сохраняются.
- `backend-kt/identity-gateway`: переиспользование существующего публичного OAuth-клиента `dsbuilder-studio-plugin` для CLI/MCP; проверка PKCE S256, audience, loopback redirect и документация публичной авторизации без создания новой регистрации.
- `frontend-kt/core-auth`, `core-network`, `core-application`, `feature-auth`, `feature-components`, `feature-theme`, `feature-docs`, `feature-status`, `mcp-server-core`, `mcp-node`, `cli`: общие порты, адаптеры JVM/macOS/Node, реестр и тесты.
- Сессии остаются в `~/.sdds/sessions`; миграция формата хранит принадлежность OAuth-клиенту. При несовместимой старой сессии требуется повторный вход.
- `js`: схема БД, enum платформ, миграции и действующие контракты web-клиента не меняются; расширение API выполняется совместимо с ними.
- Нового микросервиса и обязательной новой внешней зависимости не требуется. Изменения защищённых файлов процесса, архитектурных тестов и Strictacode policy не разрешаются этим Change.
