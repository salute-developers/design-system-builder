## ADDED Requirements

### Requirement: Версия импортированной меты хранится по платформе

`ds-service` SHALL хранить для каждой платформы компонентов не более одной записи версии меты: версия библиотеки, из которой собрана мета, sha256 файла меты, имя файла-источника, идентификатор администратора и момент импорта. Запись MUST принадлежать `ds-service` и создаваться миграцией Flyway; таблица MUST NOT быть привязана к дизайн-системе или проекту.

#### Scenario: Первая запись версии

- **WHEN** администратор выполняет импорт меты платформы без `dryRun` и передаёт версию и sha256, а записи для платформы нет
- **THEN** backend MUST сохранить версию, sha256, имя источника, идентификатор администратора и время импорта
- **AND** итог по версии в ответе MUST быть `recorded`.

#### Scenario: Запись одна на платформу

- **WHEN** импорт выполняется повторно для той же платформы с другой версией
- **THEN** запись платформы MUST быть заменена, а не добавлена ещё одна.

### Requirement: Запись версии выполняется в транзакции импорта

Запись версии меты SHALL выполняться в той же транзакции, что и запись компонентов, свойств, состояний и платформенных имён. Версия MUST NOT измениться, если импорт завершился ошибкой и данные откатились, и MUST NOT измениться при `dryRun`.

#### Scenario: Ошибка импорта не меняет версию

- **WHEN** транзакция импорта откатывается
- **THEN** ранее записанная версия MUST остаться без изменений.

#### Scenario: Пробный запуск не пишет версию

- **WHEN** запрос содержит `dryRun = true`
- **THEN** запись версии MUST NOT измениться
- **AND** итог по версии в ответе MUST описывать, что произошло бы при записи.

### Requirement: Импорт той же версии идемпотентен и защищён от подмены

Если переданные версия и sha256 совпадают с записанными, импорт SHALL оставлять запись без изменений и возвращать итог `unchanged`. Если версия совпадает, а sha256 отличается, backend MUST отклонить весь импорт ответом `409` с кодом `meta_changed_without_version` и MUST NOT изменить данные.

#### Scenario: Повторный импорт той же меты

- **WHEN** администратор повторно импортирует мету с теми же версией и sha256
- **THEN** итог по версии MUST быть `unchanged`
- **AND** запись версии MUST остаться без изменений.

#### Scenario: Мета изменена без смены версии

- **WHEN** передана записанная версия с другим sha256
- **THEN** backend MUST ответить `409` с кодом `meta_changed_without_version`
- **AND** компоненты, свойства, состояния и платформенные имена MUST NOT измениться
- **AND** ответ MUST содержать записанную версию и её sha256.

#### Scenario: Конфликт виден при пробном запуске

- **WHEN** запрос с `dryRun = true` содержит записанную версию с другим sha256
- **THEN** backend MUST ответить `409` с тем же кодом.

### Requirement: Новая версия заменяет записанную и сообщает предыдущую

Если переданная версия отличается от записанной, backend SHALL заменить запись и вернуть итог `replaced` с предыдущим значением версии и sha256.

#### Scenario: Замена версии

- **WHEN** передана версия, отличная от записанной
- **THEN** запись MUST содержать новые версию и sha256
- **AND** итог MUST быть `replaced` и содержать предыдущие версию и sha256.

### Requirement: Версия необязательна для совместимости

Метаданные запроса SHALL допускать отсутствие версии и sha256 вместе. Если обе опущены, backend MUST оставить запись версии без изменений и вернуть итог `not_provided`. Если задано только одно из значений, backend MUST ответить ошибкой валидации и MUST NOT изменить данные.

#### Scenario: Запрос без версии

- **WHEN** запрос импорта не содержит версии и sha256
- **THEN** импорт MUST выполниться по прежним правилам
- **AND** итог по версии MUST быть `not_provided`.

#### Scenario: Задано одно значение

- **WHEN** запрос содержит версию без sha256 или sha256 без версии
- **THEN** backend MUST ответить ошибкой валидации и MUST NOT изменить данные.

### Requirement: Версия меты читается по проектному маршруту

Backend SHALL предоставлять `GET /api/projects/{projectId}/ds/component-meta-versions/{platform}`, доступный участнику проекта с правом `components:read`. Ответ MUST содержать `platform`, `uikitComposeVersion`, `sha256` и `importedAt`. Если версия для платформы не записана, backend MUST ответить `404`.

#### Scenario: Версия записана

- **WHEN** участник проекта с правом `components:read` запрашивает версию платформы `compose`
- **THEN** ответ MUST содержать записанные `uikitComposeVersion`, `sha256` и `importedAt`.

#### Scenario: Версия не записана

- **WHEN** для платформы нет записи версии
- **THEN** backend MUST ответить `404`.

#### Scenario: Нет права чтения

- **WHEN** запрос выполняет пользователь без права `components:read` в проекте
- **THEN** backend MUST отказать в доступе, как для остальных маршрутов компонентов проекта.

#### Scenario: Неизвестная платформа

- **WHEN** `platform` не входит в словарь платформ компонентов
- **THEN** backend MUST ответить ошибкой валидации.

### Requirement: Контракт маршрута описан и проверен

Маршрут чтения версии SHALL быть описан в `src/main/resources/openapi/documentation.yaml` `ds-service`, в манифесте маршрутов и аудите потребителей, а изменение контракта `import-api-meta` MUST быть отражено там же. Контрактная проверка MUST падать при расхождении кода и описания.

#### Scenario: Документация соответствует коду

- **WHEN** запускается контрактная проверка `ds-service`
- **THEN** новый маршрут и расширенные поля импорта MUST присутствовать в OpenAPI-описании и манифесте маршрутов.
