## Адресация

Публичный путь остаётся `/api/projects/{projectId}/design-systems/{designSystemId}/…`.
Внутренний путь ds-service — `/api/design-systems/{designSystemId}/…`; gateway связывает эти пути.
Списки определений токенов, тем и значений остаются массивами. Входные DTO новых инструментов
не дублируют `designSystemId`. Обновлены два устаревших пути OpenAPI-теста и ссылки на архив зависимости.

## Сверка интерфейса и незавершённая проверка

В интерфейсе подтверждены `round.xxs=23`, его iOS `22` и Android `23`, `spacing.0x=23`,
слой `down.soft.s` с X `0`, Y `1`, blur `2`, spread `0`, прозрачностью `20%` и fallback `23`,
а также Display L `23 px`. У компонента видны значение Compact `14`, базовое значение `12`
и ссылка `background.dark.primary`.

Полная задача 6.4 остаётся открытой из-за несогласованности существующих контрактов UI/экспорта:
после установки `displayName="Verified density"` экспорт использует это имя как ключ вариации,
а `editor-bundle.variations` содержит физическое имя `density-…`. Поиск в `Config.getVariationName`
не находит соответствие; `ComponentEditorPreview` падает на `upperFirstLetter(undefined)`.
После явного сброса имени через MCP интерфейс снова открывается и показывает значения.
Файлы JS и backend компонентов этим изменением не менялись; исправление сопоставления имён
не подменяется обходом серверных правил в MCP.

Сервер также возвращает `422 incompatible_value_type` при привязке токена типа `spacing`
к свойству `dimension`. MCP сохраняет этот отказ; изменение серверной совместимости типов
в данный change не включено.

Временные backend и UI остановлены после проверки. Отдельные тестовые БД сохранены;
временные файлы авторизации удалены. Rebase выполнен локально, новые изменения не закоммичены.
