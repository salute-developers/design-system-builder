# MCP-редактор и единая адресация данных дизайн-системы

## Зачем

MCP читает модель DS Builder, но пока не позволяет редактировать её. Добавление мутаций требует явной области дизайн-системы: доступ к двум системам одного проекта не должен позволять случайно прочитать или изменить ресурс другой системы по перепутанному ID.

## Что изменится

- MCP получит точечные операции токенов, операции цветовых семейств и групп, редактор конфигураций, осей, вариантов, свойств и состояний согласно спецификациям редактирования.
- **BREAKING** Все публичные чтения и мутации данных конкретной DS в `ds-service` переходят под `/api/projects/{projectId}/design-systems/{designSystemId}/…`, без промежуточного `/ds`. Коллекция систем проекта располагается на `/api/projects/{projectId}/design-systems`. Общий каталог и административные операции не становятся данными конкретной DS.
- Выбранная DS передаётся общим контекстом в транзакцию. Чтения ограничиваются этой системой; записи проверяются общим механизмом БД для редакций и прямых записей DS-таблиц. Полноценная RLS не вводится.
- Серверное воспроизведение результатов учитывает DS и работает после удаления ресурса без предварительного GET. Подключается недостающая идемпотентность обновлений размеров и типографики.
- Все потребители переносимых маршрутов обновляются в этом Change: веб-клиент, общие Kotlin-модули CLI/MCP, IDE-плагины и серверные потребители. Старые публичные маршруты данных DS удаляются без альтернативных путей записи.

## Возможности

### Новые возможности

- `mcp-token-editing`: точечное и семейное редактирование токенов, цветовых групп и получение исходных значений.
- `mcp-component-editing`: редактирование конфигураций, осей, вариантов и значений свойств с состояниями.

### Изменённые возможности

- `design-system-model-api`: единые маршруты данных DS, строгая область чтений, сохранение форм ответов при переносе и проверка всех потребителей.
- `multi-user-design-system-editing`: общая защита записи выбранной DS, область повторяемости и идемпотентность специализированных обновлений.
- `frontend-mcp-server`: реестр мутаций, вложенные схемы, контекст черновика, безопасные результаты и ошибки.
- `backend-monolith-runtime`: публичная граница новых DS-маршрутов и их авторизация в монолите.
- `gateway-api-reference`: корректная публикация смешанных маршрутов коллекции, конкретной DS и общего каталога.

- `gateway-authorization`: перенос используемых DS URL при сохранении пользовательского поведения.
- `gateway-response-compression`: перенос используемых DS URL при сохранении пользовательского поведения.
- `frontend-cli`: перенос используемых DS URL при сохранении пользовательского поведения.
- `cli-components`: перенос используемых DS URL при сохранении пользовательского поведения.
- `cli-themes`: перенос используемых DS URL при сохранении пользовательского поведения.
- `tenant-aware-theme-editor`: перенос используемых DS URL при сохранении пользовательского поведения.
- `theme-palette-editor`: перенос используемых DS URL при сохранении пользовательского поведения.
- `frontend-design-systems-listing`: перенос используемых DS URL при сохранении пользовательского поведения.
- `ide-plugin-token-browser`: перенос используемых DS URL при сохранении пользовательского поведения.

## Влияние

- `backend-kt/ds-service`: presentation всех затронутых фич; общий контекст, транзакции, ограничение чтений, повторяемость и отображение ошибок; новая Flyway-миграция защиты DS-таблиц. Предметные алгоритмы сохраняются, но фильтры чтения и проверки прямых записей изменяются там, где общего механизма недостаточно. Обновляются OpenAPI, манифест и контрактные проверки.
- `backend-kt/app`: авторизация, классификация/регистрация публичных маршрутов, кэш тела и проверка дерева маршрутов. Конфигурация самостоятельного входа DS и оставшиеся gateway-конфигурации/API Reference приводятся к одному контракту.
- `backend-kt/documentation-service`: адаптер проверки владельца DS и его тесты переводятся на согласованный контракт; внутрипроцессное взаимодействие монолита сохраняется. Остальные серверные потребители проверяются по инвентаризации.
- `frontend-kt/core-network`, `core-application`, `feature-ds`, `feature-theme`, `feature-components`, `feature-status`, `cli`, `mcp-server-core`, `mcp-node`: построение URL, общий контекст и сценарии редактирования. IDE-плагины обновляются вместе с их интерфейсами выбора DS и тестами.
- `js/apps/client`: все запросы данных DS, автосохранение, SSE, обработка метаданных, кэши и тесты. `js/cli` и остальные скрипты проверяются на потребление переносимых маршрутов; новые предметные возможности генератора не добавляются.
- Новых сервисов, зависимостей, RLS и отдельных ролей БД нет. Новые URL требуют согласованного развёртывания backend и клиентов; источники API и локальный контур обновляются в том же изменении.

## Вне целей

Общий каталог не доступен MCP для записи; новые виды групп, публикация через новые MCP-tools и семейное создание/удаление теней не добавляются. Перенос существующих операций версий, публикации и журнала меняет адресацию и область DS, но не их предметное поведение. Публичные API других подсистем, например документационные публикации, не переименовываются без зависимости от переносимых DS-маршрутов.
