## ADDED Requirements

### Requirement: Специализированные записи размеров и типографики сохраняют повторяемый ответ

В области DS, определённой `scope-design-system-routes`, PUT `/tenants/{tenantId}/size-tokens/{tokenId}/value` и PATCH `/tenants/{tenantId}/typography-styles/{tokenId}` SHALL использовать существующий механизм повторяемых команд. Пути указаны относительно `/api/projects/{projectId}/design-systems/{designSystemId}`. Отпечаток SHALL учитывать исходный DTO до нормализации и область DS. Статус, тело и технические метаданные SHALL сохраняться в предметной транзакции.

#### Scenario: Повтор после конкурентной правки

- **WHEN** завершённая запись spacing, radius, shadow или типографики повторяется с тем же ключом и телом после более поздней правки другого пользователя
- **THEN** API MUST вернуть сохранённые статус, тело и метаданные до сравнения базовых редакций
- **THEN** повтор MUST NOT перезаписать более позднюю правку или создать новые редакции и уведомления

#### Scenario: Ключ другой команды

- **WHEN** ключ завершённой записи повторяется с другим исходным телом или другой DS
- **THEN** API MUST вернуть 409 IDEMPOTENCY_KEY_REUSED без предметных изменений

#### Scenario: Повтор после перезапуска и удаления ресурса

- **WHEN** завершённая специализированная запись повторяется после перезапуска клиента и удаления её ресурса
- **THEN** API MUST использовать порядок воспроизведения зависимого change и вернуть сохранённый ответ без требования существования ресурса

#### Scenario: Запрос без ключа

- **WHEN** HTTP-клиент вызывает специализированную запись без Idempotency-Key
- **THEN** API MUST сохранить прежние правила предметной записи и базовых редакций в обязательной области DS

#### Scenario: Проверка прав при повторе

- **WHEN** завершённую команду повторяет пользователь без необходимых проектных прав
- **THEN** API MUST отказать согласно общей авторизации до выдачи сохранённого ответа
