## MODIFIED Requirements

### Requirement: Данные отдельных компонентов также загружаются лениво

Раздел компонентов SHALL сначала читать краткий список без полных конфигураций. При выборе
компонента клиент SHALL читать все его данные, включая API-мету, оформления, конфигурации,
оси и стили. Отдельная ленивость оформлений, осей и стилей не требуется. Обход всех
компонентов для подготовки списка запрещён.

Данные выбранного компонента и каждого связанного компонента превью SHALL читаться одним
запросом `GET /api/projects/{projectId}/design-systems/{designSystemId}/components/{componentId}/editor-bundle`
на компонент, а не набором списков всей дизайн-системы. Связанные компоненты SHALL загружаться
одновременно в пределах одного уровня ссылок. Разделы токенов, нужные выбранному компоненту,
SHALL читаться одновременно.

#### Scenario: Открыт список компонентов

- **WHEN** пользователь открыл раздел компонентов без выбора конкретного компонента
- **THEN** клиент MUST NOT запрашивать полные конфигурации, свойства, оси и стили всего списка

#### Scenario: Выбран компонент

- **WHEN** пользователь выбрал Web- или Compose-компонент
- **THEN** клиент MUST получить все данные выбранного компонента и необходимых зависимостей превью
- **THEN** добавление невыбранных компонентов MUST NOT увеличивать число HTTP-чтений выбранной конфигурации
- **THEN** разрешение ссылок MUST NOT использовать полную загрузку темы или всех компонентов как резервный путь

#### Scenario: Компонент без ссылок на другие компоненты

- **WHEN** пользователь выбрал ещё не загруженный компонент, который не ссылается на стили других компонентов
- **THEN** клиент MUST прочитать данные компонента одним запросом `editor-bundle` с платформой компонента и `versionId` выбранной версии, если она выбрана
- **THEN** клиент MUST NOT читать `design-system-components`, `components`, `appearances`, `property-platform-params`, `property-variations`, `component-dependencies`, `component-config/export`, `component-config/web-adapter`, свойства, вариации и стили компонента отдельными запросами

#### Scenario: Компонент ссылается на стили других компонентов

- **WHEN** выбранный компонент ссылается на стили нескольких ещё не загруженных компонентов
- **THEN** клиент MUST начать запросы `editor-bundle` для всех компонентов этого уровня ссылок одновременно, не дожидаясь каждого по очереди
- **THEN** каждый компонент MUST загружаться не больше одного раза, даже если на него ссылаются несколько компонентов
- **THEN** данные связанных компонентов MUST совмещаться в снимке так же, как при последовательной загрузке

#### Scenario: Компонент со связанными компонентами превью

- **WHEN** пользователь выбрал Web-компонент, у которого есть зависимости или родитель по `compose`
- **THEN** клиент MUST загрузить на первом уровне вместе со ссылками его зависимости и родителей по `compose`, по одному запросу `editor-bundle` на компонент
- **THEN** превью MUST получить стили этих компонентов, а не пустые записи индекса

#### Scenario: Компоненту нужны разделы токенов

- **WHEN** свойства выбранного компонента требуют нескольких ещё не загруженных разделов токенов
- **THEN** клиент MUST начать чтение всех этих разделов одновременно, не дожидаясь каждого по очереди
- **THEN** токены каждого раздела MUST оказаться в снимке после завершения чтений
- **THEN** раздел цветов MUST читаться для любого компонента, даже без цветовых свойств: фон области превью — цветовой токен

#### Scenario: Выбрано другое оформление загруженного компонента

- **WHEN** пользователь переключил оформление актуального загруженного компонента
- **THEN** клиент MUST использовать уже загруженные данные компонента без отдельного чтения оформления
