## Context

Раздел «Компоненты» скрывается сборочным флагом `VITE_COMPONENT_EDITOR_ENABLED` (`js/apps/client/src/utils/featureFlags.ts`). Значение подставляется при сборке клиента: DEV собирается с `'true'`, PROM — с `'false'`, оба значения прописаны прямо в workflow публикации, а не в GitHub Variables.

## Goals / Non-Goals

**Goals:**
- Включить раздел «Компоненты» на PROM.

**Non-Goals:**
- Удалять флаг и код, который на него опирается.
- Публиковать web-плагин превью и компоненты на стенды: это отдельные ручные шаги.

## Decisions

- **Флаг остаётся, меняется только значение PROM.** Альтернатива — убрать флаг из клиента и тестов. Она удаляет быстрый откат и затрагивает код, поэтому её откладываем до момента, когда раздел станет стабильным на проде.
- **Значение остаётся в workflow, а не в GitHub Variables.** Так флаг меняется ревьюируемым коммитом, как и раньше.

## Risks / Trade-offs

- [Раздел на PROM покажет компоненты без превью, если web-плагин превью не опубликован на стенд] → Перед выкаткой проверить, что на PROM опубликован плагин актуальной версии.
- [Изменение вступает в силу только после новой сборки и выкатки клиента PROM] → Выкатка выполняется workflow `deploy-front-apps-prom.yml` после влития.

## Rollout

Вернуть `'false'` в workflow PROM и пересобрать клиент — раздел снова скрыт, данные не затрагиваются.
