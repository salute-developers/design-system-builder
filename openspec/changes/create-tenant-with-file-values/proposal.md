## Why

Импорт дизайн-системы из файла создаёт тему, которая сразу получает около 7,4 тыс. начальных значений по профилю, а
затем перезаписывает те же значения пакетным `PUT /tenants/{id}/token-values`. Эта ручка рассчитана на правки
редактора: пишет значения по одному с проверкой базовых редакций и триггерами журнала. Импорт пишет всё дважды,
второй раз самым дорогим способом, не укладывается в таймаут шлюза (504 на стенде разработки) и заполняет журнал
черновика тысячами «изменений» новой темы.

## What Changes

- `POST /tenants` принимает необязательный список `values` в форме значений `PUT /tenants/{id}/token-values`. Значения
  из списка заменяют начальные значения профиля для своих комбинаций `tokenId + platform + mode` до записи, и тема
  создаётся одной пакетной вставкой, как сейчас.
- Значения проходят те же проверки, что пакетная запись: токены принадлежат дизайн-системе, комбинации не повторяются,
  цветовые значения допустимы для палитры темы. Ошибка откатывает создание темы целиком.
- Импорт дизайн-системы в веб-клиенте создаёт тему сразу со значениями файла и больше не вызывает
  `PUT /tenants/{id}/token-values`.
- Создание без `values` работает как раньше.
