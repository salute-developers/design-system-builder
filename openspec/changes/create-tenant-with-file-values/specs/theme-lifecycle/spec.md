## ADDED Requirements

### Requirement: Тема создаётся с переданными начальными значениями
API SHALL принимать в `POST /tenants` необязательный список `values` с элементами `tokenId`, `platform`, `mode`,
`paletteId`, `value` — в той же форме, что значения `PUT /tenants/{id}/token-values`. Переданные значения MUST заменить
начальные значения профиля для своих комбинаций `tokenId + platform + mode` и MUST быть записаны в той же транзакции
создания, что и остальные начальные значения. Остальные комбинации MUST получить значения профиля как при создании
без `values`.

#### Scenario: Тема создана со значениями файла
- **WHEN** Editor, Maintainer или Owner отправляет `POST /tenants` со списком `values`
- **THEN** `GET /tenants/{id}/token-values` возвращает переданные значения для их комбинаций и значения профиля для
  остальных
- **THEN** журнал черновика показывает создание темы одной записью, без отдельных изменений значений

#### Scenario: Переданный токен не принадлежит дизайн-системе
- **WHEN** список `values` содержит `tokenId`, которого нет в дизайн-системе темы
- **THEN** API MUST вернуть `400` с кодом `invalid_tenant_token` и MUST NOT создавать тему

#### Scenario: Комбинация повторяется
- **WHEN** список `values` содержит две записи с одинаковыми `tokenId`, `platform` и `mode`
- **THEN** API MUST вернуть `400 invalid_body` и MUST NOT создавать тему

#### Scenario: Цветовое значение недопустимо
- **WHEN** значение цветового или градиентного токена в `values` не проходит проверку, которую выполняет
  `PUT /tenants/{id}/token-values`
- **THEN** API MUST вернуть ту же ошибку проверки и MUST NOT создавать тему

#### Scenario: Список не передан
- **WHEN** `POST /tenants` не содержит `values` или содержит пустой список
- **THEN** API MUST создать тему со значениями профиля, как раньше
