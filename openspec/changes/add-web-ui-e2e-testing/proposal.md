## Зачем

Нужен исполняемый Product UI E2E и простая основа PageObjects/Steps/Helpers/Credentials/
fixtures для последующих сценариев. Прежняя инфраструктура bootstrap/journal/lock/recovery
и 175 внутренних unit-проверок была избыточной для одного пилота.

По уточнению пользователя от 28.10.2026 запуск должен обходиться без ручного projectId:
один раз заполнить credentials внутри проекта, затем выполнять npm run test:e2e.

## Что меняется

- Один Owner lifecycle через настоящий браузер, независимый GET, reload, готовый обзор,
  reopen и точечный cleanup своей системы по подтверждённому ID.
- .env.e2e.local рядом с package.json автоматически читается и игнорируется Git.
  Публичный e2e.env.example содержит пустые credentials. Env/явный dotenv остаются доступны.
- Helper находит собственный active E2E Automation по имени/владельцу; при отсутствии
  создаёт один проект публичным API. Проект сохраняется для последующих запусков.
  Ручной DSB_E2E_PROJECT_ID исключён; неоднозначный выбор даёт отказ.
- Docker/seed/миграции, создание пользователей, постоянные журналы/lock/recovery,
  отдельный infrastructure unit-набор и CI не входят в пилот.
- Старые runtime journals/credentials/evidence сохраняются. Изменяются тестовые
  файлы/документация, без изменений API, схем, зависимостей и protected gates.

## Возможности

Новая возможность: web-ui-e2e-testing — локальные браузерные проверки пользовательского
результата на готовом стенде с собственными данными и ограниченной очисткой.
Изменённая возможность: web-projects-workflow — возврат клавиатурного фокуса
на «Создать проект» после закрытия окна. Правила доступа и продуктовые API
не меняются.

## Влияние

js/apps/client: тестовая конфигурация, helpers/fixtures/Page Objects, пять
E2E-spec-файлов с десятью сценариями, инструкции и исправление возврата фокуса.
Тестовая инфраструктура остаётся в анализе Strictacode с прежними baseline/порогами. Ручные проверки DTO заменяются содержательными штатными assertions без ослабления контрактов; дублирующиеся обёртки и повторный путь cleanup удаляются. Файлы не переименовываются и не переносятся ради обхода анализатора.
Тестовые данные: один переиспользуемый выделенный проект и временная система на прогон.
Проект и исходные системы сохраняются; создаваемая тестом система удаляется.
Windows/macOS используют общие исходники и команды. Приёмка включает реальные прогоны;
недоступный стенд не считается успехом. Commit/push/PR/archive не выполняются автоматически.
