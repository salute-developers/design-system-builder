# Задачи

## 1. Версия и локальные дистрибутивы

- [ ] 1.1 Передавать версию релизной сборки из проверенного тега в CLI; проверить тестами неправильный тег, локальное значение и соответствие `--version`.
- [ ] 1.2 Дополнить упаковку четырёх ZIP локальными установщиками, добавить JVM shell-установщик; проверить структуру, bin/lib и права архивов Gradle-проверкой.
- [ ] 1.3 Переиспользовать локальные установщики из локального контура; проверить установку без сети, повтор, PATH, пути с пробелами и восстановление предыдущей установки при сбое shell/PowerShell-тестами.

## 2. Сетевые установщики

- [ ] 2.1 Создать shell/PowerShell установщики в `distribution/bootstrap/` с выбором версии/платформы и проверкой Java для JVM; проверить тестами матрицу выбора и отказ неподдерживаемых ОС/архитектур.
- [ ] 2.2 Реализовать манифесты, скачивание, SHA-256, безопасную распаковку, вызов локального уровня и очистку временных файлов; проверить локальным HTTP-сервером 404, неверный манифест, hash mismatch, отсутствие инструментов и сохранение установленного CLI.

## 3. Доставка

- [ ] 3.1 Расширить релизный workflow сборкой четырёх дистрибутивов, манифестами и SHA256SUMS; проверить YAML и сборку всех задач без публикации.
- [ ] 3.2 Переиспользовать AWS secrets публикации клиента и добавить только GitHub vars CLI_S3_PREFIX/CLI_DOWNLOAD_BASE_URL, подстановку URL в сетевые скрипты, неизменяемые версии и последовательное обновление stable; проверить на тестовом S3-совместимом хранилище полный выпуск, повтор, конфликт SHA-256, прерванную загрузку и запрет понижения версии.
- [ ] 3.3 Сохранить GitHub Releases JVM asset и его имя; проверить сформированные команды и совместимость структуры с потребителем, не меняя plasma-android.

## 4. Комплексная проверка

- [ ] 4.1 Выполнить `tools/verify fast --change publish-cli-distributions`, независимое review и `tools/verify full --change publish-cli-distributions`; сохранить результаты, включая Gradle build/test/Detekt/Spotless.
- [ ] 4.2 [внешняя проверка] На macOS arm64/x64, Windows x64 и Linux с Java 17 установить собранные ZIP в временные пользовательские каталоги; проверить `--help`, `--version` и локальную установку без сети, сохранить команды и exit codes. Недоступная ОС означает незавершённую проверку.

## Дальнейшие действия процесса

- После проверок архивировать Change через OPSX: Archive и проверить общие спецификации.
- Настройку реального S3/nginx и проверку первого опубликованного выпуска выполняет разработчик после развёртывания; пользовательская инструкция создаётся другой задачей.
- Оставить результат незакоммиченным для человеческого review; публикация требует отдельного запроса.
