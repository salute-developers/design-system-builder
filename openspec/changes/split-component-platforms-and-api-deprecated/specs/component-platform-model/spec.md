## ADDED Requirements

### Requirement: Component identity includes the platform

Компонент SHALL идентифицироваться парой `(name, platform)`, где `platform` принимает значения `web`, `compose`, `xml`, `ios` и обязательна. `components.name` MUST NOT быть уникальным глобально. Свойства, состояния, вариации, конфиги оформления, значения конфигов и зависимости компонента SHALL принадлежать компоненту конкретной платформы и MUST NOT разделяться между платформами.

#### Scenario: Один компонент на двух платформах

- **WHEN** в базе есть `Avatar` для `compose` и `Avatar` для `xml`
- **THEN** это MUST быть две разные строки `components` со своими свойствами, состояниями и вариациями

#### Scenario: Дубликат в пределах платформы

- **WHEN** создаётся второй компонент с тем же `(name, platform)`
- **THEN** БД MUST отклонить запись

#### Scenario: Платформа обязательна

- **WHEN** создаётся компонент без `platform`
- **THEN** БД MUST отклонить запись

### Requirement: Single platform vocabulary for components

Платформа компонентов, свойств и алиасов SHALL браться из одного словаря `web`, `compose`, `xml`, `ios`. У свойства и конфига оформления MUST NOT быть собственной колонки платформы: платформа определяется компонентом. Платформа значений токенов (`token_values.platform`) этим словарём не меняется.

#### Scenario: У свойства нет собственной платформы

- **WHEN** свойство читается из БД
- **THEN** его платформа MUST определяться через компонент

#### Scenario: Конфиги разных платформ не конфликтуют

- **WHEN** для одной дизайн-системы есть конфиг `default` компонента `Avatar` на `web` и на `compose`
- **THEN** это MUST быть два appearance двух разных компонентов и запись одного MUST NOT затирать другой

### Requirement: Alias platform matches the component platform

Платформа алиаса `property_platform_params` SHALL совпадать с платформой компонента его свойства.

#### Scenario: Алиас чужой платформы

- **WHEN** создаётся алиас с платформой, не совпадающей с платформой компонента свойства
- **THEN** БД MUST отклонить запись

### Requirement: Design system links point to platform components

Привязка дизайн-системы SHALL указывать на компонент конкретной платформы; набор платформ дизайн-системы MUST определяться платформами её компонентов.

#### Scenario: Привязка к компоненту платформы

- **WHEN** дизайн-система привязывается к `Avatar` платформы `compose`
- **THEN** привязка MUST ссылаться на строку `Avatar[compose]` и MUST NOT распространяться на `Avatar[xml]`

### Requirement: Platform is explicit in component requests

Запросы, выбирающие компонент по имени (конфиги компонентов, push, fetch, чтение компонента), SHALL содержать платформу. Backend MUST отвечать `400` на запрос без платформы и MUST NOT выбирать платформу по умолчанию.

#### Scenario: Запрос без платформы

- **WHEN** запрос на push или fetch конфигураций не содержит `platform`
- **THEN** backend MUST ответить `400` с указанием на отсутствие платформы и MUST NOT изменить данные

#### Scenario: Запрос с платформой

- **WHEN** запрос содержит `platform`
- **THEN** backend MUST искать компонент по `(name, platform)` и MUST NOT использовать компонент другой платформы

### Requirement: Deprecation is stored on the platform alias

`property_platform_params` SHALL хранить `deprecated` (boolean, по умолчанию `false`) и `deprecated_message` (text). `deprecated_message` MUST быть `NULL`, если `deprecated` равно `false`. Пустая строка при `deprecated = true` MUST быть допустимой и означать устаревший алиас без сообщения.

#### Scenario: Алиас устарел с сообщением

- **WHEN** алиас помечен устаревшим с сообщением
- **THEN** `deprecated` MUST быть `true`, а `deprecated_message` MUST содержать сообщение

#### Scenario: Алиас устарел без сообщения

- **WHEN** алиас помечен устаревшим с пустым сообщением
- **THEN** `deprecated` MUST быть `true`, а `deprecated_message` MUST быть пустой строкой, а не `NULL`

#### Scenario: Сообщение у неустаревшего алиаса

- **WHEN** запись имеет `deprecated = false` и непустое `deprecated_message`
- **THEN** БД MUST отклонить запись

#### Scenario: Статус устаревания у View выставляется по алиасу

- **WHEN** у свойства View два алиаса и устарел только один
- **THEN** второй алиас MUST остаться неустаревшим

### Requirement: Data migration preserves design system content

Миграция данных SHALL раскладывать существующие компоненты по платформам, сохраняя идентификаторы строк, на которые ссылается контент дизайн-систем, и MUST завершаться ошибкой с откатом при нарушении инвариантов раскладки. Правила раскладки MUST быть такими:

- компонент с веб-признаком (свойство `platform = web`, appearance `web` или алиас `web`) остаётся строкой с прежним идентификатором и получает платформу `web`; все его appearances, значения, вариации, стили, состояния и зависимости остаются на нём;
- для каждой нативной платформы (`compose`, `xml`, `ios`), по алиасам которой у компонента есть данные, создаётся компонент этой платформы; компонент без веб-признака сохраняет идентификатор и получает первую нативную платформу в порядке `compose`, `xml`, `ios`;
- нативное свойство (платформа `NULL`) переносится в компонент первой платформы среди своих алиасов, а в компонентах остальных платформ его алиасов создаются копии с теми же `name`, `type`, `default_value`, `description` и алиасами своей платформы;
- веб-свойство с нативными алиасами остаётся на веб-компоненте, а его нативные алиасы удаляются;
- appearances без платформы остаются на нативной строке компонента либо переносятся на компонент первой нативной платформы, если оригинал веб;
- привязки дизайн-системы без appearances переносятся на компонент первой нативной платформы компонента.

#### Scenario: Контент веба не меняется

- **WHEN** миграция применена к базе с веб-контентом
- **THEN** число appearances, вариаций, стилей и значений конфигов MUST совпадать с числом до миграции
- **THEN** их идентификаторы и ссылки на компонент и свойства MUST остаться прежними

#### Scenario: Нативные платформы разнесены

- **WHEN** у компонента есть алиасы `compose` и `xml`
- **THEN** после миграции MUST существовать компонент `compose` и компонент `xml`, а свойство с алиасами обеих платформ MUST присутствовать в обоих компонентах

#### Scenario: Общее веб-свойство теряет нативные алиасы

- **WHEN** веб-свойство имеет алиас `compose`
- **THEN** алиас `compose` MUST быть удалён
- **THEN** свойство и его веб-алиасы MUST остаться без изменений

#### Scenario: Нарушение инварианта откатывает миграцию

- **WHEN** после раскладки остался компонент без платформы либо алиас, чья платформа не совпадает с платформой компонента
- **THEN** миграция MUST завершиться ошибкой и MUST NOT изменить данные
