# ai-agent-tooling Specification

## Purpose
Определяет цикл агента встроенного ИИ-чата и его инструменты: собственный каталог поверх use case ds-service внутри монолита, отбор по разрешениям, контекст вызова, историю для модели и эталонные сценарии.
## Requirements
### Requirement: Каталог инструментов чата

Подсистема ИИ-ассистента SHALL объявлять инструменты в собственном каталоге: имя, описание, JSON Schema аргументов, разрешение и вид операции (чтение, запись, удаляющая). Выполнение SHALL идти через порт `ChatToolExecutor`, реализованный адаптером монолита к use case ds-service. Подсистема MUST NOT зависеть от `frontend-kt/mcp-server-core` и от модулей ds-service, а адаптер MUST NOT содержать предметных правил: проверки прав, ревизий, повторяемости и данных остаются в use case.

#### Scenario: Сверка каталога при запуске
- **WHEN** монолит запускается с `AI_ENABLED=true`, и для инструмента каталога нет обработчика в адаптере
- **THEN** приложение MUST NOT открывать готовность и MUST назвать инструмент

#### Scenario: Расхождение с MCP
- **WHEN** у инструмента MCP с тем же именем другая схема или описание
- **THEN** каталог чата MUST оставаться прежним, и подсистема MUST работать без изменений

### Requirement: Отобранный набор инструментов

Агенту SHALL быть доступны только инструменты каталога. Каждый инструмент MUST передаваться модели, только если `PolicyEvaluator` разрешает участнику проекта его точное разрешение. Удаляющие инструменты MUST требовать подтверждения. Вызов вне каталога или без разрешения MUST отклоняться без обращения к адаптеру.

#### Scenario: Модель запросила инструмент вне каталога
- **WHEN** модель вернула вызов `token_delete`
- **THEN** агент MUST NOT вызывать адаптер и MUST вернуть модели результат с `isError: true` и кодом `tool_not_allowed`

#### Scenario: Отбор по точному разрешению
- **WHEN** `PolicyEvaluator` разрешает участнику `components:variations:write`, но не `components:variations:delete`
- **THEN** `component_property_set` MUST передаваться модели, а `component_property_reset` MUST NOT передаваться и MUST отклоняться при прямом вызове

#### Scenario: Поиск по документации недоступен
- **WHEN** модель запрашивает `documentation_search`
- **THEN** агент MUST отклонить вызов с `tool_not_allowed`, пока поиск не проверяет принадлежность публикации к DS чата

### Requirement: Контекст вызова инструмента

DS, версия, ключ идемпотентности и ожидаемый черновик SHALL задаваться сервером и SHALL отсутствовать в схемах для модели. Адаптер MUST вызывать use case с участником проекта из запроса, начавшего ход, и DS этого хода; чтение MUST идти из черновика, а запись MUST NOT задавать версию и MUST попадать в активный черновик. Каждый вызов записи MUST получать новый ключ идемпотентности, а ожидаемый черновик MUST передаваться только у подтверждённой операции. Одноимённые поля, присланные моделью, MUST отбрасываться. Аргументы MUST проверяться по схеме каталога до обращения к адаптеру.

#### Scenario: Модель указала другую дизайн-систему
- **WHEN** аргументы модели содержат поле `designSystemId` или `designSystem` с другой DS
- **THEN** use case MUST выполниться в DS хода

#### Scenario: Аргументы не проходят схему
- **WHEN** у вызова нет обязательного аргумента или у аргумента неверный тип
- **THEN** агент MUST вернуть модели `isError: true` с кодом `invalid_arguments` без обращения к адаптеру

#### Scenario: Повтор записи с тем же ключом
- **WHEN** адаптер повторно выполняет запись с тем же ключом идемпотентности и той же командой
- **THEN** `tool_result` MUST содержать сохранённый результат первой записи без ошибки, и вторая запись MUST NOT появиться

#### Scenario: Повтор создания с тем же ключом
- **WHEN** адаптер повторно выполняет `component_axis_value_create` с тем же ключом
- **THEN** use case создания MUST вернуть сохранённый результат по своим правилам повторяемости, и второго значения MUST NOT появиться

#### Scenario: Вызов не уложился в срок
- **WHEN** запись инструмента не завершилась за `AI_TOOL_CALL_TIMEOUT_SECONDS`
- **THEN** ход MUST получить `OUTCOME_UNKNOWN` в срок, не дожидаясь транзакции, а слот пользователя MUST освободиться по завершении хода

#### Scenario: Отказ use case по правам
- **WHEN** вызов дошёл до адаптера, но use case отказал участнику в праве
- **THEN** `tool_result` MUST содержать `isError: true` и `code: "FORBIDDEN"`, а данные MUST NOT измениться

#### Scenario: Конфликт ревизии
- **WHEN** запись отклонена из-за устаревшей ревизии
- **THEN** агент MUST вернуть ошибку модели без автоматического повтора
- **THEN** новый вызов модели после перечитывания MUST получить новый ключ идемпотентности

### Requirement: Последовательное выполнение вызовов

Агент SHALL выполнять вызовы инструментов по одному в порядке ответа модели. Если ответ содержит вызов, требующий подтверждения, вызовы до него MUST выполняться, а он и последующие MUST NOT выполняться до решения пользователя.

#### Scenario: Несколько вызовов в одном ответе
- **WHEN** модель вернула три вызова, второй из которых требует подтверждения
- **THEN** агент MUST выполнить первый вызов, отправить `confirmation_required` для второго и MUST NOT выполнять третий
- **THEN** `state` MUST содержать только выполненный вызов и ожидающий подтверждения

### Requirement: Ограничение истории для модели

Перед каждым обращением к модели агент SHALL укладывать историю в `AI_HISTORY_MAX_CHARS`. Результат одного инструмента для модели MUST ограничиваться `AI_TOOL_RESULT_MAX_CHARS`. Сначала сокращается текст старых результатов инструментов, затем старые реплики. Сообщение с результатом инструмента MUST NOT удаляться при сокращении: его текст заменяется пометкой о сокращении. Системный промпт и последнее сообщение пользователя MUST NOT сокращаться.

#### Scenario: Длинный разговор
- **WHEN** история превышает лимит
- **THEN** модель MUST получить историю не длиннее лимита с последним сообщением пользователя без изменений
- **THEN** у каждого вызова инструмента в истории MUST оставаться сообщение с его результатом

#### Scenario: Много вызовов в одном ходе
- **WHEN** результаты вызовов текущего хода не помещаются в лимит даже после сокращения прошлых ходов
- **THEN** модель MUST получить ранние результаты текущего хода с пометкой о сокращении, а последний результат — целиком, и ход MUST продолжиться без `context_overflow`

#### Scenario: Длинный результат инструмента
- **WHEN** инструмент вернул результат длиннее `AI_TOOL_RESULT_MAX_CHARS`
- **THEN** модель MUST получить результат не длиннее лимита с пометкой о сокращении

### Requirement: Эталонные сценарии

Подсистема SHALL содержать набор эталонных сценариев и задачу Gradle, которая прогоняет их против настроенного провайдера и локального контура и сообщает результат по каждому сценарию.

#### Scenario: Проверка новой модели
- **WHEN** разработчик меняет `AI_MODEL` и запускает задачу проверки
- **THEN** задача MUST вывести для каждого сценария «прошёл» или «не прошёл» и причину
- **THEN** сценарии MUST включать изменение цвета свойства компонента, изменение значения размера, вопрос без изменений и сброс свойства от maintainer с ожиданием подтверждения

#### Scenario: Нет ключа или контура
- **WHEN** задача запущена без ключа провайдера или без доступного локального контура
- **THEN** задача MUST завершиться ошибкой, а не пропуском сценариев
