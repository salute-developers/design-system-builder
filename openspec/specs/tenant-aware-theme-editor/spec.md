## Requirements
### Requirement: Маршрут редактора однозначно выбирает tenant

Веб-клиент SHALL открывать существующий редактор по стабильным `projectId`, `designSystemId` и `tenantId`, не используя имя или версию темы как идентификатор.

#### Scenario: Тема открыта из обзора дизайн-системы

- **WHEN** пользователь выбирает карточку tenant
- **THEN** клиент MUST перейти на маршрут с `projectId`, `designSystemId` и `tenantId`
- **THEN** обновление страницы MUST снова открыть тот же tenant

#### Scenario: Tenant не принадлежит дизайн-системе

- **WHEN** маршрут содержит `tenantId`, не принадлежащий указанному `designSystemId`
- **THEN** клиент MUST показать состояние отсутствующей темы
- **THEN** клиент MUST NOT подставлять первый tenant дизайн-системы

### Requirement: Редактор собирает модель выбранной темы

Веб-клиент SHALL загружать общие определения токенов и компонентные настройки дизайн-системы отдельно от значений выбранного tenant.

#### Scenario: Данные редактора загружены

- **WHEN** пользователь открывает существующий tenant
- **THEN** клиент MUST загрузить метаданные дизайн-системы, определения токенов и компонентные настройки по `designSystemId`
- **THEN** клиент MUST загрузить метаданные tenant и значения токенов по `tenantId`
- **THEN** клиент MUST собрать существующие объекты редактора только после проверки связи tenant с дизайн-системой

#### Scenario: У выбранного tenant отсутствует значение

- **WHEN** для общего определения токена отсутствует значение выбранного tenant
- **THEN** клиент MUST показать контролируемое состояние неполных данных
- **THEN** клиент MUST NOT использовать значение другого tenant

#### Scenario: Пользователь переключает темы

- **WHEN** пользователь переходит с одного `tenantId` на другой
- **THEN** клиент MUST синхронно записать локальный черновик прежнего tenant до освобождения его состояния
- **THEN** клиент MUST сбросить вычисленное состояние прежней темы и отменить либо проигнорировать её устаревшие ответы
- **THEN** интерфейс MUST показывать только данные нового tenant

### Requirement: Черновики редактора изолированы по tenant

Локальные несохранённые изменения SHALL храниться с ключом, включающим `projectId`, `designSystemId` и `tenantId`.

#### Scenario: Две темы имеют несохранённые изменения

- **WHEN** пользователь изменяет одинаковый токен в двух tenant одной дизайн-системы
- **THEN** клиент MUST хранить два независимых набора изменений
- **THEN** открытие одного tenant MUST NOT применять черновик другого

#### Scenario: Пользователь возвращается к теме

- **WHEN** пользователь возвращается к tenant после редактирования другого tenant
- **THEN** клиент MUST загрузить актуальный серверный снимок выбранного tenant
- **THEN** клиент MUST применить поверх него только сохранённый локальный черновик этого tenant
- **THEN** несохранённые изменения MUST быть восстановлены в редакторе

#### Scenario: Изменения темы сохранены

- **WHEN** сохранение выбранного tenant успешно завершено
- **THEN** клиент MUST очистить только локальный черновик этого tenant
- **THEN** черновики остальных tenant MUST сохраниться

### Requirement: Значения одного выбранного tenant сохраняются пакетно и атомарно

API SHALL предоставлять tenant-scoped операцию пакетного сохранения набора значений токенов одного tenant, а веб-клиент SHALL использовать её вместо отдельного запроса на каждое значение.

#### Scenario: Editor сохраняет тему

- **WHEN** Editor, Maintainer или Owner сохраняет изменения выбранной темы
- **THEN** клиент MUST отправить `tenantId`, текущий `editRevision` и полный согласованный набор изменённых значений одним запросом
- **THEN** API MUST проверить, что все `tokenId` принадлежат дизайн-системе tenant
- **THEN** API MUST атомарно применить значения только к выбранному tenant
- **THEN** API MUST увеличить и вернуть `editRevision`

#### Scenario: Платформенные значения сохраняются раздельно

- **WHEN** пакет содержит значения одного токена для `web`, `ios` или `android` и режимов Light или Dark
- **THEN** API MUST различать строки по `tokenId + tenantId + platform + mode`
- **THEN** сохранение одной комбинации MUST NOT подменять значение другой платформы или режима

#### Scenario: Одно значение пакета невалидно

- **WHEN** хотя бы одно значение пакетного запроса не прошло проверку
- **THEN** API MUST отклонить весь запрос без частичного изменения значений tenant

#### Scenario: Сохраняется одна из двух тем

- **WHEN** пользователь сохраняет tenant A в дизайн-системе, также содержащей tenant B
- **THEN** значения tenant B MUST остаться без изменений

#### Scenario: Viewer открывает редактор

- **WHEN** Viewer открывает тему
- **THEN** клиент MUST показать редактор в режиме чтения
- **THEN** клиент MUST NOT показывать действия сохранения или изменения данных

### Requirement: Конкурентное редактирование одного tenant не теряет изменения незаметно

Система SHALL использовать технический `editRevision` для оптимистичной блокировки сохранения одного tenant и SHALL NOT представлять его пользователю как версию Theme.

#### Scenario: Два редактора изменяют разные tenant

- **WHEN** два редактора одновременно сохраняют разные tenant одной дизайн-системы с актуальными `editRevision`
- **THEN** оба сохранения MUST завершиться независимо
- **THEN** изменение одного tenant MUST NOT изменить ревизию или значения другого tenant

#### Scenario: Второй редактор сохраняет устаревший снимок того же tenant

- **WHEN** один редактор уже сохранил tenant и увеличил `editRevision`, а второй отправляет прежнюю ревизию
- **THEN** API MUST вернуть `409 Conflict` с кодом `TENANT_EDIT_CONFLICT`
- **THEN** API MUST NOT частично применять значения второго запроса
- **THEN** ответ MUST сообщить актуальный `editRevision`

#### Scenario: Клиент получает конфликт редактирования

- **WHEN** пакетное сохранение возвращает `TENANT_EDIT_CONFLICT`
- **THEN** клиент MUST сохранить локальный черновик
- **THEN** клиент MUST предложить перезагрузить актуальные данные и повторить изменения
- **THEN** клиент MUST NOT выполнять автоматическое слияние или повторную отправку поверх новой ревизии

### Requirement: Theme не получает отдельную версию

Веб-клиент SHALL считать `editRevision` техническим счётчиком конкурентного сохранения и SHALL NOT представлять его как версию Theme. Изменение legacy-сценария публикации npm-пакета и создание публикационной версии не входят в эту capability.

#### Scenario: Интерфейс редактора показывает данные Theme

- **WHEN** пользователь открывает выбранный tenant в редакторе
- **THEN** клиент MUST NOT показывать `editRevision` или иной номер как версию отдельной Theme
- **THEN** существующая модель версий дизайн-системы MUST NOT копироваться в tenant
