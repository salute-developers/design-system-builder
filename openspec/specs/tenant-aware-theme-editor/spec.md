## Requirements
### Requirement: Маршрут редактора однозначно выбирает tenant

Веб-клиент SHALL открывать существующий редактор по стабильным `projectId`, `designSystemId` и `tenantId`, не используя имя или версию темы как идентификатор.

#### Scenario: Тема открыта из обзора дизайн-системы

- **WHEN** пользователь выбирает карточку tenant
- **THEN** клиент MUST перейти на маршрут с `projectId`, `designSystemId` и `tenantId`
- **THEN** обновление страницы MUST снова открыть тот же tenant

#### Scenario: Tenant не принадлежит дизайн-системе

- **WHEN** маршрут содержит `tenantId`, не принадлежащий указанному `designSystemId`
- **THEN** клиент MUST показать состояние отсутствующей темы
- **THEN** клиент MUST NOT подставлять первый tenant дизайн-системы

### Requirement: Редактор собирает модель выбранной темы

Веб-клиент SHALL загружать общие определения токенов и компонентные настройки дизайн-системы отдельно от значений
выбранного tenant и SHALL учитывать выбранную версию дизайн-системы.

#### Scenario: Данные редактора загружены

- **WHEN** пользователь открывает существующий tenant без `versionId`
- **THEN** клиент MUST загрузить метаданные дизайн-системы, определения токенов и компонентные настройки активного
  черновика по `designSystemId`
- **THEN** клиент MUST загрузить метаданные tenant и значения токенов по `tenantId`
- **THEN** клиент MUST собрать объекты редактора только после проверки связи tenant с дизайн-системой

#### Scenario: Данные опубликованной версии загружены

- **WHEN** пользователь открывает tenant с `versionId` опубликованной версии
- **THEN** клиент MUST передать `versionId` всем предметным запросам данных дизайн-системы
- **THEN** клиент MUST показать редактор в режиме только для чтения
- **THEN** клиент MUST NOT отправлять изменяющие запросы

#### Scenario: У выбранного tenant отсутствует значение

- **WHEN** для общего определения токена отсутствует значение выбранного tenant на выбранной границе
- **THEN** клиент MUST показать контролируемое состояние неполных данных
- **THEN** клиент MUST NOT использовать значение другого tenant или другой версии

#### Scenario: Пользователь переключает темы

- **WHEN** пользователь переходит с одного `tenantId` на другой
- **THEN** клиент MUST дождаться либо сохранить сведения о неподтверждённых запросах прежнего tenant
- **THEN** клиент MUST сбросить вычисленное состояние прежней темы и отменить либо проигнорировать её устаревшие ответы
- **THEN** интерфейс MUST показывать только серверное состояние нового tenant

### Requirement: Значения одного выбранного tenant сохраняются пакетно и атомарно

API SHALL сохранять пакет значений токенов одного tenant одной транзакцией, а веб-клиент SHALL автоматически вызывать
существующую tenant-scoped операцию после изменения данных вместо отдельного явного сохранения всего редактора.

#### Scenario: Editor сохраняет тему

- **WHEN** Editor, Maintainer или Owner изменяет одно или несколько значений выбранной темы
- **THEN** клиент MUST отправить `tenantId`, базовые редакции затронутых логических значений и согласованный набор
  намеренно изменённых значений одним запросом
- **THEN** API MUST проверить, что все `tokenId` принадлежат дизайн-системе tenant
- **THEN** API MUST атомарно применить значения только к выбранному tenant активного черновика
- **THEN** API MUST вернуть актуальные значения и их технические редакции

#### Scenario: Открытый журнал наблюдает успешное автосохранение

- **WHEN** журнал черновика открыт и автосохранение значения успешно завершилось
- **THEN** клиент MUST перечитать журнал без закрытия и повторного открытия панели

#### Scenario: Платформенные значения сохраняются раздельно

- **WHEN** пакет содержит значения одного токена для `web`, `ios` или `android` и режимов Light или Dark
- **THEN** API MUST различать логические сущности по `tokenId + tenantId + platform + mode`
- **THEN** сохранение одной комбинации MUST NOT изменить редакцию другой платформы или режима

#### Scenario: Клиент пытается изменить платформу или режим значения

- **WHEN** изменяющий запрос существующего значения содержит другие `platform` или `mode`
- **THEN** API MUST отклонить изменение неизменяемого ключа
- **THEN** клиент MUST использовать существующие операции удаления и создания другого значения

#### Scenario: Клиент повторно создаёт удалённую комбинацию

- **WHEN** устойчивое значение с теми же `tokenId`, `tenantId`, `platform`, `mode` существует с последней редакцией `deleted = true`
- **THEN** API MUST использовать прежний устойчивый идентификатор
- **THEN** API MUST создать редакцию активного черновика с `deleted = false` и новым значением

#### Scenario: Одно значение пакета невалидно

- **WHEN** хотя бы одно значение пакетного запроса не прошло проверку
- **THEN** API MUST отклонить весь запрос без частичного изменения значений tenant

#### Scenario: Сохраняется одна из двух тем

- **WHEN** пользователь изменяет tenant A в дизайн-системе, также содержащей tenant B
- **THEN** значения и технические редакции tenant B MUST остаться без изменений

#### Scenario: Viewer открывает редактор

- **WHEN** Viewer открывает тему
- **THEN** клиент MUST показать редактор в режиме чтения
- **THEN** клиент MUST NOT отправлять изменяющие запросы

### Requirement: Конкурентное редактирование одного tenant не теряет изменения незаметно

Система SHALL назначать техническую редакцию каждому логическому значению tenant и SHALL NOT представлять её
пользователю как версию Theme.

#### Scenario: Два редактора изменяют разные tenant

- **WHEN** два редактора одновременно изменяют разные tenant одной дизайн-системы
- **THEN** оба сохранения MUST завершиться независимо
- **THEN** изменение одного tenant MUST NOT изменить редакции или значения другого tenant

#### Scenario: Редакторы изменяют разные значения одного tenant

- **WHEN** запрос основан на устаревшей редакции другого логического значения tenant
- **THEN** API MUST применить изменение без `TENANT_EDIT_CONFLICT`
- **THEN** API MUST сохранить уже подтверждённое значение другого пользователя

#### Scenario: Второй редактор сохраняет устаревший снимок того же tenant

- **WHEN** второй запрос изменяет путь, уже изменённый после его базовой редакции
- **THEN** API MUST применить последнюю успешно зафиксированную запись
- **THEN** ответ MUST содержать машиночитаемое предупреждение и актуальную редакцию
- **THEN** первая версия интерфейса MAY не показывать предупреждение пользователю

#### Scenario: Клиент получает конфликт редактирования

- **WHEN** клиент пытается откатить изменение tenant с неактуальной редакцией
- **THEN** API MUST вернуть `409 Conflict` с кодом `DRAFT_CHANGE_STALE`
- **THEN** клиент MUST обновить журнал без автоматического повторения отката

### Requirement: Theme не получает отдельную версию

Веб-клиент SHALL считать `editRevision` техническим счётчиком конкурентного сохранения и SHALL NOT представлять его как версию Theme. Изменение legacy-сценария публикации npm-пакета и создание публикационной версии не входят в эту capability.

#### Scenario: Интерфейс редактора показывает данные Theme

- **WHEN** пользователь открывает выбранный tenant в редакторе
- **THEN** клиент MUST NOT показывать `editRevision` или иной номер как версию отдельной Theme
- **THEN** существующая модель версий дизайн-системы MUST NOT копироваться в tenant

### Requirement: Цветовые токены tenant сохраняются операциями над отдельным токеном

Веб-клиент SHALL сохранять правки цветов и градиентов выбранной темы автоматически существующими
атомарными операциями над токеном с предметными редакциями. Он SHALL NOT сохранять их во втором
локальном черновике или отправлять полную замену всех значений темы.

#### Scenario: Пользователь меняет цветовой токен

- **WHEN** Editor, Maintainer или Owner меняет значение цветового токена
- **THEN** клиент MUST отправить только предметное изменение этого токена с редакциями и ключом повторяемости
- **THEN** клиент MUST NOT записывать подтверждённое значение в локальный черновик темы

#### Scenario: Цвета и черновик других разделов

- **WHEN** в очереди другой секции есть неподтверждённые изменения, а цвет сохранён автоматически
- **THEN** другая очередь MUST сохранить свои изменения
- **THEN** публикация и фоновое обновление MUST учитывать обе очереди и не отправлять устаревшие цвета

#### Scenario: Viewer открывает тему

- **WHEN** Viewer открывает тему или выбран `versionId` опубликованной версии
- **THEN** клиент MUST NOT отправлять операции над цветовыми токенами

### Requirement: Загрузка темы не падает на определениях без значений

Веб-клиент SHALL загружать тему, в которой у определения токена дизайн-системы нет значений выбранного
tenant, и SHALL показывать такой токен как неполный.

#### Scenario: У токена нет значений в теме

- **WHEN** определение цветового токена есть в дизайн-системе, а значений выбранного tenant нет
- **THEN** клиент MUST открыть тему и показать токен с отметкой «Нет значений в этой теме»
- **THEN** клиент MUST позволить заполнить Light и Dark и сохранить их операцией изменения значений
- **THEN** клиент MUST NOT подставлять значения другого tenant

### Requirement: Редактор принимает адрес предметного источника из журнала

Веб-клиент SHALL поддерживать адресуемое открытие токена или компонента из журнала дизайн-системы и SHALL сохранять
границу исторического чтения.

#### Scenario: Открывается конкретный токен

- **WHEN** маршрут редактора токенов содержит `tokenId` существующего токена выбранной дизайн-системы
- **THEN** клиент MUST открыть соответствующий раздел, выбрать токен после загрузки данных и сделать его видимым
- **THEN** обновление страницы MUST восстановить тот же выбор

#### Scenario: Открывается конкретный компонент

- **WHEN** маршрут содержит имя существующего компонента выбранной дизайн-системы
- **THEN** клиент MUST открыть редактор этого компонента
- **THEN** обновление страницы MUST восстановить тот же выбор

#### Scenario: Источник открыт из опубликованного журнала

- **WHEN** переход к токену или компоненту содержит `versionId`
- **THEN** клиент MUST сохранить `versionId` во всех последующих предметных запросах и переходах внутри редактора
- **THEN** редактор MUST оставаться в режиме только для чтения

#### Scenario: Указанный токен отсутствует

- **WHEN** `tokenId` не существует на выбранной временной границе
- **THEN** клиент MUST открыть соответствующий раздел без произвольного выбора другого токена как источника
- **THEN** клиент MUST показать, что точный источник недоступен

### Requirement: Данные разделов редактора загружаются по потребности

Оболочка SHALL читать только лёгкие метаданные навигации, доступа, выбранной границы и
счётчика изменений. Каждый обычный раздел SHALL загружать целиком свои данные при открытии,
включая все его платформы и режимы, без чтения остальных разделов за исключением необходимых
общих данных. Полный журнал SHALL NOT читаться ради счётчика.
Изменение загрузки кода разделов не требуется.

#### Scenario: Прямой вход в цветовые токены

- **WHEN** пользователь открывает цветовые токены темы при включённом редакторе компонентов
- **THEN** клиент MUST загрузить оболочку и данные цветового раздела с его необходимыми зависимостями
- **THEN** клиент MUST NOT читать конфигурации, свойства, оси и стили компонентов или значения остальных разделов
- **THEN** rail и счётчик MUST NOT зависеть от загрузки конфигураций и полного журнала

#### Scenario: Переход между разделами

- **WHEN** пользователь переходит в типографику, размеры, палитру, журнал, версии или настройки
- **THEN** выбранный раздел MUST загрузить целиком свои данные, если они ещё не загружены либо устарели
- **THEN** остальные разделы MUST NOT начинать чтения без фактической зависимости
- **THEN** ошибка одного раздела MUST NOT скрывать оболочку и блокировать остальные разделы

### Requirement: Данные отдельных компонентов также загружаются лениво

Раздел компонентов SHALL сначала читать краткий список без полных конфигураций. При выборе
компонента клиент SHALL читать все его данные, включая API-мету, оформления, конфигурации,
оси и стили. Отдельная ленивость оформлений, осей и стилей не требуется. Обход всех
компонентов для подготовки списка запрещён.

#### Scenario: Открыт список компонентов

- **WHEN** пользователь открыл раздел компонентов без выбора конкретного компонента
- **THEN** клиент MUST NOT запрашивать полные конфигурации, свойства, оси и стили всего списка

#### Scenario: Выбран компонент

- **WHEN** пользователь выбрал Web- или Compose-компонент
- **THEN** клиент MUST получить все данные выбранного компонента и необходимых зависимостей превью
- **THEN** добавление невыбранных компонентов MUST NOT увеличивать число HTTP-чтений выбранной конфигурации
- **THEN** разрешение ссылок MUST NOT использовать полную загрузку темы или всех компонентов как резервный путь

#### Scenario: Выбрано другое оформление загруженного компонента

- **WHEN** пользователь переключил оформление актуального загруженного компонента
- **THEN** клиент MUST использовать уже загруженные данные компонента без отдельного чтения оформления

### Requirement: Подтверждённые данные зон редактора переиспользуются изолированно

Клиент SHALL хранить подтверждённые данные в памяти сессии редактора по авторизационному
контексту, проекту, ДС, теме, версии и зоне: разделу, списку или выбранному компоненту/платформе.
Не загруженное состояние SHALL
отличаться от пустого результата. Кэш SHALL NOT становиться вторым локальным черновиком.

#### Scenario: Возврат в актуальный раздел

- **WHEN** пользователь возвращается к ресурсу, который загружен и не инвалидирован
- **THEN** клиент MUST переиспользовать подтверждённый результат без повторного HTTP-чтения
- **THEN** одновременные потребители MUST разделять выполняющееся чтение одного адреса

#### Scenario: Контекст изменился во время запроса

- **WHEN** пользователь сменил тему, версию или авторизационную сессию до завершения чтения
- **THEN** поздний ответ MUST NOT подменять данные нового контекста
- **THEN** закрытие сессии MUST освобождать её кэш и ненужные чтения

### Requirement: SSE инвалидирует зоны без полной загрузки редактора

Клиент SHALL переводить затронутые событием зоны в устаревшее состояние и автоматически
перечитывать открытый обычный раздел целиком либо список и выбранный компонент.
Получение all или неизвестной области
SHALL NOT запускать чтения всех разделов и компонентов.

#### Scenario: Изменён скрытый раздел

- **WHEN** SSE затронул скрытый раздел или невыбранный компонент
- **THEN** клиент MUST сохранить инвалидацию без запроса предметных данных
- **THEN** следующее открытие раздела или выбор компонента MUST получить целиком его актуальные данные

#### Scenario: Восстановлено соединение или получена область all

- **WHEN** требуется сверка всех ресурсов черновика после пропущенных или неизвестных событий
- **THEN** клиент MUST сверить лёгкий курсор и инвалидировать ресурсы соответствующего контекста
- **THEN** он MUST перечитать только открытый обычный раздел либо список и выбранный компонент, а также лёгкие общие сведения
- **THEN** обновление курсора MUST NOT снимать отложенные инвалидации скрытых ресурсов

#### Scenario: Событие пришло во время чтения

- **WHEN** ресурс инвалидирован после начала его запроса
- **THEN** поздний ответ MUST NOT объявлять ресурс актуальным вопреки новой инвалидации
- **THEN** необходимые повторные чтения MUST объединяться для открытой зоны

#### Scenario: Выбрана опубликованная версия

- **WHEN** пользователь читает versionId, а SSE сообщает изменения черновика
- **THEN** исторические предметные ресурсы MUST NOT перечитываться или заменяться данными черновика

### Requirement: Ленивость чтения сохраняет неподтверждённые изменения

Переход между разделами и адресная сверка SHALL сохранять существующие очереди мутаций,
их редакции, восстановление и глобальный учёт сохранения/публикации. Ответ чтения SHALL NOT
заменять неподтверждённый локальный ввод.

#### Scenario: Раздел скрыт с несохранённой правкой

- **WHEN** пользователь перешёл в другой раздел до подтверждения записи
- **THEN** правка MUST оставаться учтённой очередью, индикатором сохранения и барьером публикации
- **THEN** ошибка этой очереди MUST NOT блокировать чтение независимых ресурсов другого раздела

#### Scenario: Локальная отмена завершилась частично

- **WHEN** часть команд отмены сохранена, а последующая команда или сверка завершилась ошибкой
- **THEN** затронутые ресурсы MUST инвалидироваться независимо от SSE-эха
- **THEN** активные ресурсы MUST сверяться с сохранением исходной ошибки и неподтверждённого ввода
- **THEN** скрытые ресурсы MUST оставаться устаревшими до следующего обращения
