## Requirements
### Requirement: Команда icons publish

`dsbuilder` SHALL предоставлять команду `icons publish`, которая отправляет каталог иконок на бэкенд через `POST /api/admin/icons/catalog`. Команда SHALL принимать ровно один из источников: `--from-dir <каталог>` (корень пакета `@salutejs/sdds-icons`, то есть `packages/sdds-icons` репозитория `plasma`, с подкаталогами `svg/16`, `svg/24`, `svg/36`) или `--from <icons-manifest.json>`, а также обязательный `--api-url`, необязательные `--package-version`, `--write-manifest`, `--allow-removing-used` и флаг `--apply`. Без `--apply` команда MUST выполнять пробную отправку (`dryRun=true`). Команда MUST NOT читать проектный `.sdds` и `.env`.

#### Scenario: Пробная отправка по умолчанию

- **WHEN** команда запущена без `--apply`
- **THEN** CLI MUST отправить запрос с `dryRun=true`, напечатать различия с каталогом бэкенда и MUST NOT изменять бэкенд.

#### Scenario: Запись с --apply

- **WHEN** команда запущена с `--apply`
- **THEN** CLI MUST отправить запрос с `dryRun=false` и напечатать итог `published`, `activated` или `unchanged`.

#### Scenario: Источник не указан или указаны оба

- **WHEN** не задан ни `--from-dir`, ни `--from`, либо заданы оба
- **THEN** CLI MUST завершиться ошибкой использования до обращения к сети.

#### Scenario: Нет адреса API

- **WHEN** `--api-url` не задан
- **THEN** CLI MUST завершиться ошибкой использования, потому что команда пишет на бэкенд.

### Requirement: Сборка манифеста из каталога SVG

При `--from-dir` CLI SHALL обойти подкаталоги `svg/16`, `svg/24` и `svg/36`, взять имя каждого файла `*.svg` без расширения как каноническое имя, прочитать содержимое файла и собрать для каждого имени объект «размер → SVG» по подкаталогам, где файл найден. Файлы без расширения `.svg` и вложенные каталоги CLI MUST игнорировать. CLI MUST сообщать об иконках, у которых нет всех трёх размеров, предупреждением и MUST NOT считать это ошибкой.

#### Scenario: Полный набор размеров

- **WHEN** файл `AddOutline.svg` есть во всех трёх подкаталогах
- **THEN** манифест MUST содержать для `AddOutline` три размера с содержимым соответствующих файлов.

#### Scenario: Неполный набор размеров

- **WHEN** файл `NewFill.svg` есть только в `svg/24`
- **THEN** манифест MUST содержать `NewFill` только с размером `24`, а CLI MUST напечатать предупреждение о недостающих размерах.

#### Scenario: Нет подкаталогов размеров

- **WHEN** в указанном каталоге нет ни одного из `svg/16`, `svg/24`, `svg/36`
- **THEN** CLI MUST завершиться ненулевым кодом, назвать путь и MUST NOT обращаться к бэкенду.

#### Scenario: Пустой каталог

- **WHEN** подкаталоги есть, но SVG-файлов нет
- **THEN** CLI MUST завершиться ненулевым кодом и MUST NOT отправлять пустой каталог.

#### Scenario: Слишком большой файл

- **WHEN** один из SVG больше 64 КиБ
- **THEN** CLI MUST завершиться ненулевым кодом, назвать файл и MUST NOT обращаться к бэкенду.

### Requirement: Категория и синонимы из метаданных SVG

При `--from-dir` CLI SHALL читать из элемента `<metadata>` каждого SVG JSON-объект с полями `category` и `aliases`, раскодировать XML-сущности (`&amp;` → `&`) и записывать их в манифест иконки. Метаданные MUST браться из размера `24`, а при его отсутствии из первого найденного размера. Если у иконки отличаются `category` или `aliases` между размерами, CLI MUST использовать значения размера `24` и MUST напечатать предупреждение. Если `<metadata>` отсутствует или не разбирается, CLI MUST выпустить иконку без категории и синонимов с предупреждением и MUST NOT считать это ошибкой.

#### Scenario: Метаданные в SVG

- **WHEN** `AddOutline.svg` содержит `<metadata>{"aliases":["add","добавить"],"category":"Actions &amp; Feedback"}</metadata>`
- **THEN** манифест MUST содержать для `AddOutline` категорию `Actions & Feedback` и синонимы `add`, `добавить`.

#### Scenario: Метаданные не совпадают между размерами

- **WHEN** категории в `svg/16` и `svg/24` различаются
- **THEN** CLI MUST использовать категорию размера `24` и напечатать предупреждение с именем иконки.

#### Scenario: Метаданных нет

- **WHEN** в SVG нет `<metadata>`
- **THEN** CLI MUST выпустить иконку без категории и синонимов и напечатать предупреждение.

### Requirement: Чтение готового манифеста

При `--from` CLI SHALL читать JSON-файл формата `icons-manifest.json` (`schemaVersion`, `source`, `icons`) и MUST завершаться ненулевым кодом до обращения к бэкенду, если файл не найден, не разбирается или не соответствует формату. Режим `--from-dir` MUST формировать тот же формат и записывать его в файл при `--write-manifest <файл>`.

#### Scenario: Файл не найден

- **WHEN** файл по `--from` отсутствует
- **THEN** CLI MUST завершиться ненулевым кодом и назвать путь.

#### Scenario: Запись манифеста для проверки

- **WHEN** команда запущена с `--from-dir` и `--write-manifest`
- **THEN** CLI MUST записать манифест в файл и продолжить обычную отправку.

### Requirement: Источник пакета в манифесте

Поле `source` манифеста SHALL содержать `package` со значением `@salutejs/sdds-icons` и `version`. Версию CLI MUST брать из `--package-version`, а при `--from-dir` без этого параметра MUST читать `version` из `package.json` в указанном каталоге, если файл есть. Если версию установить нельзя, CLI MUST указать `unknown`.

#### Scenario: Версия из package.json

- **WHEN** в указанном каталоге лежит `package.json` с версией `0.14.0`
- **THEN** `source.version` MUST быть `0.14.0`.

#### Scenario: Версия не найдена

- **WHEN** `--package-version` не задан и `package.json` отсутствует
- **THEN** `source.version` MUST быть `unknown`.

### Requirement: Вход служебной учёткой

Команда SHALL входить так же, как `preview-plugin publish`: по переменным `DSBUILDER_CLIENT_ID` и `DSBUILDER_CLIENT_SECRET` через `client_credentials` без сохранения токена на диск, а при их отсутствии — по сохранённой сессии системного администратора. Секрет MUST NOT приниматься аргументом командной строки. Заданная одна из двух переменных MUST считаться ошибкой.

#### Scenario: Вход служебной учёткой в CI

- **WHEN** заданы обе переменные окружения
- **THEN** CLI MUST получить короткоживущий токен и отправить запрос с ним.

#### Scenario: Секрет аргументом

- **WHEN** передан `--client-secret`
- **THEN** CLI MUST отклонить его как неизвестный параметр.

### Requirement: Отчёт о результате

CLI SHALL печатать итог загрузки (`published`, `activated`, `unchanged` или различия пробной отправки): число добавленных, удалённых, изменённых и неизменных иконок, первые имена добавленных и удалённых, список используемых иконок, которые удаляются, и отчёт сверки значений с каталогом. Код ответа `409 icons_in_use` MUST завершать команду ненулевым кодом с перечнем иконок и подсказкой про `--allow-removing-used`. Остальные ошибки бэкенда (`400`, `403`, `413`, `503`) MUST завершать команду ненулевым кодом с понятным сообщением.

#### Scenario: Отчёт пробной отправки

- **WHEN** бэкенд вернул различия
- **THEN** CLI MUST напечатать числа и имена и завершиться кодом `0`.

#### Scenario: Удаляется используемая иконка

- **WHEN** бэкенд ответил `409 icons_in_use`
- **THEN** CLI MUST завершиться ненулевым кодом, перечислить иконки и число ссылок и подсказать `--allow-removing-used`.

#### Scenario: Отказ в правах

- **WHEN** бэкенд ответил `403`
- **THEN** CLI MUST завершиться ненулевым кодом и сообщить о нехватке прав публикации.
