# ide-plugin-token-browser Specification

## Purpose
Определяет read-only плагин DS Builder для Android Studio / IntelliJ IDEA (`frontend-kt/plugins/android-studio`): авторизация пользователя, просмотр проектов/дизайн-систем/токенов и UI-требования к нему.
## Requirements
### Requirement: Plugin module structure

`frontend-kt` SHALL предоставлять модуль `:plugins:android-studio` — плагин для Android Studio / IntelliJ IDEA, реализованный как plain JVM Gradle-модуль на IntelliJ Platform Gradle Plugin, зависящий от `core-domain`, `core-network`, `core-auth`, `core-application`, `feature-projects`, `feature-theme` и `feature-auth` того же composite build.

#### Scenario: Модуль зарегистрирован в settings

- **WHEN** разработчик открывает `frontend-kt/settings.gradle.kts`
- **THEN** список активных модулей включает `:plugins:android-studio`

#### Scenario: Плагин переиспользует общий прикладной слой там, где паттерн доступа совпадает

- **WHEN** разработчик инспектирует Gradle-зависимости `:plugins:android-studio`
- **THEN** модуль зависит от `core-domain`, `core-network`, `core-auth`, `core-application` через `project(...)`
- **THEN** модуль зависит от `feature-projects` (список проектов), `feature-theme` (tenant дизайн-системы и code-ссылка токена) и `feature-auth` (OAuth PKCE-логин) через `project(...)`
- **THEN** модуль не дублирует резолвинг контекста, credential-резолвинг или OAuth-оркестрацию, уже реализованные в этих модулях
- **THEN** модуль продолжает содержать собственный REST-клиент чтения токенов дизайн-системы (`DesignSystemDataClient`/`HttpDesignSystemDataClient`) — единственный доступный в `feature-theme` аналог (`TokenReadUseCases.values`) читает значения по одному `tokenId` за раз и не подходит для bulk-отображения списка токенов без N+1 запросов; это не дублирование существующей переиспользуемой возможности, а иной, оправданно локальный паттерн доступа

### Requirement: Plugin authentication

Плагин SHALL требовать интерактивной авторизации пользователя через OAuth Authorization Code + PKCE в системном браузере перед доступом к данным DS Builder и SHALL NOT запрашивать логин/пароль напрямую в своём UI.

#### Scenario: Неавторизованный пользователь видит экран логина

- **WHEN** пользователь открывает tool window `SDDS` без активной сессии
- **THEN** плагин показывает экран логина с кнопкой "Войти в DS Builder"
- **THEN** плагин не показывает списки проектов, дизайн-систем или токенов

#### Scenario: Экран логина не содержит полей пароля

- **WHEN** пользователь видит экран логина плагина
- **THEN** экран MUST NOT содержать поля ввода логина или пароля

#### Scenario: Успешная авторизация переключает экран

- **WHEN** пользователь завершает вход через системный браузер и плагин получает access и refresh токены
- **THEN** плагин сохраняет refresh token в защищённом хранилище IDE (`PasswordSafe`) и переключается с экрана логина на основной экран

#### Scenario: Ошибка авторизации отображается пользователю

- **WHEN** обмен authorization code на токены завершается ошибкой или пользователь закрывает браузер до завершения флоу
- **THEN** плагин показывает состояние ошибки на экране логина с возможностью повторить попытку

#### Scenario: Сессия молча восстанавливается при перезапуске

- **WHEN** плагин запускается в новом процессе IDE и в защищённом хранилище есть сохранённый refresh token
- **THEN** плагин пытается тихо обновить сессию через `grant_type=refresh_token`, не показывая экран логина, пока попытка не завершится неудачей

#### Scenario: Истечение сессии во время работы возвращает на экран логина

- **WHEN** запрос к REST API DS Builder завершается неудачей из-за отсутствующей или не восстановленной сессии (нет токена, либо тихое обновление по `401` не удалось)
- **THEN** плагин показывает сообщение об ошибке с кнопкой "Войти", которая возвращает пользователя на экран логина

#### Scenario: Явный выход завершает сессию и в браузере, и локально

- **WHEN** пользователь нажимает кнопку "Выйти"
- **THEN** плагин открывает системный браузер на end-session endpoint Keycloak, чтобы завершить SSO-сессию (иначе следующий вход молча продолжил бы прежнюю browser-сессию без формы логина)
- **THEN** плагин очищает локальную сессию (access token из памяти, refresh token из защищённого хранилища) независимо от того, удался ли браузерный шаг

### Requirement: Read-only token browsing

Плагин SHALL предоставлять только просмотр данных дизайн-системы через REST API DS Builder и SHALL NOT изменять файлы, зависимости или конфигурацию проекта пользователя. Для платформ `android` и `ios` плагин SHALL показывать превью значения токена, специфичное для его типа (`color`, `gradient`, `shadow`, `shape`, `spacing`, `typography`), вместо сырого JSON-текста.

#### Scenario: Просмотр доступных проектов

- **WHEN** пользователь авторизован
- **THEN** плагин запрашивает `GET /api/projects` и показывает только проекты, в которых пользователь состоит участником

#### Scenario: Пустой список проектов

- **WHEN** у авторизованного пользователя нет ни одного проекта с ролью `viewer` и выше
- **THEN** плагин показывает явное пустое состояние с пояснением, что владелец проекта должен добавить пользователя участником, а не выглядит как ошибка

#### Scenario: Единственный доступный вариант выбирается автоматически

- **WHEN** на шаге выбора проекта или дизайн-системы доступен только один вариант
- **THEN** плагин выбирает его автоматически, не заставляя пользователя явно кликать по единственному пункту списка, и не оставляет этот шаг в истории навигации

#### Scenario: Просмотр токенов выбранной дизайн-системы

- **WHEN** пользователь выбрал проект, дизайн-систему, версию и платформу
- **THEN** плагин запрашивает `GET /api/projects/{projectId}/ds/tokens` и `GET /api/projects/{projectId}/ds/token-values`
- **THEN** плагин показывает токены, сгруппированные по типу (`color`, `gradient`, `typography`, `spacing`, `shape`, `shadow`) во вкладках с поиском по имени токена внутри вкладки; тип `fontFamily` из просмотра исключён — его значение является именем шрифта и не несёт визуальной информации, полезной в этом UI

#### Scenario: Значение токена подбирается под выбранную тему

- **WHEN** пользователь выбрал светлую или тёмную тему просмотра токенов
- **THEN** плагин показывает значение токена, опубликованное для этой темы, если оно есть, иначе — значение, не зависящее от темы (например для `spacing`/`shape`)
- **THEN** выбор темы просмотра не зависит от текущей темы оформления самой IDE и может отличаться от неё

#### Scenario: Превью значения формы (`shape`) на android/ios

- **WHEN** выбранная платформа — `android` или `ios`, и значение токена типа `shape` разобрано как объект `{"kind":"round","cornerRadius":N}`
- **THEN** плагин показывает квадрат фиксированного размера, обрезанный по `RoundedCornerShape(N.dp)`, вместо сырого JSON-текста

#### Scenario: Превью значения отступа (`spacing`) на android/ios

- **WHEN** выбранная платформа — `android` или `ios`, и значение токена типа `spacing` разобрано как объект `{"value":N}`
- **THEN** плагин показывает полоску шириной `N.dp` рядом с числовой подписью значения, вместо сырого JSON-текста

#### Scenario: Превью значения градиента (`gradient`) на android/ios

- **WHEN** выбранная платформа — `android` или `ios`, и значение токена типа `gradient` разобрано как массив слоёв, каждый со своим `kind` (`linear`, `radial`, `angular` или `color`)
- **THEN** плагин показывает квадрат, залитый градиентной кистью, построенной из полей слоя (используя `com.sdds.compose.uikit.graphics.Gradients.Linear`/`Radial`/`Sweep` из уже подключённой `sdds-uikit-compose` для `linear`/`radial`/`angular` соответственно, или сплошной цвет `background` для `kind: "color"`), вместо сырого JSON-текста

#### Scenario: Превью значения тени (`shadow`) на android/ios

- **WHEN** выбранная платформа — `android` или `ios`, и значение токена типа `shadow` разобрано как массив из одного или нескольких слоёв (`color`, `offsetX`, `offsetY`, `spreadRadius`, `blurRadius`)
- **THEN** плагин показывает карточку с тенью, отрисованной по всем слоям (используя `com.sdds.compose.uikit.shadow.ShadowAppearance`/`Modifier.shadow` из уже подключённой `sdds-uikit-compose`), вместо сырого JSON-текста

#### Scenario: Превью значения типографики (`typography`) на android/ios

- **WHEN** выбранная платформа — `android` или `ios`, и значение токена типа `typography` разобрано в общую модель (размер, межстрочный интервал, начертание, трекинг) независимо от того, что имена полей в исходном JSON отличаются между `android` и `ios`
- **THEN** плагин показывает текст-сэмпл, отрисованный этим размером, межстрочным интервалом, начертанием и трекингом, вместо сырого JSON-текста

#### Scenario: Значения платформы `web` остаются текстом

- **WHEN** выбранная платформа — `web`
- **THEN** плагин показывает значение токена как текст (как для `color` сегодня — значение как есть), не пытаясь построить специфичное для типа визуальное превью

#### Scenario: Нераспознанная форма значения не ломает список

- **WHEN** значение токена не соответствует ожидаемой для его типа форме (например неизвестный `kind` у `shape`, или структура не совпадает с описанной для `android`/`ios`)
- **THEN** плагин показывает значение как текст, как это происходит для `web` сегодня, вместо падения с ошибкой или пустой строки

#### Scenario: Плагин не пишет в проект пользователя

- **WHEN** пользователь выполняет любое действие в любом экране плагина
- **THEN** плагин MUST NOT создавать директорию `.sdds` в открытом проекте
- **THEN** плагин MUST NOT записывать, изменять или удалять какие-либо файлы открытого проекта
- **THEN** плагин MUST NOT запускать генерацию кода дизайн-системы

### Requirement: Plugin UI theming

UI плагина SHALL быть реализован на Compose Desktop, встроенном в tool window через `ComposePanel`, и оформлен библиотекой `sdds-serv-compose`/`sdds-uikit-compose`, с автоматическим переключением цветовой схемы chrome плагина в зависимости от текущей темы IDE.

#### Scenario: Светлая тема IDE

- **WHEN** текущая тема IDE светлая
- **THEN** плагин оборачивает содержимое tool window в `SddsServTheme` со светлой цветовой схемой

#### Scenario: Тёмная тема IDE

- **WHEN** текущая тема IDE тёмная
- **THEN** плагин оборачивает содержимое tool window в `SddsServTheme` с тёмной цветовой схемой

#### Scenario: UI остаётся пригодным для узкого/низкого tool window

- **WHEN** tool window `SDDS` задокан узкой полосой или уменьшен по высоте
- **THEN** экран логина и список токенов остаются читаемыми и прокручиваемыми, без обрезанного или наложенного друг на друга содержимого

### Requirement: Design-system agnostic data

Плагин SHALL уметь отображать токены любой дизайн-системы DS Builder, доступной авторизованному пользователю, независимо от того, что UI самого плагина построен на конкретной библиотеке `sdds-serv-compose`.

#### Scenario: Данные дизайн-системы, отличной от той, что стилизует плагин

- **WHEN** пользователь выбрал проект с дизайн-системой, отличной от той, что использована для оформления самого плагина (например `sdds_finai` вместо `sdds_serv`)
- **THEN** плагин отображает её токены как данные внутри UI, построенного на `sdds-serv-compose`
- **THEN** плагин не подключает и не требует отдельную Compose-библиотеку под каждую отображаемую дизайн-систему

### Requirement: Tenant selection for token values

Плагин SHALL позволять выбрать tenant дизайн-системы при просмотре токенов, если у дизайн-системы больше одного tenant, и SHALL фильтровать значения токенов по выбранному tenant.

#### Scenario: У дизайн-системы один tenant

- **WHEN** пользователь выбрал дизайн-систему, у которой ровно один tenant (`GET /api/projects/{projectId}/ds/design-systems/{designSystemId}/tenants`, use case `feature-theme`)
- **THEN** плагин выбирает этот tenant автоматически, не показывая отдельный шаг выбора

#### Scenario: У дизайн-системы несколько tenant

- **WHEN** пользователь выбрал дизайн-систему, у которой больше одного tenant
- **THEN** плагин показывает шаг выбора tenant перед просмотром токенов

#### Scenario: Значения токенов фильтруются по выбранному tenant

- **WHEN** пользователь выбрал конкретный tenant (автоматически или вручную)
- **THEN** плагин запрашивает значения токенов для выбранного `tenantId`
- **THEN** плагин не показывает значения токена, принадлежащие другому tenant той же дизайн-системы

### Requirement: Copy token code reference to clipboard

Плагин SHALL предоставлять на платформе Android действие копирования в буфер обмена code-ссылки на токен (например `SddsServTheme.colors.textDefaultAccent`), получая её по нажатию на конкретный токен из CodeBinding (`kind=token`) опубликованной документации выбранной дизайн-системы (поле `themeReference`).

#### Scenario: Ссылка найдена в публикации

- **WHEN** выбрана платформа Android и пользователь нажимает «Копировать код» у токена
- **THEN** плагин находит последнюю публикацию дизайн-системы для платформы `compose` (`GET /documentation/publications/active` без `version`)
- **THEN** плагин ищет биндинг токена по точному `subject` — `tokens.<режим>.<имя>` для токенов, зависящих от темы (режим — выбранный в плагине), иначе `tokens.<имя>`
- **THEN** плагин копирует в буфер обмена значение `themeReference` и показывает статус «Скопировано»

#### Scenario: Ссылки нет — сообщается пользователю

- **WHEN** дизайн-система не опубликована для платформы, токена нет в публикации или `themeReference` пуст (например у `fontFamily`)
- **THEN** плагин ничего не копирует и показывает статус «Нет ссылки»
- **THEN** при ошибке запроса плагин показывает статус «Ошибка»

#### Scenario: Запрос выполняется по нажатию

- **WHEN** пользователь просматривает список токенов
- **THEN** плагин не загружает биндинги заранее и обращается к API документации только после нажатия «Копировать код»

#### Scenario: Действие недоступно вне платформы Android

- **WHEN** выбрана платформа `ios` или `web`
- **THEN** плагин не показывает действие "скопировать код" ни для одного токена

### Requirement: Full selection path in breadcrumbs

Плагин SHALL показывать в хлебных крошках полный путь выбора (проект / дизайн-система / tenant / платформа), включая шаги, выбранные автоматически.

#### Scenario: Автовыбранные шаги видны, но не кликабельны

- **WHEN** проект, дизайн-система или tenant выбраны автоматически как единственный вариант
- **THEN** их названия присутствуют в крошках как обычный текст
- **THEN** возврат на такой шаг невозможен, чтобы единственный вариант не выбирался заново автоматически

#### Scenario: Вручную выбранные шаги позволяют вернуться

- **WHEN** пользователь выбрал элемент вручную из списка
- **THEN** его название в крошках кликабельно и возвращает на шаг выбора этого элемента

### Requirement: Navigation state survives panel collapse

Плагин SHALL сохранять состояние навигации (выбранные проект, дизайн-система, tenant, платформа, текущий экран, режим темы токенов, выбранная вкладка типа токена и текст поиска) при сворачивании и повторном разворачивании tool window.

#### Scenario: Возврат на тот же экран

- **WHEN** пользователь на экране списка токенов сворачивает панель `SDDS` и разворачивает её снова
- **THEN** плагин показывает тот же список токенов с теми же проектом, дизайн-системой, tenant, платформой, режимом, вкладкой типа токена и текстом поиска, а не первый шаг выбора

#### Scenario: Выход сбрасывает навигацию

- **WHEN** пользователь нажимает «Выйти» или сессия истекает
- **THEN** сохранённая навигация сбрасывается к выбору проекта

### Requirement: Token filters use Segment with even vertical rhythm

Переключатель типа токенов на экране токенов SHALL быть реализован компонентом `Segment` из `sdds-uikit-compose` (`SegmentHorizontal`/`SegmentItem`). Режим темы SHALL переключаться компактной иконкой-кнопкой в одной строке с полем поиска, а не отдельным сегментом, чтобы не конкурировать с сегментом типов. Сегмент типов и строка поиска SHALL располагаться в одной группе фильтров с одинаковым вертикальным шагом между блоками, заданным единым отступом группы, а не отступами отдельных блоков.

#### Scenario: Переключение режима темы иконкой

- **WHEN** пользователь на экране токенов нажимает иконку режима справа от поля поиска
- **THEN** плагин переключается между светлым и тёмным режимом и показывает значения токенов нового режима
- **THEN** иконка отражает текущий режим (солнце — светлый, полумесяц — тёмный), а состояние режима сохраняется как и раньше
- **WHEN** пользователь наводит курсор на иконку режима
- **THEN** плагин показывает тултип с названием текущего режима и действием (например «Светлая тема, переключить на тёмную»); на заблокированной иконке — пояснение, что режим влияет только на цвета и градиенты

#### Scenario: Переключение типа токенов через Segment

- **WHEN** в дизайн-системе больше одного типа токенов и пользователь выбирает пункт в сегменте типов
- **THEN** плагин показывает токены выбранного типа, порядок пунктов остаётся фиксированным, а выбор сохраняется при сворачивании и разворачивании tool window

#### Scenario: Сегмент типов не помещается по ширине

- **WHEN** tool window узкий, и пункты сегмента типов не помещаются по ширине
- **THEN** сегмент типов прокручивается по горизонтали, пункты не обрезаются и не переносятся, а выбранный пункт находится в видимой области

#### Scenario: Ровные вертикальные отступы между фильтрами

- **WHEN** на экране токенов показаны режим, тип токенов и поиск
- **THEN** расстояние между любыми двумя соседними строками группы одинаково, и такой же отступ отделяет группу от хлебных крошек сверху и от списка токенов снизу
- **THEN** сегменты занимают ширину по содержимому и не растягиваются на всю ширину окна, а прокручиваются, только если не помещаются
- **THEN** при единственном типе токенов сегмент типов не показывается и не оставляет пустого промежутка над строкой поиска

#### Scenario: Режим темы доступен только для цветов и градиентов

- **WHEN** выбран тип токенов `color` или `gradient`
- **THEN** иконка режима темы активна и переключает значения токенов
- **WHEN** выбран любой другой тип (`typography`, `spacing`, `shape`, `shadow`, «Другое»)
- **THEN** иконка режима темы остаётся на месте, но заблокирована и приглушена, а ритм отступов и положение списка не меняются
