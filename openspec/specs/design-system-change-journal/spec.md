# design-system-change-journal Specification

## Purpose
Вычисляемый журнал предметных изменений дизайн-системы, его чтение клиентом и отмена изменений черновика.

## Requirements

### Requirement: Журнал вычисляется из предметных редакций

Система SHALL формировать журнал как разницу предметных редакций выбранной версии и состояния на предыдущей
опубликованной границе или `BASELINE` и SHALL NOT принимать записи журнала от клиента.

#### Scenario: Сущность создана в черновике

- **WHEN** выбранная версия содержит действующую предметную редакцию сущности, отсутствовавшей на предыдущей границе
- **THEN** журнал MUST вернуть операцию `CREATE`

#### Scenario: Сущность изменена в черновике

- **WHEN** предметные поля выбранной версии отличаются от предыдущего состояния
- **THEN** журнал MUST вернуть операцию `UPDATE` и изменённые пути

#### Scenario: Сущность удалена в черновике

- **WHEN** выбранная версия содержит последнюю редакцию `deleted = true`, а сущность существовала ранее
- **THEN** журнал MUST вернуть операцию `DELETE`
- **THEN** предыдущее состояние MUST оставаться доступным для отката и исторического чтения

#### Scenario: Изменение вернулось к предыдущему состоянию

- **WHEN** все предметные поля снова равны предыдущему опубликованному состоянию
- **THEN** сущность MUST отсутствовать в журнале

### Requirement: Клиент читает журнал дизайн-системы

`GET /api/ds/design-systems/{id}/changes` SHALL возвращать понятное пользователю описание фактических предметных
изменений.

Для компонентной конфигурации одна запись журнала SHALL соответствовать устойчивой строке существующего ресурса API,
а не всему компоненту и не произвольной группе строк импорта.

#### Scenario: Запрошен журнал активного черновика

- **WHEN** клиент вызывает маршрут без `versionId`
- **THEN** API MUST вернуть изменения активного черновика
- **THEN** каждая запись MUST содержать `changeId`, `versionId`, `entityType`, `entityId`, `operation`, изменённые пути,
  прежние и новые отображаемые значения, автора, время и текущую техническую редакцию

#### Scenario: Запрошен журнал опубликованной версии

- **WHEN** клиент передаёт `versionId` опубликованной версии этой дизайн-системы
- **THEN** API MUST вернуть её разницу с предыдущей опубликованной границей или `BASELINE`

#### Scenario: Журнал превышает защитный предел

- **WHEN** полный журнал содержит более 10 000 отображаемых изменений или один предметный обработчик находит более 100 000 кандидатов
- **THEN** предметный SQL MUST прекратить чтение после 100 001 строки
- **THEN** API MUST вернуть `422` с кодом `JOURNAL_LIMIT_EXCEEDED`
- **THEN** API MUST NOT возвращать усечённый журнал как полный

#### Scenario: Клиент создаёт запись журнала

- **WHEN** клиент вызывает прежний `POST /api/ds/design-system-changes`
- **THEN** маршрут MUST отсутствовать в публичном API

#### Scenario: Изменён общий каталог API компонентов

- **WHEN** импорт API-меты создаёт общий компонент, свойство, состояние или меняет признак устаревания платформенного
  имени
- **THEN** журналы дизайн-систем MUST NOT содержать эти изменения
- **THEN** импорт MUST NOT записывать строку `components:import-api-meta` в удаляемую `design_system_changes`

#### Scenario: Тема создана вместе с начальными значениями

- **WHEN** tenant отсутствовал на предыдущей опубликованной границе и создан в выбранном черновике
- **THEN** журнал MUST вернуть одну операцию `CREATE` для tenant
- **THEN** журнал MUST NOT возвращать отдельные операции создания значений токенов этого tenant
- **THEN** сервер MUST сохранить неизменяемое исходное состояние начальных значений внутри границы создания темы

#### Scenario: Пользователь изменил начальное значение новой темы

- **WHEN** пользователь изменил значение токена после атомарного создания tenant, но до первой публикации темы
- **THEN** журнал MUST вернуть отдельную операцию `UPDATE` значения относительно сохранённого исходного состояния
- **THEN** служебная запись начального значения MUST по-прежнему отсутствовать в журнале
- **THEN** откат этой операции MUST восстановить исходное значение, а не удалить устойчивую строку значения

#### Scenario: Одно действие изменило зависимые токены и их платформенные значения

- **WHEN** один атомарный пакет автосохранения изменил несколько зависимых токенов или значения одного токена для нескольких платформ
- **THEN** клиент MUST показать эти строки как одно действие с детализацией по токенам
- **THEN** детализация MUST содержать имя токена, режим, прежнее и новое значения и список платформ
- **THEN** клиент MUST показать имя автора, если оно доступно в составе проекта, иначе краткий технический идентификатор
- **THEN** каждый предметный `changeId` MUST остаться отдельно доступен для безопасного отката

#### Scenario: Новая дизайн-система получила канонические определения токенов

- **WHEN** система автоматически создаёт канонические определения токенов вместе с новой дизайн-системой
- **THEN** определения MUST принадлежать исходной границе `BASELINE`
- **THEN** журнал первого черновика MUST NOT возвращать их как пользовательские операции создания токенов
- **THEN** последующее ручное изменение определения токена MUST отображаться в журнале

### Requirement: Черновое изменение можно откатить

`POST /api/ds/design-systems/{id}/changes/{changeId}/revert` SHALL направлять откат типизированному обработчику
предметного модуля и SHALL принимать `X-DS-Base-Revision` и ключ повторяемости.

#### Scenario: Откатывается изменение опубликованной сущности

- **WHEN** актуальная запись журнала имеет операцию `UPDATE` или `DELETE`
- **THEN** обработчик MUST восстановить состояние предыдущей опубликованной границы удалением или изменением
  предметной редакции черновика
- **THEN** журнал MUST быть пересчитан после завершения транзакции

#### Scenario: Откатывается создание

- **WHEN** актуальная запись журнала имеет операцию `CREATE`
- **THEN** обработчик MUST удалить черновую редакцию и устойчивую сущность после проверки зависимостей
- **THEN** опубликованные данные MUST остаться без изменений

#### Scenario: Откатывается создание темы с начальными значениями

- **WHEN** пользователь откатывает единственную запись создания tenant в активном черновике
- **THEN** предметный обработчик темы MUST удалить редакции и устойчивые строки значений этого tenant, не имеющие опубликованной истории
- **THEN** предметный обработчик темы MUST удалить технические сведения этих значений и сам tenant одной транзакцией
- **THEN** при опубликованной истории или иной зависимости операция MUST завершиться целиком с `REVERT_DEPENDENCY_CONFLICT`

#### Scenario: Откатывается изменение начального значения новой темы

- **WHEN** пользователь откатывает видимое изменение значения tenant, созданного в том же активном черновике
- **THEN** предметный обработчик MUST восстановить сохранённое исходное значение темы
- **THEN** устойчивые строки tenant и значения MUST остаться существовать

#### Scenario: На созданный ресурс появилась зависимость

- **WHEN** после создания ресурса другой действующий ресурс начал ссылаться на него
- **THEN** откат создания MUST вернуть `409 Conflict` с кодом `REVERT_DEPENDENCY_CONFLICT`
- **THEN** API MUST NOT выполнять каскадный откат зависимых изменений

#### Scenario: Изменение успело измениться повторно

- **WHEN** переданная базовая редакция не совпадает с текущей редакцией записи журнала
- **THEN** API MUST вернуть `409 Conflict` с кодом `DRAFT_CHANGE_STALE` и актуальной редакцией
- **THEN** API MUST NOT выполнять откат автоматически
- **THEN** клиент MUST обновить журнал

#### Scenario: Поиск записи для отката превышает защитный предел

- **WHEN** полный поиск `changeId` потребовал бы более 100 000 кандидатов одного предметного типа
- **THEN** API MUST вернуть `422` с кодом `JOURNAL_LIMIT_EXCEEDED`
- **THEN** API MUST NOT выполнять частичный или неоднозначный откат

#### Scenario: Клиент откатывает опубликованную версию

- **WHEN** `changeId` относится не к активному черновику
- **THEN** API MUST отклонить откат без изменения предметных данных

### Requirement: Журнал цветовых токенов не показывает производный тип

Путь `/type` определения цветового токена SHALL считаться производным от значений семейства. Журнал SHALL NOT
показывать запись `token`, у которой изменился только `/type`, и SHALL NOT показывать `/type` среди изменённых
путей других записей цветового токена. Признак `/overridden` значения SHALL показываться как изменение
значения платформы.

#### Scenario: Градиент в одном режиме

- **WHEN** пользователь задал градиент в Dark темы B, и семейство из-за этого сменило тип на `gradient`
- **THEN** журнал MUST показать записи изменённых значений Dark темы B
- **THEN** журнал MUST NOT показывать записи определений семейства о смене типа

#### Scenario: Смена имени вместе с типом

- **WHEN** в черновике у определения изменились имя и тип
- **THEN** запись `token` MUST показывать только изменённое имя

#### Scenario: Своё значение платформы

- **WHEN** пользователь задал своё значение Android, и у редакции значения изменились `/value` и `/overridden`
- **THEN** запись значения MUST показывать изменение значения и признак своего значения платформы
- **THEN** полный откат записи MUST вернуть и значение, и признак

#### Scenario: Откат значения возвращает тип

- **WHEN** пользователь откатывает запись значения, которая внесла единственный градиент семейства
- **THEN** после отката семейство MUST иметь тип `color`, а журнал MUST NOT содержать ни записи этого значения,
  ни записей о типе семейства

### Requirement: Счётчик независим от построения полного журнала

`GET /api/ds/design-systems/{id}/changes/summary` SHALL возвращать точное `{total}` по тем же правилам видимости и детализации, что журнал. Подсчёт SHALL обрабатывать минимальные предметные отличия порциями в Kotlin с общими правилами журнала. Подсчёт SHALL NOT строить полный список публичных записей или удерживать все previous/current в памяти и SHALL NOT зависеть от предела полного журнала.

#### Scenario: Журнал доступен целиком
- **WHEN** summary и полный журнал читаются на одной границе редакций
- **THEN** total MUST совпадать с количеством отображаемых строк с учётом параметров, платформ и скрытых технических изменений
- **THEN** начальные значения новой темы и производный тип MUST учитываться по тем же правилам

#### Scenario: Полный журнал превышает предел
- **WHEN** полный `changes` возвращает `JOURNAL_LIMIT_EXCEEDED`
- **THEN** summary MUST продолжать возвращать точный total без усечённого приблизительного количества
- **THEN** полный маршрут MUST сохранять прежний защитный предел и отказ, не выдавая частичный список за полный

#### Scenario: Запрошена другая граница или недоступный проект
- **WHEN** передан `versionId` или доступ к проекту запрещён
- **THEN** summary MUST применять прежнюю границу версий и project-scoped авторизацию
- **THEN** кеш или компактность MUST NOT расширять доступ к изменениям

### Requirement: Изменённые токены читаются компактно по потребности

`GET /api/ds/design-systems/{id}/changes/token-ids` SHALL принимать обязательный tenantId и существующие селекторы version/versionId через ModelReadSelection и возвращать `{tokenIds: string[]}`. Ответ SHALL содержать уникальные ID видимо изменённых определений и значений выбранной темы в одном согласованном чтении, без полных записей, авторов и прежних/новых значений. Предел полного журнала SHALL NOT ограничивать компактный список. Пагинация и курсоры не требуются.

#### Scenario: Изменена другая тема
- **WHEN** изменено только значение темы B, а отметки запрошены для A
- **THEN** токен MUST NOT помечаться для A только из-за изменения B
- **THEN** изменение общего определения MUST учитываться для обеих тем

#### Scenario: Новая тема и возврат к исходному значению
- **WHEN** значение сравнивается с состоянием создания темы или предыдущей границей
- **THEN** нетронутые начальные значения и возвращённые к исходному токены MUST NOT считаться изменёнными при отсутствии других видимых изменений

#### Scenario: Неверный контекст
- **WHEN** tenant принадлежит другой ДС или проект недоступен
- **THEN** сервер MUST вернуть предусмотренный отказ без раскрытия чужих данных

### Requirement: Диагностика не меняет семантику revert

При профилировании сервис SHALL связывать этапы revert и чтения размеров с HTTP correlation ID, различая ожидание соединения, предметную работу, проверки и завершение транзакции. Диагностика SHALL NOT логировать учётные данные/значения токенов или ослаблять проверки ради ускорения.

#### Scenario: Измеряется завершение транзакции
- **WHEN** диагностируется успешный revert
- **THEN** время завершения транзакции MUST измеряться включая фактический COMMIT, а не только тело use case
- **THEN** предметные блокировки, идемпотентность и проверки зависимостей MUST сохраняться

#### Scenario: Диагностика выключена
- **WHEN** сервис работает с настройками по умолчанию
- **THEN** подробные SQL-параметры и значения MUST NOT попадать в постоянный HTTP-журнал

### Requirement: Компактные чтения используют существующий контекст модели

Новая проекция SHALL использовать действующие project-scoped контекст, ModelReadSelection и readOnly-транзакцию и возвращать X-DS-Read-Context фактической границы. Параллельный механизм разрешения версии SHALL NOT создаваться.

#### Scenario: Читается опубликованная версия
- **WHEN** клиент задаёт version или versionId
- **THEN** проекция MUST соответствовать разрешённой опубликованной границе без примеси draft
- **THEN** конфликтующие селекторы MUST отклоняться согласно существующему контракту

### Requirement: Полный журнал несёт точный счётчик своего снимка

Успешный полный GET changes SHALL сохранять массив записей и SHALL возвращать X-DS-Journal-Total с точным числом отображаемых строк той же границы чтения. Подсчёт SHALL использовать общие Kotlin-правила и уже прочитанные изменения, без второго построения журнала. Заголовок SHALL быть доступен клиенту через CORS.

#### Scenario: Revert при открытом журнале
- **WHEN** после команды отмены клиент получил полный журнал с X-DS-Journal-Total
- **THEN** клиент MUST использовать этот total без дополнительного GET summary
- **AND** клиент MUST NOT вычислять новое число простым вычитанием одной строки

#### Scenario: Полный журнал недоступен
- **WHEN** полный журнал ограничен 422 или старый сервер не возвращает точный total
- **THEN** независимый компактный summary MUST оставаться доступен для счётчика
