# versioned-palette-integration Specification

## Purpose
Определяет версионное хранение палитры и групп, их участие в журнале и независимой отмене,
историческое чтение цветов и конфигураций Web/Compose и безопасный переход со схемы актуального dev.
## Requirements
### Requirement: Палитра и группы принадлежат версии дизайн-системы

Система SHALL разрешать палитру, её копию шаблона, группы, растяжки, правки ступеней, привязки токенов
и группы токенов на той же временной границе, что значения токенов и конфигурации компонентов.
Публикация MUST NOT копировать все предметные данные или создавать общий JSON-снимок ДС.

#### Scenario: Неизменяемая копия шаблона

- **WHEN** общая палитра изменена после создания темы
- **THEN** копия `tenant_palette_template` этой темы MUST оставаться прежней и доступной её историческим версиям
- **THEN** система MUST NOT создавать редакции или повторные копии этого неизменяемого шаблона при публикации

#### Scenario: Палитра изменена после публикации

- **WHEN** после публикации версии пользователь изменяет источник растяжки или значение ступени
- **THEN** чтение прежней версии MUST вернуть прежнюю палитру и прежние разрешённые цвета токенов
- **THEN** редактор этой версии MUST оставаться доступным только для чтения

### Requirement: Палитра участвует в журнале и отмене

Журнал SHALL вычислять изменения палитры относительно последней публикации и показывать понятные
группу, растяжку, ступень, значения, автора и время. Отмена SHALL использовать существующую ручку.

#### Scenario: Ступень влияет на несколько токенов

- **WHEN** пользователь изменяет одну ступень палитры и у ссылающихся токенов меняется только вычисленный цвет
- **THEN** журнал MUST показывать одну запись изменения ступени без дополнительных записей этих токенов
- **THEN** отмена ступени MUST вернуть прежние вычисленные цвета, не меняя сохранённых ссылок токенов

#### Scenario: Отмена ступени

- **WHEN** пользователь отменяет правку одной ступени
- **THEN** сервер MUST сохранить соседние правки и вернуть согласованные технические метаданные
- **THEN** клиент MUST обновить палитру и зависящие цвета без перезагрузки редактора

#### Scenario: Перестроение растяжки

- **WHEN** пользователь перестраивает растяжку от опорного цвета, изменяя несколько рассчитанных ступеней
- **THEN** журнал MUST показывать одну запись перестроения с названием растяжки, группой, опорным цветом и сравнением палитр
- **THEN** рассчитанные ступени MUST NOT создавать отдельные строки журнала
- **THEN** отмена записи MUST атомарно вернуть параметры и рассчитанные цвета к состоянию публикации
- **THEN** несколько перестроений MUST сводиться к итоговой разнице, а не истории промежуточных действий

#### Scenario: Ручная правка после перестроения

- **WHEN** после перестроения пользователь вручную изменяет ступень, в том числе опорную
- **THEN** эта правка MUST показываться отдельно от перестроения и MUST NOT менять параметры расчёта всей растяжки
- **THEN** отмена ручной правки MUST возвращать рассчитанный цвет текущей растяжки
- **THEN** отмена перестроения MUST сохранять независимую ручную правку

#### Scenario: Составное изменение устарело

- **WHEN** состав палитры изменился после получения записи журнала до её отмены
- **THEN** сервер MUST вернуть `DRAFT_CHANGE_STALE` без частичной отмены
- **THEN** редакция составной записи MUST учитывать дочерние цвета

#### Scenario: Понятные подробности перестроения

- **WHEN** пользователь открывает подробности перестроения
- **THEN** клиент MUST показывать цвета до и после, понятное название группы и параметры редактора
- **THEN** клиент MUST NOT показывать UUID, `rebuild`, `general` и технические поля слота как пользовательские изменения

#### Scenario: Удаление с зависимостями

- **WHEN** удаление растяжки переписывает сохранённые ссылки токенов на другую растяжку или HEX
- **THEN** журнал MUST показывать удаление растяжки и фактические изменения токенов отдельными записями
- **THEN** отмена удаления MUST восстановить растяжку без автоматической отмены изменений ссылок
- **THEN** каждая отмена MUST восстанавливать соответствующее состояние относительно последней публикации

#### Scenario: Отмена ссылки требует отсутствующую растяжку

- **WHEN** пользователь отменяет изменение ссылки токена, но требуемая растяжка ещё не восстановлена
- **THEN** сервер MUST отклонить отмену предметной ошибкой без изменения токена
- **THEN** после восстановления растяжки пользователь MUST иметь возможность повторно запросить отмену ссылки

#### Scenario: Отмена нарушает целостность

- **WHEN** отмена удаления группы или растяжки не может восстановить согласованные ссылки
- **THEN** сервер MUST отклонить отмену предметной ошибкой без частично восстановленных данных

#### Scenario: Начальная палитра темы

- **WHEN** пользователь создаёт тему
- **THEN** журнал MUST показывать создание темы без отдельных строк на каждую начальную ступень

### Requirement: Обе части редактора сохраняются после совмещения

Клиент SHALL сохранять новый UI цветов, палитры и Compose из `dev` и UI журнала, селектор версий,
отмену параметров и автосохранение ветки версий. Удалённая npm-публикация MUST NOT возвращаться.

#### Scenario: Источник цвета

- **WHEN** пользователь переходит к источнику записи цветового токена
- **THEN** новый редактор MUST открыть соответствующий токен с сохранением `versionId`
- **THEN** он MUST NOT переключаться на прежний экран цветовых токенов

#### Scenario: Исторический Compose

- **WHEN** пользователь выбирает опубликованную версию и раздел Compose
- **THEN** конфигурация MUST загружаться через `ds-service` на выбранной границе, а не из legacy API

### Requirement: Миграции не перезаписывают актуальный dev

Изменение SHALL сохранять содержимое применённых миграций `dev` и все существующие предметные UUID.
Локальная база прежней ветки MUST NOT сбрасываться автоматически.

#### Scenario: Обновление актуального dev

- **WHEN** миграции запускаются на схеме `dev` с существующей палитрой и группами
- **THEN** они MUST завершиться без дублирующихся версий Flyway и без потери данных и ссылок
- **THEN** повторный запуск MUST не создавать новые редакции или дубли

#### Scenario: Ошибка единого перехода

- **WHEN** единая миграция V7 завершается ошибкой на любом этапе переноса с V6
- **THEN** схема и данные MUST целиком остаться в состоянии V6 без частично созданных редакций
- **THEN** после устранения причины повторный запуск MUST выполнить ровно одну миграцию V7
- **THEN** обычный запуск MUST NOT вызывать очистку БД или исправление истории Flyway
