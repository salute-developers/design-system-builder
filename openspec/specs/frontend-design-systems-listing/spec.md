# frontend-design-systems-listing Specification

## Purpose
Определяет общий клиентский список доступных дизайн-систем проекта для CLI, MCP и IDE до разрешения контекста конкретной системы.

## Requirements

### Requirement: Дизайн-системы доступного проекта до выбора контекста

Общие клиентские сценарии SHALL возвращать дизайн-системы явно указанного проекта без `.sdds/config.json` и без заранее выбранной системы, используя выбранные учётные данные PAT/OAuth и существующие проверки доступа backend.

#### Scenario: Список систем
- **WHEN** авторизованный клиент передаёт projectId
- **THEN** он MUST получить список из `GET /api/projects/{projectId}/ds/design-systems` с ID, именем и описанием при наличии
- **THEN** CLI, MCP и Android Studio plugin MUST использовать общий сценарий получения списка

#### Scenario: Пустой список
- **WHEN** доступный проект не содержит систем
- **THEN** результат MUST быть успешным пустым списком

#### Scenario: Отказ и некорректный ответ
- **WHEN** не найдены PAT и сессия, backend запрещает доступ, недоступен либо возвращает неправильный формат
- **THEN** клиент MUST различать `AUTH_REQUIRED`, `PAT_INVALID`, `FORBIDDEN`, `NOT_FOUND`, `BACKEND_UNAVAILABLE` и `INVALID_BACKEND_RESPONSE`
- **THEN** он MUST NOT менять тип учётных данных после отказа и MUST NOT возвращать чужие системы

#### Scenario: Выбор авторизации задаёт клиент
- **WHEN** сценарий вызывается CLI или MCP
- **THEN** клиент MUST предоставить общий выбор PAT/OAuth без требования ProjectContext и без зависимости бизнес-сценария от launcher
- **WHEN** сценарий вызывается IDE с явно выбранной OAuth-сессией
- **THEN** сценарий MUST использовать эту сессию, не читая PAT из окружения IDE

#### Scenario: PAT отклонён
- **WHEN** сервер отвечает 401 выбранному PAT
- **THEN** сценарий MUST вернуть PAT_INVALID без повтора с OAuth-сессией и без изменения сохранённой сессии
