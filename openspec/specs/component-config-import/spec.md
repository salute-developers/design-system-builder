## Requirements
### Requirement: Ссылка на стиль типографики без экрана привязывается к токену screen-s

Импорт конфигураций компонентов SHALL разрешать ссылку на токен свойства типа `typography` так же, как её пишет экспорт: ссылку без экрана (`body.l.bold`) — к токену типографики `screen-s.body.l.bold` дизайн-системы, ссылку с экраном (`screen-l.body.l.bold`) — к токену этого экрана. Найденный токен MUST сохраняться привязкой (`token_id`), а не текстом значения.

#### Scenario: Ссылка без экрана

- **WHEN** импортируется конфигурация, где `labelStyle` типа `typography` ссылается на `body.l.bold`, а в дизайн-системе есть токен `screen-s.body.l.bold`
- **THEN** значение MUST быть привязано к токену `screen-s.body.l.bold`
- **THEN** `body.l.bold` MUST NOT попасть в список ненайденных токенов

#### Scenario: Ссылка с экраном

- **WHEN** значение типа `typography` ссылается на `screen-l.body.l.bold`
- **THEN** значение MUST быть привязано к токену `screen-l.body.l.bold`

### Requirement: Литерал не считается ссылкой на токен

Импорт конфигураций компонентов SHALL искать токен для каждого текстового значения свойства токенного типа, в том числе для имени без точки. Найденный токен MUST сохраняться привязкой (`token_id`). Если токен не найден, а значение — литерал CSS (`transparent`, `inherit`, `initial`, `unset`, `currentColor`, `none`; цвет `#…`, `rgb(…)`, `rgba(…)`, `hsl(…)`, `hsla(…)`), импорт SHALL сохранять его литералом и MUST NOT включать в список ненайденных токенов отчёта. Остальные ненайденные значения MUST попадать в список ненайденных токенов.

#### Scenario: Прозрачный фон

- **WHEN** `backgroundColor` стиля имеет значение `transparent`, а токена `transparent` в дизайн-системе нет
- **THEN** значение MUST сохраниться литералом `transparent`
- **THEN** список ненайденных токенов MUST NOT содержать `transparent`

#### Scenario: Тень с именем без точки

- **WHEN** `shadow` стиля ссылается на `card`, а в дизайн-системе есть токен тени `card`
- **THEN** значение MUST быть привязано к токену `card`
- **THEN** повторная загрузка выгрузки MUST дать `unchanged`

#### Scenario: Неизвестное имя без точки

- **WHEN** значение токенного типа равно `missing`, а токена `missing` нет и это не литерал CSS
- **THEN** список ненайденных токенов MUST содержать `missing`

### Requirement: Повторная загрузка выгрузки ничего не меняет

Пакет, полученный экспортом конфигураций компонентов дизайн-системы, при импорте без изменений в ту же дизайн-систему SHALL давать отчёт, в котором каждая конфигурация `unchanged`, а список ненайденных токенов пуст.

#### Scenario: Круг экспорт → импорт

- **WHEN** конфигурации компонентов дизайн-системы экспортируются и сразу импортируются обратно пробным импортом
- **THEN** отчёт MUST содержать `updated = 0`, `created = 0` и пустой список ненайденных токенов

### Requirement: Дизайн-система из сидов хранит корень по правилу фолбэка

Создание компонентов дизайн-системы из сидов SHALL назначать каждому appearance с осями корневую ось по правилу фолбэка: ось `size`, иначе первая по позиции, кроме оси цветовой схемы. Выгрузка такой дизайн-системы MUST содержать `rootVariationId`.

#### Scenario: Новая дизайн-система

- **WHEN** создаётся дизайн-система, а у компонента в сидах есть ось `size`
- **THEN** выгрузка конфигурации компонента MUST содержать `rootVariationId: "size"`

### Requirement: Дизайн-система из сидов хранит значения так же, как импорт

Создание компонентов дизайн-системы из сидов SHALL записывать позицию значения как импорт: базовое значение свойства — `0`, значения состояний того же свойства — `1…n` в порядке сидов. Числовое смещение значения из поправки платформенного параметра SHALL записываться в `adjustment` значения. Имена стилей одной вариации компонента в сидах MUST NOT совпадать без учёта регистра.

#### Scenario: Кнопка с состояниями и смещением формы

- **WHEN** создаётся дизайн-система, а у `Button` в сидах `backgroundColor` с состояниями `hovered` и `pressed` и `shape` с web-поправкой `-2`
- **THEN** выгрузка и повторная загрузка `Button` MUST дать `unchanged`

#### Scenario: Стили Badge

- **WHEN** создаётся дизайн-система из сидов
- **THEN** стили вариаций `Badge` MUST иметь строчные имена без дублей по регистру, а выгрузка и повторная загрузка `Badge` MUST дать `unchanged`
