# plasma-component-import Specification

## Purpose
Определяет инструмент импорта web-компонента из репозитория plasma в prod-сид `db-service` и манифест генератора: источники, правила приведения конфига оформления к модели DS Builder, отчёт о спорных местах и режимы применения.

## Requirements

### Requirement: Import reads plasma sources and writes the component seed

Инструмент импорта SHALL читать объект токенов компонента из `plasma-new-hope` и конфиг оформления из
`sdds-serv` и записывать папку сида компонента в формате `component-seed-format` и манифест генератора.

#### Scenario: Сухой прогон по умолчанию

- **WHEN** инструмент запущен без `--apply`
- **THEN** он MUST напечатать отчёт и MUST NOT записать ни одного файла

#### Scenario: Применение пишет папку целиком

- **WHEN** инструмент запущен с `--apply`
- **THEN** папка `seeds/prod/components/<имя>/` MUST быть записана целиком
- **THEN** манифест `templates/<X>/component.json` в генераторе MUST быть записан, если у компонента есть сведения, не выводимые из данных

#### Scenario: Удаление трогает только папку компонента

- **WHEN** инструмент запущен с `--remove --apply`
- **THEN** папка названного компонента MUST быть удалена
- **THEN** папки дочерних компонентов и список зависимостей MUST остаться без изменений

#### Scenario: Компонент без объекта токенов

- **WHEN** у компонента ядра нет объекта токенов
- **THEN** инструмент MUST отказать с сообщением, что компонент в модель не ложится
- **THEN** сид MUST NOT быть записан

### Requirement: Import report classifies findings

Отчёт импорта SHALL делить находки на «требует решения», «приближения», «пропущено» и «справка»;
всё, что нельзя выразить в модели однозначно, SHALL попадать в отчёт, а не в сид.

#### Scenario: Неизвестный токен темы требует решения

- **WHEN** конфиг ссылается на идентификатор темы, которому нет токена базовой ДС
- **THEN** находка MUST попасть в «требует решения»
- **THEN** значение MUST быть записано только после указания `--alias=<ident>=<token.name>`

#### Scenario: Соседний конфиг требует решения

- **WHEN** рядом с `<X>.config.ts` лежит `<X>.<variant>.config.ts`
- **THEN** инструмент MUST NOT заводить его как второй appearance сам
- **THEN** находка MUST попасть в «требует решения» с указанием на режим `--dir`

#### Scenario: Пересечения вариаций пропускаются

- **WHEN** конфиг содержит `intersections`
- **THEN** они MUST NOT быть перенесены
- **THEN** число пересечений MUST быть указано в «пропущено»

#### Scenario: Устаревший стиль пропускается

- **WHEN** стиль помечен `deprecated` в конфиге
- **THEN** он MUST NOT быть перенесён
- **THEN** находка MUST попасть в «пропущено»

### Requirement: Config values are mapped to the model by fixed rules

Инструмент SHALL приводить значения конфига к модели по правилам, одинаковым для всех компонентов.

#### Scenario: Web-параметр равен ключу токена ядра

- **WHEN** свойство заведено по ключу объекта токенов ядра
- **THEN** имя web-параметра свойства MUST совпадать с этим ключом

#### Scenario: Шрифтовая группа становится одним свойством

- **WHEN** конфиг задаёт шесть шрифтовых токенов одной группы
- **THEN** они MUST стать одним свойством типа `typography` с именем `<prefix>Style`
- **THEN** значение MUST ссылаться на типографический токен темы вида `body.l.normal`
- **THEN** одиночный шрифтовой токен без остальных частей MUST попасть в «пропущено»

#### Scenario: Радиус сверяется с токенами формы

- **WHEN** все значения свойства-радиуса совпадают с web-значениями токенов `round.*`
- **THEN** свойство MUST получить тип `shape` со ссылками на токены
- **WHEN** хотя бы одно значение не совпадает
- **THEN** всё свойство MUST получить тип `dimension`
- **THEN** радиус от 500px MUST считаться токеном `round.circle`

#### Scenario: Многозначное значение выражается шаблоном

- **WHEN** значение содержит несколько чисел (`padding: a b`)
- **THEN** свойство MUST получить один шаблон web-параметра, где `$1` — число стиля
- **THEN** расхождение остальных чисел между размерами MUST попасть в «приближения»

#### Scenario: Строка без токена становится value

- **WHEN** значение — `auto`, `100%`, `fit-content`, transition, `url(...)` или ссылка на CSS-переменную ядра
- **THEN** свойство MUST получить тип `value`, а строка MUST быть записана как есть
- **WHEN** значения одного ключа смешивают число и строку
- **THEN** всё свойство MUST стать `value`, а находка попасть в «приближения»

#### Scenario: disabled и readOnly становятся инвариантами

- **WHEN** конфиг содержит вариации `disabled` или `readOnly`
- **THEN** их токены MUST быть записаны инвариантами, а не вариациями

#### Scenario: Флаг заводится одним стилем

- **WHEN** вариация в конфиге имеет единственный стиль `true`
- **THEN** сид MUST содержать этот стиль без дефолта
- **THEN** стиль `false` MUST NOT быть заведён

#### Scenario: Дефолты берутся из темы, затем из ядра

- **WHEN** блок `defaults` конфига темы не задаёт дефолт вариации
- **THEN** инструмент MUST взять дефолт из базового конфига ядра, если такой стиль есть в теме
- **THEN** без такого стиля вариация MUST остаться без дефолта, а находка попасть в «справку»

### Requirement: Composite components are imported from a directory

Инструмент SHALL импортировать компонент с несколькими appearance и дочерними элементами из папки
`sdds-serv`, где подпапки — appearance, а файлы `<Appearance><Element>.config.ts` — конфиги элементов.

#### Scenario: Подпапки становятся appearance

- **WHEN** инструмент запущен с `--dir=<папка>`
- **THEN** каждая подпапка MUST стать appearance с именем подпапки
- **THEN** свойства и вариации MUST быть объединены по всем appearance
- **THEN** расхождение типа одного свойства между appearance MUST завершить импорт ошибкой

#### Scenario: Элемент с именем компонента — родитель

- **WHEN** в папке есть конфиги нескольких элементов
- **THEN** элемент с именем `--component` MUST стать родителем
- **THEN** остальные MUST стать дочерними компонентами со связью `compose`

#### Scenario: Проп выбора appearance уходит в манифест

- **WHEN** импорт составного компонента завершён
- **THEN** манифест генератора MUST содержать `appearances: { prop, default }`, где `prop` — значение `--root` или `orientation`
