# component-catalog-panel Specification

## Purpose
Левая панель раздела компонентов: список компонентов дизайн-системы по группам, поиск, фильтр по платформам, изменяемая ширина, скрытие, возврат и добавление компонентов из шаблонов с учётом зависимостей между ними.

## Requirements
### Requirement: Список компонентов по группам

Панель SHALL показывать компоненты выбранной дизайн-системы, сгруппированные по категориям, со счётчиком видимых компонентов в заголовке группы. Группа MUST сворачиваться. Компонент без категории MUST попадать в группу «Другое». Скрытые компоненты MUST NOT отображаться в списке.

#### Scenario: Открытие панели

- **WHEN** пользователь открывает раздел компонентов
- **THEN** панель MUST показать группы со счётчиками и выделить компонент из URL.

#### Scenario: Компонент вне таблицы категорий

- **WHEN** категория компонента неизвестна клиенту
- **THEN** компонент MUST отображаться в группе «Другое».

### Requirement: Поиск компонентов

Панель SHALL открывать поле поиска по кнопке и фильтровать компоненты по вхождению подстроки в имя без учёта регистра. Закрытие поиска MUST сбрасывать запрос. Поиск MUST работать совместно с фильтром платформ.

#### Scenario: Ничего не найдено

- **WHEN** запросу не соответствует ни один компонент
- **THEN** панель MUST показать сообщение с текстом запроса.

#### Scenario: Закрытие поиска

- **WHEN** пользователь закрывает поиск
- **THEN** панель MUST показать полный список текущей платформы.

### Requirement: Фильтр по платформам

Панель SHALL предлагать значения «Все», Web, Compose, Android XML и iOS. На «Все» компонент с записями на нескольких платформах MUST отображаться одной строкой. Выбор строки на «Все» MUST открывать Web, а при его отсутствии Compose.

#### Scenario: Платформа без компонентов

- **WHEN** на выбранной платформе нет компонентов
- **THEN** панель MUST показать «Для выбранной платформы компонентов нет».

#### Scenario: Компонент на двух платформах

- **WHEN** компонент есть на Web и Compose и выбрано «Все»
- **THEN** список MUST содержать одну строку, а её выбор MUST открыть Web-версию.

### Requirement: Скрытие компонента

Пользователь SHALL иметь возможность скрыть компонент кнопкой в строке. На вкладке платформы операция MUST затрагивать только эту платформу, на «Все» — все платформы компонента. В режиме только для чтения кнопка MUST быть недоступна. При отказе сервера в правах панель MUST показать сообщение об ошибке.

#### Scenario: Скрытие на одной платформе

- **WHEN** пользователь скрывает компонент на вкладке Compose
- **THEN** компонент MUST исчезнуть из Compose и MUST остаться на Web.

#### Scenario: Повторное нажатие

- **WHEN** пользователь нажимает «скрыть» у компонента, скрытие которого уже отправлено
- **THEN** кнопка этой строки MUST быть недоступна до перечитывания состава, а повторный запрос MUST NOT отправляться.

#### Scenario: Кнопки скрытия других строк

- **WHEN** скрытие одного компонента выполняется
- **THEN** кнопки скрытия остальных строк MUST оставаться невидимыми без наведения и доступными.

#### Scenario: Скрытие открытого компонента

- **WHEN** пользователь скрывает открытый компонент
- **THEN** редактор MUST открыть следующий доступный компонент.

#### Scenario: Скрыты все компоненты

- **WHEN** в дизайн-системе не осталось видимых компонентов
- **THEN** страница MUST остаться в разделе компонентов и показать сообщение с возможностью вернуть компонент.

#### Scenario: Раздел после скрытия всех компонентов

- **WHEN** у дизайн-системы не осталось связей с компонентами, но есть их оформления
- **THEN** кнопка раздела «Компоненты» MUST оставаться в навигации редактора.

#### Scenario: Ошибка посреди операции

- **WHEN** запрос завершился ошибкой
- **THEN** панель MUST сообщить об ошибке и показать фактическое состояние каталога.

### Requirement: Зависимости при скрытии и возврате

Панель MUST NOT скрывать компонент, который используют другие компоненты в составе дизайн-системы (`component-deps`): подтверждение SHALL перечислить их и предложить сначала скрыть их. Возврат компонента SHALL возвращать и скрытые компоненты, от которых он зависит, а диалог MUST их назвать.

#### Scenario: Скрытие используемого компонента

- **WHEN** пользователь пытается скрыть Avatar, а AvatarGroup в составе и зависит от него
- **THEN** диалог MUST сообщить, что Avatar использует AvatarGroup, и MUST NOT отправлять скрытие.

#### Scenario: Возврат с зависимостью

- **WHEN** пользователь возвращает AvatarGroup, а Avatar скрыт
- **THEN** вместе с AvatarGroup MUST вернуться Avatar, а диалог MUST предупредить об этом до подтверждения.

### Requirement: Возврат скрытого компонента

Кнопка «+» SHALL открывать диалог «Добавить компоненты» со скрытыми компонентами дизайн-системы и web-компонентами из шаблонов, которых в дизайн-системе ещё нет: поиск, группы «Скрытые» и «Новые» с числом компонентов, чекбокс у каждого компонента, чекбокс в заголовке каждой группы для её найденных компонентов и группа «Платформа компонента» со всеми платформами; платформа, на которой ни один отмеченный компонент недоступен, MUST быть недоступна. Скрытый компонент MUST возвращаться с прежней конфигурацией, новый — собираться из шаблона. Компоненты, от которых выбранные зависят, добавляются вместе с ними, и диалог MUST назвать их до подтверждения. После добавления панель MUST открыть первый добавленный компонент и сбросить фильтр на «Все». В режиме только для чтения кнопка MUST быть недоступна.

#### Scenario: Возврат на одной платформе

- **WHEN** компонент скрыт на Web и Compose, а пользователь возвращает его на Web
- **THEN** компонент MUST появиться на Web и MUST остаться скрытым на Compose.

#### Scenario: Новый компонент из шаблона

- **WHEN** в дизайн-системе нет Card и пользователь выбирает его в диалоге
- **THEN** Card MUST появиться в списке с конфигурацией из шаблона и открыться в редакторе.

#### Scenario: Дизайн-система без компонентов

- **WHEN** у дизайн-системы нет ни одного компонента
- **THEN** раздел «Компоненты» MUST быть доступен, а диалог MUST предлагать все web-компоненты из шаблонов.

#### Scenario: Выбрать все

- **WHEN** пользователь отмечает чекбокс в заголовке группы при активном поиске
- **THEN** диалог MUST отметить все найденные компоненты этой группы, не трогая другую, а при частичном выборе в группе её чекбокс MUST быть в промежуточном состоянии.

#### Scenario: Нечего добавлять

- **WHEN** скрытых компонентов нет и все web-компоненты из шаблонов уже в дизайн-системе
- **THEN** диалог MUST показать «Все компоненты уже добавлены».

### Requirement: Изменяемая ширина панели

Пользователь SHALL менять ширину панели перетаскиванием разделителя на её правом крае и стрелками с клавиатуры в пределах 220–320px. Ширина по умолчанию MUST быть 280px, выбранная ширина MUST сохраняться в браузере.

#### Scenario: Перетаскивание за границу

- **WHEN** пользователь тянет разделитель дальше 320px
- **THEN** ширина панели MUST остановиться на 320px и сохраниться.

#### Scenario: Клавиатура

- **WHEN** разделитель в фокусе и пользователь нажимает стрелку вправо с Shift
- **THEN** ширина MUST увеличиться на 16px.

### Requirement: Каталог обновляется после отката

После отката изменения связи в журнале панель SHALL показывать актуальный состав дизайн-системы.

#### Scenario: Откат скрытия

- **WHEN** пользователь откатывает скрытие в журнале
- **THEN** компонент MUST вернуться в панель без перезагрузки страницы.
