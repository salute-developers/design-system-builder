# mcp-token-editing Specification

## Purpose
Редактирование токенов выбранной дизайн-системы через MCP с отдельными точечными и семейными операциями, исходными значениями и существующими серверными ограничениями.

## Requirements

### Requirement: Точечное редактирование определений

MCP SHALL предоставлять `token_create`, `token_update`, `token_delete` для отдельных определений: создание, изменение и удаление используют DS URL, адресуют определения по ID внутри неё и сохраняют серверные права. Эти операции MUST NOT неявно создавать, переименовывать или удалять остальные определения семейства.

#### Scenario: Создание и изменение определения
- **WHEN** пользователь создаёт токен с именем и типом, затем изменяет его метаданные
- **THEN** результат MUST содержать стабильный tokenId и подтверждённые сервером данные
- **THEN** создание значений MUST оставаться отдельной операцией

#### Scenario: Удаление одного определения
- **WHEN** вызван `token_delete` для члена цветового семейства
- **THEN** инструмент MUST запросить удаление только данного определения по существующим правилам сервера
- **THEN** описание MUST отличать эту операцию от `color_token_delete`

### Requirement: Точечное редактирование значений

MCP SHALL предоставлять `token_value_create`, `token_value_update`, `token_value_delete`. Создание MUST требовать tokenId, tenantId, platform и mode; mode SHALL принимать `null` для значений без режима и `light`/`dark` для цветовых значений; изменение и удаление MUST адресовать существующий valueId. Серверная проверка значения MUST сохраняться.

#### Scenario: Изменение отдельной пары
- **WHEN** меняется значение токена одной темы для web/dark
- **THEN** инструмент MUST передать только запрошенные поля значения
- **THEN** он MUST NOT записывать значения других тем, платформ и режимов от себя

#### Scenario: Значение без режима
- **WHEN** создаётся значение отступа с `platform=web`, `mode=null` и числовым значением
- **THEN** MCP MUST передать явный `mode=null` в серверный запрос без подстановки цветового режима

#### Scenario: Неизменяемый ключ
- **WHEN** обновление существующего значения пытается изменить tokenId, tenantId, platform или mode
- **THEN** MCP MUST отклонить аргументы до записи и предложить отдельное создание/удаление

#### Scenario: Цветовые правила при точечной записи
- **WHEN** отдельное значение цвета заменено градиентом через общий инструмент
- **THEN** серверная валидация и пересчёт типа семейства MUST выполняться существующим API
- **THEN** MCP MUST вернуть серверный результат и метаданные без локального назначения типа семьи

#### Scenario: Изменение только палитры
- **WHEN** вызывается `token_value_update` с `valueId` и `paletteId` без `value`
- **THEN** MCP MUST передать PATCH без поля `value`, сохранив прежнее значение
- **THEN** повтор MUST сохранить исходные тело и ключ

#### Scenario: Явный null вместо значения
- **WHEN** в `token_value_update` передан `value: null`
- **THEN** схема MUST отклонить аргументы до отправки мутации, поскольку backend не поддерживает такой PATCH

### Requirement: Операции цветового семейства

MCP SHALL предоставлять `color_token_create`, `color_token_values_update`, `color_token_move`, `color_token_delete`. Они MUST использовать существующий семейный API, адресовать семейство через tokenId его члена и сохранять серверную атомарность одной операции.

#### Scenario: Создание семейства
- **WHEN** переданы допустимые группа, имя и члены с начальными значениями
- **THEN** MCP MUST вызвать существующее создание семейства с заполнением тем по серверным правилам
- **THEN** ответ MUST содержать члены с tokenId

#### Scenario: Обновление выбранных членов
- **WHEN** переданы выбранные члены семейства с полным набором пар web/ios/android и light/dark для каждого
- **THEN** MCP MUST передать их одним семейным запросом
- **THEN** остальные члены и темы MUST NOT добавляться клиентом в запрос

#### Scenario: Неполные или повторяющиеся пары
- **WHEN** член содержит неполный набор пар платформы/режима или повтор одной пары
- **THEN** MCP MUST отклонить аргументы без записи
- **THEN** описание MUST направить к `token_edit_data_get` для подготовки полного набора или к точечному инструменту

#### Scenario: Перенос с переименованием
- **WHEN** семейство переносится в другую поддерживаемую группу с новым именем или позицией
- **THEN** MCP MUST использовать существующую операцию move и сохранить серверные ID членов

#### Scenario: Удаление семейства
- **WHEN** вызван `color_token_delete`
- **THEN** MCP MUST запросить удаление всего семейства по серверным правилам
- **THEN** описание MUST сообщать об удалении значений и привязок семейства во всех темах

### Requirement: Специализированная запись размеров и типографики

MCP SHALL предоставлять `size_token_value_update` и `typography_style_update` поверх существующих специализированных API. Платформенное наследование, составные значения и производные параметры MUST определяться сервером, а не формулами в MCP.

#### Scenario: Платформенное значение размера
- **WHEN** пользователь меняет размер или тень с поддерживаемыми платформенными параметрами
- **THEN** инструмент MUST передать исходные параметры и базовые редакции существующему редактору размеров

#### Scenario: Составные параметры типографики
- **WHEN** пользователь меняет размер, высоту строки, трекинг, веса или шрифт стиля
- **THEN** инструмент MUST передать только заданные параметры и выбранную платформу специализированному API
- **THEN** общие точечные инструменты MUST оставаться доступны для отдельных токенов

### Requirement: Цветовые группы и подгруппы

MCP SHALL предоставлять `token_group_create`, `token_group_update`, `token_group_delete` для поддерживаемого kind=color. Обновление SHALL поддерживать название, перенос подгруппы и позицию. Новые виды групп и дополнительные уровни вложенности MUST NOT добавляться.

#### Scenario: Перестановка и перенос
- **WHEN** пользователь меняет позицию группы либо переносит подгруппу между группами
- **THEN** инструмент MUST вызвать существующий API и сохранить его правила порядка и переименования токенов

#### Scenario: Каскадное удаление
- **WHEN** пользователь удаляет непустую группу
- **THEN** описание MUST явно сообщать об удалении вложенных групп и токенов с зависимыми данными
- **THEN** инструмент MUST сохранить поведение существующего удаления и серверные проверки прав

#### Scenario: Неподдерживаемое дерево
- **WHEN** указан нецветовой kind либо попытка вложить подгруппу в подгруппу
- **THEN** операция MUST завершиться ошибкой без расширения серверной модели

### Requirement: Исходные данные редактирования токена

`token_edit_data_get` SHALL возвращать данные черновика для tokenId и tenantId выбранной системы: определение, исходные и вычисленные значения, ссылки, признаки платформенных переопределений и доступные предметные редакции. Для распознаваемого цветового семейства SHALL возвращаться его члены и значения.

#### Scenario: Значение из палитры
- **WHEN** читается токен со ссылкой на палитру
- **THEN** результат MUST сохранять доступные sourceValue, paletteRef, paletteId и overridden
- **THEN** вычисленный цвет MUST NOT выдаваться за исходное хранимое значение

#### Scenario: Данные для семейной записи
- **WHEN** читается член цветового семейства
- **THEN** результат MUST позволять подготовить полный набор пар выбранных членов с базовыми редакциями
- **THEN** данные MUST быть ограничены выбранной дизайн-системой и темой

### Requirement: Тени не требуют семейного создания и удаления

MCP SHALL поддерживать точечные операции определений и значений теней и существующую специализированную запись значения. Семейное создание и удаление теней SHALL оставаться вне этого изменения; правило одновременного создания четырёх вариантов MUST NOT становиться обязательным контрактом MCP.

#### Scenario: Изменение существующего варианта тени
- **WHEN** пользователь меняет существующий вариант тени
- **THEN** MCP MUST использовать точечный инструмент либо size_token_value_update без создания других вариантов
