# design-system-version-journal-ui Specification

## Purpose
Раздел журнала версий в клиенте: отображение предметных изменений, отмена черновых правок и переход к их источнику.

## Requirements
### Requirement: Журнал открывается отдельным разделом дизайн-системы

Веб-клиент SHALL предоставлять полноэкранный раздел изменений выбранной дизайн-системы и SHALL использовать `tenantId`
маршрута только как контекст возврата к редактору.

#### Scenario: Пользователь открывает журнал из редактора темы

- **WHEN** пользователь выбирает раздел изменений в редакторе темы
- **THEN** клиент MUST открыть журнал по `projectId` и `designSystemId`
- **THEN** клиент MUST сохранить текущий `tenantId` для переходов к предметным источникам
- **THEN** экран MUST обозначать владельцем журнала дизайн-систему, а не отдельную Theme

#### Scenario: Журнал загружается

- **WHEN** клиент ожидает ответ списка изменений
- **THEN** экран MUST показать состояние загрузки без устаревших строк другой дизайн-системы

#### Scenario: Журнал обновляется после отмены

- **WHEN** клиент перечитывает журнал того же контекста после отмены изменения или события SSE
- **THEN** подтверждённые строки MUST оставаться видимыми до получения ответа без очистки списка и замены его экраном загрузки
- **THEN** новый список MUST заменить прежний за одно обновление
- **THEN** ошибка обновления MUST показываться рядом с сохранённым списком

#### Scenario: Журнал пуст

- **WHEN** сервер вернул пустой список изменений активного черновика
- **THEN** экран MUST сообщить, что неопубликованных изменений нет
- **THEN** экран MUST предложить вернуться в редактор

#### Scenario: Журнал не загрузился

- **WHEN** запрос журнала завершился ошибкой
- **THEN** экран MUST сохранить навигационный контекст и показать повтор загрузки
- **THEN** экран MUST NOT представлять ошибку как пустой журнал

### Requirement: Журнал показывает фактические предметные изменения

Веб-клиент SHALL преобразовывать `DraftChangeDto` в понятные пользовательские действия без вычисления влияния на
компоненты и без сведений о проверках.

#### Scenario: Показано одиночное изменение

- **WHEN** сервер вернул изменение темы, токена или компонентной конфигурации
- **THEN** заголовок записи токена MUST иметь формат «Тип: Имя» без кавычек и префикса «Изменение токена»
- **THEN** строка MUST показать предметную область, название сущности, вид операции, прежнее и новое значения, автора и
  время
- **THEN** подробности MUST показать человекочитаемые названия и прежние и новые значения изменённых полей
- **THEN** составные значения MUST быть разложены на отдельные поля без вывода JSON, служебных путей и идентификаторов
- **THEN** значения цветов MUST сопровождаться цветовыми образцами
- **THEN** ссылки на известные цвета палитры MUST разрешаться в цветовой образец с сохранением подписи ссылки
- **THEN** подпись палитровой ссылки MUST быть без квадратных скобок и показываться в одну строку с многоточием; полная подпись MUST быть доступна при наведении
- **THEN** размеры и параметры теней MUST показываться числами редактора без платформенных строк с `rem`
- **THEN** элемент массива слоёв MUST иметь подпись «Слой N», например «Слой 1 · Размытие»
- **THEN** старое значение скалярного токена, обёрнутое массивом из одного элемента, MUST сравниваться с новым скаляром как одно значение
- **THEN** параметры типографики MUST использовать английские названия, например `Font size`, `Line height` и `Font weight`

#### Scenario: Пакет содержит платформенные значения токена

- **WHEN** одно пользовательское действие изменило значения токена нескольких платформ одного режима
- **THEN** клиент MUST показать отдельную запись каждой платформы с её названием
- **THEN** клиент MUST сохранить отдельные `changeId` и технические редакции для доступных операций отмены
- **THEN** отмена записи MUST затронуть только выбранную платформу

#### Scenario: Пользователь фильтрует журнал

- **WHEN** пользователь выбирает источник: темы, палитру, цветовые токены, типографику, размеры и радиусы или компоненты
- **THEN** экран MUST показать только соответствующие действия и их количество
- **THEN** выбор фильтра MUST NOT запускать повторный сетевой запрос
- **THEN** текст и счётчик выбранного пункта MUST иметь горизонтальные отступы от его фона
- **THEN** ненулевые количества MUST показываться компактными серыми счётчиками, выровненными справа; нулевые счётчики фильтров MUST отсутствовать
- **THEN** заголовок «Черновик изменений» MUST NOT дублировать счётчик пункта «Все изменения»
- **THEN** меню MUST NOT содержать заголовок «Область», а подпись «По источнику» и названия пунктов MUST быть выровнены по горизонтали
- **THEN** подпись количества MUST склонять слово «изменение», а не использовать «действий»

#### Scenario: Данные проверок отсутствуют

- **WHEN** журнал и версии успешно загружены
- **THEN** интерфейс MUST NOT показывать влияние на компоненты, предупреждения, квитанции проверок, принятые исключения
  или готовые исправления
- **THEN** отсутствие этих данных MUST NOT блокировать просмотр журнала или публикацию

### Requirement: Изменение активного черновика можно отменить из журнала

Веб-клиент SHALL разрешать отмену только записи активного черновика пользователю с правом изменения дизайн-системы.

#### Scenario: Изменены несколько параметров значения токена

- **WHEN** у существующего значения одной платформы изменены несколько параметров без структурного изменения
- **THEN** клиент MUST показать отдельную строку и сравнение для каждого параметра, а счётчики MUST считать эти строки
- **THEN** отмена MUST передать путь выбранного параметра в `paths` существующей операции `revert`
- **THEN** сервер MUST восстановить параметр из своего состояния сравнения и сохранить все соседние значения
- **THEN** сервер MUST сохранить проверки прав, редакции и повторяемости и включить пути в отпечаток запроса
- **THEN** пустой или отсутствующий `paths` MUST сохранить прежнюю отмену записи целиком

#### Scenario: Клиент работает с прежней версией сервера

- **WHEN** в записи журнала отсутствует `parameterRevertSupported: true`
- **THEN** клиент MUST NOT разрешать или отправлять частичную отмену, которую прежний сервер мог бы трактовать как полную

#### Scenario: Изменился состав или обнаружена перестановка слоёв

- **WHEN** изменилось число слоёв либо совпадающий элемент перемещён на другую позицию
- **THEN** клиент MUST показать одну структурную запись без превью первого параметра, с полным составом в подробностях
- **THEN** сервер MUST отклонить частичное восстановление параметра по индексу этого массива
- **THEN** отмена структурной записи целиком MUST оставаться доступной

#### Scenario: Указан неподходящий путь отмены

- **WHEN** путь неизвестен, не изменён, затрагивает другую сущность или требует структурной отмены
- **THEN** сервер MUST вернуть `400 invalid_revert_paths` без изменения данных
- **THEN** создание и удаление сущности MUST NOT поддерживать частичную отмену

#### Scenario: Изменение успешно отменено

- **WHEN** пользователь запускает отмену доступного действия
- **THEN** клиент MUST передать `changeId`, его актуальную техническую редакцию и новый ключ повторяемости
- **THEN** после успеха клиент MUST перечитать журнал и затронутые данные редактора
- **THEN** кнопка отмены MUST быть доступна в строке списка и в подробностях изменения
- **THEN** повторный запуск отмены MUST быть заблокирован до завершения текущего запроса

#### Scenario: Запись журнала устарела

- **WHEN** сервер возвращает `409 DRAFT_CHANGE_STALE`
- **THEN** клиент MUST перечитать журнал
- **THEN** клиент MUST сообщить, что показаны актуальные данные
- **THEN** клиент MUST NOT повторять отмену автоматически

#### Scenario: Отмена нарушает зависимости

- **WHEN** сервер возвращает `409 REVERT_DEPENDENCY_CONFLICT`
- **THEN** клиент MUST сохранить актуальный журнал и объяснить, что изменение нельзя отменить из-за зависимых данных

#### Scenario: Открыта опубликованная версия или режим просмотра

- **WHEN** журнал открыт с `versionId` либо у пользователя нет права изменения
- **THEN** экран MUST показывать изменения только для чтения
- **THEN** действие отмены MUST отсутствовать

### Requirement: Запись журнала ведёт к предметному источнику

Веб-клиент SHALL строить цель перехода из типа сущности, прежнего и нового состояний и загруженной конфигурации.

#### Scenario: Источник определён точно

- **WHEN** для темы, токена, значения токена или компонента восстановлен точный маршрут
- **THEN** действие «Открыть источник» MUST перейти к соответствующей теме, токену или компоненту
- **THEN** переход из опубликованного журнала MUST сохранить `versionId`

#### Scenario: Определена только предметная область

- **WHEN** верхнеуровневую сущность удалённой или вложенной компонентной записи нельзя восстановить
- **THEN** действие MUST открыть соответствующий раздел редактора
- **THEN** интерфейс MUST NOT выбирать произвольную сущность как точный источник

#### Scenario: Источник недоступен

- **WHEN** сущность больше не существует и для неё нет подходящего раздела
- **THEN** интерфейс MUST обозначить переход недоступным
- **THEN** просмотр прежнего и нового значений MUST оставаться доступным

### Requirement: Раздел версий объединяет черновик публикации и историю

Веб-клиент SHALL показывать активный черновик и опубликованные версии одной дизайн-системы в самостоятельном
полноэкранном разделе.

#### Scenario: Выбран активный черновик

- **WHEN** пользователь открывает раздел версий без выбранной опубликованной версии
- **THEN** экран MUST показать предлагаемый номер, редактируемое описание и состав активного журнала
- **THEN** экран MUST показать текущую опубликованную версию и количество включаемых изменений
- **THEN** боковое меню MUST содержать один пункт «Черновик публикации» без отдельного заголовка секции, с серым счётчиком справа при ненулевом количестве

#### Scenario: Выбрана опубликованная версия

- **WHEN** пользователь выбирает опубликованную версию
- **THEN** экран MUST показать её номер, дату публикации, описание и журнал относительно предыдущей границы
- **THEN** все данные выбранной версии MUST быть доступны только для чтения
- **THEN** выбор MUST менять только `historyVersionId` и MUST NOT менять `versionId`, загруженную версию и доступность записи в редакторе
- **THEN** выбор изменения из истории MUST показать его подробности внутри раздела версий без перехода редактора на эту версию
- **THEN** счётчик пункта «Черновик публикации» MUST продолжать показывать количество изменений активного черновика, не выбранной истории

#### Scenario: Опубликованных версий нет

- **WHEN** список опубликованных версий пуст
- **THEN** экран MUST показать активный черновик как единственный пункт
- **THEN** экран MUST объяснить, что первая версия появится после публикации непустого черновика

#### Scenario: Версии не загрузились

- **WHEN** запрос списка версий завершился ошибкой
- **THEN** экран MUST показать ошибку и действие повторной загрузки
- **THEN** экран MUST NOT подставлять сохранённый в браузере список версий

### Requirement: Версия редактора выбирается только в верхней панели

Веб-клиент SHALL показывать выпадающий селектор версии в существующей стилистике проекта.
Настройки темы SHALL быть последним пунктом боковой панели, а журнал SHALL находиться под разделителем.
Выбранный элемент боковой панели SHALL иметь серый фон и рамку без акцентной заливки.
Верхняя панель SHALL содержать акцентную кнопку «Изменения · N», открывающую журнал; число SHALL NOT иметь отдельного фона.
Кнопка и меню селектора версии SHALL иметь ширину по содержимому с ограничением размером окна.

#### Scenario: Пользователь открывает настройки темы из rail

- **WHEN** пользователь открывает настройки темы или меняет их подраздел
- **THEN** маршрут MUST оставаться внутри оболочки редактора `Main`, сохраняя весь rail и верхнюю панель
- **THEN** загрузка, ошибка и успешное отображение настроек MUST NOT создавать повторную оболочку с другим rail
- **THEN** отложенный переход из rail MUST NOT удерживать предыдущий раздел как промежуточное содержимое рабочей области
- **THEN** прямой адрес настроек с `versionId` MUST NOT предоставлять изменение активного черновика

#### Scenario: Пользователь переключает раздел редактора

- **WHEN** пользователь открывает раздел токенов, компонентов, журнала, версий или настроек темы
- **THEN** хлебные крошки MUST показывать проект, дизайн-систему, тему и название текущего раздела
- **THEN** название раздела MUST быть последним элементом с `aria-current="page"`
- **THEN** ссылка на тему MUST сохранять выбранный `versionId`

#### Scenario: Выбрана опубликованная версия редактора

- **WHEN** пользователь выбирает опубликованную версию в верхней панели
- **THEN** клиент MUST задать `versionId` и загрузить предметные данные выбранной версии только для чтения
- **THEN** верхняя панель MUST NOT показывать надписи «Режим просмотра» и «Сохранено»

#### Scenario: Пользователь возвращается к черновику

- **WHEN** пользователь выбирает активный черновик в верхней панели
- **THEN** клиент MUST убрать `versionId` и загрузить актуальный черновик с учётом прав пользователя
- **THEN** индикатор сохранения MUST показываться только для активного черновика с правом записи
- **THEN** активный черновик MUST иметь подпись «Черновик» в селекторе

#### Scenario: Подтверждено автосохранение

- **WHEN** сервер подтвердил сохранение в текущей сессии
- **THEN** вместо текста «Сохранено» MUST показываться дискета с зелёной галочкой в углу и подсказкой «Последнее сохранение — <время>»
- **THEN** время MUST относиться к подтверждённому сохранению текущей темы, а не загрузке страницы или другой теме
- **THEN** до первого подтверждения без известного времени MUST показываться подсказка «Нет несохранённых изменений»
- **THEN** ожидание, сохранение и ошибка MUST оставаться различимыми и доступными для вспомогательных технологий
- **THEN** подсказка MUST явно открываться при наведении и фокусе поверх рабочей области

#### Scenario: Сохранение завершилось ошибкой после успешного сохранения

- **WHEN** очередное сохранение завершилось ошибкой
- **THEN** дискета MUST показывать красный крестик и предлагать повтор нажатием
- **THEN** подсказка MUST сохранять время последнего успешного сохранения и сообщать об ошибке
- **THEN** если подтверждённого успеха ещё не было, интерфейс MUST NOT придумывать время

#### Scenario: Перед переключением есть несохранённые изменения

- **WHEN** пользователь выбирает другую версию во время автосохранения черновика
- **THEN** клиент MUST дождаться завершения очередей и MUST NOT переключать редактор при ошибке сохранения

### Requirement: Пользователь публикует актуальный серверный черновик

Веб-клиент SHALL запускать публикацию только после завершения локальных очередей автосохранения и повторного чтения
актуальных `draftId` и `draftRevision`.

#### Scenario: Публикация доступна

- **WHEN** активный журнал непуст, номер соответствует `major.minor.patch` и пользователь имеет право
  изменения
- **THEN** действие публикации MUST быть доступно
- **THEN** клиент MUST показать включаемые изменения до отправки запроса

#### Scenario: Примечания не заполнены

- **WHEN** остальные условия публикации выполнены, а примечания пусты
- **THEN** действие публикации MUST оставаться доступным
- **THEN** сервер MUST принимать пустой `changelog` или его отсутствие и сохранять примечания как пустую строку

#### Scenario: Публиковать нечего

- **WHEN** активный журнал пуст
- **THEN** действие публикации MUST быть недоступно
- **THEN** экран MUST предложить открыть редактор

#### Scenario: Черновик успешно опубликован

- **WHEN** сервер создал опубликованную версию
- **THEN** клиент MUST сохранить полученный `DesignSystemVersionDto` как подтверждённый результат
- **THEN** список версий и новый пустой черновик MUST быть перечитаны

#### Scenario: Черновик изменился перед публикацией

- **WHEN** сервер возвращает `409 DRAFT_STALE`
- **THEN** клиент MUST перечитать данные черновика, журнал и список версий
- **THEN** клиент MUST предложить пользователю проверить состав и повторить публикацию явно
- **THEN** клиент MUST NOT повторять публикацию автоматически

#### Scenario: Пользователь не имеет права публикации

- **WHEN** пользователь может только просматривать дизайн-систему
- **THEN** форма публикации MUST быть доступна только для чтения
- **THEN** действие публикации MUST отсутствовать

### Requirement: Результат публикации отражает создание версии дизайн-системы

Веб-клиент SHALL считать публикацию завершённой после создания версии в `ds-service` и SHALL NOT запускать или
показывать публикацию npm-пакета в этом потоке.

#### Scenario: Версия дизайн-системы создана

- **WHEN** сервер вернул созданную версию
- **THEN** интерфейс MUST показать номер созданной версии
- **THEN** клиент MUST перечитать список версий и новый пустой черновик

#### Scenario: Версия дизайн-системы не создана

- **WHEN** операция публикации завершилась ошибкой до создания версии
- **THEN** интерфейс MUST сообщить, что версия не создана и черновик сохранён

#### Scenario: Публикация не запускает создание npm-пакета

- **WHEN** сервер вернул созданную версию дизайн-системы
- **THEN** клиент MUST NOT вызывать операцию публикации npm-пакета
- **THEN** интерфейс MUST NOT показывать состояние или результат публикации npm-пакета

### Requirement: Экран сохраняет доступность и адаптивную компоновку

Полноэкранные журнал и версии SHALL оставаться управляемыми с клавиатуры и на узком экране.

#### Scenario: В списке есть длинные значения

- **WHEN** строка показывает прежнее и новое значения
- **THEN** область сравнения MUST использовать доступную ширину рядом с названием изменения
- **THEN** текст значения MUST переноситься при недостатке места без обрезания многоточием, кроме палитровых ссылок с однострочной подписью
- **THEN** в широкой компоновке сравнение MUST занимать около 30% строки, оставляя место названию и кнопке отмены
- **THEN** выделение выбранной строки MUST включать всю ширину, в том числе область кнопки отмены

#### Scenario: Пользователь работает с клавиатуры

- **WHEN** пользователь перемещается между фильтрами, строками, подробностями и действиями
- **THEN** порядок фокуса MUST соответствовать визуальному порядку
- **THEN** выбранные фильтр, запись и версия MUST иметь доступное текстовое состояние

#### Scenario: Экран имеет малую ширину

- **WHEN** ширины недостаточно для трёх колонок
- **THEN** фильтры, список и подробности MUST располагаться последовательно без потери действий
- **THEN** прежнее и новое значения MUST оставаться различимыми без опоры только на цвет

### Requirement: Журнал показывает градиентные значения цветовых токенов понятно

Журнал SHALL показывать значения цветового токена в терминах редактора, а не хранимого JSON. Цвет SHALL
показываться свотчем и именем ступени палитры или HEX. Градиент SHALL показываться свотчем с градиентом и подписью
вида «Linear · 45°», «Radial» или «Conic · 90°». Ссылки на палитру внутри стопов SHALL показываться именами ступеней,
например «Green 400». Изменённые параметры градиента SHALL называться по-человечески: «Вид значения», «Тип»,
«Угол», «Центр», «Радиус», «Начальный угол», «Стоп N · цвет», «Стоп N · позиция».

#### Scenario: Цвет стал градиентом

- **WHEN** в черновике значение Dark сменилось с цвета Green 400 на градиент Conic
- **THEN** запись MUST показать «Green 400 → Conic · 0°» со свотчами цвета и градиента
- **THEN** запись MUST NOT показывать CSS-строку, JSON слоя или ссылки вида `[general.green.400]`

#### Scenario: Изменился стоп градиента

- **WHEN** у градиента изменились угол и цвет второго стопа с Teal 400 на Blue 500, а тип и число стопов прежние
- **THEN** запись MUST показать отдельные строки «Угол» и «Стоп 2 · цвет: Teal 400 → Blue 500»
- **THEN** для `ios` и `android` отмена строки «Стоп 2 · цвет» MUST передать путь этого параметра в `paths`
  (например `/value/0/colors/1`) и вернуть только его
- **THEN** для `web` слой хранится одной CSS-строкой: если в записи изменился один параметр слоя, его строку MUST
  отменять путём `/value/0`; если несколько, строки MUST показываться без частичной отмены, а запись MUST
  отменяться целиком

#### Scenario: Смена вида значения

- **WHEN** значение сменилось с цвета на градиент или обратно, либо изменились тип градиента или число стопов
- **THEN** запись MUST быть одной структурной строкой, и её MUST отменять только целиком

#### Scenario: Значение платформы

- **WHEN** изменилось значение `ios` или `android`
- **THEN** запись MUST показывать его так же, как значение web, с указанием платформы, без путей вида
  «Слой 1 · Параметр · Слой 2»
