# figma-token-export Specification

## Purpose
Экспорт темы DS Builder из плагина Figma в переменные и стили открытого файла по структуре образца `DS BUILDER | STYLES`.

## Requirements
### Requirement: Действие экспорта

Окно темы SHALL предлагать действие «Экспортировать в Figma» для выбранной темы и версии. Экспорт SHALL читать токены, значения web, палитру темы, группы токенов, типографику и размеры на одной границе версии через общий модуль `:plugins:figma-core` и записывать результат в открытый файл Figma. Во время экспорта действие MUST быть недоступно повторно.

#### Scenario: Экспорт опубликованной версии

- **WHEN** пользователь выбрал тему, версию `1.2.0` и нажал «Экспортировать в Figma»
- **THEN** все чтения MUST выполняться с `versionId` этой версии
- **THEN** после записи окно MUST показать отчёт с темой, версией и числом созданных, обновлённых, устаревших и пропущенных объектов

#### Scenario: Ошибка чтения

- **WHEN** gateway отвечает ошибкой на одно из чтений
- **THEN** файл Figma MUST NOT изменяться, а окно MUST показать сообщение об ошибке с действием «Повторить»

### Requirement: Коллекции и режимы

Экспорт SHALL создавать коллекции переменных `00. Palette` с одним режимом, `01. Theme` с режимами `Light` и `Dark`, `02. SubTheme` с режимами `Default`, `onDark`, `onLight`, `Inverse`, `03. Typography` с режимами `Large`, `Medium`, `Small`, `04. Numbers` и `05. Spacing` с одним режимом.

#### Scenario: Пустой файл

- **WHEN** экспорт выполняется в файле без переменных DS Builder
- **THEN** в файле MUST появиться шесть коллекций с перечисленными режимами в указанном порядке

#### Scenario: Тариф не разрешает режимы

- **WHEN** Figma отказывает в добавлении режима
- **THEN** экспорт MUST прекратиться, а отчёт MUST содержать причину отказа Figma

### Requirement: Цвета темы

Каждый включённый токен `color` и токен `gradient` со сплошными значениями в обоих режимах SHALL становиться переменной `COLOR` в `01. Theme` со значениями режимов `Light` и `Dark` из web. Имя переменной SHALL собираться как `<корень>/<контекст>/<категория>/<имя>`: корень — подпись корневой группы токена со сжатием `" & "` до `"&"`, контекст `Default`, `onDark`, `onLight`, `Inverse` (у группы `background` — `onDark` для `dark`, `onLight` для `light`, без сегмента для `default`), категория — подпись вложенной группы, разбитая по `/`, без подписи `Default`, имя — последний сегмент имени токена в PascalCase; у составной категории из двух и более частей первое слово имени, совпадающее с последней частью категории, отбрасывается. Токены с суффиксом состояния `-hover`, `-active`, `-brightness` и выключенные токены MUST NOT экспортироваться.

#### Scenario: Прозрачный акцент

- **WHEN** токен `surface.on-dark.transparent-accent` входит в группу «Surfaces» / «Accent / Transparent»
- **THEN** экспорт MUST создать переменную `Surfaces/onDark/Accent/Transparent/Accent`

#### Scenario: Простая категория

- **WHEN** токен `text.default.accent-minor` входит в группу «Text & Icons» / «Accent»
- **THEN** экспорт MUST создать переменную `Text&Icons/Default/Accent/AccentMinor`

#### Scenario: Фон по умолчанию

- **WHEN** токен `background.default.primary` входит в группу «BG» / «Default»
- **THEN** экспорт MUST создать переменную `BG/Primary`

#### Scenario: Состояние

- **WHEN** у темы есть токен `text.default.accent-hover`
- **THEN** переменная для него MUST NOT создаваться, а отчёт MUST учитывать его как пропущенный

### Requirement: Ссылки на палитру

Экспорт SHALL создавать в `00. Palette` переменную `<подпись группы палитры>/<имя шкалы>/<ступень>` для каждой ступени палитры темы. Значение режима темы с `paletteRef` SHALL записываться ссылкой на переменную ступени той группы палитры, к которой привязан токен; прозрачность ссылки SHALL сохраняться составным цветом Figma с прозрачностью в процентах. Значение без `paletteRef` или со ступенью, которой нет в палитре, SHALL записываться цветом RGBA.

#### Scenario: Ссылка с прозрачностью

- **WHEN** значение режима Dark имеет `paletteRef` `[general.gray.900][0.16]`, а токен привязан к группе палитры «Neutral»
- **THEN** значение переменной темы в режиме Dark MUST быть ссылкой на `Neutral/Gray/900` с прозрачностью 16

#### Scenario: Значение задано вручную

- **WHEN** значение режима Light — `#F5F5F593` без `paletteRef`
- **THEN** значение переменной MUST быть цветом с прозрачностью `0x93 / 255`

### Requirement: Подтемы

Для каждого корня, категории и имени цветовой переменной темы экспорт SHALL создавать переменную в `02. SubTheme` с именем без контекста. Значение режима подтемы SHALL ссылаться на переменную темы с соответствующим контекстом, а при её отсутствии — на переменную контекста `Default`.

#### Scenario: Подтема onDark

- **WHEN** в теме есть `Text&Icons/Default/General/Primary` и `Text&Icons/onDark/General/Primary`
- **THEN** переменная `Text&Icons/General/Primary` в `02. SubTheme` MUST ссылаться в режиме `onDark` на `Text&Icons/onDark/General/Primary`, а в режиме `Default` — на `Text&Icons/Default/General/Primary`

### Requirement: Градиенты

Токен `gradient`, у которого хотя бы в одном режиме значение web содержит градиент, SHALL экспортироваться парой стилей заливки `Light/<имя переменной темы>` и `Dark/<имя переменной темы>`. Слой `linear-gradient` SHALL становиться линейным градиентом Figma с углом и стопами, сплошной слой — сплошной заливкой. Значение, которое не удалось разобрать, SHALL пропускаться с причиной в отчёте.

#### Scenario: Градиент в одном режиме

- **WHEN** у токена в Light значение `#1A9E32`, а в Dark `linear-gradient(45deg, #1A9E32FF 0%, #04C6C9FF 100%)`
- **THEN** экспорт MUST создать стиль `Light/…` со сплошной заливкой и стиль `Dark/…` с линейным градиентом из двух стопов

### Requirement: Типографика

Экспорт SHALL создавать в `03. Typography` переменные `Font Size`, `Line Height`, `Letter Spacing` в px и `Font Weight` для каждого стиля и варианта начертания со значениями экранов `screen-l`, `screen-m`, `screen-s` в режимах `Large`, `Medium`, `Small`, а также строковые переменные `FontFamily/<Имя>` со шрифтом семейства. Для каждого стиля и варианта SHALL создаваться текстовый стиль с привязкой размера, высоты строки, интервала, насыщенности и семейства к этим переменным. Если шрифта семейства нет в Figma, текстовый стиль SHALL пропускаться с причиной, а переменные MUST создаваться.

#### Scenario: Заголовок

- **WHEN** у стиля `header.h1` есть вариант `bold` с размером 48 px на `screen-l` и 32 px на `screen-s`
- **THEN** переменная `Header/H1 B/Font Size` MUST иметь значение 48 в режиме `Large` и 32 в режиме `Small`
- **THEN** текстовый стиль `Header/H1 B` MUST быть привязан к этой переменной

#### Scenario: Шрифт не найден

- **WHEN** шрифта `SB Sans Display` нет среди доступных шрифтов Figma
- **THEN** текстовые стили этого семейства MUST быть пропущены с причиной, а переменные типографики MUST быть созданы

### Requirement: Размеры и тени

Экспорт SHALL создавать `CornerRadius/<хвост имени>` в `04. Numbers` с областью применения `CORNER_RADIUS` (полное скругление — 9999), `Spacing/<хвост имени>` в `05. Spacing` с областью применения `GAP`, и стиль эффектов `Shadows/<сегменты имени>` из слоёв тени web.

#### Scenario: Тень из двух слоёв

- **WHEN** у тени `down.soft.s` два слоя web
- **THEN** стиль эффектов `Shadows/Down/Soft/S` MUST содержать два `DROP_SHADOW` с теми же смещением, размытием, расширением и цветом

### Requirement: Повторный экспорт

Каждый объект, созданный экспортом, SHALL получать общий ключ плагина в пространстве `dsbuilder`. Повторный экспорт SHALL находить объекты по этому ключу и обновлять имя, значения, области применения и привязки, не создавая дубликатов. Объекты с ключом DS Builder, которых нет в новом плане, MUST NOT удаляться и SHALL учитываться в отчёте как устаревшие. Если имя из плана занято устаревшей переменной DS Builder, она SHALL получить имя с пометкой «(устарело)»; если имя занято переменной, созданной не DS Builder, переменная плана SHALL быть пропущена с причиной. Экспорты в одном файле SHALL выполняться по очереди.

#### Scenario: Изменился цвет

- **WHEN** после экспорта цвет токена изменён в DS Builder и экспорт выполнен снова
- **THEN** значение существующей переменной MUST обновиться, число переменных в коллекции MUST NOT вырасти, а слои, привязанные к переменной, MUST получить новый цвет

#### Scenario: Имя занято устаревшей переменной

- **WHEN** токен удалён и создан заново с тем же именем, и экспорт выполнен снова
- **THEN** старая переменная MUST получить имя с пометкой «(устарело)», а новая MUST получить имя токена, и экспорт MUST завершиться без отказа

#### Scenario: Токен переименован

- **WHEN** токен переименован в DS Builder и экспорт выполнен снова
- **THEN** существующая переменная MUST получить новое имя вместо создания второй переменной

### Requirement: Построение плана в общем модуле

Правила имён, ссылок и состава экспорта MUST находиться в `:plugins:figma-core`. Основной поток плагина MUST применять полученный план без собственных правил DS Builder.

#### Scenario: Проверка исходного кода

- **WHEN** выполняются тесты плагина
- **THEN** они MUST завершаться ошибкой, если код основного потока обращается к сети или содержит путь `/api/`
