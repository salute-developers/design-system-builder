# cli-node-runtime Specification

## Purpose
Полный CLI `dsbuilder` под Node.js с общими сценариями JVM/native, инфраструктурой файлов, процессов, авторизации, терминала и MCP.

## Requirements
### Requirement: Полный набор команд Node.js CLI

Node.js-вариант `dsbuilder` SHALL использовать общее с JVM/native дерево команд и сценарии application, сохраняя имена, параметры, форматы файлов, сообщения и коды завершения при одинаковых входных данных и возможностях ОС.

#### Scenario: Дерево команд
- **WHEN** установленный Node.js CLI получает корневой либо вложенный `--help`
- **THEN** он MUST предоставлять те же команды `init`, `status`, `auth`, `theme`, `components`, `ds`, `docs`, `toolchain`, `icons`, `preview-plugin`, `analytics` и `mcp` с теми же вложенными командами и параметрами, что JVM CLI из того же исходного кода
- **THEN** справка, версия и ошибки разбора MUST работать без backend, credentials, Docker и `.sdds`

#### Scenario: Выполнение пользовательских сценариев
- **WHEN** одинаковые входные файлы, параметры и управляемые ответы backend переданы JVM и Node CLI
- **THEN** создание проекта, загрузка/публикация данных, aliases, импорт API, публикация и генерация MUST сохранять одинаковые результаты, форматы и коды завершения
- **THEN** отсутствие необходимого SDK или инструмента MUST давать прежнюю диагностическую ошибку, а не отсутствие команды или JS-заглушку

### Requirement: Приостанавливаемый жизненный цикл команд

Общий CLI SHALL ожидать завершение приостанавливаемой команды, обработки результата и освобождения ресурсов. Синхронное ожидание корутины SHALL быть допустимо только на верхней платформенной границе JVM/native, не в общем коде и не в Node.js.

#### Scenario: Ожидание сети
- **WHEN** команда ожидает ответ локального тестового HTTP-сервера
- **THEN** цикл событий Node MUST продолжать обслуживать ответ, таймеры и отмену
- **THEN** CLI MUST завершиться после результата команды, сохранив её код завершения

#### Scenario: Ошибка и отмена
- **WHEN** команда завершается ошибкой либо отменяется пользователем
- **THEN** CLI MUST освободить принадлежащие ему HTTP-клиенты, потоки и обработчики, ограничить ожидание аналитики и восстановить терминал
- **THEN** отмена MUST распространяться к активному процессу и давать CLI-код 130 без вывода успешного результата
- **THEN** принудительное завершение Node до записи итоговых stdout/stderr MUST NOT обрезать вывод

### Requirement: Общая инфраструктура Node для CLI и MCP

CLI и отдельный MCP launcher SHALL использовать общие Node-реализации портов `ClientRuntime` из инфраструктурного модуля без зависимостей между executable-приложениями и без переноса бизнес-логики в runtime.

#### Scenario: Совместимая сессия
- **WHEN** CLI сохраняет пользовательскую сессию для backend и Node MCP читает её либо обновляет токен
- **THEN** оба приложения MUST использовать существующие формат сессии, адрес backend и PID-блокировку, совместимые с JVM/native
- **THEN** конкурирующие записи MUST оставаться взаимно исключающими, а блокировка завершённого владельца MUST восстанавливаться
- **THEN** токены MUST NOT появляться в выводе `auth status` или диагностике блокировки

#### Scenario: Браузерный вход и MCP
- **WHEN** пользователь запускает `auth login` под Node.js
- **THEN** CLI MUST использовать существующий PKCE-поток и сообщать об успехе только после сохранения сессии
- **WHEN** запускается `mcp serve` либо отдельный `dsbuilder-mcp serve`
- **THEN** запуск MUST NOT открывать браузер, а stdout MUST содержать только JSON-RPC
- **THEN** initialize и tools/list MUST сохранять общий набор инструментов из `mcp-server-core`

### Requirement: Полноценная файловая система Node

Node runtime SHALL реализовать все операции `WorkspaceFileSystem`, включая бинарные данные и файловые потоки, с сохранением контрактов локальных файлов и учётных данных.

#### Scenario: Бинарная запись и поток
- **WHEN** файл с произвольными байтами записан через `writeBytes` либо `sink` и затем прочитан
- **THEN** байты MUST совпадать, закрытие потока MUST сохранять данные, а пути с пробелами и Unicode MUST работать
- **THEN** операции MUST NOT возвращать ошибку о неподдерживаемом MCP-сценарии

#### Scenario: Атомарная запись
- **WHEN** запись пользовательской сессии прерывается до атомарной замены
- **THEN** предыдущая сессия MUST оставаться читаемой, а временные файлы MUST очищаться
- **THEN** ограничения доступа MUST сохраняться согласно существующим правилам ОС

### Requirement: Документация и preview-плагин на Node

Node.js CLI SHALL выполнять существующие команды документации и публикации preview-плагина без платформенных заглушек и ослабления проверок входных архивов.

#### Scenario: Архив документации
- **WHEN** `docs generate` получает допустимые локальные файлы и успешный ответ платформенного инструмента
- **THEN** результат MUST содержать совместимый TAR.GZ с прежними исключениями, вложенными каталогами, бинарными ресурсами и длинными именами
- **THEN** `docs publish` MUST передавать точные байты архива существующему API
- **WHEN** необходимого файла или каталога нет
- **THEN** CLI MUST завершиться содержательной ошибкой без ложного успешного результата

#### Scenario: ZIP preview-плагина
- **WHEN** допустимый ZIP передан `preview-plugin publish`
- **THEN** CLI MUST извлечь manifest/meta и передать неизменённые байты ZIP существующему API
- **WHEN** архив повреждён, превышает действующие лимиты или содержит запрещённые пути/состав
- **THEN** CLI MUST отклонить его до публикации по тем же правилам, что существующие таргеты

### Requirement: Интерактивный терминал Node

Node.js CLI SHALL сохранять контракт интерактивного `init` и подтверждений аналитики в поддерживаемом TTY и детерминированное поведение без TTY.

#### Scenario: Меню и восстановление
- **WHEN** пользователь выбирает проект, систему и платформы через стрелки, Enter и Space
- **THEN** Node CLI MUST сохранить выбранные значения по прежнему контракту
- **WHEN** ввод завершён, получен EOF, Ctrl+C либо произошла ошибка
- **THEN** режим терминала и видимость курсора MUST восстанавливаться
- **THEN** отменённый выбор MUST NOT создавать `.sdds/config.json`

#### Scenario: Явные параметры без терминала
- **WHEN** оба ID переданы без TTY
- **THEN** `init` MUST работать без меню и сетевого запроса выбора
- **WHEN** ID недостаёт
- **THEN** CLI MUST вернуть ошибку с нужными параметрами без ожидания stdin

### Requirement: Согласие и аналитика Node CLI

Node CLI SHALL соблюдать существующие согласие, отзыв, каналы CLI/MCP и переменные отключения аналитики с приостанавливаемой обработкой и ограниченным ожиданием завершения.

#### Scenario: Запрет аналитики
- **WHEN** согласие отсутствует, отозвано либо аналитика отключена поддерживаемой переменной окружения
- **THEN** Node CLI MUST NOT отправлять события вопреки существующей политике
- **THEN** help/version, CI и MCP MUST NOT инициировать интерактивный вопрос

#### Scenario: Завершение и ошибка доставки
- **WHEN** разрешённое событие ожидает отправки при завершении команды
- **THEN** ожидание MUST быть ограничено существующим бюджетом завершения аналитики
- **THEN** ошибка доставки MUST NOT менять результат команды или нарушать JSON-RPC stdout
- **THEN** аналитика MUST NOT поглощать отмену основной операции
