# ide-plugin-component-storybook Specification

## Purpose

Определяет просмотр Compose-компонентов дизайн-системы в плагине Android Studio / IntelliJ IDEA: поиск, окно превью, выбор вариации и конфигурации и копирование опубликованной ссылки на код без изменения данных и проекта пользователя.

## Requirements

### Requirement: Список компонентов дизайн-системы

Плагин SHALL предоставлять раздел «Компоненты» рядом с разделом токенов. Раздел SHALL показывать Compose-компоненты выбранной дизайн-системы с поиском по имени и SHALL NOT показывать компоненты других платформ.

#### Scenario: Открытие раздела

- **WHEN** пользователь выбрал проект, дизайн-систему и tenant и открыл раздел «Компоненты»
- **THEN** плагин показывает список Compose-компонентов дизайн-системы
- **THEN** компоненты других платформ в списке отсутствуют

#### Scenario: Поиск

- **WHEN** пользователь вводит текст в поле поиска
- **THEN** список содержит только компоненты, в имени которых есть этот текст без учёта регистра

#### Scenario: Нет компонентов

- **WHEN** у дизайн-системы нет Compose-компонентов
- **THEN** плагин показывает пустое состояние с пояснением, а не ошибку

### Requirement: Окно компонента с превью

Плагин SHALL открывать по выбору компонента окно компонента с превью, названием и элементами управления вариацией и конфигурацией. Основные данные окна SHALL запрашиваться через `GET /api/design-systems/{designSystemId}/components/{componentId}/editor-bundle?platform=compose`. Для используемых ссылок `component_style` плагин SHALL дополнительно загружать конфигурации целевых Compose-компонентов той же дизайн-системы, включая транзитивные ссылки; сведения `dependencyComponents` SHALL NOT считаться экспортом конфигураций.

#### Scenario: Открытие окна

- **WHEN** пользователь выбирает компонент в списке
- **THEN** плагин запрашивает `editor-bundle` компонента с `platform=compose`
- **THEN** окно показывает превью компонента с вариацией и конфигурацией по умолчанию

#### Scenario: Вложенный стиль другого компонента

- **WHEN** выбранная конфигурация содержит ссылку `component_style` на другой компонент
- **THEN** плагин загружает его `editor-bundle` и необходимые транзитивные цели до сборки payload
- **THEN** превью содержит разрешённый вложенный стиль, включая выбранные значения и значения по умолчанию целевой конфигурации

#### Scenario: Зависимость не разрешена

- **WHEN** цель ссылки отсутствует, неоднозначна, недоступна, образует цикл или превышает предел глубины TypeScript-сборщика
- **THEN** плагин показывает диагностику с путём ссылки и не отправляет неполный payload
- **THEN** выбор конфигурации и копирование кода остаются доступными

#### Scenario: Общая зависимость и повтор загрузки

- **WHEN** несколько ссылок требуют один компонент в том же контексте
- **THEN** плагин переиспользует успешный ответ либо запрос в полёте вместо повторного запроса
- **THEN** после ошибки явный повтор заново читает данные и не использует ошибку как кешированный успех

#### Scenario: Возврат к списку

- **WHEN** пользователь возвращается к списку из окна компонента
- **THEN** список сохраняет текст поиска и позицию

#### Scenario: Ошибка загрузки

- **WHEN** запрос `editor-bundle` завершается ошибкой
- **THEN** окно показывает сообщение об ошибке с кнопкой повтора, а не пустое превью

### Requirement: Выбор вариации и конфигурации

Окно компонента SHALL позволять выбрать значение по каждой оси вариаций и конфигурацию (оформление) компонента. Выбор SHALL влиять только на превью и на кнопку копирования кода и SHALL NOT сохраняться в DS Builder или в проект пользователя.

#### Scenario: Смена вариации

- **WHEN** пользователь выбирает другое значение оси вариаций
- **THEN** плагин собирает новый payload и показывает обновлённое превью в той же сессии без перезагрузки плагина превью

#### Scenario: Смена конфигурации

- **WHEN** пользователь выбирает другую конфигурацию компонента
- **THEN** превью показывает компонент с её значениями

#### Scenario: Изменения не сохраняются

- **WHEN** пользователь меняет вариацию или конфигурацию
- **THEN** плагин MUST NOT отправлять запросы изменения данных в ds-service
- **THEN** плагин MUST NOT создавать или менять файлы открытого проекта

#### Scenario: Единственный вариант

- **WHEN** у компонента нет осей вариаций или одна конфигурация
- **THEN** соответствующий элемент управления не показывается

### Requirement: Копирование кода вариации

Окно компонента SHALL содержать кнопку «Копировать код», которая копирует в буфер обмена представление выбранной вариации в коде: значение `composeReference` с добавленным вызовом `.style()` (например, `Switch.L.style()`) из биндинга `component-style` (subject `components.<key>`) последней публикации дизайн-системы для платформы `compose`. Плагин SHALL сначала однозначно сопоставить имя выбранной конфигурации из экспорта с `styles[].styleName`, затем полный набор выбранных осей и значений по умолчанию с `variations[].props` этого оформления независимо от порядка пар. Имена SHALL нормализоваться обрезкой краевых пробелов, удалением дефисов, подчёркиваний и пробельных символов и приведением регистра через `Locale.ROOT`; остальные символы сохраняются. Коллизия нормализованных имён, повтор оси, отсутствие или множественность совпадений SHALL приводить к статусу «Нет ссылки» без копирования.

#### Scenario: Ссылка найдена

- **WHEN** пользователь нажимает «Копировать код»
- **THEN** плагин находит последнюю публикацию (`GET /documentation/publications/active` без `version`) и биндинг компонента по точному `subject`
- **THEN** плагин выбирает оформление текущей конфигурации, затем его вариацию по полному набору осей, копирует выражение `<composeReference>.style()` и показывает статус «Скопировано»

#### Scenario: Одинаковые оси в разных оформлениях

- **WHEN** биндинг содержит два оформления с одинаковыми `props`, но разными `composeReference`, и пользователь переключает конфигурацию
- **THEN** следующее нажатие копирует ссылку только выбранного оформления

#### Scenario: Нормализация экспортных имён

- **WHEN** выбранная конфигурация называется `basic-button`, оформление — `BasicButton`, а выбранное значение `m` опубликовано как `M`
- **THEN** плагин сопоставляет их по нормализованным именам при единственном совпадении всех пар

#### Scenario: Неоднозначное совпадение

- **WHEN** нормализация даёт коллизию имён либо несколько оформлений или вариаций совпадают с выбором
- **THEN** плагин показывает «Нет ссылки» и не копирует первый найденный результат

#### Scenario: Выбор изменился во время запроса

- **WHEN** после нажатия пользователь меняет конфигурацию или оси до получения ответа
- **THEN** ответ для прежнего выбора не изменяет буфер обмена и не показывает «Скопировано» для нового выбора

#### Scenario: Ссылки нет

- **WHEN** дизайн-система не опубликована, компонента, выбранного оформления или вариации нет в публикации либо `composeReference` пуст
- **THEN** плагин ничего не копирует и показывает статус «Нет ссылки»
- **THEN** при ошибке запроса плагин показывает статус «Ошибка»

#### Scenario: Запрос по нажатию

- **WHEN** пользователь просматривает список и окно компонента
- **THEN** плагин не загружает биндинги заранее и обращается к API документации только после нажатия «Копировать код»

#### Scenario: Копирование работает без превью

- **WHEN** превью недоступно (нет JCEF или плагин превью не загрузился)
- **THEN** кнопка «Копировать код» остаётся доступной

### Requirement: Оформление окна компонента

Плагин SHALL использовать компактные выпадающие списки для выбора конфигурации и значений осей вариаций по образцу инспектора клиента DS Builder. Режим темы SHALL переключаться компактной кнопкой с иконкой солнца или луны, как в списке токенов.

#### Scenario: Выбор конфигурации и вариации

- **WHEN** пользователь открывает окно компонента
- **THEN** конфигурация (при наличии нескольких) и оси с несколькими значениями представлены селектами с текущим значением и доступным по клавиатуре списком
- **THEN** выбор конфигурации восстанавливает её значения по умолчанию и обновляет превью и копируемый стиль

#### Scenario: Фон соответствует песочнице plasma-android

- **WHEN** пользователь выбирает светлый или тёмный режим превью
- **THEN** фон холста и `surface.background` используют `backgroundDefaultPrimary` темы `integration-core/sandbox-compose`: `#F9F9F9` в светлой теме и `#080808` в тёмной
- **THEN** при переключении темы обновляются и токены компонента, и фон превью

#### Scenario: Обновление без сдвига превью

- **WHEN** пользователь меняет конфигурацию, вариацию или тему и превью загружается повторно
- **THEN** сообщение «Обновляем превью…» отображается поверх самого холста внутри браузерной обёртки и не добавляет строку над превью
- **THEN** холст сохраняет высоту и положение, а после завершения обновления сообщение исчезает

#### Scenario: Селект раскрывается поверх превью

- **WHEN** пользователь раскрывает конфигурацию или ось вариации рядом с холстом
- **THEN** список полностью отображается поверх превью и не перекрывается нативной поверхностью браузера
- **THEN** браузер использует off-screen rendering с отдельным request context, а Compose-панель использует отдельные Swing popup-слои (`COMPONENT`) и Swing graphics, чтобы список и обработка кликов находились над SwingPanel

#### Scenario: Подсказка темы сохраняет доступность панели

- **WHEN** пользователь наводит курсор на кнопку темы, переключает тему и уводит курсор
- **THEN** подсказка показывает текущий режим и действие внутри основной Compose-сцены над кнопкой, не создавая прозрачный Swing popup-слой на всю панель
- **THEN** размер кнопки и положение превью не меняются; кнопки, селекты, возврат к списку и вкладки плагина продолжают принимать ввод

### Requirement: Шрифты выбранной дизайн-системы

Превью SHALL загружать TTF/OTF-файлы из выбранных токенов шрифтов. Публичные внешние HTTPS-файлы SHALL загружаться анонимным JVM-клиентом без cookie, авторизационных заголовков и автоматических перенаправлений. DNS-адреса внешнего хоста SHALL проверяться на принадлежность публичной сети, а соединение SHALL использовать проверенный IP с исходным TLS server name и HTTP Host без повторного DNS-разрешения при подключении. Файлы SHALL кешироваться в памяти сессии и предоставляться iframe через адреса origin плагина превью. Разрешённые origin навигации и сетевых ресурсов самого браузера SHALL оставаться прежними.

#### Scenario: Шрифт из внешнего CDN

- **WHEN** токен выбранной дизайн-системы содержит публичный HTTPS-адрес шрифта
- **THEN** превью использует указанный файл и начертание, включая SB Sans Text и SB Sans Display
- **THEN** при ошибке обязательного файла показывается диагностика вместо незаметной подстановки системного шрифта

#### Scenario: Ограничения ресурсов шрифтов

- **WHEN** загружаются внешние файлы шрифтов
- **THEN** принимаются только корректные TTF/OTF-файлы размером до 4 MiB, максимум 128 файлов и 32 MiB на сессию; действуют таймауты загрузки
- **THEN** ответы с перенаправлениями, неподдерживаемые схемы, адреса с user-info и превышение лимитов отклоняются
- **THEN** при закрытии сессии кеш и клиент загрузки освобождаются
