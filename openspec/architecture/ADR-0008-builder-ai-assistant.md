# ADR-0008: ИИ-ассистент в билдере

## Статус

Принято. Реализуется изменением `openspec/changes/add-builder-ai-chat`.

## Контекст

Пользователь хочет менять дизайн-систему фразами в чате прямо в билдере: «перекрась кнопку в красный». Публичный backend — один процесс `backend-kt/app`, в котором уже есть прикладные операции ds-service. Use case DS принимают проверенного участника проекта и предметную команду и сами проверяют права, ревизии и повторяемость.

В `frontend-kt/mcp-server-core` есть 61 инструмент для внешних агентов (ADR-0004). Это клиентский вход: его use case разрешают локальный контекст, адрес API и учётные данные и ходят в публичный API. Модели, с которыми нужно работать, — ZAI (формат API OpenAI) и GigaChat (свой формат).

## Решение

1. **Подсистема монолита.** ИИ-ассистент — подсистема `backend-kt/ai-assistant` внутри `backend-kt/app`, а не отдельный сервис. Маршруты — под `/api/projects/{projectId}/ai` с проверенным контекстом.
2. **Свои инструменты поверх use case DS.** Подсистема объявляет каталог инструментов (имя, описание, схема, разрешение, вид операции) и порт выполнения `ChatToolExecutor`. Порт реализует адаптер `InProcessChatTools` в `backend-kt/app`: он строит `DsRequestContext` и вызывает use case ds-service внутри процесса. Адаптер переводит аргументы в команду и результат в JSON, но не содержит предметных правил. `ai-assistant` не зависит от модулей ds-service: межподсистемные адаптеры, как и прежде, живут в `app`.
3. **Актуальные права перед каждым инструментом.** Ход начинается с `ProjectPrincipal` из проверенного контекста запроса, Bearer пользователя в подсистему не передаётся. Перед каждым вызовом инструмента права актуализируются внутри процесса через порт подсистемы: роль и членство в проекте из `ProjectAuthorization`, а для PAT — что токен не отозван, не истёк и владелец активен. Флаг системного администратора пользователя без PAT держится весь ход: перечитать его без токена в монолите негде. Отзыв доступа к проекту завершает ход с `access_revoked`, потеря права на инструмент даёт `tool_not_allowed`. Use case проверяет права на каждую операцию по актуализированному участнику. Срок хода ограничивает и ожидание модели, а остановка его прерывает.
4. **Провайдеро-независимый слой.** Цикл агента работает с нейтральной моделью сообщений и портом `LlmClient`. Адаптеры: `OpenAiCompatibleClient` (ZAI и другие API формата OpenAI, провайдер выбирается настройками; по умолчанию ZAI `glm-4.5-flash`) и `GigaChatClient`.
5. **Фоновый ход.** Ход агента выполняется в области подсистемы, не связанной с HTTP-запросом; события читаются возобновляемым потоком. Отключение клиента не прерывает запись.

## Рассмотренные варианты

- **Встроить `mcp-server-core` и вызывать публичный API по `127.0.0.1` с Bearer пользователя.** Отклонён. Нужно исключение из требования монолита «Независимость поведения от транспорта», пересылка и повторная проверка токена с риском его истечения посреди хода, а в образ монолита пришлось бы собирать клиентские модули `frontend-kt` с MCP SDK. Проверок прав это не добавляет: их делает use case.
- **Модули адаптеров внутри `ai-assistant` с зависимостью от модулей ds-service.** Отклонён: связывает подсистемы напрямую и мешает их будущему выделению.
- **Отдельный сервис агента с внутренним HTTP к сервисам DS.** Отклонён: монолит — единственный поддерживаемый прикладной процесс. При выделении DS в отдельный сервис меняется только реализация `ChatToolExecutor`.

## Отношение к ADR-0004

ADR-0004 для внешних агентов не меняется: MCP-ядро, его инструменты и порядок выбора учётных данных остаются прежними. Встроенный чат MCP-ядро не использует. Инструменты двух входов ведутся отдельно, их имена, описания и схемы могут расходиться.

## Последствия

- Новая операция DS становится доступна чату только после записи в каталоге, обработчика в адаптере и тестов.
- Сборка монолита не зависит от `frontend-kt`.
- Отзыв PAT, смена роли и удаление из проекта действуют на чат с ближайшего вызова инструмента. При выходе клиент останавливает активный ход.
- Данные дизайн-системы уходят внешнему провайдеру модели; клиент чата обязан предупреждать об этом пользователя.
- `DsRequestContext` получает необязательное поле `expectedDraftId` для привязки подтверждённой операции к черновику. Публичный HTTP API ds-service не меняется.
