# Backend E2E tests

E2E tests проверяют систему через публичный Gateway, реальную авторизацию и общий локальный контур из
`setup-local.sh`. Сценарий может вызывать JVM CLI `dsbuilder`, если пользовательский путь проходит через CLI.

E2E запускает разработчик, CI или внешний оркестратор. TAKT эти сценарии не запускает. Если E2E нужны для задачи TAKT,
цикл останавливается на внешней проверке, а результат отдельного запуска передаётся обратно через recovery-механизм.

## Запуск

Из корня репозитория:

```bash
./tools/e2e all
./tools/e2e api-project-access
./tools/e2e cli-auth-session
./tools/e2e list
```

Runner сначала вызывает обычный `./setup-local.sh`. Используются те же общие Docker images, build cache, контейнеры,
порты и volumes, что при ручном локальном запуске. Отдельные Compose projects для E2E не создаются, а запущенный контур
после тестов не останавливается.

`setup-local.sh` пересоздаёт volumes JavaScript-контура, выполняет миграции и общий seed. После этого
`e2e/seed/common.sh` создаёт через Gateway данные, общие для E2E-сценариев, и записывает только идентификаторы и имена
пользователей в `e2e/artifacts/<run-id>/context.env`. Токены и пароли туда не записываются.

Остановить общий локальный контур можно обычной командой:

```bash
./setup-local.sh --down
```

## Новый сценарий

Добавьте исполняемый Bash-файл `e2e/scenarios/<name>.sh`. Сценарий получает:

- `E2E_GATEWAY_URL` — публичный URL Gateway, по умолчанию `http://localhost:8080`;
- `E2E_ARTIFACTS_DIR` — каталог результатов текущего запуска;
- `E2E_CONTEXT_FILE` — общие идентификаторы из seed;
- `E2E_CLI` — путь к JVM CLI `dsbuilder` для сценариев с префиксом `cli-`.

Используйте функции из `e2e/lib/common.sh`, `curl --fail-with-body` для успешных запросов и структурные проверки через
`jq`. Сценарий завершается с кодом `0` при успехе и ненулевым кодом при нарушении ожиданий.
