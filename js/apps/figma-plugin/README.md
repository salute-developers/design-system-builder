# Плагин DS Builder для Figma и Pixso

Приватный плагин организации: вход в DS Builder, просмотр токенов темы и экспорт темы в переменные и стили
открытого файла Figma или Pixso.

## Устройство

- `src/main` — основной поток: `clientStorage` редактора, внешний браузер и запись плана экспорта в документ.
  Об API, OAuth и правилах DS Builder не знает. `code.ts` и `pixso.ts` передают в `startPlugin` глобальный объект
  редактора, его описание (`src/shared/editor.ts`) и запись плана.
- `src/ui` — окно плагина на React: экраны и связь с общими Kotlin-модулями.
- `frontend-kt/plugins/figma-core` — вход, сессия, запросы к API и построение плана экспорта на Kotlin/JS. Сборка
  плагина собирает его сама, поэтому нужен JDK 17.
- `src/shared` — протокол сообщений между ними.

Запросы к API идут из окна. Его origin — `null`, поэтому gateway нужна настройка `OIDC_PLUGIN_ORIGINS=null`.

## Экспорт в Figma

Кнопка «Экспортировать в Figma» читает выбранную тему и версию и записывает в открытый файл структуру образца
`DS BUILDER | STYLES`:

| Коллекция | Режимы | Содержимое |
|---|---|---|
| `00. Palette` | Default | ступени палитры темы `<группа>/<шкала>/<ступень>` |
| `01. Theme` | Light, Dark | цвета всех контекстов, ссылки на палитру; скрыты из выбора |
| `02. SubTheme` | Default, onDark, onLight, Inverse | цвета без контекста, ссылки на тему |
| `03. Typography` | Large, Medium, Small | размер, высота строки, интервал, насыщенность, семейства |
| `04. Numbers` | Default | скругления |
| `05. Spacing` | Default | отступы |

Кроме переменных создаются текстовые стили с привязкой к `03. Typography`, стили эффектов для теней и стили заливки
для градиентов. Стопы и сплошные слои градиента — переменные `01. Theme`
`GradientStops/<имя переменной темы>/Stop N` и `Fill N`, а стиль один и привязан к ним, поэтому меняется вместе с
режимом фрейма. Если слои Light и Dark различаются (число слоёв, угол, стопы), остаётся пара стилей `Light/…` и
`Dark/…`, а отчёт показывает причину в разделе «Создано с оговоркой». Состояния `-hover`, `-active`, `-brightness` лежат рядом с основным цветом:
`Primary`, `PrimaryHover`, `PrimaryActive`, `PrimaryBrightness`. Скругления повторяют набор образца: `cRxxs` … `cRxxl`,
`null` = 0, `Rounded` = 1000 и внутренние радиусы `calc:[cR<размер>-2]`. Выключенные в DS Builder токены не
экспортируются.

Повторный экспорт находит созданное по общему ключу плагина `dsbuilder` и обновляет его: дубликатов нет, привязанные
слои получают новые значения. Если ключ сменился, а дизайн-система, имя и тип те же (токен создан заново), переменная
переходит к новому ключу и привязки сохраняются. То, чего больше нет в теме, не удаляется и считается в отчёте устаревшим.

Слои теней со ссылкой на палитру привязаны к переменным `01. Theme` `ShadowColors/<тень>/Layer N`: ссылка на ступень
палитры с прозрачностью слоя, поэтому тень меняется вслед за палитрой.

Один файл Figma рассчитан на одну дизайн-систему: экспорт другой дизайн-системы в тот же файл пометит прежние
переменные устаревшими. Темы одной дизайн-системы перезаписывают значения друг друга, отчёт называет последнюю.

Ограничения Figma: на тарифе Starter у коллекции один режим, и экспорт остановится с причиной на втором режиме.
Текстовый стиль пропускается, если шрифта семейства нет у пользователя Figma; отчёт называет недостающие шрифты и
даёт кнопку, которая скачивает файлы `.otf` из токенов `fontFamily` одним архивом `dsbuilder-fonts.zip`. Файлы качает
Kotlin-ядро с CDN `cdn-app.sberdevices.ru` (он разрешён в манифесте), ZIP собирает основной поток.
Figma desktop видит шрифты, установленные в системе, поэтому у дизайнеров с SB Sans стили создаются.

В просмотре токенов любое имя и значение копируется нажатием.

## Запуск

```bash
npm install
npm run build:dev   # адрес gateway http://localhost:8080
```

В Figma desktop: Plugins → Development → Import plugin from manifest, выбрать `manifest.json`.

Локальному контуру нужны клиент `dsbuilder-figma-plugin` и роль `offline_access` в составе `user`: они создаются
импортом realm. Импорт не выполняется поверх существующей базы Keycloak, поэтому пересоздайте её.

## Запуск в Pixso

Сборка Pixso отличается только основным потоком и манифестом: окно и общие Kotlin-модули те же. В API Pixso нет
`openExternal`, поэтому адрес подтверждения входа открывает окно плагина.

```bash
npm run build:pixso:dev   # адрес gateway http://localhost:8080
npm run dev:pixso         # отдаёт dist-pixso отладчику на ws://localhost:5201/plugin
```

В Pixso откройте панель плагинов рядом с кнопкой Share и нажмите значок отладки слева в её заголовке. Сервер перечитывает
`dist-pixso` при каждом подключении; веб-Pixso держит загруженный плагин, поэтому после новой сборки перезагрузите вкладку.

Экспорт в Pixso записывает тот же план с отличиями: ссылка на палитру с прозрачностью становится цветом, градиент —
парой стилей `Light/…` и `Dark/…`, текстовые стили не привязаны к переменным `03. Typography`. Отчёт называет каждое
отличие одной оговоркой.

## Проверки

```bash
npm test
npm run build       # адрес боевого gateway
npm run build:pixso # то же и каталог dist-pixso
```

## Публикация

Приватная публикация выполняется в организации Figma. Figma выдаёт `id` плагина: запишите его в `manifest.json`
вместо значения для разработки.
