# Выбор аналитики

Веб и CLI со встроенным MCP запрашивают отдельное разрешение до отправки аналитики. Выбор не требует аккаунта и не влияет на доступность функций. Уведомление короткое, целиком показано рядом с выбором; отдельного полного текста нет.

## Веб

При первом посещении, включая страницу входа, появляется неблокирующий баннер. До разрешения и серверной квитанции не загружается даже скрипт Метрики. После подтверждения учитывается текущий раздел, прежние переходы не воспроизводятся. Кнопка «Настройки аналитики» позволяет изменить выбор и отозвать разрешение.

При перезагрузке страницы сохранённое разрешение проверяется одним GET. Переходы SPA не повторяют проверку. Ошибка проверки выключает аналитику для этой загрузки, не сбрасывая сохранённый выбор. Записи между вкладками сериализуются через Web Locks; при недоступности этой возможности аналитика выключена. Отказ и отзыв действуют сразу во всех вкладках; разрешение из другой вкладки само по себе не включает сбор.

## CLI и встроенный MCP

Перед первой рабочей командой в интерактивном терминале показывается вопрос с ответом по умолчанию «Нет». Help, version, группы без команды, ошибки разбора и mcp serve вопросов не задают. MCP и неинтерактивный CLI без разрешения работают без аналитики.

Управление выбором:

```sh
dsbuilder analytics enable
dsbuilder analytics disable
dsbuilder analytics status
```

Enable требует интерактивного терминала и явного ответа. Эти команды не создают продуктовых просмотров. Файл `~/.dsbuilder/privacy/analytics-consent.json` общий для CLI/MCP, записывается атомарно под блокировкой с правами 0600. Области разделены по адресу backend и счётчику, чтобы DEV/PROM не переносили разрешение друг другу.

Сохранённое разрешение проверяется один раз при запуске рабочей команды или MCP. Ожидание, включая файловую блокировку, ограничено одной секундой; при ошибке текущий запуск остаётся без аналитики. В долгоживущем MCP нет повторных GET или таймеров. Перед отправкой проверяется локальный отзыв; очередь после отзыва отбрасывается. Новая редакция на сервере обнаруживается при следующем запуске.

CI=true/1, DSBUILDER_ANALYTICS_DISABLED=1 и DO_NOT_TRACK=1 подавляют автоматические вопросы, запросы истории и аналитику. Изменение окружения не является отзывом. Явные команды настройки доступны отдельно, но не обходят запрет сбора окружением. Node.js MCP не подключает аналитику или историю согласий.

## Серверная история

Модуль backend-kt/consent-history работает внутри существующего backend-app и использует PostgreSQL проектов (те же PROJECTS_DATABASE_URL, PROJECTS_POSTGRES_USER и PROJECTS_POSTGRES_PASSWORD). Дополнительные контейнеры, OAuth и переменные аналитических токенов ему не нужны. Собственный небольшой пул закрывается вместе с приложением; Flyway создаёт схему consent и одну прикладную таблицу consent_history. Служебная таблица миграций не хранит решения пользователей.

Контракт: GET и POST /api/privacy/analytics/consent с отдельным заголовком X-Consent-Key. GET возвращает уведомление и последнее собственное решение. POST возвращает квитанцию после COMMIT. Исходный 256-битный ключ остаётся у клиента; в БД хранится SHA-256. Это другой идентификатор, чем ClientID Метрики. События идут напрямую в Яндекс; ключ и квитанция в Метрику не добавляются.

Source of truth API: backend-kt/consent-history/src/main/resources/openapi/documentation.yaml. Редакции уведомлений лежат в ресурсах notices; изменённые условия получают новую версию, старые байты сохраняются, пока на них ссылается история. Служебный доступ к истории выполняется через БД, публичного API истории нет.

Отказ или отзыв сначала сохраняется локально. При недоступном сервере решение остаётся pending и синхронизируется при следующем подходящем запуске. Точный повтор использует тот же request_id; после конфликта отрицательное решение обновляет серверную ревизию. Старое разрешение или его запоздалый ответ не отменяет локальный запрет.

Квитанция подтверждает запись решения от обладателя анонимного ключа, не личность человека. Конкретные сроки действия согласия, хранения и удаления этим изменением не устанавливаются; автоматического истечения или очистки по выдуманным срокам нет. Это не утверждение бессрочной политики хранения.
